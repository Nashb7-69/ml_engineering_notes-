Lesson 2: Loading & Inspecting Data

Mission context: Real ML projects start with raw files — CSVs, Parquet, databases. You need to load them efficiently, diagnose problems immediately, and verify the data matches your expectations before any modeling.

The ML Data Loading Workflow

# 1. Load with intentional dtypes & parsing
df = pd.read_csv("data/train.csv",
    dtype={"id": "int32", "category": "category"},
    parse_dates=["timestamp"],
    na_values=["NA", "N/A", "missing", ""],
    low_memory=False
)

# 2. Immediate diagnosis
df.info()           # ← ALWAYS RUN THIS FIRST
df.head()
df.describe(include="all")

# 3. Verify assumptions
assert df.shape == (expected_rows, expected_cols)
assert df["target"].notna().all()
assert set(df.columns) == expected_columns

Reading Common ML Formats

CSV — The Universal Interchange

# Basic
df = pd.read_csv("data.csv")

# Production-grade for ML
df = pd.read_csv("data/train.csv",
    # Performance
    dtype={"id": "int32", "cat_col": "category", "price": "float32"},
    low_memory=False,

    # Parsing
    parse_dates=["created_at", "updated_at"],
    date_format="%Y-%m-%d %H:%M:%S",  # Faster than inference

    # Missing values
    na_values=["NA", "N/A", "null", "NULL", "missing", "", " "],
    keep_default_na=True,

    # Sampling for exploration
    nrows=10000  # Quick peek without loading all
)

✅ Pro Tip: Specify dtype Upfront

Without dtype, pandas infers types row-by-row (slow) and may guess wrong (e.g., integers with one NaN become float64). Explicit dtypes: faster load, correct types, less memory.

Parquet — The ML Default

# Fast, columnar, preserves dtypes exactly
df = pd.read_parquet("data/train.parquet")

# Read only needed columns (huge speedup on wide data)
df = pd.read_parquet("data/train.parquet",
    columns=["feature_1", "feature_2", "target"])

# Partition pruning (if data is partitioned by date/category)
df = pd.read_parquet("data/train.parquet",
    filters=[("date", ">=", "2024-01-01"), ("category", "in", ["A", "B"])])

💡 Why Parquet for ML?

  • 10-100x faster reads than CSV
  • Preserves dtypes exactly (no inference)
  • Column pruning — read only what you need
  • Partition pruning — skip irrelevant files
  • Compressed by default (snappy/zstd)

SQL — When Data Lives in a Database

from sqlalchemy import create_engine

engine = create_engine("postgresql://user:pass@host/db")

# Push computation to DB where possible
df = pd.read_sql("""
    SELECT user_id, COUNT(*) as order_count, SUM(amount) as total_spent
    FROM orders
    WHERE created_at >= '2024-01-01'
    GROUP BY user_id
""", engine)

# Parameterized queries (safe, reusable)
df = pd.read_sql("SELECT * FROM users WHERE country = %s", engine, params=("US",))

# Chunked for large result sets
for chunk in pd.read_sql("SELECT * FROM huge_table", engine, chunksize=50000):
    process(chunk)

⚠ describe() Only Shows Numeric by Default

Always run df.describe(include="all") or df.describe(include="object") to see categorical distributions (unique count, top, freq).

Use the built-in seaborn dataset (no download needed):

Key Takeaways

  1. Always run df.info() first — it's your diagnostic dashboard
  2. Specify dtype and parse_dates in read_csv — faster, correct types, less memory
  3. Prefer Parquet for ML workflows — faster, preserves dtypes, column pruning
  4. Check describe(include="all") — numeric and categorical distributions
  5. Verify assumptions with assertions — catch data drift early
