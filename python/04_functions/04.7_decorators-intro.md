# 04.7 Decorators — An Introduction

## Learning Objectives

- Understand wrapping: a decorator is a higher-order callable that takes and returns a callable.
- Master `@decorator` syntax sugar and its desugaring into assignment.
- Preserve metadata with `functools.wraps` / `WRAPPER_ASSIGNMENTS`.
- Correctly stack multiple decorators and predict their execution order.
- Defer decoration with arguments via a decorator factory (`@decorator(args)` as two nested calls).

---

## 1. What a Decorator Is (and Is Not)

A **decorator** is a **callable that takes a callable and returns a callable**, conventionally used to extend or modify the behavior of the returned callable. The `@decorator` syntax is **sugar** for rebinding a name to the decorator's return.

What decorators are **not**:

- Not syntax magic. `@decorator` desugars to an assignment (see §2).
- Not class-only. Most decorators today decorate **functions**, but Python also supports decorating **classes** and, with helpers, properties. Our focus is functions.
- Not inheritance or metaclass. Decorators wrap at definition time per-name, one object at a time.
- Not always wrappers that call the original. Some decorators **register** the function and return it unchanged, replace it with a non-callable, or memoize.

Mental model: decorators are higher-order functions (§04.6) with a conventional return convention (a callable compatible with the original's signature). They benefit from closures (§04.5) and `*args/**kwargs` forwarding (§04.3).

---

## 2. `@` Syntax Sugar — Desugaring

```python
@my_decorator
def func(a, b):
    return a + b

# Desugars (exactly) to:
def func(a, b):
    return a + b
func = my_decorator(func)
```

The assignment happens **at definition time** — when the interpreter executes the `def` statement. The body of `func` does not run yet, but `my_decorator(func)` runs immediately, and its return value becomes the new `func` name.

With arguments (see §7):

```python
@my_decorator("arg", key=1)
def func(a, b):
    return a + b

# Desugars to:
def func(a, b):
    return a + b
func = my_decorator("arg", key=1)(func)
#   i.e., (my_decorator("arg", key=1)) is called first, must return a decorator callable
```

Implications:

1. Without `@`, you can decorate manually — useful for conditional decoration or testing.
2. The decorator can return anything: usually a wrapper function with compatible signature, sometimes the original function (registration pattern), sometimes a sentinel value.
3. `@` binds **after** evaluating the decorator expression left-to-right with the object it decorates as the single argument in the simple case.

Evidence — definition-time execution:

```python
def noisy(label):
    print(f"noisy('{label}') evaluated")
    def deco(func):
        print(f"  decorating {func.__name__} with '{label}'")
        return func  # return unchanged (registration-like)
    return deco

print("before def")
@noisy("A")
@noisy("B")
def hello():
    print("inside hello")

print("after def")
hello()
```

Output (order matters — see §6):

```
before def
noisy('A') evaluated
noisy('B') evaluated
  decorating hello with 'B'
  decorating hello with 'A'
after def
inside hello
```

```

Notes:
- `noisy('A')` and `noisy('B')` are evaluated top-to-bottom as Python executes the decorator list.
- The actual wrapping (`deco(func)`) is then applied bottom-to-top (see stacking section).

## 3. Wrapping: The Core Pattern

### 3.1 The simplest wrapper

```python
def logged(func):
    """Decorator that logs every call (simple version)."""
    def wrapper(*args, **kwargs):
        print(f"-> {func.__name__}{args} {kwargs}")
        result = func(*args, **kwargs)
        print(f"<- {result!r}")
        return result
    return wrapper

def add(a, b):
    return a + b

add = logged(add)  # manual decoration — same as @logged
print(add(2, 3))
# -> add(2, 3) {}   (wrapper's log)
# <- 5
# 5
```

Explanation:
- `logged` is a higher-order function: takes `func`, defines `wrapper` that **closes over** `func` (closure cell), returns `wrapper`.
- `wrapper(*args, **kwargs)` uses variadic parameters to forward **any** signature — essential for general-purpose decorators (lesson 04.3).
- `wrapper` calls `func(*args, **kwargs)` inside, so the original logic executes, but surrounding behavior (logging) happens first/after.

With `@`:

```python
@logged
def add(a, b):
    return a + b

print(add(2, b=3))
# -> add(2,) {'b': 3}
# <- 5
```

### 3.2 Realistic examples progressing simple → advanced

**Example 1 — Timer (side effect around call):**

```python
import time, functools

def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            print(f"{func.__name__} took {elapsed:.4f}s")
    return wrapper

@timed
def slow_add(a, b):
    time.sleep(0.02)
    return a + b

print(slow_add(2, 3))
```

**Example 2 — Validate / Guard (pre-condition check):**

```python
import functools

def require_positive(func):
    @functools.wraps(func)
    def wrapper(x, y):
        if x <= 0 or y <= 0:
            raise ValueError("arguments must be positive")
        return func(x, y)
    return wrapper

@require_positive
def ratio(x, y):
    return x / y

# ratio(5, 2)  # 2.5
# ratio(-1, 2) # ValueError
```

Note this wrapper chose explicit `(x, y)` not `*args/**kwargs` — fine for decorators targeting a specific signature, but limits reuse.

**Example 3 — Retry (control flow around call):**

```python
import functools, random

def retry(max_attempts=3):
    """Decorator factory (see §7) — for now consider @retry."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as exc:
                    last_exc = exc
                    print(f"attempt {attempt} failed: {exc}")
                    if attempt == max_attempts:
                        raise
            raise last_exc  # unreachable; keeps type checker happy
        return wrapper
    return decorator

# Pretend manual factory use:
# multiply = retry(max_attempts=3)(multiply) — see §7 for full @retry syntax

# Lifecycle-with-context: always return / propagate exceptions correctly.

# Example 4 — Cache / Memoize (stateful, with closure dict):
import functools

def memoize(func):
    cache = {}  # closure dict — lives as long as wrapper
    @functools.wraps(func)
    def wrapper(*args):
        if args in cache:
            return cache[args]
        result = func(*args)
        cache[args] = result
        return result
    wrapper.cache = cache  # expose for introspection/tests
    return wrapper

@memoize
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)   # recursive calls go through wrapper -> cached

print(fib(10))            # 55
print(fib.cache)          # cache dict visible
# Note: functools.lru_cache / functools.cache is production-grade (with maxsize, thread-safety)
```

**Example 5 — Registration (decorator that does not wrap):**

```python
registry = {}
def register(func):
    registry[func.__name__] = func
    return func  # return original unchanged

@register
def greet(name):
    return f"Hello, {name}!"

print(registry)              # {'greet': <function greet ...>}
print(greet("Ada"))          # Hello, Ada!
print(greet is registry["greet"])  # True — no wrapper
```

This decorator's purpose is **side effect** (registration), not behavior injection.

## 4. Preserving Metadata — Why `functools.wraps` Matters

### 4.1 The problem: wrapper hides the original

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        """Wrapper docstring."""
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def add(a, b):
    """Add two numbers."""
    return a + b

print(add.__name__)   # wrapper — lost!
print(add.__doc__)    # Wrapper docstring. — not "Add two numbers."
print(add.__module__) # original module preserved? partly but not name/doc
help(add)             # shows wrapper signature (*args, **kwargs) — useless
```

Stack traces and `inspect.signature(add)` show `wrapper(*args, **kwargs)` — debugging becomes miserable. In a codebase with many decorators, losing metadata makes tooling, Sphinx docs, and debuggers misbehave.

### 4.2 The fix: `functools.wraps` (and `update_wrapper` / `WRAPPER_ASSIGNMENTS`)

```python
import functools

def my_decorator(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def add(a, b):
    """Add two numbers."""
    return a + b

print(add.__name__)       # add — preserved
print(add.__doc__)        # Add two numbers. — preserved
print(add.__module__)     # __main__
print(add.__wrapped__)    # <function add at ...> — reference to original
print(add.__wrapped__ is not add)  # True
```

`@functools.wraps(func)` does roughly:

```python
wrapper = functools.update_wrapper(wrapper, func)
# copies: __module__, __name__, __qualname__, __doc__, __annotations__
# updates: __dict__
# sets: __wrapped__ = func
# wraps's WRAPPER_ASSIGNMENTS = ('__module__', '__name__', '__qualname__', '__doc__', '__annotations__')
# wraps's WRAPPER_UPDATES = ('__dict__',)
```

Full idiom for decorators that must also preserve signature introspection for tools that need it — combine with `inspect.signature` follow-chains via `__wrapped__`:

```python
import inspect

def deco(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@deco
def f(a, b, c=1): pass

print(inspect.signature(f))            # (a, b, c=1) — unwraps via __wrapped__
print(inspect.unwrap(f) is f.__wrapped__) # True — inspect can chase __wrapped__
```

> **Rule:** Every non-registration wrapper **must** use `@functools.wraps(func)` (or `update_wrapper`) on its inner function. Treat omission as a bug.

Registration decorators that `return func` need no wrapping — they return the original.

## 5. Stacked Decorators and Order

### 5.1 Syntactic order

```python
@decorator_A
@decorator_B
@decorator_C
def func():
    ...

# Desugars to:
def func(): ...
func = decorator_A(decorator_B(decorator_C(func)))
# i.e., bottom decorator applied first, then its result wrapped by the next up.
```

Think of it as a **pipeline**: innermost `decorator_C` wraps the original function, then `decorator_B` wraps that, then `decorator_A` wraps the result. At **definition time**, `decorator_C(func)` runs first; at **call time**, `decorator_A`'s wrapper executes outermost (first entry, last exit).

Visual:

```
Call:  caller -> A.wrapper -> B.wrapper -> C.wrapper -> original func
Def:   func = A(B(C(func)))   # C first, A last
```

### 5.2 Concrete demonstration — order matters

```python
import functools

def tag(label):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(f"enter {label}")
            result = func(*args, **kwargs)
            print(f"exit {label}")
            return result
        return wrapper
    return decorator  # tag is a factory; see §7

@tag("A")
@tag("B")
@tag("C")
def work():
    print("  inside work")

work()
```

Output:
```
enter A
enter B
enter C
  inside work
exit C
exit B
exit A
```

Explanation: Definition built `work = tag("A")(tag("B")(tag("C")(work_original)))`. The outermost call (`A`) enters first, recurses to `B`, then `C`, then original.

**Non-commutative consequence:** Swapping order can change semantics:

```python
import functools

def double(func):
    @functools.wraps(func)
    def w(*a, **kw): return func(*a, **kw) * 2
    return w

def add_one(func):
    @functools.wraps(func)
    def w(*a, **kw): return func(*a, **kw) + 1
    return w

@double
@add_one
def five(): return 5
# desugars: five = double(add_one(five_orig))
# call: double's w -> add_one's w (5+1=6) *2 =12

print(five())  # 12

@add_one
@double
def five2(): return 5
# five2 = add_one(double(five2_orig))
# call: add_one's w -> double's w (5*2=10) +1 =11
print(five2())  # 11 — different!
```

> **Heuristic for ordering:** Keep decorators that **handle exceptions or suppress errors** closest to the function (innermost), and decorators that **set up/tear down resources** or **require auth** outermost (so they guard outermost). Authentic real-world stacks often look like:
> ```python
> @count_calls
> @require_auth
> @transaction.atomic
> @cache
> def view(...): ...
> ```

### 5.3 Debugging stacked decorators

Use `inspect.unwrap` to peel layers:

```python
import inspect

print(inspect.unwrap(work))               # original work function
print(work.__wrapped__)                   # one layer peeled (B's wrapper)
print(inspect.unwrap(work).__name__)      # 'work'

# Also see all layers:
cur = work
while hasattr(cur, "__wrapped__"):
    print(cur.__name__, "->", cur.__wrapped__.__name__)
    cur = cur.__wrapped__
```

## 6. Edge Cases and Pitfalls

### 6.1 Forgetting to `return` the wrapper

```python
def bad(func):
    def wrapper(*a, **kw):
        func(*a, **kw)   # computed but discarded; not returned!
    return wrapper

@bad
def add(a, b): return a + b
print(add(2, 3))  # None — wrapper didn't return func's result
```

Always `return func(*args, **kwargs)` (or its transformed `return`).

### 6.2 Wrapper signature breaks introspection or keyword calls

A wrapper with fixed params (`wrapper(x, y)`) cannot wrap variadic targets:

```python
def rigid(func):
    def wrapper(x, y):  # only two positional
        return func(x, y)
    return wrapper

@rigid
def sum_many(*args): return sum(args)

# sum_many(1, 2, 3)  # TypeError: wrapper takes 2 positional args but 3 given
```

Solution: **always** use `*args, **kwargs` in generic wrappers; copy signature with `__wrapped__` chain for introspection.

### 6.3 Losing `self` in method decorators (descriptor protocol — advanced preview)

Wrapping a **method** inside a class definition as `def method(self):` with a naive function wrapper is fine — Python's descriptor protocol will bind `self` when accessed via instance. But **stacking property-like decorators** or writing class-level state requires care. The basic case just works:

```python
import functools

def logged_method(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"calling {func.__name__} args={args[1:]}")  # args[0] is self
        return func(*args, **kwargs)
    return wrapper

class Account:
    def __init__(self, balance):
        self.balance = balance

    @logged_method
    def deposit(self, amount):
        self.balance += amount
        return self.balance

a = Account(100)
print(a.deposit(50))  # calling deposit args=(50,) -> 150
```

Explanation: When you define `deposit = logged_method(deposit_orig)` inside the class body, `deposit` becomes a plain function object in the class dict. Access via `a.deposit` triggers descriptor `__get__`, binding `self` automatically. The wrapper receives `self` as `args[0]`. This "just works" for simple method decorators.

The pitfall appears only with descriptors like `@property` or `@classmethod`, where order matters relative to the descriptor wrapper — keep those outermost / ensure you compose descriptors explicitly (beyond introductory scope, see Python data model docs for descriptor protocol).

### 6.4 Decorators vs decorator factories — parentheses matters

```python
def mydec(func): ...  # usage: @mydec

def mydec_factory(arg):
    def deco(func): ...
    return deco       # usage: @mydec_factory("x")

# @mydec           # correct — passes function
# @mydec()         # TypeError — mydec() called with no args during decoration attempt (if it expects func)
# @mydec_factory   # wrong — passes function to factory's arg slot, not func
# @mydec_factory("x")  # correct — factory returns deco, then deco(func)
```

A missing/extra `()` is the most common syntax error in this chapter.

## 7. Decorators with Arguments (Decorator Factories)

A **decorator with arguments** such as `@retry(max_attempts=5)` or `@tag("label")` is **not** a decorator expecting extra params — it's a **factory**: a normal function that takes those arguments and **returns a decorator** (which then takes the function). So evaluation is **two steps**:

```python
@retry(max_attempts=5)
def fragile():
    ...

# Equivalent (desugared):
def fragile(): ...
decorator = retry(max_attempts=5)  # step 1: factory call -> returns a decorator
fragile = decorator(fragile)       # step 2: decorator applied to function
```

### 7.1 Minimal factory — two nested functions

```python
import functools

def repeat(times):
    """Decorator factory: repeat the call `times` times, return list of results."""
    if times <= 0:
        raise ValueError("times must be >= 1")

    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            return [func(*args, **kwargs) for _ in range(times)]
        return wrapper

    return decorator

@repeat(times=3)
def greet(name):
    return f"Hello, {name}!"

print(greet("Ada"))  # ['Hello, Ada!', 'Hello, Ada!', 'Hello, Ada!']

# Manual equivalent — reveals the two steps:
def greet_raw(name): return f"Hello, {name}!"
greet_raw = repeat(times=2)(greet_raw)
print(greet_raw("Bob"))  # ['Hello, Bob!', 'Hello, Bob!']
```

Explanation:
- `repeat(times)` is called **at decoration time**, before `greet`'s body runs. It closes over `times` and returns `decorator`.
- `decorator(greet)` is called with the new function, closing over both `times` (from factory) and `greet`, and returns `wrapper`.

Visually:

```
Factory:  repeat(times=3) -> decorator
Decorator: decorator(greet) -> wrapper
Result:   greet = wrapper  (wrapper closes over times=3 and func=greet_original)
```

### 7.2 Factory with positional and keyword arguments

```python
import functools

def with_tag(tag, suffix=""):
    """Factory whose decorator tags each return value with prefix/suffix."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            return f"{tag}{func(*args, **kwargs)}{suffix}"
        return wrapper
    return decorator

@with_tag("[INFO]", suffix=" !")
def message(name): return f"Hello, {name}"

print(message("Ada"))  # [INFO]Hello, Ada !

@with_tag(">> ")  # suffix defaults to ""
def other(x): return x

print(other(42))  # >> 42
```

`tag` and `suffix` are lexically closed over at factory call time, per-decorated function.

### 7.3 Supporting `@decorator` and `@decorator(args)` with one name (optional-argument decorators)

Some decorators aim to work both ways:

```python
import functools

# The goal: @mydec and @mydec(option=...) both valid
# Pattern A: detect callability
def optional_args_decorator(_func=None, *, flag=True):
    """Can be used as @mydec or @mydec(flag=False)."""
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            if flag:
                print("flag is True — extra behavior")
            return func(*args, **kwargs)
        return wrapper

    if _func is None:
        return decorator          # called as @deco(flag=False) -> return decorator
    else:
        return decorator(_func)   # called as @deco -> _func is the function itself

@optional_args_decorator
def f(a): return a

@optional_args_decorator(flag=False)
def g(a): return a

print(f(1))  # flag is True...
print(g(1))  # no flag message
```

Explanation:
- `@optional_args_decorator` without parentheses passes `f` as `_func` (positional, no `flag` override).
- `@optional_args_decorator(flag=False)` calls `_func=None, flag=False`, returns `decorator`; then Python applies `decorator(g)`.
- The `*,` keyword-only separation after `_func` prevents ambiguity.

A cost: this pattern is clever but subtle; many projects avoid it and instead require explicit parentheses (`@deco()` even when no args) to stay uniform.

**Note:** This dual-mode trick is an **optional** idiom, not a requirement. The primary mental model to master is the factory two-step.

### 7.4 Realistic factory example — per-function rate limit

```python
import functools, time, collections

def rate_limit(max_calls, per_seconds=1.0):
    """Factory that enforces at most `max_calls` per `per_seconds` window."""
    def decorator(func):
        calls: collections.deque = collections.deque()
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            now = time.monotonic()
            # evict old calls
            while calls and now - calls[0] > per_seconds:
                calls.popleft()
            if len(calls) >= max_calls:
                raise RuntimeError(f"rate limit exceeded: {max_calls}/{per_seconds}s")
            calls.append(now)
            return func(*args, **kwargs)
        wrapper._calls = calls  # test hook
        return wrapper
    return decorator

@rate_limit(max_calls=2, per_seconds=10)
def do_work(x):
    return x * 2

print(do_work(10))  # 20
print(do_work(20))  # 40
# do_work(30)       # RuntimeError: rate limit exceeded...
```

Each use of `@rate_limit(...)` closes over independent `max_calls`/`per_seconds`; each decorated function gets its own `calls` deque (shared via the closure cell among wrappers for multiple functions decorated with the same factory invocation would *not* be shared — the decorator is called *per function*).

## 8. Execution Timeline — When Each Code Runs

| Phase | What runs | Example |
|---|---|---|
| `import` / module execution | `def` body not run; decorator factory `decorator_factory(args)` runs; decorator `deco(func)` runs | `@factory(a)(func)` → both calls at definition |
| Function call | Wrapper (`*args/**kwargs` forwarding) → original (maybe multiple times, maybe not) | `func()` enters wrapper |
| Introspection (`help`, `inspect`) | Reads through `__wrapped__` chain via `wraps` | `help(func)` shows original signature |

Demonstrating timeline side effects:

```python
import functools

print("module start")

def deco(func):
    print(f"deco({func.__name__}) at decoration time")
    @functools.wraps(func)
    def wrapper(*a, **kw):
        print("wrapper at call time")
        return func(*a, **kw)
    return wrapper

print("before def")
@deco
def f(): print("inside f")
print("after def")

print("before call")
f()
print("after call")
```

Output order:

```
module start
before def
deco(f) at decoration time
after def
before call
wrapper at call time
inside f
after call
```

## 9. Quick Reference

| Concept | Desugars to | Key property |
|---|---|---|
| `@deco` | `func = deco(func)` | Decoration at definition time; call time is wrapper execution |
| `@deco(a, b)` = factory | `func = deco(a,b)(func)` | `deco(a,b)` must return a callable decorator |
| Wraps | `@functools.wraps(func)` on inner wrapper | Preserves `__name__`, `__doc__`, `__wrapped__` |
| Stack | `@A @B @C def f():` → `f = A(B(C(f)))` | Bottom applied first; outermost wrapper runs first at call |
| Registration | `def register(func): registry[func.__name__]=func; return func` | No wrapper; side-effect + identity return |
| Factory shape | `def factory(args): def decorator(func): @wraps(func) def wrapper(*a,**kw): ... return wrapper; return decorator; return decorator` | Two levels: factory closure over config, decorator over func |

**Checklist for writing good wrappers:**

1. Use `*args, **kwargs` unless you deliberately target a fixed signature.
2. `return func(*args, **kwargs)` (or its transformed result) — never drop the return.
3. Apply `@functools.wraps(func)` to the wrapper.
4. Expose any per-decorator state via closure or attribute; allow `inspect.unwrap` for debugging.
5. Document whether your decorator **wraps**, **registers**, or **replaces** the function.
