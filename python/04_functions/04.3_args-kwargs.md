# 04.3 *args and **kwargs

## Learning Objectives

- Master variadic positional (`*args`) and keyword (`**kwargs`) parameters.
- Understand packing (in `def`) vs unpacking (at call sites) with `*` and `**`.
- Internalize the full parameter ordering: `pos, defaults, *args, kwonly, **kwargs`.
- Forward arguments correctly in wrappers and decorators.
- Avoid argument-collision and ordering bugs when mixing forms.

---

## 1. Why Variadic Parameters?

Sometimes the number of inputs is not known ahead of time:

- `print(*objects, sep=' ', end='\n')` — any number of objects.
- `max(iterable, *iterables)` — at least one, possibly more.
- Logging wrappers that must accept *anything* the wrapped function does.
- Constructors like `dict(*args, **kwargs)` or DSL builders.

Python solves this with two parameter forms:

| Syntax | Where | What it captures |
|---|---|---|
| `*args` | In `def` | Excess positional arguments as a **tuple** |
| `**kwargs` | In `def` | Excess keyword arguments as a **dict** |
| `*iterable` | At **call** | Unpacks an iterable into positional arguments |
| `**mapping` | At **call** | Unpacks a mapping into keyword arguments |

`*` and `**` are **packing** when inside `def` and **unpacking** when at a call site.

---

## 2. `*args`: Variadic Positional Parameters

### 2.1 Basic packing

```python
def summarize(*args):
    print(f"args={args!r}, type={type(args).__name__}")

summarize()              # args=(), type=tuple
summarize(1)             # args=(1,)
summarize(1, 2, 3)       # args=(1, 2, 3)
```

Explanation:
- `*args` collects all extra positional arguments into a tuple. Zero arguments → empty tuple `()`.
- The name `args` is conventional; any valid identifier works (`*values`, `*nums`). The `*` is the operator.

Inside the function, `args` is a normal tuple — iterate, slice, len, etc.:

```python
def average(*nums):
    if not nums:
        raise ValueError("at least one number required")
    return sum(nums) / len(nums)

print(average(10, 20, 30))  # 20.0
print(average(5))           # 5.0
# average() -> ValueError

def join(sep, *parts):
    return sep.join(str(p) for p in parts)

print(join(", ", "a", "b", "c"))  # a, b, c
print(join(" | "))                # '' — no parts, sum is empty
```

### 2.2 `*args` with preceding parameters

```python
def greet(greeting, *names):
    for name in names:
        print(f"{greeting}, {name}!")

greet("Hello", "Ada", "Bob", "Carol")
# Hello, Ada!
# Hello, Bob!
# Hello, Carol!

greet("Hi")   # no names — loop body not executed, no error
```

Positional parameters before `*args` are filled first; surplus goes into `args`. If no surplus, `args` is `()`.

### 2.3 `*args` is always a tuple (even with one element)

```python
def demo(*args):
    print(args, type(args))

demo(42)
# (42,) <class 'tuple'>
```

Note the trailing comma in repr `(42,)` — single-element tuple syntax.

## 3. `**kwargs`: Variadic Keyword Parameters

```python
def describe(**kwargs):
    print(f"kwargs={kwargs!r}, type={type(kwargs).__name__}")

describe()                      # kwargs={}, type=dict
describe(name="Ada", age=36)    # kwargs={'name': 'Ada', 'age': 36}
```

- `**kwargs` collects excess keyword arguments into a **new dict**.
- Key names are always strings; the dict preserves insertion order (Python 3.7+ guarantees order).

Realistic use:

```python
def build_profile(username, **extra):
    """Build a profile dict; username required, any other fields in extra."""
    profile = {"username": username}
    profile.update(extra)
    return profile

print(build_profile("ada"))                          # {'username': 'ada'}
print(build_profile("bob", role="admin", active=True))
# {'username': 'bob', 'role': 'admin', 'active': True}
```

Inside, `kwargs` is a plain dict — `.keys()`, `.get()`, `.items()`, etc.

### 3.1 Mixing `*args` and `**kwargs`

```python
def show(*args, **kwargs):
    print(f"args={args}")
    print(f"kwargs={kwargs}")

show(1, 2, x=10, y=20)
# args=(1, 2)
# kwargs={'x': 10, 'y': 20}

show()                  # args=() kwargs={}
show(1, y=2)            # args=(1,) kwargs={'y': 2}
show(x=1, y=2)          # args=() kwargs={'x': 1, 'y': 2}
```

## 4. The Full Parameter Order

This ordering is **mandatory** and is enforced by syntax:

```python
def function(
    positional,                  # 1. required positional-or-keyword
    with_default="x",             # 2. optional with defaults
    *args,                       # 3. *var-positional — or bare * if no var
    keyword_only,                # 4. keyword-only (after * or *)
    with_kw_default=123,         #    keyword-only with default
    **kwargs                     # 5. **var-keyword
):
    pass
```

More precisely (Python grammar):

```
def f(
    posonly, /              # optional positional-only segment (Python 3.8+, lesson 04.4)
    pos_or_kw,
    pos_or_kw_with_default=...,
    *args,                  # captures surplus positional
    kwonly,                 # bare -> keyword-only required
    kwonly_with_default=...,# keyword-only optional
    **kwargs
):
```

Rules:

- Everything before `*args` (or bare `*`) may be passed positionally or by keyword (subject to `/` restrictions).
- Everything **after** `*args` or `*` is **keyword-only** — it must be called as `kw=value`; positional passing fails.
- `**kwargs` must be last.
- You may have at most one `*args` and one `**kwargs`, but you may also use a **bare `*`** to introduce keyword-only parameters without capturing `*args`:

```python
def example(a, b, *, c, d=10):
    # a, b are positional-or-keyword
    # c, d are keyword-only (no *args to hold extras)
    print(a, b, c, d)

example(1, 2, c=3)         # 1 2 3 10
example(a=1, b=2, c=3, d=4)# 1 2 3 4
# example(1, 2, 3)         # TypeError: missing keyword-only argument 'c'
```

Bare `*` separates "may be positional" from "must be keyword." It appears often in API design for clarity.

Full-dress example:

```python
def request(
    method,
    url,
    *segments,
    params=None,
    headers=None,
    timeout=10,
    **options,
):
    """Build an HTTP request representation (demo only)."""
    full_url = "/".join([url.strip("/"), *(s.strip("/") for s in segments)])
    return {
        "method": method,
        "url": full_url,
        "params": dict(params) if params else {},
        "headers": dict(headers) if headers else {},
        "timeout": timeout,
        "options": options,
    }

print(request("GET", "https://example.com", "api", "users", timeout=5, retries=3))
# {'method': 'GET', 'url': 'https://example.com/api/users', 'params': {}, ...}

# params, headers, timeout are keyword-only (after *segments)
# retries=3 lands in **options
```

Explanation: `method` and `url` are required. Extra path segments go in `*segments` positionally. `params`/`headers`/`timeout` must be named; extras like `retries` collect into `**options`.

### 4.1 Common ordering errors

```python
# def bad(**kwargs, *args):  # SyntaxError: * must come before **
# def bad(*args, a):         # Actually valid: a is keyword-only after *args
# def bad(a, **kwargs, b):   # SyntaxError: ** must be last
# def bad(a=1, b):            # SyntaxError: non-default follows default
```

Python's parser gives specific errors for each — read them carefully.

## 5. Unpacking at the Call Site: `*` and `**`

`*` and `**` are inverses of `*args`/`**kwargs`. At a **call**, they unpack iterables/mappings into arguments.

### 5.1 `*` unpacking: iterable → positional arguments

```python
def add(a, b, c):
    return a + b + c

nums = [1, 2, 3]
print(add(*nums))        # add(1, 2, 3) -> 6
print(add(*(x*2 for x in nums)))  # add(2, 4, 6) -> 12

# Also works with strings, tuples, sets, generators — any iterable:
print(add(*"abc"))       # add('a','b','c') -> 'abc' (string concatenation via +)
print(add(*{10, 20, 30}))# order not guaranteed for sets — avoid for ordered params!
```

Explanation: `add(*nums)` is sugar for `add(nums[0], nums[1], nums[2])` (generalized to any iterable). The unpacking is evaluated left to right and spliced into the argument list.

You can mix literal and unpacked arguments:

```python
def show(a, b, c, d):
    print(a, b, c, d)

vals = [2, 3]
show(1, *vals, 4)  # show(1, 2, 3, 4)

first = [1]
mid = [2, 3]
show(*first, *mid, 4)  # show(1, 2, 3, 4)
```

### 5.2 `**` unpacking: mapping → keyword arguments

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

info = {"name": "Ada", "greeting": "Hi"}
print(greet(**info))  # greet(name="Ada", greeting="Hi") -> Hi, Ada!

# Merge dicts into keywords:
base = {"name": "Bob"}
extra = {"greeting": "Hey"}
print(greet(**base, **extra))  # Hey, Bob!
```

Rules:
- Keys must be strings matching parameter names.
- Duplicate keys raise `TypeError`.

```python
def f(a, b): pass
d = {"a": 1}
# f(**d, a=2)  # TypeError: multiple values for argument 'a'
```

### 5.3 Packing ↔ unpacking symmetry

```python
def outer(*args, **kwargs):
    print(f"outer received args={args} kwargs={kwargs}")

values = [1, 2]
options = {"x": 10, "y": 20}

# Packing (def):  *args/**kwargs gather
# Unpacking (call): *values/**options spread

outer(*values, **options)  # outer received args=(1, 2) kwargs={'x': 10, 'y': 20}
```

## 6. Forwarding and Wrapper Functions

The primary real-world use of `*args`/`**kwargs` is **argument forwarding** — writing functions that wrap others without enumerating their signatures.

### 6.1 Simple forwarder

```python
def trace(func, *args, **kwargs):
    print(f"calling {func.__name__} with args={args} kwargs={kwargs}")
    result = func(*args, **kwargs)
    print(f"-> {result!r}")
    return result

def add(a, b):
    return a + b

trace(add, 2, 3)              # args=(2,3)
trace(add, 2, b=3)            # kwargs={'b': 3}
trace(add, a=2, b=3)          # fun with keywords
```

This is the template for decorators (lesson 04.7): intercept call, forward with `*`/`**`.

### 6.2 Partial application / adapter wrappers

```python
import time

def timed(func, *args, **kwargs):
    start = time.perf_counter()
    try:
        return func(*args, **kwargs)
    finally:
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f}s")

def slow_add(a, b):
    time.sleep(0.05)
    return a + b

timed(slow_add, 2, b=3)
```

### 6.3 Forwarding with additional parameters

```python
def with_retry(func, *args, retries=3, **kwargs):
    """Call func(*args, **kwargs), retrying on exception."""
    last_exc = None
    for attempt in range(1, retries + 1):
        try:
            return func(*args, **kwargs)
        except Exception as exc:
            last_exc = exc
            print(f"attempt {attempt} failed: {exc}")
    raise last_exc

def unstable(x):
    import random
    if random.random() < 0.7:
        raise RuntimeError("flaky")
    return x * 2

# with_retry(unstable, 10, retries=5)  — retries is consumed here, not forwarded
```

Note: `retries=3` is **keyword-only** (after `*args`). Callers must write `retries=5` if overriding; `with_retry(func, 1, 2, 3)` would treat `3` as part of `*args` forwarded to `func`, not as retry count. This is idiomatic placement for wrapper control parameters.

### 6.4 Kwargs forwarding collision pitfall

```python
def wrapper(func, *args, verbose=False, **kwargs):
    if verbose:
        print(f"calling {func.__name__} kwargs={kwargs}")
    return func(*args, **kwargs)

def greet(name, greeting="Hello", verbose=False):
    return f"{greeting}, {name}! verbose={verbose}"

# Problem if caller's kwargs contains 'verbose':
# wrapper(greet, "Ada", verbose=True)  # wrapper consumes verbose=True;
#                                     # greet never sees it.
# But: wrapper(greet, **{"name": "Ada", "verbose": True}) —
# greet gets verbose=True via **kwargs? Let's see:
wrapper(greet, name="Ada", verbose=True)  # wrapper's verbose=True,
                                           # greet called as greet(name="Ada")
                                           # greet's verbose default survives

# If you need to forward wrapper's own kwargs too, pop it:
def wrapper2(func, *args, **kwargs):
    verbose = kwargs.pop("verbose", False)
    if verbose:
        print(f"forwarding {kwargs} to {func.__name__}")
    return func(*args, **kwargs)

print(wrapper2(greet, name="Ada", verbose=True))  # forwards without collision
print(wrapper2(greet, "Ada", greeting="Hi", verbose=True))
```

Lesson: In wrapper APIs, never let wrapper-control keywords collide with wrapped-function parameters unless you `pop` them from `**kwargs`.

## 7. Advanced Unpacking Patterns

### 7.1 Destructuring assignment with `*` (sequence unpacking)

Not call-site unpacking, but same star idea — worth knowing together:

```python
first, *middle, last = [1, 2, 3, 4, 5]
print(first, middle, last)  # 1 [2, 3, 4] 5

a, *rest = [10, 20, 30, 40]
print(a, rest)              # 10 [20, 30, 40]

*head, tail = [1, 2, 3]
print(head, tail)           # [1, 2] 3

first, *rest = [42]
print(first, rest)          # 42 [] — rest allowed to be empty
```

Only **one** `*` target allowed per assignment, but at call sites you may have multiple `*` unpackings (as above with `show(*first, *mid, 4)`).

### 7.2 Dict merging with `**`

```python
defaults = {"color": "blue", "size": "M"}
overrides = {"size": "L", "active": True}

merged = {**defaults, **overrides, "color": "red"}
# {'color': 'red', 'size': 'L', 'active': True} — last wins left-to-right
print(merged)

# Equivalent call-site unpacking:
def configure(color, size, active=False):
    return f"{color} {size} active={active}"

print(configure(**defaults))              # color=blue, size=M (defaults)
print(configure(**{**defaults, **overrides}))  # color=blue, size=L — overrides wins
```

In dict literals `{**a, **b}` the `**` merges; at calls `f(**a, **b)` it supplies keyword arguments (duplicate keys raise there, whereas literal merging silently lets last win).

### 7.3 Multiple unpackings in a single call

```python
def combine(a, b, c, d, e):
    return (a, b, c, d, e)

left = [1, 2]
right = {"d": 4, "e": 5}
print(combine(*left, 3, **right))  # (1, 2, 3, 4, 5)

# Also: star unpacking works in tuple/list literals
extra = [3, 4]
full = [1, 2, *extra, 5]   # [1, 2, 3, 4, 5]
print(full)
```

Evaluation order: positional expansions (`*iterable`) are spliced first, then keyword expansions (`**mapping`). Two `*`s yield their iterables left-to-right. E.g. `f(*[1], *[2])` is `f(1, 2)`.

## 8. Edge Cases, Mistakes, and Pythonic Idioms

### 8.1 Forgetting to unpack

```python
nums = [1, 2, 3]

def total(*args):
    return sum(args)

print(total(nums))   # nums as single element: args=([1,2,3],) -> TypeError: sum of list?
print(total(*nums))  # correct: 6

def greet(name, age): pass
info = {"name": "Ada", "age": 36}
# greet(info)   # TypeError: missing required argument 'age' — dict as single arg
greet(**info)    # correct
```

### 8.2 Mutating `args`/`kwargs` inside

`args` is a tuple (immutable); `kwargs` is a **new dict** per call. Mutation idioms:

```python
def append_more(*args):
    # args is a tuple — must create new tuple to "mutate"
    args = args + (99,)
    return args

print(append_more(1, 2))  # (1, 2, 99)

def with_defaults(**kwargs):
    kwargs.setdefault("color", "blue")  # safe — kwargs is a copy
    return kwargs

d = {"size": "L"}
print(with_defaults(**d))  # {'size': 'L', 'color': 'blue'}
print(d)                   # {'size': 'L'} — caller not mutated
```

### 8.3 Ordering bugs: positional after unpacking

```python
def f(a, b, c): pass

# f(*[1, 2], 3)      # OK — positional after unpack → c=3
# f(*[1, 2], b=3)    # TypeError: multiple values for b (b got both positionally and by keyword)
# f(a=1, *[2, 3])    # OK in recent Python — but subtle; avoid mixing this way
```

Keep it simple: unpacked forms usually at the end: `f(1, *rest, **kw)`.

### 8.4 Realistic: Logging decorator skeleton (preview of 04.7)

```python
import functools

def logged(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"-> {func.__name__}{args} {kwargs}")
        result = func(*args, **kwargs)
        print(f"<- {result!r}")
        return result
    return wrapper

@logged
def add(a, b):
    return a + b

add(2, b=3)
# -> add(2,) {'b': 3}
# <- 5
```

The wrapper needs `*args, **kwargs` so it can wrap **any** signature without rewriting.

### 8.5 Performance note

`*args`/`**kwargs` add a small overhead: tuple/dict creation per call. For hot loops, prefer explicit parameters. For wrappers and generic APIs, the flexibility is worth it.

## 9. Quick Reference

| Pattern | Meaning |
|---|---|
| `def f(*args):` | Collect surplus positional args into tuple `args` |
| `def f(**kwargs):` | Collect surplus keyword args into dict `kwargs` |
| `def f(*args, **kwargs):` | Collect all surplus args/kwargs |
| `def f(a, *args, b, **kwargs):` | `a` pos, `*args` catch extras, `b` keyword-only, `**kwargs` extras |
| `def f(*, b):` | No var-positional, but `b` keyword-only (bare `*`) |
| `f(*iterable)` | Unpack iterable into positional args |
| `f(**mapping)` | Unpack mapping into keyword args |
| `f(*a, *b, **c)` | Multiple unpackings in one call |
| `first, *mid, last = seq` | Unpack assignment (one `*`) |
| `wrapper(*args, **kwargs)` | Forward exactly what caller gave |

## 10. Exercises

1. Write `def product(*nums):` returning the product; raise `ValueError` if empty. Test with `product(2, 3, 4)`, `product(*[5,6])`.
2. Write `def make_config(**opts):` that returns a dict merging defaults `{"timeout":10, "retries":3}` with `opts`, caller wins. Test `make_config(timeout=5, verbose=True)`.
3. Implement `def call_twice(func, *args, **kwargs)` that calls `func(*args, **kwargs)` twice, returns list of results. What if `func` mutates `args[0]`?
