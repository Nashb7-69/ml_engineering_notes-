# 04.5 Scope, Closures, and nonlocal

## Learning Objectives

- Master the LEGB resolution rule and know where each lookup goes.
- Distinguish `global` vs `nonlocal` and when each is required.
- Understand closures as cells that capture **variables**, not values, and diagnose the late-binding loop/lambda pitfall.
- Build factory functions, read `__closure__` cells, and reason about lifetime/memory of closed-over state.

---

## 1. Scope: Regions Where Names Are Visible

A **scope** is the textual region of code where a bare name (`x`, `foo`) binds to a particular variable without qualification (`m.x`, `obj.attr` — not simple names). Python has **four** nested scope types. Together they form **LEGB**:

| Letter | Scope | Where it lives | Lookup order |
|---|---|---|---|
| **L** | **Local** (function) | Inside the current `def` / `lambda` body | First |
| **E** | **Enclosing** | Any enclosing `def` / `lambda` bodies (outside L, inside G) | Second |
| **G** | **Global** (module) | Top-level of the current `.py` file | Third |
| **B** | **Built-in** | `builtins` module (`len`, `range`, etc.) | Last |

Python resolves a read of a name by scanning **L → E → G → B**. An **assignment** (`x = ...`) or `def`/`class`/`import` rebinds in the **nearest enclosing scope that contains `x` as local** — unless `global`/`nonlocal` redirects it.

### 1.1 Visual: LEGB nesting

```python
import builtins          # B: builtins.len, etc.

VALUE = "global"         # G: module level

def outer():             # G also introduces 'outer' in module
    value = "enclosing"  # E: relative to inner()

    def inner():         # E for yet-more-inner; L is this body
        value = "local"  # L: shadows enclosing
        print(value)     # resolves to L -> "local"
        print(len)       # L/E/G miss -> B -> builtins.len

    inner()

outer()
```

If `inner` omitted `value = "local"`, `print(value)` would find `value` in E (`"enclosing"`). Remove that too and it finds G (`"global"`). Remove that and `NameError`.

### 1.2 Scopes are established statically (lexically)

A function's scopes are fixed from source structure — not from call stack:

```python
x = "global"

def foo():
    print(x)       # E/G lookup determined at definition time

def bar():
    x = "bar local"
    foo()          # prints "global", not "bar local"

bar()
```

`foo`'s `x` resolves to the global, even though `bar`'s local `x` is on the stack during the call. **Lexical** scope: enclosing scopes are parent `def`s in the file, not callers on the stack. Dynamic scoping (as in Bash `local` or Emacs Lisp) behaves differently — this is a common point of confusion for newcomers from those languages.

### 1.3 Blocks that do *not* create scopes

In Python **only** `def`, `lambda`, `class` (and module/comprehension scopes) introduce new scope. `if`, `for`, `while`, `with`, `try` **do not**:

```python
for i in range(3):
    x = i * 10

print(i)  # 2 — loop variable leaked!
print(x)  # 20 — body variable leaked!

if True:
    y = 99

print(y)  # 99 — if does not scope

# Contrast with e.g. Java/C where blocks scope.
```

This also means a function can read a variable defined "later" in the module only if the call occurs *after* that assignment runs — the scope exists, but the name binding must have happened by call time:

```python
def use():
    print(later)   # looks up G: later — must exist by call time

later = "assigned after def"
use()              # OK — G has 'later' by now

def use2():
    print(way_later)

# use2()             # NameError if called here — way_later not yet assigned
way_later = "now it exists"
use2()               # OK now
```

### 1.4 Comprehension scope (a subtle exception)

List/dict/set/genexp comprehensions have their **own scope** for the iteration variable (Python 3+), but still see enclosing scopes:

```python
nums = [1, 2, 3]
x = "outside"

# The x inside is a *different* x, local to the listcomp scope:
result = [x * 2 for x in nums]
print(x)       # "outside" — not overwritten (Python 3 behavior)
print(result)  # [2, 4, 6]

# Generator and dictcomps too:
gen = (x * 2 for x in nums)
print(next(gen)) # 2
print(x)         # still "outside"

# But closures inside listcomps still close over the comprehension's locals
funcs = [lambda: x for x in range(3)]
# funcs are closures over the listcomp's x — late binding applies (see §4)
```

In Python 2, listcomps leaked — another reason Python 3's scoped comps can surprise Python 2 migrants.

### 1.5 Class scope is peculiar

`class` introduces a scope, but **methods inside don't see it as enclosing**:

```python
class Foo:
    val = 10        # in Foo's class namespace

    def method(self):
        # print(val)   # NameError — class scope NOT in E for methods
        print(Foo.val) # must qualify
        print(self.val)

Foo().method()  # 10, 10
```

Class scopes sit *outside* the normal LEGB chain for enclosed `def`s; this is historical. Use `self.` or `ClassName.` inside methods, and for comprehension inside class body, know that Python 3.12+ has adapted shadowing rules — keep it simple.

## 2. Local Scope and the Assignment Rule

### 2.1 Assignment creates a local by default

If **any** assignment to `x` appears anywhere in a function body (including `def`, `import`, `for` unpacking, `with ... as x`, etc.), Python marks `x` as **local** to that function for the **entire** body, in a compile-time scan:

```python
x = "global"

def broken():
    print(x)    # expects local x — but not yet assigned
    x = "local" # this assignment makes x local for the *whole* function

# broken()      # UnboundLocalError: local variable 'x' referenced before assignment
```

Explanation: The compiler sees `x = "local"` anywhere in `broken` and marks `x` local. Therefore `print(x)` on the first line is a read of a **local** not yet bound, even though a global `x` exists. The fix is explicit:

```python
x = "global"

def ok_global():
    global x
    print(x)        # now reads global
    x = "mutated"
    print(x)        # "mutated"

ok_global()
print(x)            # "mutated" — global was modified

def ok_shadow():
    x = "shadow"    # local without global — shadows global, but no read before assignment
    print(x)        # "shadow"

ok_shadow()
print(x)            # still "mutated" (previous global)
```

`global x` says *"for this whole function, reads/writes to `x` mean the module-level `x`"*.

### 2.2 Shadowing builtins

Because B is last, locals can shadow builtins silently:

```python
def bad_sum(nums):
    sum = 0  # shadows builtins.sum in L — subsequent sum(...) would break
    for n in nums:
        sum += n
    return sum   # works here only by accident

print(bad_sum([1, 2, 3]))  # 6

def also_bad(nums):
    sum = 0
    return sum(nums)  # TypeError: 'int' object is not callable — local sum is int, not builtin

# also_bad([1,2])  # fails

# Remedy: avoid builtin names for locals. If you must reach the builtin:
import builtins
def safe_sum(nums):
    shadow = 0  # better: use another name
    for n in nums:
        shadow += n
    return builtins.sum(nums)  # explicit
```

## 3. `global` vs `nonlocal`

| Statement | Redirects to | Scope it must exist in | Used for |
|---|---|---|---|
| `global x` | Module global | Module (may create it) | Mutate module state, shared config |
| `nonlocal x` | Nearest enclosing function containing `x` | An enclosing `def` (must already exist) | Closure state mutation (counters, caches) |

### 3.1 `global` details

```python
count = 0

def increment():
    global count
    count += 1
    return count

print(increment())  # 1
print(increment())  # 2
print(count)        # 2 — module global mutated

def create_global():
    global brand_new
    brand_new = "hello"  # creates at module even if not existed

create_global()
print(brand_new)  # hello
```

`global` may list multiple names: `global x, y, z`. It applies to the **entire** function body from top to bottom — order does not matter.

### 3.2 `nonlocal` details and factory pattern

`nonlocal` targets an **enclosing `def`** scope — not the module, not the builtin. The name **must** already exist in that enclosing scope at definition/compile time, else `SyntaxError`:

```python
def make_counter(start=0):
    count = start                # enclosing variable

    def increment(step=1):
        nonlocal count           # redirect to outer's count
        count += step
        return count

    def current():
        return count             # read-only -> closure capture (no nonlocal needed to read)

    return increment, current

inc, cur = make_counter(10)
print(cur())     # 10
print(inc())     # 11
print(inc(5))    # 16
print(cur())     # 16 — both share the same cell

inc2, cur2 = make_counter(0)  # independent instance
print(cur2())    # 0
print(inc2())    # 1
print(cur())     # 16 — unaffected (separate closure cells)
```

Explanation:
- Each call to `make_counter` creates a **new local** `count`. The two inner functions each hold a **cell** referencing that same cell object (shared among them). `increment` needs `nonlocal` because it **rebinds** (`count += step` has `count = count + step`), while `current` only **reads**, so it closes implicitly without `nonlocal`.

Contrast without `nonlocal`:

```python
def make_broken(start=0):
    count = start
    def increment(step=1):
        count += step  # assignment makes count local to increment -> UnboundLocalError
        return count
    return increment

# broken = make_broken(5)
# broken()  # UnboundLocalError
```

### 3.3 When you need `nonlocal` vs when you do not

| Operation inside inner | Needs `nonlocal`? | Why |
|---|---|---|
| `print(x)` | No | Read — resolved via E |
| `x.attr = ...` / `x.append(...)` | No | Mutating the object, not rebinding the name |
| `x = ...` | **Yes** | Rebinding — otherwise makes local |
| `x += ...` | **Yes** | Desugars to `x = x + ...` — rebinding |

Mutating a mutable object is the exception: you can close over a list/dict without `nonlocal`:

```python
def make_stack():
    items = []               # enclosing mutable

    def push(x):
        items.append(x)      # mutation, not rebinding -> no nonlocal
        return items

    def pop():
        return items.pop()

    def view():
        return list(items)   # copy for inspection

    return push, pop, view

push, pop, view = make_stack()
push(1); push(2)
print(view())  # [1, 2]
push(3)
print(pop())   # 3
print(view())  # [1, 2]
```

This is the "mutable closure state without `nonlocal`" idiom, predating Python 3's `nonlocal`. Still valid, but `nonlocal` with immutable counters is often clearer.

### 3.4 `global` vs `nonlocal` in nested hierarchy

```python
val = "global"

def outer():
    val = "outer"

    def middle():
        val = "middle"

        def inner():
            nonlocal val   # resolves to 'middle' (nearest enclosing with val)
            # global val   # would resolve to module 'val' instead
            print(val)
            val = "inner-mutated"
            print(val)

        print(f"before inner, middle val={val}")
        inner()
        print(f"after inner, middle val={val}")

    middle()
    print(f"outer val={val}")

outer()
print(f"global val={val}")
```

Output:
```
before inner, middle val=middle
middle
inner-mutated
after inner, middle val=inner-mutated
outer val=outer
global val=global
```

`nonlocal` finds the **nearest** enclosing `def` that defines the name, not necessarily the outermost.

Chaining: `nonlocal` inside multiple layers can shadow:

```python
def outer2():
    x = "outer2"
    def a():
        nonlocal x   # outer2's x
        x = "from a"
        def b():
            nonlocal x  # now a's x after a rebound it? Actually still the same cell chain
            print(x)
        b()
    a()
    print(x)  # "from a" — a rebound outer2's cell

outer2()  # b prints "from a"; outer prints "from a"
```

## 4. Closures: Functions That Remember

A **closure** occurs when an inner function **reads or `nonlocal`-binds** a variable from an enclosing `def`, and the inner function **outlives** the enclosing call. Python preserves that variable in a **cell** attached to the inner function.

### 4.1 Minimal closure

```python
def make_multiplier(factor):
    def multiply(x):
        return x * factor   # factor from enclosing scope -> closure
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))  # 20
print(triple(10))  # 30
print(double.__closure__)            # tuple of cells, not None -> is a closure
print(double.__closure__[0].cell_contents)  # 2
print(triple.__closure__[0].cell_contents)  # 3
```

Explanation:
- `make_multiplier` returns `multiply` without calling it. `factor` was a parameter of the call to `make_multiplier`, which normally would die when that call returns. But `multiply` closes over `factor`, so Python allocates a **cell** to keep `factor`'s object alive. Each call to `make_multiplier` gets a **fresh** cell.

Inspect cells:

```python
print(double.__code__.co_freevars)     # ('factor',)
print(multiply_not_yet := double) # already double
print(double.__closure__ is not triple.__closure__)  # True — distinct cells
```

`__closure__` is `None` if the function closes over nothing; otherwise it is a tuple of `cell` objects parallel to `__code__.co_freevars`.

### 4.2 Mutable vs rebinding reminder (closure edition)

```python
# Mutation-only closure — no nonlocal needed:
def make_logger(prefix):
    history = []  # enclosing mutable

    def log(msg):
        entry = f"[{prefix}] {msg}"
        history.append(entry)  # mutation
        return entry

    def history_copy():
        return list(history)

    return log, history_copy

log, hist = make_logger("INFO")
print(log("start"))  # [INFO] start
print(log("end"))    # [INFO] end
print(hist())        # ['[INFO] start', '[INFO] end']

# Rebinding closure — nonlocal required:
def make_counter2(start=0):
    count = start
    def bump():
        nonlocal count
        count += 1
        return count
    return bump

c = make_counter2(100)
print(c(), c(), c())  # 101 102 103
```

## 5. The Late-Binding Pitfall and Its Fixes

### 5.1 The classic bug: loop + closure / lambda

This is Python's most infamous closure trap:

```python
funcs = []
for i in range(3):
    def f():
        return i
    funcs.append(f)

print([fn() for fn in funcs])  # [2, 2, 2] — expected [0, 1, 2]!
```

Explanation: Each `f` closes over the **variable** `i`, not its value at `def` time. Inside the loop, there is **one** `i` variable that gets rebound each iteration (the `for` loop rebinds `i`). All three `f`s close over the *same cell*. When you call them afterwards, they all read `i`'s latest value `2`.

Same with lambdas:

```python
funcs = [lambda: i for i in range(3)]
print([fn() for fn in funcs])  # [2, 2, 2]

buttons = []
for label in ["save", "load", "quit"]:
    buttons.append({"label": label, "action": lambda: print(label)})
# Every button prints "quit"
```

Truth table for "captures variable vs value":

| Language | `f` captures |
|---|---|
| Python | The **variable** (cell) — late binding |
| Some others (C++ `[x]`, Rust `move \|x\|`) | Optionally value/copy |

### 5.2 Fix 1: Default-argument capture (idiomatic classic)

```python
funcs = []
for i in range(3):
    def f(i=i):       # i as default captures current value (evaluated at def time)
        return i
    funcs.append(f)

print([fn() for fn in funcs])  # [0, 1, 2]

# Lambda form:
funcs = [lambda i=i: i for i in range(3)]
print([fn() for fn in funcs])  # [0, 1, 2]

# Button example:
buttons = []
for label in ["save", "load", "quit"]:
    buttons.append({"label": label, "action": lambda label=label: print(label)})
buttons[0]["action"]()  # save
buttons[1]["action"]()  # load
```

Why it works: Default arguments are evaluated at `def` time (lesson 04.2), with one object per function. So `i=i` freezes the current integer value into that `f`'s `__defaults__`.

### 5.3 Fix 2: Factory function (clearest, especially for larger closures)

```python
def make_action(label):
    def action():
        print(label)
    return action

buttons = []
for label in ["save", "load", "quit"]:
    buttons.append({"label": label, "action": make_action(label)})

buttons[0]["action"]()  # save — each make_action call has its own label cell
```

Each call to `make_action` gets a **fresh** `label` variable / cell, so closures are independent.

### 5.4 Fix 3: `functools.partial` (when wrapping a pre-existing function)

```python
import functools

def greet(name):
    print(f"hello {name}")

funcs = [functools.partial(greet, f"user{i}") for i in range(3)]
funcs[0]()  # hello user0 — no late-binding problem; args frozen inside partial
```

### 5.5 Bonus: listcomp late-binding is *still* late binding

Even scoped listcomps build closures late:

```python
# Comprehension variable is scoped, but funcs still close over it late:
funcs = [lambda: x for x in range(3)]
print([f() for f in funcs])  # [2, 2, 2] — same trap!
```

Fix with default: `[lambda x=x: x for x in range(3)]`.

## 6. Factory Functions: A Common Closure Design Pattern

A **factory** is a function that returns another function tuned with enclosed data.

```python
def make_adder(n):
    def adder(x):
        return x + n
    return adder

add10 = make_adder(10)
print(add10(5))    # 15
print(add10(100))  # 110

def make_validator(min_len, max_len, alphabet=None):
    import string
    if alphabet is None:
        alphabet = set(string.ascii_letters + string.digits)

    def validate(value):
        if not (min_len <= len(value) <= max_len):
            return False, f"length must be {min_len}..{max_len}"
        if not set(value).issubset(alphabet):
            return False, "invalid character"
        return True, "ok"

    return validate

username_ok = make_validator(3, 12)
print(username_ok("ab"))           # (False, 'length must be 3..12')
print(username_ok("Ada_01"))       # (False, 'invalid character') — underscore not in alphabet
print(username_ok("Ada01"))        # (True, 'ok')

# Factory with stateful power (nonlocal + closure):
def rate_limiter(max_calls, period=1.0):
    import time
    calls = []  # timestamps; mutated via closure

    def allow():
        nonlocal calls  # rebinding _is_ needed here because we do calls = calls[-k:]
        now = time.monotonic()
        # drop expired
        calls = [t for t in calls if now - t < period]
        if len(calls) < max_calls:
            calls.append(now)
            return True
        return False

    return allow

# allow = rate_limiter(3, period=5.0)
# allow(); allow(); allow() -> True, True, True
# allow() -> False until window slides
```

Factories via closures are Python's lightweight alternative to a full class for single-method stateful objects. Decide based on complexity: closures for small, single-function state; classes when you need multiple methods and public attributes.

## 7. Cells, `__closure__`, and Lifetime

### 7.1 Anatomy

```python
def demo():
    secret = "closure data"
    def inner():
        return secret
    return inner

fn = demo()
print(fn.__closure__)                  # (<cell at 0x...: str object at ...>,)
print(fn.__code__.co_freevars)         # ('secret',)
print(fn.__code__.co_varnames)         # () — cells are freevars, not local varnames
print(fn.__closure__[0].cell_contents) # 'closure data'
print(type(fn.__closure__[0]))         # <class 'cell'>

# Mutate through cell (advanced/debugging only):
fn.__closure__[0].cell_contents = "tampered"
print(fn())  # tampered — you've mutated the closed-over variable!
```

`cell` is an internal container that holds a reference. Both the outer `demo`'s local and `inner`'s freevar reference the **same** cell before `demo` returns. After `demo` returns, its frame is destroyed but the cell survives, kept alive by `fn.__closure__`.

### 7.2 Shared cells: multiple inner functions cooperating

```python
def pair():
    shared = 0
    def inc():
        nonlocal shared
        shared += 1
        return shared
    def get():
        return shared
    return inc, get

inc, get = pair()
print(inc.__closure__[0] is get.__closure__[0])  # True — same cell!
inc(); inc()
print(get())  # 2
```

Both functions close over the **same** `shared` cell object. That is how cooperating closures manage shared state without a class. The cell is the *rendezvous point*.

### 7.3 Memory: closures keep objects alive

A closure keeps its closed-over objects alive **as long as the closure itself is alive**:

```python
import weakref, sys

def holder():
    big = bytearray(10**6)  # 1 MB
    print(f"big refcount during holder: {sys.getrefcount(big)}")
    def inner():
        return len(big)
    return inner

fn = holder()
# holder's big is unreachable elsewhere except fn.__closure__
# So big survives until fn is garbage-collected:
print(fn())   # 1000000 — big still alive through cell

# To release, drop the reference:
del fn
# big becomes collectible now (if no other closure holds it)
```

**Beware accidental capture of large objects.** If a factory closes over a huge structure, the returned function holds it. Avoid:

```python
def make_filter(data):
    # Mistake — closing over entire dataset when only a threshold needed:
    threshold = sum(data) / len(data)
    # Don't close over data itself; just threshold:
    def is_above(x):
        return x > threshold  # closes over threshold (small), not data (big)
    return is_above  # data drops when make_filter returns, freed promptly
```

And closures closing over `self` in methods can keep entire objects alive even if you only need one attribute — capture the attribute explicitly if lifetime matters.

### 7.4 No `nonlocal` means read-only closure — still a cell

Even reading needs a cell if the enclosing call has ended:

```python
def read_only(n):
    def inner():
        return n   # no assignment -> no nonlocal needed, but still a closure
    return inner

print(read_only(5).__closure__[0].cell_contents)  # 5
```

So `nonlocal` signals *rebinding*; absence signals *immutable* closed-over state (implemented as cell too).

## 8. Common Mistakes & Edge Cases Consolidated

```python
# 1. UnboundLocalError from missing nonlocal
def broken_counter():
    n = 0
    def inc():
        n += 1   # local to inc -> UnboundLocalError without nonlocal
        return n
    return inc

# 2. Late binding loop/lambda — use i=i or factory
funcs = [lambda: i for i in range(3)]  # all 2
funcs = [lambda i=i: i for i in range(3)]  # fixed

# 3. global where nonlocal intended (silently goes to module)
val = "global"
def outer():
    val = "enclosed"
    def inner():
        global val
        val = "oops global mutated"  # not outer's val
    inner()
    print(val)  # still "enclosed"
outer()
print(val)  # oops global mutated

# 4. Leaked loop variable interferes with closure intention
x = "global leak"
for x in range(3):
    pass
def use_x():
    return x        # reads module global 'x' (now 2) — not "leak"
print(use_x())      # 2

# 5. Using comprehension hoping to avoid leak — still LEGB, but scoped iter var
# listcomp x is not the global x in Python 3, but closure inside still late-binds as above.
```

## 9. Quick Reference

| Concept | Rule |
|---|---|
| Resolution | **L → E → G → B** |
| Which scopes exist? | `def`/`lambda`/`class`/module/comp — not `if`/`for`/`try` |
| Assignment | Creates **local** unless `global`/`nonlocal` |
| `global x` | Redirect to module `x` (may create) |
| `nonlocal x` | Redirect to nearest enclosing `def`'s `x` (must exist) |
| Closure | Inner function that closes over enclosing var → cell in `__closure__` |
| Cell | Keeps object alive while inner lives; shared among co-closures |
| Late binding | `for i in ...: def f(): return i` → all read final `i`; fix with `i=i` or factory |
| Factory | `def factory(cfg): def inner(): return use(cfg); return inner` |
