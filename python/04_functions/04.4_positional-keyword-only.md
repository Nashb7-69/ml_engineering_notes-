# 04.4 Positional-Only and Keyword-Only Parameters

## Learning Objectives

- Master the three parameter kinds: positional-only (`/`), positional-or-keyword (flexible), and keyword-only (`*`).
- Read and write signatures with `/` and `*` / `*args`, including hybrids.
- Explain *why* these markers exist: API evolution, clarity, and safety.
- Recognize stdlib examples (`len(obj, /)`, `print(*objects, sep=...)`) and design your own APIs like them.
- Diagnose TypeError messages for argument-passing violations.

---

## 1. The Three Kinds of Parameters

Every parameter in Python belongs to exactly one of three **kinds**:

| Kind | How caller may pass it | Syntax marker |
|---|---|---|
| **Positional-only** | *Only* positionally (`f(1)`) | Before `/` |
| **Positional-or-keyword** (flexible) | Either `f(1)` or `f(x=1)` | Between `/` and `*` (or no markers) |
| **Keyword-only** | *Only* by keyword (`f(x=1)`) | After `*` or `*args` |

Historically Python had only the middle kind — every parameter could be passed either way. PEP 570 (Python 3.8) introduced an explicit syntax for **positional-only**, and PEP 3102 (Python 3.0) introduced **keyword-only**. Together they give full control.

The markers are `"/"` and `"*"` placed **in the parameter list**:

```python
def f(pos_only, /, standard, *, kw_only):
    print(pos_only, standard, kw_only)

# pos_only: positional-only    (before /)
# standard: positional-or-kw  (between / and *)
# kw_only:  keyword-only       (after *)
```

A visual map for every possible signature:

```
def func(posOnly1, posOnly2, /, flex1, flex2, flexWithDefault=0, *args, kwOnly1, kwOnly2=0, **kwargs):
#        |--- pos-only ---|  |--- flex (pos-or-kw) ---|  |*args|  |-- kw-only --| |**kwargs|
#                         /                           *                          (or bare *)
```

If a marker is absent, its segment is empty. So:

- `def g(a, b):` — both flexible (no markers → obvious legacy form).
- `def g(a, /, b):` — `a` pos-only, `b` flexible.
- `def g(a, *, b):` — `a` flexible, `b` kw-only (bare `*`).
- `def g(a, *args, b):` — `a` flexible, `*args` var-positional, `b` kw-only.

## 2. Positional-Only Parameters (`/`)

### 2.1 Syntax and meaning

`/`, when present, must appear **once** in the parameter list. Everything to its **left** is positional-only.

```python
def pow2(x, /):
    return x * x

print(pow2(5))        # 25 — positional, OK
# print(pow2(x=5))    # TypeError: got some positional-only arguments passed as keyword arguments: 'x'

def divide(a, b, /):
    return a / b

print(divide(10, 2))  # 5.0
# divide(a=10, b=2)   # TypeError: ... passed as keyword arguments
# divide(10, b=2)     # TypeError even for the second one — both are pos-only
```

Explanation: Writing `a, b, /` says "callers **must not** use the name `a` or `b` as a keyword." The name is still visible inside the function (`a` and `b` are ordinary local variables); the restriction is on the **call site**.

### 2.2 Before Python 3.8: builtins were implicity pos-only

Before `/` existed, many builtins written in C already had positional-only parameters — they simply lacked Python's keyword binding machinery. You could see it in `help()`:

```python
# Python 3.7 and earlier:
# help(len) -> len(obj, /)   (displayed with /, but / not writable in Python defs)
# help(divmod) -> divmod(x, y, /)

print(len([1, 2, 3]))    # 3
# len(obj=[1,2,3])       # TypeError even before 3.8
```

PEP 570 made the `/` syntax **expressible** in Python so stdlib maintainers and users could write the same kind of signature.

Explore in any modern Python:

```python
import inspect

print(inspect.signature(len))      # (obj, /)
print(inspect.signature(divmod))   # (x, y, /)
print(inspect.signature(pow))      # (x, y, z=None, /) — in some builds positional-only

# User-defined:
def mixed(a, b, /, c, d):
    pass

print(inspect.signature(mixed))    # (a, b, /, c, d)
print(list(inspect.signature(mixed).parameters.values()))
# a=pos-only, b=pos-only, c=pos-or-kw, d=pos-or-kw
```

### 2.3 Hybrid pos-only with flexible tail

```python
def greet(name, /, greeting="Hello", punctuation="!"):
    return f"{greeting}, {name}{punctuation}"

print(greet("Ada"))                              # Hello, Ada!
print(greet("Ada", "Hi"))                        # Hi, Ada!
print(greet("Ada", greeting="Hi"))               # Hi, Ada! — greeting is flexible
print(greet("Ada", punctuation="."))             # Hello, Ada.
# greet(name="Ada")                              # TypeError: pos-only
```

Here only `name` is pos-only; `greeting` and `punctuation` are flexible. This hybrid is extremely common: the **primary** operand is pos-only (its name is not a useful keyword), while **options** remain keyword-friendly.

Real stdlib example:

```python
# dict.get is roughly:
# def dict.get(self, key, default=None, /)  — in CPython, key is pos-only in some builds
d = {"a": 1}
print(d.get("a"))            # 1 — positional
# d.get(key="a")             # TypeError in builds where key is pos-only
print(d.get("missing", 0))   # 0
```

### 2.4 Why positional-only?

| Reason | Illustration |
|---|---|
| **Name freedom** — implementation may rename parameter without breaking callers who use it positionally | `def len(obj, /):` — callers never wrote `len(obj=my_list)`, so renaming `obj` → `o` is not a breaking change |
| **Clearer intent** — names like `a`, `b`, `x`, `y` carry no meaning as keywords | `pow(2, 10)` is natural; `pow(x=2, y=10)` adds noise |
| **Performance** — positional-only avoids keyword dict lookup (minor) | C builtins and hot paths |
| **Consistency with math operators** — `divmod(x, y)` mirrors `x // y, x % y` which has no "names" |  |
| **Avoiding collisions with `**kwargs`** | Wrapper can forward `**kwargs` without risking overlap with positional parameter names |

Example of the `**kwargs` collision avoidance:

```python
# Without pos-only:
def wrap(*args, **kwargs):
    pass

def legacy(a, **kwargs):  # 'a' is flexible — caller might pass a=1 via **kwargs indirectly?
    print(a, kwargs)

# If legacy's 'a' were pos-only, a caller unpacking **{"a": 1} would clearly conflict;
# pos-only makes intended API unambiguous.

def clean(name, /, **kwargs):
    """name must be positional — kwargs keys will never shadow it."""
    print(name, kwargs)

clean("Ada", role="admin")        # Ada {'role': 'admin'}
# clean(name="Ada", role="admin") # TypeError — prevented
# clean(**{"name": "Ada"})        # TypeError — same
```

## 3. Keyword-Only Parameters (`*` / `*args`)

### 3.1 Syntax: bare `*` and `*args`

Any parameter **after** a `*` marker or `*args` is keyword-only:

```python
# Bare * -> no var-positional capture, but introduces kw-only:
def configure(host, port, *, timeout=10, retries=3):
    return (host, port, timeout, retries)

print(configure("example.com", 80))                          # ('example.com', 80, 10, 3)
print(configure("example.com", 80, timeout=5))               # timeout=5
# configure("example.com", 80, 5)                            # TypeError: takes 2 positional args but 3 given
# configure("example.com", port=80, timeout=5)               # OK — port is flexible
# configure(host="a", port=80, timeout=5)                    # OK

# With *args -> surplus positional collected, rest is still kw-only:
def log(message, *args, level="INFO", sep=" "):
    parts = sep.join(str(a) for a in args)
    return f"[{level}] {message} {parts}"

print(log("start", 1, 2, level="DEBUG"))  # [DEBUG] start 1 2
# log("start", 1, 2, "DEBUG")             # TypeError: 'level' must be keyword
```

Explanation: `timeout`/`retries`/`level`/`sep` live **after** `*`. The parser enforces keyword passing. At the call site you *must* write `timeout=5`; the positional slot is disabled.

### 3.2 Distinguishing `*` vs `*args` vs bare

| Signature tail | Captures surplus pos args? | Introduces kw-only after it? | Example |
|---|---|---|---|
| `a, b` | No | No | `def f(a,b):` |
| `a, *args` | Yes (tuple) | Yes | `def f(a, *args, c):` — `c` kw-only |
| `a, *` | No (surplus → error) | Yes | `def f(a, *, c):` — `c` kw-only |
| `a, *args, b, **kw` | Yes | Yes | `def f(a, *args, b, **kw):` |

```python
def bare_demo(a, *, b, c=10):
    print(a, b, c)

# bare_demo(1, 2)      # TypeError: takes 1 positional arg but 2 given
bare_demo(1, b=2)      # 1 2 10 — required kw-only b, optional c
bare_demo(1, b=2, c=3) # 1 2 3

def var_demo(a, *args, b, c=10):
    print(f"a={a} args={args} b={b} c={c}")

var_demo(1, 2, 3, b=4)      # a=1 args=(2,3) b=4 c=10
var_demo(1, b=2)             # a=1 args=()   b=2 c=10
# var_demo(1, 2, b=3, 4)     # SyntaxError at call — positional after keyword
```

### 3.3 Why keyword-only?

| Reason | Illustration |
|---|---|
| **Readability** — boolean or numeric literals unclear positionally | `connect("host", 443, 5, 3)` — what are `5` and `3`? vs `connect(..., timeout=5, retries=3)` |
| **Extensibility** — adding new options does not disturb positional order | New kw-only param never shifts existing positional slots |
| **Safety** — reordering flexible params silently changes meaning if positional; kw-only calls are name-anchored | `draw(w=10, h=20)` order independent; `draw(10, 20)` order dependent |
| **Avoid positional ambiguity** | `sorted(iterable, /, *, key=None, reverse=False)` — clear separation |
| **API consistency with stdlib** | `print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)` — `sep` etc. kw-only |

Classic stdlib case:

```python
# print signature (Python 3):
# def print(*objects, sep=' ', end='\n', file=None, flush=False): ...
# sep, end, file, flush are keyword-only (after *objects)

print("a", "b", sep="-", end="!\n")  # a-b!
# print("a", "b", "-")  # would treat "-" as third object, not sep — wrong
```

## 4. Hybrid Signatures: Putting `/` and `*` Together

The most expressive signatures use both:

```python
def hybrid(a, b, /, c, d, *, e, f=0, **kwargs):
    """Full anatomy example."""
    print(f"a pos-only={a}, b pos-only={b}")
    print(f"c flex={c}, d flex={d}")
    print(f"e kw-only={e}, f kw-only={f}")
    print(f"kwargs={kwargs}")

# Valid calls:
hybrid(1, 2, 3, d=4, e=5)
# a=1 (pos-only), b=2 (pos-only), c=3 (pos), d=4 (kw), e=5 (kw-only)

hybrid(1, 2, c=3, d=4, e=5, f=6, extra=99)
# **kwargs captures extra

# Invalid calls:
# hybrid(a=1, b=2, c=3, d=4, e=5)  # TypeError pos-only a,b passed as keyword
# hybrid(1, 2, 3, 4, 5)            # TypeError missing kw-only e (5 treated as pos but e requires keyword)
```

Real-world hybrid mirroring stdlib `sorted`:

```python
def sorted_like(iterable, /, *, key=None, reverse=False):
    """Mimic sorted(): iterable pos-only, options kw-only."""
    result = list(iterable)
    if key is not None:
        result.sort(key=key, reverse=reverse)
    else:
        result.sort(reverse=reverse)
    return result

print(sorted_like([3, 1, 2]))                    # [1, 2, 3]
print(sorted_like([3, 1, 2], reverse=True))      # [3, 2, 1]
print(sorted_like(["bob", "alice"], key=len))    # ['bob', 'alice'] — key kw-only
# sorted_like(iterable=[1,2,3])                  # TypeError: pos-only
# sorted_like([1,2], True)                       # TypeError: reverse kw-only
```

Another realistic example — an HTTP helper:

```python
def fetch(url, /, *segments, params=None, headers=None, timeout=10, **options):
    """Demonstrate pos-only URL + var-positional segments + kw-only options.

    url: the base URL — positional-only because `fetch(url=...)` adds no clarity.
    *segments: optional path segments.
    params, headers, timeout: keyword-only options.
    **options: forwarded options like retries, cache.
    """
    path = "/".join([url.rstrip("/"), *(s.strip("/") for s in segments)])
    print(f"fetch {path} timeout={timeout} params={params} options={options}")

fetch("https://example.com", "api", "users", timeout=5, retries=3)
# fetch https://example.com/api/users timeout=5 params=None options={'retries': 3}

fetch("https://example.com", params={"q": "ada"}, timeout=2)
fetch("https://example.com", "v2", params={"page": 1})
# fetch("https://example.com", url="https://clone.com")  # TypeError — url pos-only
```

## 5. Parameter Kinds in `inspect`

For introspection, `inspect.Parameter.kind` has five values (the two "flexible" subkinds map to pos-or-kw):

```python
import inspect

def demo(a, b, /, c, d=0, *args, e, f=1, **kwargs):
    pass

for name, param in inspect.signature(demo).parameters.items():
    print(f"{name:6s} {param.kind!s:30s} default={param.default!r}")
```

Output:
```
a      POSITIONAL_ONLY                default=<class 'inspect._empty'>
b      POSITIONAL_ONLY                default=<class 'inspect._empty'>
c      POSITIONAL_OR_KEYWORD          default=<class 'inspect._empty'>
d      POSITIONAL_OR_KEYWORD          default=0
args   VAR_POSITIONAL                 default=<class 'inspect._empty'>
e      KEYWORD_ONLY                   default=<class 'inspect._empty'>
f      KEYWORD_ONLY                   default=1
kwargs VAR_KEYWORD                    default=<class 'inspect._empty'>
```

All five `Parameter` kinds:

| `Parameter.kind` | Meaning | Display |
|---|---|---|
| `POSITIONAL_ONLY` | Before `/` | `a, b, /` |
| `POSITIONAL_OR_KEYWORD` | Between `/` and `*` | `c, d` |
| `VAR_POSITIONAL` | `*args` | `*args` |
| `KEYWORD_ONLY` | After `*` / `*args` | `e, f` |
| `VAR_KEYWORD` | `**kwargs` | `**kwargs` |

## 6. API Design Guidance — When to Use Which

| Need | Choose |
|---|---|
| Core operands whose name is not meaningful to caller (`obj`, `x`, `key`, `url`) | **Positional-only** `x, /` |
| Tunable options, booleans, or values clearer with name (`timeout=`, `reverse=`) | **Keyword-only** `*, timeout` |
| Simple one-or-two-arg helper where both passing styles are fine | **Flexible** (no markers) — default legacy style |
| Public API you plan to evolve (add params, rename internals) | **Hybrid**: pos-only for stable core + kw-only for evolving options |
| Internal helper called only within your module | Flexible is usually fine; don't over-constrain |

Heuristics:

1. **If a parameter's name could change without callers noticing, make it positional-only.** Example: Rename `obj` → `object` in `len` — no caller used `len(obj=...)` so nothing breaks.
2. **If positional use would be unclear (`True`/`5` without context), make it keyword-only.** Example: `open(..., buffering=..., encoding=...)` — bare numbers meaningless.
3. **Be consistent with stdlib idioms.** If stdlib analogue is `sort(key=..., reverse=...)` kw-only, follow suit.
4. **Don't use `/` everywhere by default.** Python's ecosystem largely uses flexible params for historical reasons. Apply `/` and `*` where they *improve* the API, not mechanically.

Migration tip: You can *relax* a positional-only to flexible without breaking old callers (old positional calls still work, new keyword calls become possible). But you can **never** *restrict* a flexible param to pos-only or kw-only without breaking keyword callers. Start permissive; tighten only with a major version.

## 7. Call-Site Rules and Error Messages

Make sure you can predict — and remedy — these `TypeError`s:

```python
def api(a, b, /, c, *, d, e=0):
    pass

# 1. Pos-only passed by keyword
# api(a=1, b=2, c=3, d=4)  # TypeError: got some positional-only arguments passed as keyword arguments: 'a, b'

# 2. Keyword-only passed positionally
# api(1, 2, 3, 4)           # TypeError: missing a required argument: 'd'  (4 consumed as c's surplus? see next)

# Actually for api(1,2,3,4):
# a=1 pos-only OK, b=2 pos-only OK, c=3 flexible OK,
# 4 has no positional slot after c? No *args -> "takes 3 positional arguments but 4 were given"
api(1, 2, 3, d=4)           # OK

# 3. Required kw-only missing
# api(1, 2, c=3)            # TypeError: missing a required keyword-only argument: 'd'

# 4. Mixing positional after keyword at call site
# api(1, c=3, 2)            # SyntaxError: positional argument follows keyword argument

# 5. Duplicate value
# api(1, 2, 3, c=4, d=5)    # TypeError: multiple values for argument 'c'
```

Reading the message is half the diagnosis:
- `"positional-only arguments passed as keyword arguments"` → you used `name=` for a `/`-protected param.
- `"takes N positional arguments but M were given"` → too many positionals (likely tried to pass kw-only positionally, or extra args without `*args`).
- `"missing a required keyword-only argument"` → forgot `name=` for a `*`-protected param.

Unpacking respects kind (section 8):

```python
def pos_only_demo(x, /, y, *, z):
    print(x, y, z)

pos_only_demo(*[1, 2], **{"z": 3})  # 1 2 3 — OK, unpack honors kinds
# pos_only_demo(**{"x": 1, "y": 2, "z": 3})  # TypeError pos-only x via **
```

## 8. Positional-Only, Keyword-Only, and Unpacking Interactions

### 8.1 `*` / `**` unpacking at the call site vs definition

| Definition marker | Effect on caller's `*`/`**` |
|---|---|
| `/` | Parameter **cannot** be filled via `**` unpacking that names it; must come from positional channel. But `*[...]` expansion that lands positionally is allowed. |
| `*` / `*args` | Parameter **cannot** be filled via positional `*` expansion beyond its positional budget; must come via `keyword=` or `**{...}`. |

```python
def f(a, /, b, *, c):
    print(a, b, c)

# Positional expansion — OK for pos-only a:
args = [1, 2]
f(*args, c=3)              # 1 2 3 — a positionally via *, b positionally, c by keyword

# Keyword expansion — fails for pos-only a:
kw = {"a": 1, "b": 2, "c": 3}
# f(**kw)                  # TypeError: got some positional-only...

# Works for flexible / kw-only:
f(1, b=2, c=3)             # flexible b can be positional or kw
f(1, 2, c=3)               # also OK for flexible
f(1, b=2, **{"c": 3})      # kw-only c via **
```

### 8.2 Argument forwarding with heterogeneous wrappers

```python
import functools

def forwarder(func, /, *args, **kwargs):
    """Forward any call — func is pos-only so **kwargs never shadows it."""
    print(f"forwarding to {func.__name__}")
    return func(*args, **kwargs)

print(forwarder(len, [1, 2, 3]))     # 3
print(forwarder(pow, 2, 8))          # 256 — pow is positional-only itself

# Making func pos-only (func, /) prevents this ambiguity:
# forwarder(func=len, args=...)  # would be nonsense; pos-only prevents misuse

# Bare * inside forwarded signature: callee's kw-only demands are honored via **kwargs:
def target(x, *, key=None):
    return (x, key)

print(forwarder(target, "hello", key="upper"))  # ('hello', 'upper')
print(forwarder(target, "hello", **{"key": "yes"}))
```

Rule for wrapper authors: For maximal compatibility, use `def wrapper(*args, **kwargs):` and let the wrapped function's signature errors surface naturally. Add wrappers' own control params as **keyword-only** after `*args` to keep namespace clean (see lesson 04.3).

## 9. Quick Reference

```
def name(pos_only1, pos_only2, /, flex1, flex2=default, *args, kw_only, kw_with_default=val, **kwargs):
#        |---- pos-only ------|  |---- flex --------|  |*args| |---- kw-only -----|  |**kwargs|
#                             /                     *               (after * or *args)
```

| Marker | Meaning | Position in `def` |
|---|---|---|
| `/` | Left side pos-only | Exactly once, separates pos-only from flex |
| `*` (bare) | Introduces kw-only, no capture | Once, separates flex from kw-only |
| `*args` | Capture surplus positional + introduce kw-only | Once, separates flex from kw-only |
| `**kwargs` | Capture surplus keyword | Must be last |
| None | All flexible (legacy) | No explicit marker |

**Call rules:**

| Parameter kind | `f(1)` | `f(x=1)` | `f(*[1])` | `f(**{"x":1})` |
|---|---|---|---|---|
| Positional-only | OK | TypeError | OK (positional channel) | TypeError |
| Flexible | OK | OK | OK | OK |
| Keyword-only | TypeError | OK | TypeError | OK |
