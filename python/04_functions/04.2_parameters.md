# 04.2 Parameters

## Learning Objectives

- Master positional vs keyword arguments at the call site.
- Understand default parameter values: evaluation time, the mutable-default trap, and the `None`-sentinel idiom.
- Predict argument evaluation order and binding.
- Choose correctly between required, optional, and sentinel-based parameters in API design.
- Diagnose and avoid shared-state bugs from mutable defaults.

---

## 1. Terminology: Parameters vs Arguments

The terms are used interchangeably in casual speech, but Python's docs are precise:

| Term | Meaning | Where |
|---|---|---|
| **Parameter** | Variable listed in `def` | Definition time: `def f(a, b=0): ...` — `a` and `b` are parameters |
| **Argument** | Value supplied at call time | Call site: `f(10, b=5)` — `10` and `5` are arguments |

A **parameter** is the *name* inside the function; an **argument** is the *object* you pass in.

We also distinguish:

- **Positional argument** — matched by position: `f(10, 20)`
- **Keyword argument** — matched by name: `f(a=10, b=20)`
- **Default parameter value** — `b=0` in `def f(a, b=0)`

That last distinction powers everything in this lesson.

---

## 2. Basic Parameter Forms

```python
def greet(name):
    return f"Hello, {name}!"

print(greet("Ada"))        # positional argument
print(greet(name="Grace")) # keyword argument — same binding
```

Explanation: `name` is a **required positional-or-keyword** parameter (unless slash/star restrictions from lesson 04.4). At the call site you may pass it either way. Inside `greet`, `name` is just a local variable bound to whatever object you passed.

Add a default:

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Ada"))                    # Hello, Ada!  — greeting uses default
print(greet("Ada", "Hi"))              # Hi, Ada!     — positional override
print(greet("Ada", greeting="Hey"))    # Hey, Ada!    — keyword override
print(greet(greeting="Yo", name="Bob"))# Yo, Bob!     — order does not matter when keywords used
```

Rules:
1. Non-default parameters must come first: `def f(a, b=1):` is valid, `def f(a=1, b):` is `SyntaxError` (follows from positional matching — required params cannot follow optional ones).
2. Positional arguments must precede keyword arguments at call site: `greet("Ada", greeting="Hi")` OK, `greet(greeting="Hi", "Ada")` is `SyntaxError`.
3. Each parameter may be filled at most once: `greet("Ada", name="Bob")` raises `TypeError: multiple values for argument 'name'`.

## 3. Argument Evaluation: Before Binding

This section answers *when* arguments are evaluated.

### 3.1 Arguments are evaluated left-to-right *before* the function body runs

```python
def log(value):
    print(f"inside log, value={value}")
    return value * 2

def produce(n):
    print(f"produce({n})")
    return n

print("calling log(produce(3))")
result = log(produce(3))
print(f"result={result}")
```

Output:
```
calling log(produce(3))
produce(3)
inside log, value=3
result=6
```

Explanation: At call site, `produce(3)` is evaluated first (left to right), producing `3`, *then* `log` is entered with `value=3`. By the time the body starts, all arguments are objects already.

Why it matters:

```python
counter = 0
def inc():
    global counter
    counter += 1
    return counter

def show(a, b):
    print(f"a={a}, b={b}")

show(inc(), inc())
print(f"counter={counter}")  # 2 — inc() called twice, left to right
```

Each argument expression (`inc()`) executes once, in order, before `show`'s body runs. If `inc()` had side effects or raised, that happens at evaluation time, not inside `show`.

### 3.2 Evaluation includes keyword arguments too

```python
def show2(a, b):
    print(f"inside show2 a={a} b={b}")

show2(b=inc(), a=inc())
# inc() for b runs first? Let's test:
counter = 0
show2(b=inc(), a=inc())
# inc() for b (first in source? Actually Python evaluates left-to-right
# in call order, but keyword argument expressions are evaluated
# left-to-right as written)
```

From CPython semantics: **all argument expressions at a call site are evaluated left to right as they appear**, regardless of positional vs keyword. After all are evaluated, they are **bound** to parameters. So `show2(b=inc(), a=inc())` calls `inc()` for `b` first (it appears first), then `inc()` for `a`. The binding to `a`/`b` inside the function uses the parameter names to place them correctly, not source order.

Verify:

```python
def demo(a, b):
    print(f"a={a} b={b}")

counter = 0
demo(b=inc(), a=inc())
# prints: a=2 b=1  (b's inc() produced 1, a's produced 2)
print(f"counter={counter}")  # 2

counter = 0
demo(inc(), inc())  # positional left-to-right, as written
# a=1 b=2
```

Inside `demo`, `a` and `b` are local names. The left-to-right evaluation of *call-site expressions* is separate from *parameter placement*.

## 4. Default Values: Evaluation Time and the Mutable Trap

### 4.1 The rule: defaults are evaluated **once** at `def` time

```python
def add(item, target=[]):
    target.append(item)
    return target

print(add(1))  # [1]
print(add(2))  # [1, 2]  — surprise!
print(add(3))  # [1, 2, 3]
```

Explanation: The expression `[]` is executed **once**, when the `def` statement runs. The resulting list object is stored in `add.__defaults__`:

```python
print(add.__defaults__)  # ([1, 2, 3],)
```

Every call that omits `target` reuses **the same list object**. Appending mutates the shared object.

This is not a bug in Python — it is a deliberate, documented semantics. Defaults are **part of the function object**, not recomputed per call. It is the single most reported "gotcha" for newcomers.

Introspection confirms:

```python
def sample(a, b=10, c=[]):
    pass

print(sample.__defaults__)  # (10, [])
```

`__defaults__` is a tuple aligned to trailing parameters that have defaults. Only the last N params have entries here (parameters without defaults have no slot).

When defaults include computed expressions, they too run once:

```python
import time

def timestamped(msg, ts=time.time()):
    return f"[{ts}] {msg}"

print(timestamped("hello"))
time.sleep(0.5)
print(timestamped("hello again"))
# Both timestamps are identical! ts frozen at import/def time.
```

### 4.2 Mutable-default pitfall catalog

Any **mutable** object as a default is dangerous if mutated inside:

| Mutable default | Why dangerous | Symptom |
|---|---|---|
| `[]` or `list()` | Appended/extended | Items accumulate across calls |
| `{}` or `dict()` | Keys added | Entries leak between calls |
| `set()` | Items added | Same |
| Custom mutable object | State modified | Stale/shared state |

Immutable defaults are safe because you cannot mutate them in place (you only rebind the local name):

```python
def next_id(current=0):
    current += 1   # rebinding local; does NOT mutate the default object (int is immutable)
    return current

print(next_id())  # 1
print(next_id())  # 1 — not 2, because current was rebound, not mutated
```

Strings, ints, floats, tuples (without mutable contents), `None`, `frozenset`, are safe.

### 4.3 The `None`-sentinel idiom (the fix)

The Pythonic fix: default to `None`, create a fresh mutable inside:

```python
def add(item, target=None):
    if target is None:
        target = []         # new list per call
    target.append(item)
    return target

print(add(1))            # [1]
print(add(2))            # [1]  — independent!
print(add(3, [10, 20]))  # [10, 20, 3]  — caller's list, respected
```

Why `is None` not `== None`? `is` tests identity (the `None` singleton), not equality. And `if not target:` would misfire for empty lists passed intentionally.

This idiom generalizes:

```python
def connect(host, port, options=None):
    if options is None:
        options = {}
    options.setdefault("timeout", 10)
    # ...

def record_visit(user_id, visited=None):
    """Return set with user_id added."""
    if visited is None:
        visited = set()
    visited.add(user_id)
    return visited
```

Checklist for defaults:

1. **Is the default mutable?** If yes, use `None` sentinel + fresh creation.
2. **Is the default an expression with side effects (`time.time()`, `random.random()`, `datetime.now()`)?** Use `None` sentinel and evaluate inside.

```python
import datetime

# Wrong — frozen timestamp
def log(msg, when=datetime.datetime.now()):
    print(f"[{when}] {msg}")

# Right — fresh timestamp per call
def log(msg, when=None):
    if when is None:
        when = datetime.datetime.now()
    print(f"[{when}] {msg}")
```

### 4.4 When you *want* a mutable default (intentional cached state)

Rarely, the single-evaluation is a feature — cheap memoization:

```python
def fibonacci(n, _cache={0: 0, 1: 1}):
    """_cache is intentionally shared across calls."""
    if n not in _cache:
        _cache[n] = fibonacci(n - 1) + fibonacci(n - 2)
    return _cache[n]

print(fibonacci(10))  # 55
print(fibonacci._cache if hasattr(fibonacci, "_cache") else fibonacci.__defaults__)
```

Explanation: `_cache` is a single dict attached to the function object. Each call mutates it, so later calls benefit from earlier computation. The leading underscore `_cache` signals "private, do not pass manually."

> **Recommendation:** Do **not** rely on mutable defaults for caching in new code — use `functools.cache` / `functools.lru_cache` (Python 3.8+ / 3.9+ `functools.cache`). Mutable-default caching obscures intent and surprises readers.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

This is explicit, introspectable (`fibonacci.cache_info()`), and clearable.

### 4.5 The shared-state object identity proof

Demonstrate the sharing explicitly:

```python
def append_one(lst=[]):
    lst.append(1)
    return lst

a = append_one()
b = append_one()
print(a is b)        # True — same object!
print(a)             # [1, 1]
print(append_one.__defaults__[0] is a)  # True

# Fixed version
def append_one_fixed(lst=None):
    if lst is None:
        lst = []
    lst.append(1)
    return lst

c = append_one_fixed()
d = append_one_fixed()
print(c is d)        # False — different objects
print(c, d)          # [1] [1]
```

## 5. Defaults and `__defaults__` / `__kwdefaults__`

```python
def example(a, b, c=10, d=20, *, e=30, f=40):
    pass

print(example.__defaults__)    # (10, 20)  — for c, d
print(example.__kwdefaults__)  # {'e': 30, 'f': 40} — for keyword-only params
```

- `__defaults__` holds defaults for **positional-or-keyword** trailing params.
- `__kwdefaults__` holds defaults for **keyword-only** params (see lessons 04.3/04.4).

Mutating `__defaults__` is technically possible but strongly discouraged:

```python
def foo(x=1):
    return x

foo.__defaults__ = (99,)
print(foo())  # 99 — you've monkey-patched the default at runtime
```

In production code, treat these as introspection, not configuration API.

## 6. When to Use Defaults vs Required Parameters

| Situation | Design |
|---|---|
| Parameter always needed, no sensible default | Required: `def connect(host, port):` |
| Common value covers 80% of calls | Default: `def connect(host, port, timeout=10):` |
| Per-call fresh collection needed | Sentinel: `def add(item, buf=None): buf = [] if buf is None else buf` |
| Caller must be explicit for safety | Keyword-only or no default: `def divide(a, b):` (require both) |
| Overriding `None` may be valid input | Use custom sentinel object |

### 6.1 When `None` itself is valid input

Sometimes `None` is a legitimate argument (e.g., "clear the field"). Then `None` is ambiguous as a "no argument given" sentinel. Use a private sentinel object:

```python
_MISSING = object()   # unique singleton

def update(name, value=_MISSING):
    if value is _MISSING:
        print(f"no value supplied for {name} — leaving unchanged")
    elif value is None:
        print(f"clearing {name}")
    else:
        print(f"setting {name} = {value}")

update("email")              # no value supplied...
update("email", None)        # clearing email
update("email", "a@b.com")   # setting email = a@b.com
```

Because `_MISSING = object()` creates a fresh unique identity, no caller can accidentally pass it. This pattern appears throughout the standard library (`dataclasses.MISSING`, `inspect.Parameter.empty`).

## 7. Putting It All Together: Realistic Example

```python
import datetime
from typing import Optional

def create_user(
    username: str,
    email: str,
    roles=None,
    created_at=None,
):
    """Create a user dict with safe defaults.

    Args:
        username: Unique handle, required.
        email: Contact email, required.
        roles: Iterable of role names. Defaults to ['viewer'] without sharing.
        created_at: Timestamp. Defaults to now.
    """
    if roles is None:
        roles = ["viewer"]          # new list each call
    else:
        roles = list(roles)         # defensive copy — don't share caller's list

    if created_at is None:
        created_at = datetime.datetime.now(datetime.timezone.utc)

    # Early guard — required params validated up front
    if not username or not email:
        raise ValueError("username and email are required")

    return {
        "username": username,
        "email": email.strip().lower(),
        "roles": roles,
        "created_at": created_at,
    }

# All of these behave independently:
u1 = create_user("ada", "Ada@Example.COM")
u2 = create_user("bob", "bob@example.com")
u1["roles"].append("editor")
print(u1["roles"])  # ['viewer', 'editor']
print(u2["roles"])  # ['viewer'] — not polluted

u3 = create_user("carol", "c@x.com", roles=["admin"])
print(u3["roles"])  # ['admin']
# Mutating the original list after call does not affect u3:
orig = ["admin"]
u4 = create_user("dave", "d@x.com", roles=orig)
orig.append("viewer")
print(u4["roles"])  # ['admin'] — defensive copy protected it
```

Explanation:
- `username`, `email` are required (no default) — callers must supply them.
- `roles=None` + fresh `["viewer"]` avoids shared state; `list(roles)` avoids aliasing caller's list.
- `created_at=None` + `datetime.now()` inside ensures a fresh timestamp per call.
- Guard `if not username...` raises immediately on bad input (early return with exception).

## 8. Common Mistakes Revisited

```python
# 1. Mutable default — silent cross-call pollution
def collect(value, out=[]):
    out.append(value)
    return out

# 2. Using `== None` or `if not x` for None checks — use `is None`
def maybe(items=None):
    if items == None:   # works but wrong idiom; overloadable via __eq__
        items = []
    if not items:       # misfires — empty list passed intentionally looks falsy!
        items = []

# Better:
def maybe(items=None):
    if items is None:
        items = []

# 3. Assuming defaults recompute — time, random, datetime trap
import random
def choice(items, rng=random.random):  # rng is the function itself once; or rng=random.random() is frozen
    ...

# 4. Ordering defaults before non-defaults — SyntaxError
# def bad(a=1, b):  # SyntaxError: non-default argument follows default argument

# 5. Supplying same argument twice — TypeError
def two(a, b): pass
# two(1, a=2)  # TypeError: multiple values for argument 'a'
```

## 9. Quick Reference

| Concept | Rule |
|---|---|
| `def f(a, b=1):` | `a` required, `b` optional (default `1`) |
| Default evaluation | Once, at `def` time; stored in `f.__defaults__` |
| Mutable default | **Always** use `None` sentinel + fresh creation inside |
| `is None` | Idiomatic None test (not `==`) |
| Sentinel object | `_MISSING = object()` when `None` is valid input |
| Argument evaluation | Left-to-right at call site, before body executes |
| Positional before keyword | `f(1, b=2)` OK, `f(b=2, 1)` SyntaxError |
