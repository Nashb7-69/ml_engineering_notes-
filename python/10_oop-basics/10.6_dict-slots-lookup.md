# 10.6 `__dict__`, `__slots__`, and Attribute Lookup

> **Mental model:** Every attribute access `obj.x` triggers a well-defined search through a chain of namespace dicts. The order is: data descriptors on the class, then the instance dict, then non-data descriptors and plain class attributes, then `__getattr__` fallback. `__dict__` is the dict that holds instance (or class) attributes. `__slots__` replaces the per-instance `__dict__` with fixed, array-like storage for speed and memory savings — but at the cost of flexibility and with sharp inheritance rules. Understanding this lookup is the key to mastering descriptors, properties, methods, and every "magic" attribute behavior in Python.

---

## 1. `__dict__` — The Namespace Dict

### 1.1 Instance `__dict__`

Every ordinary instance carries a `__dict__` — a plain `dict` that stores its per-instance attributes:

```python
class Dog:
    species = "Canis familiaris"   # class attribute — lives on Dog.__dict__

    def __init__(self, name, age):
        self.name = name           # instance attribute — lives on instance.__dict__
        self.age = age

buddy = Dog("Buddy", 3)
print(buddy.__dict__)    # {'name': 'Buddy', 'age': 3}
print(vars(buddy))       # {'name': 'Buddy', 'age': 3} — vars() returns __dict__

# Assignment is dict insertion:
buddy.breed = "Labrador"
print(buddy.__dict__)    # {'name': 'Buddy', 'age': 3, 'breed': 'Labrador'}
# Equivalent to:
buddy.__dict__["color"] = "brown"
print(buddy.color)       # brown — found via __dict__

# Deletion is dict removal:
del buddy.age
print(buddy.__dict__)    # {'name': 'Buddy', 'breed': 'Labrador', 'color': 'brown'}
# print(buddy.age)       # AttributeError — no longer in instance dict or class

# Mutation is dict mutation:
buddy.__dict__.update({"tricks": ["sit", "stay"]})
print(buddy.tricks)      # ['sit', 'stay']

# vars() without args returns the current scope's locals — same mechanism:
def func():
    x = 10
    print(vars())   # {'x': 10} — local namespace is also a dict (in functions, an optimization applies)
```

**Explanation:** `self.name = value` is syntactic sugar for `self.__dict__["name"] = value` — unless a data descriptor (like a `property` with a setter) intercepts the assignment. The instance `__dict__` is a regular Python `dict`: ordered (insertion order since 3.7), resizable, and fully mutable. Each instance has its own independent dict.

```python
buddy = Dog("Buddy", 3)
rex   = Dog("Rex", 5)
print(buddy.__dict__ is rex.__dict__)  # False — separate dicts
buddy.__dict__["extra"] = "buddy only"
print(rex.__dict__)   # {'name': 'Rex', 'age': 5} — unaffected
```

### 1.2 Class `__dict__` — A `mappingproxy`

A class's `__dict__` is **not** a plain `dict` — it is a `mappingproxy`, a read-only view:

```python
class Dog:
    species = "Canis familiaris"
    def bark(self): return "woof"

print(type(Dog.__dict__))           # <class 'mappingproxy'>
print(isinstance(Dog.__dict__, dict))  # False
print(Dog.__dict__["species"])       # Canis familiaris — mappingproxy supports mapping protocol
print(list(Dog.__dict__.keys())[:5])  # ['__module__', 'species', 'bark', '__dict__', ...]

# Direct mutation is blocked:
# Dog.__dict__["species"] = "Felis catus"  # TypeError: 'mappingproxy' object does not support item assignment
# del Dog.__dict__["species"]              # TypeError

# Correct way — assign/delete via the class:
Dog.species = "Felis catus"         # works — goes through type.__setattr__
print(Dog.species)                  # Felis catus
del Dog.species
# print(Dog.species)                # AttributeError — removed
Dog.species = "Canis familiaris"    # restore

# Bypassing the proxy (don't do this — shown only for understanding):
type.__setattr__(Dog, "species", "Canis lupus")  # same as Dog.species = ...
# Or via the underlying dict (CPython internal):
# Dog.__dict__ is a proxy wrapping Dog's internal dict — accessible as vars(Dog) in some contexts
print(vars(Dog) is Dog.__dict__)    # True — vars(Dog) returns the same mappingproxy
```

**Why `mappingproxy`?** It prevents accidental mutation of the class dict through the proxy and ensures that class attribute assignment goes through `type.__setattr__`, which handles descriptors, `__slots__`, and metaclass hooks correctly. If `Dog.__dict__` were a plain `dict`, `Dog.__dict__["x"] = val` would bypass descriptor `__set__` — a subtle bug.

### 1.3 `vars()` vs `__dict__` vs `dir()`

| Expression | Returns | Scope |
|------------|---------|-------|
| `obj.__dict__` | Instance dict (plain `dict`) or class `mappingproxy` | Direct dict access |
| `vars(obj)` | Same as `obj.__dict__` (or raises `TypeError` if no `__dict__`) | Builtin accessor — identical to `__dict__` |
| `vars()` (no arg) | Local namespace `dict` of current scope | Equivalent to `locals()` |
| `dir(obj)` | Sorted list of all reachable attribute names (instance dict + class MRO + descriptors) | Full attribute discovery — walks the entire lookup chain |
| `dir()` (no arg) | Names in current local scope | Equivalent to `list(locals().keys())` |

```python
class Animal:
    kingdom = "Animalia"
    def speak(self): return "..."

class Dog(Animal):
    species = "Canis familiaris"
    def __init__(self, name):
        self.name = name
    def bark(self): return "woof"

buddy = Dog("Buddy")
buddy.trick = "sit"

print(vars(buddy))
# {'name': 'Buddy', 'trick': 'sit'} — instance dict ONLY

print(vars(Dog))
# mappingproxy({'__module__': ..., 'species': ..., '__init__': ..., 'bark': ..., ...})

print([x for x in dir(buddy) if not x.startswith("_")])
# ['bark', 'kingdom', 'name', 'speak', 'species', 'trick'] — everything reachable
# dir walks: buddy.__dict__ + Dog.__dict__ + Animal.__dict__ + object.__dict__

# has lab but __dict__ doesn't:
print("species" in dir(buddy))            # True — found via class
print("species" in buddy.__dict__)         # False — not in instance dict
print("species" in Dog.__dict__)           # True — in class dict
```

```python
# dir() also respects __dir__ customization:
class Custom:
    def __dir__(self):
        return ["custom_a", "custom_b"]

print(dir(Custom()))  # ['custom_a', 'custom_b'] — overridden
```

## 2. The Complete Attribute Lookup Order

This is the single most important section in this lesson — and arguably in all of Python's OOP model. Every `obj.x` follows these steps:

### 2.1 Lookup Order for `obj.x` (Getting)

```
1. Data descriptor on type(obj) or its ancestors (MRO)
      → if found and has __get__ and __set__/__delete__, call __get__
      → this is how @property (with setter) and slots win over instance dict

2. Instance dict: obj.__dict__["x"]
      → if "x" in obj.__dict__, return it — instance attribute shadows non-data descriptors

3. Non-data descriptor OR plain class attribute on type(obj) / MRO
      → if it has __get__ (but no __set__), call __get__(obj, type(obj))
         (this is how methods bind: function.__get__ returns a bound method)
      → else return the plain value

4. __getattr__ fallback
      → if type(obj).__getattr__ is defined, call type(obj).__getattr__(obj, "x")
      → this is your last chance to provide a dynamic attribute

5. Raise AttributeError
```

**Crucially, `__getattribute__` wraps ALL of the above.** If a class defines `__getattribute__`, it is called first and must explicitly invoke the default lookup (via `super().__getattribute__`) or implement its own. `__getattr__` is only called when `__getattribute__` raises `AttributeError`.

### 2.2 Visualizing Each Step

```python
# Step 1 — Data descriptor wins over instance dict:
class DataDescriptor:
    def __get__(self, instance, owner):
        if instance is None: return self
        return "from data descriptor"
    def __set__(self, instance, value):
        print(f"data descriptor __set__({value})")

class MyClass:
    x = DataDescriptor()   # data descriptor (has __get__ + __set__)

obj = MyClass()
obj.__dict__["x"] = "from instance dict"
print(obj.x)          # "from data descriptor" — descriptor wins!
print(obj.__dict__["x"])  # "from instance dict" — still there, but hidden
obj.x = 999           # data descriptor __set__(999) — not dict insertion
print(obj.__dict__["x"])  # "from instance dict" — dict NOT modified

# Step 2 — Instance dict wins over non-data descriptor:
class NonDataDescriptor:
    def __get__(self, instance, owner):
        if instance is None: return self
        return "from non-data descriptor"
    # no __set__ — so it's a non-data descriptor

class MyClass2:
    x = NonDataDescriptor()  # non-data descriptor (only __get__)

obj2 = MyClass2()
print(obj2.x)          # "from non-data descriptor" — no instance entry, so descriptor runs
obj2.__dict__["x"] = "from instance dict"
print(obj2.x)          # "from instance dict" — instance dict wins over non-data descriptor!
print(obj2.__dict__["x"])  # "from instance dict"
del obj2.__dict__["x"]
print(obj2.x)          # "from non-data descriptor" — falls through again

# Step 3a — Non-data descriptor binding (methods):
class MyClass3:
    def method(self): return f"method of {self}"

obj3 = MyClass3()
print(obj3.method)     # <bound method MyClass3.method of <MyClass3>> — function.__get__ bound self
print(type(obj3.method))  # <class 'method'>
# function is a non-data descriptor (has __get__, no __set__), so instance dict check comes first.
# But functions are rarely shadowed by instance dict — unless you do obj3.method = lambda: ...

# Step 3b — Plain class attribute:
class MyClass4:
    x = 42

obj4 = MyClass4()
print(obj4.x)          # 42 — found on class (step 3, plain value, no descriptor)
obj4.x = 100           # creates obj4.__dict__["x"] = 100 — shadows class
print(obj4.x)          # 100 — now step 2 (instance dict) wins
print(MyClass4.x)      # 42 — class unchanged
del obj4.x             # removes instance shadow
print(obj4.x)          # 42 — falls through to class again

# Step 4 — __getattr__ fallback:
class MyClass5:
    def __getattr__(self, name):
        return f"dynamic {name}"

obj5 = MyClass5()
print(obj5.anything)     # "dynamic anything" — __getattr__ provides it
print(obj5.existing)     # "dynamic existing" — same
obj5.existing = "real"   # creates instance dict entry
print(obj5.existing)     # "real" — instance dict (step 2) wins, __getattr__ not called
del obj5.existing
print(obj5.existing)     # "dynamic existing" — __getattr__ again
```

### 2.3 Lookup Order for `obj.x = value` (Setting)

```
1. Data descriptor on type(obj) / MRO with __set__
      → call descriptor.__set__(obj, value) — instance dict NOT touched

2. Otherwise: obj.__dict__["x"] = value
      → plain instance dict insertion (may shadow a non-data descriptor or class attr)
```

```python
# Data descriptor intercepts setting:
class Validated:
    def __get__(self, instance, owner):
        if instance is None: return self
        return instance.__dict__.get("_validated", 0)
    def __set__(self, instance, value):
        if value < 0: raise ValueError("negative")
        instance.__dict__["_validated"] = value

class MyClass:
    x = Validated()

obj = MyClass()
obj.x = 10            # → Validated.__set__(obj, 10) → stores in _validated
print(obj.x)          # 10 — Validated.__get__
# obj.x = -5          # ValueError
print(obj.__dict__)   # {'_validated': 10} — note: "x" is NOT in __dict__, "_validated" is

# Non-data descriptor does NOT intercept setting:
class Plain:
    x = NonDataDescriptor()  # only __get__

obj2 = Plain()
obj2.x = 999           # no __set__, so goes to obj2.__dict__["x"] = 999
print(obj2.__dict__)   # {'x': 999} — shadows the descriptor!
print(obj2.x)          # 999 — instance dict wins
# To get the descriptor back:
del obj2.x
print(obj2.x)          # "from non-data descriptor"
```

### 2.4 `__getattribute__` vs `__getattr__` — The Two Hooks

```python
class GetAttributeDemo:
    def __getattribute__(self, name):
        print(f"  __getattribute__({name!r})")
        # Must use super().__getattribute__ to do normal lookup — or infinite recursion!
        return super().__getattribute__(name)

    def __getattr__(self, name):
        print(f"  __getattr__({name!r})")
        return f"fallback for {name!r}"

obj = GetAttributeDemo()
obj.existing = "hello"

print("--- access existing ---")
print(obj.existing)
# __getattribute__('existing') → finds in instance dict → returns "hello"
# __getattr__ NOT called — only called on failure

print("--- access missing ---")
print(obj.missing)
# __getattribute__('missing') → walks chain, finds nothing → raises AttributeError
# Python catches that and calls __getattr__('missing') → returns "fallback for 'missing'"

# WARNING: __getattribute__ is called for EVERY attribute access, including methods and dunders.
# A buggy __getattribute__ easily causes infinite recursion:

class Broken:
    def __getattribute__(self, name):
        # return self.__dict__[name]  # BUG — self.__dict__ triggers __getattribute__("__dict__") → recursion!
        return object.__getattribute__(self, name)  # correct — bypass recursion

class AlsoCorrect:
    def __getattribute__(self, name):
        return super().__getattribute__(name)  # correct — super() bypasses this __getattribute__
```

| Hook | When called | Typical use |
|------|-------------|-------------|
| `__getattribute__(self, name)` | **Every** `obj.name` access, unconditionally first | Intercept or log all access; proxy objects; lazy loading |
| `__getattr__(self, name)` | Only when normal lookup (including `__getattribute__`) raises `AttributeError` | Dynamic / virtual attributes; delegation; computed fallbacks |

**Never confuse them:** `__getattr__` is the safe, surgical fallback. `__getattribute__` is the powerful but dangerous total interceptor.

## 3. Descriptors — The Mechanism Behind Properties, Methods, and Slots

### 3.1 What Is a Descriptor?

Any object that implements at least one of `__get__`, `__set__`, or `__delete__` and is stored in a **class dict** (not an instance dict) is a descriptor. Python checks for these methods during attribute lookup on the class/MRO.

```python
# Data descriptor: has __get__ AND __set__ (and/or __delete__)
class DataDesc:
    def __get__(self, instance, owner): ...
    def __set__(self, instance, value): ...

# Non-data descriptor: has only __get__
class NonDataDesc:
    def __get__(self, instance, owner): ...

# Classification matters because it determines lookup priority
# (data > instance dict > non-data, as shown above).
```

### 3.2 How Each Python Feature Maps to Descriptors

| Feature | Descriptor type | `__get__` | `__set__` | Lookup priority |
|---------|----------------|-----------|-----------|-----------------|
| `property` (with setter) | Data descriptor | Yes | Yes | Wins over instance `__dict__` |
| `property` (read-only, no setter) | Technically data descriptor in CPython* | Yes | Raises `AttributeError` | Still wins over `__dict__` (CPython treats it as data) |
| `function` (instance method) | Non-data descriptor | Yes (binds `self`) | No | Instance `__dict__` can shadow it |
| `classmethod` | Non-data descriptor | Yes (binds `cls`) | No | Instance `__dict__` can shadow (but rarely does) |
| `staticmethod` | Non-data descriptor | Yes (returns raw function) | No | Instance `__dict__` can shadow |
| `__slots__` member | Data descriptor | Yes | Yes | Wins over instance `__dict__` (but there is no `__dict__`) |

*CPython's `property` always counts as a data descriptor even without a setter, because it implements `__set__` that raises `AttributeError`. Some alternative Python implementations historically treated read-only properties as non-data, but CPython's behavior is the standard.

### 3.3 `__get__` Signature Deep Dive

```python
def __get__(self, instance, owner):
    """
    instance: the object being accessed (e.g., buddy in buddy.name)
              None if accessed via class (e.g., Dog.name)
    owner:    the class where the descriptor lives (e.g., Dog)
    """

class Verbose:
    def __get__(self, instance, owner):
        print(f"__get__(instance={instance}, owner={owner})")
        if instance is None:
            return self  # class access → return descriptor itself (common convention)
        return 42

class MyClass:
    x = Verbose()

print("--- via class ---")
print(MyClass.x)          # __get__(instance=None, owner=MyClass) → returns Verbose object
print(type(MyClass.x))    # Verbose

print("--- via instance ---")
print(MyClass().x)        # __get__(instance=<MyClass object>, owner=MyClass) → 42
```

## 4. `__slots__` — Trading Flexibility for Speed and Memory

### 4.1 The Problem `__slots__` Solves

Every ordinary instance carries a `__dict__` (a hash table) plus overhead for the dict object itself. For classes with millions of instances, this is expensive:

```python
import sys

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(sys.getsizeof(p.__dict__))  # ~100+ bytes for the dict alone (CPython, varies)
print(sys.getsizeof(p))           # instance overhead + pointer to dict

# For 1_000_000 points: ~72 MB just for dicts (approximate, CPython 3.11, 64-bit)
# With __slots__: ~32 MB — roughly half (exact numbers depend on CPython version)
```

`__slots__` replaces the per-instance `__dict__` with a fixed-size array (like a C struct), saving memory and speeding up attribute access.

### 4.2 Basic `__slots__` Usage

```python
class Point:
    __slots__ = ("x", "y")    # declare the ONLY allowed instance attributes

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
print(p.x, p.y)        # 3 4 — attribute access looks normal
p.x = 10               # assignment works — writes to the slot
print(p.x)             # 10

# What's different:
print(hasattr(p, "__dict__"))  # False — no instance dict!
# print(p.__dict__)            # AttributeError: 'Point' object has no attribute '__dict__'
# vars(p)                      # TypeError: vars() argument must have __dict__ attribute
# p.z = 99                     # AttributeError: 'Point' object has no attribute 'z' — only x,y allowed
# p.__dict__["x"] = 5          # AttributeError — no dict to manipulate

# But the class still has its dict/mappingproxy:
print(Point.__dict__.keys())   # includes 'x', 'y' as member descriptors, plus '__slots__'
print(type(Point.__dict__["x"]))  # <class 'member_descriptor'> — the slot descriptor
```

**Explanation:** `__slots__ = ("x", "y")` tells Python: "instances of this class will have exactly two attributes, `x` and `y`, stored as fixed offsets in a C array — not in a dict." For each name in `__slots__`, Python creates a `member_descriptor` (a data descriptor) in the class dict. That descriptor's `__get__`/`__set__` reads/writes the corresponding array slot.

### 4.3 Memory and Performance

```python
import sys
import timeit

class DictPoint:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class SlotPoint:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x = x
        self.y = y

# Memory:
# DictPoint instance: ~56 bytes (object) + ~100+ bytes (dict) + overhead per entry
# SlotPoint instance: ~56 bytes including slots — no separate dict allocation

# Quick benchmark (CPython 3.11, results vary):
# Attribute read:
#   DictPoint:  ~45 ns
#   SlotPoint:  ~30 ns  — faster (array offset vs hash lookup)
# Attribute write:
#   DictPoint:  ~55 ns
#   SlotPoint:  ~35 ns  — faster

# For 1M instances:
dict_points = [DictPoint(i, i) for i in range(100_000)]
slot_points = [SlotPoint(i, i) for i in range(100_000)]
# slot_points uses measurably less RSS — try: psutil or tracemalloc to measure

import tracemalloc
tracemalloc.start()
before = tracemalloc.get_traced_memory()[0]
pts = [SlotPoint(i, i) for i in range(100_000)]
after_slots = tracemalloc.get_traced_memory()[0]
pts = None  # free

pts2 = [DictPoint(i, i) for i in range(100_000)]
after_dict = tracemalloc.get_traced_memory()[0]
print(f"Slots overhead: ~{(after_slots - before) / 100_000:.0f} bytes/instance")
print(f"Dict overhead:  ~{(after_dict - after_slots) / 100_000:.0f} bytes/instance")
# Typical: slots ~40-56 bytes/instance, dict ~150-200 bytes/instance
```

### 4.4 `__slots__` Restrictions

```python
class Slotted:
    __slots__ = ("x", "y")

s = Slotted()
s.x = 1
s.y = 2

# 1. No __dict__ by default — no dynamic attributes:
# s.z = 3          # AttributeError
# s.__dict__       # AttributeError

# 2. No default values — slots start uninitialized:
class Slotted2:
    __slots__ = ("x",)

s2 = Slotted2()
# print(s2.x)      # AttributeError: 'Slotted2' object has no attribute 'x' — not yet assigned!
s2.x = 10
print(s2.x)        # 10 — now assigned

# Provide defaults via __init__ or descriptors:
class Slotted3:
    __slots__ = ("x",)
    def __init__(self, x=0):
        self.x = x  # default via __init__

# 3. Can't use vars() or __dict__-based introspection:
# vars(s)          # TypeError
# Use getattr/setattr/hasattr instead, or inspect __slots__:
print(Slotted.__slots__)              # ('x', 'y')
print([getattr(s, name) for name in Slotted.__slots__])  # [1, 2]

# 4. dir() still works (walks class descriptors):
print([n for n in dir(s) if not n.startswith("_")])  # ['x', 'y']

# 5. Pickling works, but requires care with __getstate__/__setstate__
#    for slots that hold unpicklable values.
import pickle
pickled = pickle.dumps(s)
print(pickle.loads(pickled).x)  # 1 — pickle handles slots
```

### 4.5 `__slots__` with `__dict__` — Getting Both

If you need slots for performance but also want dynamic attributes on some instances:

```python
class Hybrid:
    __slots__ = ("x", "y", "__dict__")  # include "__dict__" as a slot name

    def __init__(self, x, y):
        self.x = x
        self.y = y

h = Hybrid(1, 2)
print(h.x, h.y)       # 1 2 — slots still work
print(h.__dict__)     # {} — dict exists now!
h.z = 99              # dynamic attribute — goes to __dict__
print(h.z)            # 99
print(h.__dict__)     # {'z': 99} — only dynamic attrs in dict, slots still in array
print(Hybrid.__dict__["x"])  # <member_descriptor> — slot
print(Hybrid.__dict__["__dict__"])  # <getset_descriptor> — the dict slot

# Similarly, "__weakref__" can be added to allow weak references:
import weakref

class NoWeakRef:
    __slots__ = ("x",)

# weakref.ref(NoWeakRef())  # TypeError: cannot create weak reference — no __weakref__ slot

class WithWeakRef:
    __slots__ = ("x", "__weakref__")

r = weakref.ref(WithWeakRef())  # works
```

| `__slots__` declaration | Instance has `__dict__` | Supports weak refs | Supports dynamic attrs |
|-------------------------|------------------------|--------------------|-----------------------|
| `__slots__ = ("x",)` | No | No (unless `__weakref__` added) | No |
| `__slots__ = ("x", "__dict__")` | Yes | No | Yes (via `__dict__`) |
| `__slots__ = ("x", "__weakref__")` | No | Yes | No |
| `__slots__ = ("x", "__dict__", "__weakref__")` | Yes | Yes | Yes |
| No `__slots__` (normal class) | Yes | Yes | Yes |

### 4.6 `__slots__` and Inheritance — The Sharp Edges

This is where `__slots__` gets tricky:

```python
# Rule 1: Child without __slots__ gets a __dict__ (and __weakref__) automatically,
#         even if parent has __slots__.
class Parent:
    __slots__ = ("x",)

class ChildNoSlots(Parent):
    pass  # no __slots__ → gets __dict__ + __weakref__

c = ChildNoSlots()
c.x = 1              # slot from Parent
c.y = 2              # dynamic — goes to ChildNoSlots's __dict__!
print(c.__dict__)    # {'y': 2}
print(c.x)           # 1 — slot still works

# Rule 2: Child WITH __slots__ must redeclare — slots are NOT inherited additively
#         in the naive sense. The child's __slots__ adds to the parent's.
class Parent2:
    __slots__ = ("x",)

class ChildWithSlots(Parent2):
    __slots__ = ("y",)   # adds y — instances have BOTH x (from Parent2) and y

c2 = ChildWithSlots()
c2.x = 1
c2.y = 2
print(c2.x, c2.y)    # 1 2
# c2.z = 3           # AttributeError — no __dict__, only x and y

# But if you accidentally redeclare a parent slot, it's an error in some cases
# and wasted space in others — don't do it.

# Rule 3: Multiple inheritance with slots — all parents' slots are included,
#         but diamond issues arise:
class A:
    __slots__ = ("a",)
class B:
    __slots__ = ("b",)
class C(A, B):
    __slots__ = ("c",)   # instances have a, b, c

c3 = C()
c3.a = 1; c3.b = 2; c3.c = 3
print(c3.a, c3.b, c3.c)  # 1 2 3

# Rule 4: If a parent has __dict__, children effectively have __dict__ too
#         (the dict lives on the parent's layout, but child instances share it).
class DictParent:
    pass  # has __dict__

class SlotChild(DictParent):
    __slots__ = ("x",)

sc = SlotChild()
sc.x = 1          # slot
sc.y = 2          # __dict__ from DictParent — works!
print(sc.__dict__)  # {'y': 2}

# Rule 5: __slots__ must be a tuple/list of strings. An empty tuple means "no slots, no dict".
class NoAttrs:
    __slots__ = ()  # no instance attributes at all!

n = NoAttrs()
# n.x = 1  # AttributeError — no slots, no dict, nothing can be stored
# But class attributes still work:
NoAttrs.class_attr = 42
print(NoAttrs.class_attr)  # 42
```

**Inheritance summary table:**

| Parent | Child `__slots__` | Child instance has |
|--------|-------------------|---------------------|
| `__slots__ = ("x",)` | *(none)* | `x` (slot) + `__dict__` + `__weakref__` |
| `__slots__ = ("x",)` | `("y",)` | `x` + `y` (both slots), no `__dict__` |
| `__slots__ = ("x",)` | `("__dict__",)` | `x` (slot) + `__dict__` |
| *(no slots)* | `("x",)` | `x` (slot) + `__dict__` (from parent layout) |
| `("x",)` and `("y",)` (multiple inheritance) | `("z",)` | `x` + `y` + `z` |

### 4.7 When to Use `__slots__`

**Use `__slots__` when:**

- You will create **millions of instances** and memory matters (data pipelines, game entities, ORM rows).
- You want **faster attribute access** in a tight loop (micro-optimization — measure first).
- You want to **prevent accidental dynamic attributes** — `__slots__` without `__dict__` makes typos raise `AttributeError` instead of silently creating a new attribute:
  ```python
  class Point:
      __slots__ = ("x", "y")
      def __init__(self, x, y): self.x = x; self.y = y

  p = Point(1, 2)
  # p.z = 3  # AttributeError — catches typo immediately
  # With __dict__, p.z = 3 would silently create a new attribute — a bug that hides.
  ```

**Do NOT use `__slots__` when:**

- You have a small number of instances — the memory saving is negligible and the restrictions hurt.
- You need **dynamic attributes** (e.g., setting arbitrary keys from a JSON payload).
- You use **multiple inheritance heavily** — slot layout conflicts are confusing.
- You need **weak references** and forgot `__weakref__`.
- You want to use **class assignment to set defaults that are per-instance mutable** — slots have no `__dict__` to shadow into.
- You are writing a **base class for unknown subclasses** — subclasses that don't know about your slots will behave surprisingly (they get a `__dict__`, but the interaction is subtle).
- You rely on **`__dict__`-based introspection, serialization, or `vars()`** — many libraries (e.g., `dataclasses`, `json`, ORMs) assume `__dict__` exists.

**Modern alternative — `dataclasses` with `slots=True` (Python 3.10+):**

```python
from dataclasses import dataclass

@dataclass(slots=True)
class Point:
    x: float
    y: float

p = Point(1, 2)
print(p.x)          # 1
# p.z = 3           # AttributeError — slots enforced
# p.__dict__        # AttributeError — no dict

# dataclass generates __init__, __repr__, __eq__, and __slots__ automatically.
# This is the cleanest way to get slots when your class is primarily data.
```

## 5. Putting It All Together — Introspection Tools

### 5.1 Seeing the Full Picture

```python
class Animal:
    kingdom = "Animalia"
    def speak(self): return "..."

class Dog(Animal):
    __slots__ = ("name", "age", "__dict__")  # slots + dict for demo
    species = "Canis familiaris"

    def __init__(self, name, age):
        self.name = name
        self.age = age

    @property
    def human_age(self):
        return self.age * 7

    def bark(self): return "woof"

buddy = Dog("Buddy", 3)
buddy.trick = "sit"   # dynamic — goes to __dict__ because we included __dict__ in slots

# ── Instance dict ──
print(buddy.__dict__)              # {'trick': 'sit'} — only dynamic attrs (slots not in dict)
print(vars(buddy))                 # same

# ── Class dict (mappingproxy) ──
print(list(k for k in vars(Dog) if not k.startswith("_")))
# ['species', 'human_age', 'bark', ...] plus 'name', 'age' as member_descriptors

# ── Slot descriptors ──
print(type(Dog.__dict__["name"]))  # <class 'member_descriptor'>
print(type(Dog.__dict__["species"]))  # <class 'str'> — plain class attr, not a descriptor

# ── Property ──
print(type(Dog.__dict__["human_age"]))  # <class 'property'>

# ── dir() — everything reachable ──
print([x for x in dir(buddy) if not x.startswith("_")])
# ['age', 'bark', 'human_age', 'kingdom', 'name', 'speak', 'species', 'trick']

# ── MRO — the class search chain ──
print(Dog.__mro__)
# (<class 'Dog'>, <class 'Animal'>, <class 'object'>)

# ── Which class owns what ──
for cls in Dog.__mro__:
    print(f"{cls.__name__}.__dict__ keys: {[k for k in cls.__dict__ if not k.startswith('_')]}")
# Dog.__dict__ keys: ['species', 'human_age', 'bark', 'name', 'age']
# Animal.__dict__ keys: ['kingdom', 'speak']
# object.__dict__ keys: [...many dunders...]

# ── getattr vs direct dict access ──
print(getattr(buddy, "species"))           # Canis familiaris — walks MRO
print(buddy.__dict__.get("species"))       # None — not in instance dict
print(Dog.__dict__.get("species"))         # Canis familiaris — in Dog's dict

# ── has slots? ──
print(hasattr(Dog, "__slots__"))           # True
print(Dog.__slots__)                       # ('name', 'age', '__dict__')

# ── Check if instance has dict ──
print(hasattr(buddy, "__dict__"))          # True (because we included __dict__ in slots)
# For a pure-slotted class without __dict__:
class Pure:
    __slots__ = ("x",)
print(hasattr(Pure(), "__dict__"))         # False

# ── Memory ──
import sys
print(sys.getsizeof(buddy))               # smaller than a pure-dict instance, but has dict overhead too (hybrid)
print(sys.getsizeof(Pure()))              # minimal — no dict
```

### 5.2 A Complete Lookup Trace

```python
class VerboseDescriptor:
    def __init__(self, name):
        self.name = name
    def __get__(self, instance, owner):
        print(f"  [{self.name}.__get__(instance={instance is not None}, owner={owner.__name__})]")
        if instance is None:
            return self
        return f"<{self.name} value>"
    def __set__(self, instance, value):
        print(f"  [{self.name}.__set__({value!r})]")

class DataDesc(VerboseDescriptor):
    def __set__(self, instance, value):
        super().__set__(instance, value)
        instance.__dict__[f"_{self.name}"] = value
    def __get__(self, instance, owner):
        super().__get__(instance, owner)
        if instance is None:
            return self
        return instance.__dict__.get(f"_{self.name}", f"<{self.name} default>")

class NonDataDesc(VerboseDescriptor):
    pass  # only __get__, no __set__

class Demo:
    data = DataDesc("data")
    non_data = NonDataDesc("non_data")
    plain = "plain value"

    def __getattr__(self, name):
        print(f"  [__getattr__({name!r})]")
        return f"<getattr:{name}>"

obj = Demo()

print("── data descriptor (no instance entry) ──")
print(f"result: {obj.data}")
# [data.__get__(instance=True, owner=Demo)] → returns default or stored

print("\n── set data descriptor ──")
obj.data = "hello"
# [data.__set__('hello')] → stores in _data

print(f"\n── data descriptor (with instance backing) ──")
print(f"result: {obj.data}")
# [data.__get__] → returns "hello" — descriptor wins even though _data is in dict

print("\n── non-data descriptor (no instance entry) ──")
print(f"result: {obj.non_data}")
# [non_data.__get__] → returns "<non_data value>"

print("\n── shadow non-data descriptor ──")
obj.__dict__["non_data"] = "shadowed!"
print(f"result: {obj.non_data}")
# No descriptor call — instance dict wins over non-data descriptor
print(f"  (direct dict: {obj.__dict__['non_data']!r})")
del obj.__dict__["non_data"]
print(f"after del: {obj.non_data}")
# [non_data.__get__] → descriptor again

print("\n── plain class attribute ──")
print(f"result: {obj.plain}")   # "plain value" — step 3, plain value

print("\n── shadow plain attribute ──")
obj.plain = "shadowed plain"
print(f"result: {obj.plain}")   # "shadowed plain" — instance dict wins
del obj.plain
print(f"after del: {obj.plain}")  # "plain value" — falls through again

print("\n── missing → __getattr__ ──")
print(f"result: {obj.missing}")
# [__getattr__('missing')] → "<getattr:missing>"

print("\n── instance dict direct ──")
obj.__dict__["injected"] = "injected value"
print(f"result: {obj.injected}")  # "injected value" — step 2, instance dict
```

**Output annotated with which step fired:**

```
── data descriptor (no instance entry) ──
  [data.__get__(instance=True, owner=Demo)]
result: <data default>

── set data descriptor ──
  [data.__set__('hello')]

── data descriptor (with instance backing) ──
  [data.__get__(instance=True, owner=Demo)]
result: hello

── non-data descriptor (no instance entry) ──
  [non_data.__get__(instance=True, owner=Demo)]
result: <non_data value>

── shadow non-data descriptor ──
result: shadowed!                          ← step 2 wins, no descriptor call

── plain class attribute ──
result: plain value                        ← step 3 plain value

── missing → __getattr__ ──
  [__getattr__('missing')]
result: <getattr:missing>                  ← step 4 fallback
```

## 6. `dir()` vs `__dict__` vs `vars()` — When to Use Each

| Tool | What it shows | Use when |
|------|---------------|----------|
| `obj.__dict__` | Instance's own attributes only (or `mappingproxy` for classes) | You need the exact storage — e.g., to check if an attribute is per-instance vs inherited |
| `vars(obj)` | Same as `obj.__dict__` but raises `TypeError` if no `__dict__` | Idiomatic accessor for `__dict__`; handles the `__slots__` case with an error |
| `dir(obj)` | All reachable names: `__dict__` + class MRO + descriptors + `__dir__` customization | You want to discover what you *can* access — e.g., in a REPL, debugger, or `hasattr` check |
| `getattr(obj, name)` | Walks the full lookup chain, including descriptors and `__getattr__` | Dynamic attribute access by string name |
| `hasattr(obj, name)` | `True` if `getattr` would succeed (catches `AttributeError`) | Safe existence check |
| `type(obj).__mro__` | The class search order | You need to know which ancestor provides an attribute |
| `inspect.getattr_static(obj, name)` | Gets the attribute *without* invoking descriptors | You need the raw descriptor object, not its bound result |

```python
import inspect

class Demo:
    @property
    def x(self): return 42

obj = Demo()
print(getattr(obj, "x"))                    # 42 — invokes property.__get__
print(inspect.getattr_static(obj, "x"))     # <property object> — raw descriptor, no invocation
print(obj.__dict__)                         # {} — property not in instance dict
print(Demo.__dict__["x"])                   # <property object> — raw descriptor via class dict
print("x" in dir(obj))                      # True — dir finds it via class
print("x" in obj.__dict__)                  # False — not in instance dict
print(hasattr(obj, "x"))                    # True — getattr would succeed
```

## 7. Edge Cases and Gotchas

### 7.1 `__dict__` Is Shared Across Instances? No — But the Class Dict Is Shared

```python
class Foo:
    x = 10

a = Foo()
b = Foo()
print(a.__dict__ is b.__dict__)  # False — each instance has its own dict
print(type(a).__dict__ is type(b).__dict__)  # True — same class, same mappingproxy
print(Foo.__dict__ is type(a).__dict__)      # True — all point to the same class dict proxy
```

### 7.2 Assigning to `__dict__` Itself

```python
class Foo:
    pass

f = Foo()
f.__dict__ = {"x": 1, "y": 2}   # replace the entire instance dict!
print(f.x, f.y)                  # 1 2 — new dict is now the instance namespace
print(f.__dict__)                # {'x': 1, 'y': 2}

# For classes, __dict__ is read-only — you cannot replace it:
# Foo.__dict__ = {}  # AttributeError: attribute '__dict__' of 'type' objects is not writable
```

### 7.3 `__slots__` and `__dict__` Assignment

```python
class Slotted:
    __slots__ = ("x",)

s = Slotted()
# s.__dict__ = {}  # AttributeError — no __dict__ slot, so no dict to replace
s.x = 10

class Hybrid:
    __slots__ = ("x", "__dict__")

h = Hybrid()
h.__dict__ = {"extra": 1}  # works — Hybrid has __dict__ in slots
print(h.extra)              # 1
```

### 7.4 Class `__dict__` Mutation via `vars()` Proxy

```python
class Foo:
    x = 1

# vars(Foo) IS Foo.__dict__ — the mappingproxy:
print(vars(Foo) is Foo.__dict__)  # True

# Mutating the proxy is blocked, but you can mutate via setattr:
Foo.y = 2
print(Foo.y)                # 2 — added to class dict via type.__setattr__
print("y" in Foo.__dict__)  # True — now in the proxy

# The proxy reflects live changes:
Foo.z = 3
print("z" in vars(Foo))     # True — proxy is a live view, not a snapshot
```

### 7.5 Slots and Default Values — Use Descriptors or `__init__`

```python
# Slots have no per-instance defaults in the declaration — you must assign in __init__:
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x=0, y=0):
        self.x = x
        self.y = y

# Alternative — descriptor with default:
class DefaultSlot:
    def __init__(self, default=None):
        self.default = default
        self.name = None
    def __set_name__(self, owner, name):
        self.name = f"_{name}_slot_default_{id(self)}"
    def __get__(self, instance, owner):
        if instance is None:
            return self
        return getattr(instance, self.name, self.default)
    def __set__(self, instance, value):
        setattr(instance, self.name, value)

# But this is complex — just use __init__ for defaults.
```

## 8. Decision Guide — `__dict__` vs `__slots__` vs `dataclass(slots=True)`

```
Do you need millions of instances or is memory profiling showing pressure?
├── YES → Consider __slots__ or @dataclass(slots=True)
│         ├── Is the class simple data (fields + generated __init__/__repr__)?
│         │   └── YES → @dataclass(slots=True)  — cleanest, least error-prone
│         └── Is the class behavioral (methods, inheritance, descriptors)?
│             └── Use __slots__ manually — but handle inheritance carefully
│
└── NO → Use normal classes (with __dict__)
         ├── Need to prevent typos / accidental attributes?
         │   └── Consider __slots__ for strictness (without __dict__)
         │       — but weigh against lost flexibility
         └── Default — normal class is simplest and most compatible
```

## 9. Summary

- **Instance `__dict__`** — a plain `dict` per instance holding per-object attributes. `self.x = val` writes to it (unless a data descriptor intercepts). Each instance has its own dict.
- **Class `__dict__`** — a `mappingproxy` (read-only view) wrapping the class's namespace. Mutate via `ClassName.attr = val` or `setattr`, not via the proxy. `vars(ClassName)` returns the same proxy.
- **`dir(obj)`** walks the entire lookup chain (instance dict + class MRO + descriptors) and returns all reachable names. `vars(obj)` / `obj.__dict__` shows only the instance's own storage.
- **Attribute lookup order for `obj.x`:** (1) data descriptors on the class/MRO → (2) instance `__dict__` → (3) non-data descriptors / plain class attributes on the MRO → (4) `__getattr__` fallback → (5) `AttributeError`. `__getattribute__` wraps all of this.
- **Assignment `obj.x = val`:** (1) data descriptor `__set__` if present, else (2) `obj.__dict__["x"] = val`.
- **Descriptors** are objects with `__get__`/`__set__`/`__delete__` stored in a class dict. Data descriptors (`__set__` present) win over instance dict; non-data descriptors (`__get__` only) lose to instance dict. This single rule explains `property` vs methods vs slots.
- **`__slots__ = ("x", "y")`** replaces per-instance `__dict__` with a fixed array + `member_descriptor` data descriptors. Saves memory (~50-70% per instance), speeds access, prevents dynamic attributes, but adds restrictions: no `__dict__`/`vars()`, no weak refs (without `__weakref__`), no dynamic attrs, uninitialized slots raise `AttributeError`, and inheritance requires careful `__slots__` declarations in every child.
- **Hybrid `__slots__ = ("x", "__dict__")`** gives both fixed slots and a dict for dynamic attributes. Useful when you want slot performance for known fields but still need extensibility.
- **`@dataclass(slots=True)`** (Python 3.10+) is the modern, low-boilerplate way to get slotted data classes.

*This concludes Module 10 — OOP Basics. You now understand that classes are live objects, instances carry their own dicts, methods bind via descriptors, naming conventions encode intent, properties intercept access without breaking APIs, and the full lookup chain — including `__slots__` — is a single, consistent protocol.*
