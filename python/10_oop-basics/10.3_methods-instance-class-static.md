# 10.3 Methods — Instance, Class, and Static

> **Mental model:** In Python there is only one underlying callable type — the function. What you call a "method" is just a function that lives in a class dict and gets *bound* to an object when accessed. *How* it binds depends on the descriptor wrapping it: plain functions bind the instance (`self`), `classmethod` binds the class (`cls`), and `staticmethod` does not bind at all. Choosing the wrong kind is not a style nit — it determines what state you can access and how inheritance behaves.

---

## 1. The Descriptor Foundation (Brief Preview)

Every method type is a **descriptor** — an object with a `__get__` method that controls what happens on attribute access. You will see the full mechanics in 10.6; here is the minimum needed:

```python
# Pseudocode for what happens on `obj.attr`:
# 1. Find `attr` in type(obj).__dict__ (or its MRO).
# 2. If the object has __get__, call attr.__get__(obj, type(obj)).
# 3. That __get__ returns whatever "bound" thing you actually get.

# - function.__get__(instance, owner)  → bound method (curries instance)
# - classmethod.__get__(instance, owner) → bound method (curries owner/class)
# - staticmethod.__get__(instance, owner) → raw function (no currying)
```

Understanding this explains why `self` and `cls` appear "magically" — they are arguments curried by `__get__`.

## 2. Instance Methods — The Default

### 2.1 Definition and Binding

```python
class Counter:
    def __init__(self, start=0):
        self.value = start

    def increment(self, amount=1):
        """An instance method — operates on one object's state."""
        self.value += amount
        return self.value

    def reset(self):
        self.value = 0

c = Counter(10)
print(c.increment(5))   # 15
print(c.value)          # 15

# What Python actually does:
print(Counter.__dict__["increment"])
# <function Counter.increment at 0x...>

print(Counter.increment)
# <function Counter.increment at 0x...> — via class → raw function (unbound in Py3)

print(c.increment)
# <bound method Counter.increment of <Counter object>> — via instance → bound method

print(c.increment.__self__)   # <Counter object> — the instance it's bound to
print(c.increment.__func__)   # <function Counter.increment at 0x...> — the underlying function

# Manual equivalent — no magic:
print(Counter.increment(c, 5))  # 20 — explicitly passing self, same as c.increment(5)

import types
print(isinstance(c.increment, types.MethodType))   # True — bound method
print(isinstance(Counter.increment, types.FunctionType))  # True — plain function via class
```

**Explanation:** When you define `def increment(self, amount=1)` inside a class, you are just storing a `function` object in `Counter.__dict__["increment"]`. Functions implement `__get__`, so `c.increment` triggers `Counter.__dict__["increment"].__get__(c, Counter)` which wraps the function and `c` into a `method` object. Calling that method inserts `c` as the first argument automatically. Accessing via the class (`Counter.increment`) passes `None` as the instance to `__get__`, so it returns the raw function unwrapped — you must supply the instance yourself.

### 2.2 `self` Is Always Explicit

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def move(self, dx, dy):       # self is required — no implicit this
        self.x += dx
        self.y += dy

    def distance_from(self, other):
        return ((self.x - other.x)**2 + (self.y - other.y)**2) ** 0.5

p = Point(0, 0)
q = Point(3, 4)
p.move(1, 1)
print(p.distance_from(q))  # distance between p(1,1) and q(3,4)

# Forgetting self:
class Broken:
    def greet():                # no self
        return "hello"

b = Broken()
# b.greet()  # TypeError: greet() takes 0 positional arguments but 1 was given
# Python tried to pass `b` as the first arg, but greet accepts none.

# Python 3 lets you call via class without binding, so the error surfaces only on instance calls:
print(Broken.greet())  # works when called on class? No — Broken.greet is a function taking 0 args
# Actually: Broken.greet() → TypeError only if you pass an arg; Broken.greet() with 0 args works!
# But Broken.greet(b) would also work. The point: instance access auto-passes self regardless.
```

### 2.3 What Instance Methods Can Access

| Access | How | Example |
|--------|-----|---------|
| Instance state | `self.attr` | `self.value`, `self.name` |
| Class state | `self.__class__.attr` or `type(self).attr` or `ClassName.attr` | `type(self).default` |
| Other instances | Via parameters | `self.distance_from(other)` |
| Globals / module state | Normal scope | `import math` at top |

Instance methods are the workhorse — they read and mutate per-instance `__dict__` and can reach class state when needed. If your method needs instance state, it must be an instance method.

### 2.4 Realistic Example — Instance Methods Everywhere

```python
from __future__ import annotations
import math

class Vector:
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    # Instance methods — all operate on self's coordinates:
    def magnitude(self) -> float:
        return math.hypot(self.x, self.y)

    def normalized(self) -> Vector:
        mag = self.magnitude()
        if mag == 0:
            raise ValueError("cannot normalize zero vector")
        return Vector(self.x / mag, self.y / mag)

    def dot(self, other: Vector) -> float:
        return self.x * other.x + self.y * other.y

    def scaled(self, factor: float) -> Vector:
        return Vector(self.x * factor, self.y * factor)

    def __repr__(self) -> str:
        return f"Vector({self.x}, {self.y})"

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Vector):
            return NotImplemented
        return self.x == other.x and self.y == other.y

v = Vector(3, 4)
print(v.magnitude())          # 5.0
print(v.normalized())         # Vector(0.6, 0.8)
print(v.dot(Vector(1, 0)))   # 3.0
```

## 3. Class Methods — Bound to the Class

### 3.1 Definition and Binding

```python
class Counter:
    count = 0

    def __init__(self, name):
        self.name = name
        type(self).count += 1

    @classmethod
    def total(cls):
        """A class method — receives the CLASS, not an instance."""
        return cls.count

    @classmethod
    def reset_count(cls):
        cls.count = 0

print(Counter.total())    # 0 — called on class, cls is Counter
c1 = Counter("a")
c2 = Counter("b")
print(Counter.total())    # 2
print(c1.total())         # 2 — called on instance, cls is STILL Counter (type(c1))
print(c1.total() is Counter.total())  # conceptually same, but bound to same class

# What Python stores:
print(Counter.__dict__["total"])
# <classmethod(<function Counter.total at 0x...>)>

# How binding differs:
print(Counter.total)       # <bound method Counter.total of <class 'Counter'>>
print(c1.total)            # <bound method Counter.total of <class 'Counter'>>
# Both are bound to Counter, not to c1!
print(Counter.total.__self__)  # <class 'Counter'>
print(c1.total.__self__)       # <class 'Counter'> — same!
print(Counter.total.__func__)  # <function Counter.total at 0x...>

# For subclasses, cls is the SUBCLASS:
class SubCounter(Counter):
    pass

print(SubCounter.total.__self__)  # <class 'SubCounter'> — not Counter!
SubCounter("c")
print(SubCounter.total())  # 3 (inherited counter via MRO, but cls is SubCounter)
```

**Explanation:** `@classmethod` wraps the function in a `classmethod` descriptor object. Its `__get__(instance, owner)` ignores the instance entirely and binds `owner` (the class) as the first argument. Whether you call `Counter.total()` or `c1.total()`, the `cls` parameter receives `Counter` (or the actual subclass if called through a subclass). This is what makes classmethods polymorphic with respect to inheritance — unlike hard-coding `Counter.count` inside the method.

### 3.2 What Class Methods Can Access

| Access | How | Example |
|--------|-----|---------|
| Class state | `cls.attr` | `cls.count`, `cls.registry` |
| Instance state | **Cannot** — no `self` | Must not access `self` |
| Create instances | `cls(...)` | `return cls(x, y)` — respects subclass |

Class methods cannot access any single instance's state — they do not have `self`. They operate on state shared across the class and are the correct place for anything that concerns the class as a whole.

### 3.3 The Killer Feature — Alternative Constructors

This is the primary reason classmethods exist. Instance methods create or modify *one* object; classmethods create *new* objects, and they do so polymorphically:

```python
from __future__ import annotations
import json
from datetime import date

class Employee:
    def __init__(self, name: str, salary: float, hire_date: date) -> None:
        self.name = name
        self.salary = salary
        self.hire_date = hire_date

    # Standard constructor: Employee("Alice", 90000, date(2020, 1, 15))

    @classmethod
    def from_string(cls, data: str) -> Employee:
        """Alternative constructor: 'Alice,90000,2020-01-15'"""
        name, salary, date_str = data.split(",")
        return cls(name.strip(), float(salary), date.fromisoformat(date_str.strip()))

    @classmethod
    def from_dict(cls, data: dict) -> Employee:
        """Alternative constructor from a dict."""
        return cls(
            data["name"],
            float(data["salary"]),
            date.fromisoformat(data["hire_date"]),
        )

    @classmethod
    def from_json(cls, json_str: str) -> Employee:
        """Alternative constructor from JSON."""
        return cls.from_dict(json.loads(json_str))

    @classmethod
    def with_default_date(cls, name: str, salary: float) -> Employee:
        """Convenience constructor using today's date."""
        return cls(name, salary, date.today())

    def __repr__(self) -> str:
        return f"Employee({self.name!r}, {self.salary}, {self.hire_date})"

# All construction paths:
e1 = Employee("Alice", 90000, date(2020, 1, 15))
e2 = Employee.from_string("Bob, 75000, 2019-06-01")
e3 = Employee.from_dict({"name": "Carol", "salary": "82000", "hire_date": "2021-03-10"})
e4 = Employee.from_json('{"name": "Dave", "salary": 60000, "hire_date": "2022-11-20"}')
e5 = Employee.with_default_date("Eve", 70000)

print(e2)  # Employee('Bob', 75000.0, 2019-06-01)
```

**Why `cls(...)` instead of `Employee(...)` inside the classmethod?** Inheritance:

```python
class Manager(Employee):
    def __init__(self, name, salary, hire_date, team_size=0):
        super().__init__(name, salary, hire_date)
        self.team_size = team_size

    def __repr__(self):
        return f"Manager({self.name!r}, team_size={self.team_size})"

# Because from_string uses cls(...), it constructs the RIGHT class:
m = Manager.from_string("Frank, 120000, 2018-04-10")
print(type(m))  # <class 'Manager'> — not Employee!
print(m)        # Manager('Frank', team_size=0)

# If from_string had used Employee(...) instead of cls(...):
#   m would be an Employee, slicing off Manager behavior — a bug.
```

**Table — `cls(...)` vs `ClassName(...)` inside a classmethod:**

| Call | When invoked via `Manager.from_string(...)` | Result type |
|------|---------------------------------------------|-------------|
| `cls(...)` | `cls` is `Manager` | `Manager` instance — correct, polymorphic |
| `Employee(...)` | Hard-coded | `Employee` instance — wrong for subclass callers |

### 3.4 More Realistic Classmethod Examples

```python
from __future__ import annotations
import re

class IPAddress:
    """An IPv4 address with validation."""

    def __init__(self, octets: tuple[int, int, int, int]) -> None:
        if any(not 0 <= o <= 255 for o in octets):
            raise ValueError(f"octet out of range: {octets}")
        self.octets = octets

    @classmethod
    def from_string(cls, s: str) -> IPAddress:
        parts = s.split(".")
        if len(parts) != 4:
            raise ValueError(f"expected 4 octets, got {s!r}")
        try:
            octets = tuple(int(p) for p in parts)
        except ValueError:
            raise ValueError(f"non-numeric octet in {s!r}")
        return cls(octets)  # type: ignore[arg-type]

    @classmethod
    def localhost(cls) -> IPAddress:
        return cls((127, 0, 0, 1))

    @classmethod
    def from_int(cls, n: int) -> IPAddress:
        if not 0 <= n <= 0xFFFFFFFF:
            raise ValueError(f"out of range: {n}")
        return cls((
            (n >> 24) & 0xFF,
            (n >> 16) & 0xFF,
            (n >> 8) & 0xFF,
            n & 0xFF,
        ))

    def __str__(self) -> str:
        return ".".join(str(o) for o in self.octets)

    def __repr__(self) -> str:
        return f"IPAddress({str(self)!r})"

print(IPAddress.from_string("192.168.1.1"))  # IPAddress('192.168.1.1')
print(IPAddress.localhost())                 # IPAddress('127.0.0.1')
print(IPAddress.from_int(0xC0A80101))        # IPAddress('192.168.1.1')
```

```python
# Factory / registry pattern with classmethods:
from __future__ import annotations
from typing import ClassVar

class Shape:
    _registry: ClassVar[dict[str, type[Shape]]] = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        # Auto-register every subclass by its lowercase name:
        Shape._registry[cls.__name__.lower()] = cls

    @classmethod
    def create(cls, kind: str, *args, **kwargs) -> Shape:
        """Factory: Shape.create('circle', radius=5) → Circle(5)."""
        try:
            sub = cls._registry[kind.lower()]
        except KeyError:
            raise ValueError(f"unknown shape kind: {kind!r}")
        return sub(*args, **kwargs)

class Circle(Shape):
    def __init__(self, radius: float):
        self.radius = radius
    def __repr__(self): return f"Circle({self.radius})"

class Rectangle(Shape):
    def __init__(self, width: float, height: float):
        self.width = width; self.height = height
    def __repr__(self): return f"Rectangle({self.width}, {self.height})"

print(Shape.create("circle", radius=5))          # Circle(5)
print(Shape.create("rectangle", width=3, height=4))  # Rectangle(3, 4)
```

## 4. Static Methods — No Binding At All

### 4.1 Definition and Binding

```python
class MathUtils:
    @staticmethod
    def add(a, b):
        return a + b

    @staticmethod
    def is_prime(n):
        if n < 2:
            return False
        for i in range(2, int(n**0.5) + 1):
            if n % i == 0:
                return False
        return True

print(MathUtils.add(3, 4))       # 7 — called on class, no binding
m = MathUtils()
print(m.add(3, 4))               # 7 — called on instance, STILL no binding
print(m.is_prime(17))            # True

# What Python stores:
print(MathUtils.__dict__["add"])
# <staticmethod(<function MathUtils.add at 0x...>)>

print(MathUtils.add)             # <function MathUtils.add at 0x...> — raw function
print(m.add)                     # <function MathUtils.add at 0x...> — same raw function
print(MathUtils.add is m.add)    # True — no wrapping at all!

# Compare: instance/class methods return bound methods, staticmethods return the raw function.
import types
print(isinstance(MathUtils.add, types.FunctionType))   # True
print(isinstance(m.add, types.FunctionType))            # True — not MethodType!
```

**Explanation:** `@staticmethod` wraps the function in a `staticmethod` descriptor whose `__get__` simply returns the underlying function unchanged — it ignores both `instance` and `owner`. No argument is curried. Whether you access via class or instance, you get the exact same function object and must pass all arguments explicitly.

### 4.2 What Static Methods Can Access

| Access | Can it? | How |
|--------|---------|-----|
| Instance state (`self`) | **No** — no instance bound | Would need to receive it as a regular argument |
| Class state (`cls`) | **No** — no class bound | Would need to reference `ClassName.attr` explicitly (not polymorphic) |
| Nothing implicitly | — | Pure function that happens to live in the class namespace |

A static method is essentially a **namespaced function** — it is grouped with the class for organizational reasons but has no privileged access to the class or its instances.

### 4.3 When to Use Static Methods (and When Not To)

**Legitimate uses:**

```python
class Temperature:
    def __init__(self, celsius: float):
        self.celsius = celsius

    @staticmethod
    def c_to_f(c: float) -> float:
        """Pure conversion — needs no instance or class state."""
        return c * 9/5 + 32

    @staticmethod
    def f_to_c(f: float) -> float:
        return (f - 32) * 5/9

    @classmethod
    def from_fahrenheit(cls, f: float) -> Temperature:
        return cls(cls.f_to_c(f))  # classmethod uses static helper

    @property
    def fahrenheit(self) -> float:
        return self.c_to_f(self.celsius)  # instance method/property uses static helper

print(Temperature.c_to_f(100))              # 212.0
print(Temperature.from_fahrenheit(212).celsius)  # 100.0
print(Temperature(37).fahrenheit)           # 98.6
```

```python
class Validator:
    """Group related validation helpers under one namespace."""

    @staticmethod
    def is_valid_email(s: str) -> bool:
        return bool(re.match(r"^[^@]+@[^@]+\.[^@]+$", s))

    @staticmethod
    def is_valid_phone(s: str) -> bool:
        return bool(re.match(r"^\+?[\d\s\-()]+$", s))

    @staticmethod
    def sanitize(s: str) -> str:
        return s.strip().lower()

# These have no reason to be instance/class methods — they touch no class/instance state.
```

**When a staticmethod is the wrong choice:**

```python
class BadExample:
    count = 0

    @staticmethod
    def increment():           # WRONG — needs class state but has no cls!
        BadExample.count += 1  # hard-coded class name — breaks for subclasses

class GoodExample:
    count = 0

    @classmethod
    def increment(cls):        # RIGHT — cls is polymorphic
        cls.count += 1

class SubGood(GoodExample):
    pass

BadExample.increment()
SubGood.increment()
print(BadExample.count)   # 1
print(SubGood.count)      # AttributeError? Actually: BadExample.count is 1, SubGood has no own count
# Wait — BadExample.increment hard-coded BadExample.count, so SubGood.increment()
# incremented BadExample.count, not SubGood.count — bug!
# GoodExample's version with cls.count would correctly increment SubGood.count.
```

**Guideline:** If you are reaching for `ClassName.attr` inside a `@staticmethod`, you almost certainly want a `@classmethod` with `cls.attr` instead — otherwise subclasses will break.

**Alternative viewpoint — do you need a staticmethod at all?**

```python
# Instead of:
class Helpers:
    @staticmethod
    def helper(x): return x * 2

# You could just use a module-level function:
def helper(x): return x * 2

# Staticmethods are justified when:
# 1. The function conceptually belongs to the class's domain (Temperature.c_to_f).
# 2. You want subclasses to be able to override it.
# 3. You are grouping tightly related helpers (Validator).
# Otherwise, a plain module function is simpler. Python is not Java —
# not every function needs to live inside a class.
```

## 5. How Each Binds — Descriptor Mechanics

This section shows the descriptor protocol that makes the three method types work. Full details are in 10.6; here we focus on the practical differences.

```python
# The three descriptors side-by-side:
class Demo:
    def instance_method(self):  pass
    @classmethod
    def class_method(cls):      pass
    @staticmethod
    def static_method():        pass

import types

# Check what lives in the class dict:
print(type(Demo.__dict__["instance_method"]))  # <class 'function'>
print(type(Demo.__dict__["class_method"]))     # <class 'classmethod'>
print(type(Demo.__dict__["static_method"]))    # <class 'staticmethod'>

# Each has a different __get__:
func = Demo.__dict__["instance_method"]
cm   = Demo.__dict__["class_method"]
sm   = Demo.__dict__["static_method"]

obj = Demo()

# Instance method — function.__get__(obj, Demo) → bound method currying obj
bound_instance = func.__get__(obj, Demo)
print(bound_instance)                  # <bound method Demo.instance_method of <Demo>>
print(bound_instance.__self__ is obj)  # True
print(bound_instance.__func__ is func) # True

# Via class — function.__get__(None, Demo) → raw function
unbound = func.__get__(None, Demo)
print(unbound is func)                 # True

# Class method — classmethod.__get__(obj, Demo) → bound method currying Demo
bound_class_via_instance = cm.__get__(obj, Demo)
print(bound_class_via_instance.__self__ is Demo)  # True — bound to class!

bound_class_via_class = cm.__get__(None, Demo)
print(bound_class_via_class.__self__ is Demo)     # True — same, even via class!

# For a subclass, the bound class changes:
class SubDemo(Demo): pass
print(cm.__get__(None, SubDemo).__self__ is SubDemo)  # True — polymorphic!

# Static method — staticmethod.__get__(obj, Demo) → raw function, no binding
print(sm.__get__(obj, Demo) is Demo.__dict__["static_method"].__func__)  # True (underlying func)
print(sm.__get__(None, Demo) is sm.__get__(obj, Demo))                    # True — same either way
```

**Summary table — what `__get__` returns:**

| Descriptor | `__get__(instance, owner)` returns | First arg on call |
|------------|-------------------------------------|-------------------|
| `function` (instance method) | `method` bound to `instance` (or raw function if `instance is None`) | `self` = instance |
| `classmethod` | `method` bound to `owner` (the class, polymorphic) | `cls` = class |
| `staticmethod` | Raw function, no binding | Nothing implicit — all args explicit |

You can even write your own descriptors that bind differently — any object with `__get__` placed in a class dict participates in this protocol.

## 6. Choosing the Right Decorator — Decision Guide

```
Does the method need instance state (self.attr)?
├── YES → instance method (no decorator, def method(self, ...))
│
└── NO → Does it need class state (cls.attr) or need to
          construct instances polymorphically (cls(...))?
          ├── YES → @classmethod (def method(cls, ...))
          │
          └── NO → Does it logically belong to the class's
                    domain / should be overridable by subclasses?
                    ├── YES → @staticmethod (def method(...))
                    └── NO → plain module-level function
                              (not every function needs a class!)
```

### 6.1 Decision Examples

```python
class Order:
    tax_rate = 0.08          # class-level config
    _next_id = 1             # class-level counter

    def __init__(self, items: list[str], total: float):
        self.items = items
        self.total = total
        self.id = type(self)._next_id
        type(self)._next_id += 1

    # Instance method — needs self.items, self.total, self.id
    def summary(self) -> str:
        return f"Order #{self.id}: {len(self.items)} items, ${self.total:.2f}"

    # Instance method — needs self.total + class tax_rate
    def total_with_tax(self) -> float:
        return self.total * (1 + type(self).tax_rate)

    # Class method — creates instances, needs cls to be polymorphic
    @classmethod
    def from_csv(cls, line: str) -> Order:
        parts = line.split(",")
        return cls(items=parts[:-1], total=float(parts[-1]))

    # Class method — operates on class-level state
    @classmethod
    def set_tax_rate(cls, rate: float) -> None:
        if not 0 <= rate <= 1:
            raise ValueError("tax rate must be between 0 and 1")
        cls.tax_rate = rate

    # Static method — pure logic, no self/cls, belongs to Order's domain
    @staticmethod
    def validate_total(total: float) -> bool:
        return total >= 0 and total == round(total, 2)

    # Module function would also work for validate_total, but grouping
    # it inside Order keeps the API discoverable: Order.validate_total(x)
```

## 7. Common Mistakes

### 7.1 Forgetting the Decorator

```python
class MyClass:
    def from_string(data):        # intended as alternative constructor
        return MyClass(data)      # but forgot @classmethod!

    @classmethod
    def correct_from_string(cls, data):
        return cls(data)

# MyClass.from_string("hello") — when called as MyClass.from_string("hello"),
#   Python sees a plain function, no binding. "hello" becomes `data` — accidentally works via class!
# MyClass().from_string("hello") — via instance, tries to bind self as `data` → wrong argument!

obj = MyClass()
# obj.from_string("hello")  # passes obj as `data`, "hello" has nowhere to go → TypeError or wrong behavior
```

Without `@classmethod`, the method binds as an instance method — the first argument becomes `self` (the instance), not the class. It may appear to work when called on the class but breaks when called on an instance or subclass.

### 7.2 Using `@staticmethod` When `@classmethod` Is Needed (Subclass Breakage)

```python
class Base:
    default = "base"

    @staticmethod
    def create_static(value=None):
        return Base(value or Base.default)  # hard-coded Base!

    @classmethod
    def create_class(cls, value=None):
        return cls(value or cls.default)     # polymorphic

    def __init__(self, value):
        self.value = value

class Child(Base):
    default = "child"

print(Child.create_static().value)  # "base" — wrong! Used Base.default, created Base
print(type(Child.create_static()))  # Base — wrong type!

print(Child.create_class().value)   # "child" — correct
print(type(Child.create_class()))   # Child — correct type
```

### 7.3 Using `self` to Modify Class State

```python
class Counter:
    count = 0

    def increment_wrong(self):
        self.count += 1  # creates instance shadow — see 10.2!

    def increment_right(self):
        type(self).count += 1  # modifies class — correct

    @classmethod
    def increment_class(cls):
        cls.count += 1   # also correct, and polymorphic

# If you find yourself writing self.__class__.attr or type(self).attr
# inside an instance method to modify class state, consider whether
# the method should be a @classmethod instead.
```

### 7.4 Confusing `@classmethod` First Arg Name

```python
class MyClass:
    @classmethod
    def method(self):   # legal but misleading — first arg is the CLASS, not an instance
        print(self)     # prints <class 'MyClass'>, not an instance

# Always name it `cls` by convention — never `self` for classmethods.
```

### 7.5 Calling Instance Methods Without an Instance

```python
class Dog:
    def bark(self): return "woof"

# Dog.bark()  # TypeError: bark() missing 1 required positional argument: 'self'
# In Python 3, Dog.bark is a plain function — you must pass self explicitly:
Dog.bark(Dog())  # works but pointless

# In Python 2, Dog.bark was an "unbound method" that enforced the type of self.
# Python 3 removed unbound methods — Dog.bark is just a function.
```

### 7.6 Overusing Static Methods — Java-ism

```python
# Java habit — everything in a class:
class StringUtils:          # unnecessary class
    @staticmethod
    def capitalize(s): return s.capitalize()
    @staticmethod
    def reverse(s): return s[::-1]

# Pythonic — just use module functions:
def capitalize(s): return s.capitalize()
def reverse(s): return s[::-1]

# Or use a class only if there's shared state or polymorphism to justify it.
```

## 8. Advanced — Manually Creating Each Method Type

```python
# You can construct the descriptors programmatically:
class Manual:
    pass

def my_func(self):
    return f"hello from {self}"

# Instance method — just assign a function:
Manual.method = my_func
print(Manual().method())  # hello from <Manual object>

# Class method — wrap with classmethod():
def my_class_func(cls):
    return f"hello from class {cls.__name__}"
Manual.cm = classmethod(my_class_func)
print(Manual.cm())     # hello from class Manual
print(Manual().cm())   # hello from class Manual

# Static method — wrap with staticmethod():
def my_static_func(x, y):
    return x + y
Manual.sm = staticmethod(my_static_func)
print(Manual.sm(3, 4))    # 7
print(Manual().sm(3, 4))  # 7

# You can also use the decorator as a plain callable:
class Also:
    @classmethod
    def a(cls): return cls.__name__

    # equivalent without @ syntax:
    def b(cls): return cls.__name__
    b = classmethod(b)
```

### 8.1 `__self__` and `__func__` Inspection

```python
class Demo:
    def inst(self): pass
    @classmethod
    def clsm(cls): pass
    @staticmethod
    def stat(): pass

d = Demo()
print(d.inst.__self__)   # <Demo object> — instance
print(d.inst.__func__)   # <function Demo.inst>
print(Demo.clsm.__self__)  # <class 'Demo'> — class
print(Demo.clsm.__func__)  # <function Demo.clsm>
# d.stat has no __self__ or __func__ — it's a plain function
print(hasattr(d.stat, "__self__"))  # False
print(type(d.stat))                 # <class 'function'>
```

## 9. Comparison Table

| Feature | Instance method | `@classmethod` | `@staticmethod` |
|---------|----------------|----------------|-----------------|
| Decorator | *(none)* | `@classmethod` | `@staticmethod` |
| First param | `self` (instance) | `cls` (class) | *(none)* |
| Bound to | Instance | Class (polymorphic) | Nothing |
| Access via instance | `method` currying instance | `method` currying class | Raw function |
| Access via class | Raw function (unbound) | `method` currying class | Raw function |
| Can access instance state | Yes (`self.attr`) | No | No |
| Can access class state | Yes (`type(self).attr`) | Yes (`cls.attr`) — polymorphic | Only via hard-coded `ClassName.attr` — not polymorphic |
| Subclass-aware | Yes (via `self`'s type) | Yes (via `cls`) | No |
| Primary use | Operate on instance data | Alternative constructors, factory methods, class-level operations | Namespaced utility grouped with class |
| Descriptor type in `__dict__` | `function` | `classmethod` | `staticmethod` |

---

## 10. Summary

- **Instance methods** (`def method(self, ...)`) are plain functions whose `__get__` binds the instance as `self`. They are the default — use them when you need per-object state.
- **Class methods** (`@classmethod def method(cls, ...)`) bind the class as `cls`, polymorphically (subclasses get their own class). They are the idiomatic way to write alternative constructors (`from_string`, `from_dict`, `from_json`) and to operate on class-level state without hard-coding the class name.
- **Static methods** (`@staticmethod def method(...)`) bind nothing — they are namespaced plain functions. Use them for pure utilities that conceptually belong to the class but need no instance or class state. Prefer module-level functions when namespacing alone does not justify a method.
- Binding is implemented by the **descriptor protocol** (`__get__`): `function.__get__` curries the instance, `classmethod.__get__` curries the class, `staticmethod.__get__` curries nothing.
- **Common mistakes:** forgetting the decorator (method binds wrong), using `@staticmethod` when `@classmethod` is needed (breaks subclasses), and using `self.attr += 1` to modify class state (creates instance shadow).
- When in doubt, apply the **decision tree**: need `self` → instance method; need `cls` / `cls(...)` → classmethod; need neither but belongs to class domain → staticmethod; otherwise → module function.
