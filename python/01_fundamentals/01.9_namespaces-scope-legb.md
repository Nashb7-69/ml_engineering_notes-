# 01.9 Namespaces, Scope, and the LEGB Rule

> **Mental model:** A namespace is a mapping from names to objects (think `dict`). A scope is the region of code where a namespace is directly accessible. When Python encounters a name, it searches four namespaces in order — **L**ocal, **E**nclosing, **G**lobal, **B**uilt-in — and that order (LEGB) determines what the name refers to.

---

## 1. Namespaces — The Dicts Behind Names

A **namespace** is an abstract mapping from names (strings) to objects. Python implements most namespaces as `dict` objects, though some are optimised.

```python
# Every namespace is (conceptually) a dict.

# Global namespace — module level
x = 10
y = "hello"

# Introspect it:
print(globals())
# {'__name__': '__main__', '__doc__': None, '__package__': None,
#  '__loader__': ..., 'x': 10, 'y': 'hello', ...}
print(type(globals()))  # <class 'dict'>

# globals() IS the module's namespace dict — mutating it creates globals!
globals()["z"] = 99
print(z)  # 99 — created a global via the dict

# Local namespace — inside a function
def demo():
    a = 1
    b = 2
    print(locals())  # {'a': 1, 'b': 2}
    print(type(locals()))  # <class 'dict'> — but see warning below

demo()

# Built-in namespace — names like len, print, int, range
import builtins
print(builtins.__dict__.keys())
# dict_keys(['__name__', '__doc__', '__package__', ..., 'len', 'print', 'range', ...])
print(len)           # <built-in function len>
print(builtins.len)  # same object
print(len is builtins.len)  # True

# Object namespaces — attributes live in __dict__ (when not using __slots__)
class MyClass:
    class_attr = 42
    def __init__(self, value):
        self.value = value

obj = MyClass(100)
print(obj.__dict__)        # {'value': 100} — instance namespace
print(MyClass.__dict__.keys())  # dict_keys([...'class_attr', '__init__', ...])

# Namespace lifetimes:
# - Built-in: entire interpreter lifetime
# - Global (module): as long as the module is loaded
# - Local (function): from call until return (or closure extends it)
# - Class: from class definition until class is deleted
```

> **Warning — `locals()` is a snapshot, not a live view (inside functions):** In CPython, `locals()` inside a function returns a *copy* of the local namespace. Mutating it does NOT reliably create locals. Only use `locals()` for inspection.

```python
def tricky():
    a = 1
    loc = locals()
    loc["b"] = 2       # try to create local `b` via the dict
    print(loc)         # {'a': 1, 'b': 2} — dict has it
    try:
        print(b)       # NameError! — `b` was NOT actually created as a local
    except NameError as e:
        print(f"NameError: {e}")

tricky()
```

## 2. Scope — Where Names Are Visible

A **scope** is the textual region of a program where a namespace is directly accessible. Python has four scope levels, searched in order:

```
  ┌─────────────────────────────────┐
  │  Built-in  (builtins)            │  ← Last resort: len, print, range, ...
  │  ┌───────────────────────────┐  │
  │  │  Global  (module)          │  │  ← Module-level names
  │  │  ┌─────────────────────┐  │  │
  │  │  │  Enclosing (outer   │  │  │
  │  │  │  function)          │  │  │  ← For nested functions
  │  │  │  ┌───────────────┐  │  │  │
  │  │  │  │  Local        │  │  │  │
  │  │  │  │  (function)   │  │  │  │  ← Innermost: current function
  │  │  │  └───────────────┘  │  │  │
  │  │  └─────────────────────┘  │  │
  │  └───────────────────────────┘  │
  └─────────────────────────────────┘
         LEGB search order: innermost → outermost
```

### Scope is Determined Statically (Lexically)

Python determines the scope of every name at **compile time** by looking at where the name is bound (assigned, `def`, `class`, `import`, `for`, `with`, parameter) within the source text. It is NOT determined by runtime call stack.

```python
# Lexical scoping — the enclosing scope is where the function was DEFINED,
# not where it was CALLED.

x = "global"

def outer():
    x = "enclosing"
    def inner():
        print(x)  # which x? — lexically, the enclosing one ("enclosing")
    return inner

f = outer()
f()  # enclosing — not "global", even though f() is called at global scope

# Contrast with dynamic scoping (which Python does NOT use):
# In a dynamically-scoped language, f() would print "global" because
# the caller is at global scope. Python is lexically scoped — it prints "enclosing".
```

## 3. The LEGB Rule — Step by Step

When Python encounters a name `x`, it searches:

1. **L**ocal — current function's locals (including parameters)
2. **E**nclosing — any enclosing functions' locals, from innermost to outermost
3. **G**lobal — current module's globals
4. **B**uilt-in — `builtins` module

First match wins. If nothing is found → `NameError`.

```python
# Full LEGB demonstration
import builtins

# B — built-in
# len is in builtins

# G — global
global_var = "I am global"

def outer():
    # E — enclosing (from inner's perspective)
    enclosing_var = "I am enclosing"
    local_to_outer = "outer local"

    def inner():
        # L — local
        local_var = "I am local"
        print(f"  L: {local_var}")
        print(f"  E: {enclosing_var}")       # from enclosing scope
        print(f"  G: {global_var}")          # from global scope
        print(f"  B: {len('hello')}")        # from builtins (len)
        # What about local_to_outer? Also enclosing — outer is enclosing for inner
        print(f"  E2: {local_to_outer}")

    inner()
    # inner's local_var is NOT accessible here
    try:
        print(local_var)
    except NameError as e:
        print(f"  NameError (expected): {e}")

outer()

# Shadowing — inner scope names hide outer scope names
x = "global x"

def shadow_demo():
    x = "local x"  # shadows global x — LEGB finds local first
    print(f"  inside: {x}")  # local x

shadow_demo()
print(f"  outside: {x}")     # global x — unaffected

# Built-in shadowing — also LEGB (local/global shadows built-in)
def builtin_shadow():
    len = 42  # shadows built-in len inside this function!
    print(f"  len = {len}")  # 42
    # Need builtins.len to reach the real len:
    print(f"  real len: {builtins.len([1, 2, 3])}")  # 3

builtin_shadow()
print(f"  global len: {len([1, 2, 3])}")  # 3 — global not affected
```

### Name Resolution is Determined at Compile Time

```python
# Python decides whether a name is local at COMPILE time by scanning for
# any binding (assignment, def, import, for, etc.) in the function body.

x = 10  # global

def read_global():
    print(x)  # no binding of x in this function → treated as global → prints 10

read_global()

def would_be_local():
    print(x)  # Python sees `x = 20` below → x is LOCAL for the ENTIRE function
    x = 20    # binding makes x local — even before this line!

try:
    would_be_local()
except UnboundLocalError as e:
    print(f"UnboundLocalError: {e}")
    # local variable 'x' referenced before assignment
    # This is NOT a NameError — Python KNOWS x is local but it has no value yet.

# This is why `global` and `nonlocal` declarations exist — to override the
# compile-time decision:

def fixed_with_global():
    global x
    print(x)  # now explicitly global — prints 10
    x = 20    # modifies global x

fixed_with_global()
print(f"global x is now {x}")  # 20
x = 10  # reset for later examples
```

## 4. `global` — Rebinding Module-Level Names

`global name` declares that `name` refers to the module's global namespace, not a local. Required when you want to **rebind** (assign to) a global from inside a function.

```python
count = 0  # global

def read_count():
    # Reading a global — no declaration needed
    print(f"count is {count}")  # LEGB finds global count — fine

read_count()  # count is 0

def increment_bad():
    # Trying to REBIND without `global` — creates a local instead!
    # count += 1  # equivalent to count = count + 1 — sees `count =` → local
    # print(count)  # UnboundLocalError!
    pass

try:
    def increment_broken():
        count += 1  # UnboundLocalError — `count` is local (due to `+=` binding) but uninitialised
    increment_broken()
except UnboundLocalError as e:
    print(f"UnboundLocalError: {e}")

def increment_good():
    global count
    count += 1      # now explicitly global — modifies module-level count
    print(f"incremented to {count}")

increment_good()  # incremented to 1
print(f"global count: {count}")  # 1

# `global` can declare multiple names
a, b, c = 1, 2, 3

def modify_many():
    global a, b, c
    a, b, c = 10, 20, 30

modify_many()
print(a, b, c)  # 10 20 30

# `global` is needed ONLY for rebinding. Mutating a global object needs no declaration:
items: list[int] = [1, 2, 3]

def mutate_global():
    # No `global` needed — we're not rebinding `items`, just mutating the object it points to
    items.append(4)
    print(f"  mutated items: {items}")

mutate_global()  # mutated items: [1, 2, 3, 4]
print(items)     # [1, 2, 3, 4] — mutated (no `global` needed)

def rebind_global():
    global items
    items = [99, 99]  # rebinding — `global` IS needed
    print(f"  rebound items: {items}")

rebind_global()  # rebound items: [99, 99]
print(items)     # [99, 99] — rebound

# Reset
items = [1, 2, 3]

# When to use `global` — sparingly! Heavy use of globals is a code smell.
# Prefer: function parameters, return values, classes, or closures.
```

## 5. `nonlocal` — Rebinding Enclosing Scope (Python 3+)

`nonlocal name` declares that `name` refers to the nearest enclosing function scope (not global, not local). Required to **rebind** a variable in an enclosing function.

```python
def outer():
    count = 0  # enclosing scope

    def increment():
        nonlocal count
        count += 1
        print(f"  count = {count}")

    def get_count():
        return count  # reading — no declaration needed

    return increment, get_count

inc, get = outer()
inc()  # count = 1
inc()  # count = 2
print(get())  # 2

# Without `nonlocal`, assignment would create a local instead
def outer_broken():
    count = 0

    def increment_broken():
        # count += 1  # UnboundLocalError — `count` treated as local
        count = 1     # creates a NEW local `count`, doesn't affect enclosing
        print(f"  broken count = {count}")

    increment_broken()
    print(f"  enclosing count still {count}")  # 0 — unchanged!

outer_broken()

# `nonlocal` walks outward through enclosing scopes — finds the NEAREST binding
def level1():
    x = "level1"
    def level2():
        x = "level2"
        def level3():
            nonlocal x  # refers to level2's x (nearest enclosing with `x`)
            print(f"  before: {x}")  # level2
            x = "modified by level3"
            print(f"  after: {x}")   # modified by level3
        level3()
        print(f"  level2 x is now: {x}")  # modified by level3
    level2()
    print(f"  level1 x still: {x}")  # level1 — unaffected

level1()

# `nonlocal` CANNOT refer to global or built-in — only enclosing function scopes
x_global = 10

def try_nonlocal_global():
    # nonlocal x_global  # SyntaxError: no binding for nonlocal 'x_global' found
    pass

# Use `global` for globals, `nonlocal` for enclosing functions — they are distinct:
#   global  → module scope
#   nonlocal → enclosing function scope(s)
#   (no declaration) + no local binding → LEGB search (read-only access to any level)

# Practical — closure with state (factory pattern)
def make_counter(start: int = 0):
    """Create a counter closure. Demonstrates nonlocal for shared mutable state."""
    count = start

    def increment(step: int = 1) -> int:
        nonlocal count
        count += step
        return count

    def decrement(step: int = 1) -> int:
        nonlocal count
        count -= step
        return count

    def value() -> int:
        return count  # read-only — no nonlocal needed

    return increment, decrement, value

inc, dec, val = make_counter(10)
print(inc())    # 11
print(inc(5))   # 16
print(dec(3))   # 13
print(val())    # 13

# Independent counters — each closure has its own `count`
inc2, _, val2 = make_counter(100)
print(inc2())   # 101
print(val())    # 13 — first counter unaffected
```

## 6. Function, Module, and Class Scope

### Module Scope — The Global Scope

Each `.py` file is a module with its own global namespace. Names defined at the top level of a file are globals *for that module* — not program-wide globals.

```python
# module_a.py:  x = 10
# module_b.py:  x = 20
# These are DIFFERENT globals — module_a.x vs module_b.x

# Simulate with two module dicts:
import types

mod_a = types.ModuleType("mod_a")
mod_a.x = 10
mod_a.greet = lambda: f"Hello from mod_a, x={mod_a.x}"

mod_b = types.ModuleType("mod_b")
mod_b.x = 20

print(mod_a.x)  # 10
print(mod_b.x)  # 20 — independent

# `if __name__ == "__main__":` — module scope idiom
# Code at module scope runs on import — guard executable code:
# if __name__ == "__main__":
#     main()  # only when run directly, not when imported
```

### Function Scope — New Scope Per Call

Each function call creates a fresh local namespace. Parameters and local variables live there.

```python
def func(x, y=10):
    # x, y, z are all local to this call
    z = x + y
    print(f"  x={x}, y={y}, z={z}")
    print(f"  locals: {locals()}")

func(5)        # x=5, y=10, z=15
func(5, 20)    # x=5, y=20, z=25

# Each call has independent locals — no sharing between calls
# (unlike `static` locals in C)

# Nested calls — each has its own frame
def factorial(n: int) -> int:
    print(f"  factorial({n}) called, id(n)={id(n)}")
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(4))
# factorial(4) → factorial(3) → factorial(2) → factorial(1)
# Each call has its own `n` — no interference
```

### Class Scope — Special Rules

Class bodies execute in a temporary namespace that becomes the class's `__dict__`. But class scope is **not** an enclosing scope for methods — LEGB skips it for method bodies.

```python
# Class scope — names defined in class body become class attributes
class MyClass:
    class_var = "I am a class var"
    count = 0

    # Class body can reference earlier class names
    doubled = count * 2  # 0 — class_var not yet needed here
    print(f"  Inside class body: class_var={class_var}, count={count}")

print(MyClass.class_var)  # I am a class var
print(MyClass.doubled)    # 0

# CRITICAL — class scope is NOT enclosing for methods!
x = "global x"

class Demo:
    x = "class x"

    def method(self):
        # LEGB for `x` here: L (method locals) → E (no enclosing function)
        # → G (module global "global x") → B
        # Class scope ("class x") is SKIPPED!
        print(f"  x in method: {x}")  # global x — NOT class x!

Demo().method()  # x in method: global x

# To access class scope from a method, use self/class name:
class DemoFixed:
    x = "class x"

    def method_via_class(self):
        print(f"  via DemoFixed.x: {DemoFixed.x}")  # class x
        print(f"  via self.x: {self.x}")            # class x (via instance lookup)
        print(f"  via type(self).x: {type(self).x}")  # class x

    @classmethod
    def class_method(cls):
        print(f"  via cls.x: {cls.x}")  # class x

DemoFixed().method_via_class()
DemoFixed.class_method()

# Why class scope is skipped — to avoid ambiguity between instance and class lookup.
# Methods use `self.` / `cls.` explicitly, making the intent clear.
```

## 7. Comprehension Scope — Own Scope in Python 3

In Python 2, list comprehensions leaked their loop variable. In Python 3, **all comprehensions** (list, dict, set, generator) have their own scope — implemented as an implicit function.

```python
# Comprehension has its own scope — loop variable does NOT leak
result = [x * 2 for x in range(5)]
print(result)  # [0, 2, 4, 6, 8]
try:
    print(x)   # NameError — x was local to the comprehension
except NameError as e:
    print(f"NameError: {e}")

# Same for dict, set, generator
d = {x: x**2 for x in range(3)}
try:
    print(x)
except NameError:
    print("  x not leaked from dict comprehension")

s = {x * 2 for x in range(3)}
try:
    print(x)
except NameError:
    print("  x not leaked from set comprehension")

gen = (x * 2 for x in range(3))
try:
    print(x)
except NameError:
    print("  x not leaked from generator expression")

# BUT — for loops DO leak (they are not comprehensions)
for y in range(5):
    pass
print(f"y after for loop: {y}")  # 4 — for loop variable leaks!

# Walrus operator in comprehensions — leaks intentionally
# [y := x * 2 for x in range(3)] — y IS visible after (it's in enclosing scope)
# This is by design — walrus binds in the enclosing scope, not the comprehension scope
filtered = [y for x in range(5) if (y := x * 2) > 4]
print(f"filtered: {filtered}")  # [6, 8]
print(f"y after walrus comprehension: {y}")  # 8 — walrus leaked y

# Nested comprehension scoping
# The outer `for` is evaluated in the enclosing scope; inner `for` creates its scope
# This matters for closures capturing loop variables — see below

# Class scope + comprehension interaction (Python 3.8+ fix)
# In class scope, comprehensions cannot see class variables directly in some cases:
class Foo:
    n = 5
    # In Python 3.7 and earlier, this would fail:
    # items = [n for _ in range(3)]  # NameError in some versions
    # Workaround — use a local or default arg:
    items = [n for n in range(n)]  # n from class scope used as iterable — works
    print(f"  Foo.items: {items}")

print(Foo.items)
```

### Loop Variable Closure Trap (Related to Scope)

Though technically about closures, this trap is directly caused by comprehension/function scope:

```python
# The classic closure-in-loop bug
funcs = [lambda: i for i in range(5)]
print([f() for f in funcs])  # [4, 4, 4, 4, 4] — all return 4!

# Why? Each lambda captures the VARIABLE `i` (by reference), not its VALUE.
# After the comprehension, `i` is not leaked in Python 3, but the lambdas
# were created inside the comprehension's scope where `i` ended as 4.
# Actually in list comprehension with Python 3, let's verify:
funcs2 = []
for i in range(5):
    funcs2.append(lambda: i)
print([f() for f in funcs2])  # [4, 4, 4, 4, 4] — same bug with for loop

# Fix — capture the VALUE via default argument
funcs_fixed = [lambda i=i: i for i in range(5)]
print([f() for f in funcs_fixed])  # [0, 1, 2, 3, 4] — correct!

# Or use functools.partial, or define a factory function
def make_func(val):
    return lambda: val

funcs_factory = [make_func(i) for i in range(5)]
print([f() for f in funcs_factory])  # [0, 1, 2, 3, 4]
```

## 8. Shadowing Built-ins — A Common Hazard

Because LEGB searches local → enclosing → global → built-in, any name you define at global or local scope *shadows* the built-in of the same name.

```python
# Shadowing at global scope
# list = [1, 2, 3]  # DON'T DO THIS — shadows built-in `list` type!
# Now `list(...)` would fail: TypeError: 'list' object is not callable
# Common casualties: list, dict, str, int, type, id, input, open, sum, max, min

# Example of the breakage:
str_shadow = "hello"  # shadows `str` type in this scope
# x = str(42)  # would be: TypeError: 'str' object is not callable
# Fix: don't name variables after built-ins
str_value = "hello"  # OK — different name
x = str(42)          # OK — str type still accessible
print(x)

# Shadowing at local scope — also dangerous but contained
def bad_function():
    sum = 0  # shadows built-in sum inside this function
    for i in range(5):
        sum += i
    print(f"  sum = {sum}")
    # sum([1, 2, 3])  # TypeError here — sum is now int, not function
    # Need builtins.sum:
    import builtins
    print(f"  real sum: {builtins.sum([1, 2, 3])}")

bad_function()
print(f"  global sum still works: {sum([1, 2, 3])}")  # 6 — global not affected

# How to detect shadowing — linters catch it
# ruff / pylint / flake8 warn: "A001 variable `list` is shadowing a Python builtin"
# Enable these checks in your project!

# Shadowing `__builtins__` edge case
# In modules, `__builtins__` may be either `builtins` module or its dict — don't rely on it
import builtins
print(__builtins__ is builtins or __builtins__ is builtins.__dict__)  # True (one or the other)

# Safe pattern — if you MUST use a name that collides, add a suffix
# `list_` is common (e.g., `filter` param named `list_` or `type_`):
def process(list_: list[int]) -> int:
    import builtins
    return builtins.sum(list_)

print(process([1, 2, 3]))  # 6
```

## 9. Realistic Example — Scoping in a Mini Framework

```python
"""
Demonstrates LEGB, global/nonlocal, comprehension scope, and shadowing
in a realistic configuration + plugin system.
"""
import builtins
from collections.abc import Callable

# === Global scope — module-level configuration ===
_config: dict[str, str] = {"env": "production", "debug": "false"}
_plugins: list[Callable[[], str]] = []

def configure(key: str, value: str) -> None:
    """Update global config. Mutates the global dict (no `global` needed)."""
    _config[key] = value  # mutation — no `global` declaration required

def reset_config() -> None:
    """Reset global config. Rebinds the global name — `global` IS needed."""
    global _config
    _config = {"env": "production", "debug": "false"}

def get_config(key: str) -> str | None:
    """Read global config. No declaration needed for reading."""
    return _config.get(key)  # LEGB finds global _config

# === Enclosing scope + nonlocal — plugin factory ===
def create_plugin_manager():
    """Factory that uses enclosing scope + nonlocal for encapsulated state."""
    call_count = 0           # enclosing variable — shared by all inner functions
    history: list[str] = []  # enclosing — mutable, but rebinding needs nonlocal

    def register(plugin: Callable[[], str]) -> None:
        nonlocal history  # not strictly needed for .append (mutation), but for reassignment
        history.append(plugin.__name__)
        _plugins.append(plugin)  # global list — mutation, no `global` needed

    def run_all() -> list[str]:
        nonlocal call_count
        call_count += 1
        print(f"  [run #{call_count}] history: {history}")
        # Comprehension scope — `p` does not leak
        results = [p() for p in _plugins]  # _plugins from global scope
        return results

    def get_count() -> int:
        return call_count  # read-only — no nonlocal needed

    def clear_history() -> None:
        nonlocal history
        history = []  # rebinding — nonlocal IS needed
        print("  History cleared")

    return register, run_all, get_count, clear_history

# === Usage ===
register, run_all, get_count, clear_history = create_plugin_manager()

def plugin_alpha() -> str:
    # Reads global config via LEGB — no declaration needed
    env = get_config("env")
    return f"alpha({env})"

def plugin_beta() -> str:
    return f"beta(debug={get_config('debug')})"

register(plugin_alpha)
register(plugin_beta)

print(run_all())  # [alpha(production), beta(debug=false)]
print(run_all())  # [alpha(production), beta(debug=false)] — call_count=2
print(f"Call count: {get_count()}")  # 2

# Comprehension scope — verify no leak
results = [x.upper() for x in ["hello", "world"]]
print(f"Results: {results}")
try:
    print(x)
except NameError:
    print("  x not leaked from comprehension — good")

# Shadowing demonstration — safe vs unsafe
# UNSAFE — would shadow built-in:
# sum = 0  # shadows built-in sum!

# SAFE — distinct name:
total = builtins.sum(len(p()) for p in _plugins)  # generator scope — `p` doesn't leak
print(f"Total plugin name lengths: {total}")

# Global mutation vs rebinding
print(f"\nConfig before: {_config}")
configure("env", "staging")
print(f"After configure: {_config}")  # mutated via dict — no `global` in configure()
reset_config()
print(f"After reset: {_config}")      # rebound via `global` in reset_config()

# Class scope — plugins as classes
class PluginBase:
    kind = "base"

    def describe(self) -> str:
        # Class scope NOT in LEGB for methods — must use self/type
        # print(kind)  # NameError — class scope skipped!
        return f"{type(self).kind} plugin: {type(self).__name__}"

class AlphaPlugin(PluginBase):
    kind = "alpha"

print(AlphaPlugin().describe())  # alpha plugin: AlphaPlugin
print(PluginBase().describe())   # base plugin: PluginBase

# Cleanup
clear_history()
print(f"Count after clear: {get_count()}")  # still 2 — clear doesn't reset count
```

## 10. Common Mistakes and Pythonic Idioms

| Mistake | What Happens | Fix |
|---|---|---|
| `x += 1` inside function without `global` | `UnboundLocalError` | `global x` if rebinding global; or pass as arg |
| `count += 1` in nested function without `nonlocal` | `UnboundLocalError` | `nonlocal count` |
| `list = [1,2]` at module level | Shadows `list` built-in globally | Name it `my_list`, `items`, `values` |
| Assuming `for` loop doesn't leak | `for x in ...: pass` leaves `x` bound | Don't rely on `x` after loop; use comprehension for isolation |
| `lambda: i` in a loop | All lambdas capture same `i` (final value) | `lambda i=i: i` or factory function |
| Assuming class scope is enclosing for methods | `NameError` — class scope skipped in LEGB | Use `self.attr` / `ClassName.attr` / `cls.attr` |
| `locals()["x"] = 1` to create a local | Doesn't reliably create a local | Just write `x = 1` |
| Heavy use of `global` | Hidden coupling, hard to test | Pass parameters, use classes, return values |

**Pythonic idioms:**

```python
# Prefer parameters and return values over global
# BAD:
# count = 0
# def increment():
#     global count
#     count += 1

# GOOD:
def increment(count: int) -> int:
    return count + 1

# Or encapsulate in a class:
class Counter:
    def __init__(self) -> None:
        self.count = 0
    def increment(self) -> None:
        self.count += 1

# Use nonlocal for closures that need shared state
def make_accumulator():
    total = 0
    def add(n: int) -> int:
        nonlocal total
        total += n
        return total
    return add

# Avoid shadowing built-ins — add trailing underscore if needed
def process(str_: str, type_: str) -> str:
    return f"{type_}: {str_}"

# Use comprehensions for isolated scope (not for loops)
squares = [x*x for x in range(10)]  # x doesn't leak

# Access class attributes explicitly
class Foo:
    attr = 42
    def method(self):
        print(self.attr)        # via instance
        print(type(self).attr)  # via class
        print(Foo.attr)         # via class name
```

## 11. Summary

- **Namespace** = mapping `name → object` (usually a `dict`); **scope** = region where that namespace is accessible.
- **LEGB** — name lookup order: **L**ocal → **E**nclosing → **G**lobal → **B**uilt-in. First match wins; failure → `NameError`.
- **Scope is lexical** — determined at compile time by where names are *bound* in the source, not by the call stack at runtime. Any binding (`=`, `def`, `import`, `for`) in a function makes the name local for the *entire* function.
- **`global`** — declares that a name refers to the module's global namespace. Needed only to **rebind** globals (mutating a global object needs no declaration).
- **`nonlocal`** (3.x) — declares that a name refers to the nearest enclosing function's scope. Needed to **rebind** enclosing variables. Cannot refer to global/built-in.
- **Function scope** — new namespace per call; **module scope** — one global namespace per file; **class scope** — temporary namespace that becomes `__dict__`, but is **skipped** in LEGB for methods (use `self.`/`cls.`).
- **Comprehensions** (Python 3) have their own scope — loop variable doesn't leak. `for` loops **do** leak. Walrus (`:=`) inside comprehensions binds in the enclosing scope.
- **Shadowing built-ins** (`list`, `str`, `sum`, etc.) at any scope hides the built-in via LEGB. Avoid it; use `name_` suffix if needed; enable linter checks.

> **Key takeaway:** LEGB is simple to state but has sharp edges where compile-time binding decisions, class-scope skipping, and comprehension isolation surprise newcomers. When in doubt, ask: "Where is this name *bound* in the source?" — that determines its scope, and LEGB determines where it is *found*.
