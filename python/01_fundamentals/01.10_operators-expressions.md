# 01.10 Operators and Expressions

> **Mental model:** An *expression* is any code that produces a value (`2 + 3`, `f(x)`, `a if b else c`). A *statement* is an action that does something (`if`, `for`, `import`, `x = 1`). Python's operators transform expressions into new expressions, and every operator maps to a dunder method (`__add__`, `__lt__`, etc.) that you can override.

---

## 1. Expression vs Statement

This distinction matters because expressions can appear *inside* other expressions, while statements cannot (with a few modern exceptions like the walrus).

```python
# Expressions — produce a value, can be nested
42                          # literal expression
2 + 3                       # operator expression
"hello".upper()             # call expression
x if y else z               # conditional expression
lambda n: n * 2             # lambda expression
[x * 2 for x in range(3)]   # comprehension expression
(a := 10)                   # walrus — expression that also assigns (3.8+)

# You can nest expressions arbitrarily:
result = (2 + 3) * max(4, 5) if True else 0
print(result)  # 25

# Statements — perform an action, don't produce a value for nesting
# x = 10        # assignment statement (but `x := 10` IS an expression)
# if x > 0: ... # if statement
# for x in range(3): ...  # for statement
# import os     # import statement
# def f(): ...  # def statement
# class C: ...  # class statement
# return x      # return statement
# with open(...) as f: ...  # with statement

# The key test — can you assign it?
value = 2 + 3       # OK — 2+3 is an expression
value = lambda x: x # OK — lambda is an expression
# value = if True: 1  # SyntaxError — `if` is a statement, not an expression
value = 1 if True else 0  # OK — ternary `if/else` IS an expression

# Expression statements — an expression used as a standalone statement
# (its value is computed and discarded, unless in the REPL where it's printed)
"hello"             # expression statement — does nothing in a script
42 + 10             # expression statement — computed and discarded
print("hi")         # call expression used as a statement (return value discarded)
```

> **Python 3.8+ blurs the line slightly:** The walrus operator `:=` lets assignment appear inside expressions. But plain `=` remains a statement.

## 2. Arithmetic Operators

| Operator | Name | Example | Result | Notes |
|---|---|---|---|---|
| `+` | Addition | `3 + 4` | `7` | Also concat for `str`/`list`/`tuple` |
| `-` | Subtraction | `10 - 3` | `7` | |
| `*` | Multiplication | `3 * 4` | `12` | Also repeat for `str`/`list` |
| `/` | True division | `7 / 2` | `3.5` | Always `float` |
| `//` | Floor division | `7 // 2` | `3` | Floor toward −∞ |
| `%` | Modulo | `7 % 3` | `1` | Sign follows divisor |
| `**` | Exponentiation | `2 ** 10` | `1024` | Right-associative |
| `+x` | Unary plus | `+5` | `5` | Rarely used |
| `-x` | Unary minus | `-5` | `-5` | |
| `~x` | Bitwise NOT | `~5` | `-6` | `-(x+1)` |

```python
# True division vs floor division
print(7 / 2)     # 3.5 — always float
print(7 // 2)    # 3 — floor
print(-7 // 2)   # -4 — floor toward -infinity (not truncation!)
print(7.0 // 2)  # 3.0 — floor division with floats gives float
print(7 // 2.0)  # 3.0

# Modulo — sign follows divisor (like floor division)
print(7 % 3)     # 1  — 7 == 2*3 + 1
print(-7 % 3)    # 2  — -7 == (-3)*3 + 2
print(7 % -3)    # -2 — 7 == (-3)*(-3) + (-2)
print(-7 % -3)   # -1
# Invariant: (a // b) * b + (a % b) == a  ALWAYS holds

# Exponentiation — right-associative
print(2 ** 3)       # 8
print(2 ** 3 ** 2)  # 512 — means 2**(3**2) = 2**9
print((2 ** 3) ** 2)# 64 — parenthesise for left-associative
print(4 ** 0.5)     # 2.0 — float exponent
print(2 ** -1)      # 0.5

# Unary minus vs exponentiation — precedence trap!
print(-3 ** 2)      # -9 — means -(3**2), NOT (-3)**2
print((-3) ** 2)    # 9
print(-2 ** 3)      # -8 — -(2**3)
print((-2) ** 3)    # -8 — same here (odd exponent)

# divmod — quotient and remainder together (more efficient than separate // and %)
print(divmod(17, 5))   # (3, 2)
print(divmod(-7, 3))   # (-3, 2)

# Augmented assignment — in-place when possible
x = 10
x += 5    # x = x + 5  (tries __iadd__ first)
x -= 3    # x = x - 3
x *= 2    # x = x * 2
x /= 4    # x = x / 4
x //= 2   # x = x // 2
x %= 3    # x = x % 3
x **= 2   # x = x ** 2
x &= 0xFF # x = x & 0xFF
x |= 1    # x = x | 1
x ^= 1    # x = x ^ 1
x <<= 2   # x = x << 2
x >>= 1   # x = x >> 1

# For mutables, augmented assignment mutates in place:
lst = [1, 2]
old_id = id(lst)
lst += [3, 4]        # list.__iadd__ — same object
print(id(lst) == old_id)  # True
lst = lst + [5]      # list.__add__ — new object
print(id(lst) == old_id)  # False
```

## 3. Comparison Operators and Chaining

### Basic Comparisons

| Operator | Meaning | Example |
|---|---|---|
| `==` | Equal value | `3 == 3` → `True` |
| `!=` | Not equal | `3 != 4` → `True` |
| `<` | Less than | `3 < 4` → `True` |
| `<=` | Less or equal | `3 <= 3` → `True` |
| `>` | Greater than | `4 > 3` → `True` |
| `>=` | Greater or equal | `4 >= 4` → `True` |
| `is` | Same identity | `a is b` |
| `is not` | Different identity | `a is not b` |
| `in` | Membership | `3 in [1,2,3]` |
| `not in` | Non-membership | `4 not in [1,2,3]` |

```python
# Value equality vs identity
a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)   # True — same value
print(a is b)   # False — different objects
print(a is not b)  # True

# None checks — always use `is`
x = None
print(x is None)      # True — correct
print(x is not None)  # False

# Membership
print(3 in [1, 2, 3])       # True
print("ell" in "hello")     # True — substring
print("key" in {"key": 1})  # True — dict key
print(10 not in {1, 2, 3})  # True

# Comparisons return bool
print(type(3 < 4))    # <class 'bool'>
print((3 < 4) == True)  # True — but don't write `== True`, just `if 3 < 4:`

# Cross-type comparisons — mostly TypeError in Python 3 (unlike Python 2)
try:
    print(3 < "hello")
except TypeError as e:
    print(f"TypeError: {e}")  # '<' not supported between instances of 'int' and 'str'

# But == and != NEVER raise TypeError for cross-type — they return False/True
print(3 == "hello")   # False
print(3 != "hello")   # True
print(None == 0)      # False

# Numeric tower — cross-numeric comparisons work
print(3 == 3.0)       # True — int and float
print(3 < 3.5)        # True
print(True == 1)      # True — bool is int
print(True > 0)       # True

# Complex has no ordering
try:
    print((3+4j) < (1+2j))
except TypeError as e:
    print(f"TypeError: {e}")
```

### Comparison Chaining — A Python Superpower

Python chains comparisons mathematically: `a < b < c` means `a < b and b < c` but `b` is evaluated **only once**.

```python
# Chaining — reads like mathematics
x = 5
print(1 < x < 10)     # True — means (1 < x) and (x < 10)
print(1 < x < 3)      # False — x is 5, not < 3
print(0 < x < 10)     # True

# Equivalent to `and` but with single evaluation of middle operand
# This matters when the middle expression has side effects or is expensive
def get_value():
    print("  get_value() called")
    return 5

print(1 < get_value() < 10)
# get_value() called ONCE — not twice as `1 < get_value() and get_value() < 10` would

# Any comparison operators can be chained
print(1 < 2 < 3)       # True
print(1 < 2 > 1)       # True — means (1 < 2) and (2 > 1)
print(1 == 1 == 1)     # True — means (1 == 1) and (1 == 1)
print(1 < 2 <= 2 < 3)  # True — mixed operators
print(5 > 4 == 4 < 6)  # True — means (5>4) and (4==4) and (4<6)

# Chaining with `is` and `in` also works (but reads oddly — prefer explicit `and`)
x = None
print(x is None is not True)  # True — means (x is None) and (None is not True) — valid but weird
# Better: x is None and True is not None  (clearer)

# Range check — the classic use case
def in_range(n: int, lo: int, hi: int) -> bool:
    return lo <= n <= hi  # Pythonic — reads like math

print(in_range(5, 1, 10))   # True
print(in_range(15, 1, 10))  # False

# Non-chain equivalent (less readable, double evaluation if n is an expression):
# return lo <= n and n <= hi
```

## 4. Identity vs Equality — `is` vs `==`

(Also covered in Lesson 01.1; key operator-focused summary here.)

```python
# `==` calls __eq__ — value comparison (can be overridden)
# `is` compares identity (id) — cannot be overridden, single pointer comparison

# Always use `is` for singletons:
if x is None:           # correct
    pass
if x is not None:       # correct
    pass

# Never use `is` for value comparison:
# if s is "hello":      # WRONG — relies on interning accident
if s == "hello":        # correct
    pass

# `is` with literals triggers a SyntaxWarning in modern Python:
# ```python
# if x is 42:    # SyntaxWarning: "is" with a literal. Did you mean "=="?
# if s is "hi":  # SyntaxWarning: "is" with a literal.
# ```

# The `is` / `==` contract for custom classes:
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __eq__(self, other):
        if isinstance(other, Point):
            return self.x == other.x and self.y == other.y
        return NotImplemented  # let the other type try
    def __repr__(self):
        return f"Point({self.x}, {self.y})"

p1 = Point(1, 2)
p2 = Point(1, 2)
p3 = p1

print(p1 == p2)   # True — same coordinates (via __eq__)
print(p1 is p2)   # False — different objects
print(p1 is p3)   # True — same object
print(p1 == p3)   # True — same object is also equal value
print(p1 != p2)   # False — __ne__ defaults to `not __eq__`
```

## 5. Membership — `in` / `not in`

```python
# `in` calls __contains__ (or falls back to __iter__ / __getitem__)
print(3 in [1, 2, 3])           # True — list
print(3 in (1, 2, 3))           # True — tuple
print(3 in {1, 2, 3})           # True — set (O(1) hash lookup)
print("ell" in "hello")         # True — substring
print("key" in {"key": 1})      # True — dict key (checks keys, not values)
print("key" in {"key": 1}.keys())  # True — same
print(1 in {"key": 1}.values()) # True — check values explicitly
print(2 in range(10))           # True — range (no iteration, arithmetic check)

# `not in` is `not (x in y)` — but as a single operator
print(4 not in [1, 2, 3])       # True
print("xyz" not in "hello")     # True

# Performance — `in` speed depends on the container:
#   set / dict / frozenset: O(1) average — hash table
#   list / tuple: O(n) — linear scan
#   str: O(n*m) — substring search (efficient algorithm, but still linear)
#   range: O(1) — arithmetic, no iteration!

# For membership-heavy code, prefer set:
# BAD:  if item in large_list:  # O(n) each check
# GOOD: large_set = set(large_list); if item in large_set:  # O(1)

# Custom __contains__
class SortedList:
    def __init__(self, items):
        self.items = sorted(items)
    def __contains__(self, value):
        import bisect
        idx = bisect.bisect_left(self.items, value)
        return idx < len(self.items) and self.items[idx] == value
    def __repr__(self):
        return f"SortedList({self.items})"

sl = SortedList([3, 1, 4, 1, 5])
print(3 in sl)   # True — via __contains__ (binary search)
print(2 in sl)   # False
```

## 6. Logical Operators — `and`, `or`, `not`

(Also covered deeply in Lesson 01.4; operator-focused recap here.)

```python
# `and` / `or` return an OPERAND, not necessarily bool
# `not` always returns bool

# `and` — return first falsy, or last value if all truthy
print(1 and 2)          # 2
print(0 and 2)          # 0
print(1 and 0 and 2)    # 0
print([] and "hello")   # [] — [] is falsy, returned
print("hi" and "hello") # hello — both truthy, last wins

# `or` — return first truthy, or last value if all falsy
print(0 or 1)           # 1
print(1 or 0)           # 1
print(0 or "" or None)  # None — all falsy, last value
print("" or "default")  # default
print("hi" or "default")# hi

# Short-circuit — right side not evaluated if result determined by left
def side_effect(msg):
    print(f"  side_effect({msg!r}) called")
    return msg

print("Test: truthy or side_effect")
print("hi" or side_effect("called"))    # side_effect NOT called
print("Test: falsy or side_effect")
print("" or side_effect("called"))      # side_effect IS called

# `not` — always bool
print(not True)     # False
print(not False)    # True
print(not 0)        # True
print(not "hello")  # False
print(type(not 0))  # <class 'bool'> — always bool

# Precedence — `not` > `and` > `or`
print(not True and False)    # False — means (not True) and False → False and False → False
print(not (True and False))  # True  — not (True and False) → not False → True
print(True or False and False)  # True — means True or (False and False) → True or False → True
print((True or False) and False)# False — means True and False → False

# The `or` default trap — swallows valid falsy values
def greet_bad(name=None):
    name = name or "Anonymous"  # BUG — "" becomes "Anonymous"
    return f"Hello, {name}"

print(greet_bad(""))    # Hello, Anonymous — wrong if "" was intentional
print(greet_bad(None))  # Hello, Anonymous — correct

def greet_good(name=None):
    if name is None:
        name = "Anonymous"
    return f"Hello, {name}"

print(greet_good(""))    # Hello,  — respects empty string
print(greet_good(None))  # Hello, Anonymous
```

## 7. Bitwise Operators

Operate on integers as if they were infinite-width two's complement. For non-negative ints, they behave like fixed-width binary.

| Operator | Name | Example | Result |
|---|---|---|---|
| `&` | AND | `0b1010 & 0b1100` | `0b1000` (8) |
| `\|` | OR | `0b1010 \| 0b1100` | `0b1110` (14) |
| `^` | XOR | `0b1010 ^ 0b1100` | `0b0110` (6) |
| `~` | NOT | `~0b1010` | `-11` |
| `<<` | Left shift | `0b1010 << 2` | `0b101000` (40) |
| `>>` | Right shift | `0b1010 >> 1` | `0b0101` (5) |

```python
# Basic bitwise
a = 0b1010  # 10
b = 0b1100  # 12
print(f"{a:04b} & {b:04b} = {a & b:04b} ({a & b})")  # 1000 (8)
print(f"{a:04b} | {b:04b} = {a | b:04b} ({a | b})")  # 1110 (14)
print(f"{a:04b} ^ {b:04b} = {a ^ b:04b} ({a ^ b})")  # 0110 (6)
print(f"~{a:04b} = {~a} ({~a:08b} — infinite width)")  # ~10 = -11

# ~x == -(x+1) — infinite two's complement
print(~0)    # -1
print(~1)    # -2
print(~-1)   # 0
print(~42)   # -43

# Shifts
print(0b0001 << 4)  # 16 — 0b10000
print(0b10000 >> 2) # 4  — 0b100
print(1 << 10)      # 1024 — common for powers of two
print(1024 >> 3)    # 128

# Right shift is arithmetic — sign extended (preserves sign for negatives)
print(-8 >> 1)   # -4 — arithmetic shift
print(-8 >> 2)   # -2
print(-1 >> 10)  # -1 — -1 is all 1s, shifting keeps it -1

# Practical — flags and masks
READ    = 0b100  # 4
WRITE   = 0b010  # 2
EXECUTE = 0b001  # 1

permissions = READ | WRITE           # 0b110 — read + write
print(f"permissions: {permissions:03b}")  # 110

# Check a flag
print(bool(permissions & READ))      # True — has read
print(bool(permissions & EXECUTE))   # False — no execute

# Add a flag
permissions |= EXECUTE
print(f"after |EXECUTE: {permissions:03b}")  # 111

# Remove a flag
permissions &= ~WRITE
print(f"after &~WRITE: {permissions:03b}")   # 101 — write removed

# Toggle a flag
permissions ^= WRITE
print(f"after ^WRITE: {permissions:03b}")    # 111 — write toggled back on

# Extract bits
value = 0b11010110
low_nibble = value & 0x0F         # 0b0110 — lower 4 bits
high_nibble = (value >> 4) & 0x0F # 0b1101 — upper 4 bits
print(f"value={value:08b}, low={low_nibble:04b}, high={high_nibble:04b}")

# Common mistake — `&` has LOWER precedence than comparisons and shifts
# Always parenthesise bitwise with comparisons:
# if flags & READ == READ:  # WRONG — means flags & (READ == READ) → flags & True → flags & 1
# if (flags & READ) == READ:  # CORRECT — check read bit
flags = READ | WRITE
if (flags & READ) == READ:
    print("  has READ — correct check")
# Or more simply:
if flags & READ:  # truthy if READ bit set
    print("  has READ — simpler check")
```

## 8. The Walrus Operator `:=` (Python 3.8+)

The **assignment expression** (walrus) assigns a value to a name *and* evaluates to that value — allowing assignment inside expressions.

```python
# Without walrus — two statements, or redundant computation
data = [1, 2, 3, 4, 5]
# n = len(data)
# if n > 3:
#     print(f"Long list: {n} items")

# With walrus — assign and test in one expression
if (n := len(data)) > 3:
    print(f"Long list: {n} items")  # Long list: 5 items

# The walrus ASSIGNS and RETURNS the value
print(n)  # 5 — n is bound in the enclosing scope (not a new scope)

# More examples
# Loop — read and check in one condition
# while (line := file.readline()) != "":
#     process(line)

# Comprehension — reuse an expensive computation
import math
# Without walrus — computes sqrt twice (or need a helper)
values = [1, 4, 9, 16, 25]
# [math.sqrt(x) for x in values if math.sqrt(x) > 2]  # two sqrt calls!

# With walrus — compute once, use twice
filtered = [y for x in values if (y := math.sqrt(x)) > 2]
print(filtered)  # [3.0, 4.0, 5.0] — y bound, sqrt called once per element

# Regex — match and use in one step
import re
text = "Contact: alice@example.com for info"
if (match := re.search(r"(\w+)@(\w+)\.(\w+)", text)):
    print(f"  Found: {match.group(0)}")  # alice@example.com
    print(f"  User: {match.group(1)}")   # alice

# Chained walrus — right to left
# (a := (b := 10)) — b=10, a=10
# Generally avoid chaining — hurts readability

# Walrus scope — binds in the CURRENT scope, not a new one
# This is different from `for`/`comprehension` scoping!
if (val := 42):
    print(f"  val inside if: {val}")  # 42
print(f"  val outside if: {val}")    # 42 — leaked to enclosing scope!

# In comprehensions, walrus leaks to the enclosing scope too
result = [y for x in range(5) if (y := x * 2) > 4]
print(f"  result: {result}")  # [6, 8]
print(f"  y after comprehension: {y}")  # 8 — walrus leaked y

# Precedence — walrus has very LOW precedence (lower than comma!)
# This traps people:
# x := 1, 2  # means x := (1, 2) → x is (1, 2), NOT x=1 then tuple
x = 0
(x := 1, 2)  # x is 1, expression value is (1, 2) — parens change meaning
print(f"  x = {x}")  # 1

# Walrus needs parens in many contexts (function args, lambda, etc.)
# func(a := 10)  # SyntaxError — must parenthesise: func((a := 10))
# lambda: x := 10  # SyntaxError — must parenthesise: lambda: (x := 10)

# When NOT to use walrus — when plain assignment is clearer
# BAD — walrus for simple assignment:
# if (name := input("Name: ")):  # works but `name = input(...)` above the if is clearer
# GOOD — walrus when it avoids duplication or enables the pattern:
# while (line := file.readline().strip()):
#     process(line)  # avoids: line = file.readline().strip() before AND inside loop

# Walrus vs `=` — the distinction:
# `=` is a STATEMENT — cannot appear inside expressions
# `:=` is an EXPRESSION — can appear inside expressions (and also assigns)
```

## 9. Operator Precedence — The Full Table

From **highest** (binds tightest) to **lowest** (binds loosest):

| Precedence | Operators | Description | Associativity |
|---|---|---|---|
| 1 | `(...)`, `[...]`, `{...}`, `f(...)`, `x[...]`, `x.attr` | Grouping, calls, subscripts, attribute | Left |
| 2 | `x[...]`, `x.attr` | Subscription, slicing, attribute | Left |
| 3 | `await x` | Await | Right |
| 4 | `x ** y` | Exponentiation | **Right** |
| 5 | `+x`, `-x`, `~x` | Unary plus/minus/NOT | Right |
| 6 | `*`, `@`, `/`, `//`, `%` | Multiplicative | Left |
| 7 | `+`, `-` | Additive | Left |
| 8 | `<<`, `>>` | Shifts | Left |
| 9 | `&` | Bitwise AND | Left |
| 10 | `^` | Bitwise XOR | Left |
| 11 | `\|` | Bitwise OR | Left |
| 12 | `in`, `not in`, `is`, `is not`, `<`, `<=`, `>`, `>=`, `!=`, `==` | Comparisons, membership, identity | Left (chained) |
| 13 | `not x` | Boolean NOT | Right |
| 14 | `and` | Boolean AND | Left |
| 15 | `or` | Boolean OR | Left |
| 16 | `if`–`else` | Conditional expression | Right |
| 17 | `:=` | Walrus (assignment expression) | Right |
| 18 | `lambda` | Lambda | Right |

Plus: `,` has lower precedence than `:=` (relevant for walrus in tuples).

```python
# Precedence in action — know when to parenthesise

# ** vs unary minus — ** wins
print(-2 ** 2)      # -4 — means -(2**2)
print((-2) ** 2)    # 4

# * vs + — * wins
print(2 + 3 * 4)    # 14 — not 20

# & vs == — == wins! (common trap)
# 3 & 5 == 1  →  3 & (5 == 1)  →  3 & False  →  3 & 0  →  0 (falsy!)
print(3 & 5 == 1)       # 0 — WRONG, not what you meant
print((3 & 5) == 1)     # True — CORRECT — 3&5 is 1, 1==1 is True
print(bool(3 & 5))      # True — if you just want to test the bit

# << vs + — + wins! (another trap)
print(1 << 2 + 1)       # 8 — means 1 << (2+1) → 1<<3 → 8
print((1 << 2) + 1)     # 5 — means 4+1
# When mixing shifts and arithmetic, always parenthesise

# and vs or — and wins
print(True or False and False)   # True — means True or (False and False)
print((True or False) and False) # False

# not vs and — not wins
print(not True and False)       # False — means (not True) and False
print(not (True and False))     # True

# Conditional expression — very low precedence
print(1 if True else 0 + 100)   # 1 — means 1 if True else (0+100)
print((1 if True else 0) + 100) # 101 — need parens for different meaning

# Walrus — very low precedence
# a := 1 + 2  →  a := (1+2)  →  a is 3 (walrus lower than +)
a = 0
print((a := 1 + 2))  # 3
print(a)             # 3

# When in doubt — parenthesise. Clarity beats cleverness.
# No one will fault you for extra parens; everyone will fault you for a precedence bug.
```

## 10. Dunder Methods — How Operators Map to Code

Every operator delegates to a double-underscore ("dunder") method on the left operand (or right operand for reflected operations).

| Expression | Dunder Call | Description |
|---|---|---|
| `a + b` | `a.__add__(b)` | Addition |
| `a - b` | `a.__sub__(b)` | Subtraction |
| `a * b` | `a.__mul__(b)` | Multiplication |
| `a / b` | `a.__truediv__(b)` | True division |
| `a // b` | `a.__floordiv__(b)` | Floor division |
| `a % b` | `a.__mod__(b)` | Modulo |
| `a ** b` | `a.__pow__(b)` | Exponentiation |
| `a & b` | `a.__and__(b)` | Bitwise AND |
| `a \| b` | `a.__or__(b)` | Bitwise OR |
| `a ^ b` | `a.__xor__(b)` | XOR |
| `~a` | `a.__invert__()` | Bitwise NOT |
| `a << b` | `a.__lshift__(b)` | Left shift |
| `a >> b` | `a.__rshift__(b)` | Right shift |
| `-a` | `a.__neg__()` | Unary minus |
| `+a` | `a.__pos__()` | Unary plus |
| `a == b` | `a.__eq__(b)` | Equality |
| `a != b` | `a.__ne__(b)` | Inequality |
| `a < b` | `a.__lt__(b)` | Less than |
| `a <= b` | `a.__le__(b)` | Less or equal |
| `a > b` | `a.__gt__(b)` | Greater than |
| `a >= b` | `a.__ge__(b)` | Greater or equal |
| `a in b` | `b.__contains__(a)` | Membership (note: on `b`!) |

```python
# Demonstrate — operators ARE dunder calls
print((10).__add__(5))      # 15 — same as 10 + 5
print((10).__mul__(3))      # 30 — same as 10 * 3
print((10).__pow__(2))      # 100 — same as 10 ** 2
print("hello".__contains__("ell"))  # True — same as "ell" in "hello"

# Augmented assignment — tries __iadd__ first, falls back to __add__
# a += b  →  a.__iadd__(b) if exists, else a = a.__add__(b)

# Reflected operations — when left operand doesn't know how
# 5 + MyNumber(10) → (5).__add__(MyNumber(10)) → NotImplemented
#                  → MyNumber(10).__radd__(5) → handles it
class MyInt:
    def __init__(self, value):
        self.value = value
    def __add__(self, other):
        if isinstance(other, MyInt):
            return MyInt(self.value + other.value)
        return NotImplemented
    def __radd__(self, other):
        # Called when `other + MyInt` and other's __add__ returned NotImplemented
        if isinstance(other, int):
            return MyInt(other + self.value)
        return NotImplemented
    def __repr__(self):
        return f"MyInt({self.value})"

a = MyInt(10)
print(a + MyInt(5))   # MyInt(15) — __add__
print(5 + a)          # MyInt(15) — __radd__
print(a + 5)          # MyInt(15) — wait, int is not MyInt, so __add__ returns
                      # NotImplemented, then int.__radd__(MyInt) also NotImplemented,
                      # actually... let's check:

# More precisely:
class VerboseInt:
    def __init__(self, v):
        self.v = v
    def __add__(self, other):
        print(f"  VerboseInt.__add__({other!r})")
        if isinstance(other, VerboseInt):
            return VerboseInt(self.v + other.v)
        print("    → NotImplemented")
        return NotImplemented
    def __radd__(self, other):
        print(f"  VerboseInt.__radd__({other!r})")
        if isinstance(other, int):
            return VerboseInt(other + self.v)
        return NotImplemented
    def __repr__(self):
        return f"VerboseInt({self.v})"

vi = VerboseInt(10)
print("5 + vi:")
print(5 + vi)    # int.__add__ → NotImplemented → vi.__radd__(5) → VerboseInt(15)
print("vi + 5:")
try:
    print(vi + 5)  # vi.__add__(5) → NotImplemented → int.__radd__(vi) → NotImplemented → TypeError
except TypeError as e:
    print(f"  TypeError: {e}")

# Custom class — full operator support
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, other):
        if isinstance(other, Vector):
            return Vector(self.x + other.x, self.y + other.y)
        return NotImplemented
    def __mul__(self, scalar):
        if isinstance(scalar, (int, float)):
            return Vector(self.x * scalar, self.y * scalar)
        return NotImplemented
    def __rmul__(self, scalar):
        return self.__mul__(scalar)  # scalar * vector == vector * scalar
    def __eq__(self, other):
        if isinstance(other, Vector):
            return self.x == other.x and self.y == other.y
        return NotImplemented
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"
    def __abs__(self):
        return (self.x**2 + self.y**2) ** 0.5

v1 = Vector(1, 2)
v2 = Vector(3, 4)
print(v1 + v2)     # Vector(4, 6)
print(v1 * 3)      # Vector(3, 6)
print(3 * v1)      # Vector(3, 6) — via __rmul__
print(v1 == Vector(1, 2))  # True
print(abs(v1))     # 2.236... — via __abs__
```

## 11. Realistic Example — Expression Power in Data Processing

```python
import re
import math
from collections import Counter

def analyse_scores(
    raw_data: list[dict],
    *,
    min_score: int = 0,
    max_score: int = 100,
) -> dict:
    """
    Analyse student scores using many operator categories together.
    Demonstrates: arithmetic, comparison chaining, logical, membership,
    walrus, conditional expressions, and bitwise flags.
    """
    # Bitwise flags for status
    PASS = 0b01
    HONOURS = 0b10

    # Validate bounds with comparison chaining
    assert 0 <= min_score <= max_score <= 100, "Invalid score bounds"

    results: list[dict] = []
    all_scores: list[int] = []

    for record in raw_data:
        # Membership — check required keys
        if not all(k in record for k in ("name", "score")):
            continue  # skip malformed

        name: str = record["name"]
        score_raw = record["score"]

        # Walrus — parse and validate in one step
        if (score_str := str(score_raw).strip()) == "":
            continue

        try:
            score = int(score_str)
        except (ValueError, TypeError):
            continue

        # Comparison chaining — range check
        if not (min_score <= score <= max_score):
            continue  # out of range

        # Arithmetic + conditional expression
        grade = (
            "A" if score >= 90 else
            "B" if score >= 80 else
            "C" if score >= 60 else
            "F"
        )

        # Bitwise — encode status
        status = 0
        if score >= 60:
            status |= PASS
        if score >= 85:
            status |= HONOURS

        # Logical — check honours with bitwise AND
        is_honours = bool(status & HONOURS)
        passed = bool(status & PASS)

        # Membership + logical for filtering display
        display_grade = grade if grade in ("A", "B", "C") else "—"

        results.append({
            "name": name,
            "score": score,
            "grade": display_grade,
            "passed": passed,
            "honours": is_honours,
            "status_bits": f"{status:02b}",
        })
        all_scores.append(score)

    # Arithmetic — statistics
    if not all_scores:
        return {"results": [], "stats": None}

    n = len(all_scores)
    # Walrus in comprehension — compute mean once
    mean = sum(all_scores) / n
    variance = sum((s - mean) ** 2 for s in all_scores) / n
    std = math.sqrt(variance)

    # Comparison chaining + logical for outlier detection
    outliers = [
        r for r in results
        if (s := r["score"]) < mean - 2 * std or s > mean + 2 * std
    ]

    # Conditional expression for summary
    overall = "Strong" if mean >= 75 else "Average" if mean >= 60 else "Weak"

    return {
        "results": results,
        "stats": {
            "count": n,
            "mean": round(mean, 1),
            "std": round(std, 1),
            "min": min(all_scores),
            "max": max(all_scores),
            "overall": overall,
            "outliers": outliers,
        },
    }

# --- Demo ---
data = [
    {"name": "Alice", "score": "92"},
    {"name": "Bob", "score": " 78 "},
    {"name": "Charlie", "score": "  "},       # empty → skipped
    {"name": "Diana", "score": "105"},         # out of range → skipped
    {"name": "Eve", "score": "55"},
    {"name": "Frank", "score": "88"},
    {"name": "Grace", "score": "42"},
    {"name": "Heidi", "score": "91"},
    {"name": "Ivan"},                          # missing score → skipped
    {"name": "Judy", "score": "abc"},          # non-numeric → skipped
    {"name": "Karl", "score": "73"},
]

report = analyse_scores(data)
print("Results:")
for r in report["results"]:
    honours_str = " (honours)" if r["honours"] else ""
    print(f"  {r['name']:10s} {r['score']:3d}  grade={r['grade']}  "
          f"passed={r['passed']}  bits={r['status_bits']}{honours_str}")

# Additional operator demos in context:
# Chained comparison for grading — already shown above
# Walrus to avoid double computation:
#   if (score := int(score_str)) >= 90: grade = "A"
# Bitwise for compact status — two booleans in one int
# Membership for filtering — `grade in ("A", "B", "C")`
# Conditional expression for concise branching

## 12. Common Mistakes and Pythonic Idioms

| Mistake | What Happens | Fix |
|---|---|---|
| `if x == 1 or 2:` | Always `True` — means `(x==1) or 2` | `if x in (1, 2):` or `if x == 1 or x == 2:` |
| `-3 ** 2 == 9` | Gives `-9` — `**` before unary `-` | `(-3) ** 2` |
| `flags & MASK == MASK` | `&` lower than `==` → wrong | `(flags & MASK) == MASK` or `flags & MASK` |
| `1 << 2 + 1 == 8` | `+` before `<<` → `1<<(2+1)` | `(1<<2)+1` if you meant 5 |
| `a is "hello"` | Identity vs equality; SyntaxWarning | `a == "hello"` |
| `a = b` in an `if` | `SyntaxError` — `=` is a statement | `(a := b)` for walrus, or assign before |
| `x += [1]` vs `x = x + [1]` for lists | `+=` mutates (affects aliases), `+` creates new | Know which you need |
| `1 < x < 10` thinking it means `1 < (x < 10)` | No — it chains correctly as `(1<x) and (x<10)` | It's already correct — just know it |
| `not x == 1` vs `x != 1` | Same value but `!=` is clearer | `x != 1` |
| `a and b or c` as ternary | Fails when `b` is falsy | `b if a else c` |

**Pythonic idioms:**

```python
# Range checks — chain!
if 0 <= x < len(items):           # not `x >= 0 and x < len(items)`

# Membership — `in` with tuple/set
if colour in ("red", "green", "blue"):  # not `colour == "red" or colour == "green" ...`
if key in valid_keys:                    # where valid_keys is a set for O(1)

# None checks — `is`
if x is None:                      # not `x == None`
if x is not None:                  # not `x != None`

# Default values — explicit None check (not `or`)
value = x if x is not None else default  # not `x or default` when 0/"" valid

# Walrus — avoid duplication
while (line := file.readline().strip()):
    process(line)

# Or with regex:
if (m := re.match(pattern, text)):
    use(m)

# Bitwise flags — named constants
READ, WRITE, EXEC = 0b100, 0b010, 0b001
if perms & READ:
    read_file()

# Conditional expression — concise branching
status = "pass" if score >= 60 else "fail"  # not a multi-line if/else for simple cases

# Augmented assignment — prefer for clarity
total += value    # not `total = total + value` (especially for mutables where it matters)
```

## 13. Summary

- **Expression** (produces a value) vs **statement** (performs an action) — expressions nest, statements don't (except `:=` which bridges the gap).
- **Arithmetic:** `/` always `float`; `//` floors toward −∞; `%` sign follows divisor; `**` is right-associative and binds tighter than unary `-` (`-3**2 == -9`).
- **Comparisons chain:** `1 < x < 10` means `1 < x and x < 10` with single evaluation of `x`. All comparison/membership/identity operators chain.
- **Identity (`is`)** vs **equality (`==`)** — `is` for singletons (`None`), `==` for values. Never `is` with literals.
- **Membership (`in`/`not in`)** — delegates to `__contains__`; `set`/`dict` are O(1), `list`/`tuple` O(n), `range` O(1).
- **Logical (`and`/`or`)** return an operand (not `bool`), short-circuit, and are value-selecting. `not` always returns `bool`. Never `if x == 1 or 2:`.
- **Bitwise** (`&`/`|`/`^`/`~`/`<<`/`>>`) — infinite-width two's complement; `~x == -(x+1)`; `&` has lower precedence than `==` and `<<` — parenthesise mixed expressions.
- **Walrus `:=`** (3.8+) — assignment expression: assigns and evaluates. Binds in the enclosing scope (leaks from `if`/`while`/comprehensions). Low precedence — parenthesise in many contexts.
- **Precedence** — `**` > unary > `*`/`/` > `+`/`-` > shifts > `&` > `^` > `|` > comparisons > `not` > `and` > `or` > ternary > `:=` > `lambda`. When in doubt, parenthesise.
- **Dunder mapping** — every operator calls a `__dunder__` method; reflected methods (`__radd__`) handle `other + self`; `NotImplemented` signals "try the other side."

> **Key takeaway:** Python's operators are concise but have sharp precedence edges — especially `**` vs unary `-`, `&` vs `==`, and `<<` vs `+`. Master comparison chaining and the value-returning `and`/`or` for Pythonic code, use `:=` to eliminate duplication, and parenthesise any mixed-operator expression where precedence isn't instantly obvious.
