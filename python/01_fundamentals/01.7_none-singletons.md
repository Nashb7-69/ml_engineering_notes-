# 01.7 None and Singletons

> **Mental model:** `None` is not "nothing" — it is a *real object*, the sole instance of `NoneType`, living at a fixed address for the lifetime of the interpreter. It means "no value was provided / no result exists." Several other singletons (`Ellipsis`, `NotImplemented`) follow the same pattern for different "no value" semantics.

Programmers from languages with `null`/`nil`/`NULL` often expect `None` to behave like a zero, an empty string, or a falsy placeholder that blends into surrounding code. In Python, `None` is deliberately distinct from every other value — and the idioms around it (`is None`, sentinel pattern, `Optional`) reflect that.

---

## 1. `None` — The Absent Value

### What `None` Is

- The **sole instance** of `NoneType` — a singleton created at interpreter startup.
- Its `id()` never changes; `None is None` is always `True`.
- Its boolean value is `False` (falsy), but it is **not** `False`, `0`, or `""`.
- Its type is `NoneType`, accessible as `type(None)`.
- It is the **default return value** of any function that doesn't explicitly `return` something.
- It is the conventional "no value" / "not provided" marker throughout Python.

```python
# None is an object — the only instance of NoneType
print(type(None))        # <class 'NoneType'>
print(type(None).__name__)  # NoneType
print(id(None))          # fixed for the interpreter lifetime

# NoneType cannot be instantiated — there is only one None
import types
print(types.NoneType)    # <class 'NoneType'> (3.10+)
# NoneType()  # conceptually impossible — no public constructor
# In older Python, `type(None)` was the only way to reference NoneType.

# None is falsy — but not False
print(bool(None))        # False
print(None is False)     # False — different objects!
print(None == False)     # False — None only equals itself
print(None == 0)         # False
print(None == "")        # False
print(not None)          # True — because bool(None) is False

# Identity — None is always itself
x = None
y = None
print(x is y)            # True — same singleton
print(x is None)         # True — idiomatic check
print(id(x) == id(None)) # True — same object
```

### How Functions Return `None`

```python
# Implicit None — no return statement
def no_return():
    x = 42
    print(f"inside: {x}")

result = no_return()
print(result)            # None
print(result is None)    # True
print(type(result))      # <class 'NoneType'>

# Explicit bare return — also None
def bare_return():
    return

print(bare_return())     # None
print(bare_return() is None)  # True

# Explicit return None — same, but documents intent
def explicit_none():
    return None

print(explicit_none() is None)  # True
# Prefer `return None` when the None is semantically meaningful,
# bare `return` or no return when the function is called for side effects.

# Functions that sometimes return a value and sometimes don't
def find_user(user_id: int) -> str | None:
    users = {1: "Alice", 2: "Bob"}
    return users.get(user_id)  # dict.get returns None if key missing

print(find_user(1))  # Alice
print(find_user(99)) # None — no user with that id
print(find_user(99) is None)  # True — must check before using!
```

## 2. `is None` vs `== None` — Always Use `is`

This is not a style preference — it is a correctness and performance requirement.

### Why `is None` Is Correct

```python
# CORRECT — identity check against the singleton
x = None
if x is None:
    print("x is None — correct, fast, idiomatic")

if x is not None:
    print("x has a value")

# WRONG — value equality (works by accident, but fragile)
if x == None:       # works because None.__eq__ returns True only for None
    print("works but WRONG — linter will flag (E711)")

if x != None:       # same issue
    print("also wrong")

# Why `==` is dangerous — a class can override __eq__ to hijack it
class Tricky:
    def __eq__(self, other):
        if other is None:
            print("  Tricky.__eq__(None) called — returning True!")
            return True
        return False

t = Tricky()
print(t == None)   # True — Tricky claims to equal None!
print(t is None)   # False — but `is` cannot be fooled (identity is not overridable)
print(t is not None)  # True — correct

# Another example — numpy arrays
try:
    import numpy as np
    arr = np.array([1, 2, 3])
    # arr == None  # returns array([False, False, False]) — element-wise!
    # bool(arr == None)  # ValueError: truth value of array is ambiguous
    # arr is None  # False — safe, no element-wise shenanigans
    print("numpy: `is None` is safe where `== None` would break")
except ImportError:
    print("numpy not installed — but the principle applies to any __eq__ override")

# Performance — `is` is a single pointer comparison; `==` calls __eq__
# For None checks in hot loops, `is` is measurably faster (though rarely the bottleneck).
```

### The Rule

```python
# ALWAYS:
#   if x is None:
#   if x is not None:
#   if x is None or y is None:
#   assert x is not None

# NEVER:
#   if x == None:
#   if x != None:
#   if x == None or y == None:
```

> **Linter enforcement:** `flake8` (E711), `pylint`, `ruff`, and `mypy` all flag `== None`. Configure your tools to catch it.

## 3. Other Singletons — `Ellipsis` and `NotImplemented`

Python has two other notable singletons that follow the same "one instance, check with `is`" pattern.

### `Ellipsis` (`...`)

- The sole instance of `ellipsis` type, spelled `...` (three dots) or `Ellipsis`.
- Used as a placeholder meaning "not yet implemented" or "any value" in different contexts.

```python
# Ellipsis is a singleton
print(Ellipsis)          # Ellipsis
print(... is Ellipsis)   # True — ... is syntax for the Ellipsis object
print(type(...))         # <class 'ellipsis'>
print(type(...) is type(Ellipsis))  # True

# Use 1 — Stub / placeholder for unimplemented code (alternative to `pass` or `raise`)
def future_feature(x: int) -> int:
    ...  # no body yet — valid syntax, does nothing (evaluates Ellipsis and discards it)

print(future_feature(42))  # None — `...` as a statement evaluates then returns None implicitly
# Contrast with `pass` — `...` is an expression, `pass` is a statement. Both do nothing.

# Use 2 — Type hints: Callable[..., int] means "callable with any args returning int"
from collections.abc import Callable

def apply(func: Callable[..., int]) -> int:
    return func(1, 2, 3)  # we don't care about func's signature

# Use 3 — Numpy / slicing: a[..., 0] means "all dimensions up to the last"
# try:
#     import numpy as np
#     arr = np.zeros((3, 4, 5))
#     print(arr[..., 0].shape)  # (3, 4) — Ellipsis fills dimensions
# except ImportError:
#     pass

# Use 4 — Stub files (.pyi) — ... indicates "implementation not shown"
# In .pyi files:
#   def greet(name: str) -> str: ...

# Truthiness — Ellipsis is truthy!
print(bool(...))         # True
print(bool(Ellipsis))    # True
if ...:
    print("Ellipsis is truthy — don't use `if ...:` to mean `if not implemented`")

# Identity check — like None, use `is`
x = ...
if x is Ellipsis:
    print("x is Ellipsis")
if x is ...:
    print("x is ... — same check")
```

### `NotImplemented`

- The sole instance of `types.NotImplementedType`, returned by `__dunder__` methods to signal "I don't know how to handle this type — try the other operand's method."
- **Not** the same as `NotImplementedError` (an exception) or `None`.

```python
# NotImplemented is a singleton
print(NotImplemented)           # NotImplemented
print(NotImplemented is NotImplemented)  # True
print(type(NotImplemented))     # <class 'types.NotImplementedType'>

# Purpose — binary operator fallback
class MyNumber:
    def __init__(self, value: int):
        self.value = value

    def __add__(self, other):
        if isinstance(other, MyNumber):
            return MyNumber(self.value + other.value)
        # "I don't know how to add MyNumber + <other type>"
        return NotImplemented

    def __radd__(self, other):
        # Called when `other + MyNumber` and `other.__add__` returned NotImplemented
        if isinstance(other, int):
            return MyNumber(other + self.value)
        return NotImplemented

    def __repr__(self):
        return f"MyNumber({self.value})"

a = MyNumber(10)
b = MyNumber(20)
print(a + b)        # MyNumber(30) — __add__ handles MyNumber

print(a + 5)        # MyNumber(15) — a.__add__(5) returns NotImplemented,
                    # so Python tries (5).__radd__(a) which is int.__radd__ → NotImplemented,
                    # then tries a.__radd__(5) → MyNumber(15)

# What happens when BOTH sides return NotImplemented:
try:
    result = a + "hello"  # MyNumber.__add__ → NotImplemented, str.__radd__ → NotImplemented
    print(result)
except TypeError as e:
    print(f"TypeError: {e}")  # unsupported operand type(s) for +: 'MyNumber' and 'str'

# NEVER return None where NotImplemented is expected — breaks the protocol
class BadNumber:
    def __add__(self, other):
        if isinstance(other, BadNumber):
            return BadNumber(1)
        return None  # WRONG — should be NotImplemented

# weird = BadNumber() + "hello"  # would return None instead of raising TypeError — silent bug!

# Truthiness — NotImplemented is truthy!
print(bool(NotImplemented))  # True
if NotImplemented:
    print("NotImplemented is truthy — always check with `is`")

# Correct check
value = NotImplemented
if value is NotImplemented:
    print("value is NotImplemented — operator not supported")
```

### Singleton Comparison Table

| Singleton | Type | Spelling | Truthy? | Meaning | Check With |
|---|---|---|---|---|---|
| `None` | `NoneType` | `None` | Falsy | No value / absent | `is None` |
| `Ellipsis` | `ellipsis` | `...` / `Ellipsis` | Truthy | Placeholder / any | `is Ellipsis` / `is ...` |
| `NotImplemented` | `NotImplementedType` | `NotImplemented` | Truthy | Operator not supported | `is NotImplemented` |

> **Do not confuse:**
> - `None` (value) vs `NoneType` (its type) vs `Optional[X]` (type hint meaning `X | None`)
> - `NotImplemented` (singleton for operator fallback) vs `NotImplementedError` (exception to raise)
> - `...` / `Ellipsis` (singleton) vs `pass` (do-nothing statement)

## 4. The Sentinel Pattern — When `None` Is a Valid Value

The most important practical application of singletons. When `None` itself is a legitimate argument or return value, you need a *different* sentinel to mean "not provided."

### The Problem

```python
# Suppose None is a valid value the caller might intentionally pass.
# How do you distinguish "caller passed None" from "caller passed nothing"?

def find_item_bad(items: list, default=None):
    """Find first item — but what if None IS in the list?"""
    for item in items:
        if item is not None:  # skip Nones? But what if we're SEARCHING for None?
            return item
    return default

# Can't distinguish these:
print(find_item_bad([None, 1, 2]))  # 1 — skipped the None we might have wanted
print(find_item_bad([]))            # None — but is this "found None" or "not found"?

# The classic dict.get already solved this — but what about YOUR functions?
```

### The Solution — Private Sentinel Object

```python
# Create a unique sentinel — a plain object with a distinct identity
_MISSING = object()  # each object() call creates a unique instance

def find_first(items: list, default=_MISSING):
    """
    Find first truthy item. If none, return `default` if provided,
    else raise LookupError. Uses sentinel to distinguish
    "no default given" from "default is None".
    """
    for item in items:
        if item:
            return item
    if default is _MISSING:
        raise LookupError("No truthy item found and no default provided")
    return default

# Now all cases are distinguishable:
print(find_first([0, "", "hello", "world"]))  # hello — found
print(find_first([0, "", None], default=None))  # None — explicitly returned None
print(find_first([0, "", None], default="fallback"))  # fallback
try:
    find_first([0, "", None])  # no default, nothing found → raises
except LookupError as e:
    print(f"LookupError: {e}")

# The sentinel's identity is what matters — its value is irrelevant
print(_MISSING)              # <object object at 0x...>
print(_MISSING is None)      # False
print(_MISSING is _MISSING)  # True
print(bool(_MISSING))        # True — object() instances are truthy

# Verify the sentinel is truly unique — no other object() equals it
other = object()
print(_MISSING is other)     # False — different object instances
print(_MISSING == other)     # False — object.__eq__ is identity-based
```

### Sentinel with Type Hints

```python
from typing import Union

_MISSING = object()

# For type checkers, the sentinel needs special handling.
# Option 1 — use `object` as the sentinel type (simple, less precise)
def get_value(
    data: dict[str, str],
    key: str,
    default: Union[str, object] = _MISSING,  # object covers the sentinel
) -> str | None:
    if key in data:
        return data[key]
    if default is _MISSING:
        raise KeyError(f"Key {key!r} not found and no default given")
    # At this point default is str | None (if caller passed str/None)
    assert isinstance(default, (str, type(None)))
    return default

# Option 2 — use a dedicated sentinel class (more type-safe, verbose)
class _MissingType:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
    def __repr__(self):
        return "<MISSING>"

MISSING = _MissingType()

def get_value_typed(
    data: dict[str, str],
    key: str,
    default: str | None | _MissingType = MISSING,
) -> str | None:
    if key in data:
        return data[key]
    if default is MISSING:
        raise KeyError(key)
    return default  # type checker knows this is str | None

print(get_value_typed({"a": "hello"}, "a"))              # hello
print(get_value_typed({"a": "hello"}, "b", default=None)) # None
try:
    get_value_typed({"a": "hello"}, "b")
except KeyError as e:
    print(f"KeyError: {e}")
```

### Standard Library Sentinels

The stdlib uses the same pattern in several places:

```python
import dataclasses

# dataclasses.MISSING — sentinel for "no default"
print(dataclasses.MISSING)           # <dataclasses._MISSING_TYPE object>
print(dataclasses.MISSING is dataclasses.MISSING)  # True

@dataclasses.dataclass
class Config:
    host: str = "localhost"
    port: int = 8080

# Inspecting field defaults — MISSING means "no default"
for field in dataclasses.fields(Config):
    has_default = field.default is not dataclasses.MISSING
    print(f"  {field.name}: has_default={has_default}, default={field.default!r}")

# inspect.Parameter.empty — sentinel for "no default / no annotation"
import inspect

def example(a, b=None, c=42):
    pass

sig = inspect.signature(example)
for name, param in sig.parameters.items():
    has_default = param.default is not inspect.Parameter.empty
    print(f"  {name}: has_default={has_default}, default={param.default!r}")
```

## 5. `Optional` Returns and `None` Handling Patterns

### `Optional[X]` / `X | None` — The Type Hint

```python
from typing import Optional

# These are equivalent (3.10+ prefers X | None):
def find_user_old(user_id: int) -> Optional[str]:  # Optional[str] == str | None
    ...

def find_user_new(user_id: int) -> str | None:     # preferred in 3.10+
    ...

# At runtime, Optional is just Union — no enforcement
def get_name(user_id: int) -> str | None:
    if user_id == 1:
        return "Alice"
    return None

# Caller MUST handle the None case — but nothing forces them at runtime
name = get_name(1)
print(name.upper())  # Alice — OK, but...

name2 = get_name(99)  # None
try:
    print(name2.upper())  # AttributeError: 'NoneType' has no attribute 'upper'
except AttributeError as e:
    print(f"AttributeError: {e} — forgot to check for None!")

# Type checkers (mypy/pyright) WILL flag the unchecked .upper() on str | None:
# error: Item "None" of "str | None" has no attribute "upper"

# Correct handling — explicit check
name3 = get_name(99)
if name3 is not None:
    print(name3.upper())  # only reached if not None — checker is satisfied
else:
    print("No user found")

# Or with walrus (3.8+)
if (name := get_name(99)) is not None:
    print(f"Found: {name.upper()}")
else:
    print("Not found")

# Or assert when you KNOW it should not be None (e.g., after validation)
name4 = get_name(1)
assert name4 is not None  # narrows type for checker; raises if wrong
print(name4.upper())      # checker now knows name4 is str
```

### Patterns for `None` Handling

```python
# 1. Early return / guard clause
def process(data: str | None) -> str:
    if data is None:
        return "default"
    return data.upper()

print(process(None))     # default
print(process("hello"))  # HELLO

# 2. Ternary for simple defaults
def process_ternary(data: str | None) -> str:
    return data.upper() if data is not None else "DEFAULT"

print(process_ternary(None))     # DEFAULT
print(process_ternary("hello"))  # HELLO

# 3. `or` for defaults — ONLY when falsy values aren't valid!
# Dangerous if "" is valid (see Lesson 01.4):
def process_or_bad(data: str | None) -> str:
    return (data or "default").upper()  # "" becomes "default" — maybe wrong!

print(process_or_bad(""))    # DEFAULT — bug if "" was intentional
print(process_or_bad(None))  # DEFAULT

# Safe version — explicit None check
def process_or_safe(data: str | None) -> str:
    actual = data if data is not None else "default"
    return actual.upper()

print(process_or_safe(""))    # "" → "".upper() → "" — respects empty string
print(process_or_safe(None))  # default → DEFAULT

# 4. Unwrapping with `assert` (when invariant guarantees non-None)
def get_first(items: list[str]) -> str:
    first = next(iter(items), None)
    assert first is not None, "items must not be empty"
    return first  # checker knows first is str after assert

print(get_first(["a", "b"]))  # a

# 5. Chaining — safely traverse nested Optional
user_data: dict[str, str | None] | None = {"name": "Alice", "email": None}

# Verbose but safe
if user_data is not None:
    email = user_data.get("email")
    if email is not None:
        print(f"Email: {email.lower()}")
    else:
        print("No email")
else:
    print("No user data")

# Concise with walrus + and/or (use sparingly — can hurt readability)
email_display = (
    user_data.get("email") if user_data is not None else None
)
print(f"Email display: {email_display!r}")

# 6. `Optional` in dataclasses / attrs
from dataclasses import dataclass, field

@dataclass
class User:
    name: str
    email: str | None = None  # optional field — defaults to None
    bio: str | None = None

u1 = User("Alice")
print(u1)  # User(name='Alice', email=None, bio=None)
u2 = User("Bob", email="bob@test.com", bio="Hello!")
print(u2)  # User(name='Bob', email='bob@test.com', bio='Hello!')
```

## 6. `None` in Collections and Comparisons

```python
# None in collections
items = [1, None, 3, None, 5]
print(items)                      # [1, None, 3, None, 5]
print(items.count(None))          # 2
print(None in items)              # True
print([x for x in items if x is not None])  # [1, 3, 5] — filter Nones

# Sorting with None — TypeError! None is not orderable with other types
try:
    print(sorted([3, None, 1, 2]))
except TypeError as e:
    print(f"TypeError: {e}")  # '<' not supported between instances of 'NoneType' and 'int'

# Fix — custom key that handles None
data = [3, None, 1, None, 2]
print(sorted(data, key=lambda x: (x is None, x or 0)))
# [1, 2, 3, None, None] — Nones last (True sorts after False)

# Or filter before sorting
print(sorted(x for x in data if x is not None))  # [1, 2, 3]

# None comparisons — only `is` / `is not` and `==` / `!=` are meaningful
# Ordering comparisons with None always raise TypeError (Python 3):
try:
    print(None < 0)
except TypeError as e:
    print(f"TypeError: {e}")

try:
    print(None > "hello")
except TypeError as e:
    print(f"TypeError: {e}")

# But equality works (always False except None == None):
print(None == None)   # True
print(None != None)   # False
print(None == 0)      # False
print(None == False)  # False
print(None is None)   # True

# None as dict key — valid! (None is hashable and immutable)
d = {None: "no value", "key": "has value"}
print(d[None])        # no value
print(d["key"])       # has value
print(None in d)      # True

# None in sets — also valid
s = {None, 1, 2, None}
print(s)              # {1, 2, None} — one None (set deduplicates)
```

## 7. Realistic Example — Configuration with Sentinels and Optional

```python
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any

# Sentinel for "not configured" — distinct from None ("explicitly set to no value")
_UNSET = object()

@dataclass
class AppConfig:
    """Application configuration where None and 'not set' mean different things."""
    host: str | None = "localhost"  # None means "bind to no host"
    port: int | None = 8080         # None means "no port / use socket"
    debug: bool = False
    # Extra settings — use sentinel to detect "not provided"
    _extra: dict[str, Any] = field(default_factory=dict, repr=False)

    def get(self, key: str, default: Any = _UNSET) -> Any:
        """Get a config value, distinguishing 'not set' from 'set to None'."""
        if key in self._extra:
            return self._extra[key]
        # Check dataclass fields
        if hasattr(self, key):
            return getattr(self, key)
        if default is _UNSET:
            raise KeyError(f"Config key {key!r} not found and no default given")
        return default

    def set(self, key: str, value: Any) -> None:
        """Set a config value (including None as an explicit value)."""
        if hasattr(self, key) and key != "_extra":
            setattr(self, key, value)
        else:
            self._extra[key] = value

    def is_set(self, key: str) -> bool:
        """Check if a key has been explicitly configured (even to None)."""
        return key in self._extra or hasattr(self, key)

# --- Usage ---

# Default config — host/port have values
config = AppConfig()
print(f"Default host: {config.host!r}, port: {config.port!r}")
# Default host: 'localhost', port: 8080

# Explicitly set to None — means "disabled"
config_no_host = AppConfig(host=None, port=None)
print(f"No host: {config_no_host.host!r}, port: {config_no_host.port!r}")
# No host: None, port: None

# Check before using — Optional handling
def start_server(config: AppConfig) -> None:
    host = config.host
    port = config.port

    # Must check Optional before using
    if host is None:
        print("  No host configured — skipping server start")
        return
    if port is None:
        print(f"  Starting server on {host} (no port — using Unix socket)")
        return
    print(f"  Starting server on {host}:{port}")

start_server(config)          # Starting server on localhost:8080
start_server(config_no_host)  # No host configured

# Sentinel distinguishes "not set" from "set to None"
config2 = AppConfig()
config2.set("cache_size", None)  # explicitly set to None — "no cache"
config2.set("timeout", 30)

print(f"\ncache_size: {config2.get('cache_size')!r}")  # None — explicitly None
print(f"timeout: {config2.get('timeout')!r}")          # 30
try:
    config2.get("nonexistent")  # no default → raises
except KeyError as e:
    print(f"nonexistent: KeyError {e}")

print(f"nonexistent with default: {config2.get('nonexistent', default='fallback')!r}")
print(f"nonexistent with None default: {config2.get('nonexistent', default=None)!r}")

# The critical distinction:
#   config.get("cache_size") → None  (was SET to None — "no cache")
#   config.get("nonexistent") → raises  (was NEVER set)
# Without a sentinel, both would return None and be indistinguishable!

# --- Type narrowing in action ---
def connect(config: AppConfig) -> str:
    """Demonstrates type narrowing after `is not None` checks."""
    host: str | None = config.host
    port: int | None = config.port

    if host is None:
        return "Cannot connect: no host"

    # After the check, type checker knows `host` is `str`
    # (without the check, `host.upper()` would be flagged as error)
    host_upper = host.upper()  # OK — narrowed to str

    if port is None:
        return f"Connecting to {host_upper} via socket"

    return f"Connecting to {host_upper}:{port}"

print(f"\n{connect(config)}")          # Connecting to LOCALHOST:8080
print(connect(config_no_host))         # Cannot connect: no host
print(connect(AppConfig(host="example.com", port=None)))
# Connecting to EXAMPLE.COM via socket
```

## 8. Common Mistakes and Pythonic Idioms

| Mistake | Why It Fails | Correct Approach |
|---|---|---|
| `if x == None:` | Hijackable via `__eq__`, slower | `if x is None:` |
| `if not x:` when `x` might be `0`/`""`/`[]` | Falsy valid values treated as missing | `if x is None:` |
| `def f(x=None): if not x: x = []` | `[]`, `0`, `""` also trigger | `if x is None: x = []` |
| `return` vs `return None` confusion | Both return `None`, but intent differs | `return None` for meaningful None; bare `return` for side-effect functions |
| `NotImplemented` vs `NotImplementedError` | Different things — one is a singleton, one is an exception | `return NotImplemented` in `__dunder__`; `raise NotImplementedError` in stubs |
| `...` as "do nothing" without understanding | `...` is the `Ellipsis` object, not `pass` | Both work as no-ops, but `pass` is more explicit for empty blocks |
| Using `None` as sentinel when `None` is valid input | Can't distinguish "not given" from "given None" | `sentinel = object()` + `is` check |

**Pythonic idioms:**

```python
# Singleton checks — always `is` / `is not`
if x is None:
    handle_missing()
if x is not None:
    handle_present(x)

# Sentinel pattern — when None is valid
_SENTINEL = object()
def func(value=_SENTINEL):
    if value is _SENTINEL:
        value = default_value()
    ...

# Optional unwrapping — explicit over implicit
if (result := maybe_none()) is not None:
    use(result)

# Filtering Nones from a collection
clean = [x for x in items if x is not None]
# Or: clean = list(filter(None, items))  # but this also removes 0, "", etc.!

# Assert narrowing for type checkers
assert x is not None  # after this, checker knows x is not None
x.method()            # safe

# Dataclass optional fields
@dataclass
class Item:
    name: str
    description: str | None = None  # 3.10+ syntax
```

---

## 9. Summary

- **`None` is the singleton instance of `NoneType`** — falsy, hashable, the default return value, and the universal "no value" marker. It is not `False`, `0`, or `""`.
- **Always use `is None` / `is not None`** — never `== None`. Identity cannot be hijacked by `__eq__` overrides and is faster.
- **`Ellipsis` (`...`)** is a truthy singleton used as a placeholder in stubs, type hints (`Callable[..., int]`), and `numpy` slicing. Check with `is Ellipsis`.
- **`NotImplemented`** is a truthy singleton for `__dunder__` operator fallback — `return NotImplemented` means "try the other operand." Do not confuse it with `raise NotImplementedError`.
- **The sentinel pattern** (`_SENTINEL = object()` + `is` check) is essential when `None` is itself a valid value and you need to distinguish "not provided" from "provided as None." The stdlib uses the same pattern (`dataclasses.MISSING`, `inspect.Parameter.empty`).
- **`Optional[X]` / `X | None`** means the value might be `None` — callers must check with `is not None` before using it. Type checkers enforce this; the runtime does not.
- **`None` in collections** is valid (hashable, can be a `dict` key) but not orderable — `sorted` with `None` raises `TypeError`.

> **Key takeaway:** `None` is a real object with a clear meaning: "no value." Respect its singularity by checking identity (`is None`), handle `Optional` returns explicitly, and reach for the sentinel pattern whenever `None` itself is a legitimate value that must be distinguished from absence.
