# 01.8 Mutability and Immutability

> **Mental model:** Immutable objects are *values* — like the number 42, they never change; operations on them produce new values. Mutable objects are *containers* — like a box, they stay the same box but their contents can change. This distinction determines aliasing behaviour, hashability, default-argument safety, and whether `id()` changes.

---

## 1. The Two Families

### Immutable Types — Value Semantics

Once created, the object's value never changes. Any "modification" creates a new object.

| Type | Example | Notes |
|---|---|---|
| `int` | `42`, `10_000` | Arbitrary precision, never mutates |
| `float` | `3.14` | IEEE 754, never mutates |
| `complex` | `3+4j` | Both parts are floats |
| `bool` | `True`, `False` | Subclass of `int` |
| `str` | `"hello"` | Sequence of code points |
| `bytes` | `b"hello"` | Sequence of 0–255 |
| `tuple` | `(1, 2, 3)` | Ordered, heterogeneous |
| `frozenset` | `frozenset({1,2})` | Immutable set |
| `NoneType` | `None` | Singleton |
| `ellipsis` | `...` | Singleton |

### Mutable Types — Container Semantics

The object's contents can change in place. The container identity stays the same.

| Type | Example | Notes |
|---|---|---|
| `list` | `[1, 2, 3]` | Ordered, heterogeneous |
| `dict` | `{"a": 1}` | Key-value mapping |
| `set` | `{1, 2, 3}` | Unordered, unique elements |
| `bytearray` | `bytearray(b"hi")` | Mutable bytes |
| `memoryview` | `memoryview(b"hi")` | View (if writable) |

```python
# Immutable — operations create NEW objects
s = "hello"
print(id(s))
s2 = s.upper()
print(id(s2) == id(s))  # False — new object
print(s)                 # hello — original unchanged

n = 42
print(id(n))
n2 = n + 1
print(id(n2) == id(n))  # False — new int
print(n)                 # 42 — original unchanged

t = (1, 2, 3)
# t[0] = 99  # TypeError: 'tuple' object does not support item assignment

# Mutable — operations can modify IN PLACE
lst = [1, 2, 3]
print(id(lst))
lst.append(4)
print(id(lst))           # SAME id — mutated in place
print(lst)               # [1, 2, 3, 4] — same object, new contents

d = {"a": 1}
old_id = id(d)
d["b"] = 2
print(id(d) == old_id)   # True — same dict
print(d)                 # {'a': 1, 'b': 2}

ba = bytearray(b"hello")
ba[0] = 72               # mutate a byte
print(ba)                # bytearray(b'Hello') — same object
```

## 2. `id()` Changes — The Observable Difference

The most direct way to see mutability: does `id()` change after an "update"?

```python
# Immutable — id ALWAYS changes on "modification"
x = 1000
old = id(x)
x += 1                   # x = x + 1 → new int, rebound
print(id(x) == old)      # False — new object

s = "hello"
old = id(s)
s += " world"            # new string, rebound
print(id(s) == old)      # False

t = (1, 2, 3)
old = id(t)
t += (4,)                # new tuple, rebound (t = t + (4,))
print(id(t) == old)      # False

# Mutable — id STAYS THE SAME for in-place operations
lst = [1, 2, 3]
old = id(lst)
lst += [4]               # list.__iadd__ — mutates in place
print(id(lst) == old)    # True — same list!

lst2 = [1, 2, 3]
old2 = id(lst2)
lst2.append(4)           # in-place mutation
print(id(lst2) == old2)  # True

d = {"a": 1}
old = id(d)
d.update({"b": 2})       # in-place
print(id(d) == old)      # True

# BUT — rebinding STILL changes id even for mutables
lst = [1, 2, 3]
old = id(lst)
lst = lst + [4]          # lst + [4] creates NEW list, then rebinds name
print(id(lst) == old)    # False — new list via concatenation
# `+=` vs `+` is the key: += tries in-place (__iadd__), + always creates new

# Demonstrate += vs + for lists
a = [1, 2]
b = a                    # alias — same list
a += [3]                 # in-place → b sees the change!
print(a, b)              # [1, 2, Cari, 3] [1, 2, 3] — both changed (same object)

a = [1, 2]
b = a
a = a + [3]              # new list → b unaffected
print(a, b)              # [1, 2, 3] [1, 2] — b still old list
```

## 3. Aliasing and Sharing — Where Mutability Bites

### Immutable Sharing Is Safe

```python
# Sharing immutables is harmless — neither alias can mutate the shared value
a = 1000
b = a            # both → same int object
print(a is b)    # True — same object (or may share via interning)

# "Modifying" a creates a new object — b is unaffected
a += 1
print(a, b)      # 1001 1000 — b still 1000
print(a is b)    # False — now different objects

# Same for strings and tuples
s1 = "hello"
s2 = s1
s1 += " world"   # new string
print(s1, s2)    # hello world  hello — s2 unchanged

t1 = (1, 2, 3)
t2 = t1
t1 += (4,)       # new tuple
print(t1, t2)    # (1, 2, 3, 4)  (1, 2, 3) — t2 unchanged

# This is why immutable defaults are safe (see Default Argument section)
def good_func(value="default"):
    return value.upper()
# Each call gets the same "default" string object, but no call can mutate it.
```

### Mutable Sharing Is Dangerous

```python
# Sharing mutables means mutations are visible through ALL aliases
original = [1, 2, 3]
alias = original          # NOT a copy — same list
alias.append(4)
print(original)           # [1, 2, 3, 4] — original mutated!

# Dict aliasing
config = {"host": "localhost", "tags": ["prod"]}
backup = config           # alias
backup["host"] = "remote"
backup["tags"].append("canary")
print(config)
# {'host': 'remote', 'tags': ['prod', 'canary']} — both mutated!

# Function arguments — the caller's object can be mutated
def add_tag(tags: list[str], tag: str) -> None:
    tags.append(tag)  # mutates the caller's list!

my_tags = ["prod"]
add_tag(my_tags, "canary")
print(my_tags)  # ['prod', 'canary'] — mutated behind your back

# Defensive — copy if you must not mutate the input
def add_tag_safe(tags: list[str], tag: str) -> list[str]:
    new_tags = tags.copy()  # or list(tags) or tags[:]
    new_tags.append(tag)
    return new_tags

my_tags = ["prod"]
result = add_tag_safe(my_tags, "canary")
print(my_tags)  # ['prod'] — safe
print(result)   # ['prod', 'canary']

# Nested structures — shallow copy is NOT enough
import copy

nested = {"a": [1, 2], "b": [3, 4]}
shallow = nested.copy()          # or dict(nested)
shallow["a"].append(99)
print(nested)  # {'a': [1, 2, 99], 'b': [3, 4]} — inner list shared!

deep = copy.deepcopy(nested)
deep["a"].append(100)
print(nested)  # {'a': [1, 2, 99], 'b': [3, 4]} — deep copy isolated
print(deep)    # {'a': [1, 2, 99, 100], 'b': [3, 4]}
```

### The Tuple Wrinkle — Immutable Container, Mutable Contents

A `tuple` is immutable — you cannot reassign its slots — but if those slots hold mutable objects, the *contents* of those objects can still change. The tuple's *structure* is frozen, not the *values* inside.

```python
# Tuple with mutable element — the tuple is immutable, the list inside is not
t = ([1, 2], [3, 4])
print(t)         # ([1, 2], [3, 4])
# t[0] = [9, 9]  # TypeError — cannot reassign tuple slot
t[0].append(99)  # BUT this works — mutating the list INSIDE the tuple
print(t)         # ([1, 2, 99], [3, 4]) — tuple "changed" via its mutable contents!

# This means tuples containing mutables are NOT hashable
try:
    hash(t)
except TypeError as e:
    print(f"TypeError: {e}")  # unhashable type: 'list'

# Purely immutable tuple — hashable
pure = (1, 2, "hello", (3, 4))
print(hash(pure))  # succeeds — all elements immutable and hashable
print(pure in {(1, 2): "value"})  # tuples as dict keys — works when hashable

# frozenset similarly — immutable set, but elements must be hashable
fs = frozenset([1, 2, 3])
print(hash(fs))  # OK
# frozenset([[1, 2]])  # TypeError — list inside frozenset is unhashable

# Lesson: "immutable" means the container's references don't change,
# not that the referenced objects are frozen. True deep immutability
# requires all nested objects to also be immutable.
```

## 4. Hashability — Why It Follows from Immutability

An object is **hashable** if it has a hash value that never changes during its lifetime, allowing it to be used as a `dict` key or `set` member.

- Hashable objects must be immutable (or at least their hash-relevant state must be immutable).
- Mutable objects are unhashable — their contents could change, invalidating the hash table.

```python
# Hashable (immutable) — can be dict keys / set members
print(hash(42))              # OK
print(hash("hello"))         # OK
print(hash((1, 2, 3)))       # OK — tuple of immutables
print(hash(frozenset({1,2})))# OK
print(hash(None))            # OK
print(hash(b"bytes"))        # OK
print(hash(3.14))            # OK

# Unhashable (mutable) — TypeError
for obj in [[1,2], {"a": 1}, {1,2}, bytearray(b"hi")]:
    try:
        hash(obj)
    except TypeError as e:
        print(f"  {type(obj).__name__} {obj!r} → TypeError: {e}")

# Tuple with mutable element — unhashable
try:
    hash(([1, 2],))
except TypeError as e:
    print(f"  tuple with list → TypeError: {e}")

# Dict keys and set members — must be hashable
valid_dict = {
    "str_key": 1,            # str — hashable
    42: 2,                   # int — hashable
    (1, 2): 3,               # tuple — hashable
    frozenset({1, 2}): 4,    # frozenset — hashable
}
print(valid_dict)

valid_set = {"hello", 42, (1, 2), frozenset({3, 4})}
print(valid_set)

# The hash-equality contract:
# If a == b, then hash(a) == hash(b) must hold.
# This is why hash must not change — if a dict key mutated and its hash changed,
# the dict could no longer find it!
print(hash("hello") == hash("hello"))  # True
print(hash(42) == hash(42.0))          # True — 42 == 42.0, so hashes equal (usually)

# Custom objects — hashable by default (identity-based), but defining __eq__
# without __hash__ makes them unhashable
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __eq__(self, other):
        return isinstance(other, Point) and self.x == other.x and self.y == other.y
    # No __hash__ defined → unhashable!

p = Point(1, 2)
try:
    hash(p)
except TypeError as e:
    print(f"  Point with __eq__ but no __hash__ → TypeError: {e}")
    # Must define __hash__ explicitly (and ensure immutability!)

class HashablePoint:
    def __init__(self, x, y):
        self._x, self._y = x, y
    @property
    def x(self): return self._x
    @property
    def y(self): return self._y
    def __eq__(self, other):
        return isinstance(other, HashablePoint) and self.x == other.x and self.y == other.y
    def __hash__(self):
        return hash((self.x, self.y))
    def __repr__(self):
        return f"HashablePoint({self.x}, {self.y})"

hp = HashablePoint(1, 2)
print(hash(hp))              # OK
print({hp: "value"}[hp])     # value — usable as dict key
```

## 5. The Mutable Default Argument Pitfall

The single most notorious Python gotcha — and a direct consequence of mutability + how `def` works.

### The Bug

```python
# BROKEN — default list created ONCE at function definition time, shared across calls
def append_to_bad(value, target=[]):
    target.append(value)
    return target

print(append_to_bad(1))  # [1]
print(append_to_bad(2))  # [1, 2] — surprise! Same list, not a fresh one
print(append_to_bad(3))  # [1, 2, 3] — keeps growing
print(append_to_bad(1, target=[10]))  # [10, 1] — explicit arg works (new list)
print(append_to_bad(4))  # [1, 2, 3, 4] — back to the shared default!

# Why? `def` is executable — `target=[]` creates ONE list when the `def` statement runs.
# That single list object is stored in append_to_bad.__defaults__ and reused
# for every call that doesn't pass `target`.

# Inspect the defaults
print(append_to_bad.__defaults__)  # ([1, 2, 3, 4],) — the shared list!

# Same bug with dict and set
def add_user_bad(name, registry={}):
    registry[name] = True
    return registry

print(add_user_bad("Alice"))  # {'Alice': True}
print(add_user_bad("Bob"))    # {'Alice': True, 'Bob': True} — shared!

def add_tag_bad(tag, tags=set()):
    tags.add(tag)
    return tags
```

### The Fix — `None` Sentinel

```python
# CORRECT — use None as sentinel, create new mutable inside the function
def append_to_good(value, target=None):
    if target is None:
        target = []       # new list EACH call
    target.append(value)
    return target

print(append_to_good(1))  # [1]
print(append_to_good(2))  # [1] — independent!
print(append_to_good(3, target=[10]))  # [10, 3] — explicit still works

# Same fix for dict
def add_user_good(name, registry=None):
    if registry is None:
        registry = {}
    registry[name] = True
    return registry

print(add_user_good("Alice"))  # {'Alice': True}
print(add_user_good("Bob"))    # {'Bob': True} — independent

# Same fix for set
def add_tag_good(tag, tags=None):
    if tags is None:
        tags = set()
    tags.add(tag)
    return tags

# For dataclasses — use default_factory
from dataclasses import dataclass, field

@dataclass
class TeamBad:
    members: list[str] = []  # WRONG — shared list! (dataclasses will actually error/warn)

@dataclass
class TeamGood:
    members: list[str] = field(default_factory=list)  # CORRECT — new list per instance

t1 = TeamGood()
t1.members.append("Alice")
t2 = TeamGood()
print(t1.members)  # ['Alice']
print(t2.members)  # [] — independent (correct)

# When you DO want a shared default (rare) — document it explicitly
# and consider whether a module-level constant is clearer:
_DEFAULT_TAGS: list[str] = []  # intentional singleton — but usually still wrong
```

### Why Immutable Defaults Are Safe

```python
# Immutable defaults — no aliasing hazard, safe to share
def greet(name, greeting="Hello"):  # str is immutable — safe
    return f"{greeting}, {name}!"

def count(value, start=0):          # int is immutable — safe
    return start + value

def configure(host="localhost", port=8080):  # all immutables — safe
    return f"{host}:{port}"

# Even tuple defaults are safe (if they contain only immutables)
def process(items=()):              # empty tuple — safe (immutable)
    return list(items)

# Tuple with mutable inside — STILL dangerous despite tuple being "immutable"!
def tricky(items=([],)):            # tuple containing a list — the list IS mutable!
    items[0].append(1)
    return items

print(tricky())  # ([1],)
print(tricky())  # ([1, 1],) — the inner list is shared!
# Fix: don't nest mutables in defaults — use None sentinel for the outer too.
```

## 6. Copying — Shallow vs Deep

When you need independence from the original, you must copy. The type of copy depends on nesting.

```python
import copy

# === Shallow copy — new outer container, but inner objects still shared ===

# For lists
original = [1, 2, 3]
shallow1 = original.copy()       # or list(original) or original[:] or copy.copy(original)
print(shallow1 is original)      # False — different list
print(shallow1 == original)      # True — same contents
print(shallow1[0] is original[0])# True — elements still shared (but ints are immutable, so safe)

# For dicts
d = {"a": 1, "b": 2}
shallow_d = d.copy()             # or dict(d) or copy.copy(d)
print(shallow_d is d)            # False

# For sets
s = {1, 2, 3}
shallow_s = s.copy()             # or set(s) or copy.copy(s)
print(shallow_s is s)            # False

# Shallow copy is sufficient when elements are immutable
# (which is the common case for flat lists/dicts of strings/numbers)

# === When shallow copy FAILS — nested mutables ===

nested = {"a": [1, 2], "b": {"x": 10}}
shallow = nested.copy()
print(f"Before: nested={nested}")

# Top-level key — shallow copy IS independent
shallow["c"] = "new"
print(f"After adding key: nested has 'c'? {'c' in nested}")  # False — independent

# Nested mutable — shallow copy STILL SHARED
shallow["a"].append(99)
print(f"After shallow['a'].append(99): nested={nested}")
# nested is {'a': [1, 2, 99], ...} — inner list was shared!

shallow["b"]["x"] = 999
print(f"After shallow['b']['x']=999: nested={nested}")
# nested is {'a': [1, 2, 99], 'b': {'x': 999}} — inner dict shared!

# === Deep copy — fully independent clone ===

nested2 = {"a": [1, 2], "b": {"x": 10}}
deep = copy.deepcopy(nested2)
deep["a"].append(99)
deep["b"]["x"] = 999
print(f"After deep mutation: nested2={nested2}")  # {'a': [1, 2], 'b': {'x': 10}} — untouched!
print(f"deep={deep}")                              # {'a': [1, 2, 99], 'b': {'x': 999}}

# === Visualising the difference ===

# Original:  nested ──► {"a" ──► [1, 2],  "b" ──► {"x": 10}}
#
# Shallow:   shallow ──► {"a" ──► SAME [1,2],  "b" ──► SAME {"x":10}}
#                        (new dict, but arrows point to same inner objects)
#
# Deep:      deep ──► {"a" ──► NEW [1, 2],  "b" ──► NEW {"x": 10}}
#                        (new dict AND new inner objects)

# === Performance note ===
# deepcopy is expensive — it must recursively traverse and copy everything,
# handling cycles. Use it only when you need full independence of nested structures.
# For flat collections of immutables, shallow copy is sufficient and much faster.

# === Other copy idioms ===
lst = [1, 2, 3]
print(lst[:])                    # slice copy — idiomatic for lists
print(list(lst))                 # constructor copy
print([*lst])                    # unpacking copy (3.5+)
print(copy.copy(lst))            # explicit shallow copy

# For custom objects — define __copy__ and __deepcopy__ if needed
class MyContainer:
    def __init__(self, items):
        self.items = items
    def __copy__(self):
        return MyContainer(self.items.copy())
    def __deepcopy__(self, memo):
        return MyContainer(copy.deepcopy(self.items, memo))
```

## 7. Implications for Function Design

### Mutating vs Non-Mutating APIs

```python
# Python's conventions:
# - Methods that MUTATE return None (to make it obvious they mutated in place)
# - Functions/methods that DON'T mutate return a new value

# Mutating — return None
lst = [3, 1, 2]
result = lst.sort()
print(result)   # None — sort mutated lst in place
print(lst)      # [1, 2, 3]

result = lst.append(4)
print(result)   # None
print(lst)      # [1, 2, 3, 4]

result = lst.reverse()
print(result)   # None

d = {"b": 2, "a": 1}
result = d.update({"c": 3})
print(result)   # None

# Non-mutating — return new value
nums = [3, 1, 2]
result = sorted(nums)    # new list, original unchanged
print(result)   # [1, 2, 3]
print(nums)     # [3, 1, 2] — untouched

text = "hello"
result = text.upper()    # new string
print(result)   # HELLO
print(text)     # hello

# This convention prevents a common mistake:
# lst = [3, 1, 2].sort()  # BUG — lst is None! sort() returns None
# Correct:
# lst = [3, 1, 2]
# lst.sort()
# or: lst = sorted([3, 1, 2])
```

### Designing Functions That Handle Mutability Safely

```python
# BAD — mutates the caller's data without warning
def normalise_bad(items: list[str]) -> None:
    for i in range(len(items)):
        items[i] = items[i].strip().lower()

# GOOD — option A: mutate explicitly, document it, return None
def normalise_inplace(items: list[str]) -> None:
    """Normalise items IN PLACE. Modifies the input list."""
    for i in range(len(items)):
        items[i] = items[i].strip().lower()

# GOOD — option B: don't mutate, return new list
def normalise_copy(items: list[str]) -> list[str]:
    """Return a new list with normalised items. Input is not modified."""
    return [s.strip().lower() for s in items]

# GOOD — option C: let the caller choose
def normalise(items: list[str], *, inplace: bool = False) -> list[str] | None:
    """
    Normalise items. If inplace, modifies `items` and returns None.
    Otherwise returns a new list.
    """
    normalised = [s.strip().lower() for s in items]
    if inplace:
        items[:] = normalised  # mutate via slice assignment
        return None
    return normalised

# Usage
data = ["  Hello ", " WORLD "]
print(normalise(data))        # ['hello', 'world'] — new list, data unchanged
print(data)                   # ['  Hello ', ' WORLD '] — original safe

normalise(data, inplace=True)
print(data)                   # ['hello', 'world'] — mutated in place
```

## 8. Realistic Example — Configuration Manager

```python
import copy

# Module-level defaults — immutable where possible, but some mutables are needed
DEFAULT_CONFIG: dict = {
    "host": "localhost",
    "port": 8080,
    "tags": frozenset({"production"}),  # frozenset — immutable alternative to set
    "limits": (100, 200),               # tuple — immutable alternative to list
    "metadata": {"version": "1.0"},     # dict — mutable, needs careful handling
}

class ConfigManager:
    """
    Manages configuration with safe copy semantics.

    Demonstrates: mutability, hashing, default arguments, shallow vs deep copy,
    and the frozenset/tuple immutable alternatives.
    """

    def __init__(self, overrides: dict | None = None):
        # CORRECT — None sentinel, deep copy to isolate from DEFAULT_CONFIG
        # Shallow copy would share the inner "metadata" dict!
        self._config: dict = copy.deepcopy(DEFAULT_CONFIG)

        if overrides is not None:
            # Must also handle nested mutables in overrides
            for key, value in overrides.items():
                self._config[key] = copy.deepcopy(value)

    def get(self, key: str, default=None):
        return self._config.get(key, default)

    def set(self, key: str, value) -> None:
        # Deep copy the value to prevent aliasing with caller's object
        self._config[key] = copy.deepcopy(value)

    def add_tag(self, tag: str) -> None:
        """
        Add a tag. Must handle the frozenset → set conversion since
        frozenset is immutable.
        """
        current: frozenset[str] = self._config["tags"]
        # frozenset has no .add — create a new frozenset
        self._config["tags"] = current | frozenset({tag})
        # Alternatively, store as set internally if mutation is frequent:
        # self._config["tags"] = set(current) | {tag}

    def snapshot(self) -> dict:
        """Return an independent snapshot of the current config."""
        return copy.deepcopy(self._config)

    def __repr__(self) -> str:
        return f"ConfigManager({self._config!r})"


# --- Demonstration ---

# Two managers — fully independent
mgr1 = ConfigManager()
mgr2 = ConfigManager()

# Mutating one doesn't affect the other or the default
mgr1.add_tag("canary")
mgr1.set("metadata", {"version": "2.0", "extra": True})

print(f"mgr1 tags: {mgr1.get('tags')}")           # frozenset({'production', 'canary'})
print(f"mgr2 tags: {mgr2.get('tags')}")           # frozenset({'production'}) — unaffected
print(f"DEFAULT tags: {DEFAULT_CONFIG['tags']}")  # frozenset({'production'}) — untouched
print(f"mgr1 metadata: {mgr1.get('metadata')}")   # {'version': '2.0', 'extra': True}
print(f"mgr2 metadata: {mgr2.get('metadata')}")   # {'version': '1.0'} — unaffected
print(f"DEFAULT metadata: {DEFAULT_CONFIG['metadata']}")  # {'version': '1.0'} — untouched

# Snapshot — also independent
snap = mgr1.snapshot()
snap["metadata"]["version"] = "9.9"
print(f"After snap mutation, mgr1 metadata: {mgr1.get('metadata')}")
# {'version': '2.0', 'extra': True} — snapshot didn't affect mgr1

# Hashability — frozenset and tuple configs can be dict keys
config_key = (frozenset({"a", "b"}), (100, 200))
cache: dict[tuple, str] = {config_key: "cached_result"}
print(f"Cache hit: {cache[config_key]}")

# Aliasing trap avoided — passing a mutable to set()
external_tags = ["external", "tags"]
mgr3 = ConfigManager(overrides={"tags": set(external_tags)})
external_tags.append("injected")
print(f"mgr3 tags after external mutation: {mgr3.get('tags')}")
# frozenset({'external', 'tags'}) — "injected" NOT present (deep copied)
```

## 9. Common Mistakes and Pythonic Idioms

| Mistake | Why It Fails | Fix |
|---|---|---|
| `def f(x=[])` | Shared mutable default | `def f(x=None): if x is None: x = []` |
| `b = a` then mutating `b` expecting `a` unchanged | Alias, not copy | `b = a.copy()` / `copy.deepcopy(a)` |
| `lst.sort()` expecting a return value | Returns `None` (in-place) | `sorted(lst)` for a new list |
| `hash([1,2])` | Lists are unhashable | Use `tuple([1,2])` or `frozenset` |
| `([1,2],)` as dict key | Contains mutable list → unhashable | `((1,2),)` or `(frozenset(...),)` |
| `+=` vs `+` confusion for lists | `+=` mutates, `+` creates new | Know which you need; `+=` affects aliases |
| Assuming `tuple` is deeply immutable | Mutable elements inside can change | Ensure all nested elements are immutable too |
| `copy()` when `deepcopy()` needed | Inner mutables still shared | `copy.deepcopy()` for nested structures |

**Pythonic idioms:**

```python
# Safe mutable defaults
def func(items=None):
    if items is None:
        items = []
    ...

# In dataclasses
from dataclasses import field
@dataclass
class Foo:
    items: list = field(default_factory=list)

# Copying
shallow = original.copy()              # or list(original), dict(original)
deep = copy.deepcopy(original)         # for nested mutables

# Immutable alternatives for dict keys / set members
key = (frozenset(tags), tuple(limits)) # hashable composite key

# In-place vs new — follow the convention
# Mutating methods return None:
lst.sort()          # sort in place
lst.append(x)       # add in place
# Non-mutating functions return new values:
new = sorted(lst)   # new sorted list
new = lst + [x]     # new list

# Slice assignment for in-place replacement
lst[:] = new_values  # mutate lst to contain new_values (preserves identity/aliases)
```

## 10. Summary

- **Immutable** (`int`/`str`/`tuple`/etc.) — value never changes; operations create new objects (`id` changes); safe to share/alias; hashable (usable as `dict` keys / `set` members).
- **Mutable** (`list`/`dict`/`set`/etc.) — contents can change in place (`id` stays the same for in-place ops); aliasing means mutations are visible through all names; unhashable.
- **`tuple` is shallowly immutable** — its slots can't be reassigned, but mutable elements inside can still be mutated. Only tuples of hashable (deeply immutable) elements are themselves hashable.
- **Hashability requires immutability** — if `a == b` then `hash(a) == hash(b)` must hold, so hash-relevant state must not change. Use `frozenset` and `tuple` as immutable alternatives to `set` and `list` when hashability is needed.
- **Mutable default arguments** are created once at `def` time and shared — always use `None` + creation inside the function (or `field(default_factory=...)` in dataclasses).
- **Copying:** `copy()` / `list()` / `dict()` for shallow (sufficient for flat collections of immutables); `copy.deepcopy()` for nested mutables.
- **API convention:** In-place mutating methods return `None`; non-mutating operations return new values. Follow this in your own APIs.

> **Key takeaway:** Mutability determines whether an object is a *value* (immutable, freely shared, hashable) or a *container* (mutable, aliased, unhashable). Internalise this, and you will understand aliasing bugs, know when to copy, choose the right default-argument pattern, and design APIs that make mutation explicit.
