# 01.3 Numbers

> **Mental model:** Python has no separate "primitive" numeric types. Every number is a heap object with arbitrary-precision integers, IEEE 754 floats, and first-class complex support — plus standard-library types that trade performance for correctness when you need it.

Programmers coming from languages with fixed-width `int`/`long`/`float`/`double` often assume overflow, truncation, and silent precision loss are inevitable. In Python, `int` never overflows, `float` follows IEEE 754 exactly, and `Decimal`/`Fraction` exist for when neither is sufficient.

---

## 1. `int` — Arbitrary-Precision Integers

### No Fixed Width, No Overflow

Python's `int` (called `PyLong` in CPython's C internals) uses a variable-length array of 30-bit "digits" (or 15-bit on some builds). It grows as large as memory allows.

```python
# Small ints look ordinary
x = 42
print(type(x))        # <class 'int'>
print(x.bit_length()) # 6

# But they can grow without bound — no int32/int64 overflow
huge = 2 ** 1000
print(huge)           # 107150860718626732094842504906000181056140...
print(len(str(huge))) # 302 digits
print(huge.bit_length())  # 1001

# Factorials that would overflow in C are trivial
import math
print(math.factorial(100))  # 933262154439...000000 (158 digits)
print(len(str(math.factorial(1000))))  # 2568 digits — still just an int

# Shifting never loses bits either
print(1 << 1000)  # same as 2**1000
```

> **Performance note:** Small ints (fitting in one or two machine words) are fast — CPython has optimised paths. Very large ints (thousands of digits) use Karatsuba and FFT multiplication internally, but are still slower than native machine-word arithmetic. For tight numeric loops over bounded ranges, `numpy` with fixed-width dtypes is faster.

### Integer Literals — Bases and Underscores

```python
# Decimal (default)
count = 1_000_000        # underscores are visual separators — ignored by parser
print(count)             # 1000000
big = 1_000_000_000_000  # grouping like 1,000,000,000,000
print(big)

# Underscores can appear between digits and after base prefixes — but not
# at the start/end, not adjacent to each other, and not next to a decimal point.
# Valid:   0x_FF_FF, 1_0.0_1 (but unusual) — actually 1_0.0_1 is invalid!
# Let's see what IS valid:
valid = 0xCAFE_BABE
print(hex(valid))        # 0xcafebabe
# Invalid examples (SyntaxError):
# _100, 100_, 1__0, 0x_100, 100._0

# Hexadecimal (base 16) — prefix 0x or 0X
hex_val = 0xFF
hex_val2 = 0XCAFE
print(hex_val)           # 255
print(hex_val2)          # 51966
print(hex(255))          # '0xff' — hex() builtin

# Binary (base 2) — prefix 0b or 0B
bin_val = 0b1010
print(bin_val)           # 10
print(bin(10))           # '0b1010'

flags = 0b1101_0010       # underscores work in non-decimal too
print(f"{flags:08b}")    # 11010010

# Octal (base 8) — prefix 0o or 0O (NOT leading zero like C!)
oct_val = 0o17
print(oct_val)           # 15
print(oct(15))           # '0o17'
# 017 in Python is just 17 — NOT octal. Must use 0o prefix.

# Arbitrary base via int(string, base)
print(int("FF", 16))     # 255
print(int("1010", 2))    # 10
print(int("77", 8))      # 63
print(int("ZZ", 36))     # 1295 — base up to 36 (0-9 + A-Z)

# int() with base 0 auto-detects prefix
print(int("0xFF", 0))    # 255 — detects 0x
print(int("0b1010", 0))  # 10  — detects 0b
print(int("0o17", 0))    # 15  — detects 0o
print(int("42", 0))      # 42  — no prefix → decimal
```

### Integer Operations

```python
# Arithmetic — all produce ints (except / which produces float)
a, b = 17, 5
print(a + b)    # 22
print(a - b)    # 12
print(a * b)    # 85
print(a ** b)   # 1419857 — exponentiation (right-associative: 2**3**2 == 2**(3**2) == 512)
print(a / b)    # 3.4 — true division ALWAYS returns float, even for evenly divisible ints
print(a // b)   # 3 — floor division (round toward -infinity)
print(a % b)    # 2 — modulo (sign follows divisor in Python)
print(divmod(a, b))  # (3, 2) — quotient and remainder together

# Floor division vs truncation — critical for negatives!
print(-7 // 3)   # -3 — floor toward -infinity (not -2)
print(-7 % 3)    # 2  — because -7 == (-3)*3 + 2
print(7 // -3)   # -3
print(7 % -3)    # -2 — sign follows divisor
# In C/Java, -7/3 truncates to -2 and -7%3 is -1. Python floors — know the difference!

# Bitwise (ints are conceptually infinite-width two's complement)
x = 0b1010  # 10
y = 0b1100  # 12
print(f"{x & y:04b}")  # 1000 — AND
print(f"{x | y:04b}")  # 1110 — OR
print(f"{x ^ y:04b}")  # 0110 — XOR
print(f"{~x:04b}")     # -1011 — NOT (infinite leading 1s → negative!)
print(f"{x << 2:08b}") # 00101000 — left shift
print(f"{x >> 1:04b}") # 0101 — right shift (arithmetic — sign extended)

# Bit length and byte conversion
n = 255
print(n.bit_length())              # 8
print(n.to_bytes(2, "big"))        # b'\x00\xff'
print(int.from_bytes(b'\x00\xff', "big"))  # 255
```

## 2. `float` — IEEE 754 Double Precision

Python's `float` is a C `double` — 64-bit IEEE 754 binary floating point (1 sign bit, 11 exponent bits, 52 mantissa bits). It is **not** arbitrary precision.

```python
import sys
print(sys.float_info)
# sys.float_info(max=1.7976931348623157e+308, max_exp=1024,
#   max_10_exp=308, min=2.2250738585072014e-308, min_exp=-1021,
#   min_10_exp=-307, dig=15, mant_dig=53, epsilon=2.220446049250313e-16, ...)

f = 3.14
print(type(f))        # <class 'float'>
print(f.hex())        # 1.91eb851eb851fp+1 — exact hex representation

# Float literals
a = 3.14              # decimal
b = 3.14e10           # scientific: 3.14 × 10¹⁰
c = 3.14E-5           # 3.14 × 10⁻⁵
d = 1_000.5           # underscores allowed
e = float("inf")      # infinity
f = float("-inf")     # negative infinity
g = float("nan")      # not-a-number
print(a, b, c, d, e, f, g)
```

### The `0.1 + 0.2` Problem — And Why It's Not a Python Bug

```python
# The most famous floating-point surprise
print(0.1 + 0.2)          # 0.30000000000000004 — not 0.3!
print(0.1 + 0.2 == 0.3)   # False

# Why? 0.1 cannot be represented exactly in binary floating point.
# Just as 1/3 = 0.333... in decimal, 1/10 = 0.0001100110011... in binary.
print(f"{0.1:.55f}")  # 0.1000000000000000055511151231257827021181583404541015625
print(f"{0.2:.55f}")  # 0.200000000000000011102230546251...
print(f"{0.3:.55f}")  # 0.299999999999999991118215802998...

# Python DISPLAYS floats nicely (shortest round-trip representation since 3.1)
# but the stored value is still imprecise.
print(0.1)  # 0.1 — looks exact, but isn't stored exactly
print(format(0.1, ".17g"))  # 0.10000000000000001 — closer to truth
print(0.1.hex())            # 0x1.999999999999ap-4 — exact value

# NEVER compare floats with ==
# Instead, use tolerance:
import math
print(math.isclose(0.1 + 0.2, 0.3))              # True
print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9)) # True — explicit tolerance
print(math.isclose(0.1 + 0.2, 0.3, abs_tol=1e-9)) # True

# Accumulation amplifies error
total = 0.0
for _ in range(10):
    total += 0.1
print(total)                          # 0.9999999999999999 — not 1.0
print(math.isclose(total, 1.0))       # True — but == would be False

# For exact decimal arithmetic, use Decimal (next section)
```

### Special Float Values

```python
import math

pos_inf = float("inf")
neg_inf = float("-inf")
nan = float("nan")

print(pos_inf > 1e308)       # True — inf is larger than any finite float
print(pos_inf + 100)         # inf
print(pos_inf - pos_inf)     # nan — indeterminate
print(nan == nan)            # False — NaN is never equal to anything, even itself!
print(math.isnan(nan))       # True — must use isnan()
print(math.isinf(pos_inf))   # True
print(math.isfinite(3.14))   # True
print(math.isfinite(pos_inf))# False

# NaN propagation — any operation with NaN yields NaN
print(nan + 1)    # nan
print(nan * 100)  # nan

# Division by zero with floats gives inf/nan, not an exception
print(1.0 / 0.0)  # inf — wait, actually...
# Let's test:
try:
    print(1.0 / 0.0)
except ZeroDivisionError as e:
    print(f"ZeroDivisionError: {e}")  # Python DOES raise ZeroDivisionError for float / 0

# But math operations can produce inf:
print(math.exp(1000))   # inf — overflow
print(math.exp(-1000))  # 0.0 — underflow
```

> **Correction:** Unlike some languages where `1.0/0.0` silently gives `inf`, Python raises `ZeroDivisionError` for `float / 0`. Infinity arises from `float("inf")` or overflow in `math` functions.

## 3. `complex` — First-Class Complex Numbers

Python has built-in complex numbers — unusual among mainstream languages. They are useful in engineering, signal processing, and anywhere `sqrt(-1)` appears.

```python
# Complex literals — `j` suffix (engineering convention, not `i`)
z = 3 + 4j
print(type(z))       # <class 'complex'>
print(z.real)        # 3.0
print(z.imag)        # 4.0
print(abs(z))        # 5.0 — magnitude (hypotenuse)

# Both parts are floats
print(type(z.real))  # <class 'float'>

# Construction
a = complex(3, 4)    # complex(real, imag)
print(a)             # (3+4j)
b = complex("3+4j")  # from string
print(b)             # (3+4j)
c = 5j               # pure imaginary
print(c)             # 5j

# Operations
x = 2 + 3j
y = 1 - 1j
print(x + y)   # (3+2j)
print(x - y)   # (1+4j)
print(x * y)   # (5+1j) — (2+3j)(1-1j) = 2 -2j +3j -3j² = 5+j
print(x / y)   # (-0.5+2.5j)
print(x.conjugate())  # (2-3j)

# Magnitude and phase
import cmath
z = 1 + 1j
print(abs(z))              # 1.414... — same as math.hypot
print(cmath.phase(z))      # 0.785... — π/4
print(cmath.polar(z))      # (1.414..., 0.785...) — (r, phi)
print(cmath.rect(1.414, 0.785))  # back to complex

# Pitfall — `j` alone is not complex!
try:
    val = j  # NameError — `j` is not a variable
except NameError as e:
    print(f"NameError: {e}")
print(1j)    # 1j — need the numeric prefix
print(1 + 1j) # (1+1j) — correct
# print(1 + j)  # NameError

# Complex has no ordering — comparison raises TypeError
try:
    print((3+4j) < (1+2j))
except TypeError as e:
    print(f"TypeError: {e}")  # '<' not supported between instances of 'complex'
```

## 4. `Decimal` — Exact Decimal Arithmetic

When binary floating point's imprecision is unacceptable (financial calculations, tax, legal rounding), use `decimal.Decimal`.

```python
from decimal import Decimal, getcontext, ROUND_HALF_UP, localcontext

# Decimal stores values in base 10 — 0.1 IS exact
a = Decimal("0.1")       # construct from STRING for exactness
b = Decimal("0.2")
print(a + b)              # 0.3 — exact!
print(a + b == Decimal("0.3"))  # True

# Pitfall — constructing from float carries the float's imprecision
bad = Decimal(0.1)        # Decimal(0.100000000000000005551115...)
print(bad)
good = Decimal("0.1")     # Decimal(0.1) — exact
print(good)
print(bad == good)        # False!

# Precision and rounding are configurable
print(getcontext())       # Context(prec=28, rounding=ROUND_HALF_EVEN, ...)

# Set precision — affects all Decimal operations in this context
getcontext().prec = 6
print(Decimal("1") / Decimal("7"))  # 0.142857 — 6 significant digits

# Reset for subsequent examples
getcontext().prec = 28

# Local context — doesn't affect global state
with localcontext() as ctx:
    ctx.prec = 50
    print(Decimal("1") / Decimal("7"))
    # 0.14285714285714285714285714285714285714285714285714 — 50 digits

print(Decimal("1") / Decimal("7"))  # back to 28 digits

# Rounding modes — critical for financial code
# ROUND_HALF_EVEN (banker's rounding) is the default — minimises bias
print(Decimal("2.5").quantize(Decimal("1"), rounding=ROUND_HALF_EVEN))  # 2
print(Decimal("3.5").quantize(Decimal("1"), rounding=ROUND_HALF_EVEN))  # 4

# ROUND_HALF_UP — the "school" rounding most people expect
print(Decimal("2.5").quantize(Decimal("1"), rounding=ROUND_HALF_UP))    # 3

# Realistic financial example — NEVER use float for money
from decimal import Decimal

def calculate_total(price: str, quantity: int, tax_rate: str) -> Decimal:
    """Calculate total with exact decimal arithmetic."""
    p = Decimal(price)
    t = Decimal(tax_rate)
    subtotal = p * quantity
    tax = (subtotal * t).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
    total = subtotal + tax
    return total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

print(calculate_total("19.99", 3, "0.0825"))  # 64.92

# Compare with float — accumulates error
float_total = 19.99 * 3 * 1.0825
print(f"{float_total:.20f}")  # 64.917... — close but not exact cents
```

> **When to use what:**
> | Need | Use |
> |---|---|
> | Speed, scientific computing, graphics | `float` |
> | Exact decimal (money, tax, legal) | `Decimal` (construct from `str`!) |
> | Exact fractions without decimal rounding | `Fraction` |

## 5. `Fraction` — Exact Rational Arithmetic

```python
from fractions import Fraction

# Fractions store numerator/denominator exactly — no rounding
a = Fraction(1, 3)          # 1/3
b = Fraction(1, 6)          # 1/6
print(a + b)                # 1/2 — exact
print(a + b == Fraction(1, 2))  # True

# Construct from various types
print(Fraction("0.5"))      # 1/2 — from string (exact decimal → fraction)
print(Fraction(0.5))        # 1/2 — from float (converts via exact binary value)
# Fraction(0.1) is 3602879701896397/36028797018963968 — the exact float value!
print(Fraction(0.1))        # 3602879701896397/36028797018963968
print(Fraction("0.1"))      # 1/10 — string gives the expected fraction
print(Fraction(Decimal("0.1")))  # 1/10 — from Decimal

# Operations preserve exactness
x = Fraction(2, 3)
y = Fraction(3, 4)
print(x + y)   # 17/12
print(x * y)   # 1/2
print(x / y)   # 8/9
print(x ** 2)  # 4/9

# Auto-reduces
print(Fraction(4, 8))  # 1/2

# Access parts
f = Fraction(7, 12)
print(f.numerator)    # 7
print(f.denominator)  # 12
print(float(f))       # 0.583333... — convert to float when needed

# Realistic use — recipe scaling without floating-point drift
def scale_recipe(ingredients: dict[str, Fraction], factor: Fraction) -> dict[str, Fraction]:
    return {item: amount * factor for item, amount in ingredients.items()}

recipe = {"flour": Fraction(3, 4), "sugar": Fraction(1, 3), "butter": Fraction(1, 2)}
scaled = scale_recipe(recipe, Fraction(3, 2))  # 1.5×
for item, amount in scaled.items():
    print(f"  {item}: {amount} ({float(amount):.4f})")
# flour: 9/8 (1.1250)
# sugar: 1/2 (0.5000)
# butter: 3/4 (0.7500)
```

## 6. The `math` Module — Essential Functions

```python
import math

# Constants
print(math.pi)    # 3.141592653589793
print(math.e)     # 2.718281828459045
print(math.tau)   # 6.283185307179586 — 2π (added in 3.6)
print(math.inf)   # inf
print(math.nan)   # nan

# Basic
print(math.sqrt(16))       # 4.0
print(math.isqrt(16))      # 4 — integer square root (exact, returns int)
print(math.isqrt(15))      # 3 — floor sqrt as int (no float involved)
print(math.pow(2, 10))     # 1024.0 — always returns float (use ** for int pow)
print(2 ** 10)             # 1024 — int exponentiation (preferred for ints)
print(math.exp(1))         # e¹
print(math.log(100, 10))   # 2.0 — log base 10
print(math.log2(8))        # 3.0
print(math.log10(1000))    # 3.0

# Rounding and truncation — KNOW THE DIFFERENCES
print(math.floor(3.7))    # 3 — toward -infinity
print(math.floor(-3.7))   # -4 — toward -infinity (not -3!)
print(math.ceil(3.2))     # 4 — toward +infinity
print(math.ceil(-3.7))    # -3
print(math.trunc(3.7))    # 3 — toward zero (truncate)
print(math.trunc(-3.7))   # -3 — toward zero
print(round(3.7))         # 4 — banker's rounding (ROUND_HALF_EVEN)
print(round(2.5))         # 2 — rounds to even!
print(round(3.5))         # 4 — rounds to even!
# For "school" rounding, use Decimal with ROUND_HALF_UP.

# Trigonometry (radians)
print(math.sin(math.pi / 2))  # 1.0
print(math.cos(0))            # 1.0
print(math.degrees(math.pi))  # 180.0
print(math.radians(180))      # 3.14159...

# Number theory
print(math.gcd(48, 36))       # 12 — greatest common divisor
print(math.lcm(4, 6))         # 12 — least common multiple (3.9+)
print(math.comb(10, 3))       # 120 — binomial coefficient (3.8+)
print(math.perm(10, 3))       # 720 — permutations (3.8+)
print(math.factorial(5))      # 120
print(math.prod([1, 2, 3, 4]))# 24 — product (3.8+)

# Floating-point utilities
print(math.isclose(0.1 + 0.2, 0.3))           # True
print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9))  # True
print(math.isfinite(42.0))    # True
print(math.isinf(math.inf))   # True
print(math.isnan(math.nan))   # True
print(math.nextafter(1.0, 2.0))  # 1.0000000000000002 — next representable float
print(math.ulp(1.0))          # 2.220446049250313e-16 — unit in last place

# cmath for complex math
import cmath
print(cmath.sqrt(-1))     # 1j
print(cmath.exp(1j * math.pi))  # (-1+1.2246e-16j) — Euler's identity (approx -1)
print(cmath.phase(1+1j))  # 0.785... — π/4
```

### Edge — `math.isclose` Parameters

```python
import math

# isclose(a, b, rel_tol=1e-09, abs_tol=0.0) checks:
#   |a - b| <= max(rel_tol * max(|a|, |b|), abs_tol)

# rel_tol — relative tolerance (scales with magnitude)
print(math.isclose(1000.0, 1000.001, rel_tol=1e-3))  # True — within 0.1%
print(math.isclose(1.0, 1.001, rel_tol=1e-3))        # True

# abs_tol — absolute tolerance (for values near zero)
print(math.isclose(0.0, 1e-10, abs_tol=1e-9))  # True — within absolute tolerance
print(math.isclose(0.0, 1e-10, rel_tol=1e-9))   # False — relative tol meaningless near 0

# For near-zero comparisons, set abs_tol:
print(math.isclose(0.0, 0.0, abs_tol=1e-9))     # True
```

## 7. `int` and `bool` — The Subclass Relationship

This is covered deeply in Lesson 01.4, but the numeric implications belong here too:

```python
# bool is a subclass of int — this is intentional and relied upon
print(issubclass(bool, int))  # True
print(isinstance(True, int))  # True
print(True + True)            # 2
print(True * 5)               # 5
print(False * 100)            # 0
print(sum([True, True, False, True]))  # 3 — counting Trues

# But type() distinguishes them
print(type(True) is bool)  # True
print(type(True) is int)   # False

# Practical — counting with booleans is Pythonic
scores = [85, 92, 78, 90, 88]
passing = sum(s >= 80 for s in scores)  # s >= 80 is bool → int
print(passing)  # 4 — number of passing scores

# Pitfall — isinstance(True, int) is True can surprise type checks
def process(value: int) -> None:
    if isinstance(value, int):
        print(f"int: {value}")

process(True)  # "int: True" — True sneaks in as int!
# Guard with exact type check if needed:
def process_strict(value: int) -> None:
    if type(value) is not int:  # excludes bool
        print(f"not a pure int: {value!r} ({type(value).__name__})")
        return
    print(f"pure int: {value}")

process_strict(True)  # not a pure int: True (bool)
process_strict(42)    # pure int: 42
```

## 8. Operator Precedence (Numeric Context)

From highest to lowest (see Lesson 01.10 for the full table):

```
  **          exponentiation (right-associative)
  +x  -x  ~x  unary plus/minus/bitwise NOT
  *  /  //  %  multiplication / division / floor div / modulo
  +  -        addition / subtraction
  <<  >>      shifts
  &           bitwise AND
  ^           bitwise XOR
  |           bitwise OR
```

```python
# Exponentiation is right-associative
print(2 ** 3 ** 2)    # 512 — not 64 — means 2**(3**2) = 2**9
print((2 ** 3) ** 2)  # 64  — parenthesised left-associative

# Unary minus binds tighter than **  — a common surprise
print(-3 ** 2)    # -9 — means -(3**2), NOT (-3)**2
print((-3) ** 2)  # 9  — parenthesise to negate before exponentiation

# Mixing arithmetic and bitwise — use parentheses!
# `&` has LOWER precedence than `+` and `<<` — often surprising
print(1 + 2 & 3)    # 3 — means (1+2) & 3 = 3 & 3 = 3
print(1 << 2 & 3)   # 0 — means (1<<2) & 3 = 4 & 3 = 0, NOT 1 << (2&3) = 1<<2 = 4
# When mixing arithmetic and bitwise, always parenthesise for clarity.
print((1 << 2) & 3) # 0 — explicit
print(1 << (2 & 3)) # 4 — explicit (different!)

# Floor division and modulo with negatives — floor, not truncation
print(-7 // 4)   # -2
print(-7 % 4)    # 1  — because -7 == (-2)*4 + 1
```

## 9. Common Mistakes and Pythonic Idioms

| Mistake | What Happens | Fix |
|---|---|---|
| `0.1 + 0.2 == 0.3` | `False` due to binary float | `math.isclose(0.1+0.2, 0.3)` |
| `round(2.5) == 3` | `False` — banker's rounding gives `2` | `Decimal("2.5").quantize(Decimal("1"), ROUND_HALF_UP)` for school rounding |
| `-3 ** 2 == 9` | `False` — gives `-9` | `(-3) ** 2` |
| `017` as octal | Just `17` in Python | `0o17` |
| `Decimal(0.1)` | Carries float imprecision | `Decimal("0.1")` |
| `Fraction(0.1)` | Huge fraction from float | `Fraction("0.1")` or `Fraction(1, 10)` |
| `isinstance(True, int)` guard | `True` passes as `int` | `type(x) is int` if you must exclude `bool` |
| `1 / 2 == 0` (from C) | `0.5` in Python 3 | Use `//` for floor division |

**Pythonic idioms:**

```python
# Counting with booleans
num_passing = sum(score >= 60 for score in scores)

# Readable large numbers
MAX_SIZE = 10_000_000
PERMISSIONS = 0b110_101_100

# Safe float comparison
import math
if math.isclose(a, b, rel_tol=1e-9, abs_tol=1e-12):
    print("close enough")

# Money — always Decimal from string
from decimal import Decimal
price = Decimal("19.99")
tax = Decimal("0.07")
total = (price * Decimal("3") * (Decimal("1") + tax)).quantize(Decimal("0.01"))

# Exact fractions for ratios
from fractions import Fraction
ratio = Fraction(3, 4) / Fraction(2, 3)  # 9/8 — exact
```

## 10. Choosing the Right Numeric Type

```
  Need arbitrary large integers?
  └─► int (built-in, no overflow)
           │
  Need real numbers?
  ├── Fast & approximate (science, graphics, ML)?
  │    └─► float (IEEE 754, hardware-accelerated)
  │
  ├── Exact decimals (money, tax, legal rounding)?
  │    └─► Decimal (base-10, configurable precision/rounding)
  │
  ├── Exact fractions (ratios, recipe scaling)?
  │    └─► Fraction (numerator/denominator, auto-reduced)
  │
  └── Complex math (engineering, signal processing)?
       └─► complex (built-in, cmath for functions)
```

```python
# Quick decision guide — runnable
from decimal import Decimal
from fractions import Fraction
import math

# 1. int — no overflow, ever
print(2 ** 1000)  # just works

# 2. float — fast, hardware-backed, but approximate
print(sum(0.1 for _ in range(10)))  # 0.999999... — not 1.0

# 3. Decimal — exact base-10
print(sum(Decimal("0.1") for _ in range(10)))  # 1.0 — exact

# 4. Fraction — exact rational
print(sum(Fraction(1, 10) for _ in range(10)))  # 1 — exact

# 5. complex — first-class
print(cmath.sqrt(-4))  # 2j
```

---

## 11. Summary

- **`int`** is arbitrary-precision — never overflows, grows as large as memory allows. Use `0x`/`0b`/`0o` prefixes and `_` separators for readable literals.
- **`float`** is IEEE 754 double — fast but binary-approximate. `0.1 + 0.2 != 0.3`; use `math.isclose()` for comparisons, never `==`.
- **`complex`** is built-in (`3+4j`) with `cmath` for functions. No ordering — `<`/`>` raise `TypeError`.
- **`Decimal`** gives exact base-10 arithmetic — essential for money. Always construct from `str`, not `float`. Control precision and rounding via `getcontext()`/`localcontext()`.
- **`Fraction`** gives exact rational arithmetic — numerator/denominator, auto-reduced.
- **`math`** provides constants, rounding (`floor`/`ceil`/`trunc` differ for negatives), number theory (`gcd`/`lcm`/`comb`), and float utilities (`isclose`/`isfinite`/`ulp`).
- **`bool` is `int`** — `True == 1`, `isinstance(True, int)` is `True`. Use `type(x) is int` to exclude booleans.
- **Precedence:** `**` is right-associative and binds tighter than unary `-` (`-3**2 == -9`); bitwise ops have lower precedence than arithmetic — parenthesise mixed expressions.

> **Key takeaway:** Python's `int` frees you from overflow thinking; its `float` demands the same IEEE 754 respect as in any language; and `Decimal`/`Fraction` are there when "close enough" is not enough. Choose the type that matches your correctness requirements, not just habit.
