# 9.1 Introspection — Peeking Inside Python Objects

> In Python, introspection is not a debugging afterthought — it is a language feature. The runtime *is* the IDE. Understanding how to ask objects *what they are* is how you write decorators, ORMs, serializers, test frameworks, and plugins.

## Learning Goals

- Understand Python's object model enough to query any object at runtime.
- Master the core introspection builtins: `type`, `isinstance`, `issubclass`, `dir`, `getattr`/`setattr`/`hasattr`/`delattr`, `vars`, `callable`, `id`.
- Learn the difference between instance `__dict__`, class `__dict__` (`mappingproxy`), and `__slots__`.
- Use `__doc__` and `__annotations__` for documentation and type-introspection.
- Become productive with the `inspect` module: `signature`, `getmembers`, `isfunction`/`ismethod`/`isclass`/`ismodule`, `getsource`, frames.
- Avoid common traps: `hasattr` swallowing exceptions, `isinstance` vs `type(x) is T`, `dir` vs `__dict__`.

---

## 1. The Philosophical Starting Point: Everything Is an Object, and Objects Are Introspectable

In C++ or Java, reflection is opt-in, gated behind APIs, and sometimes expensive. In Python:

1. Every value is a `PyObject` on the heap with a type pointer and a reference count.
2. Every object carries its type, and every type carries its namespace.
3. The interpreter exposes that namespace directly.

Consequences:

- You can inspect a class you did not author, at runtime, without recompiling.
- Tools like `pytest`, `dataclasses`, `pydantic`, `SQLAlchemy`, and `click` are *all* introspection engines.

```python
# Example 1: The simplest possible introspection — asking "what are you?"
x = 42
print(type(x))        # <class 'int'>
print(x.__class__)    # <class 'int'>   — same thing, but not identical in purpose (see §3)
print(dir(x)[:5])     # ['__abs__', '__add__', '__and__', ...] — what can I do with you?
```

*Explanation:* `type(x)` is the canonical way to get an object's type. `dir(x)` lists the attributes the object *exposes* (including inherited ones). Even the humble integer reveals its double-underscore protocol.

## 2. `dir()` — What Can This Object Do?

`dir([obj])` tries to return a *useful* list of valid attribute names.

- If called with no argument, `dir()` returns names in the current local scope (like `locals().keys()` sorted).
- If called with an object, it collects: keys of `__dict__` (if any), attributes of the type and its MRO, and whatever `__dir__` returns (if defined).

### 2.1 Basic Behavior

```python
class Point:
    """A point in 2D space."""
    def __init__(self, x: float, y: float) -> None:
        self.x = x
        self.y = y

    def distance_from_origin(self) -> float:
        return (self.x ** 2 + self.y ** 2) ** 0.5

p = Point(3, 4)
print(dir(p))
# ['__class__', '__delattr__', '__dict__', '__dir__', '__doc__', ...,
#  'distance_from_origin', 'x', 'y']
```

*Explanation:* `dir(p)` merges instance attributes (`x`, `y`), class attributes (`distance_from_origin`), and the universal `object` protocol.

### 2.2 `dir` vs `__dict__` — The Critical Distinction

| Aspect | `dir(obj)` | `obj.__dict__` (or `vars(obj)`) |
|---|---|---|
| Includes inherited attributes | Yes | No (only the object's own writable dict) |
| Includes `__slots__` attributes | Yes | No (slot instances may have no `__dict__`) |
| Includes descriptors / properties | Yes (shows the name) | No |
| Honors `__dir__` | Yes | No |
| Return type | Sorted `list[str]` | `dict[str, Any]` |
| Goal | *Human-friendly discovery* | *Machine-readable namespace* |

```python
class WithSlots:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x = x
        self.y = y

s = WithSlots(1, 2)
print(dir(s))               # includes 'x', 'y', '__slots__', ...
print(hasattr(s, "__dict__"))  # False — no dict at all!
try:
    print(s.__dict__)
except AttributeError as exc:
    print("no __dict__:", exc)

# Customizing dir
class Secret:
    def __init__(self):
        self.public = 1
        self._hidden = 2
    def __dir__(self):
        # Only advertise public API
        return ["public"]

print(dir(Secret()))  # ['public']
print(vars(Secret())) # {'public': 1, '_hidden': 2} — vars sees reality, dir sees marketing
```

*Explanation:* Frameworks customize `__dir__` for tab-completion and `dir()` ergonomics (e.g., `pandas.DataFrame`). Never use `dir()` for program logic that needs completeness — use `vars()`/`__dict__` + MRO walk instead.

### 2.3 Common Mistake: Using `dir()` for Logic

```python
# Bad — dir is curated, sorted, and may be overridden
if "password" in dir(user):
    ...

# Good — exact membership test on the instance or class dict chain
if hasattr(user, "password"):   # triggers descriptor protocol; see §5 for nuance
    ...
if "password" in vars(user):    # only instance dict
    ...
```

## 3. `type`, `isinstance`, and `issubclass` — Asking "What Are You?" Correctly

### 3.1 `type(obj)` vs `obj.__class__` vs `type(obj) is T`

- `type(obj)` — builtin that returns `obj.__class__` *unless* `__class__` is overridden via assignment (legal but rare). Prefer `type()`.
- `obj.__class__` — attribute lookup; can be shadowed. Assignment `obj.__class__ = Foo` is allowed and changes the instance's type (a power move; rarely wise).
- `type(obj) is T` — exact type match. Fails for subclasses. Rarely what you want in production.

```python
class Animal: pass
class Dog(Animal): pass

d = Dog()

print(type(d) is Dog)       # True — exact match
print(type(d) is Animal)    # False — Dog is not Animal, even though Dog *is an* Animal
print(isinstance(d, Animal))  # True — respects inheritance
print(d.__class__)          # <class '__main__.Dog'>

# Tricky: bool is a subclass of int!
print(isinstance(True, int))   # True
print(type(True) is int)       # False
print(issubclass(bool, int))   # True
```

*Explanation:* `bool` subclassing `int` is a deliberate language design wart. If you test `type(x) is int` you exclude `bool`; if you test `isinstance(x, int)` you include it. For "integer-like but not bool" code, you often see `isinstance(x, int) and not isinstance(x, bool)` or `type(x) is int`.

### 3.2 `isinstance` and `issubclass` Are the Polymorphic Choice

```python
# Simple → realistic
def save(obj: object) -> None:
    if isinstance(obj, str):
        print(f"saving text: {obj!r}")
    elif isinstance(obj, (bytes, bytearray)):
        print(f"saving {len(obj)} bytes")
    else:
        raise TypeError(f"cannot save {type(obj).__name__}")

save("hello")
save(b"hello")
# save(123)  # TypeError

# issubclass with a tuple of candidates — just like isinstance
print(issubclass(Dog, (Animal, object)))  # True — any match
print(issubclass(Dog, Animal))            # True

# Advanced: Abstract Base Classes — isinstance can be virtual
from collections.abc import Sequence
print(isinstance([1, 2], Sequence))   # True — even though list doesn't inherit Sequence directly
print(isinstance("abc", Sequence))    # True — strings are sequences

# How? Sequence registers virtual subclasses via __subclasshook__ and ABCMeta
# This is duck-typing made explicit.
```

*Explanation:* Since Python 3, many `collections.abc` types use `__subclasshook__` to answer `isinstance` structurally ("do you have `__getitem__` and `__len__`?") rather than nominally. This is why introspection-aware code prefers `isinstance` — it respects ABCs and virtual subclasses.

### 3.3 The `__mro__` (Method Resolution Order) Behind `isinstance`

```python
class A: pass
class B(A): pass
class C(B): pass

print(C.__mro__)
# (<class '__main__.C'>, <class '__main__.B'>, <class '__main__.A'>, <class 'object'>)
print(issubclass(C, A))  # True — A is in C.__mro__

# Edge: old-style confusion (Python 2 leftover) — not relevant now, but you will read about it
# In Python 3, every class is new-style, MRO is C3 linearization. issubclass follows it.
```

### 3.4 Common Mistakes and Table

| Mistake | Why it hurts | Correct idiom |
|---|---|---|
| `type(x) == SomeClass` | Misses subclasses, misses virtual ABCs | `isinstance(x, SomeClass)` |
| `isinstance(x, SomeClass) == True` | Redundant; `isinstance` already returns bool | `if isinstance(x, SomeClass):` |
| `issubclass(x, SomeClass)` where `x` is an instance | `issubclass` expects a *class*; `isinstance` expects an *instance* | `isinstance(x, SomeClass)` for instances |
| Forgetting `bool` ⊂ `int` | Logic bug: `isinstance(True, int)` is `True` | Guard with `not isinstance(x, bool)` if needed |

```python
# Edge: issubclass requires a class; passing an instance is TypeError
try:
    issubclass(d, Animal)   # d is an instance, not a class!
except TypeError as exc:
    print(exc)  # issubclass() arg 1 must be a class

# Correct
print(isinstance(d, Animal))  # True
print(issubclass(type(d), Animal))  # True — get the class first
```

## 4. `vars()` and `__dict__` — The Namespace Dictionary

Every object *may* have a `__dict__`: a `dict[str, Any]` holding its writable attributes. But not every object *does*.

### 4.1 Basics

```python
class Person:
    species = "Homo sapiens"   # class attribute — lives in Person.__dict__

    def __init__(self, name: str, age: int) -> None:
        self.name = name       # instance attributes — live in instance __dict__
        self.age = age

p = Person("Ada", 30)
print(vars(p))          # {'name': 'Ada', 'age': 30}
print(p.__dict__)       # same object as vars(p)
print(vars(Person))     # mappingproxy({... 'species': 'Homo sapiens', ...})
print(Person.__dict__["species"])  # 'Homo sapiens'

# vars(obj) is exactly obj.__dict__ when it exists; otherwise TypeError
# vars() with no argument is locals()

def demo(a, b=2):
    x = 10
    print(vars())  # not implemented — vars() with no args? actually... let's check
    print(locals())

demo(1)
```

*Explanation:* `vars(p)` is syntactic sugar for `p.__dict__`. For modules, classes, and instances with a dict, it returns the dict. For modules, `vars(module)` is the module's global namespace. For classes, `Class.__dict__` is a `mappingproxy` (read-only view) — you cannot `Class.__dict__["x"] = 1` directly; you must `setattr(Class, "x", 1)` or `Class.x = 1`.

### 4.2 `__dict__` Chain: Instance → Class → Bases

Attribute lookup is NOT "check `__dict__`": it is MRO + descriptor protocol. Introspection must walk it.

```python
class Base:
    base_attr = "from Base"

class Child(Base):
    child_attr = "from Child"
    def __init__(self):
        self.instance_attr = "from instance"

c = Child()
print(c.__dict__)                # {'instance_attr': 'from instance'} — only instance
print(Child.__dict__.keys())     # dict_keys([... 'child_attr', ...])  — plus inherited? No!
print("base_attr" in Child.__dict__)  # False — it's in Base.__dict__
print("base_attr" in dir(c))     # True — dir follows MRO
print(c.base_attr)               # "from Base" — lookup follows MRO

# Realistic: collect all attributes across MRO
def all_attributes(obj: object) -> dict[str, object]:
    merged: dict[str, object] = {}
    for klass in reversed(type(obj).__mro__):  # base-first so child overrides
        merged.update(vars(klass))
    merged.update(vars(obj) if hasattr(obj, "__dict__") else {})
    return merged

print(all_attributes(c).keys())
```

### 4.3 When `__dict__` Does Not Exist

- Objects with `__slots__` and no `__dict__` slot.
- Built-in types (`int`, `list`, `str`) — no per-instance dict (for performance).
- Instances of extension types.

```python
print(hasattr(42, "__dict__"))     # False
print(hasattr([], "__dict__"))     # False
print(hasattr(object(), "__dict__"))  # False — plain object is slot-like

# Slots example with optional __dict__
class Compact:
    __slots__ = ("x", "y", "__dict__")  # yep, you can opt back in
    def __init__(self, x, y, extra=None):
        self.x = x
        self.y = y
        if extra is not None:
            self.extra = extra  # goes into __dict__

c1 = Compact(1, 2)
c2 = Compact(1, 2, extra="hello")
print(hasattr(c1, "__dict__"), vars(c1))  # True {} — dict exists but empty
print(vars(c2))                           # {'extra': 'hello'}
```

*Explanation:* This is why generic serializers use `getattr`/`hasattr` or `inspect.getmembers` rather than `__dict__` alone — half the ecosystem would be invisible otherwise.

### 4.4 `mappingproxy` — Why `Class.__dict__` Is Read-Only

```python
class Foo:
    a = 1

print(type(Foo.__dict__))  # <class 'mappingproxy'>

try:
    Foo.__dict__["a"] = 2
except TypeError as exc:
    print(exc)  # 'mappingproxy' object does not support item assignment

# The supported way:
Foo.a = 2
setattr(Foo, "b", 3)
print(Foo.a, Foo.b)

# If you truly want a mutable copy:
mutable = dict(Foo.__dict__)
mutable["a"] = 99  # doesn't affect Foo
```

## 5. `getattr`, `hasattr`, `setattr`, `delattr` — Dynamic Attribute Access

These four are the runtime equivalent of the dot operator, but dynamic.

| Function | Static equivalent | Notes |
|---|---|---|
| `getattr(obj, "name")` | `obj.name` | Optionally `getattr(obj, "name", default)` |
| `hasattr(obj, "name")` | `try: obj.name; except AttributeError: False` | Swallows *any* exception from descriptors! |
| `setattr(obj, "name", val)` | `obj.name = val` | Calls descriptor `__set__` if present |
| `delattr(obj, "name")` | `del obj.name` | Calls descriptor `__delete__` if present |

### 5.1 `getattr` with a Default — Avoiding Exceptions

```python
class Config:
    timeout = 30

cfg = Config()

# Without default — raises
try:
    print(getattr(cfg, "retries"))
except AttributeError as exc:
    print("missing:", exc)

# With default — safe
print(getattr(cfg, "retries", 3))   # 3
print(getattr(cfg, "timeout", 3))   # 30  — default ignored when attr exists

# Nested getattr — common idiom for optional chains
# Instead of if hasattr(obj, "a") and hasattr(obj.a, "b"): ...
value = getattr(getattr(cfg, "nested", None), "value", None)
print(value)  # None
```

### 5.2 The `hasattr` Trap — It Swallows More Than `AttributeError`

This is a *critical* subtlety. `hasattr(obj, name)` is implemented as:

```python
def hasattr(obj, name):
    try:
        getattr(obj, name)
    except Exception:  # not just AttributeError!
        return False
    else:
        return True
```

If a `@property` raises any exception, `hasattr` returns `False`, silently hiding the bug.

```python
class Broken:
    @property
    def value(self):
        raise RuntimeError("database is down")

b = Broken()
print(hasattr(b, "value"))  # False — misleading! Attribute *exists* but is broken

# Correct introspection: distinguish "missing" from "broken"
try:
    getattr(b, "value")
except AttributeError:
    print("truly missing")
except Exception as exc:
    print(f"attribute exists but errored: {exc!r}")
```

*Rule:* In library code or any place where a property/descriptor might do work, prefer a `try: getattr / except AttributeError` pattern over `hasattr`.

### 5.3 `setattr` / `delattr` and Valid Identifiers

```python
obj = type("Dynamic", (), {})()  # anonymous class instance

# You can set attributes that aren't valid Python identifiers — but you must use getattr to read them
setattr(obj, "with spaces", 123)
setattr(obj, "123invalid", 456)
print(getattr(obj, "with spaces"))   # 123
# obj.with spaces  # SyntaxError — must use getattr

# delattr removes from __dict__ or triggers descriptor __delete__
setattr(obj, "temp", "bye")
print(vars(obj))
delattr(obj, "temp")
print(vars(obj))
try:
    delattr(obj, "nonexistent")
except AttributeError as exc:
    print(exc)
```

### 5.4 Realistic Example: Plugin Registry via Introspection

```python
# plugins.py — a realistic dispatch based on introspection
class Plugin:
    def execute(self) -> str:
        raise NotImplementedError

class HelloPlugin(Plugin):
    def execute(self) -> str:
        return "hello"

class GoodbyePlugin(Plugin):
    def execute(self) -> str:
        return "goodbye"

# Discover plugins by introspecting the current module
import sys
import inspect

def discover_plugins(module) -> dict[str, type[Plugin]]:
    plugins: dict[str, type[Plugin]] = {}
    for name, obj in inspect.getmembers(module, inspect.isclass):
        # Only classes defined in *this* module, that subclass Plugin, but aren't Plugin itself
        if obj is Plugin:
            continue
        if issubclass(obj, Plugin) and obj.__module__ == module.__name__:
            plugins[name] = obj
    return plugins

# In real code, you'd pass a module object; here we simulate with the current namespace
current_module = sys.modules[__name__]
print(discover_plugins(current_module))
# {'GoodbyePlugin': <class '__main__.GoodbyePlugin'>, 'HelloPlugin': <class '__main__.HelloPlugin'>}

# Dynamic instantiation from a config string
def make_plugin(name: str) -> Plugin:
    registry = discover_plugins(current_module)
    klass = registry.get(name)
    if klass is None:
        raise ValueError(f"unknown plugin {name!r}; known: {sorted(registry)}")
    return klass()

print(make_plugin("HelloPlugin").execute())  # "hello"
```

## 6. `callable()` — Can I Call It?

`callable(obj)` returns `True` if `obj` appears callable (has `__call__`). Since Python 3.2 it is just `hasattr(obj, "__call__")` plus some C-level fast paths.

```python
def func(): pass
class CallableClass:
    def __call__(self, x):  # instances become callable
        return x * 2

print(callable(func))               # True
print(callable(CallableClass))      # True — classes are callable (they construct)
print(callable(CallableClass()))    # True — instance with __call__
print(callable(42))                 # False
print(callable("hello".upper))      # True — bound method
print(callable(lambda x: x))        # True

# Distinguish callable *types* vs *instances*
# inspect.isfunction vs inspect.isbuiltin vs callable
import inspect
print(inspect.isfunction(func))     # True
print(inspect.isfunction(CallableClass()))  # False — it's not a function, but callable
print(callable(CallableClass()))    # True

# Edge: classes with __call__ defined only on the instance's type, not the class
# (callable checks the type, not the instance dict)
class Weird:
    pass

w = Weird()
w.__call__ = lambda: "surprise"
print(callable(w))  # False — __call__ must be on the type, not the instance dict!
print(hasattr(w, "__call__"))  # True — but not found via type lookup
```

*Explanation:* Python's callable check is *type-based*. Writing `instance.__call__ = ...` does not make `instance` callable, because `type(instance).__call__` is what the interpreter checks when you write `instance()`. This is the descriptor/type-slot protocol at work.

### 6.1 When to Use `callable` vs `inspect`

```python
from collections.abc import Callable
# For type checking at runtime:
if callable(maybe_func):
    maybe_func()

# For type hints, use collections.abc.Callable:
def run(callback: Callable[[int], str]) -> str:
    return callback(42)
```

## 7. `id()` — Identity, Not Equality, Not Memory (Quite)

`id(obj)` returns an integer that is *guaranteed* unique among simultaneously existing objects. In CPython, it is the memory address of the `PyObject`. In PyPy or GraalPy, it is not.

- `x is y`  ⟺  `id(x) == id(y)` (for simultaneously alive objects).
- `x == y`  ⟺  `x.__eq__(y)` — value equality, unrelated to `id`.

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)          # True — same value
print(a is b)          # False — different objects
print(id(a) == id(b))  # False
print(a is c)          # True
print(id(a) == id(c))  # True

# id reuse after garbage collection — the classic pitfall
x_id = id([1, 2, 3])  # temporary list created, id taken, then garbage collected
y = [4, 5, 6]
print(id(y) == x_id)  # *may* be True! The old address was recycled
# Never store id() for later identity checks on objects that may have died.

# Correct: keep a reference, or use weakref, or compare with `is` while both alive
a = [1, 2, 3]
a_id = id(a)
# a is still alive here, so a_id is still valid for `a is ...` checks
print(a_id == id(a))  # True
```

*Explanation:* `id()` is *not* a permanent fingerprint. It is a *live* address. The moment the object dies, its id may be reassigned. This is why `id`-based caches must hold a strong or weak reference to the object, or they risk collisions.

### 7.1 `id` with Interning and Small-Integer Caching (Preview)

```python
a = 256
b = 256
print(a is b, id(a) == id(b))   # True — small ints are singletons in CPython

a = 257
b = 257
# In a script, the compiler may intern 257 too — but in general:
# Do NOT rely on `is` for ints/strings. Use `==`.
# The `is` truth for 257 is an implementation detail of the compiler's constant folding.

# Force non-interned ints:
import sys
a = int("257")
b = int("257")
print(a is b)  # False (usually) — now they are distinct objects
print(a == b)  # True
```

(See §9.3 for full interning semantics.)

## 8. `__doc__` and `__annotations__` — Documentation and Type Introspection

### 8.1 `__doc__`

Every function, class, module, and (optionally) method can carry a docstring. At runtime it lives in `__doc__`. `help()` and IDEs read it.

```python
def greet(name: str) -> str:
    """Return a greeting for *name*.

    Args:
        name: Person to greet.
    Returns:
        A greeting string.
    """
    return f"Hello, {name}!"

print(greet.__doc__)
help(greet)  # renders __doc__ with signature

class Foo:
    """Foo is a demonstration class."""

print(Foo.__doc__)
print(Foo.__init__.__doc__)  # None unless you document __init__ explicitly

# Edge: if no docstring, __doc__ is None (not "")
print((lambda x: x).__doc__)  # None
```

*Idiom:* Libraries like `click` and `argparse` *read* `__doc__` to auto-generate CLI help. Docstrings are data, not just comments.

### 8.2 `__annotations__`

PEP 484 + PEP 563: annotations are stored as a dict on the object. *They are not enforced at runtime* — they are metadata for tools.

```python
def add(a: int, b: int) -> int:
    return a + b

print(add.__annotations__)
# {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}

# Annotations are *not evaluated* until you ask? Actually in Python 3.10+,
# stringized annotations via `from __future__ import annotations` store strings.
# Use typing.get_type_hints() to resolve them (handles forward refs + stringization).

from typing import get_type_hints

class Node:
    def __init__(self, value: int, next: "Node | None" = None) -> None:
        self.value = value
        self.next = next

print(Node.__init__.__annotations__)
# {'value': <class 'int'>, 'next': 'Node | None', 'return': None}  — 'Node | None' is a string!

print(get_type_hints(Node.__init__))
# {'value': <class 'int'>, 'next': Node | None, 'return': <class 'NoneType'>}  — resolved!

# PEP 563 future behavior: `from __future__ import annotations` makes ALL annotations strings
# Python 3.14+ / PEP 649 will change this again (deferred evaluation). Always use get_type_hints
# for reliable runtime type reading.
```

```python
# Realistic: a tiny runtime validator built on __annotations__ + inspect
import inspect

def validate_call(func, *args, **kwargs):
    hints = get_type_hints(func)
    sig = inspect.signature(func)
    bound = sig.bind(*args, **kwargs)
    bound.apply_defaults()
    for name, value in bound.arguments.items():
        expected = hints.get(name)
        if expected is not None and not isinstance(value, expected):
            # Note: this naive check fails for generics like list[int] — need typing logic
            print(f"WARNING: {name}={value!r} expected {expected}, got {type(value).__name__}")

def repeat(text: str, times: int) -> str:
    return text * times

validate_call(repeat, "hi", 3)       # ok
validate_call(repeat, "hi", "3")     # WARNING: times='3' expected <class 'int'>, got str
```

*Explanation:* Runtime annotation checks are *advisory*. Production validators use `pydantic`, `typeguard`, or `beartype`, which handle `list[int]`, `Union`, `Annotated`, etc., properly. `__annotations__` alone is raw.

## 9. The `inspect` Module — Industrial-Strength Introspection

`inspect` is where introspection graduates from "cute trick" to "framework engine." Key tools:

| Function | What it does |
|---|---|
| `inspect.getmembers(obj, predicate)` | Returns `[(name, value), ...]` for all members satisfying predicate |
| `inspect.signature(obj)` | Returns a `Signature` object describing parameters |
| `inspect.getsource(obj)` | Returns source code (if available) |
| `inspect.getfile(obj)` | Returns filename where obj was defined |
| `inspect.isfunction` / `ismethod` / `isbuiltin` / `isclass` / `ismodule` | Precise type checks for callables |
| `inspect.stack()` / `currentframe()` | Frame introspection (debuggers, logging) |
| `inspect.getattr_static(obj, name)` | Like `getattr` but *without* triggering descriptors |

### 9.1 `getmembers` and the `is*` Predicates

```python
import inspect

class Example:
    class_attr = 42
    def method(self): pass
    @staticmethod
    def static(): pass
    @classmethod
    def klass(cls): pass
    @property
    def prop(self): return 1

# All members
print(inspect.getmembers(Example)[:4])

# Only methods (functions defined on the class, before binding)
print([n for n, _ in inspect.getmembers(Example, predicate=inspect.isfunction)])
# ['method', 'static'] — note: staticmethod unwraps to function? Let's check:

# On an *instance*, isfunction vs ismethod differs
ex = Example()
print(inspect.isfunction(ex.method))   # False — on instance it's a bound method
print(inspect.ismethod(ex.method))     # True
print(inspect.isfunction(Example.method))  # True — on class it's a function
print(inspect.ismethod(Example.method))    # False

# What about builtins vs Python functions?
print(inspect.isbuiltin(len))          # True
print(inspect.isfunction(len))         # False
print(callable(len))                   # True — all are callable, but different kinds

# isclass / ismodule
print(inspect.isclass(Example))        # True
print(inspect.ismodule(inspect))       # True
```

*Why this matters:* A serializer that wants to "find all methods to expose as API endpoints" must distinguish `isfunction` (unbound, on class) from `ismethod` (bound, on instance) from `isbuiltin` (C-implemented). `getmembers` with a predicate is the robust way.

```python
# Realistic: auto-document all public methods of a class
def document_api(cls: type) -> None:
    for name, member in inspect.getmembers(cls, predicate=inspect.isfunction):
        if name.startswith("_"):
            continue
        sig = inspect.signature(member)
        doc = inspect.getdoc(member) or "(no docs)"
        print(f"{cls.__name__}.{name}{sig}\n  {doc.splitlines()[0]}")

document_api(Example)
```

### 9.2 `inspect.signature` — Reading Call Signatures Without Calling

`inspect.signature` returns a `Signature(parameters, return_annotation)` where each `Parameter` has `name`, `annotation`, `default`, `kind`.

```python
import inspect

def func(a, b: int, *args: float, c: str = "hi", d=None, **kwargs) -> bool:
    """Example with every parameter kind."""
    return True

sig = inspect.signature(func)
print(sig)  # (a, b: int, *args: float, c: str = 'hi', d=None, **kwargs) -> bool

for name, param in sig.parameters.items():
    print(f"{name:6} kind={param.kind.name:20} default={param.default!r:10} annotation={param.annotation!r}")

print("return annotation:", sig.return_annotation)

# Parameter kinds — the taxonomy that makes Python's call syntax work
# POSITIONAL_ONLY, POSITIONAL_OR_KEYWORD, VAR_POSITIONAL (*args),
# KEYWORD_ONLY (after *), VAR_KEYWORD (**kwargs)

def all_kinds(pos_only, /, standard, *args, kw_only, **kw):
    pass

for n, p in inspect.signature(all_kinds).parameters.items():
    print(n, p.kind)

# Binding — check if arguments would be valid WITHOUT calling
sig = inspect.signature(func)
try:
    bound = sig.bind(1, 2, 3, 4, c="hello")
    print("bound args:", bound.arguments)
    bound.apply_defaults()
    print("with defaults:", bound.arguments)
except TypeError as exc:
    print("bind error:", exc)

try:
    sig.bind()  # missing required
except TypeError as exc:
    print("expected error:", exc)
```

*Explanation:* Frameworks like `FastAPI`, `click`, `pytest`, and `dataclasses` use `signature` + `get_type_hints` to map HTTP params → function args, CLI args → function args, or fixtures → test functions, automatically.

#### Realistic Example: A Minimal Dependency-Injection Decorator

```python
import inspect
from typing import get_type_hints

registry = {"db": "DATABASE_CONNECTION", "cache": "REDIS_CONNECTION"}

def inject(func):
    sig = inspect.signature(func)
    hints = get_type_hints(func)

    def wrapper(*args, **kwargs):
        bound = sig.bind_partial(*args, **kwargs)
        for name, param in sig.parameters.items():
            if name not in bound.arguments and name in registry:
                bound.arguments[name] = registry[name]
        return func(*bound.args, **bound.kwargs)

    return wrapper

@inject
def handle_request(user_id: int, db=None, cache=None):
    print(f"user {user_id} via {db} + {cache}")

handle_request(42)  # user 42 via DATABASE_CONNECTION + REDIS_CONNECTION
print(inspect.signature(handle_request))  # wrapper's sig — see functools.wraps fix in Ch. 9.2
```

#### Edge: Signatures of Builtins May Be Unavailable

```python
try:
    print(inspect.signature(len))
except ValueError as exc:
    print(f"no signature for len: {exc}")
# In CPython 3.11+, many builtins now *do* have signatures (PEP 570), so this may succeed
# Always be prepared for ValueError / TypeError when introspecting C extensions
```

### 9.3 `getsource`, `getfile`, `getsourcelines` — Where Was This Defined?

```python
import inspect
import pathlib

print(inspect.getfile(inspect))           # .../inspect.py
print(inspect.getfile(Example))           # this file
print(inspect.getsource(Example).splitlines()[:3])
print(inspect.getsourcelines(Example.method))

# Edge: no source for REPL-defined, C-builtin, or dynamically generated code
import math
try:
    print(inspect.getsource(math.sin))
except (OSError, TypeError) as exc:
    print(f"no source for math.sin: {exc}")

# Dynamically created via exec — also no file
code = compile("def dyn(): return 42", "<string>", "exec")
ns: dict = {}
exec(code, ns)
try:
    print(inspect.getfile(ns["dyn"]))
except TypeError as exc:
    print(f"no file for exec'd function: {exc}")
```

### 9.4 `getattr_static` — Introspection Without Side Effects

`inspect.getattr_static(obj, name)` bypasses the descriptor protocol. Essential when the descriptor *does work* (DB query, network call) and you just want to know "what is stored?"

```python
import inspect

class Lazy:
    @property
    def value(self):
        print("EXPENSIVE computation!")
        return 42

obj = Lazy()
print(inspect.getattr_static(obj, "value"))  # <property object> — no computation!
print(getattr(obj, "value"))                 # prints "EXPENSIVE computation!" then 42

# Vars shows instance dict only; getattr_static shows the class's raw descriptor
print(vars(obj))  # {} — property is on the class, not the instance
print(vars(Lazy)["value"])  # <property object>
```

### 9.5 Frame Introspection — Powerful, Fragile

```python
import inspect

def who_called_me():
    frame = inspect.currentframe()
    try:
        caller = frame.f_back
        print(f"called by {caller.f_code.co_name} at {caller.f_code.co_filename}:{caller.f_lineno}")
        print(f"caller locals: {list(caller.f_locals.keys())[:3]}")
    finally:
        del frame  # CRITICAL — avoid reference cycles (frames hold references to locals)
        del caller

def caller_func():
    x = 100
    who_called_me()

caller_func()

# inspect.stack() is convenient but expensive — it captures all frames
for frame_info in inspect.stack()[:2]:
    print(frame_info.function, frame_info.filename, frame_info.lineno)
```

*Warning:* Frames hold references to local variables, which can keep large objects alive and create cycles. Always `del frame` when done with `currentframe()`. Production loggers cache this carefully.

## 10. Putting It All Together — A Realistic Introspective Serializer

This example integrates `dir` vs `__dict__`, `isinstance`, `getattr`, `inspect.signature`, `__annotations__`, and `callable` into something you might actually ship.

```python
import inspect
from typing import get_type_hints

class Serializer:
    """Serialize an object's public attributes and computed properties."""

    @staticmethod
    def serialize(obj: object) -> dict:
        result: dict = {"_type": type(obj).__name__}

        # 1. Instance dict attributes (fast path)
        if hasattr(obj, "__dict__"):
            for k, v in vars(obj).items():
                if not k.startswith("_"):
                    result[k] = Serializer._value(v)

        # 2. Class-level properties and computed attributes (via inspect)
        for name, member in inspect.getmembers(type(obj)):
            if name.startswith("_"):
                continue
            if name in result:
                continue  # instance already won
            # Only include properties / simple attributes, not methods
            if isinstance(member, property):
                try:
                    # Use getattr to trigger the property — might fail!
                    result[name] = Serializer._value(getattr(obj, name))
                except Exception as exc:
                    result[name] = f"<error: {exc}>"
            elif not callable(member) and not inspect.isclass(member):
                # For slot attributes or plain class attrs, getattr_static to avoid side effects
                try:
                    val = inspect.getattr_static(obj, name)
                    # If it's not a descriptor, fetch the real value
                    if not hasattr(val, "__get__"):
                        result[name] = Serializer._value(getattr(obj, name))
                except AttributeError:
                    pass

        return result

    @staticmethod
    def _value(v):
        # Recurse for nested objects? Simplified here
        if isinstance(v, (str, int, float, bool, type(None))):
            return v
        if isinstance(v, (list, tuple, set)):
            return [Serializer._value(x) for x in v]
        return repr(v)

# Demo
class Product:
    """A product with a computed price."""
    category = "general"  # class attr

    def __init__(self, name: str, price: float, stock: int) -> None:
        self.name = name
        self.price = price
        self.stock = stock

    @property
    def in_stock(self) -> bool:
        return self.stock > 0

    def restock(self, n: int) -> None:  # should NOT appear in serialization
        self.stock += n

p = Product("Widget", 9.99, 5)
print(Serializer.serialize(p))
# {'_type': 'Product', 'name': 'Widget', 'price': 9.99, 'stock': 5, 'in_stock': True}

# Edge: slots
class SlottedProduct:
    __slots__ = ("name", "price")
    def __init__(self, name, price):
        self.name = name
        self.price = price

print(Serializer.serialize(SlottedProduct("Gadget", 19.99)))
# Works even though vars() would fail — getmembers path catches slots
```

*Explanation:* A production serializer (e.g., `dataclasses.asdict`, `pydantic`, `marshmallow`) is more sophisticated — it uses `get_type_hints`, handles generics, respects `__slots__`, and avoids triggering expensive properties. But the skeleton above is the pattern.

## 11. Distinguishing Commonly Confused Pairs

### 11.1 `type(x) is T` vs `isinstance(x, T)` vs `x.__class__ is T`

| Check | Respects inheritance | Respects ABC virtual subclasses | Fast | Use when |
|---|---|---|---|---|
| `type(x) is T` | No | No | Fastest | You need *exact* type (e.g., exclude `bool` from `int`) |
| `isinstance(x, T)` | Yes | Yes | Fast | Almost always — polymorphic code |
| `x.__class__ is T` | Same as `type(x) is T` but can be shadowed | No | Fast | Rarely; prefer `type()` |

### 11.2 `dir` vs `vars` vs `inspect.getmembers`

| Tool | Scope | Triggers descriptors | Includes inherited | Mutable result |
|---|---|---|---|---|
| `dir(obj)` | Curated, `__dir__`-aware | No (lists names) | Yes | No (`list`) |
| `vars(obj)` / `obj.__dict__` | Instance namespace only | No | No | Yes (`dict`) |
| `inspect.getmembers(obj)` | Full MRO + descriptors | **Yes** (fetches values) | Yes | No (list of pairs) |
| `inspect.getattr_static` | Single attribute, raw | No | Via MRO | — |

### 11.3 `hasattr` vs `getattr` with Default vs `try/except`

| Pattern | Behavior on broken property | Signals missing vs broken |
|---|---|---|
| `hasattr(obj, "x")` | Returns `False` (hides error) | No |
| `getattr(obj, "x", sentinel)` | Returns `sentinel` on `AttributeError`, but propagates other errors? Actually `getattr` with default still propagates non-AttributeError from property! Wait — no: 3-arg getattr *also* catches only AttributeError? Let's clarify: | Partially |
| `try: getattr(obj,"x"); except AttributeError:` | Correctly distinguishes | **Yes** |

```python
class Tricky:
    @property
    def broken(self):
        raise ValueError("oops")
    @property
    def missing_via_descriptor(self):
        raise AttributeError("not found")

t = Tricky()
print(hasattr(t, "broken"))                        # False — hides ValueError
print(getattr(t, "broken", "default"))             # raises ValueError! — 3-arg getattr does NOT suppress ValueError
try:
    getattr(t, "broken", "default")
except ValueError as exc:
    print(f"getattr raised: {exc}")               # correct: ValueError propagates

# For truly missing via AttributeError, default works:
print(getattr(t, "missing_via_descriptor", "default"))  # "default"
```

*Correction:* `hasattr` suppresses *all* exceptions; 3-argument `getattr` suppresses only `AttributeError` (returning the default), letting other exceptions propagate. This is why `hasattr` is more dangerous.

### 11.4 `callable` vs `inspect.isfunction` vs `inspect.ismethod` vs `inspect.isbuiltin`

```python
import inspect

def f(): pass
class C:
    def m(self): pass

c = C()
print(f"f: callable={callable(f)} isfunction={inspect.isfunction(f)} ismethod={inspect.ismethod(f)} isbuiltin={inspect.isbuiltin(f)}")
print(f"C.m (class): callable={callable(C.m)} isfunction={inspect.isfunction(C.m)} ismethod={inspect.ismethod(C.m)}")
print(f"c.m (bound): callable={callable(c.m)} isfunction={inspect.isfunction(c.m)} ismethod={inspect.ismethod(c.m)}")
print(f"len: callable={callable(len)} isfunction={inspect.isfunction(len)} isbuiltin={inspect.isbuiltin(len)}")
```

## 12. Common Mistakes and How to Avoid Them

| Mistake | Why it fails | Fix |
|---|---|---|
| `type(x) == int` to check "is integer" | Excludes `bool`, subclasses, virtual subclasses | `isinstance(x, int)` (or `type(x) is int` if you deliberately exclude subclasses) |
| `hasattr(obj, "attr")` to test optional feature where attr is a property | Property may raise, `hasattr` lies | `try: getattr(obj, "attr"); except AttributeError:` |
| Using `__dict__` to enumerate all attributes | Misses slots, class attrs, inherited, descriptors | Walk `type(obj).__mro__` + `vars()` + `inspect.getmembers` |
| `dir(obj)` for program logic | `__dir__` may be customized, order is sorted | Use `hasattr` / `getattr` / `vars` for logic; `dir` for REPL only |
| Storing `id(obj)` after `obj` may die | id is recycled | Keep a reference or use `weakref` |
| Assuming `callable(x)` means `inspect.isfunction(x)` | Classes, bound methods, builtins, callable instances all pass | Use specific `inspect.is*` if you need the kind |
| Reading `__annotations__` directly for forward refs | Forward refs stay as strings | Use `typing.get_type_hints(obj)` |
| Forgetting `vars(Class)` is a `mappingproxy` | `Class.__dict__[k] = v` raises `TypeError` | Use `setattr(Class, k, v)` |

## Summary

- Introspection is a first-class feature of Python's object model; every object knows its type and namespace.
- `type` / `isinstance` / `issubclass` answer "what are you?" — prefer `isinstance` for polymorphism, `type(x) is T` only for exact checks.
- `dir` is for humans; `vars`/`__dict__` + `inspect.getmembers` + MRO walking is for programs.
- `getattr`/`setattr`/`hasattr`/`delattr` are dynamic dot-operators; `hasattr` hides descriptor errors — prefer `try/except AttributeError`.
- `callable` checks type-level `__call__`; `inspect.isfunction`/`ismethod`/`isbuiltin` distinguish *kinds* of callables.
- `id` is a live address, not a fingerprint; it is recycled after GC.
- `__doc__` and `__annotations__` are runtime-accessible metadata; resolve annotations via `typing.get_type_hints`.
- `inspect` is the industrial toolkit: `signature` for call interfaces, `getmembers` for discovery, `getsource`/`getfile` for provenance, `getattr_static` for side-effect-free lookup, and frame introspection for debuggers (with care).
