# 9.3 Garbage Collection and Memory Management — How Python Manages Objects in Memory

> Understanding Python's memory model is the difference between "it works" and "it works at scale." The model is simple on the surface — *everything is a reference-counted heap object* — but the details (cyclic GC, weak references, `__del__`, interning, `__slots__`) determine whether your long-running service leaks, how fast it runs, and why `id()` can reuse addresses.

## Learning Goals

- Understand CPython's `PyObject`, `ob_refcnt`, `ob_type`, and the object heap.
- Master reference counting: how `sys.getrefcount` works, temporary references, and why deterministic destruction is a CPython artifact.
- Understand `id()` and reference semantics vs value semantics, and why id reuse happens.
- Learn string/integer interning and the small-int cache.
- Master the cyclic garbage collector: why it exists, the three generations, `gc` module, thresholds, and `gc.collect`/`get_referrers`/`get_referents`.
- Use `weakref` (`ref`, `WeakKeyDictionary`, `WeakValueDictionary`, `WeakSet`, `finalize`) to break cycles without leaking.
- Understand `__del__` pitfalls: resurrection, suppressed exceptions, non-deterministic order, and `weakref.finalize` as the safe alternative.
- Preview `__slots__` for memory savings and its trade-offs.
- Know the tools: `tracemalloc`, `gc` debugging, `pympler` / `objgraph` (overview), `sys.getsizeof`, and `__sizeof__`.

## 1. The Object Heap: `PyObject`, `ob_refcnt`, `ob_type`

In CPython, every Python value is a `PyObject` allocated on the private heap. Conceptually (simplified C):

```c
// Include/object.h — simplified
typedef struct _object {
    Py_ssize_t ob_refcnt;   // reference count
    PyTypeObject *ob_type;  // pointer to type (e.g., &PyLong_Type)
    // ... object-specific data follows
} PyObject;

typedef struct {
    PyObject ob_base;
    long ob_digit[1];       // variable-length digit array for ints
} PyLongObject;

typedef struct {
    PyObject ob_base;
    Py_ssize_t ob_size;     // length
    Py_hash_t ob_hash;      // cached hash, -1 means not computed
    // ... characters, etc.
} PyUnicodeObject;
```

What this means for Python programmers:

- **No value lives on the stack.** Assignment never copies a value; it copies a *pointer* and bumps `ob_refcnt`.
- **Types are objects too.** `type(int)` is `type`; `type(type)` is `type` — turtles all the way down (with a bootstrap).
- **The heap is managed by CPython's allocator** (pymalloc + system `malloc`), not directly by the OS.

```python
# Everything is an object — even types and functions
x = 42
print(type(x))              # <class 'int'>
print(type(type(x)))        # <class 'type'>
print(isinstance(int, object))  # True — int is an object too
print(isinstance(type, object)) # True — type is an object too

# Assignment copies references, not values — cheap, O(1)
a = [1, 2, 3]     # list object allocated on heap; `a` holds a pointer
b = a             # no copy — increments ob_refcnt of that list
print(a is b)     # True — same object
b.append(4)
print(a)          # [1, 2, 3, 4] — mutation visible via both names
```

### 1.1 Variables Are Names, Not Boxes

If you come from C++/Java, rewire your mental model:

| Language | `int x = 42; int y = x;` does | Python `x = 42; y = x` does |
|---|---|---|
| C++ (value) | Copies 42 into a new stack slot | — |
| C++ (pointer) | Copies a pointer explicitly | — |
| Java (primitive) | Copies value | — |
| Python | Both names point to the *same* `PyLongObject` (refcount 2 → 3 with `x`, `y`, plus internal refs) | No copy at all |

```python
# Illustrating reference semantics
original = [1, 2]
alias = original
copy = original.copy()  # or list(original), original[:], copy.copy(original)

print(original is alias)  # True — same object
print(original is copy)   # False — distinct object, equal value
print(original == copy)   # True

# Mutation affects aliases, not copies
alias.append(99)
print(original)  # [1, 2, 99]
print(copy)      # [1, 2]
```

## 2. Reference Counting — The Primary Collector

### 2.1 How It Works

Every `PyObject` has `ob_refcnt`. The interpreter maintains it via `Py_INCREF` / `Py_DECREF` macros:

- `x = obj` → `Py_INCREF(obj)` (count += 1)
- `del x` or `x = other` or scope exit → `Py_DECREF(old)` (count -= 1)
- When `ob_refcnt` hits 0 → `ob_type->tp_dealloc(obj)` is called *immediately* (in CPython).

This is *deterministic* in CPython: the moment the last reference dies, the object is finalized and its memory may be freed (or returned to a free list). In PyPy, GraalPy, or Jython, destruction is *non-deterministic* (GC may run later).

```python
import sys

# sys.getrefcount(obj) — returns ob_refcnt, but note: calling it creates a temporary reference!
x = [1, 2, 3]
print(sys.getrefcount(x))
# Usually 2: one for `x`, one for the temporary argument to getrefcount()
# If you write `print(sys.getrefcount([1,2,3]))` the count may be 1 (no name holds it except the temp)

# Demonstrating INCREF / DECREF
import sys
a = object()
print(sys.getrefcount(a))  # 2 (a + temp)
b = a
print(sys.getrefcount(a))  # 3 (a + b + temp)
del b
print(sys.getrefcount(a))  # 2 again
b = a
c = [a, a, a]              # list holds 3 references to the same object
print(sys.getrefcount(a))  # 6 (a + b + 3 in list + temp)
del c
print(sys.getrefcount(a))  # 3

# Scope-based DECREF — function exit releases locals
def demo():
    lst = [1] * 1000
    print(f"inside demo: {sys.getrefcount(lst)}")  # 2 inside

demo()
# after demo() returns, the list's refcount hit 0 and it was freed
```

*Explanation:* `sys.getrefcount` is a diagnostic, not a precise counter — it reports `ob_refcnt` at the instant of the call, including the temporary reference from argument passing. Its absolute number is rarely useful; the *delta* (did it increase?) is.

### 2.2 Immortal Objects (Python 3.12+)

Since Python 3.12, certain globally shared singletons (`None`, `True`, `False`, small ints, interned strings, etc.) are *immortal*: their `ob_refcnt` is set to a sentinel (`_Py_IMMORTAL_REFCNT`, 2³⁰ or greater) and `Py_INCREF`/`Py_DECREF` are no-ops for them. This avoids cache-line bouncing on the refcount in multi-threaded (free-threaded 3.13) builds.

```python
import sys
print(sys.getrefcount(None))   # e.g., 4294967295 — immortal sentinel, not a real count
print(sys.getrefcount(True))   # similarly huge
print(sys.getrefcount(0))      # also immortal (small int)
# For immortals, getrefcount returns the sentinel, not a meaningful count.
# Don't use getrefcount to reason about immortals.
```

### 2.3 Containers Hold References, Not Values

```python
import sys

inner = [1, 2, 3]
outer = [inner, inner, inner]
print(sys.getrefcount(inner))  # 5? — outer holds 3 refs + inner name + temp
print(outer[0] is outer[1] is outer[2])  # True — three pointers to one object

# Reassigning a slot decrefs the old value
outer[0] = [99]
print(sys.getrefcount(inner))  # drops by one — outer[0] no longer references it

# Clearing a container decrefs all elements
outer.clear()
print(sys.getrefcount(inner))  # back to 2 (inner + temp)
```

### 2.4 Temporary References — The Hidden Bumps

The interpreter creates hidden references constantly: argument tuples, frame objects, exception tracebacks, comprehensions, and more.

```python
import sys

x = []
print(sys.getrefcount(x))  # 2

# A function call creates a temporary argument tuple holding a ref
def take(obj):
    print(sys.getrefcount(obj))  # higher inside

take(x)  # 4? — x + temp for take's arg + frame's locals + getrefcount's temp

# Exception traceback holds a reference to the frame, which holds locals
try:
    raise ValueError("oops")
except ValueError as exc:
    import traceback
    tb = exc.__traceback__
    print(tb.tb_frame.f_locals)  # contains exc and tb — a reference cycle!
    # If you store `tb` globally, you keep the entire frame (and all locals) alive
    # Always `del tb` or use `traceback.print_exc()` and let it go

# Comprehension scoping (Python 3: list comps have their own scope, but not leaked)
y = [i for i in range(3)]
# The iteration variable `i` does NOT leak in Python 3 (it did in 2)
try:
    print(i)
except NameError:
    print("i not leaked — listcomp has its own scope")
```

*Rule:* Any time you reason about `getrefcount`, remember to subtract 1 for the `getrefcount` call itself, and consider frames, closures, containers, and tracebacks as hidden refs.

## 3. `id()`, Identity, and Address Reuse

### 3.1 `id()` Is the Address (in CPython)

As noted in §9.1, `id(obj)` returns the `PyObject*` address as an integer in CPython. It is *unique among simultaneously alive objects*, not globally unique over time.

```python
a = [1, 2, 3]
b = a
print(a is b)           # True
print(id(a) == id(b))   # True

c = [1, 2, 3]
print(a == c)           # True — equal value
print(a is c)           # False — distinct objects
print(id(a) == id(c))   # False

# The classic id-reuse trap
old_id = id([1, 2, 3])  # temporary list created, id taken, then refcount → 0, freed
# The address is now free. The next allocation may reuse it.
new_list = [4, 5, 6]
print(id(new_list) == old_id)  # *may* be True! — address recycled

# Safe pattern: keep the object alive if you need its id
a = [1, 2, 3]
a_id = id(a)
# a is still alive, so a_id is still a's address
assert a_id == id(a)

# Never do this:
ids = set()
for i in range(5):
    ids.add(id([i]))  # each list dies immediately; ids may contain duplicates!
print(ids)  # may have fewer than 5 entries — collision!

# Correct id-tracking — hold strong (or weak) references:
objects = [[i] for i in range(5)]
ids_correct = {id(obj) for obj in objects}
print(len(ids_correct))  # 5 — distinct, because objects are alive
```

### 3.2 When Object Identity Matters

```python
# Identity is meaningful for sentinels and singletons
_MISSING = object()  # unique sentinel — identity is the point
def get(d: dict, key, default=_MISSING):
    if default is _MISSING:
        # caller didn't pass a default — use different behavior
        return d[key]  # will raise KeyError
    return d.get(key, default)

# Identity vs equality for singletons
print(None is None)   # True — None is a singleton
print(True is True)   # True — immortal
# For general values, prefer ==; for singletons/sentinels, prefer `is`
```

## 4. Interning and the Small-Object Caches

CPython reuses *some* immutable objects rather than allocating new ones — an optimization that also happens to make `is` appear to work for values (which it should not).

### 4.1 Small Integer Cache: `[-5, 256]`

```python
# At interpreter startup, CPython pre-allocates PyLongObjects for -5..256
a = 100
b = 100
print(a is b)  # True — both point to the pre-allocated "100" object

a = 257
b = 257
# In a script, the compiler's constant folding may merge them, so `is` may be True!
# To see non-cached behavior, force runtime creation:
import sys
a = int("257")
b = int("257")
print(a is b)  # False — distinct objects (usually)
print(a == b)  # True

# Negative side
a = -5
b = -5
print(a is b)  # True — cached
a = int("-6")
b = int("-6")
print(a is b)  # False — -6 is below the cache range
print(a == b)  # True

# Never use `is` for integer value comparison — use `==`.
# The cache is an implementation detail; PyPy may cache differently.
```

### 4.2 String Interning

```python
import sys

# String interning: CPython interns some strings — identifiers, short strings in code,
# and explicitly via sys.intern()
a = "hello"
b = "hello"
print(a is b)  # True — compiler interned the literal (often, but not guaranteed for all strings)

# Dynamically built strings are usually NOT interned:
a = "hello world".replace(" ", "_")
b = "hello world".replace(" ", "_")
print(a is b)  # False — runtime construction, distinct objects
print(a == b)  # True

# Explicit interning for performance — when you have many duplicate strings (e.g., CSV columns)
a = sys.intern("hello_world_dynamic_12345_!@#")
b = sys.intern("hello_world_dynamic_12345_!@#")
print(a is b)  # True — interned to the same object

# Why intern? Dict lookups on interned strings can use pointer comparison first (fast path),
# and many copies of the same string save memory (one object, many references).
# CPython's dict and set implementations exploit string interning for speed.

# Interning happens automatically for:
# - String literals that look like identifiers (PEP 223/659 details, but roughly /[A-Za-z0-9_]+/)
# - Attribute names, variable names
# Not interned: strings with spaces/punctuation built at runtime, unless you intern them.
```

### 4.3 Other Caches: Empty Tuple, Frozenset, etc.

```python
# The empty tuple is a singleton
a = ()
b = ()
print(a is b)  # True — one immortal empty tuple

# Empty frozenset is also a singleton (implementation detail)
print(frozenset() is frozenset())  # True

# Floats and larger tuples are NOT cached — each literal creates a new object (unless constant-folded)
```

*Rule:* Never write `x is "hello"` or `x is 257` expecting value comparison. Interning is an optimization that you *benefit from* implicitly (faster `==` for interned strings, less memory for repeated keys) but should never *rely on* for correctness.

## 5. The Cyclic Garbage Collector — When Reference Counting Is Not Enough

Reference counting alone cannot reclaim *reference cycles*: groups of objects that reference each other but are unreachable from any root.

```python
# The classic cycle
class Node:
    def __init__(self, name):
        self.name = name
        self.ref = None
    def __repr__(self):
        return f"Node({self.name!r})"

a = Node("a")
b = Node("b")
a.ref = b
b.ref = a        # a ↔ b cycle
# a.refcount: a → b (via a.ref), b → a (via b.ref), plus variables a, b

del a
del b
# Now the two Nodes each have refcount 1 (from each other), but no variable reaches them.
# Pure reference counting would leak them forever.
# CPython's cyclic GC will collect them — eventually.
```

### 5.1 Why Cycles Only Affect Containers

Non-containers (ints, floats, strings, tuples of non-containers) cannot be part of a cycle — they hold no references to other Python objects (or, for tuples, the GC tracks them but they cannot create self-cycles without help). The GC only tracks *containers*: `list`, `dict`, `set`, user-defined classes with `__dict__`/`__slots__`, etc. Objects with `__slots__` that hold only non-container slots may be untracked.

```python
import gc

# gc.is_tracked — is this object tracked by the cyclic GC?
print(gc.is_tracked([]))          # True — list is a container
print(gc.is_tracked({}))          # True — dict
print(gc.is_tracked(42))          # False — int cannot hold refs
print(gc.is_tracked("hello"))     # False
print(gc.is_tracked((1, 2)))      # False — tuple of non-containers is untracked
print(gc.is_tracked(([1],)))      # True — tuple containing a tracked object is tracked

class WithSlots:
    __slots__ = ("x",)            # only one slot
print(gc.is_tracked(WithSlots())) # False — no __dict__, no tracked refs

class WithDict:
    pass
print(gc.is_tracked(WithDict()))  # True — has __dict__
```

### 5.2 How the GC Finds Cycles (Conceptual)

1. **Collect candidates:** Walk all tracked container objects; for each, subtract the number of references *from other tracked containers* from its `ob_refcnt`. If the count drops to 0, the object is *only* referenced from within the container subgraph and is unreachable.
2. **Identify unreachable subgraphs:** Move those objects to an "unreachable" set.
3. **Reclaim:** Destroy the unreachable objects (calling `tp_clear` to break cycles, then `tp_dealloc`).

This is roughly a *generational, incremental* GC. Details: CPython uses doubly-linked lists per generation and a tri-color marking variant for efficiency.

### 5.3 Generations: 0, 1, 2

Objects start in *generation 0*. If they survive a collection, they are promoted to generation 1, then 2. Each generation has a threshold. The GC triggers when `allocations - deallocations > threshold`.

```python
import gc

print(gc.get_threshold())  # e.g., (700, 10, 10) — defaults
# gen0: collect when 700 more allocs than deallocs since last gen0 collect
# gen1: collect when gen0 has been collected 10 times without gen1 being collected
# gen2: similarly for gen1 → gen2

# You can tune thresholds:
# gc.set_threshold(700, 10, 10)  # defaults — don't change unless you measure

# Generational hypothesis: "most objects die young" — so gen0 is collected often, gen2 rarely.
# This makes GC fast for the common case (short-lived temporaries).

# Inspect generations
print(gc.get_count())  # (gen0_count, gen1_count, gen2_count) — current allocation surplus per gen
# Example output: (123, 4, 1)

# Force a collection
collected = gc.collect()            # collect gen2 (and thus all gens) — returns number of objects collected
print(f"collected {collected}")
print(gc.collect(generation=0))     # collect only gen0 — less disruptive

# Generation of an object?
# There is no public API for "which generation is obj in?" — but you can infer:
print(gc.get_referrers([]))  # not generational, just referrers
```

**Tuning advice:**

- *Almost never* tune `gc.set_threshold`. The defaults are well-chosen.
- Disabling GC (`gc.disable()`) can speed up bulk allocations (e.g., loading a large dataset) if you know you create no cycles — but you must re-enable it.
- For latency-sensitive servers, some teams run `gc.collect(generation=1)` periodically to avoid a long gen2 pause — measure with `gc.get_stats()`.

```python
import gc, time

# Experimental: measuring GC pause (do not tune blindly)
gc.enable()
stats_before = gc.get_stats()  # per-generation stats: collections, collected, uncollectable
# ... run workload ...
# gc.set_threshold(700, 10, 10)  # only after profiling
```

### 5.4 The `gc` Module — Debugging Cycles

```python
import gc

# gc.get_referrers(*objs) — who points TO obj?
# gc.get_referents(*objs) — who obj points TO
a = Node("a")
b = Node("b")
a.ref = b
b.ref = a

print(gc.get_referents(a))   # [Node(b)] — what a references (its __dict__ contains b)
print(gc.get_referrers(b))   # includes a.__dict__ and variable b

# Finding leaked cycles
gc.collect()  # clean start

# Intentionally leak a cycle for demo (in Python 3.4+, cycles with __del__ are collectable via PEP 442,
# but historically they were "uncollectable" and put in gc.garbage — see §7)
gc.set_debug(gc.DEBUG_SAVEALL)  # save all unreachable to gc.garbage instead of freeing
a = Node("leaker_a")
b = Node("leaker_b")
a.ref = b
b.ref = a
del a, b
collected = gc.collect()
print(f"collected: {collected}, garbage: {gc.garbage[:2]}")
gc.set_debug(0)
gc.garbage.clear()

# get_objects — all tracked objects (huge!) — use sparingly, for debugging only
# print(len(gc.get_objects()))  # tens of thousands

# gc.is_tracked — already covered
# gc.is_finalized(obj) — has the GC already finalized this object? (3.9+)

# Finding reference leaks with get_referrers — common technique
lst = [1, 2, 3]
referrers = gc.get_referrers(lst)
print(f"{len(referrers)} referrers")
# Note: get_referrers returns a list that itself holds a reference — beware!
```

### 5.5 When GC Runs: `gc.enable()` / `disable()` / `isenabled()`

```python
import gc

print(gc.isenabled())  # True by default

# Disable for a bulk load — manual pattern:
gc.disable()
try:
    data = [list(range(100)) for _ in range(10000)]  # many allocs, no cycles
finally:
    gc.enable()

# Or use gc.freeze() (3.7+) — move all tracked objects to the "permanent" generation
# so they are not scanned on every collection. Useful before forking.
# gc.freeze()

# Callback for GC events (3.3+)
def gc_callback(phase, info):
    if phase == "start":
        print(f"GC gen {info['generation']} starting")
    else:
        print(f"GC gen {info['generation']} done: collected {info['collected']}")

gc.callbacks.append(gc_callback)
gc.collect()
gc.callbacks.remove(gc_callback)
```

## 6. `weakref` — References That Don't Keep Objects Alive

A *weak reference* points to an object without incrementing its `ob_refcnt`. If the only remaining references are weak, the object dies and the weak reference becomes dead (`None`).

Use `weakref` when you want to *observe* or *cache* an object without preventing its collection.

### 6.1 Basic `weakref.ref`

```python
import weakref, gc

class Widget:
    def __init__(self, name):
        self.name = name
    def __repr__(self):
        return f"Widget({self.name!r})"

w = Widget("main")
r = weakref.ref(w)        # r is a weak reference to w
print(r)                  # <weakref at ...; to 'Widget' at ...>
print(r())                # Widget('main') — call the ref to dereference
print(r() is w)           # True — same object

# Callback when the object dies
def on_death(ref):
    print(f"Widget died: {ref}")

r2 = weakref.ref(w, on_death)
del w                     # refcount hits 0 → Widget finalized → callback fires
# prints: Widget died: <weakref at ...; dead>
print(r())                # None — dead reference
print(r2())               # None
gc.collect()              # ensure cleanup

# Not all types support weak references — only those with tp_weaklistoffset
# Builtins like list, dict, int, str do NOT support weakref (no weaklist slot)
try:
    weakref.ref([1, 2, 3])
except TypeError as exc:
    print(f"cannot weakref list: {exc}")

# Types that DO support weakref: user-defined classes, functions, methods, some builtins
class MyClass: pass
print(weakref.ref(MyClass()))  # ok
print(weakref.ref(lambda: None))  # ok — functions are weakrefable

# To make a class weakrefable if it uses __slots__, include "__weakref__" in slots
class SlottedNoWeak:
    __slots__ = ("x",)
try:
    weakref.ref(SlottedNoWeak())
except TypeError as e:
    print(f"slotted no weak: {e}")

class SlottedWeak:
    __slots__ = ("x", "__weakref__")
print(weakref.ref(SlottedWeak()))  # ok
```

### 6.2 `WeakKeyDictionary`, `WeakValueDictionary`, `WeakSet`

These are drop-in replacements for `dict`/`set` whose keys/values/elements do not prevent GC.

```python
import weakref, gc

# WeakKeyDictionary — keys are weak; entries disappear when keys die
class Owner: pass

cache = weakref.WeakKeyDictionary()
owner = Owner()
cache[owner] = "some data for owner"
print(len(cache))   # 1
print(cache[owner]) # "some data for owner"
del owner
gc.collect()
print(len(cache))   # 0 — entry vanished!

# WeakValueDictionary — values are weak; useful for caches / flyweights
class BigData:
    def __init__(self, key): self.key = key

images = weakref.WeakValueDictionary()
data = BigData("image1")
images["image1"] = data
print("image1" in images)  # True
del data
gc.collect()
print("image1" in images)  # False — value was collected

# WeakSet — elements are weak
ws = weakref.WeakSet()
obj = Owner()
ws.add(obj)
print(obj in ws)  # True
del obj
gc.collect()
print(len(ws))    # 0

# Realistic: observer pattern without leaking
class EventSource:
    def __init__(self):
        self._listeners = weakref.WeakSet()  # listeners can be GC'd without unregistering
    def add_listener(self, listener):
        self._listeners.add(listener)
    def emit(self, event):
        for listener in list(self._listeners):
            listener(event)

def my_listener(event):
    print(f"heard {event}")

src = EventSource()
src.add_listener(my_listener)
src.emit("hello")  # heard hello
# If using a bound method, WeakSet needs WeakMethod — see below
```

### 6.3 `weakref.WeakMethod` and Bound Methods

Bound methods are *created on access* — `obj.method` builds a new `method` object each time. A plain `weakref.ref(obj.method)` would die immediately (the method object has no other refs). Use `WeakMethod`.

```python
import weakref, gc

class Service:
    def on_event(self, event):
        print(f"Service heard {event}")

svc = Service()
src = EventSource()

# Wrong — weakref to bound method dies immediately
try:
    r = weakref.ref(svc.on_event)
    print(r())  # None — method object was temporary, already freed!
except TypeError:
    pass

# Correct — WeakMethod holds weak refs to both instance and function
wm = weakref.WeakMethod(svc.on_event)
print(wm())         # <bound method Service.on_event ...>
print(wm() is svc.on_event)  # False — new method object each time, but logically same
print(wm()() if wm() else "dead")

# WeakSet doesn't handle bound methods correctly — use WeakMethod manually or a helper
# For observer patterns with bound methods, store WeakMethod objects:
class EventSource2:
    def __init__(self):
        self._listeners: list[weakref.WeakMethod] = []
    def add_listener(self, method):
        self._listeners.append(weakref.WeakMethod(method))
    def emit(self, event):
        alive = []
        for wm in self._listeners:
            m = wm()
            if m is not None:
                m(event)
                alive.append(wm)
        self._listeners = alive

src2 = EventSource2()
svc2 = Service()
src2.add_listener(svc2.on_event)
src2.emit("hello")  # Service heard hello
del svc2
gc.collect()
src2.emit("hello again")  # no output — listener was GC'd
print(len(src2._listeners))  # 0 — pruned
```

### 6.4 `weakref.finalize` — The Safe `__del__` (see §7)

```python
import weakref, gc

class Resource:
    def __init__(self, name):
        self.name = name
        print(f"Resource {name} created")
        # Register a finalizer that doesn't keep the Resource alive
        self._finalizer = weakref.finalize(self, self._cleanup, name)

    @staticmethod
    def _cleanup(name):
        print(f"Resource {name} cleaned up!")

r = Resource("A")
print(r._finalizer.alive)  # True
del r
gc.collect()   # prints: Resource A cleaned up!

# You can also detach or check:
# r._finalizer.detach()  # cancel finalizer
# r._finalizer()         # run it early
# weakref.finalize(obj, func, *args, **kwargs) — func(*args, **kwargs) at finalization
```

## 7. `__del__` — The Finalizer and Its Pitfalls

`__del__(self)` is called when the object's refcount hits 0 (CPython) or when the GC reclaims it (other impls). It is also called for GC-collected cycles. It is *the most misunderstood method in Python*.

### 7.1 When `__del__` Is Called (and When It Is Not)

```python
class WithDel:
    def __init__(self, name):
        self.name = name
        print(f"{name} born")
    def __del__(self):
        print(f"{self.name} finalized via __del__")

# Normal case — refcount hits 0, __del__ called deterministically in CPython
obj = WithDel("normal")
del obj  # prints: normal finalized via __del__ (immediately in CPython; not in PyPy)

# Cycle case — two objects in a cycle, both with __del__
class CyclicWithDel:
    def __init__(self, name):
        self.name = name
        self.ref = None
    def __del__(self):
        print(f"{self.name} __del__")

a = CyclicWithDel("a")
b = CyclicWithDel("b")
a.ref = b
b.ref = a
del a, b
import gc
collected = gc.collect()  # In Python 3.4+ (PEP 442), cycles with __del__ ARE collectable!
print(f"collected {collected}")
# Prints: a __del__ and b __del__ (order is arbitrary — see below)
# Pre-3.4, they would have been put in gc.garbage and never finalized — a leak.
```

### 7.2 The Four Pitfalls

#### Pitfall 1: `__del__` Exceptions Are Ignored (with a Warning)

```python
import warnings

class BadDel:
    def __del__(self):
        raise RuntimeError("boom in finalizer")

obj = BadDel()
del obj
# Prints to stderr: Exception ignored in: <function BadDel.__del__>
# And: RuntimeError: boom in finalizer
# The exception is NOT propagated — it cannot be, because the call site is the GC, not your code.
# This makes bugs in __del__ silent.

# Enable warnings to see them:
warnings.filterwarnings("always")
obj2 = BadDel()
del obj2  # now louder
```

#### Pitfall 2: `__del__` Can Resurrect the Object

```python
zombie = None

class Resurrector:
    def __del__(self):
        global zombie
        zombie = self  # resurrect by storing a new reference!
        print("resurrected!")

r = Resurrector()
del r
import gc; gc.collect()
print(zombie)  # <__main__.Resurrector ...> — alive again!
# The GC will call __del__ at most once per object (PEP 442: if resurrected, not called again on second death).
del zombie
gc.collect()  # no second __del__ print — only called once
```

#### Pitfall 3: Non-Deterministic Order for Cycles

```python
class Named:
    def __init__(self, name): self.name = name; self.ref = None
    def __del__(self):
        # Accessing self.ref here is dangerous — it may already be finalized or None!
        # Order of finalization within a cycle is arbitrary.
        other = getattr(self, "ref", None)
        other_name = getattr(other, "name", "<dead>") if other else "<none>"
        print(f"{self.name} dying, ref to {other_name}")

a = Named("a")
b = Named("b")
a.ref = b
b.ref = a
# On collection, you might see:
# a dying, ref to b  — then b dying, ref to a
# but b's __dict__ might already be cleared when a runs, so a.ref could be None!
del a, b
import gc; gc.collect()
```

#### Pitfall 4: `__del__` Runs in Arbitrary Context (GC, Interpreter Shutdown)

- During `gc.collect()`, `__del__` runs *inside the GC* — the heap may be in an inconsistent state.
- At interpreter shutdown, globals may already be `None` (`sys.modules`, `open`, etc. torn down). Code that uses globals in `__del__` may fail.

```python
class AtShutdown:
    def __del__(self):
        # At shutdown, `print` or `open` may already be None!
        import sys
        # sys.stdout may be None — guard
        if sys.stdout:  # rare but real during shutdown
            print("dying at shutdown")

# The interpreter calls __del__ for remaining objects during shutdown, but order is not guaranteed,
# and some modules may already be finalized.
```

### 7.3 The Safe Alternatives

#### Alternative 1: Context Managers (`with`) for Deterministic Cleanup

```python
class ManagedResource:
    def __init__(self, name):
        self.name = name
        print(f"acquire {name}")
    def close(self):
        print(f"release {self.name}")
    def __enter__(self):
        return self
    def __exit__(self, exc_type, exc, tb):
        self.close()
        return False  # don't suppress exceptions
    # __del__ as a safety net only (optional, with warnings)
    def __del__(self):
        # Only warn — don't rely on this for correctness
        import warnings
        warnings.warn(f"Resource {self.name} not closed — use 'with'", ResourceWarning)

# Correct — deterministic
with ManagedResource("file") as r:
    print(f"using {r.name}")
# prints: acquire file / using file / release file — even if an exception occurs

# Wrong — relies on __del__
r = ManagedResource("leaky")
del r  # may or may not clean up; if a cycle, delayed; if exception in __del__, silent
```

#### Alternative 2: `weakref.finalize` (Recommended for Non-`with` Cleanup)

```python
import weakref

class SafeResource:
    def __init__(self, filename):
        self.filename = filename
        self._file = open(filename, "w")
        # Finalizer holds only weak ref to self; static method avoids cycle via `self`
        self._finalizer = weakref.finalize(self, self._close_file, self._file, filename)

    @staticmethod
    def _close_file(file_obj, filename):
        try:
            file_obj.close()
            print(f"closed {filename}")
        except Exception as exc:
            print(f"error closing {filename}: {exc}")

    def close(self):
        if self._finalizer.detach():  # cancel finalizer if we close explicitly
            self._file.close()
            print(f"explicitly closed {self.filename}")

import tempfile, os, gc
tmp = tempfile.mktemp()
r = SafeResource(tmp)
r.close()   # explicit — finalizer detached, no double-close
r2 = SafeResource(tmp)
del r2
gc.collect()  # finalizer runs if not explicitly closed
os.unlink(tmp)
```

*Rule:* Use `__del__` only if you fully understand resurrection, exception suppression, cycle order, and shutdown semantics. For 99% of code, use `with` + `weakref.finalize` as a safety net instead.

## 8. Memory Management: Allocation, pymalloc, and Free Lists

### 8.1 CPython's Allocator Layers

```
Python object (e.g., `list`, `dict`, `str`)
        │
        ├──→ pymalloc (for objects ≤ 512 bytes) — arena (256 KB) → pool (4 KB) → block
        │         Fast, low-fragmentation, per-size free lists
        └──→ system malloc (for objects > 512 bytes) — directly to `malloc`/`free`
```

- **pymalloc** is CPython's small-object allocator. It carves 256 KB arenas into 4 KB pools, each pool serving one size class (8, 16, 24, ... 512 bytes). Free blocks go on a free list and are reused quickly.
- **Free lists** for specific types: `list`, `dict`, `tuple`, `frame`, `float` etc. maintain their own free lists of deallocated objects. `[]` allocation often reuses a freed list object without calling `malloc` at all.

```python
import sys

# sys.getsizeof — shallow size in bytes (not counting referenced objects)
print(sys.getsizeof([]))        # ~56 bytes — empty list overhead
print(sys.getsizeof([1, 2, 3])) # ~88 bytes — array of 3 pointers
print(sys.getsizeof(42))        # 28 bytes — PyLongObject with one digit
print(sys.getsizeof("hello"))   # ~54 bytes — PyUnicode overhead + characters

# getsizeof is shallow — the list size doesn't include the ints it points to!
lst = [1, 2, 1000]
print(sys.getsizeof(lst))           # list overhead + pointer array
print(sum(sys.getsizeof(x) for x in lst))  # ints themselves
# For deep size, use pympler.asizeof (see §9)

# Free list demo — allocation reuses freed objects
import gc
a = [1, 2, 3]
addr_a = id(a)
del a
b = [4, 5, 6]
print(id(b) == addr_a)  # *often* True — list free list reused the block
```

### 8.2 When Memory Is Freed vs Returned to the OS

- pymalloc **rarely returns memory to the OS** — arenas are kept as free pools for reuse. A process's RSS (resident set size) may stay high even after you `del` large objects.
- `gc.collect()` frees *unreachable* cycle objects, but their arenas may remain pooled.
- To *actually* release memory to the OS, you need `malloc_trim` (Linux, `ctypes.CDLL("libc.so.6").malloc_trim(0)`) or to allocate >512 bytes with `mmap` (not typical). Usually you just accept that Python holds onto freed arenas for reuse — it is not a leak, it is a cache.

```python
# Demonstrating RSS retention (conceptual — need psutil to measure)
# pip install psutil
try:
    import psutil, os, gc
    proc = psutil.Process(os.getpid())
    before = proc.memory_info().rss
    big = [bytearray(10_000) for _ in range(1000)]
    after_alloc = proc.memory_info().rss
    print(f"RSS after alloc: {(after_alloc - before) / 1e6:.1f} MB")
    del big
    gc.collect()
    after_free = proc.memory_info().rss
    print(f"RSS after del+gc: {(after_free - before) / 1e6:.1f} MB")
    # RSS may not drop much — arenas are pooled, not returned to OS
    # This is normal; allocating again will reuse the pool without new OS allocation
except ImportError:
    print("psutil not installed — skip RSS demo")
```

## 9. `__slots__` — Trading Flexibility for Memory (and Speed)

By default, each instance has a `__dict__` (a `dict`) and a `__weakref__` slot. Both are overhead: the dict alone is ~56 bytes empty, plus table. `__slots__` replaces `__dict__` with a compact C array of slots.

### 9.1 How `__slots__` Works

```python
import sys

class Normal:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class Slotted:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x = x
        self.y = y

n = Normal(1, 2)
s = Slotted(1, 2)

print(vars(n))                    # {'x': 1, 'y': 2}
try:
    print(vars(s))
except TypeError as e:
    print(f"vars(slotted): {e}")  # vars() argument must have __dict__

print(hasattr(s, "__dict__"))     # False
print(hasattr(s, "__weakref__"))  # False — unless you include it

print(sys.getsizeof(n) + sys.getsizeof(n.__dict__))  # Normal: instance + dict
print(sys.getsizeof(s))                                # Slotted: much smaller

# Memory savings are dramatic at scale:
# For 1 million instances, Normal may use ~200 MB, Slotted ~50 MB (plus no per-instance dict)
```

### 9.2 `__slots__` Trade-offs and Gotchas

```python
# Gotcha 1: No __dict__ means no dynamic attributes
class Slotted:
    __slots__ = ("x",)
s = Slotted()
s.x = 1
try:
    s.y = 2
except AttributeError as e:
    print(f"no dynamic attr: {e}")

# If you need *some* dynamic attrs, include "__dict__" in slots
class SlottedWithDict:
    __slots__ = ("x", "__dict__")
s = SlottedWithDict()
s.x = 1
s.y = 2  # ok — goes into __dict__
print(s.__dict__)  # {'y': 2}

# Gotcha 2: No __weakref__ by default — need it for weakref support
class SlottedNoWeak:
    __slots__ = ("x",)
try:
    import weakref; weakref.ref(SlottedNoWeak())
except TypeError as e:
    print(f"no weakref: {e}")

class SlottedWeak:
    __slots__ = ("x", "__weakref__")
import weakref
print(weakref.ref(SlottedWeak()))  # ok

# Gotcha 3: Slots are descriptors on the class — class attribute access is different
class Slotted2:
    __slots__ = ("x",)
print(Slotted2.__slots__)  # ('x',)
print(type(Slotted2.x))    # <class 'member_descriptor'>

# Gotcha 4: Inheritance with slots is subtle — child must also define __slots__ or it gets a __dict__
class Base:
    __slots__ = ("a",)
class Child(Base):
    __slots__ = ("b",)  # only b here; a is inherited
    def __init__(self, a, b):
        self.a = a
        self.b = b

c = Child(1, 2)
print(c.a, c.b)
# If Child didn't define __slots__, it would have a __dict__ and lose memory benefits

# Gotcha 5: Slots don't support class-level defaults via __dict__ assignment in the usual way
class SlottedDefault:
    __slots__ = ("x",)
    x = 10  # this is a class attribute shadowing the slot — confusing!
# Use __init__ to set defaults instead

# Gotcha 6: Pickling with slots works but requires care (slot values are pickled via __getstate__/__setstate__
# or via __slots__ enumeration — stdlib pickle handles it, but custom __reduce__ may need updating)

# When to use __slots__
# - Millions of instances (e.g., graph nodes, rows, tokens) — memory and speed win.
# - Fixed schema — no dynamic attributes needed.
# - Micro-optimization for hot paths.
# When NOT to use __slots__
# - Normal application code with modest instance counts — flexibility is worth the memory.
# - When you need dynamic attributes, multiple inheritance complexity, or monkey-patching.
```

## 10. Diagnosing Memory: `tracemalloc`, `gc`, `sys.getsizeof`, and Friends

### 10.1 `sys.getsizeof` and Deep Size

```python
import sys

# Shallow
print(sys.getsizeof([1, 2, 3]))  # only the list, not the ints

# Deep — roll your own or use pympler
def deep_size(obj, seen=None):
    """Recursively compute deep size. Naïve — doesn't handle cycles."""
    if seen is None:
        seen = set()
    obj_id = id(obj)
    if obj_id in seen:
        return 0
    seen.add(obj_id)
    size = sys.getsizeof(obj)
    if isinstance(obj, dict):
        for k, v in obj.items():
            size += deep_size(k, seen)
            size += deep_size(v, seen)
    elif isinstance(obj, (list, tuple, set, frozenset)):
        for item in obj:
            size += deep_size(item, seen)
    return size

print(deep_size({"a": [1, 2, 3], "b": {"c": 42}}))
# For production, use pympler.asizeof.asizeof which handles cycles, slots, etc.
try:
    from pympler.asizeof import asizeof
    print(asizeof({"a": [1, 2, 3], "b": {"c": 42}}))
except ImportError:
    print("pympler not installed — pip install pympler for accurate deep sizing")
```

### 10.2 `tracemalloc` — The Stdlib Memory Profiler (Python 3.4+)

`tracemalloc` tracks *where* memory was allocated, per-file and per-line. It is the official way to find memory leaks in Python.

```python
import tracemalloc

tracemalloc.start()  # start tracking — takes a snapshot of current allocations

# ... run some code that should allocate ...
data = []
for i in range(10000):
    data.append([i] * 10)

snapshot = tracemalloc.take_snapshot()
print("Top 5 memory allocations by line:")
for stat in snapshot.statistics("lineno")[:5]:
    print(stat)
# Example output:
# /path/this_file.py:12: size=800 KiB, count=10000, average=80 B

# Compare snapshots to find leaks
snapshot2 = tracemalloc.take_snapshot()
top = snapshot2.compare_to(snapshot, "lineno")
print("Differences after more work:")
for stat in top[:5]:
    print(stat)

# Filter by file
for stat in snapshot.statistics("filename")[:3]:
    print(stat)

tracemalloc.stop()

# Realistic leak hunt — compare before and after an operation that should free memory
def hunt_leak():
    tracemalloc.start()
    snap_before = tracemalloc.take_snapshot()

    # Operation that should be memory-neutral
    cache = {}
    for i in range(5000):
        cache[i] = "x" * 100
    del cache
    import gc; gc.collect()

    snap_after = tracemalloc.take_snapshot()
    tracemalloc.stop()
    for stat in snap_after.compare_to(snap_before, "lineno")[:5]:
        print(stat)
        # If the delta is large, your operation leaked — look at the traceback for that line
        print("\n".join(str(tb) for tb in stat.traceback.format()[:3]))

hunt_leak()

# Important: tracemalloc only tracks Python-allocated memory (via pymalloc/malloc),
# not memory allocated by C extensions that use their own allocators.
# For full process memory, use psutil or OS tools alongside tracemalloc.
```

## 11. Common Memory Leak Patterns (and Fixes)

| Leak pattern | Why it leaks | Fix |
|---|---|---|
| **Global list/dict that only grows** | Strong refs never removed | Use `WeakValueDictionary`/`WeakSet` or LRU eviction; bound size |
| **Cache without eviction** (`dict` as cache) | Keys/values never freed | `functools.lru_cache`, `cachetools`, or manual eviction; `WeakValueDictionary` if values can be GC'd |
| **Circular refs with `__del__` (pre-3.4)** | Uncollectable cycles → `gc.garbage` | `weakref.finalize` or `weakref` to break the cycle; upgrade to 3.4+ (but still avoid `__del__`) |
| **Closure capturing large object** | `def inner(): ...` holds `large` in `__closure__` | `del large` after use, or don't close over it; use `weakref` if appropriate |
| **Traceback keeping frames alive** | `try: ... except E as e: store(e)` — `e.__traceback__` holds the frame and all locals | `del e` after handling, or `exc = None`, or don't store the exception |
| **Bound method + strong observer list** | `listeners.append(obj.method)` keeps `obj` alive | `WeakMethod` or `WeakSet` with weak refs to listeners |
| **`__slots__` without `__weakref__`** | Can't use weakrefs to break cycles involving slots instances | Add `"__weakref__"` to `__slots__` |
| **`id()` reuse confusion** | Storing `id(obj)` without holding `obj` | Keep a weak/strong reference alongside the id |
| **C extension holding `Py_INCREF`** | Native code incremented count but never decremented | Fix in C; use `tracemalloc` + `objgraph` to identify |

```python
# Closure leak example and fix
def make_handler():
    large = bytearray(10_000_000)  # 10 MB
    def handler(event):
        # handler.__closure__ holds a cell pointing to `large` — even if handler never uses it!
        print(f"handling {event}")
    return handler

h = make_handler()
print(h.__closure__)  # (<cell at ...: bytearray ...>,) — 10 MB kept alive!
# Fix: don't close over `large` if you don't need it, or delete after capture
def make_handler_fixed():
    large = bytearray(10_000_000)
    result = process(large)  # use it
    del large                # release before closing
    def handler(event):
        print(f"handling {event} with {result}")
    return handler

# Traceback leak — the classic "store the exception"
import sys, traceback
try:
    1 / 0
except ZeroDivisionError as exc:
    stored_exc = exc  # exc.__traceback__ holds the frame with all locals — leak!
# Fix: clear the traceback ref after you're done
try:
    1 / 0
except ZeroDivisionError as exc:
    stored_msg = str(exc)  # extract what you need
    stored_exc = None  # or: exc = None  (del exc) — breaks the cycle
    # Don't store `exc` in a global/long-lived object

# Observer with strong refs — leaks listeners
class Source:
    def __init__(self):
        self.listeners = []  # strong — listeners never die
    def add(self, fn):
        self.listeners.append(fn)

# Fix: weak refs for listeners that are methods
import weakref
class SourceFixed:
    def __init__(self):
        self.listeners = weakref.WeakSet()  # or list of WeakMethod for bound methods
    def add(self, fn):
        self.listeners.add(fn)
```

## 12. Putting It All Together — A Leak-Free Cache with Instrumentation

```python
import weakref, gc, tracemalloc, functools
from collections import OrderedDict

# A realistic cache: strong OrderedDict with LRU eviction + weak values for large objects
# Combines reference counting, weakrefs, GC awareness, and tracemalloc

class LRUCache:
    """Bounded cache — strong keys, LRU eviction, optional weak values."""

    def __init__(self, maxsize: int = 128, weak_values: bool = False):
        self.maxsize = maxsize
        self._data: OrderedDict | weakref.WeakValueDictionary
        if weak_values:
            # WeakValueDictionary doesn't support OrderedDict ordering — use manual + callbacks
            self._data = weakref.WeakValueDictionary()
            self._order: OrderedDict = OrderedDict()
        else:
            self._data = OrderedDict()

    def get(self, key):
        if key not in self._data:
            return None
        # Move to end (most recently used)
        if not isinstance(self._data, weakref.WeakValueDictionary):
            self._data.move_to_end(key)
        else:
            if key in self._order:
                self._order.move_to_end(key)
        return self._data[key]

    def set(self, key, value):
        if isinstance(self._data, weakref.WeakValueDictionary):
            self._data[key] = value
            self._order[key] = None
            self._order.move_to_end(key)
            # No eviction needed for weak values — GC handles it, but we still trim _order
            while len(self._order) > self.maxsize:
                oldest, _ = self._order.popitem(last=False)
                self._data.pop(oldest, None)
        else:
            self._data[key] = value
            self._data.move_to_end(key)
            while len(self._data) > self.maxsize:
                self._data.popitem(last=False)

    def __repr__(self):
        return f"LRUCache(size={len(self._data)}, maxsize={self.maxsize})"

# Demo
class BigBlob:
    def __init__(self, key, size=10000):
        self.key = key
        self.data = bytearray(size)
    def __repr__(self):
        return f"BigBlob({self.key!r})"

# Strong cache — bounded, LRU
cache = LRUCache(maxsize=2)
cache.set("a", BigBlob("a"))
cache.set("b", BigBlob("b"))
print(cache)  # LRUCache(size=2, maxsize=2)
cache.set("c", BigBlob("c"))  # evicts "a" (oldest)
print(cache.get("a"))  # None — evicted
print(cache.get("b"))  # BigBlob('b')
print(cache)  # LRUCache(size=2, maxsize=2)

# Weak-value cache — entries disappear when no strong ref remains
weak_cache = LRUCache(maxsize=10, weak_values=True)
blob = BigBlob("weak_1")
weak_cache.set("weak_1", blob)
print(weak_cache.get("weak_1"))  # BigBlob('weak_1')
del blob
gc.collect()
print(weak_cache.get("weak_1"))  # None — GC'd via weak value

# Instrument with tracemalloc — verify the strong cache doesn't leak beyond maxsize
tracemalloc.start()
snap_before = tracemalloc.take_snapshot()

for i in range(100):
    cache.set(f"key_{i}", BigBlob(f"key_{i}"))

snap_after = tracemalloc.take_snapshot()
# Even after 100 sets, cache holds at most maxsize entries — bounded memory
print(f"cache after 100 inserts: {cache}")
for stat in snap_after.compare_to(snap_before, "lineno")[:3]:
    print(stat)
tracemalloc.stop()

# Functools version — for pure function memoization use lru_cache instead of a hand-rolled cache
@functools.lru_cache(maxsize=2)
def load_blob(key: str) -> BigBlob:
    print(f"loading {key}")
    return BigBlob(key)

print(load_blob("x"))  # loading x
print(load_blob("x"))  # cached — no print
print(load_blob.cache_info())
```

*Explanation:* This cache demonstrates all the chapter's ideas: strong vs weak references, GC interaction (weak values vanish when unreferenced), bounded memory (LRU eviction), and `tracemalloc` instrumentation to verify no leak. For *function* memoization, `functools.lru_cache` is simpler; for *object* caching with GC integration, `WeakValueDictionary` is the tool.

## Summary

- Every Python value is a `PyObject` on the heap with `ob_refcnt` + `ob_type`; assignment copies pointers, not values; immortals (3.12+) bypass refcounting.
- Reference counting reclaims objects the instant `ob_refcnt` → 0; it is deterministic in CPython, non-deterministic elsewhere. `sys.getrefcount` includes a temporary `+1`.
- `id()` is a live address (CPython) that is recycled after GC — never store ids without keeping the object alive.
- Small ints (`-5..256`), the empty tuple, and interned strings are reused singletons; interning via `sys.intern` saves memory and speeds dict lookups, but never use `is` for value comparison.
- The cyclic GC handles container cycles via reachability analysis; three generations (0/1/2) optimize for short-lived objects; `gc.get_count`/`get_threshold`/`collect`/`get_referrers`/`get_referents` let you inspect and tune (sparingly).
- `weakref` (`ref`, `WeakKeyDictionary`, `WeakValueDictionary`, `WeakSet`, `WeakMethod`, `finalize`) lets you observe or cache without preventing collection — essential for caches, observers, and parent-pointer cycles.
- `__del__` is fragile: exceptions are swallowed, resurrection is possible, cycle order is arbitrary, and shutdown globals may be `None`. Prefer `with` / `try/finally` for deterministic cleanup and `weakref.finalize` as a non-leaky safety net.
- `__slots__` replaces per-instance `__dict__` with a compact array, saving large memory at the cost of no dynamic attributes — include `"__dict__"` / `"__weakref__"` explicitly if you need them.
- Instrumentation: `sys.getsizeof` (shallow) vs `pympler.asizeof` (deep), `tracemalloc` for allocation-per-line tracking, `gc` debug flags and `objgraph` for cycle visualization.
