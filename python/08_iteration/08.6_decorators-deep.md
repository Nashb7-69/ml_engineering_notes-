# 8.6 Decorators Deep Dive

Decorators are *higher-order functions* (or callable objects) that transform a function or class at definition time. The `@decorator` syntax is syntactic sugar for rebinding the name. This chapter covers parametrized decorators, stacking order, `functools.wraps`, signature preservation, method vs function decoration, decorators with optional arguments, and class decorators — with attention to subtle binding and introspection pitfalls.

---

## 1. Decorator Basics — Desugaring

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print(f"before {func.__name__}")
        result = func(*args, **kwargs)
        print(f"after {func.__name__}")
        return result
    return wrapper

# What you write:
@my_decorator
def greet(name: str):
    return f"hello {name}"

# What Python executes (at import/definition time, not call time):
# greet = my_decorator(greet)
# i.e., the original function object is passed to the decorator,
# and the name 'greet' is rebound to whatever the decorator returns.

print(greet("alice"))
# before greet
# after greet
# hello alice

# Decorators execute at DEFINITION time:
def noisy_decorator(func):
    print(f"decorating {func.__name__}")
    return func

@noisy_decorator
def foo(): pass  # prints "decorating foo" immediately on import
```
Explanation: Decoration happens *once*, when the `def` statement executes. The decorator's return value replaces the original function object in the current scope. This is why decorators can register functions, validate signatures, or wrap behavior — all at import time.

## 2. Parametrized Decorators (Decorator Factories)

A decorator that takes arguments is really a *factory* that returns a decorator. It requires one extra level of nesting.

### 2.1 The three-layer pattern

```python
# Goal: @retry(attempts=3, delay=0.1)

from functools import wraps
import time

def retry(attempts: int = 3, delay: float = 0.0, exceptions=(Exception,)):
    """Decorator factory: returns a decorator that retries the function."""
    if attempts < 1:
        raise ValueError("attempts must be >= 1")

    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, attempts + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    last_exc = e
                    print(f"attempt {attempt}/{attempts} failed: {e}")
                    if attempt < attempts and delay:
                        time.sleep(delay)
            raise last_exc  # all attempts exhausted
        return wrapper
    return decorator

@retry(attempts=3, delay=0.01)
def flaky(x: int):
    import random
    if random.random() < 0.7:
        raise ValueError("random failure")
    return x * 2

# What desugars to:
# flaky = retry(attempts=3, delay=0.01)(flaky)
# Step 1: retry(3, 0.01) -> decorator function
# Step 2: decorator(flaky) -> wrapper function
# Step 3: wrapper bound to name 'flaky'

# Another factory: logging with prefix
def log_call(prefix: str = ""):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            print(f"{prefix}{func.__name__} called with {args} {kwargs}")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@log_call(prefix="[DEBUG] ")
def add(a, b): return a + b

add(1, 2)  # [DEBUG] add called with (1, 2) {}
```
Explanation: A parametrized decorator is *called* at decoration time with its arguments; it must return a normal (single-argument) decorator. The call chain is `factory(args)(func) -> wrapper`.

### 2.2 Factory with validation and closure

```python
def validate_range(min_val=None, max_val=None):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            # Validate first positional arg for demo; real code would use inspect
            if args:
                v = args[0]
                if min_val is not None and v < min_val:
                    raise ValueError(f"{v} < min {min_val}")
                if max_val is not None and v > max_val:
                    raise ValueError(f"{v} > max {max_val}")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@validate_range(min_val=0, max_val=100)
def set_percentage(p): return f"{p}%"

print(set_percentage(50))  # 50%
# set_percentage(150)  # ValueError

# Factory captures args in closure — each decorated function gets its own closure
@validate_range(min_val=0)
def non_negative(x): return x

print(non_negative(5))  # 5
# Each wrapper's closure holds its own min_val/max_val — no cross-talk
```

## 3. Stacking Order

Multiple decorators compose bottom-up (like function composition).

```python
def dec_a(func):
    print("dec_a applied")
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("A before")
        result = func(*args, **kwargs)
        print("A after")
        return result
    return wrapper

def dec_b(func):
    print("dec_b applied")
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("B before")
        result = func(*args, **kwargs)
        print("B after")
        return result
    return wrapper

@dec_a
@dec_b
def func():
    print("  func body")

# Desugars to: func = dec_a(dec_b(func))
# Application order: dec_b first (closest to def), then dec_a wraps the result.
# So prints at decoration: dec_b applied, dec_a applied (bottom-up)

print("--- calling func() ---")
func()
# A before
# B before
#   func body
# B after
# A after
# Call order: A's wrapper outermost, B inner — like A(B(func))

# With parametrized decorators, same rule — factory calls are evaluated top-down
# at decoration time, but wrapping is bottom-up:
# @dec_a(args1)
# @dec_b(args2)
# def f(): ...  ->  f = dec_a(args1)(dec_b(args2)(f))
```
Explanation: The decorator *closest* to the `def` executes *first* (wraps the raw function). Each subsequent decorator wraps the previous result. At call time, the *outermost* (topmost) wrapper runs *first*. Think of it as `f = A(B(C(f)))` — definition builds inside-out, execution flows outside-in.

Realistic stacking example:

```python
from functools import lru_cache

def log(func):
    @wraps(func)
    def wrapper(*a, **kw):
        print(f"call {func.__name__}")
        return func(*a, **kw)
    return wrapper

@log
@lru_cache(maxsize=128)
def fib(n: int) -> int:
    if n < 2: return n
    return fib(n-1) + fib(n-2)

# fib = log(lru_cache(fib_raw))
# Each call goes through log -> lru_cache -> raw fib
# If reversed (@lru_cache @log), caching wraps logging — cached calls wouldn't log,
# which is often more efficient (log only on cache miss).

@lru_cache(maxsize=128)
@log
def fib2(n: int) -> int:
    if n < 2: return n
    return fib2(n-1) + fib2(n-2)

# fib2 = lru_cache(log(fib2_raw)) — log is inside cache, so only cache misses log
# Choose order based on whether you want to log/cache which layer.
```
Explanation: Order matters for semantics (what gets cached/logged/validated) and performance. Cache outermost if you want to skip inner work on hits; innermost if you want inner decorators to participate in caching logic.

## 4. `functools.wraps` — Preserving Identity

Without `wraps`, the wrapper erases the original function's metadata — breaking introspection, docs, debuggers, and tools that rely on `__name__`, `__doc__`, `__module__`, `__annotations__`, and `__wrapped__`.

```python
def bad_decorator(func):
    def wrapper(*args, **kwargs):
        """wrapper docstring"""
        return func(*args, **kwargs)
    return wrapper

@bad_decorator
def greet(name: str):
    """Greet someone."""
    return f"hello {name}"

print(greet.__name__)        # wrapper — wrong!
print(greet.__doc__)         # wrapper docstring — wrong!
print(greet.__annotations__) # {} — lost!
help(greet)                  # shows wrapper, not greet — confusing

# Fixed with wraps:
from functools import wraps

def good_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@good_decorator
def greet2(name: str):
    """Greet someone."""
    return f"hello {name}"

print(greet2.__name__)              # greet2 — preserved
print(greet2.__doc__)               # Greet someone. — preserved
print(greet2.__wrapped__ is greet2)  # False — __wrapped__ points to original
print(hasattr(greet2, "__wrapped__"))  # True — wraps sets this to original func
# Tools like inspect.unwrap can peel all layers:
import inspect
print(inspect.unwrap(greet2))  # original greet2 function

# wraps copies: __module__, __name__, __qualname__, __doc__, __annotations__,
# __dict__ (updated), __wrapped__
```
Explanation: Always use `@wraps(func)` on the inner wrapper. For parametrized decorators, apply it inside the inner `decorator(func)` layer (as shown in §2). For class-based decorators, assign manually or use `wraps` on `__call__`'s wrapper.

### 4.1 What `wraps` does not fix — signature

```python
from functools import wraps
import inspect

def deco(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@deco
def add(a, b, c=0): return a + b + c

print(inspect.signature(add))  # (*args, **kwargs) — not (a, b, c=0)!
# wraps preserves __wrapped__ but NOT the signature for inspect.signature
# until Python 3.4+, inspect.signature follows __wrapped__ automatically — so it DOES fix
# in modern Python. But explicit preservation is still better for older tools.
print(inspect.signature(add))  # in 3.5+ correctly shows (a, b, c=0) via __wrapped__
# However, tools that don't follow __wrapped__ still see *args, **kwargs.
# To fully preserve signature, use functools.wraps + inspect or decorator libraries.

# For 100% faithful signature, see §6.
```

## 5. `functools.lru_cache` — A Production Decorator Dissected

`lru_cache` is the canonical example of a parametrized, stateful decorator.

```python
from functools import lru_cache
import time

@lru_cache(maxsize=3)
def expensive(n: int):
    print(f"computing {n}")
    time.sleep(0.01)
    return n * n

print(expensive(2))  # computing 2 -> 4
print(expensive(2))  # cached — no print
print(expensive(3))  # computing 3
print(expensive(4))  # computing 4 — cache now [2,3,4]
print(expensive(5))  # computing 5 — evicts 2 (LRU)
print(expensive(2))  # computing 2 again — was evicted

# Introspection:
print(expensive.cache_info())
# CacheInfo(hits=1, misses=5, maxsize=3, currsize=3)
print(expensive.cache_parameters())
# {'maxsize': 3, 'typed': False}

expensive.cache_clear()  # reset

# maxsize=None -> unbounded cache (be careful — memory leak if unbounded keys)
@lru_cache(maxsize=None)
def fib_cached(n):
    if n < 2: return n
    return fib_cached(n-1) + fib_cached(n-2)

# typed=True — cache distinguishes 3 vs 3.0
@lru_cache(maxsize=None, typed=True)
def typed_func(x): return x

print(typed_func(3), typed_func(3.0))  # two separate cache entries if typed=True

# lru_cache requires hashable arguments — uses dict keyed by args
# @lru_cache
# def with_list(lst): ...  # TypeError on call with list arg (unhashable)

# For unhashable, use custom key or cachetools, or convert to tuple:
@lru_cache(maxsize=128)
def with_tuple(tup): return sum(tup)

print(with_tuple((1, 2, 3)))  # 6
# with_tuple([1,2,3])  # TypeError — must pass tuple

# lru_cache is thread-safe for simple cases (uses RLock internally)

# Since Python 3.8, @lru_cache without parens is NOT valid — must call:
# @lru_cache        # invalid — missing ()
# @lru_cache()      # valid — maxsize=128 default
# @lru_cache(maxsize=32)  # valid

# But Python 3.8+ functools.cache is unbounded shorthand for lru_cache(None):
try:
    from functools import cache  # 3.9+
    @cache
    def fib2(n):  # unbounded, hashable args
        if n < 2: return n
        return fib2(n-1) + fib2(n-2)
except ImportError:
    pass
```
Explanation: `lru_cache` wraps the function in a dict + doubly-linked list for LRU ordering. It replaces the function with a wrapper that hashes arguments (via `_make_key`), looks up the cache, and on miss calls the original. `cache_info` and `cache_clear` are attached to the wrapper for observability.

## 6. Decorators for Methods vs Functions — Binding Gotchas

Functions are descriptors: accessing them through an instance binds `self` automatically. Decorators must not break this protocol.

### 6.1 Simple wrapper works for methods — but signature matters

```python
from functools import wraps

def log_method(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"calling {func.__qualname__} with {args[1:]}")
        return func(*args, **kwargs)
    return wrapper

class Service:
    @log_method
    def process(self, value: int):
        return value * 2

s = Service()
print(s.process(5))  # calling Service.process with (5,) -> 10
# Works because wrapper is a plain function — descriptor protocol binds 's' as first arg.
# wrapper.__get__(None, Service) is not needed — functions handle binding natively,
# and wrapper IS a function.

# What if decorator returns a non-function object without descriptor protocol?
class BadDecorator:
    def __init__(self, func):
        self.func = func
        wraps(func)(self)  # copy metadata
    def __call__(self, *args, **kwargs):
        print("BadDecorator call")
        return self.func(*args, **kwargs)
    # Missing __get__ — breaks method binding!

class ServiceBad:
    @BadDecorator
    def process(self, value): return value * 2

sb = ServiceBad()
try:
    print(sb.process(5))  # TypeError: missing 1 required positional argument: 'value'
    # Because BadDecorator instance is not a descriptor — 'self' not bound!
except TypeError as e:
    print(f"failed: {e}")

# Fix: implement descriptor protocol
class GoodDecorator:
    def __init__(self, func):
        self.func = func
        wraps(func)(self)
    def __call__(self, *args, **kwargs):
        print("GoodDecorator call")
        return self.func(*args, **kwargs)
    def __get__(self, instance, owner):
        # Bind instance if accessed through instance; return self for class access
        if instance is None:
            return self
        # Return a bound method that inserts instance as first arg
        from types import MethodType
        return MethodType(self, instance)
    # Actually simpler: use functools.wraps + function wrapper, or just use function

# Better: just use a function wrapper — no descriptor needed
def good_log(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"good call {func.__qualname__}")
        return func(*args, **kwargs)
    return wrapper

class ServiceGood:
    @good_log
    def process(self, value): return value * 2

print(ServiceGood().process(5))  # works — wrapper is a function, binding automatic
```
Explanation: Plain function wrappers Just Work for methods because functions implement `__get__` to bind `self`. Class-based decorators that return *objects* must implement `__get__` themselves, or they'll fail to bind. Prefer function-based wrappers for methods unless you need stateful descriptors.

### 6.2 Decorating `@classmethod` / `@staticmethod` — order matters

```python
from functools import wraps

def my_wrap(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("wrapped")
        return func(*args, **kwargs)
    return wrapper

class Demo:
    @classmethod
    @my_wrap
    def cm_correct(cls, x): return f"cm {cls.__name__} {x}"

    @my_wrap
    @classmethod
    def cm_wrong(cls, x): return f"cm {cls.__name__} {x}"

print(Demo.cm_correct(1))  # wrapped, cm Demo 1 — correct: wrap the raw function first, then classmethod
try:
    print(Demo.cm_wrong(1))  # TypeError or wrong binding — my_wrap receives a classmethod object, not a function
except Exception as e:
    print(f"cm_wrong failed: {e} — my_wrap doesn't handle classmethod descriptor")

# Rule: @classmethod and @staticmethod must be the OUTERMOST decorator
# (topmost in stacking, applied last) — they return descriptor objects, not functions.
# So:
# @classmethod  <- outermost, applied last, sees a plain function
# @my_wrap      <- inner, applied first, wraps raw function
# def method(...)

# Same for @staticmethod, @property — always outermost.

# property + decorator interaction:
class PropDemo:
    @property
    @my_wrap  # WRONG — my_wrap gets a property object
    def value(self): return 42

    # Correct:
    # @property
    # def value(self): ...  with my_wrap needing special handling for properties
    # Or use a property-aware decorator.
```
Explanation: `@classmethod`/`@staticmethod`/`@property` return *descriptor objects*, not functions. If your decorator tries to wrap that descriptor as if it were a function, it fails. Always put them outermost (top) so your decorator wraps the raw function before it becomes a descriptor.

### 6.3 Preserving descriptors when decorating classes

When decorating methods inside a class decorator, iterate over `vars(cls)` and handle descriptors explicitly — or use helper libraries.

## 7. Preserving Signature with `inspect` — `functools.wraps` Is Not Enough

For perfect introspection (e.g., IDE autocompletion, `inspect.signature`, `help`), the wrapper should mimic the original signature, not just `(*args, **kwargs)`.

### 7.1 Why `(*args, **kwargs)` loses information

```python
import inspect
from functools import wraps

def deco(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@deco
def add(a, b, c=0): return a + b + c

# In modern Python, inspect.signature follows __wrapped__, so it shows (a,b,*,c=0)
# even though wrapper's code object is (*args, **kwargs). But not all tools do.
# To be explicit, we can set __signature__:
print(inspect.signature(add))  # (a, b, *, c=0) in 3.5+ via __wrapped__

# But calling help(add) may still show wrapper details in some environments.
# For bulletproof preservation, use one of:

# Option 1: manually assign __signature__
add_sig = inspect.signature(add.__wrapped__ if hasattr(add, "__wrapped__") else add)
# wrapper.__signature__ = add_sig  # if we had reference to wrapper

# Option 2: use functools.wraps which now handles this via __wrapped__ chain
# — no extra work needed in 3.5+ for signature, but __code__ still differs.

# Option 3: for perfect fidelity (including positional-only, etc.), use a code-gen decorator
# library like 'decorator' (Michele Simionato) or 'wrapt' or 'functools.wraps' + eval:

# Example: preserve signature by generating wrapper with matching signature
def preserve_signature(func):
    sig = inspect.signature(func)
    # Build wrapper source with same signature — advanced, often overkill
    # For most code, @wraps + __wrapped__ is sufficient.
    @wraps(func)
    def wrapper(*args, **kwargs):
        # bind to validate args match original signature
        bound = sig.bind(*args, **kwargs)
        bound.apply_defaults()
        return func(*bound.args, **bound.kwargs)
    wrapper.__signature__ = sig
    return wrapper

@preserve_signature
def greet(name: str, greeting: str = "hello") -> str:
    return f"{greeting} {name}"

print(inspect.signature(greet))  # (name: str, greeting: str = 'hello') -> str
print(greet("alice"))            # hello alice

# Option 4: use decorator library (recommended for complex cases)
# pip install decorator
# from decorator import decorator as dec
# @dec
# def my_decorator(func, *args, **kwargs): ...
# This preserves signature automatically via code generation.
```
Explanation: For most projects, `@wraps` is enough because `inspect.signature` follows `__wrapped__` since Python 3.5. If you need `wrapper.__code__` or `help` to show the original signature even to tools that don't follow `__wrapped__`, assign `__signature__` or use a dedicated library.

### 7.2 `functools.update_wrapper` vs `wraps`

`wraps` is a convenience around `update_wrapper`:

```python
from functools import update_wrapper, WRAPPER_ASSIGNMENTS, WRAPPER_UPDATES

def my_wraps(wrapped, wrapper):
    # Equivalent to @wraps(wrapped) but explicit:
    return update_wrapper(wrapper, wrapped,
                          assigned=WRAPPER_ASSIGNMENTS,  # __module__, __name__, etc.
                          updated=WRAPPER_UPDATES)       # __dict__

# WRAPPER_ASSIGNMENTS = ('__module__','__name__','__qualname__','__doc__','__annotations__')
# WRAPPER_UPDATES = ('__dict__',)
```

## 8. Class Decorators

A class decorator receives the class object and returns a (possibly modified) class. They are simpler than function decorators because there's no call-time wrapping — just class mutation or wrapping.

```python
def add_repr(cls):
    """Add __repr__ if not present."""
    if "__repr__" not in cls.__dict__:
        def __repr__(self):
            attrs = ", ".join(f"{k}={v!r}" for k, v in self.__dict__.items())
            return f"{cls.__name__}({attrs})"
        cls.__repr__ = __repr__
    return cls

@add_repr
class Point:
    def __init__(self, x, y): self.x, self.y = x, y

print(Point(1, 2))  # Point(x=1, y=2)

# Class decorator with arguments (factory pattern again):
def add_eq(use_dict=True):
    def decorator(cls):
        def __eq__(self, other):
            if not isinstance(other, cls): return NotImplemented
            d1 = self.__dict__ if use_dict else vars(self)
            d2 = other.__dict__ if use_dict else vars(other)
            return d1 == d2
        cls.__eq__ = __eq__
        return cls
    return decorator

@add_eq(use_dict=True)
class Person:
    def __init__(self, name): self.name = name

print(Person("a") == Person("a"))  # True

# Wrapping instantiation — e.g., singleton
def singleton(cls):
    instances = {}
    @wraps(cls)
    def wrapper(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return wrapper

@singleton
class Config:
    def __init__(self): self.value = 42

print(Config() is Config())  # True — same instance
# Pitfall: wrapper is a function, not a class — isinstance checks, subclassing break
# For real singletons, prefer overriding __new__ or using a metaclass.

# Realistic: dataclass-like decorator (simplified)
def auto_init(cls):
    """Generate __init__ from annotations."""
    import inspect
    sig_params = [
        inspect.Parameter(name, inspect.Parameter.POSITIONAL_OR_KEYWORD, annotation=ann)
        for name, ann in cls.__annotations__.items()
    ]
    def __init__(self, *args, **kwargs):
        bound = inspect.Signature(sig_params).bind(*args, **kwargs)
        bound.apply_defaults()
        for name, val in bound.arguments.items():
            setattr(self, name, val)
    cls.__init__ = __init__
    return cls

@auto_init
class User:
    name: str
    age: int

u = User("alice", 30)
print(u.name, u.age)  # alice 30

# Standard library class decorators: @dataclass, @total_ordering, @enum.unique, etc.
from dataclasses import dataclass
from functools import total_ordering

@total_ordering
@dataclass
class Version:
    major: int
    minor: int
    def __lt__(self, other): return (self.major, self.minor) < (other.major, other.minor)
    def __eq__(self, other): return (self.major, self.minor) == (other.major, other.minor)
# @total_ordering generates __le__, __gt__, __ge__ from __lt__ + __eq__
print(Version(1,0) < Version(2,0))  # True
```
Explanation: Class decorators execute at class definition time, immediately after the class body. They can mutate the class dict, wrap `__init__`/`__new__`, or replace the class entirely. The parametrized factory pattern (extra nesting) applies identically to class decorators.

## 9. Decorator with Optional Arguments — The Hardest Pattern

Goal: allow both `@deco` and `@deco(args...)` / `@deco()` with the same decorator. This requires detecting whether the first argument is the function or a decorator argument.

### 9.1 The pattern

```python
from functools import wraps, partial
import inspect

def flexible_decorator(_func=None, *, prefix=""):
    """Usable as @flexible_decorator, @flexible_decorator(), or @flexible_decorator(prefix='X')."""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            if prefix:
                print(f"{prefix} calling {func.__name__}")
            return func(*args, **kwargs)
        return wrapper

    if _func is not None and callable(_func) and not isinstance(_func, str):
        # Called as @flexible_decorator  (no parens) — _func is the function
        return decorator(_func)
    # Called as @flexible_decorator(...) or @flexible_decorator() — return decorator
    return decorator

# All three work:
@flexible_decorator
def f1(): return 1

@flexible_decorator()
def f2(): return 2

@flexible_decorator(prefix="[LOG] ")
def f3(): return 3

print(f1(), f2(), f3())  # 1 2 + log, 3
# f3 prints: [LOG] calling f3

# Robust detection: check if _func is a function vs decorator arg
# Pitfall: if decorator's first arg could legitimately be a callable, detection fails.
# Alternative: require keyword-only args after * to disambiguate, or document that
# bare @deco form passes the function as first positional arg.

# Alternative implementation using sentinel:
_SENTINEL = object()

def optional_args_decorator(func=_SENTINEL, *, retries=3):
    def decorator(f):
        @wraps(f)
        def wrapper(*a, **kw):
            for i in range(retries):
                try: return f(*a, **kw)
                except Exception as e:
                    if i == retries - 1: raise
        return wrapper
    if func is _SENTINEL:
        return decorator  # @deco() or @deco(retries=5)
    if callable(func):
        return decorator(func)  # @deco
    return decorator  # fallback

@optional_args_decorator
def g1(): return "g1"

@optional_args_decorator(retries=2)
def g2(): return "g2"

print(g1(), g2())
```
Explanation: The trick is a default-`None` first positional argument that captures the function when used without parentheses. If it's callable, you were called bare; wrap immediately. Otherwise, return a decorator waiting for the function. Making decorator arguments keyword-only (`*, ...`) avoids ambiguity with the function's identity.

### 9.2 Why this pattern is discouraged (sometimes)

- It complicates type hints and signature.
- It can confuse static analyzers.
- Consider supporting only `@deco` *or* `@deco(...)`, not both — simpler and more explicit (e.g., `@lru_cache` now requires `@lru_cache()` with parens in strict mode; `@dataclass` supports both but is well-documented).

## 10. Decorator Pitfalls and Best Practices

```python
# Pitfall 1: Forgetting to return from wrapper
def bad(func):
    @wraps(func)
    def wrapper(*a, **kw):
        func(*a, **kw)  # missing return — caller gets None
    return wrapper

@bad
def add(a, b): return a + b
print(add(1, 2))  # None — bug!

# Pitfall 2: Not forwarding *args/**kwargs correctly
def strict(func):
    @wraps(func)
    def wrapper(a, b):  # breaks functions with different signatures
        return func(a, b)
    return wrapper

# Pitfall 3: Mutable default in decorator factory
def bad_factory(items=[]):  # shared list across decorations!
    def decorator(func):
        items.append(func.__name__)
        @wraps(func)
        def wrapper(*a, **kw): return func(*a, **kw)
        return wrapper
    return decorator

# Fix: use None sentinel
def good_factory(items=None):
    if items is None: items = []
    ...

# Pitfall 4: Decorating recursive functions — wrapper recurses through wrapper
def count_calls(func):
    func.calls = 0
    @wraps(func)
    def wrapper(*a, **kw):
        wrapper.calls += 1
        return func(*a, **kw)
    wrapper.calls = 0
    return wrapper

@count_calls
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)  # recursive calls go through wrapper — counted!

print(fib(5), fib.calls)  # 5, 15 calls (including recursion)

# Pitfall 5: Decorators hide the original for pickle / copy
# Pickle needs to find the function by __qualname__ — if decorator replaces it
# with a wrapper function defined elsewhere, unpickling may fail.
# Fix: ensure __qualname__/__module__ correct via @wraps, and consider __reduce__.
```

Best-practice checklist:

1. Always `@wraps(func)` the wrapper.
2. Preserve signature via `__signature__` if introspection matters.
3. Put `@classmethod`/`@staticmethod`/`@property` outermost.
4. Use keyword-only arguments in factories to avoid ambiguity.
5. Document whether decorator is parametrized, and whether it supports bare `@deco`.
6. Test decorators with methods, classmethods, async functions, and signatures.

## 11. Quick-Reference

| Pattern | Skeleton | Usage |
|---------|----------|-------|
| Simple decorator | `def deco(func): @wraps(func) def w(*a,**kw): return func(*a,**kw); return w` | `@deco` |
| Factory | `def deco(arg): def d(func): @wraps(func) def w(...): ...; return w; return d` | `@deco(arg)` |
| Optional args | `def deco(_f=None,*,arg=...): ... if callable(_f): return d(_f); return d` | `@deco` or `@deco(arg)` |
| Class decorator | `def deco(cls): cls.x=...; return cls` | `@deco` on class |
| Method-safe | Function wrapper (not class) | Works with binding automatically |
| Cache | `@lru_cache(maxsize=...)` | Requires `()` even for defaults |
