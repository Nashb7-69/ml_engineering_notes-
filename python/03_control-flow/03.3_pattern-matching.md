# 3.3 Pattern Matching

> **What you will learn:** How Python 3.10+'s `match`/`case` provides structural pattern matching — a fundamentally different kind of branching from `if`/`elif`. You will learn literal, wildcard, OR, sequence, mapping, and class patterns, `as` bindings, guard clauses, nested patterns, exhaustiveness behavior, dataclass matching, common pitfalls, and when to choose `match` vs. `if`.

---

## 1. What Pattern Matching Is — And Is Not

Pattern matching, introduced in **Python 3.10** via [PEP 634](https://peps.python.org/pep-0634/), [PEP 635](https://peps.python.org/pep-0635/), and [PEP 636](https://peps.python.org/pep-0636/), looks superficially like a `switch` statement from C, Java, or JavaScript. It is far more powerful and fundamentally different.

A `switch` in most languages compares a single value against a set of constants using equality. Python's `match` **destructures** data — it inspects the *shape*, *type*, *length*, and *contents* of objects, binds variables from within them, and can match nested structures in a single concise statement.

```python
# A C-style switch — flat constant comparison
# switch (status) {
#     case 200: handle_ok(); break;
#     case 404: handle_not_found(); break;
#     default: handle_unknown();
# }

# Python match — can do the same trivially, but also far more:
http_status = 404

match http_status:
    case 200:
        print("OK")
    case 404:
        print("Not Found")
    case 500:
        print("Server Error")
    case _:                          # wildcard — like `default`
        print(f"Unknown: {http_status}")
```

**Explanation:** Each `case` is a *pattern*, not just a value. `case 200:` is a **literal pattern** — it matches when `http_status == 200`. `case _:` is a **wildcard pattern** — it matches anything and binds nothing, serving as the catch-all. The `match` block tests cases top-to-bottom and executes only the **first** matching case.

### `match` vs. `if`/`elif` — The Core Distinction

| Aspect | `if`/`elif` | `match`/`case` |
|---|---|---|
| Tests | Arbitrary boolean expressions | **Structural patterns** against a single subject |
| Subject evaluation | Each `if` re-evaluates or tests a different expression | Subject expression evaluated **once**, matched against each pattern |
| Destructuring | Manual — `if isinstance(x, list) and len(x) == 2: a, b = x` | Automatic — `case [a, b]:` binds `a` and `b` |
| Variable binding | Assignment is separate from branching | Pattern **binds variables** as part of matching |
| Exhaustiveness | No concept — `else` is optional | No enforcement — `case _:` is conventional but not required |
| Fall-through | No (each `if`/`elif` is exclusive) | No (first match wins, no fall-through, no `break` needed) |

```python
# if/elif — condition-driven branching
def describe_if(value):
    if value == 0:
        return "zero"
    elif value > 0:
        return "positive"
    else:
        return "negative"
# Each branch tests a different boolean expression.

# match/case — structure-driven branching
def describe_match(value):
    match value:
        case 0:
            return "zero"
        case int(n) if n > 0:       # class pattern + guard
            return f"positive int {n}"
        case int(n):                 # remaining ints are negative or zero (but 0 already matched)
            return f"negative int {n}"
        case _:
            return "not an int"
# Each branch matches the SHAPE/TYPE of `value`.
```

**Explanation:** Use `if`/`elif` when branching on boolean conditions or unrelated expressions. Use `match` when dispatching on the structure, type, or contents of a single value — especially when you want to destructure it at the same time.

## 2. Syntax — `match` and `case`

### Basic Structure

```python
match <subject_expression>:
    case <pattern> [if <guard>]:
        <suite>
    case <pattern> [if <guard>]:
        <suite>
    case _:                          # wildcard — optional
        <suite>
```

- `match` and `case` are **soft keywords** — they are only keywords inside a `match` block. Outside, you can still use `match` and `case` as variable names (though it is confusing and discouraged).
- The subject expression is evaluated **once** before any pattern is tested.
- Cases are tested top-to-bottom; the first match wins.
- No `break` is needed — there is no fall-through.
- Indentation follows the same colon-and-suite rule as `if`/`for`/`while`.

```python
# Soft keyword demonstration — legal but don't do this
match = "hello"       # `match` as a variable — allowed outside match blocks
case = 42             # same for `case`
print(match, case)    # hello 42

# Inside a match block, they become keywords:
value = 42
match value:
    case 42:
        print("matched 42")
    case case:                    # `case` here refers to variable `case` (=42) or is it a pattern?
        print("this is tricky")
# `case case:` — `case` is treated as a CAPTURE pattern (binds value to name `case`),
# NOT as the value 42. See Section 4 for why.

# Correct way to match against a variable's value — use dotted name or guard:
threshold = 42
match value:
    case x if x == threshold:
        print(f"matched threshold {threshold}")
```

**Explanation:** The soft-keyword design preserves backward compatibility — existing code that uses `match` or `case` as identifiers still works. But inside `match` blocks, bare names are capture patterns, not value comparisons. This is the single most confusing aspect for newcomers (see Section 4).

### Subject Expression — Evaluated Once

```python
def get_value():
    print("  get_value() called")
    return [1, 2, 3]

match get_value():        # called ONCE
    case [1, 2, 3]:
        print("  matched [1,2,3]")
    case [1, 2]:
        print("  matched [1,2]")
    case _:
        print("  no match")
# Output:
#   get_value() called
#   matched [1,2,3]

# Compare to if/elif — subject re-evaluated if you call the function each time:
if get_value() == [1, 2, 3]:      # first call
    print("  matched [1,2,3]")
elif get_value() == [1, 2]:       # second call — redundant work
    print("  matched [1,2]")
# Output:
#   get_value() called
#   matched [1,2,3]
# (second branch not tested, but if first failed, get_value would be called again)
```

## 3. Literal Patterns

The simplest patterns — match exact values using equality (`==` semantics, but with some nuances for `is` with singletons).

```python
# Literal patterns — int, str, float, bool, None
def handle_status(code):
    match code:
        case 200:
            return "OK"
        case 404:
            return "Not Found"
        case 500:
            return "Server Error"
        case _:
            return f"Unknown status {code}"

print(handle_status(200))   # OK
print(handle_status(404))   # Not Found
print(handle_status(999))   # Unknown status 999

# String literals
def handle_command(cmd):
    match cmd:
        case "quit":
            return "Exiting"
        case "help":
            return "Showing help"
        case "save":
            return "Saving"
        case _:
            return f"Unknown command: {cmd}"

# None and booleans — note: True/False are literal patterns, not capture
def handle_value(x):
    match x:
        case None:
            return "nothing"
        case True:            # matches ONLY True (bool), not truthy values
            return "true"
        case False:
            return "false"
        case 0:               # note: 0 == False is True, but match distinguishes them!
            return "zero int"
        case _:
            return f"other: {x!r}"

print(handle_value(None))   # nothing
print(handle_value(True))   # true
print(handle_value(False))  # false
print(handle_value(0))      # zero int — NOT "false"
print(handle_value(1))      # other: 1
print(handle_value(""))     # other: ''
```

**Explanation:** `match` distinguishes `True`/`False`/`0`/`1` more precisely than `==` might suggest. In Python, `True == 1` is `True`, but `match` uses an identity-aware comparison for booleans and `None` — `case True:` matches only `True`, not `1`. This is specified by PEP 634 and prevents the `bool`-is-`int` confusion.

```python
# Demonstrating that match distinguishes bool from int
value = 1
match value:
    case True:
        print("  matched True")   # NOT printed for value=1
    case 1:
        print("  matched 1")      # printed for value=1
    case _:
        print("  wildcard")

value = True
match value:
    case True:
        print("  matched True")   # printed for value=True
    case 1:
        print("  matched 1")      # NOT reached — True already matched
    case _:
        print("  wildcard")

# Numeric literal patterns — int, float
def classify_number(n):
    match n:
        case 0:
            return "zero"
        case 3.14:
            return "pi"
        case -1:
            return "negative one"
        case _:
            return "other"

# Combined with guards for range-like dispatch (since literal patterns are exact)
def number_range(n):
    match n:
        case 0:
            return "zero"
        case x if 0 < x < 10:
            return f"small positive: {x}"
        case x if x >= 10:
            return f"large: {x}"
        case x if x < 0:
            return f"negative: {x}"
```

## 4. Capture and Wildcard Patterns — The `_` Distinction

### Capture Pattern — `case x:`

A bare name in a `case` **always** matches and **binds** the subject to that name. It never tests for equality with an existing variable.

```python
# Capture — binds subject to new variable `x`
value = [1, 2, 3]

match value:
    case x:                     # ALWAYS matches — binds value to `x`
        print(f"  x = {x}")    # x = [1, 2, 3]
# No other case would ever be reached after `case x:`

# This is NOT a comparison with an existing variable!
color = "red"
value = "blue"

match value:
    case color:                 # does NOT compare value == "red"
        print(f"  color = {color}")  # color is now "blue" — rebound!
        # `case color:` captures `value` into a NEW variable called `color`,
        # shadowing the outer `color = "red"`

print(f"  outer color after match: {color}")  # blue — was rebound
# Actually, Python's scoping for match is the SAME scope — case bindings
# leak into the enclosing scope (unlike some languages).
# Let's verify:
print(f"  color is now: {color}")  # blue

# How to actually compare against an existing variable — use a guard or dotted name:
color = "red"
value = "blue"

match value:
    case x if x == color:
        print(f"  value equals color: {x}")
    case x:
        print(f"  value {x!r} does not equal color {color!r}")

# Or use an attribute / dotted name — dotted names ARE value patterns:
class Config:
    target = "red"

match value:
    case Config.target:           # dotted name — compares via == (value pattern)
        print("  matched Config.target")
    case _:
        print("  no match — value is blue, target is red")

# Enum example — the canonical use of dotted value patterns:
from enum import Enum

class Color(Enum):
    RED = 1
    GREEN = 2
    BLUE = 3

value = Color.GREEN
match value:
    case Color.RED:
        print("  red")
    case Color.GREEN:
        print("  green")        # matched
    case Color.BLUE:
        print("  blue")
```

**Explanation:** This is the most common pitfall. `case x:` always matches and binds — it never reads an existing `x`. To match against an existing variable's *value*, use either a guard (`case y if y == x:`) or a dotted/qualified name (`case SomeClass.x:` / `case Color.RED:`) which *is* treated as a value pattern.

### Wildcard Pattern — `case _:`

`case _:` also always matches but **does not bind**. It is the conventional catch-all. `_` is special — it is the only name that does not create a binding.

```python
value = "anything"

match value:
    case "hello":
        print("  hello")
    case _:                        # matches everything else, binds nothing
        print(f"  something else: {value}")

# `case _:` vs `case x:` — both always match, difference is binding
match [1, 2, 3]:
    case x:
        print(f"  x = {x}")      # x is [1, 2, 3] — available after

# print(x)  # x is [1, 2, 3] — leaked into enclosing scope!

match [1, 2, 3]:
    case _:
        print("  matched wildcard")
# print(_)  # _ was NOT bound — no leak (but `_` conventionally holds last REPL value)

# Multiple wildcards — all legal, all match (but only first is ever reached)
match value:
    case _:
        print("  first wildcard")
    case _:                        # unreachable — first _ already matched
        print("  second wildcard")
```

**Convention:** Always use `case _:` for the catch-all, not `case x:` — it signals "I intentionally handle everything remaining and don't need the value." Linters can warn about unreachable cases after a wildcard/capture.

## 5. OR Patterns — `case A | B | C:`

The `|` operator combines multiple patterns into one case. The subject matches if it matches **any** of the alternatives.

```python
# Basic OR — multiple literals in one case
def handle_status(code):
    match code:
        case 200 | 201 | 204:
            return "success"
        case 400 | 401 | 403 | 404:
            return "client error"
        case 500 | 502 | 503:
            return "server error"
        case _:
            return "unknown"

print(handle_status(201))  # success
print(handle_status(404))  # client error
print(handle_status(999))  # unknown

# OR with different pattern types
def classify(value):
    match value:
        case 0 | 0.0 | "0" | "" | None | False:
            return "falsy-ish literal"
        case [] | {} | set():
            return "empty collection"
        case _:
            return "something else"

print(classify(0))    # falsy-ish literal
print(classify(""))   # falsy-ish literal
print(classify([]))   # empty collection
print(classify([0]))  # something else

# OR with sequence patterns (Section 6)
def handle_point(point):
    match point:
        case (0, 0) | (0, 1) | (1, 0):
            return "near origin"
        case (x, 0) | (0, x):       # BUG — see below
            return f"on axis at {x}"
        case _:
            return "elsewhere"

# Pitfall: OR pattern variable binding must be CONSISTENT
# Each alternative must bind the SAME variables, or Python raises an error
# at compile time for inconsistent bindings:

# This is an ERROR — `x` bound in first alternative but not second:
# match point:
#     case (x, 0) | (0, 1):  # SyntaxError: alternative patterns bind different names
#         print(x)

# Correct — both alternatives bind `x`:
match (3, 0):
    case (x, 0) | (0, x):
        print(f"  on axis at {x}")  # x = 3

match (0, 7):
    case (x, 0) | (0, x):
        print(f"  on axis at {x}")  # x = 7

# OR with guards — guard applies to the WHOLE or-pattern
value = 42
match value:
    case 1 | 2 | 3 if value > 2:   # guard applies after OR — only 3 passes
        print(f"  1|2|3 with guard >2: {value}")
    case 1 | 2 | 3:                 # remaining: 1, 2
        print(f"  1|2|3 without guard: {value}")
    case _:
        print(f"  other: {value}")
# For value=1: "1|2|3 without guard: 1"
# For value=3: "1|2|3 with guard >2: 3"
# For value=42: "other: 42"

# Realistic: HTTP method dispatch
def handle_request(method, path):
    match (method, path):
        case ("GET", "/") | ("GET", "/home"):
            return "home page"
        case ("GET", _) | ("HEAD", _):
            return f"GET/HEAD {path}"
        case ("POST", _) | ("PUT", _) | ("PATCH", _):
            return f"write to {path}"
        case ("DELETE", _):
            return f"delete {path}"
        case _:
            return "method not allowed"
```

## 6. Sequence Patterns — Lists, Tuples, and Destructuring

Sequence patterns match ordered collections — lists and tuples (and any `collections.abc.Sequence` except `str`/`bytes`/`bytearray`, which are treated as atomic values, not sequences, in patterns).

```python
# Basic sequence patterns — exact length
def handle_point(point):
    match point:
        case (0, 0):
            return "origin"
        case (0, y):
            return f"on Y-axis at y={y}"
        case (x, 0):
            return f"on X-axis at x={x}"
        case (x, y):
            return f"point ({x}, {y})"
        case _:
            return "not a 2D point"

print(handle_point((0, 0)))   # origin
print(handle_point((0, 5)))   # on Y-axis at y=5
print(handle_point((3, 0)))   # on X-axis at x=3
print(handle_point((3, 4)))   # point (3, 4)
print(handle_point((1, 2, 3)))  # not a 2D point — length 3, no pattern matches 3 elements

# Wildcard inside sequence — ignore elements
def handle_rgb(color):
    match color:
        case (255, _, _):
            return "max red"
        case (_, 255, _):
            return "max green"
        case (r, g, b):
            return f"rgb({r},{g},{b})"
        case _:
            return "invalid"

print(handle_rgb((255, 0, 128)))  # max red
print(handle_rgb((100, 255, 0)))  # max green

# Star patterns — match variable-length sequences
def handle_scores(scores):
    match scores:
        case []:
            return "no scores"
        case [x]:
            return f"one score: {x}"
        case [first, *rest]:
            return f"first={first}, rest={rest}"
        case _:
            return "not a list"

print(handle_scores([]))              # no scores
print(handle_scores([42]))            # one score: 42
print(handle_scores([10, 20, 30]))    # first=10, rest=[20, 30]

# Star in the middle or end
def parse_command(cmd):
    match cmd.split():
        case ["quit"]:
            return "quit"
        case ["load", filename]:
            return f"load {filename}"
        case ["move", x, y]:
            return f"move to ({x}, {y})"
        case ["echo", *words]:
            return f"echo: {' '.join(words)}"
        case ["repeat", *words, "please"]:
            return f"politely repeating: {' '.join(words)}"
        case _:
            return "unknown command"

print(parse_command("quit"))                    # quit
print(parse_command("load data.csv"))           # load data.csv
print(parse_command("echo hello world foo"))    # echo: hello world foo
print(parse_command("repeat hello world please"))  # politely repeating: hello world

# Nested sequence patterns
def handle_nested(data):
    match data:
        case [[a, b], [c, d]]:
            return f"2x2 matrix: [{a},{b}],[{c},{d}]"
        case [[a, b, c]]:
            return f"single row: {a},{b},{c}"
        case [[*row], *rest]:
            return f"first row {row}, {len(rest)} more rows"
        case _:
            return "unknown shape"

print(handle_nested([[1, 2], [3, 4]]))   # 2x2 matrix
print(handle_nested([[1, 2, 3]]))         # single row
print(handle_nested([[1, 2], [3, 4], [5, 6]]))  # first row [1,2], 2 more rows
```

**Explanation:** Sequence patterns require the subject to be a sequence (list or tuple). A pattern `[a, b]` matches a 2-element sequence and binds `a` and `b`. A pattern `[a, *rest]` matches any sequence with at least one element. Only **one** starred element is allowed per sequence pattern.

### List vs. Tuple Pattern — Mostly Interchangeable, But...

```python
# Both [x, y] and (x, y) match EITHER lists or tuples in sequence patterns
# (unlike class patterns — see Section 8)

match [1, 2]:
    case (a, b):           # tuple pattern matches list subject
        print(f"  tuple pattern matched list: {a}, {b}")

match (1, 2):
    case [a, b]:           # list pattern matches tuple subject
        print(f"  list pattern matched tuple: {a}, {b}")

# But strings/bytes are NOT treated as sequences in patterns
match "ab":
    case [a, b]:           # does NOT match — "ab" is not a sequence pattern subject
        print(f"  matched string as sequence: {a}, {b}")
    case "ab":             # literal string pattern — matches
        print("  matched string literal 'ab'")
    case str(s):           # class pattern for str — matches
        print(f"  matched str: {s}")

# Bytes similarly
match b"ab":
    case [a, b]:
        print("  bytes as sequence — NOT matched")
    case b"ab":
        print("  bytes literal — matched")
```

### Sequence Pattern Edge Cases

```python
# Empty sequence
match []:
    case []:
        print("  empty list matched []")
    case _:
        print("  wildcard")

match ():
    case []:               # [] pattern matches () subject — both are empty sequences
        print("  empty tuple matched []")

# Single star — captures all remaining elements as a list
match [1, 2, 3, 4, 5]:
    case [first, *middle, last]:
        print(f"  first={first}, middle={middle}, last={last}")
        # first=1, middle=[2, 3, 4], last=5

match [1, 2]:
    case [first, *middle, last]:
        print(f"  first={first}, middle={middle}, last={last}")
        # first=1, middle=[], last=2 — middle can be empty

match [1]:
    case [first, *middle, last]:
        print(f"  matched: {first}, {middle}, {last}")
    case _:
        print("  [1] does not match [first, *middle, last] — needs >= 2 elements")

# Only one star allowed
# case [a, *b, *c]:  # SyntaxError: multiple starred names in sequence pattern

# Star with wildcard — ignore rest
match [1, 2, 3, 4]:
    case [first, *_]:
        print(f"  first={first}, rest ignored")
```

## 7. Mapping Patterns — Dictionaries

Mapping patterns match `dict` (and more generally, `collections.abc.Mapping`) objects by **key**. They are exceptionally useful for JSON-like data, API responses, and configuration dictionaries.

```python
# Basic mapping patterns — match by key, bind values
def handle_response(response):
    match response:
        case {"status": 200, "data": data}:
            return f"Success: {data}"
        case {"status": 404}:
            return "Not found"
        case {"status": status, "error": msg}:
            return f"Error {status}: {msg}"
        case {"error": msg}:               # no status key required
            return f"Error: {msg}"
        case _:
            return "Unknown response"

print(handle_response({"status": 200, "data": [1, 2, 3]}))  # Success: [1, 2, 3]
print(handle_response({"status": 404}))                      # Not found
print(handle_response({"status": 500, "error": "boom"}))     # Error 500: boom
print(handle_response({"error": "oops"}))                    # Error: oops

# Mapping patterns match SUBSETS — extra keys are allowed
match {"a": 1, "b": 2, "c": 3}:
    case {"a": 1}:                         # matches — extra keys b, c ignored
        print("  matched {'a': 1} even though dict has b, c")

# To capture extra keys — use **rest
def handle_config(config):
    match config:
        case {"host": host, "port": port, **rest}:
            print(f"  host={host}, port={port}, extra={rest}")
        case {"host": host, **rest}:
            print(f"  host={host}, extra={rest}")
        case _:
            print("  no host key")

handle_config({"host": "localhost", "port": 8080, "debug": True})
# host=localhost, port=8080, extra={'debug': True}

handle_config({"host": "localhost", "debug": True})
# host=localhost, extra={'debug': True, 'port': 8080} — wait, no port here
# Actually: host=localhost, extra={'debug': True}

# Key must be a LITERAL — not a variable
key = "status"
# case {key: value}:  # BUG — `key` here is literal string "key", not variable `key`!
# To match a dynamic key, use a guard:
response = {"status": 200, "data": "hello"}
match response:
    case dict() if key in response:        # use dict() + guard for dynamic keys
        print(f"  dynamic key '{key}' found: {response[key]}")
```

**Explanation:** Mapping patterns match if **all specified keys** are present with matching values. Extra keys in the subject are ignored (unlike sequence patterns, where length must match exactly). Keys in the pattern must be literal values (strings, numbers, etc.) — bare names are *not* treated as variables for key lookup.

### Mapping Pattern Details

```python
# Value part of mapping can be any pattern — including nested structures
def handle_event(event):
    match event:
        case {"type": "click", "pos": (x, y)}:
            return f"Click at ({x}, {y})"
        case {"type": "keypress", "key": key}:
            return f"Key pressed: {key}"
        case {"type": "quit"}:
            return "Quit event"
        case {"type": type_name, "data": {"id": id_val, **rest}}:
            return f"Generic {type_name} id={id_val} extra={rest}"
        case _:
            return "Unknown event"

print(handle_event({"type": "click", "pos": (100, 200)}))   # Click at (100, 200)
print(handle_event({"type": "keypress", "key": "Enter"}))    # Key pressed: Enter
print(handle_event({"type": "custom", "data": {"id": 42, "extra": "foo"}}))
# Generic custom id=42 extra={'extra': 'foo'}

# Shorthand: {"key": var} — binds the value at "key" to `var`
# If the key string equals the variable name, you can think of it as:
#   {"status": status}  means  status = subject["status"]  (if "status" in subject)

# Pattern with literal value check + binding
match {"status": 200, "data": [1, 2, 3]}:
    case {"status": 200, "data": data}:   # "status" must be 200, "data" bound to variable
        print(f"  success with data: {data}")
    case {"status": status}:               # any status value, bound to `status`
        print(f"  status: {status}")

# Double-star rest — only ONE ** allowed, must be last
# case {"a": a, **rest, **more}:  # SyntaxError — only one **rest
# case {"a": a, **rest, "b": b}:  # SyntaxError — **rest must be last

# Empty mapping pattern — matches any dict/mapping (including non-empty!)
match {"a": 1, "b": 2}:
    case {}:
        print("  empty mapping pattern matched non-empty dict!")
        # This DOES match — {} means "is a mapping" with no key requirements

# To match ONLY empty dicts, you need a guard:
match {"a": 1}:
    case {} if len({}) == 0:  # wrong — checks pattern's `{}`, not subject
        pass
# Correct:
data = {}
match data:
    case {} if len(data) == 0:
        print("  truly empty dict")
    case {}:
        print("  non-empty dict (is a mapping)")

# Better — just check directly:
data = {"a": 1}
match data:
    case dict() if not data:     # empty dict
        print("  empty")
    case dict():                  # any dict (non-empty, since empty case above)
        print("  non-empty dict")
    case _:
        print("  not a dict")
```

## 8. Class Patterns — Matching Objects and Dataclasses

Class patterns match objects by **type** (`isinstance` check) and optionally destructure them by attribute or positional argument.

```python
# Basic class pattern — type check
def handle_value(value):
    match value:
        case int(n):
            return f"int: {n}"
        case str(s):
            return f"str: {s!r}"
        case list(items):
            return f"list with {len(items)} items"
        case _:
            return "unknown"

print(handle_value(42))        # int: 42
print(handle_value("hello"))   # str: 'hello'
print(handle_value([1, 2]))    # list with 2 items
print(handle_value(3.14))      # unknown — float not matched

# For built-in types, class pattern with one arg captures the value
# `case int(n):` binds `n` to the int value itself
# `case str(s):` binds `s` to the string value
# This works because int/str define __match_args__ appropriately

# Important: class pattern checks isinstance, not ==
match True:
    case int(n):               # True IS an int (bool subclasses int)
        print(f"  True matched int pattern: {n}")  # printed!
    case bool(b):
        print(f"  True matched bool pattern: {b}")

# Order matters — put more specific types first:
def handle_bool_int(value):
    match value:
        case bool(b):          # check bool BEFORE int — bool is more specific
            return f"bool: {b}"
        case int(n):
            return f"int: {n}"
        case _:
            return "other"

print(handle_bool_int(True))   # bool: True
print(handle_bool_int(42))     # int: 42
```

### Dataclass Matching — The Killer Feature

Dataclasses work beautifully with class patterns because they auto-generate `__match_args__` from their fields.

```python
from dataclasses import dataclass


@dataclass
class Point:
    x: float
    y: float

@dataclass
class Circle:
    center: Point
    radius: float

@dataclass
class Rectangle:
    corner: Point
    width: float
    height: float

# Positional class patterns — use __match_args__ order (field definition order)
def describe_shape(shape):
    match shape:
        case Point(x, y):
            return f"Point({x}, {y})"
        case Circle(Point(cx, cy), r):       # nested class pattern
            return f"Circle at ({cx},{cy}) radius {r}"
        case Rectangle(Point(x, y), w, h):
            return f"Rectangle at ({x},{y}) size {w}x{h}"
        case _:
            return "Unknown shape"

print(describe_shape(Point(3, 4)))                          # Point(3, 4)
print(describe_shape(Circle(Point(0, 0), 5)))               # Circle at (0,0) radius 5
print(describe_shape(Rectangle(Point(1, 1), 10, 20)))       # Rectangle at (1,1) size 10x20

# Keyword class patterns — explicit attribute names, order-independent
def describe_shape_kw(shape):
    match shape:
        case Point(x=x, y=y):
            return f"Point({x}, {y})"
        case Circle(center=Point(x=cx, y=cy), radius=r):
            return f"Circle at ({cx},{cy}) radius {r}"
        case Rectangle(corner=Point(x=x, y=y), width=w, height=h):
            return f"Rectangle at ({x},{y}) size {w}x{h}"
        case _:
            return "Unknown shape"

# Mix positional and keyword — positional first, then keyword
def describe_mixed(shape):
    match shape:
        case Point(x, y=y):      # x positional, y keyword — allowed
            return f"Point({x}, {y})"
        case Circle(Point(0, 0), radius=r):  # nested literal + keyword
            return f"Circle at origin, radius {r}"
        case Circle(center, radius=r):       # center positional, radius keyword
            return f"Circle at {center}, radius {r}"
        case _:
            return "other"

# Matching specific values inside class patterns
def classify_point(p: Point) -> str:
    match p:
        case Point(0, 0):
            return "origin"
        case Point(0, y):
            return f"on Y-axis at {y}"
        case Point(x, 0):
            return f"on X-axis at {x}"
        case Point(x, y) if x == y:
            return f"diagonal at ({x},{y})"
        case Point(x, y):
            return f"point ({x},{y})"

print(classify_point(Point(0, 0)))   # origin
print(classify_point(Point(0, 5)))   # on Y-axis at 5
print(classify_point(Point(3, 3)))   # diagonal at (3,3)
print(classify_point(Point(2, 7)))   # point (2,7)
```

**Explanation:** `@dataclass` automatically sets `__match_args__` to the field names in definition order, enabling positional patterns like `Point(x, y)`. Without `@dataclass`, you would need to define `__match_args__` manually. Keyword patterns like `Point(x=x, y=y)` work for any class with those attributes, regardless of `__match_args__`.

### `__match_args__` — How Positional Matching Works

```python
# For a class to support positional patterns, it needs __match_args__
class PlainPoint:
    __match_args__ = ("x", "y")    # declares which attributes map to positional args

    def __init__(self, x, y):
        self.x = x
        self.y = y

# Now positional matching works:
match PlainPoint(3, 4):
    case PlainPoint(x, y):
        print(f"  PlainPoint({x}, {y})")  # PlainPoint(3, 4)

# Without __match_args__, only keyword patterns work:
class NoMatchArgs:
    def __init__(self, x, y):
        self.x = x
        self.y = y

match NoMatchArgs(3, 4):
    case NoMatchArgs(x, y):          # TypeError or no match — no __match_args__
        print(f"  matched: {x}, {y}")
    case NoMatchArgs(x=x, y=y):      # keyword — works, checks attributes directly
        print(f"  keyword matched: {x}, {y}")  # keyword matched: 3, 4
    case _:
        print("  no match")

# Dataclass auto-generates __match_args__:
from dataclasses import dataclass

@dataclass
class AutoPoint:
    x: float
    y: float

print(AutoPoint.__match_args__)  # ('x', 'y')

# NamedTuple also works:
from typing import NamedTuple

class NTPoint(NamedTuple):
    x: float
    y: float

match NTPoint(3, 4):
    case NTPoint(x, y):
        print(f"  NTPoint({x}, {y})")  # NTPoint(3, 4)

# Enum with class pattern:
from enum import Enum

class Direction(Enum):
    NORTH = 1
    SOUTH = 2
    EAST = 3
    WEST = 4

# For enums, match on value patterns (see Section 4), not class patterns:
direction = Direction.NORTH
match direction:
    case Direction.NORTH:
        print("  going north")
    case Direction.SOUTH:
        print("  going south")
    case _:
        print("  other direction")

# But you CAN use class patterns with enum if you match the enum member's structure
# (rare — value patterns are preferred for enums)
```

### Realistic Class Pattern Example

```python
from dataclasses import dataclass
from typing import Union


@dataclass
class Deposit:
    amount: float
    account: str

@dataclass
class Withdrawal:
    amount: float
    account: str

@dataclass

    amount: float
    from_account: str
    to_account: str

class Fee:
    amount: float
    reason: str

    """Process any transaction type — class patterns make this clean."""
    match tx:
        case Deposit(amount, account) if amount <= 0:
            return f"Invalid deposit: amount must be positive, got {amount}"

        case Deposit(amount, account):
            return f"Deposited ${amount:.2f} to {account}"

        case Withdrawal(amount, account) if amount <= 0:
            return f"Invalid withdrawal: amount must be positive"

        case Withdrawal(amount, account):

        case Transfer(amount, from_acct, to_acct) if from_acct == to_acct:
            return f"Cannot transfer to same account: {from_acct}"

        case Transfer(amount, from_acct, to_acct):
            return f"Transferred ${amount:.2f} from {from_acct} to {to_acct}"

        case Fee(amount, reason):
            return f"Fee of ${amount:.2f}: {reason}"

        case _:
            return f"Unknown transaction: {tx}"


transactions = [
    Deposit(100.00, "savings"),
    Withdrawal(50.00, "checking"),
    Transfer(200.00, "savings", "checking"),
    Transfer(100.00, "savings", "savings"),  # same account — error
    Fee(5.00, "monthly maintenance"),
    Deposit(-10.00, "savings"),               # invalid — guard catches it
]

for tx in transactions:
    print(f"  {process_transaction(tx)}")
```

## 9. Guards — `if` Conditions on Patterns

A guard (`if <condition>`) adds an arbitrary boolean test after the pattern matches. If the guard is `False`, the pattern is considered non-matching and the next `case` is tried.

```python
# Basic guard — range check
def classify_number(n):
    match n:
        case x if x < 0:
            return f"negative: {x}"
        case 0:
            return "zero"
        case x if 0 < x < 100:
            return f"small positive: {x}"
        case x if x >= 100:
            return f"large: {x}"
        case _:
            return "not a number"

# Guard can reference variables bound by the pattern
def handle_point(point):
    match point:
        case (x, y) if x == y:
            return f"diagonal: ({x},{y})"
        case (x, y) if x > y:
            return f"below diagonal: ({x},{y})"
        case (x, y):
            return f"above diagonal: ({x},{y})"

print(handle_point((3, 3)))  # diagonal
print(handle_point((5, 2)))  # below diagonal
print(handle_point((2, 5)))  # above diagonal

# Guard with external variables
threshold = 100
items = [10, 200, 30]

for item in items:
    match item:
        case x if x > threshold:
            print(f"  {x} exceeds threshold {threshold}")
        case x:
            print(f"  {x} within threshold")

# Guard with method calls — any expression
def handle_text(text):
    match text:
        case s if s.startswith("http"):
            return f"URL: {s}"
        case s if s.isdigit():
            return f"numeric string: {s}"
        case s if len(s) > 50:
            return f"long text ({len(s)} chars)"
        case s:
            return f"text: {s}"

# Guard with `and`/`or` — complex conditions
def handle_order(order):
    match order:
        case {"total": t, "paid": True} if t > 1000:
            return "large paid order — priority shipping"
        case {"total": t, "paid": True} if t > 100:
            return "paid order — standard shipping"
        case {"total": t, "paid": True}:
            return "small paid order"
        case {"total": _, "paid": False}:
            return "unpaid — awaiting payment"
        case _:
            return "invalid order"

# Guard on class patterns
from dataclasses import dataclass

@dataclass
class Account:
    name: str
    balance: float
    is_frozen: bool = False

def handle_account(acct: Account):
    match acct:
        case Account(name, balance, True):        # frozen — any balance
            return f"Account {name} is frozen"
        case Account(name, balance) if balance < 0:
            return f"Account {name} overdrawn: ${balance:.2f}"
        case Account(name, balance) if balance == 0:
            return f"Account {name} is empty"
        case Account(name, balance):
            return f"Account {name}: ${balance:.2f}"
```

### Guard Pitfalls

```python
# Pitfall 1: Guard references must be in scope
# The guard can reference:
#   - variables bound by the pattern (like `x` in `case x if x > 0`)
#   - variables from the enclosing scope (like `threshold`)
# But NOT variables from a different case:
# match value:
#     case [a, b]:
#         pass
#     case x if a > 0:  # NameError — `a` not in scope here
#         pass

# Pitfall 2: Guard does NOT affect exhaustiveness
# Adding a guard makes a pattern conditional — the bare pattern might match
# but the guard rejects it, falling through to the next case
value = -5
match value:
    case x if x > 0:
        print(f"  positive: {x}")
    case x if x < 0:
        print(f"  negative: {x}")    # this matches — guard passes
    case _:
        print("  zero or other")

# Pitfall 3: Guard evaluation order — pattern must match BEFORE guard is tested
# If the pattern doesn't match, the guard is never evaluated (short-circuit)
data = {"a": 1}
match data:
    case {"a": x, "b": y} if y > 0:    # pattern fails (no "b" key) — guard NOT evaluated
        print(f"  a={x}, b={y}")
    case {"a": x}:
        print(f"  only a: {x}")         # this matches instead
    case _:
        print("  no match")

# Pitfall 4: Don't use guards when a pattern alone suffices
# Bad — guard does what a literal pattern does:
# case x if x == 200:  →  case 200:
# Bad — guard does what OR pattern does:
# case x if x == 1 or x == 2 or x == 3:  →  case 1 | 2 | 3:
```

## 10. `as` Patterns — Binding the Whole Subject

The `as` keyword binds the **entire subject** (or sub-pattern) to a variable while simultaneously matching a more specific pattern.

```python
# Basic `as` — bind the subject while matching a specific shape
def handle_value(value):
    match value:
        case [x, y] as point:
            return f"2D point {point} with x={x}, y={y}"
        case {"key": v} as mapping:
            return f"mapping {mapping} with key value {v}"
        case _:
            return "other"

print(handle_value([3, 4]))              # 2D point [3, 4] with x=3, y=4
print(handle_value({"key": "hello"}))    # mapping {'key': 'hello'} with key value hello

# `as` with class patterns — bind the object and destructure it
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

def handle_point(p):
    match p:
        case Point(0, 0) as origin:
            return f"Origin: {origin}"
        case Point(x, y) as pt if x == y:
            return f"Diagonal point {pt} at ({x},{y})"
        case Point(x, y) as pt:
            return f"Point {pt} at ({x},{y})"

print(handle_point(Point(0, 0)))  # Origin: Point(x=0, y=0)
print(handle_point(Point(3, 3)))  # Diagonal point Point(x=3, y=3) at (3,3)

# `as` with OR patterns — bind regardless of which alternative matched
def handle_number(n):
    match n:
        case 1 | 2 | 3 as small:
            return f"small number: {small}"
        case int(x) as num if x > 100:
            return f"large int: {num}"
        case _:
            return "other"

print(handle_number(2))    # small number: 2
print(handle_number(150))  # large int: 150

# `as` with wildcard — technically `case _ as x:` is just `case x:`
# but `_ as x` makes intent clearer in some contexts
# (In practice, just use `case x:` — `case _ as x:` is unusual)

# Nested `as` — bind sub-patterns
def handle_nested(data):
    match data:
        case [first, *rest as remaining]:
            return f"first={first}, remaining={remaining}"
        case {"items": [*items as all_items]}:
            return f"items={all_items}"
        case _:
            return "other"

print(handle_nested([1, 2, 3, 4]))           # first=1, remaining=[2, 3, 4]
print(handle_nested({"items": [1, 2, 3]}))    # items=[1, 2, 3]

# Realistic: `as` for logging the original while destructuring
import json

def process_message(raw: str):
    """Parse JSON and handle by type — keep raw for logging."""
    try:
        data = json.loads(raw)
    except json.JSONDecodeError:
        print(f"  Invalid JSON: {raw!r}")
        return

    match data:
        case {"type": "event", "name": name, "payload": payload} as full:
            print(f"  Event '{name}': {payload} (full: {full})")
        case {"type": "error", "message": msg} as full:
            print(f"  Error: {msg} (full: {full})")
        case dict() as d if not d:
            print("  Empty dict message")
        case _ as unknown:
            print(f"  Unknown message shape: {unknown}")
```

**Explanation:** `as` is useful when you need both the destructured parts and the whole object — for logging, passing to another function, or re-wrapping. Without `as`, you would need to reconstruct the object from its parts.

## 11. Nested and Advanced Patterns

Patterns compose arbitrarily. You can nest sequence inside mapping inside class inside sequence, with guards and OR at any level.

```python
from dataclasses import dataclass


@dataclass
class Point:
    x: float
    y: float

@dataclass
class Line:
    start: Point
    end: Point

# Deeply nested pattern — matches a specific geometric configuration
def classify_drawing(drawing):
    match drawing:
        # A line from origin to a diagonal point
        case Line(Point(0, 0), Point(x, y)) if x == y:
            return f"Diagonal line from origin to ({x},{y})"

        # A line along the X-axis
        case Line(Point(x1, y1), Point(x2, y2)) if y1 == y2 == 0:
            return f"Horizontal line on X-axis: {x1} to {x2}"

        # Any line with its start point bound
        case Line(start=Point(0, 0) as origin, end=end):
            return f"Line from origin {origin} to {end}"

        # Any line
        case Line(start, end):
            return f"Line from {start} to {end}"

        # A list of points forming a polygon
        case [Point(0, 0), *rest, Point(0, 0)]:
            return f"Closed polygon with {len(rest) + 2} vertices"

        case _:
            return "Unknown drawing"

print(classify_drawing(Line(Point(0, 0), Point(5, 5))))

print(classify_drawing(Line(Point(0, 0), Point(5, 0))))

# Sequence of mappings
```

## 12. Exhaustiveness — Not Enforced, You Enforce It

Unlike Rust or Haskell, Python's `match` does **not** enforce exhaustiveness. There is no compile-time error for missing cases and no runtime error for unmatched subjects. If no pattern matches and there is no wildcard, execution silently continues after the `match` block.

```python
# Non-exhaustive — no error, just silently does nothing for unmatched values
def handle_color(color):
    match color:
        case "red":
            print("  It's red")
        case "green":
            print("  It's green")
    # If color is "blue", nothing happens — no error, no warning

handle_color("blue")    # ... silence. No output, no error.
handle_color("red")     # It's red

# Fix: always include wildcard for non-exhaustive matches that should handle all inputs
def handle_color_safe(color):
    match color:
        case "red":
            print("  It's red")
        case "green":
            print("  It's green")
        case _:
            print(f"  Unknown color: {color}")

handle_color_safe("blue")  # Unknown color: blue

# For exhaustive matching on a KNOWN set (e.g., Enum), use wildcard to catch bugs:
from enum import Enum

class Status(Enum):
    PENDING = 1
    APPROVED = 2
    REJECTED = 3

def handle_status(status: Status):
    match status:
        case Status.PENDING:
            return "Waiting"
        case Status.APPROVED:
            return "Done"
        case Status.REJECTED:
            return "Denied"
        case _:
            # If a new Status member is added but not handled, this catches it
            raise ValueError(f"Unhandled status: {status}")

# Linters CAN help — some type checkers flag non-exhaustive matches:
# - mypy with `--strict` can warn about missing Enum cases in match
# - pyright/pylance can do exhaustiveness checking for Literal and Enum types
# But the Python runtime itself never enforces it.

# Pattern to make exhaustiveness explicit and fail loudly:
def assert_exhaustive(value) -> None:
    """Call in wildcard to make non-exhaustiveness a loud error."""
    raise AssertionError(f"Unhandled case: {value!r}")

def handle_strict(value):
    match value:
        case 1:
            return "one"
        case 2:
            return "two"
        case _:
            assert_exhaustive(value)

# handle_strict(3)  # AssertionError: Unhandled case: 3 — fails loudly

# Alternative: use `assert_never` from typing (Python 3.11+)
from typing import assert_never, Literal

def handle_literal(x: Literal[1, 2, 3]) -> str:
    match x:
        case 1:
            return "one"
        case 2:
            return "two"
        case 3:
            return "three"
        case _:
            assert_never(x)  # type checker verifies exhaustiveness; runtime raises

# If you add a new Literal value but forget a case, the type checker will flag
# the `assert_never` line.
```

**Guideline:** Always decide consciously whether your `match` is exhaustive. If it should handle all possible inputs, include `case _:` with either a sensible default or an explicit error. If it intentionally handles only some cases (filtering), document that the fall-through is intentional.

## 13. When to Use `match` vs. `if`/`elif`

### Prefer `match` When:

- Dispatching on the **type** or **shape** of a single value
- Destructuring data (extracting fields, elements, keys)
- Handling AST-like or message-like variants (dataclass unions, JSON shapes)
- Matching against Enum members
- The logic reads as "what *is* this thing?" rather than "is this *condition* true?"

### Prefer `if`/`elif` When:

- Conditions involve **multiple unrelated variables** (`if a > 0 and b < 10`)
- Conditions are **boolean predicates** not tied to a single subject
- You need `or`/`and` logic across different expressions
- The branches test fundamentally different things
- You need `elif` with unrelated conditions

```python
# === match is better: dispatching on shape ===

# if/elif version — verbose, manual destructuring
def handle_event_if(event):
    if isinstance(event, dict) and event.get("type") == "click":
        x, y = event["pos"]
        return f"Click at ({x},{y})"
    elif isinstance(event, dict) and event.get("type") == "keypress":
        return f"Key: {event['key']}"
    elif isinstance(event, dict) and event.get("type") == "quit":
        return "Quit"
    else:
        return "Unknown"

# match version — concise, destructuring built in
def handle_event_match(event):
    match event:
        case {"type": "click", "pos": (x, y)}:
            return f"Click at ({x},{y})"
        case {"type": "keypress", "key": key}:
            return f"Key: {key}"
        case {"type": "quit"}:
            return "Quit"
        case _:
            return "Unknown"

# === if is better: multi-variable conditions ===

def check_access(user, resource, action):
    # Conditions involve THREE different variables — match is awkward here
    if user is None:
        return "No user"
    elif not user.is_active:
        return "Inactive user"
    elif resource.owner == user and action in ("read", "write"):
        return "Owner access"
    elif user.is_admin and action != "delete":
        return "Admin access"
    elif action == "read" and resource.is_public:
        return "Public read"
    else:
        return "Denied"

# Trying to force this into match would be contrived:
def check_access_match(user, resource, action):
    match (user, resource, action):       # packing into tuple just to match
        case (None, _, _):
            return "No user"
        case (u, _, _) if not u.is_active:
            return "Inactive user"
        # ... guards doing all the real work — no benefit over if/elif
        case _:
            return "Denied"
    # Verdict: if/elif is clearer when guards do all the heavy lifting

# === Hybrid: match for structure, if for conditions ===

def process(data, strict=False, verbose=False):
    """Use match for data shape, if for flags/modes."""
    # Flags — use if
    if data is None:
        if strict:
            raise ValueError("data is None in strict mode")
        return None

    # Shape — use match
    match data:
        case {"items": [*items]} if len(items) > 0:
            result = f"Processing {len(items)} items"
        case {"items": []}:
            result = "No items to process"
        case {"error": msg}:
            result = f"Error: {msg}"
        case _:
            result = f"Unknown data: {data}"

    # Flags again — use if
    if verbose:
        print(f"  [verbose] {result}")

    return result
```

### Decision Flowchart

```
Is there a SINGLE subject value to dispatch on?
├── No  (multiple variables / unrelated conditions) → if/elif
└── Yes
    ├── Are you checking boolean conditions? (x > 0, len(y) > 10)
    │   └── Yes → if/elif (or match with guards, but if is simpler)
    └── Are you checking type / shape / structure / contents?
        ├── Simple equality (status == 200) → either works; match is fine
        ├── Type dispatch (isinstance) → match (case int(n):)
        ├── Destructuring (extract fields) → match
        ├── JSON / dict shapes → match (mapping patterns)
        ├── Sequence shapes → match (sequence patterns)
        └── Enum dispatch → match (value patterns)
```

## 14. Common Mistakes and Pitfalls

| Mistake | Why it fails | Fix |
|---|---|---|
| `case x:` expecting comparison | `x` is a capture — always matches, binds subject | `case y if y == x:` or `case Enum.MEMBER:` |
| `case _:` in the middle | Cases after wildcard are unreachable | Put `case _:` last |
| Missing `case _:` | Unmatched subjects silently do nothing | Add wildcard or handle fall-through explicitly |
| `case [a, b]:` with 3-element list | No match — sequence pattern requires exact length | `case [a, b, c]:` or `case [a, b, *_]:` |
| `case {"a": x}:` with string key variable | Key `"a"` is literal, not variable | Keys in mapping patterns are always literals |
| `case Point(x, y):` without `__match_args__` | Positional matching fails | Add `__match_args__` or use keyword `Point(x=x, y=y)` |
| Forgetting `|` binds same variables | Inconsistent bindings → `SyntaxError` | Ensure all OR alternatives bind the same names |
| Using `match` for multi-variable logic | Guards do all work — no benefit | Use `if`/`elif` instead |
| `bool` before `int` ordering | `bool` is subclass of `int` — `case int(n):` catches `True` | Put `case bool(b):` before `case int(n):` |
| `case 1:` expecting to not match `True` | `case True:` and `case 1:` are distinguished (identity-aware) | Know that `match` distinguishes `True`/`1` — this actually works correctly |

```python
# Pitfall 1: Bare name is capture, not value lookup
threshold = 10
value = 5

match value:
    case threshold:        # BUG — `threshold` is a capture, not a comparison!
        print(f"  threshold={threshold}")  # Always matches, threshold rebound to 5!
        # This prints "threshold=5" for ANY value

print(f"  threshold after: {threshold}")  # 5 — outer variable was rebound!

# Fix:
threshold = 10
match value:
    case x if x == threshold:
        print(f"  value equals threshold: {x}")
    case x:
        print(f"  value {x} != threshold {threshold}")

# Pitfall 2: Unreachable cases after wildcard/capture
value = 42
match value:
    case x:                # captures everything — always matches
        print(f"  case x: {x}")
    case 42:               # UNREACHABLE — linter should warn
        print("  case 42 — never reached")
    case _:                # UNREACHABLE
        print("  wildcard — never reached")

# Pitfall 3: Mapping pattern with variable key
key = "name"
data = {"name": "Alice", "age": 30}

match data:
    case {key: value}:     # BUG — matches {"key": value}, not {"name": value}
        print(f"  matched key={key}, value={value}")  # not matched — no "key" in data
    case _:
        print("  no match — pattern looked for literal 'key', not variable `key`")

# Fix — use guard:
match data:
    case dict() if key in data:
        print(f"  {key} = {data[key]}")  # name = Alice
    case _:
        print("  key not found")

# Pitfall 4: Forgetting that `str` is not a sequence pattern
match "hello":
    case [a, b, c]:        # never matches — str not treated as sequence
        print(f"  sequence: {a},{b},{c}")
    case "hello":          # literal — matches
        print("  literal hello")
    case str(s):           # class pattern — matches any string
        print(f"  any string: {s}")

# Pitfall 5: Star pattern binding is always a list
match (1, 2, 3, 4):       # tuple subject
    case [first, *rest]:   # list pattern
        print(f"  rest type: {type(rest).__name__}, value: {rest}")
        # rest type: list, value: [2, 3, 4] — always a list, even for tuple subjects

# Pitfall 6: `case []:` matches any empty sequence, not just lists
match ():
    case []:
        print("  [] matched ()")  # printed — empty list pattern matches empty tuple

match []:
    case ():
        print("  () matched []")  # also printed — symmetric

# To distinguish list vs tuple emptiness, use class pattern + guard:
match []:
    case list() if len([]) == 0:  # tricky — need subject reference
        pass

data = []
match data:
    case list() as lst if len(lst) == 0 and isinstance(data, list):
        print("  empty list specifically")
    case tuple() as t if len(t) == 0:
        print("  empty tuple specifically")
# Simpler: just use isinstance outside match for this edge case

# Pitfall 7: Match subject is evaluated once — side effects happen once
call_count = 0
def get_data():
    global call_count
    call_count += 1
    return {"status": 200}

match get_data():
    case {"status": 200}:
        print(f"  matched, call_count={call_count}")  # 1
    case {"status": 404}:
        print(f"  not matched")
# get_data called exactly once regardless of number of cases
```

## 15. Realistic End-to-End Example — Event System

```python
from dataclasses import dataclass
from enum import Enum
from typing import Union


# ─── Domain model ───

class Priority(Enum):
    LOW = 1
    MEDIUM = 2
    HIGH = 3
    CRITICAL = 4

@dataclass
class UserMessage:
    sender: str
    content: str
    priority: Priority = Priority.MEDIUM

@dataclass
class SystemAlert:
    code: int
    message: str
    priority: Priority = Priority.HIGH

@dataclass
class FileEvent:
    path: str
    action: str                        # "created", "modified", "deleted"
    size: int | None = None

@dataclass
class BatchEvent:
    events: list                       # list of events

# Union type for the event system
Event = Union[UserMessage, SystemAlert, FileEvent, BatchEvent, dict, list, None]


# ─── Handler using match ───

def handle_event(event: Event) -> str:
    """Route and handle any event type — showcases all pattern types."""

    match event:
        # ── None / null event ──
        case None:
            return "No event (null)"

        # ── User messages — class patterns with guards ──
        case UserMessage(sender, content, Priority.CRITICAL):
            return f"🚨 CRITICAL from {sender}: {content}"

        case UserMessage(sender, content, Priority.HIGH) if len(content) > 100:
            return f"Long high-priority message from {sender} ({len(content)} chars)"

        case UserMessage(sender, content, priority):
            return f"Message from {sender} [{priority.name}]: {content}"

        # ── System alerts — class patterns with literal + guards ──
        case SystemAlert(code, msg, _) if 500 <= code < 600:
            return f"🔥 Server error {code}: {msg}"

        case SystemAlert(code, msg, _) if 400 <= code < 500:
            return f"⚠️  Client error {code}: {msg}"

        case SystemAlert(code, msg, Priority.CRITICAL):
            return f"🚨 Critical system alert {code}: {msg}"

        case SystemAlert(code, msg, _):
            return f"System alert {code}: {msg}"

        # ── File events — class patterns with OR and guards ──
        case FileEvent(path, "created" | "modified" as action, size) if size is not None and size > 1_000_000:
            return f"Large file {action}: {path} ({size:,} bytes)"

        case FileEvent(path, "created" | "modified" as action, _):
            return f"File {action}: {path}"

        case FileEvent(path, "deleted", _):
            return f"File deleted: {path}"

        case FileEvent(path, action, _):
            return f"Unknown file action '{action}' on {path}"

        # ── Batch events — sequence patterns inside class patterns ──
        case BatchEvent([]):
            return "Empty batch"

        case BatchEvent([single]):
            # Recursively handle the single event
            return f"Batch (single): {handle_event(single)}"

        case BatchEvent([first, second, *rest]) if len(rest) == 0:
            return f"Batch (pair): {handle_event(first)} | {handle_event(second)}"

        case BatchEvent(events) if len(events) > 10:
            return f"Large batch: {len(events)} events"

        case BatchEvent(events):
            results = [handle_event(e) for e in events]
            return f"Batch ({len(events)} events): " + " | ".join(results)

        # ── Raw dict events (e.g., from JSON / webhook) — mapping patterns ──
        case {"type": "ping"}:
            return "Pong!"

        case {"type": "subscribe", "channel": str(channel)} as raw:
            return f"Subscribe to {channel} (raw: {raw})"

        case {"type": "unsubscribe", "channel": channel}:
            return f"Unsubscribe from {channel}"

        case {"type": str(type_name), "payload": {"data": data, **rest}}:
            return f"Generic {type_name} with data={data}, extra={rest}"

        case {"error": str(msg), "code": int(code)}:
            return f"Error {code}: {msg}"

        case {} as empty if len(empty) == 0:
            return "Empty dict event"

        case dict() as d:
            return f"Unknown dict shape: {d}"

        # ── Raw list events — sequence patterns ──
        case []:
            return "Empty list event"

        case [str(cmd), *args] if cmd.startswith("/"):
            return f"Command {cmd} with args {args}"

        case [*items] if len(items) > 5:
            return f"Long list event: {len(items)} items"

        # ── Catch-all ──
        case _:
            return f"Unhandled event type: {type(event).__name__} — {event!r}"


# ─── Demo ───

events: list[Event] = [
    UserMessage("Alice", "Hello team!", Priority.MEDIUM),
    UserMessage("Bob", "URGENT: Server is down, need immediate attention, all hands on deck!", Priority.HIGH),
    UserMessage("System", "Disk failure imminent", Priority.CRITICAL),
    SystemAlert(500, "Database connection lost"),
    SystemAlert(404, "Endpoint not found"),
    FileEvent("/tmp/report.pdf", "created", 2_500_000),
    FileEvent("/tmp/notes.txt", "modified", 1024),
    FileEvent("/tmp/old.log", "deleted"),
    BatchEvent([]),
    BatchEvent([UserMessage("Charlie", "Hi", Priority.LOW)]),
    BatchEvent([SystemAlert(200, "OK"), SystemAlert(201, "Created")]),
    {"type": "ping"},
    {"type": "subscribe", "channel": "news"},
    {"error": "Rate limited", "code": 429},
    ["/help", "arg1", "arg2"],
    None,
    "unexpected string event",
]

for ev in events:
    result = handle_event(ev)
    print(f"  {result}")
```

**Explanation:** This handler demonstrates every pattern type in one realistic system: `None` literals, class patterns with positional destructuring, OR patterns (`"created" | "modified"`), `as` bindings, guards for range checks and size thresholds, sequence patterns for batch handling, mapping patterns for JSON-like dicts, and a wildcard catch-all. The `match` block replaces what would otherwise be a deeply nested `if`/`isinstance`/`len`/key-check chain.

## 16. Quick Reference

```python
# ─── Basic match ───
match subject:
    case pattern:
        ...
    case pattern if guard:
        ...
    case _:
        ...

# ─── Literal patterns ───
case 200:               # int literal
case "hello":           # str literal
case None:              # None
case True:              # bool (distinguished from 1)
case 3.14:              # float

# ─── Wildcard & capture ───
case _:                 # wildcard — matches anything, binds nothing
case x:                 # capture — matches anything, binds to x (ALWAYS matches!)

# ─── OR patterns ───
case 200 | 201 | 204:
case (0, 0) | (1, 1):
case [x, 0] | [0, x]:  # each alternative must bind SAME variables

# ─── Sequence patterns ───
case []:                # empty sequence
case [a, b]:            # exactly 2 elements
case [first, *rest]:    # 1+ elements, rest is list
case [first, *mid, last]:  # 2+ elements
case (_, 0):            # ignore first, second must be 0

# ─── Mapping patterns ───
case {"key": value}:              # key "key" must exist, value bound
case {"a": 1, "b": x}:           # "a" must be 1, "b" bound to x
case {"host": h, **rest}:        # capture extra keys in rest
case {}:                          # any mapping (not just empty!)

# ─── Class patterns ───
case Point(x, y):                 # positional — needs __match_args__
case Point(x=x, y=y):            # keyword — needs attributes x, y
case Point(0, 0):                 # literal values inside class
case Point(x, y) if x == y:      # with guard
case Config.host:                  # value pattern — dotted name compares via ==
case Color.RED:                    # enum value pattern

# ─── Guards ───
case x if x > 0:
case [a, b] if a == b:
case {"k": v} if isinstance(v, str):

# ─── As patterns ───
case [a, b] as point:            # bind whole + destructure
case {"k": v} as mapping:        # bind whole dict + extract
case 1 | 2 | 3 as n:            # bind whole across OR

# ─── Nested ───
case {"users": [{"name": str(name)}]}:
case Line(Point(0, 0), Point(x, y)) if x == y:
case [{"type": "click", "pos": (x, y)}, *rest]:

# ─── Matching existing variable's VALUE ───
# Wrong: case my_var:    — this is a capture, not a comparison
# Right: case x if x == my_var:
# Right: case MyClass.MY_CONST:   — dotted name is a value pattern
# Right: case Color.MEMBER:       — enum member is a value pattern

# ─── Exhaustiveness ───
# Always handle the wildcard explicitly:
match value:
    case 1: ...
    case 2: ...
    case _: raise ValueError(f"Unhandled: {value!r}")  # fail loudly
```

## 17. Version and Tooling Notes

| Concern | Detail |
|---|---|
| **Minimum version** | Python 3.10 (`match`/`case` is a `SyntaxError` on 3.9 and below) |
| **Soft keywords** | `match`/`case` usable as identifiers outside `match` blocks |
| **No exhaustiveness enforcement** | Runtime never errors on missing cases; use `case _:` + `assert_never` for safety |
| **Type checker support** | mypy, pyright/pylance support exhaustiveness for `Literal`/`Enum` with `assert_never` |
| **Performance** | CPython compiles `match` to efficient jump tables for literal-heavy cases; generally comparable to `if`/`elif` chains |
| **No fall-through** | Unlike C `switch`, no `break` needed and no accidental fall-through |

```python
# Guard: version check for libraries supporting both old and new Python
import sys

if sys.version_info >= (3, 10):
    def handle(value):
        match value:
            case 1:
                return "one"
            case _:
                return "other"
else:
    def handle(value):
        if value == 1:
            return "one"
        else:
            return "other"
```
