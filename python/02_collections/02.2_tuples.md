# 2.2 Tuples

If a list is a dynamic array you can change, a tuple is its disciplined sibling — an immutable, ordered sequence. Tuples appear everywhere in Python: function returns, dictionary keys, format strings, and any place where an ordered bundle should be treated as a single value. Understanding tuple semantics precisely, especially the shallow-immutability trap and the packing/unpacking machinery, is essential for writing idiomatic Python.

## What a Tuple Is

A `tuple` is:

- **Ordered** — like lists, index `0` to `len-1`, insertion order preserved.
- **Immutable** — contents cannot be changed after creation; no `append`, `extend`, `sort`, or item assignment.
- **Heterogeneous** — any mixture of objects.
- **Hashable (when contents are hashable)** — can serve as a `dict` key or `set` element.
- **Optimized** — smaller and slightly faster than lists for iteration and storage; often cached/reused by the interpreter.

```python
empty = ()                  # empty tuple
single = (42,)              # single-element — comma required!
pair = (1, "hello")
coords = 10, 20             # parentheses optional for packing
```

> **Key mental model:** Think of a tuple as a *record* or *struct* — an immutable bundle of named or positional fields — rather than just a "read-only list." Python's own terminology reinforces this: many standard APIs return tuples precisely because the caller should treat the result as a fixed-shape value.

## Construction

### Literal Syntax — Commas Make Tuples, Not Parentheses

```python
# Parentheses are often optional — commas define tuples
a = 1, 2, 3                 # (1, 2, 3) — packing
b = (1, 2, 3)               # same — parentheses for grouping/clarity
c = ()                       # empty tuple — parentheses required (no comma possible)
d = (1,)                     # single element — trailing comma mandatory
e = (1)                      # NOT a tuple — just int 1 with grouping parens
print(type(c), type(d), type(e))  # <class 'tuple'> <class 'tuple'> <class 'int'>

# Trailing commas encouraged
point = (
    3,
    4,
)

# From iterable
print(tuple([1, 2, 3]))     # (1, 2, 3)
print(tuple("abc"))          # ('a', 'b', 'c')
print(tuple({1: "a", 2: "b"}))  # (1, 2) — iterates keys like list()
print(tuple())               # ()
```

> **Classic gotcha:** The missing comma on single-element tuples has caused countless bugs. When a function expects a tuple of IDs and you pass `(id)` instead of `(id,)`, you are passing the integer itself.

```python
def process(ids: tuple):
    for i in ids:
        print(i)

# Bug: passes int, iterates its… nothing — actually TypeError if you iterate int
# process((42))   # would try to iterate int -> TypeError
process((42,))    # correct
process((42, 43))
```

### `tuple()` Constructor

```python
# Copies another iterable into a tuple (shallow)
lst = [1, 2, 3]
t = tuple(lst)
print(t)                    # (1, 2, 3)
lst.append(4)
print(t)                    # (1, 2, 3) — independent

# Idiomatic conversions
print(tuple(range(5)))      # (0, 1, 2, 3, 4)
```

### Tuple Multiplication

```python
print((0,) * 5)             # (0, 0, 0, 0, 0)
print((1, 2) * 2)           # (1, 2, 1, 2)
# Same shallow-reference semantics as lists — safe for immutables,
# still shares object refs for mutables (see shallow immutability)
```

## Tuple vs List — When to Use Which

This choice communicates intent.

| Criterion | Tuple | List |
|---|---|---|
| Mutability | Immutable | Mutable |
| Use as `dict` key / `set` element | Yes (if contents hashable) | Never |
| Homogeneous variable-length collection | Less idiomatic | **Idiomatic** — `[float]` scores |
| Heterogeneous fixed-shape record | **Idiomatic** — `(x, y)` coordinate | Less idiomatic |
| Methods | `count`, `index` only | Many mutators |
| Performance (iteration, memory) | Slightly faster/smaller | Tiny overhead |
| Intended semantics | Structure/record | Sequence/collection |

**Rule of thumb from the standard library:**

- If the collection is *homogeneous* and variable-length — a sequence of the same kind of thing (scores, names, lines) — use a **list**.
- If it is *heterogeneous* and fixed-size — a record of different kinds of things (name + age + city, x + y) — use a **tuple** (or better, a `namedtuple`/`dataclass` for clarity).

```python
# List: homogeneous, variable length — "collection of things"
scores = [98, 87, 92]
names = ["Alice", "Bob"]

# Tuple: heterogeneous, fixed arity — "bundle of fields"
person = ("Alice", 30, "NYC")          # name, age, city
coordinate = (3.0, 4.5)                # x, y
rgb = (255, 128, 0)                    # r, g, b

# Function return as record — canonical tuple use
def min_max(values: list[int]) -> tuple[int, int]:
    return min(values), max(values)    # packing

lo, hi = min_max([3, 1, 4])           # unpacking
```

> **Performance note:** The CPython allocator reuses tuples; small tuples may be interned. This is an implementation detail, but it means tuple creation is often cheaper than list creation. Do not choose tuple *only* for performance — choose by semantics — but it is a free bonus.

## Packing and Unpacking

Tuple packing/unpacking is arguably Python's most elegant assignment feature.

### Packing

```python
a = 1, 2, 3                 # packing — no parentheses needed
b = 1,                      # single-element packing
```

### Unpacking (Destructuring)

```python
point = (3, 4)
x, y = point                # unpack into names
print(x, y)                 # 3 4

# Works with any iterable, not just tuples:
first, second = [10, 20]    # from list
a, b, c = "xyz"             # from string
d, e = {"p": 1, "q": 2}    # from dict — unpacks keys -> d='p', e='q'
# dict unpacking in other contexts uses .items():
for k, v in {"a": 1, "b": 2}.items():
    print(k, v)
```

```python
# Swap idiom — no temp variable
x, y = 10, 20
x, y = y, x                 # packing + unpacking
print(x, y)                 # 20 10

# Return multiple values — actually returns a tuple
def stats(nums: list[float]) -> tuple[float, float, float]:
    return min(nums), max(nums), sum(nums) / len(nums)

lo, hi, avg = stats([1, 2, 3, 4])
print(lo, hi, avg)

# Ignoring values with _
first, _, third = (1, 2, 3)
_, second, _ = (1, 2, 3)   # convention: _ means "don't care"
# Use *_ for many
```

### Extended Unpacking with `*`

Introduced in PEP 3132, the `*` target collects remaining items into a **list** (even when unpacking a tuple).

```python
head, *tail = [1, 2, 3, 4, 5]
print(head)                 # 1
print(tail)                 # [2, 3, 4, 5] — always a list

first, *middle, last = [1, 2, 3, 4, 5]
print(middle)               # [2, 3, 4]

a, *b, c = (1, 2)          # b gets [] when nothing remains — no error
print(a, b, c)              # 1 [] 2

# Star may appear only once, but anywhere
*f, last = range(5)
print(f)                    # [0, 1, 2, 3]

# Use in function signatures too (see functions lesson), and to unpack at call site:
t = (2, 3)
print(pow(*t))              # pow(2, 3) == 8
print([*range(3), *range(2)])  # [0, 1, 2, 0, 1] — spread idiom
```

```python
# Realistic: parsing records
records = [
    ("Alice", 30, "NYC", "Engineer", "active"),
    ("Bob", 25, "SF", "Designer"),
]
for name, age, city, *extra in records:
    print(name, age, city, extra)
# Alice -> extra ['Engineer', 'active']
# Bob   -> extra ['Designer']

# Nested unpacking
point = ((1, 2), (3, 4))
(x1, y1), (x2, y2) = point
print(x1, y1, x2, y2)       # 1 2 3 4

for (a, b), c in [((1, 2), 3), ((4, 5), 6)]:
    print(a, b, c)
```

> **Common error:** Mismatch between number of targets and values without `*` raises `ValueError`.

```python
# a, b = (1, 2, 3)  # ValueError: too many values to unpack
# a, b, c = (1, 2)  # ValueError: not enough values to unpack
```

## Tuple Methods and Operations

Tuples support only two methods — a consequence of immutability:

```python
t = (1, 2, 3, 2, 1)
print(t.count(2))           # 2 — occurrences
print(t.index(2))           # 1 — first occurrence
print(t.index(2, 2))        # 3 — search from offset
# t.index(99)               # ValueError if not found
```

Common operations (same as sequences, all non-mutating):

```python
t = (1, 2, 3)
print(len(t))               # 3
print(2 in t)               # True
print(t[1])                 # 2
print(t[1:])                # (2, 3) — slice returns new tuple
print(t + (4, 5))           # (1, 2, 3, 4, 5) — concatenation, new tuple
print(t * 2)                # (1, 2, 3, 1, 2, 3)
for x in t: print(x)        # iteration
print(min(t), max(t), sum(t))

# Comparison is lexicographic
print((1, 2) < (1, 3))     # True
print((1, 2) < (1, 2, 0))  # True — shorter is smaller if prefix equal
```

## Immutability Is Shallow

Immutability prevents rebinding the tuple's *slots*, not mutating objects *inside* it.

```python
t = ([1, 2], [3, 4])
# t[0] = [9, 9]            # TypeError: 'tuple' object does not support item assignment
# t.append(5)               # AttributeError — no append

# But the inner lists ARE mutable:
t[0].append(99)
print(t)                    # ([1, 2, 99], [3, 4]) — contents changed!

# The tuple's identity never changes, but its "value" can appear to change
# if it contains mutables. This violates hashability — see below.

# Hashability tracks this: tuple is hashable only if all elements are hashable
print(hash((1, 2, 3)))      # fine — all immutables
# hash(([1, 2],))           # TypeError: unhashable type: 'list'
# hash((1, [2, 3]))         # TypeError — contains list
```

```
 ┌───────────────────────────┐
 │   tuple (immutable)       │
 │ ┌──────┐ ┌──────┐         │
 │ │ ref0 │─→│ [1,2,99] │  ← mutable inner — can change!
 │ │ ref1 │─→│ [3,4]    │  ← mutable inner
 │ └──────┘ └──────┘         │
 └───────────────────────────┘
   Slots cannot be rebound
   Objects they point to might be mutable
```

> **Rule:** For a tuple to be truly immutable *and* hashable, all its elements must be recursively immutable/hashable (ints, strings, tuples of immutables, frozensets, etc.). A tuple containing a list is neither.

```python
# Pitfall: using tuple as dict key with mutable inside
# d = {([1, 2], "a"): 1}   # TypeError — list inside tuple makes it unhashable
# Correct: use tuple of immutables only
d = {(1, 2): "a", (frozenset([1, 2]), "b"): "c"}
```

## Tuples as Dict Keys — A Canonical Use

```python
# Coordinates, edges, composite keys — natural with tuples
distances = {
    ("NYC", "Boston"): 190,
    ("Boston", "NYC"): 190,
    ("NYC", "DC"): 225,
}
print(distances[("NYC", "Boston")])

# Counting co-occurrences
from collections import Counter
pairs = [("a", "b"), ("a", "b"), ("b", "c")]
print(Counter(pairs))       # Counter({('a', 'b'): 2, ('b', 'c'): 1})

# Tuples remember insertion order as keys (dicts are insertion-ordered since 3.7)
```

## `namedtuple` — Self-Documenting Tuple Records

Tuples are concise but access by index (`person[1]`) is opaque. `collections.namedtuple` creates a `tuple` subclass with named fields — lightweight, immutable, fast.

```python
from collections import namedtuple

# Definition — two equivalent forms:
Point = namedtuple("Point", ["x", "y"])
Point2 = namedtuple("Point2", "x y")        # space- or comma-separated string
Color = namedtuple("Color", "r g b", defaults=(0, 0, 0))  # defaults (3.7+)

p = Point(3, 4)
print(p)                    # Point(x=3, y=4)
print(p.x, p.y)             # 3 4 — attribute access
print(p[0], p[1])           # 3 4 — still a tuple!
print(p._asdict())          # {'x': 3, 'y': 4} — OrderedDict
print(p._fields)            # ('x', 'y')
print(tuple(p))             # (3, 4)
print(len(p))               # 2 — tuple interface retained
print(p.count(3))           # 1 — tuple methods present

# _make and _replace (immutability: replace returns new instance)
q = Point._make([10, 20])   # from iterable
r = q._replace(x=99)        # new Point(99, 20), q unchanged
print(q, r)

# Realistic: records with type hints
try:
    from typing import NamedTuple

    class User(NamedTuple):
        name: str
        age: int
        active: bool = True

    u = User("Alice", 30)
    print(u)
except ImportError:
    pass

# Modern alternative: dataclass with frozen=True (mutable struct pattern)
# Use namedtuple when you need: tuple protocol (unpacking, hashing, comparison)
# Use dataclass when you need: mutable or complex default/member logic
```

### `namedtuple` Characteristics

| Feature | Detail |
|---|---|
| Subclass | `tuple` subclass — `isinstance(p, tuple)` is `True` |
| Immutability | Immutable like tuple — cannot assign to fields |
| Hashability | Hashable if fields are hashable |
| Memory | Uses `__slots__`-like optimization; smaller than normal objects |
| `_fields`, `_field_defaults` | Introspection attributes |

> **When to use what:**
>
> - **Plain tuple** — short-lived, local, unpacking immediately (`return (lo, hi)`).
> - **`namedtuple`** — tuple-shaped record that benefits from names, still needs tuple behavior (hashing, unpacking, `zip(*...)`).
> - **`typing.NamedTuple`** — same as `namedtuple` but with type annotations.
> - **`dataclasses.dataclass`** — richer object with `__init__` customization, mutability by default (`frozen=True` gives immutability but not tuple protocol).
> - **`SimpleNamespace` / `dict`** — fully mutable, heterogeneous attribute bag.

## Advanced Tuple Patterns

```python
# Variable-length unpacking at call site
args = (2, 3, 4)
print(max(*args))
# Equivalent to max(2, 3, 4)

# Double-star for dicts alongside tuple unpacking (not tuple, but related)
def fn(a, b, c=0): print(a, b, c)
t = (1, 2)
fn(*t)                    # fn(1, 2)
fn(*t, c=3)               # explicit override

# Using underscore to skip
(x, *_, last) = range(10)  # x=0, last=9, middle ignored

# Unpacking in comprehensions
pairs = [(1, "a"), (2, "b"), (3, "c")]
print([letter * num for num, letter in pairs])  # ['a', 'bb', 'ccc']

# zip with unpacking
xs = [1, 2, 3]
ys = [10, 20, 30]
for x, y in zip(xs, ys):
    print(x, y)

# Parallel assignment with iterables of different types
a, b = "ab"                # a='a', b='b'

# Singleton tuple unpack
(t,) = ("only",)
print(t)                   # 'only'

# Sorting a list of tuples — sorts lexicographically
data = [(3, "b"), (1, "c"), (1, "a")]
print(sorted(data))        # [(1, 'a'), (1, 'c'), (3, 'b')] — compares element 0, then 1
```

## Performance and Memory Details

```python
import sys
print(sys.getsizeof((1, 2, 3)))   # typically smaller than [1, 2, 3]
print(sys.getsizeof([1, 2, 3]))

# Iteration is micro-faster for tuples (fewer pointer chases; immutability enables caching).
# Don't micro-optimize: choose tuple vs list by semantics.

# CPython specifics:
# - Empty tuple () is a singleton — all () references share one object.
# - Small integers and interned strings may affect tuple memory sharing.
# - tuple.count/index go through the same C path as list.count/index.
```

## Common Mistakes

```python
# 1. (x) is not a tuple
print(type((1)))            # int — parens alone do nothing
print(type((1,)))           # tuple — comma makes it
# In function calls, trailing comma matters:
print((1))   # 1
print((1,))  # (1,)

# 2. Trying to mutate — all fail
# t = (1, 2)
# t[0] = 99            # TypeError
# t.append(3)          # AttributeError
# del t[0]             # TypeError
# But t += (3,) rebinds the name to a NEW tuple — does not mutate
t = (1, 2)
t += (3, 4)               # creates (1, 2, 3, 4), rebinds t
print(t)

# 3. Mutable default inside namedtuple
# Bad:
# from collections import namedtuple
# NT = namedtuple("NT", ["lst"])
# obj = NT([])  # default shared if you use defaults badly
# Use dataclass with default_factory instead for mutable defaults

# 4. Forgetting that tuples copy references, not deep-clone
t1 = ([1, 2], 3)
t2 = tuple(t1)              # shallow — same inner list object
t1[0].append(99)
print(t2)                   # ([1, 2, 99], 3)

# 5. Equality vs identity of tuples
a = (1, 2, 3)
b = (1, 2, 3)
print(a == b)               # True — value equality
print(a is b)               # May be False — not interned generally (implementation detail)

# 6. Unpacking with wrong arity
# a, b = (1, 2, 3)  # ValueError: too many values to unpack
# Fix with *
a, *rest = (1, 2, 3)
print(a, rest)              # 1 [2, 3]
```

## Summary

- Tuples are immutable, ordered, hashable-if-contents-hashable sequences — the right choice for fixed-shape records and return values.
- Commas define tuples; single-element requires trailing comma: `(1,)`.
- Packing/unpacking and extended `*` unpacking make tuples ergonomic for destructuring, swapping, and spread patterns.
- `namedtuple` / `typing.NamedTuple` add field names without losing tuple powers.
- Immutability is **shallow** — a tuple holding a list can appear to mutate and becomes unhashable.
- Prefer tuples for heterogeneous, fixed-arity records; lists for homogeneous, variable-length collections.

Tuples are not "immutable lists" so much as *values with shape*. Use them where the shape is part of the contract.
