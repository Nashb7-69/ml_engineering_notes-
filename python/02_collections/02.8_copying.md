# 2.8 Copying

Python variables are **names bound to objects**, not containers holding values. Whether `b = a`, `b = a.copy()`, `b = copy.copy(a)`, or `b = copy.deepcopy(a)` does the right thing depends on the *shape* of the data and the *intent* of isolation. Misunderstanding copying is one of the top sources of subtle bugs — mutating "another" object and watching the original bleed.

## The Three Levels of Copying

```python
# Setup: three intended levels of isolation
orig = [1, [2, 3], {"a": 4}]
# Goal: create `b` that can be mutated independently of `orig`
# Level | Operation                 | Outer container | Inner mutables | Identity (is)?
# ------|---------------------------|-----------------|----------------|---------------
# 0     | Assignment  b = a         | shared          | shared         | b is a == True
# 1     | Shallow     b = a.copy()  | new (shallow)   | shared         | b is not a, inner is
# 2     | Deep        b = copy.deepcopy(a) | new     | new (recursive)| fully independent
```

### Visual Model

```
Assignment (no copy):
  orig ──┐
         ├─→ [1, [2,3], {"a":4}]   ← one container
  alias ─┘

Shallow copy:
  orig ──→ [1, [2,3], {"a":4}]
             ├─→ [2,3]  ←──┐
             └─→ {"a":4}←─┐│ shared inner objects
  shallow ─→ [1,  ref ,  ref ]  ← new outer, same inners

Deep copy:
  orig ──→ [1, [2,3], {"a":4}]
  deep  ──→ [1, [2,3]′, {"a":4}′]  ← completely independent tree
            (recursion copies every reachable mutable; memo guards cycles)
```

## Level 0 — Assignment (No Copy)

```python
a = [1, 2, 3]
b = a                       # b names THE SAME OBJECT
print(a is b)               # True — identity
print(a == b)               # True — equality

b.append(4)                 # mutation visible through both names
print(a)                    # [1, 2, 3, 4] — "surprise" aliasing!
print(b)                    # [1, 2, 3, 4]

# Rebinding vs mutation — crucial distinction
b = [99]                    # REBIND: b now names a different object; a unaffected
print(a, b)                 # [1, 2, 3, 4] [99]
# For immutable targets, rebinding is the only option; in-place mutation never occurs.
# For mutable targets, methods like append/extend/sort mutate the shared object.

# Function parameters are assignments — shared mutation trap
def add_tag(tags, tag):
    tags.append(tag)        # mutates caller's object!
    return tags

my_tags = ["python"]
add_tag(my_tags, "ml")
print(my_tags)              # ['python', 'ml'] — caller mutated

# Even += on a list mutates (calls __iadd__); += on a tuple/int rebinds
lst = [1, 2]
lst += [3, 4]               # mutates in place — id unchanged
t = (1, 2)
old_id = id(t)
t += (3, 4)                 # new tuple — id changed
print(id(t) != old_id)
```

## Level 1 — Shallow Copy

Shallow copy creates a **new outer container** whose elements are **references to the original's objects**. Left-ship/right-ship: outer independent, inners shared.

### Five Idiomatic Shallow-Copy Forms (Equivalent Semantics)

```python
import copy

orig_list = [1, [2, 3], {"a": 4}]
# All five create independent shallow copies — same shallow behavior
slices = orig_list[:]                     # slicing idiom (list)
from_list = list(orig_list)               # constructor copy
from_dict = dict({"a": 1})                # dict constructor
method_copy = orig_list.copy()            # .copy() method (Python 3.3+)
module_copy = copy.copy(orig_list)        # copy.copy() — works generically

print(slices is orig_list, method_copy is orig_list)  # False False

# Similarly for dicts:
orig_dict = {"x": [1, 2], "y": 3}
d1 = orig_dict.copy()                     # .copy()
d2 = dict(orig_dict)                      # dict()
d3 = copy.copy(orig_dict)                 # copy.copy()
# And for sets: s.copy(), set(s), copy.copy(s)
# NOTE: "=" is NOT a copy. Everything else above IS a shallow copy.

# Subtle: copy.copy also knows how to shallow-copy via __copy__ hook (see § hooks)
```

### Demonstrating Shallow Semantics

```python
orig = [[1, 2], [3, 4]]
shallow = orig.copy()           # or orig[:], copy.copy(orig)

# Outer independent — appending to/overwriting shallow does not touch orig
shallow.append([5, 6])
print(orig, shallow)            # orig has 2 elements, shallow has 3

shallow[0] = [99]               # rebinding a slot in shallow — orig unaffected
print(orig)                     # [[1, 2], [3, 4]] — intact

# Inner shared — mutating an inner object bleeds
orig2 = [[1, 2], [3, 4]]
shallow2 = orig2.copy()
shallow2[0].append(99)          # mutates inner list [1,2] through shallow
print(orig2)                    # [[1, 2, 99], [3, 4]] — ALSO mutated
print(shallow2)                 # [[1, 2, 99], [3, 4]]

# Dict variant — inner mutables shared too
orig_d = {"scores": [10, 20], "active": True}
shallow_d = orig_d.copy()
shallow_d["scores"].append(30)
print(orig_d)                   # {'scores': [10, 20, 30], ...} — inner shared
shallow_d["new_key"] = "hello"
print("new_key" in orig_d)      # False — outer independent

# Contrast immutables inside — immutables cannot be mutated through the shared reference;
# you must REBIND a slot, which only affects one container.
a = [(1, 2), "hello", 42]
b = a.copy()
# a[0] as tuple cannot be mutated; b[0] = (99,) would rebind b only
# So shallow == effective isolation when all elements are immutable
# That is why shallow copy is "usually enough" for lists of ints/strings/tuples
```

### When Shallow Copy IS Sufficient

```python
# 1. List of immutable elements — shallow isolation is complete because inner elements cannot be mutated
flat = [1, 2, 3]
s = flat.copy()
s[0] = 99                   # rebinding only affects s — immutables
print(flat, s)              # [1, 2, 3] [99, 2, 3]

# 2. Want to snapshot outer structure but intentionally share inners (trading memory for speed)
import copy
shared_cfg = {"options": ["a", "b"], "mode": "fast"}
snapshot = copy.copy(shared_cfg)   # fast O(n) copy without cloning inner lists

# 3. Filtering/transforming pipeline — often you copy outer then rebuild elements explicitly
```

## Level 2 — Deep Copy

Deep copy recursively clones **every reachable mutable (and nominally immutable but copy-required) object**, building a fully independent tree with cycle and diamond-sharing awareness via a `memo` dict.

```python
import copy

orig = [1, [2, 3], {"a": [4, 5]}]
deep = copy.deepcopy(orig)

print(orig is deep)                 # False — different outer
print(orig[1] is deep[1])           # False — different inner list
print(orig[2] is deep[2])           # False — different dict
print(orig[2]["a"] is deep[2]["a"]) # False — nested list also independent
print(orig == deep)                 # True — same values

# Mutations are fully isolated
deep[1].append(99)
deep[2]["a"].append(99)
print(orig)                         # [1, [2, 3], {"a": [4, 5]}] — untouched
print(deep)                         # [1, [2,3,99], {"a": [4,5,99]}]

# Diamond-sharing preservation:
shared = [[1, 2]]
d = {"x": shared, "y": shared}
# orig shares sub-object: d["x"] is d["y"] -> True
deep_d = copy.deepcopy(d)
print(deep_d["x"] is deep_d["y"])   # True — deepcopy preserved sharing within the *copy*
print(d["x"] is deep_d["x"])        # False — copy isolated from original
# Shallow would also preserve single shared ref but deep keeps cycle semantics correctly
```

### Cycles and Memoization — Why `deepcopy` Isn't Just "Recursive Copy"

```python
import copy

# Self-referential object — naive recursion would infinite loop; deepcopy handles it via memo
a = [1, 2]
a.append(a)                 # a -> [1, 2, <self>]
print(a[2] is a)            # True — third slot points back
# Copy:
# shallow = a.copy()
# print(shallow[2] is a)    # True — shallow copy's cycle still points into original (shared)
# deepcopy preserves internal cycle without pointing into original:
deep = copy.deepcopy(a)
print(deep[2] is deep)      # True — cycle inside copy points to copy itself
print(deep[2] is a)         # False — not into original

# General memo: deepcopy calls __deepcopy__(self, memo) where memo dict maps id(orig) -> copy so far.
# Two refs to same mutable inside orig result in one copied object referenced twice in the copy.
```

### When You Need Deep Copy

```python
# 1. Nested mutable structures where inner mutation must NOT bleed:
orig = {"a": [1, 2], "b": {"inner": [3, 4]}}
# Need isolation? Must deepcopy.
# Shallow orig.copy() would share [1,2] and nested dict {inner:...}

# 2. Serialization checkpoints, history/undo without side effects
# Example: game state snapshot
import copy
state = {"board": [[0]*3 for _ in range(3)], "turn": "X"}
history = []
history.append(copy.deepcopy(state))   # snapshot — future board mutations don't affect saved copy
state["board"][0][0] = "X"
print(history[0]["board"])  # [[0,0,0],...] — unaffected

# 3. Don't deepcopy when unnecessary — it's expensive (recursive calls + memo dict)
# For flat collections of immutables, deep copy is just a shallow copy + wasted work
```

### Cost and Alternatives to `deepcopy`

```python
# deepcopies are expensive for large structures — O(n) with per-object overhead, memoization dict, Python dispatch
# Alternatives:

# A. Manual reconstruction via comprehensions (often faster + explicit):
import copy
nested = [[i, i+1] for i in range(1000)]
# deep = copy.deepcopy(nested)       # correct but slower
manual = [row.copy() for row in nested]  # shallow within row but rows are new; sufficient if leaves are immutables

# B. Immutable pattern — use tuples/frozensets to avoid the need to copy at all
imm = tuple(tuple(row) for row in [[1, 2], [3, 4]])  # now inner tuples can't be mutated; no isolation needed

# C. Serialization-based copy (json pickle) — sometimes faster for specific shapes
import json
deep_via_json = json.loads(json.dumps({"a": [1, 2], "b": 3}))  # only works for JSON types; drops types

# D. Structured cloning explicitly (copy what matters)
```

## Copy Methods — Reference Table

| Expression | Level | Types | Notes |
|---|---|---|---|
| `b = a` | Alias (no copy) | Any | Shared object |
| `a[:]` | Shallow | `list` only (slice) | New list, shared inners |
| `list(a)`, `tuple(a)`, `set(a)` | Shallow | Sequence/set | New outer container of that type |
| `a.copy()` | Shallow | `list`, `dict`, `set`, `bytearray`, ... | Preferred when available |
| `dict(a)` | Shallow | `dict` | Copies key-val entries (keys/vals shared) |
| `copy.copy(a)` | Shallow | Any supporting `__copy__` | Generic dispatch; falls back to `__reduce__` |
| `copy.deepcopy(a)` | Deep | Any supporting `__deepcopy__` | Recursive via memo |
| `import copy; copy.copy` | — | — | Use for code generic over types |

> **Collective takeaway:** All `.copy()` methods and constructor forms (`list/dict/set`) are **shallow**. Only `copy.deepcopy` is deep.

## Mutable Nested Pitfalls — The Three Classic Bugs

```python
# Bug 1: list * n with mutable inner — same shallow-sharing issue as slicing
grid_bug = [[0]*3] * 3      # 3 rows sharing the same inner list
grid_bug[0][0] = 1
print(grid_bug)             # [[1,0,0], [1,0,0], [1,0,0]] — all 3 corrupted
# Fix: comprehension creates fresh inner per row
grid_ok = [[0]*3 for _ in range(3)]
grid_ok[0][0] = 1
print(grid_ok)              # [[1,0,0], [0,0,0], [0,0,0]]

# Bug 2: dict.fromkeys with mutable default
bad = dict.fromkeys(["a", "b"], [])
bad["a"].append(1)
print(bad)                  # {'a': [1], 'b': [1]} — shared sentinel list
good = {k: [] for k in ["a", "b"]}  # new list per key
good["a"].append(1)
print(good)                 # {'a': [1], 'b': []}

# Bug 3: mutable default argument — the deepest-rooted Python bug
def append_one(item, lst=[]):  # ONE list shared across all calls
    lst.append(item)
    return lst
print(append_one(1))        # [1]
print(append_one(2))        # [1, 2] — leaked prior
# Fix: use None sentinel + construct fresh per call
def append_one_ok(item, lst=None):
    if lst is None: lst = []
    lst.append(item)
    return lst
print(append_one_ok(1))
print(append_one_ok(2))     # [2] — isolated per call
# Why does this relate to copying? Default mutable captures assignment semantics:
# the default object is evaluated ONCE at definition time and bound; every call aliases it.

# Bug 4: nested dict aliasing via assignment
a = {"x": [1, 2]}
b = a.copy()                # shallow — b["x"] is a["x"]
b["x"].append(3)
print(a)                    # {'x': [1, 2, 3]} — bleed despite .copy()
# Fix: copy.deepcopy(a) or reconstruct explicitly {"x": list(a["x"])}
```

## `copy` Module Internals — Hooks

```python
import copy

# Hook 1: __copy__ — called by copy.copy(obj)
class ListLike:
    def __init__(self, items): self.items = list(items)
    def __copy__(self):
        print("__copy__ called — shallow")
        new = self.__class__.__new__(self.__class__)
        new.items = self.items  # shallow — share inner list
        return new

obj = ListLike([1, 2])
clone = copy.copy(obj)
print(obj is not clone)     # True
print(obj.items is clone.items)  # True — shallow

# Hook 2: __deepcopy__ — called by copy.deepcopy(obj, memo)
class ListLike2:
    def __init__(self, items): self.items = list(items)
    def __deepcopy__(self, memo):
        print("__deepcopy__ called — deep")
        if id(self) in memo:
            return memo[id(self)]
        new = self.__class__.__new__(self.__class__)
        memo[id(self)] = new  # memo before filling to handle cycles
        new.items = copy.deepcopy(self.items, memo)
        return new

obj2 = ListLike2([1, [2, 3]])
clone2 = copy.deepcopy(obj2)
print(obj2.items is clone2.items)  # False — deep

# Fallback: if neither __copy__/__deepcopy__ defined,
# copy.copy deep via __getstate__/__setstate__/__reduce_ex__ machinery;
# objects like file handles, sockets, generators, modules generally cannot be usefully copied
# and will raise or produce nonsense — guard with try/except copy.error

# Example showing why memo must be passed through:
class Node:
    def __init__(self, value, child=None):
        self.value = value
        self.child = child
    def __deepcopy__(self, memo):
        if id(self) in memo:
            return memo[id(self)]
        new = Node.__new__(Node)
        memo[id(self)] = new
        new.value = copy.deepcopy(self.value, memo)
        new.child = copy.deepcopy(self.child, memo)  # memo propagated to nested
        return new

n1 = Node([1, 2])
n2 = Node(n1, n1)              # shared child — diamond
c2 = copy.deepcopy(n2)
print(c2.child is c2.value if hasattr(c2, 'value') else "not applicable")
# Diamond sharing preserved: both refs that pointed to same n1 now point to same copied n1' in the clone
```

> **When to implement `__copy__`/`__deepcopy__`:**
>
> - Your object owns mutable resources that need fresh copies for the clone (e.g., internal lists, buffers).
> - The default `copy` dispatch (which clones `__dict__` + `__slots__`) would be wrong or incomplete.
> - You hold *non-copyable* state (file descriptors, locks) — then define the hooks to skip or recreate them appropriately.

## Special Cases

```python
import copy

# Immutable builtins: copy.copy returns the SAME object (identity preserved)
x = (1, 2, 3)
print(copy.copy(x) is x)    # True — tuple immutable, no reason to copy
print(copy.deepcopy(x) is x) # True — same
s = "hello"
print(copy.copy(s) is s)    # True
# But tuple containing mutables is trick: (1, [2, 3]) is not fully immutable
t = (1, [2, 3])
print(copy.copy(t) is t)    # False — new tuple because it contains mutable (CPython detail varies)
# For deeply immutable structures, deep copy also trivially identity

# Functions, modules, classes, types: copy returns the same object
# Generators/iterators/coroutines: NOT copyable in a useful way

# Objects defining __slots__ without __dict__
class Slotted:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
print(copy.copy(Slotted(1, 2)).x)    # copy.copy handles __slots__
print(copy.deepcopy(Slotted(1, 2)).x)

# Subclass special cases: list/dict subclasses — .copy() keeps subclass type; copy.copy respects it
class MyList(list): pass
ml = MyList([1, 2, 3])
print(type(ml.copy()))      # <class 'MyList'> — copy preserves subclass
print(type(copy.copy(ml)))  # <class 'MyList'>

# Using slicing vs copy vs copy.copy — all shallow for lists; pick by intent clarity
# For code generic over collection type, use copy.copy / copy.deepcopy
# For local, concrete lists/dicts, prefer .copy() (self-documenting)
```

## Performance Notes

| Operation | Cost | When to Use |
|---|---|---|
| Assignment `b = a` | O(1) — pointer | Aliasing intentionally |
| Shallow copy `a.copy()` / `a[:]` / `copy.copy(a)` | O(n) — copies references | Cheap isolation of outer |
| `list(a)`, `dict(a)`, `set(a)` | O(n) | Same as shallow |
| Deep copy `copy.deepcopy(a)` | O(n) with large constant (calls + memo dict) | Full isolation of arbitrary graph |
| Comprehension `[list(row) for row in nested]` | O(n) but faster per-row | Manual deep-one-level — often faster than `deepcopy` |

```python
import timeit
small = [[i, i+1] for i in range(100)]
print(timeit.timeit("import copy; copy.deepcopy(small)", globals={"small": small}, number=1000))
print(timeit.timeit("[r.copy() for r in small]", globals={"small": small}, number=1000))
# Row-wise manual shallow (level-one deep) is typically much faster than generic deepcopy
# If you know the depth/shape (e.g., always 2 levels), prefer explicit reconstruction.
```

## Realistic Recipes

```python
# 1. Snapshot before mutation
import copy
config = {"host": "localhost", "opts": ["debug", "trace"]}
saved = copy.deepcopy(config)    # snapshot isolated
config["opts"].append("verbose")
print(saved["opts"])            # ['debug','trace'] — not polluted

# 2. Provide caller with safe copy so they cannot corrupt internal state (defensive copy)
class Registry:
    def __init__(self): self._items = {"a": [1, 2]}
    def items(self):
        return copy.deepcopy(self._items)  # callers get an independent dict

r = Registry()
client = r.items()
client["a"].append(99)
print(r._items)                 # {'a': [1, 2]} — intact

# 3. Clone with substitution — copy then mutate vs comprehension
orig = [{"id": 1, "val": [1, 2]}, {"id": 2, "val": [3, 4]}]
# Want copy where id=1's val is updated — deepcopy the one that changes:
clone = copy.deepcopy(orig)
for d in clone:
    if d["id"] == 1:
        d["val"].append(99)
print(orig[0]["val"])           # [1, 2] — untouched

# 4. Cloning data for test isolation — isolate fixture mutation from test case
# pytest fixtures should return copies, not shared dicts

# 5. Using copy with custom objects carrying memo-sensitive state
```

## Summary

- **Assignment** (`b = a`) shares identity; **shallow copy** (`a.copy()`, `a[:]`, `list(a)`, `copy.copy(a)`) shares inner mutables but gives a new outer container; **deep copy** (`copy.deepcopy(a)`) recursively clones the entire reachable graph with cycle-aware memoization.
- Every constructor form (`list`, `dict`, `set`, `.copy()`) is shallow — only `copy.deepcopy` is deep, and it is expensive.
- Shallow suffices when leaves are immutable; deep is mandatory for nested mutables where isolation is required.
- Classic pitfalls (`[[0]*m]*n`, `dict.fromkeys([], mutable)`, `def f(x=[])`) are all shallow-sharing bugs — fix with comprehensions and `None` sentinels.
- For custom classes, define `__copy__` and `__deepcopy__(self, memo)` to control behavior, propagate `memo`, and guard self-referential cycles.
- Prefer explicit shallow reconstructions for known shapes (often faster/clearer than generic `deepcopy`), and immutable data to avoid needing copies at all.
