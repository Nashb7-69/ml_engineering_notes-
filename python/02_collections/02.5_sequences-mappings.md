# 2.5 Sequences and Mappings — Abstract Collections

Python's built-in collections are concrete, but the *interfaces* they implement are abstract. Understanding the **Sequence** and **Mapping** abstractions explains why `list`, `tuple`, `str`, `bytes`, `range`, `dict`, `set`, and dozens of third-party types behave consistently with `len()`, `in`, iteration, indexing, and slicing. This is also where Python's duck typing and `collections.abc` formalize.

## The Abstract Hierarchy

```
collections.abc
───────────────
Iterable                  # __iter__
  Container               # __contains__  (x in y)
  Sized                   # __len__, __bool__ (len, truthiness)
  Collection = Iterable + Container + Sized

Reversible (Collection)   # __reversed__              (reversed())
Sequence(Collection, Reversible)  # __getitem__, __len__, index, count
  MutableSequence(Sequence)       # __setitem__, __delitem__, insert, append, ...

Mapping(Collection)       # Mapping: __getitem__, __iter__ (keys), __len__, get, keys, values, items
  MutableMapping(Mapping) # __setitem__, __delitem__, pop, popitem, clear, update, setdefault

Set(Collection)           # Set, MutableSet           (covered in 2.4)
```

> **Key idea:** An object need not *inherit* from `Sequence` to *be* a sequence. Python checks structural behavior (duck typing). `collections.abc.Sequence` provides `isinstance` registration and mixin methods for type checking and documentation.

### Concrete Type Map

| Concrete type | Abstract(s) | Notes |
|---|---|---|
| `list` | `MutableSequence` |  |
| `tuple` | `Sequence` (immutable) |  |
| `str` | `Sequence` (immutable) | Element type is 1-char `str` |
| `bytes`, `bytearray` | `Sequence` (`bytearray` mutable) | Elements are `int` in [0,255] |
| `range` | `Sequence` (immutable, lazy) | O(1) membership via math |
| `dict` | `MutableMapping` |  |
| `OrderedDict`, `defaultdict`, `Counter` | `MutableMapping` | Dict variants |
| `set` | `MutableSet` |  |
| `frozenset` | `Set` | Immutable variant |
| `collections.deque` | `MutableSequence` |  |
| `array.array`, `memoryview` | `Sequence` |  |
| `types.MappingProxyType` | `Mapping` (immutable view) |  |

## Iterable — The Root Protocol

Anything that can be iterated is `Iterable`.

```python
from collections.abc import Iterable

# Minimal protocol: define __iter__ returning an iterator
class Countdown:
    def __init__(self, n): self.n = n
    def __iter__(self):
        for i in range(self.n, 0, -1):
            yield i
    def __len__(self):  # optional but needed for Sized
        return self.n

c = Countdown(3)
print(isinstance(c, Iterable))  # True
for x in c: print(x)            # 3 2 1

# Python falls back: if __iter__ absent but __getitem__(0..n) exists, object is still iterable
class OldStyleSeq:
    def __getitem__(self, i):
        if i >= 3: raise IndexError
        return i*10
# OldStyleSeq() is iterable via sequence protocol, even without __iter__
print(list(OldStyleSeq()))       # [0, 10, 20]

# Duck typing: isinstance check is optional — for loops use protocol, not inheritance
# collections.abc exists to formalize and provide mixin methods
```

> **Distinction:** *Iterable* (has `__iter__` / `__getitem__`) vs *Iterator* (has `__next__` + `__iter__`). All iterators are iterables, not the reverse. `iter(iterable)` returns an iterator.

### `Container` (`in` / `__contains__`)

```python
# "x in y" tries y.__contains__(x); if missing, iterates via __iter__ (linear search)
lst = [1, 2, 3]
print(1 in lst)              # True — __contains__
# Custom: define __contains__ for O(1) if possible

# Seen in 2.4: sets/dicts provide O(1) __contains__; lists are O(n)
```

### `Sized` (`len` / `__len__`)

```python
# len(obj) -> obj.__len__() -> int >= 0
# Truthiness uses __len__ fallback: bool(obj) tests __bool__ first, then __len__
print(len([1, 2, 3]))        # 3
print(bool([]))              # False — __len__ == 0 => falsy
print(bool([0]))             # True — non-empty is truthy even if contents are falsy
# Custom: define __len__ to support len() and boolean tests
```

## `Sequence` — Ordered, Indexable, Sliceable

A `Sequence` formalizes what you expect from `str`, `list`, `tuple`, `range`, `bytes`:

- Inherit/implement `Iterable`, `Sized`, `Container`.
- Add `__getitem__(index)` where `index` can be `int` or `slice`.
- Add `__contains__`, `__iter__`, `__reversed__`, `index(value)`, `count(value)`.

```python
from collections.abc import Sequence, MutableSequence

print(isinstance([1,2], Sequence))   # True
print(isinstance((1,2), Sequence))   # True
print(isinstance("abc", Sequence))   # True
print(isinstance(range(5), Sequence))# True — lazy but still a sequence
print(isinstance({1,2}, Sequence))   # False — set is not ordered
print(isinstance({"a":1}, Sequence)) # False — dict is a Mapping
```

### Common Sequence Operations — Unified Table

All sequences (immutable + mutable) support these via dunder methods:

| Operation | Syntax | Dunder | Notes |
|---|---|---|---|
| Length | `len(s)` | `__len__` | O(1) for built-ins |
| Indexing | `s[i]` | `__getitem__(i)` | 0-based; negative counts from end |
| Slicing | `s[i:j:k]` | `__getitem__(slice(i,j,k))` | Returns subsequence of same type (for built-ins) |
| Membership | `x in s` | `__contains__` | Linear for list/tuple/str; O(1) for range; O(n) if no `__contains__` |
| Concatenation | `s + t` | `__add__` | Creates new sequence (same LHS type) |
| Repetition | `s * n` | `__mul__` | Shallow |
| Iteration | `for x in s:` | `__iter__` |  |
| Reversed | `reversed(s)` | `__reversed__` or `__getitem__`/`__len__` |  |
| Min/Max | `min(s)` | iterative |  |
| Index search | `s.index(x[,i[,j]])` | `index` | First occurrence; `ValueError` if absent |
| Count | `s.count(x)` | `count` |  |
| Unpacking | `a,b = s` | `__iter__` or `__getitem__` | If len matches |

```python
# Uniform across types — duck typing in action
from collections.abc import Sequence

def first_last(seq: Sequence):
    # Works for list, tuple, str, range, bytes, deque, custom Sequence
    return seq[0], seq[-1], len(seq)

print(first_last([10, 20, 30]))   # (10, 30, 3)
print(first_last("hello"))        # ('h', 'o', 5)
print(first_last((1, 2, 3, 4)))  # (1, 4, 4)
print(first_last(range(10, 21)))  # (10, 20, 11)

# Slicing works uniformly too
print("hello"[1:4])               # 'ell'
print([0,1,2,3,4][1:4])            # [1, 2, 3]
print((0,1,2,3,4)[1:4])            # (1, 2, 3)
print(range(10)[2:7])             # range(2, 7) — returns range object
```

### `range` — The Lazy Sequence Surprise

```python
# range is NOT a generator — it's a lazy immutable Sequence
r = range(10)
print(isinstance(r, Sequence))    # True
print(len(r))                     # 10 — O(1), not counted
print(r[3])                       # 3 — O(1), computed
print(r[2:5])                     # range(2, 5) — slicing returns new range (still lazy)
print(5 in r)                     # True — O(1) arithmetic, not scan
print(1_000_000 in range(1_000_000))  # False quickly — arithmetic bounds check
print(list(range(0, 10, 2)))      # [0, 2, 4, 6, 8] — materialize only when needed
# range equality compares values, not identity:
print(range(0, 3) == range(0, 3)) # True
print(range(0, 3) == [0, 1, 2])  # True — sequence equality across types? Actually range == list if values equal
```

### Immutable vs Mutable Sequences

|  | Immutable `Sequence` | `MutableSequence` |
|---|---|---|
| Types | `tuple`, `str`, `bytes`, `range` | `list`, `bytearray`, `deque` |
| Mutation | none (`s[i]=x` raises `TypeError`) | `__setitem__`, `__delitem__`, `insert`, `append`, `extend`, `pop`, `sort`, `reverse` |
| Hashable | Yes if elements hashable | No |
| Methods `count`/`index` | Yes | Yes |

```python
# Immutable: no item assignment
t = (1, 2, 3)
# t[0] = 99   # TypeError: 'tuple' object does not support item assignment
# Mutable: assignment allowed
lst = [1, 2, 3]
lst[0] = 99                 # fine

# MutableSequence adds contract:
from collections.abc import MutableSequence
print(issubclass(list, MutableSequence))   # True
print(issubclass(bytearray, MutableSequence))  # True
print(issubclass(tuple, MutableSequence)) # False
```

## `Mapping` — The Key-Value Abstraction

A `Mapping` formalizes `dict`-like behavior:

- `__getitem__(key)` → value
- `__iter__` → iterates keys (not values or items)
- `__len__` → number of keys
- plus `__contains__` (key membership), `get`, `keys`, `values`, `items`, `__eq__`

```python
from collections.abc import Mapping, MutableMapping

print(isinstance({}, Mapping))           # True
print(isinstance({"a":1}, MutableMapping))  # True
# str/list are NOT mappings — no key lookup

# Minimal custom mapping (immutable) — three methods required
from collections.abc import Mapping
class CaseDict(Mapping):
    def __init__(self, data):
        self._data = {k.lower(): v for k, v in data.items()}
    def __getitem__(self, key):
        return self._data[key.lower()]
    def __iter__(self):
        return iter(self._data)
    def __len__(self):
        return len(self._data)

m = CaseDict({"Hello": 1, "World": 2})
print(m["hello"])           # 1 — case-insensitive access
print(list(m))              # ['hello', 'world']
print("hello" in m)         # True — comes free via __getitem__
print(isinstance(m, Mapping)) # True — but due to ABC registration?
# Actually isinstance needs explicit registration or inheriting from Mapping
# Since CaseDict subclasses Mapping, methods like keys()/items() are provided as mixins!
print(list(m.keys()))       # mixin provided by Mapping ABC
print(list(m.items()))

# Mutable version requires __setitem__ and __delitem__ as well
```

### Common Mapping Operations — Table

| Operation | Syntax | Dunder | Notes |
|---|---|---|---|
| Length | `len(m)` | `__len__` |  |
| Access | `m[k]` | `__getitem__` | `KeyError` if missing |
| Assignment | `m[k]=v` | `__setitem__` | `MutableMapping` only |
| Delete | `del m[k]` | `__delitem__` | Same |
| Membership | `k in m` | `__contains__` | Checks **keys** only |
| Iteration | `for k in m:` | `__iter__` | Yields **keys** |
| Keys/values/items | `m.keys()` etc | provided by ABC mixin | Views on built-in dict |
| `get` | `m.get(k[,d])` | mixin | Returns default if missing |

```python
# Unified idiom: dict-like iteration is always keys; .items() for pairs
d = {"a": 1, "b": 2}
for k in d: print(k)           # a, b
for k, v in d.items(): print(k, v)

# Any Mapping respects the same protocol — code generic over Mapping is reusable
def print_mapping(m: Mapping):
    for k, v in m.items():     # works for dict, OrderedDict, UserDict, custom mappings
        print(f"{k!r}: {v!r}")

print_mapping({"x": 1})
print_mapping(CaseDict({"x": 1}))
```

## Duck Typing vs Nominal Typing

Python favors structural (duck) typing: "if it walks like a sequence, it is a sequence."

```python
# No inheritance required — define protocol methods
class MySeq:
    def __init__(self, items): self.items = list(items)
    def __getitem__(self, i):
        if isinstance(i, slice): return self.__class__(self.items[i])
        return self.items[i]
    def __len__(self): return len(self.items)

obj = MySeq([10, 20, 30])
print(list(obj))            # [10, 20, 30] — for-loop uses __getitem__/__len__ fallback
print(obj[1])               # 20
print(obj[0:2])             # MySeq([10, 20])
print(len(obj))             # 3
# But isinstance check fails unless registered:
from collections.abc import Sequence
print(isinstance(obj, Sequence))  # False — not subclassed nor registered
# To pass isinstance: inherit or register
Sequence.register(MySeq)
print(isinstance(obj, Sequence))  # True after registration
# Prefer inheriting from collections.abc.Sequence to gain mixin methods (index, count, __contains__)
```

> **Why use `collections.abc` at all if duck typing works?**
>
> - **Documentation:** Type hints like `def f(seq: Sequence[int]) -> None` communicate intent; linters and `mypy` enforce it.
> - **Mixin methods:** `Sequence` ABC provides `count`, `index`, `__contains__`, `__iter__`, `__reversed__` automatically when you implement `__getitem__` + `__len__`.
> - **Virtual subclass registration:** Libraries can declare conformance without inheritance.

## Iteration Protocol — How It All Connects

```python
# The iteration protocol powers for-loops, unpacking, comprehensions, and more
# Steps:
# 1. iterator = iter(obj)   → obj.__iter__()  (or fallback: Sequence via __getitem__ 0..)
# 2. Repeatedly: next(iterator) → iterator.__next__() until StopIteration

# Every collection implements this:

# A. Sequence falls back to index iteration if no __iter__
# B. Mapping iterates keys via __iter__
# C. Set iterates elements
# D. Custom iterables yield

# Realistic: any iterable works with collection tools
def head(iterable, n=3):
    from itertools import islice
    return list(islice(iterable, n))

print(head([1, 2, 3, 4, 5]))     # [1, 2, 3]
print(head({"a": 1, "b": 2}))   # ['a', 'b'] — iterates keys
print(head("hello"))            # ['h', 'e', 'l']
print(head(range(100)))         # [0, 1, 2]
print(head(x*x for x in range(10)))  # [0, 1, 4]

# Reversible protocol
print(list(reversed([1, 2, 3])))  # [3, 2, 1] — uses __reversed__ or __getitem__/__len__
# Custom: define __reversed__ for efficient reverse without materializing list
```

## Distinguishing Commonly Confused Concepts

### Iterable vs Iterator vs Sequence

| Concept | Requires | Can `len()`? | Can Index `obj[i]`? | Re-iterable? |
|---|---|---|---|---|
| **Iterable** | `__iter__` or `__getitem__` | Usually not | No | Yes (fresh iterator each `iter()`) |
| **Iterator** | `__next__` + `__iter__` | No | No | No (consumed) |
| **Sequence** | `__getitem__` by int/slice + `__len__` | Yes | Yes | Yes |
| **Set/Mapping** | `__contains__` + `__iter__` (no order) | Yes | No (except `dict[key]` lookup) | Yes |

```python
# Concrete demos
lst = [1, 2, 3]        # Sequence + Iterable + Iterator-creator
it = iter(lst)          # Iterator — __next__ exists, len(it) would fail
print(hasattr(it, "__next__"))  # True
# for x in it: ... consumes it; second loop over same it yields nothing
print(list(it))         # [1, 2, 3]
print(list(it))         # [] — exhausted

# Generator expression is (iterable + iterator at once)
gen = (x*x for x in range(3))
print(hasattr(gen, "__next__"))  # True — it's an iterator
print(list(gen), list(gen))      # [0,1,4] []

# Range is a Sequence that is also Iterable but NOT an Iterator
r = range(5)
print(iter(r) is not r)  # True — iterating creates a new iterator; range is re-iterable
```

### Sequence vs Mapping — Concrete Differences

```python
# Sequence: integer indices 0..n-1; order defines equality; slicing exists
# Mapping: arbitrary hashable keys; no integer index requirement; no slicing
# Both support len() and `in`, but membership semantics differ:
print(3 in [3, 4, 5])       # True — value membership
print(3 in {3: "a", 4: "b"}) # False — checks Key? Actually 3 in {3:"a"} is key membership -> True
# Wait: {3:"a"} has key 3 -> True! Demonstrate contrast:
print("a" in {"a": 1, "b": 2})  # True — checks keys
print("a" in ["a", "b", "c"])   # True — checks values (all are "values" for list)
# For dicts, values need explicit search:
print(1 in {"a": 1})        # False — 1 is value, not key
print(1 in {"a": 1}.values())  # True

# Conversion between Sequence <-> Mapping:
# Pairs sequence -> Mapping
pairs = [("a", 1), ("b", 2)]
print(dict(pairs))          # {'a': 1, 'b': 2}
# Mapping -> Sequence of tuples
print(list({"a": 1, "b": 2}.items()))  # [('a',1), ('b',2)]
```

## Type Annotations for Sequences and Mappings

```python
from collections.abc import Sequence, Mapping, MutableMapping, Iterable
from typing import List, Dict, Tuple  # older aliases; prefer builtins on 3.9+

# Modern preference (Python 3.9+):
def summarize(seq: Sequence[int]) -> None: ...
def process(m: Mapping[str, int]) -> None: ...

# Accept any iterable (most generic) vs sequence (need indexing/len)
def average(nums: Iterable[float]) -> float:
    # Can only iterate, not index — suitable for generators, lists, sets
    data = list(nums)
    return sum(data) / len(data) if data else 0.0

# Type hints are NOT enforced at runtime — documentation for linters/human readers
```

## Performance Conventions

| Operation | Sequences (list/tuple/str/range) | Mappings (dict) | Sets |
|---|---|---|---|
| `len(x)` | O(1) | O(1) | O(1) |
| `x in y` (`__contains__`) | O(n) for list/tuple/str; O(1) for range (math), dict, set | O(1) keys; O(n) values | O(1) |
| Index `x[i]` | O(1) | O(1) avg key lookup | N/A |
| Iteration | O(n) | O(n) (keys order) | O(n) (arbitrary order) |

## Realistic Examples — Writing Collection-Agnostic Code

```python
from collections.abc import Sequence, Mapping

# 1. Function that works with any Sequence
def middle(seq: Sequence):
    if not seq:
        raise ValueError("empty")
    return seq[len(seq) // 2]

print(middle([1, 2, 3, 4, 5]))  # 3
print(middle("hello"))          # 'l'
print(middle((10, 20, 30)))    # 20
print(middle(range(10)))       # 5

# 2. Merging any two Mappings (generic — works for dict-like objects)
def merge(a: Mapping, b: Mapping) -> dict:
    return {**a, **b}

print(merge({"x": 1}, {"y": 2}))  # {'x': 1, 'y': 2}

# 3. Coerce to list only if needed; keep iterables lazy otherwise
from collections.abc import Iterable
def first_n(iterable: Iterable, n: int = 3):
    from itertools import islice
    return list(islice(iterable, n))

print(first_n(range(10)))              # [0, 1, 2]
print(first_n(x*x for x in range(10))) # [0, 1, 4]
print(first_n({"a": 1, "b": 2}))     # ['a', 'b']

# 4. Inverting a Mapping: values must be hashable if new keys
def invert(m: Mapping) -> dict:
    inv = {}
    for k, v in m.items():
        inv.setdefault(v, []).append(k)
    return inv

print(invert({"a": 1, "b": 1, "c": 2}))  # {1: ['a','b'], 2: ['c']}

# 5. Custom Sequence with arithmetic semantics (vector example)
from collections.abc import Sequence as SeqABC
class Vector(SeqABC):
    def __init__(self, *components: float): self._c = tuple(components)
    def __getitem__(self, idx): return self._c[idx]
    def __len__(self): return len(self._c)
    def __repr__(self): return f"Vector{self._c}"

v = Vector(1, 2, 3)
print(v[1])                 # 2
print(list(v))              # [1, 2, 3]
print(v in [Vector(1,2,3)]) # True if vectors are equal? Needs __eq__ - not auto
# Because SeqABC mixin provides __contains__ via iteration, it works
```

## Summary

- Python's abstract hierarchy (`Iterable`, `Container`, `Sized`, `Sequence`, `MutableSequence`, `Mapping`, `MutableMapping`, `Set`) formalizes collection behavior.
- **Sequence** means *ordered, sliceable, indexable* (list, tuple, str, range); `range` is a lazy Sequence with O(1) membership via arithmetic.
- **Mapping** means *key-value store* (dict family); iteration yields keys; `get`/`keys`/`values`/`items` complete the protocol.
- Duck typing is primary — `collections.abc` exists for documentation, `isinstance` checks, and mixin methods, not as a requirement.
- Distinguish Iterable/iterator/Sequence carefully: re-iterability and indexability are the dividing lines.
- Writing functions against `Sequence` or `Mapping` (not just `list`/`dict`) makes APIs composable across concrete types.

Grasping these abstractions turns "Python has many collection types" into "Python has two great protocols with many concrete implementations."
