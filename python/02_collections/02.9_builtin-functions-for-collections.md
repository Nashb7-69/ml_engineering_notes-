# 2.9 Built-In Functions for Collections

Python's built-in functions are a compact power toolkit — `len`, `sum`, `min`/`max`, `sorted`, `reversed`, `enumerate`, `zip`, `any`/`all`, `filter`/`map` — plus the `collections` companions `Counter`, `defaultdict`, and `deque` that elevate idiomatic code from loops to declarative pipelines. Mastering these, especially their `key=` and `strict` parameters and generator compatibility, is the difference between Pythonic code and hand-rolled reimplementation.

## Why Built-Ins Matter

- **Single correct way** to iterate, count, aggregate — the standard library has optimized C paths (`Timsort` for `sorted`, hash probes for `in`, vector loops for `sum` on ints).
- **Protocol-based** — work uniformly on any iterable (list, tuple, generator, `range`, dict views, custom collections).
- **Memory-aware** — distinguish eager (reifying a list) from lazy (iterators/generators); choose deliberately.
- **Self-documenting** — `enumerate(items)` communicates "I need indices", `any(x>3 for x in vals)` reads as declarative logic.

## `len(obj)` — Size

```python
print(len([1, 2, 3]))       # 3
print(len("hello"))         # 5 — counts Unicode code points, not bytes (see text lesson)
print(len({"a": 1, "b": 2}))# 2 — number of keys
print(len({1, 2, 3}))       # 3
print(len(range(10)))       # 10 — O(1), lazy
print(len((x for x in range(5))))  # TypeError: object of type 'generator' has no len()
# Generator has no length; use consume or islice

# The dunder: len(x) → x.__len__() which must be int >= 0
class SizedA:
    def __len__(self): return 42
print(len(SizedA()))        # 42

# Truthiness uses __len__ (fallback) or __bool__
# bool([]) -> len==0 -> False; bool([0]) -> len!=0 -> True even though inner 0 is falsy
print(bool([]), bool([0]))  # False True

# Idiom: use len checks indirectly via truthiness
# if lst: ... means "if len(lst) != 0" but faster + more Pythonic than "if len(lst)>0"
# For generators: you cannot len() — test with try/next or list conversion.
```

## `sum(iterable, /, start=0)` — Aggregation

```python
print(sum([1, 2, 3]))       # 6
print(sum(range(5)))        # 10
print(sum([0.1, 0.2]))      # 0.300... — floating accumulation (binary)
print(sum(["a", "b", "c"])) # no — TypeError; see concatenation note
print(sum([1, 2, 3], start=10))  # 16 — start added as initial accumulator

# start type governs accumulation type:
print(sum([1.0, 2.0], start=0))  # 3.0
# Realistic: dot product, weighted sum
print(sum(x*x for x in range(5)))  # 30

# Gotcha: don't sum strings with `sum(['a','b'], "")` — O(n^2) concatenation
# `sum` concatenates with `start + items[0] + ...` using `+` per item -> quadratic on str/bytes/lists.
# Correct: ''.join(["a","b","c"]) is linear.
print("".join(["a", "b", "c"]))  # 'abc'
# For lists: sum([[1,2],[3,4]], []) is also quadratic if many lists
# Better: itertools.chain or comprehension

# Also: math.fsum for precise float sum (compensation); statistics.fsum variant
import math
print(math.fsum([0.1]*10))  # 1.0 — more accurate than sum([0.1]*10) may be
```

## `min(iterable)` / `max(iterable)` — With `key` and `default`

```python
# Basic — any iterable; uses natural ordering (comparable elements)
print(min([3, 1, 2]))       # 1
print(max("cba"))           # 'c'
print(min({"a": 5, "b": 2}))# 'a' — dict iterates keys; compares strings -> "a" wins (lexicographically smaller)

# With key — transformative comparison (evaluated once per element)
words = ["banana", "Apple", "cherry", "BANANA"]
print(min(words, key=str.lower))        # 'Apple' — comparison key is 'apple' < 'banana'
print(max(words, key=len))              # 'banana' or 'cherry' (length 6)
print(min(words, key=lambda w: (len(w), w.lower())))  # tie-break with tuple key

# Realistic: find user with max score
from dataclasses import dataclass
@dataclass
class User:
    name: str
    score: int

users = [User("Alice", 90), User("Bob", 95), User("Carol", 85)]
print(max(users, key=lambda u: u.score).name)  # 'Bob'
# Without key you'd need __lt__ overloads; key is easier than defining ordering

# Two signatures — single iterable vs multiple arguments
print(min(3, 1, 2))         # 1 — min(arg, *args)
print(min([3,1,2]))         # 1 — min(iterable)
# Default — returned when iterable is empty; otherwise would raise ValueError
print(min([], default=None))     # None — do not need a try/except
print(min([], key=len, default="empty"))  # 'empty'
# try to avoid default such that: min([], key=str.lower) still raises KeyError propagation? key() returning bad types will propagate
# If using multiple-args form, default is NOT valid.

# Pitfalls:
# 1. Unequal-type elements not comparable — raises TypeError
# min([1, "a"])             # TypeError
# 2. NaN handling — nan != nan, max involving nan is not intuitive: min([float('nan'), 1.0]) may be nan or 1.0 depending... treat NaN externally
# 3. `key` function is computed once per element (like sorting), not per comparison
```

## `sorted(iterable, *, key=None, reverse=False)` vs `list.sort()`

| Feature | `sorted(iterable)` | `list.sort()` |
|---|---|---|
| Works on | Any iterable (creates iterator) | Only `list` |
| Returns | **New list** (copy, sorted) | `None` (mutates in place) |
| Original | Unchanged | Mutated |
| Parameters | `key`, `reverse` | Same |
| Algorithm | Timsort (stable), O(n log n) | Same — but in place |
| Memory | O(n) for new list | In-place (extra O(n) working space) |

```python
nums = [3, 1, 2]
print(sorted(nums))         # [1, 2, 3] — nums unchanged
print(nums)                 # [3, 1, 2]
nums.sort()                 # nums itself is now [1, 2, 3]
print(nums.sort())          # None — do not assign: "nums is now None" bug

# key is identically the key from list.sort; see 2.1 for stable sort details
words = ["banana", "Apple", "cherry"]
print(sorted(words, key=str.lower))        # ['Apple','banana','BANANA','cherry']
print(sorted(words, key=str.lower, reverse=True))

# sorted returns list even if input is not — tuple, set, range, generator
print(sorted({3, 1, 2}))    # [1, 2, 3] — always list
print(sorted("cba"))        # ['a','b','c'] — chars as list
print(sorted((3, 1, 2)))    # [1, 2, 3] — from tuple

# Idiomatic one-liners
print(sorted(users, key=lambda u: u.score))     # top student logic
# Stable-sort trick: sort by name then age
# students.sort(key=lambda s: s[0]); students.sort(key=lambda s: s[1]) still works via stable property
```

## `reversed(seq)` — Lazy Reverse Iterator

```python
lst = [1, 2, 3]
print(list(reversed(lst)))  # [3, 2, 1] — no copy until iterated
print(type(reversed(lst)))  # <class 'list_reverseiterator'> — lazy

# Works only on sequences exposing __reversed__ or __getitem__/__len__
# Strings: reversed("abc") yields chars, not string
print("".join(reversed("abc")))  # 'cba'
# Tuple likewise
print(tuple(reversed((1, 2, 3))))  # (3, 2, 1) — need explicit tuple()

# Contrast with slicing:
# lst[::-1] -> new list, allocates eagerly (shallow copy)
# reversed(lst) -> iterator, no allocation until consumed
# Choose based on whether you need a concrete sequence immediately or streaming iteration

# Raises TypeError on unordered iterables (set, dict with views iteration counts as? Actually dict is ordered now, but reversed(dict) is allowed since 3.8):
print(list(reversed({"a": 1, "b": 2})))  # ['b','a'] — since dict is reversible (3.8+)
# print(list(reversed({1,2,3})))  # TypeError: 'set' object is not reversible — random order, no reversal semantics
```

## `enumerate(iterable, start=0)` — Index + Value

The Pythonic replacement for `range(len(lst))` anti-pattern.

```python
lst = ["a", "b", "c"]
for i, val in enumerate(lst):
    print(i, val)           # 0 a / 1 b / 2 c
print(list(enumerate(lst))) # [(0,'a'), (1,'b'), (2,'c')]

# start parameter — often forgotten; perfect for human-numbered output
for num, line in enumerate(lst, start=1):
    print(f"{num:02}: {line}")
# With strings:
print(list(enumerate("abc", start=0)))  # [(0,'a'), ...]

# Destructure with dict items:
d = {"a": 1, "b": 2}
for i, (k, v) in enumerate(d.items(), start=1):
    print(f"{i}. {k}={v}")

# Performance & readability: enumerate runs in C; avoids range(len(...)) with redundant indexing
# Anti-pattern:
# for i in range(len(lst)):
#     val = lst[i]   # slow, verbose
# Idiomatic:
# for i, val in enumerate(lst):

# Unpacking partial enumerate with `*`
first_idx, *rest = enumerate(["x", "y"])  # first_idx=(0,'x'); rest=[(1,'y')]
print(first_idx, rest)

# Edge: enumerate over a dict gives (idx, key) pairs because dict iterates keys
print(list(enumerate({"a":1,"b":2})))     # [(0,'a'), (1,'b')]
```

## `zip(*iterables)` — Parallel Iteration, and `zip(..., strict=True)` (3.10+)

`zip` truncates to the shortest iterable by default (silent data-loss risk). `strict=True` makes unequal lengths raise `ValueError`.

```python
xs = [1, 2, 3]
ys = ["a", "b", "c"]
print(list(zip(xs, ys)))    # [(1,'a'), (2,'b'), (3,'c')]

# Mismatched lengths — truncation (no error, silent bug source)
print(list(zip([1, 2, 3], ["a", "b"])))   # [(1,'a'), (2,'b')] — third item silently lost!
print(list(zip([1, 2], ["a", "b", "c"]))) # [(1,'a'), (2,'b')]

# Three+ iterables
print(list(zip([1,2], ["a","b"], [True, False])))  # [(1,'a', True), (2,'b', False)]

# Transpose — the zip(*matrix) idiom
matrix = [(1, 2, 3), (4, 5, 6)]
print(list(zip(*matrix)))   # [(1, 4), (2, 5), (3, 6)] — columns

# zip is lazy — returns iterator, not list. Wrap with list() to materialize.
# Large parallel iteration without materializing is efficient:
# for a, b in zip(huge_a, huge_b): ...

# Using with enumerate to pair index with multiple sequences:
xs = [10, 20]; ys = [1, 2]
for i, (x, y) in enumerate(zip(xs, ys), start=1):
    print(i, x, y)
```

### `strict=True` (Python 3.10) — New and Recommended

```python
# Silently truncating is often a bug (e.g., CSV columns mismatch, config misalignment)
# strict=True forces the caller to guarantee equal length

try:
    list(zip([1, 2, 3], ["a", "b"], strict=True))   # ValueError
except ValueError as e:
    print("caught:", e)  # zip() argument lengths differ (3 vs 2)

print(list(zip([1, 2], ["a", "b"], strict=True)))  # ok — equal lengths

# Also works for 3+ args:
# zip(a, b, c, strict=True) checks all lengths are equal

# Practical rule: If input sequences SHOULD be paired 1-1, pass strict=True.
# If zip truncation to shortest is *intended*, keep default but consider commenting why:
# for k, v in zip(keys, maybe_longer_vals):  # intentionally truncates? Do you know?

# Alternative pre-3.10: manual assertion
# assert len(a) == len(b), f"length mismatch {len(a)} vs {len(b)}"
# for x, y in zip(a, b): ...

# Realistic: parsing aligned records
names = ["Alice", "Bob"]
scores = [95, 87]
ids = [1, 2, 3]             # misaligned data — silent corruption without strict
# print(list(zip(names, scores, ids)))              # [(Alice,95,1), (Bob,87,2)] — id 3 lost
# print(list(zip(names, scores, ids, strict=True)))  # ValueError — catches bug
```

### `itertools.zip_longest` — Companion

```python
from itertools import zip_longest
# Fill missing with fillvalue=None by default, not truncate
print(list(zip_longest([1,2,3], ["a","b"], fillvalue="?")))  # [(1,'a'), (2,'b'), (3,'?')]
```

## `any(iterable)` / `all(iterable)` — Logical Reduction

Both are **short-circuit** — they stop iterating as soon as the answer is known, just like `or`/`and` across elements.

```python
print(any([False, 0, "", None, 0.0]))   # False — all falsy -> False
print(any([False, True, False]))        # True
print(all([1, 2, "yes", []]))           # False — last falsy [] makes all False
print(all([]))                          # True — "vacuously true" (no counterexample) — GOTCHA
print(any([]))                          # False — "vacuously false"

# Common with generator expressions:
nums = [1, 5, 3, 10]
print(any(x > 9 for x in nums))         # True — stops once 10 found
print(all(x > 0 for x in nums))         # True

# Equivalent without built-ins:
# any(gen)  == exists x in gen: bool(x)
# all(gen)  == for_all x in gen: bool(x)
# Using them lazy is important for generators: the generator stops yielding after predicate decided
# (especially relevant if iteration has side effects)

# Realistic: file validation
words = ["hello", "world", "Hi"]
print(any(w.isupper() for w in words))  # False — any word all caps?
print(all(len(w) >= 2 for w in words))  # True — all words length >=2?

# Pitfall: generator expression needs parentheses; don't materialize a list unnecessarily:
# any([x > 3 for x in huge]) builds a huge intermediate list; any(x > 3 for x in huge) streams
```

> **Edge with `all([])` / `any([])`:** Remember vacuous truth. `all([])` being `True` surprises many; if your guard is "all elements satisfy condition X", then no elements satisfies it vacuously. If you wanted "some elements exist and all satisfy X", write `if items and all(c for c in items):`.

## `filter(function, iterable)` / `map(function, iterable)` vs Comprehensions

Both return **lazy iterators** (not lists; wrap with `list()` to materialize). In modern Python, list/dict/set comprehensions and `filter`/`map` compete; comprehensions usually win on readability for simple cases, but `map`/`filter` are indispensable for function reuse and with `itertools`.

### `map(func, *iterables)` — Apply Function to Each Element

```python
# map(f, iter) applies f to each element (or zip(*) then apply if multiple iters)
print(list(map(str.upper, ["hello", "world"])))  # ['HELLO', 'WORLD']
print(list(map(len, ["a", "bb", "ccc"])))        # [1, 2, 3]
print(list(map(pow, [2,3,4], [3,2,1])))         # [8, 9, 4] -> pow(2,3), pow(3,2), pow(4,1)
# `map` stops at shortest iterable when given multiple (like zip)

# Exact comprehension equivalent (single iterable):
# map(f, seq) == (f(x) for x in seq)
print([str.upper(x) for x in ["hello", "world"]])  # comprehension alternative
# Which is faster? map(f, seq) marginally faster when f is a simple built-in;
# comprehension catches up when the expression is simple. Prefer readability claims.

# `map` with lambda vs comprehension:
# map(lambda x: x*x, range(5)) vs [x*x for x in range(5)] — comprehension wins on readability

# Realistic: process lines
raw = ["1", "2", "3"]
print(list(map(int, raw)))  # [1, 2, 3]

# With multiple iterables: legacy but clear that zip semantics applies
xs = [1, 2, 3]
ys = [10, 20, 30]
print(list(map(lambda a,b: a+b, xs, ys)))  # [11, 22, 33] -> map applies to paired tuples
# Same as: [a+b for a,b in zip(xs, ys)]
```

### `filter(func, iterable)` — Keep Elements Where Predicate Truthy

```python
# filter(pred, iter) yields those elements where pred(elem) is truthy; if pred is None, identity filter.
print(list(filter(lambda x: x % 2 == 0, range(6))))  # [0,2,4]
# Equivalence: [x for x in range(6) if x % 2 == 0]
# Counter: x%2==0  vs explicit if

# None predicate — keeps elements whose truth value is truthy (removes falsy)
print(list(filter(None, [0, 1, False, "", "hi", [], [1]])))  # [1, 'hi', [1]]

# Realistic: drop None values
items = [1, None, 2, None, 3]
print(list(filter(None, items)))        # [1, 2, 3] — drops None and other falsy
# Safer drop-only-None: filter(lambda x: x is not None, items) preserves 0/empty/""
print(list(filter(lambda x: x is not None, [0, None, ""])))  # [0, ""] — 0 kept

# If predicate is a simple callable, filter can be faster than comprehension on large iterables;
# however code review/readability prefers comprehensions in new code.
```

### Comparisons — When Each Is Idiomatic

| Criterion | Comprehension / genexp | `map` / `filter` |
|---|---|---|
| Readability | Best for expressions (`x*x`, `x if c else y`) | Best when a **named function** exists (no lambda) |
| With `lambda` | Avoid `map(lambda ...)` if `[f(x) for x...]` reads better | Lambda + map is considered un-Pythonic by many |
| Lazy | genexp: `(f(x) for x in seq)` is lazy | Both are lazy iterators always |
| Use with `itertools` | mixing styles | `map` is an `itertools` primitive (fast C loop) |
| 2+ iterables | `zip` inside comprehension | `map` handles multi-iter directly |
| Empty case | List comp creates `[]`, genexp lazy empty | Both produce empty iterator |

> **Rule of thumb for this course:** Use comprehensions/genexps as the default; use `map`/`filter` when a function object already expresses the intent clearly — e.g., `map(str, nums)`, `map(int, strs)`, `filter(None, seq)`.

## `collections.Counter` — Frequency Table

A `dict` subclass optimized for counting.

```python
from collections import Counter

# Construction from iterable or mapping or kwargs
print(Counter("abracadabra"))           # Counter({'a':5, 'b':2, 'r':2, ...})
print(Counter([1, 2, 1, 1, 3]))        # Counter({1:3, 2:1, 3:1})
print(Counter({"a": 3, "b": 1}))       # Counter({'a':3,'b':1}) — from mapping
print(Counter(a=3, b=1))               # via kwargs

# Access returns 0 for missing — never raises (like defaultdict(int) for read)
c = Counter("abc")
print(c["a"], c["z"])                   # 1 0

# Core methods:
c = Counter("hello world")
print(c.most_common(3))                 # [('l', 3), ('o', 2), ('h', 1)] — sorted by count desc
print(c.most_common())                  # fully sorted
print(list(c.elements()))               # ['h','e','l','l','l','o', ...] — expands counts (order most_common)
print(c.total())                        # 11 — sum of all counts (3.10+)

# Arithmetic (counter | counter semantics differ from dict)
a = Counter(a=2, b=1, c=0)
b = Counter(a=1, b=2)
print(a + b)                            # Counter({'a':3,'b':3}) — sum
print(a - b)                            # Counter({'a':1}) — positive-only (subtract min-zero)
print(a & b)                            # intersection: Counter({'a':1,'b':1}) — min counts
print(a | b)                            # union: Counter({'a':2,'b':2}) — max counts (probabilistic)

# Dict core still present: keys() -> Counter keys, values() -> counts, items() -> (elem,count)
for elem, cnt in c.most_common():
    print(elem, cnt)

# Gotcha: 0 and negative counts are kept after arithmetic where operation allows
c = Counter(a=1)
c.subtract({"a": 2})                    # c['a'] == -1 — persists!
print(list(c.items()))                  # includes negatives
c_positive = +c                         # prune non-positive (+c trick)
print(c_positive)                       # Counter() empty — keeps only >0
# For pure counts-only usage, keep counts non-negative; Counter doesn't enforce.

# Realistic: bag intersection for word counts
words1 = Counter("python is great Great".lower().split())
words2 = Counter("great python".split())
print(words1 & words2)                  # overlap bag
print(words1.most_common(1))            # most frequent word
```

## `collections.defaultdict` — Auto-Initializing Dict

A `dict` subclass with `_missing_` hooked to a **factory** callable.

```python
from collections import defaultdict

# Vector-of-values grouping — canonical use
groups = defaultdict(list)              # factory: () -> []
groups["fruits"].append("apple")        # no existence check needed
groups["fruits"].append("banana")
groups["vegetables"].append("carrot")
print(dict(groups))                     # {'fruits':['apple','banana'], 'vegetables':['carrot']}
print(groups["spices"])                 # [] — key auto-created on read (also via __getitem__)
print(dict(groups))                     # {'fruits':..., 'vegetables':..., 'spices': []}

# Other factories:
counts = defaultdict(int)               # missing -> 0
is_seen = defaultdict(bool)             # missing -> False
nested = defaultdict(dict)              # missing -> {}
# Factory may be custom:
def factory(): return {"count": 0, "items": []}
dd = defaultdict(factory)
dd["key"]["count"] += 1
print(dd["key"])

# Pitfall: defaultdict factory is called ONLY on __getitem__ (d[key]), NOT on .get()
d = defaultdict(int)
print(d.get("missing"))                 # None — NOT 0; no insertion
print(d.get("missing", 99))             # 99
print("missing" in d)                   # False — get() doesn't trigger factory
# Access via subscription does:
print(d["missing"])                     # 0 — inserted!

# Default factory can be None — then defaultdict behaves like plain dict (KeyError on miss)
# And with mutable default: each key gets its OWN fresh object from factory (unlike fromkeys([]))
# That's the whole point — no shared-mutable aliasing

# Pitfall: serialization / passing to other APIs
# Many libraries test isinstance(d, dict) which passes; but json.dumps accepts it; however,
# defaultdict that passes itself transitively encodes fine. To remove default behavior, cast: dict(dd)
# For copy/interplay: defaultdict shares all dict methods.

# Idiomatic vs dict.setdefault equivalence:
# defaultdict(list):      dd[key].append(x)
# plain dict:             d.setdefault(key, []).append(x)
# defaultdict is slightly faster and clearer when grouping repeatedly.
```

## `collections.deque` — Deque for Efficient Ends

A double-ended queue as a `MutableSequence`, optimal for popleft/insert-left.

```python
from collections import deque

# Construction — deque(iterable, maxlen=None)
dq = deque([1, 2, 3])
print(dq)                   # deque([1, 2, 3])

# Core ops — O(1) both ends, unlike list where front ops are O(n)
dq.append(4)                # add right — O(1)
dq.appendleft(0)            # add left — O(1)
print(dq)                   # deque([0, 1, 2, 3, 4])
print(dq.pop())             # 4 — remove right
print(dq.popleft())         # 0 — remove left — the star operation (list.pop(0) is O(n))
print(dq)                   # deque([1, 2, 3])

# Other rotation and length invariants:
dq = deque([1, 2, 3, 4])
dq.rotate(1)                # rotate right: [4, 1, 2, 3]
print(dq)
dq.rotate(-1)               # back to [1,2,3,4]
print(dq)

# Bounds:
print(len(dq))              # 4 — O(1)
print(dq[2])                # 3 — indexing allowed but O(n) mid-access (linked block proxy)
# Iteration, membership, `in` are O(n); deque is primarily for queue/stack at ends

# Bounded deque — circular buffer with maxlen
window = deque(maxlen=3)    # auto-evicts oldest when full
for x in [1, 2, 3, 4, 5]:
    window.append(x)
    print(window)           # deque([3,4,5]) after buffer fills
# Realistic: sliding window, tail of file

# When to use:
# - Queue FIFO: append() / popleft() — deque is correct; list+pop(0) is slow quadratically
# - Stack LIFO: either list (push/pop right) or deque; list slightly faster for pure stack
# - Sliding maxlen window: deque(maxlen=n) is the idiomatic circular buffer

# Traps:
# - Do not use deque for random access in hot loops (list is contiguous + O(1) indexing; deque is not)
# - sorted(deque(...)) works (consumes via iteration); d.count/d.index exist
```

## Realistic Examples — Putting Built-Ins Together

```python
# 1. CSV-like header-row workflow
headers = ["name", "age", "city"]
rows = [
    ("Alice", "30", "NYC"),
    ("Bob",   "25", "SF"),
]
records = [dict(zip(headers, row, strict=True)) for row in rows]
print(records)  # [{'name':'Alice','age':'30','city':'NYC'}, {...}]

# 2. Find cheapest product with key
from dataclasses import dataclass
@dataclass
class Product:
    name: str
    price: float
    stock: int

catalog = [Product("A", 12.5, 10), Product("B", 5.0, 0), Product("C", 7.5, 3)]
cheapest = min(catalog, key=lambda p: p.price)
print(cheapest.name)        # 'B'
# Exclude out-of-stock from consideration with filter + min
available = filter(lambda p: p.stock > 0, catalog)
cheapest_available = min(available, key=lambda p: p.price)
print(cheapest_available.name)  # 'C' or 'A' depending cheapest in stock

# 3. Group by category using defaultdict + iteration
from collections import defaultdict, Counter
sales = [("fruit", "apple"), ("fruit", "banana"), ("veg", "carrot"), ("fruit", "apple")]
by_cat = defaultdict(list)
for cat, item in sales: by_cat[cat].append(item)
print(dict(by_cat))         # {'fruit':['apple','banana','apple'], 'veg':['carrot']}
# Count per category
freq = Counter(cat for cat, _ in sales)
print(freq)                 # Counter({'fruit':3,'veg':1})

# 4. Sliding average with deque(maxlen)
from collections import deque
import math
window = deque(maxlen=3)
avgs = []
for x in [10, 20, 30, 40]:
    window.append(x)
    avgs.append(sum(window)/len(window))
print(avgs)                 # [10, 15, 20, 35? wait: [10,15,20,30]??? check: [10],[10,20]->15,[10,20,30]->20,[20,30,40]->30

# 5. Sorting by multiple keys via key tuple
words = ["banana", "Apple", "cherry", "apricot"]
print(sorted(words, key=lambda w: (len(w), w.lower())))  # length primary, alphabetic secondary
# Tie-breaking with negate for descending numeric: (-score, name)
scores = [("Alice", 92), ("Bob", 92), ("Carol", 85)]
print(sorted(scores, key=lambda p: (-p[1], p[0])))  # Carol? Actually Alice,Bob both 92 -> alphabetical tie-break
# Produces: [('Alice',92),('Bob',92),('Carol',85)] — -92 < -85 so descending price, secondary key asc.

# 6. Any/All with short-circuit for validation
config = {"port": 8080, "host": "local", "debug": False}
required = {"port", "host"}
print(all(k in config for k in required))   # True
print(any(v == "" for v in config.values()))  # False — any empty

# 7. Filtering None and grouping — combining filter, enumerate, Counter
raw_counts = {"a": 3, "b": 0, "c": 5}
nonzero = {k: v for k, v in raw_counts.items() if v}  # dict comp filtering falsy counts
print(nonzero)
# map/str join: join filtered non-empty names with commas
names = ["  alice ", "", "bob  "]
clean = ",".join(s.strip() for s in names if s.strip())
print(clean)                # 'alice,bob'

# 8. Using zip(strict=True) for safe parallel mutation
cols_a = [1, 2, 3]
cols_b = [4, 5, 6]
for a, b in zip(cols_a, cols_b, strict=True):
    assert a+b > 0
```

## Pitfalls and Anti-Patterns

```python

# 2. Materializing generator just to discard it
# Bad: any([x > 3 for x in huge]) — builds a huge list of booleans then short-circuits
```

## Summary

- `len` is O(1) via `__len__`; generators have no length — use iteration.
- `sum` aggregates with `start`; never use it for string/list concatenation (use `str.join` / `itertools.chain`).
- `min`/`max` accept `key=` and `default=` — apply transformation once per element and handle empties without `try`.
- `sorted(xs, key=..., reverse=...)` returns a new Timsort-stable list; `xs.sort()` mutates in place.
- `reversed(seq)` is a lazy backward iterator — zero-copy alternative to `seq[::-1]`.
- `enumerate(iter, start=0)` pairs `(index, value)` — the idiomatic substitute for `range(len(...))`.
- `zip(*iters)` truncates to shortest — pass `strict=True` (Python 3.10+) to turn silent data loss into a `ValueError`; `zip_longest` fills.
- `any`/`all` over generator expressions short-circuit; recall vacuous truth `all([]) == True`.
- `filter`/`map` are lazy; modern Python favors comprehensions/genexps, reserving `map`/`filter` for pre-existing function objects.
- `collections.Counter` is a specialized counting dict (`most_common`, bag arithmetic, zero on missing); `defaultdict` supplies per-missing-key factories; `deque` gives O(1) `appendleft`/`popleft` and `maxlen` circular buffers.

Lean on built-ins — they are faster, protocol-uniform, and read as intent.
