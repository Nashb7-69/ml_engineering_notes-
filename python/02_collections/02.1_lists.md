# 2.1 Lists

Python's `list` is the workhorse collection — a mutable, ordered, heterogeneous dynamic array. If you come from C++ (`std::vector`), Java (`ArrayList`), JavaScript (Array), or Go (slice), you will feel at home, but Python lists have semantics and idioms that deserve precise understanding.

## What a List Is (and Is Not)

A Python `list` is:

- **Ordered** — elements have a defined position, `0` to `len-1`, preserved across operations.
- **Mutable** — you can change, add, or remove elements in place; the object identity stays the same.
- **Heterogeneous** — any mixture of types and objects, including other lists.
- **Dynamic array** — backed by a contiguous over-allocated array of `PyObject*` pointers (CPython). Appending is amortized O(1); insertion/deletion in the middle is O(n) due to shifting.
- **Reference semantics** — the list stores *references* to objects, not copies.

```python
# Heterogeneous, nested, mutable
mixed = [1, "hello", 3.14, None, [1, 2], {"a": 1}]
mixed[1] = "world"          # mutation in place
mixed.append(lambda x: x)
print(mixed)                # list identity unchanged
print(id(mixed))
```

> **Mental model:** A list is an array of pointers. `a = [obj1, obj2]` does not copy `obj1`/`obj2`; it stores pointers. Multiple lists can point to the same objects.

## Construction

### Literal Syntax

```python
empty = []                  # idiomatic empty list
numbers = [1, 2, 3]
# Trailing comma is legal and encouraged for multiline literals and diffs
weekdays = [
    "Monday",
    "Tuesday",
    "Wednesday",
]
```

### The `list()` Constructor

`list(iterable)` creates a new list from any iterable, copying its elements.

```python
print(list("abc"))          # ['a', 'b', 'c'] — iterates the string
print(list((1, 2, 3)))      # [1, 2, 3] — from tuple
print(list({"a": 1, "b": 2}))  # ['a', 'b'] — iterates keys
print(list(range(5)))       # [0, 1, 2, 3, 4]
print(list())               # [] — same as []
```

> **Pitfall:** `list` expects at most one argument (an iterable). `list(1)` raises `TypeError`. To create a single-element list, use `[1]`, not `list(1)`.

### List Multiplication and Repetition

```python
zeros = [0] * 5             # [0, 0, 0, 0, 0]
pattern = [1, 2] * 3        # [1, 2, 1, 2, 1, 2]
```

This repeats *references* — safe for immutables (`int`, `str`, `tuple`) but dangerous for mutables (see § Pitfall below).

### Comprehension (Preview)

```python
squares = [x*x for x in range(6)]   # [0, 1, 4, 9, 16, 25]
```

Comprehensions are covered fully in 2.7; note that `[expr for ...]` builds a new list efficiently in C.

## Core Operations

| Operation | Example | Time | Notes |
|---|---|---|---|
| Length | `len(lst)` | O(1) | Stored field, not counted |
| Indexing | `lst[i]`, `lst[-1]` | O(1) | Negative = from end |
| Slicing | `lst[a:b:c]` | O(k) | Returns *new* list (shallow copy) |
| Membership | `x in lst` | O(n) | Linear scan, uses `==` |
| Concatenation | `a + b` | O(n+m) | New list |
| Repetition | `lst * n` | O(n*k) | Shallow repetition |
| Iteration | `for x in lst:` | O(n) | Uses iteration protocol |

## Methods — Complete Reference

### Modifying Methods

#### `append(x)` — Append One Element

```python
lst = [1, 2]
lst.append(3)               # [1, 2, 3]
lst.append([4, 5])          # [1, 2, 3, [4, 5]] — appends as single element
print(lst)
```

- Amortized O(1). Occasionally triggers resize (growth factor ~1.125x in CPython 3.9+).
- **Distinguish from `extend`:** `append` adds one object; `extend` iterates.

#### `extend(iterable)` — Append Many

```python
lst = [1, 2]
lst.extend([3, 4])          # [1, 2, 3, 4]
lst.extend("ab")            # [1, 2, 3, 4, 'a', 'b'] — string is iterable!
lst.extend({"x": 1})        # extends with keys: [..., 'x']

# Equivalent to:
# for item in iterable: lst.append(item)
# But implemented in C, far faster.

# Common idiom: flatten one level
# += is syntactic sugar for extend when LHS is a list
lst = [1, 2]
lst += [3, 4]               # same as extend, but rebinds? For lists, it mutates in place (calls __iadd__).
```

> **Common mistake:** `lst.append([3,4])` vs `lst.extend([3,4])`. The first nests, the second flattens.

#### `insert(i, x)` — Insert at Position

```python
lst = ["a", "c", "d"]
lst.insert(1, "b")          # ['a', 'b', 'c', 'd']
lst.insert(0, "start")      # prepend — O(n)
lst.insert(100, "end")      # if i >= len, inserts at end (no error)
lst.insert(-1, "penult")    # inserts before -1 position
print(lst)
```

- O(n): shifts elements to the right.
- Frequent insertions at the front → use `collections.deque`.

#### `remove(x)` — Remove First Occurrence by Value

```python
lst = [1, 2, 3, 2, 4]
lst.remove(2)               # [1, 3, 2, 4] — only first 2
# lst.remove(99)            # ValueError if not found
```

- Linear search + shift → O(n).
- Raises `ValueError` if absent — guard with `if x in lst` or `try/except`.

#### `pop([i])` — Remove and Return by Index

```python
lst = [10, 20, 30, 40]
print(lst.pop())            # 40 — last element, O(1)
print(lst.pop(0))           # 10 — first, O(n) shift
print(lst.pop(-1))          # same as pop()
print(lst)                  # [20, 30]
# lst.pop(100)              # IndexError
```

- Default `pop()` with no argument is O(1) — ideal for stack.
- `pop(i)` is O(n) for `i` not at the end.

#### `clear()` — Remove All

```python
lst = [1, 2, 3]
lst.clear()                 # [] — same as del lst[:], but clearer
# Equivalent to lst[:] = [] but keeps same object.
```

#### `sort(*, key=None, reverse=False)` — In-Place Stable Sort

Covered in depth below.

#### `reverse()` — In-Place Reversal

```python
lst = [1, 2, 3]
lst.reverse()               # [3, 2, 1] — O(n), in place
# Contrast with reversed(lst) which returns an iterator, and lst[::-1] which returns a new list.
```

#### `copy()` — Shallow Copy

```python
a = [1, [2, 3]]
b = a.copy()                # shallow: same as a[:] or list(a) or copy.copy(a)
b[0] = 99                   # a unaffected
b[1].append(4)              # a[1] also sees [2, 3, 4]! shared inner list
print(a)                    # [1, [2, 3, 4]]
```

See Lesson 2.8 for deep vs shallow.

### Non-Modifying Operations

```python
lst = [1, 2, 3, 2]

print(lst.count(2))         # 2 — O(n)
print(lst.index(2))         # 1 — first occurrence, O(n)
print(lst.index(2, 2))      # 3 — search starting at index 2
# lst.index(99)             # ValueError if absent
```

## Sorting — Deep Dive

### Basic Sort

```python
nums = [3, 1, 4, 1, 5, 9]
nums.sort()                 # [1, 1, 3, 4, 5, 9] ascending, in place
print(nums)

words = ["banana", "apple", "cherry"]
words.sort(reverse=True)    # descending
print(words)
```

- `list.sort()` sorts in place and returns `None` (a Python convention: mutating methods return `None` to avoid confusion with functional style). Do **not** write `lst = lst.sort()`.
- `sorted(iterable)` built-in returns a *new* sorted list, works on any iterable.

```python
orig = [3, 1, 2]
new = sorted(orig)          # orig unchanged, new is sorted
print(orig, new)
# sorted accepts same key/reverse arguments
```

### The `key` Parameter — Most Important Feature

`key` is a function called *once per element*; the return value is used for comparison. This is the Schwartzian transform (decorate-sort-undecorate) done for you in C.

```python
# Case-insensitive sort
words = ["banana", "Apple", "cherry"]
print(sorted(words, key=str.lower))        # ['Apple', 'banana', 'cherry']
print(sorted(words, key=str.casefold))     # better for Unicode

# Sort by length, then alphabetically? Use tuple key or stable sort (see below)
print(sorted(words, key=lambda w: (len(w), w.lower())))

# Sort objects by attribute
from dataclasses import dataclass

@dataclass
class User:
    name: str
    age: int

users = [User("Alice", 30), User("Bob", 25), User("Carol", 30)]
by_age = sorted(users, key=lambda u: u.age)
print(by_age)

# Expensive key? It is called exactly once per element, not per comparison.
# Sort by expensive computation without recomputing:
import math
nums = [5, 2, 10]
# key computed O(n), not O(n log n)
print(sorted(nums, key=lambda x: math.factorial(x)))  # contrived but illustrates
```

> **Mistake to avoid:** `sort(key=func())` — calling the function. You must pass the function object: `key=func`.

### Stable Sort — The Secret Weapon

Python's sort (Timsort) is **stable**: when multiple records have the same key, their original order is preserved. This enables multi-pass sorting.

```python
# Sort by age, then by name — two valid approaches:

# Approach 1: tuple key (single pass, most common)
students = [("Alice", 30), ("Bob", 25), ("Carol", 30), ("Dave", 25)]
print(sorted(students, key=lambda s: (s[1], s[0])))

# Approach 2: stable sort twice (least significant key first)
# Sort by name first, then by age — age sort preserves name order within same age
students.sort(key=lambda s: s[0])   # secondary key: name
students.sort(key=lambda s: s[1])   # primary key: age — stability keeps name order
print(students)                      # [('Bob', 25), ('Dave', 25), ('Alice', 30), ('Carol', 30)]

# Realistic: sort transactions by timestamp, then by amount using stable sort
```

### `reverse` Parameter

```python
# Descending by key
print(sorted([3, 1, 2], reverse=True))                  # [3, 2, 1]
# Key + reverse: sort longest first
print(sorted(words, key=len, reverse=True))
```

For complex reverse logic (e.g., ascending one field, descending another), negate numeric keys or sort twice leveraging stability:

```python
# Sort by score descending, name ascending
records = [("Alice", 90), ("Bob", 90), ("Carol", 85)]
# Tuple trick: negate score for descending numeric
print(sorted(records, key=lambda r: (-r[1], r[0])))
```

### Sorting Pitfalls

```python
# 1. Heterogeneous types that cannot be compared
# sorted([1, "a"])  # TypeError: '<' not supported between 'int' and 'str'

# 2. sort() returns None — classic bug
lst = [3, 1, 2]
result = lst.sort()
print(result)               # None — lst is sorted, result is not the list

# 3. key function must be total and not mutate
# 4. For custom ordering beyond key, use functools.cmp_to_key
from functools import cmp_to_key

def cmp(a, b):
    return (a > b) - (a < b)  # old-style comparator

print(sorted([3, 1, 2], key=cmp_to_key(cmp)))
```

## List as Stack and Queue

### Stack (LIFO) — Perfect Fit

```python
stack = []
stack.append("a")           # push
stack.append("b")
print(stack.pop())          # 'b' — pop, O(1) both
print(stack)                # ['a']

# Realistic: DFS, undo, expression evaluation
def is_balanced(s: str) -> bool:
    stack = []
    pairs = {")": "(", "]": "[", "}": "{"}
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in ")]}":
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

print(is_balanced("([{}])"))   # True
```

### Queue (FIFO) — Don't Use List

```python
queue = []
queue.append("a")           # enqueue
queue.append("b")
print(queue.pop(0))         # 'a' — dequeue, but O(n)! shifts all elements

# For queues, use collections.deque — O(1) popleft
from collections import deque

dq = deque()
dq.append("a")
dq.append("b")
print(dq.popleft())         # 'a' — O(1)
print(dq)
```

> **Rule:** Need `pop(0)` or `insert(0, ...)` repeatedly → `deque`.

## Aliasing — The Shared-Reference Trap

```python
# Assignment does NOT copy
a = [1, 2, 3]
b = a                       # b and a point to same list object
b.append(4)
print(a)                    # [1, 2, 3, 4] — surprise!

# Identity vs equality
print(a is b)               # True — same object
print(a == b)               # True — equal contents

# Copy to get independence
c = a.copy()                # or a[:] or list(a)
c.append(5)
print(a)                    # [1, 2, 3, 4] unchanged
print(c)                    # [1, 2, 3, 4, 5]
print(a is c)               # False

# Function argument aliasing
def append_one(lst):
    lst.append(1)

my_list = [0]
append_one(my_list)
print(my_list)              # [0, 1] — caller sees mutation

def reassign(lst):
    lst = [99, 99]          # rebinds local name, does NOT mutate caller

reassign(my_list)
print(my_list)              # still [0, 1]
```

## The `*` Pitfall — Shared Mutable Inner Objects

This is one of the most common Python bugs, appearing in interviews and production code.

```python
# Seemingly innocent: create 3x3 grid of zeros
grid = [[0] * 3] * 3
print(grid)                 # [[0, 0, 0], [0, 0, 0], [0, 0, 0]] — looks correct
print(id(grid[0]), id(grid[1]), id(grid[2]))  # SAME id! All three rows are the same object

grid[0][0] = 1
print(grid)                 # [[1, 0, 0], [1, 0, 0], [1, 0, 0]] — all rows changed!

# Visualized:
# grid -> [ row_ref, row_ref, row_ref ] where row_ref -> [0, 0, 0]
# [0]*3 creates inner list; outer *3 repeats the reference

# Correct: use comprehension to create distinct inner lists
grid_ok = [[0] * 3 for _ in range(3)]
grid_ok[0][0] = 1
print(grid_ok)              # [[1, 0, 0], [0, 0, 0], [0, 0, 0]]

# Same pitfall with other mutables
bad = [{}] * 3
bad[0]["a"] = 1
print(bad)                  # [{'a': 1}, {'a': 1}, {'a': 1}]
good = [{} for _ in range(3)]
good[0]["a"] = 1
print(good)                 # [{'a': 1}, {}, {}]

# One-dimensional * with immutables is safe:
safe = [0] * 1000           # fine — ints are immutable
# Modifying an element rebinds, not mutates:
safe[0] = 99                # replaces reference, others unaffected
print(safe[:3])             # [99, 0, 0]
```

> **Rule of thumb:** Never use `*` to repeat mutable objects. Use a comprehension: `[expr for _ in range(n)]` where `expr` creates a fresh object each iteration.

## Nested Lists and Matrices

```python
# Creating and iterating a matrix
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9],
]

# Access
print(matrix[1][2])         # 6 — row 1, col 2

# Transpose idiom
transposed = list(zip(*matrix))  # [(1,4,7), (2,5,8), (3,6,9)] — tuples
transposed_lists = [list(row) for row in zip(*matrix)]

# Flatten one level
nested = [[1, 2], [3, 4], [5]]
flat = [x for row in nested for x in row]  # [1,2,3,4,5]
# Equivalent loops:
flat2 = []
for row in nested:
    for x in row:
        flat2.append(x)
```

## Performance Notes (CPython)

| Operation | Complexity | Comment |
|---|---|---|
| `lst[i]`, `lst[i]=x`, `len(lst)` | O(1) | Direct pointer math |
| `lst.append(x)` | amortized O(1) | Over-allocation |
| `lst.pop()` | O(1) | No shifting |
| `lst.pop(0)`, `lst.insert(0,x)` | O(n) | Shifts all |
| `lst[i:j]` (slice copy) | O(k) | k = slice size |
| `x in lst` | O(n) | Use `set` for O(1) membership |
| `lst.sort()` | O(n log n) | Timsort, highly optimized |
| `lst * n` replication | O(n*k) | Shallow |

## Common Idioms and Best Practices

```python
# 1. Prefer list comprehension over manual loop + append (faster, clearer)
# Instead of:
result = []
for x in range(10):
    if x % 2 == 0:
        result.append(x*x)
# Write:
result = [x*x for x in range(10) if x % 2 == 0]

# 2. Check emptiness Pythonically
lst = []
if not lst:                 # idiomatic — empty list is falsy
    print("empty")
# Not: if len(lst) == 0

# 3. Iterate directly; avoid range(len(...))
for item in lst:
    print(item)
# If you need index, use enumerate (see 2.9)
for i, item in enumerate(lst):
    print(i, item)

# 4. Unpacking
first, *middle, last = [1, 2, 3, 4, 5]
print(first, middle, last)  # 1 [2, 3, 4] 5

# 5. Sentinel / default with pop
value = lst.pop() if lst else None

# 6. Delete with del
del lst[2]                  # remove by index (no return value)
del lst[1:3]                # remove slice
del lst[:]                  # clear (same as lst.clear())

# 7. Copy idioms — all shallow:
# lst.copy(), lst[:], list(lst), copy.copy(lst)
```

## Edge Cases and Gotchas

```python
# Modifying a list while iterating is dangerous
lst = [1, 2, 3, 4]
for x in lst:
    if x % 2 == 0:
        lst.remove(x)       # BUG: skips elements due to shifting
print(lst)                  # [1, 3, 4] — 4 was skipped!
# Correct: iterate over a copy or build a new list
lst = [1, 2, 3, 4]
lst = [x for x in lst if x % 2 != 0]
print(lst)                  # [1, 3]
# Or:
for x in lst[:]:            # iterate over shallow copy
    if x % 2 == 0:
        lst.remove(x)

# Equality is element-wise, recursive
print([1, [2, 3]] == [1, [2, 3]])   # True
print([1, 2] == [2, 1])              # False — order matters
print([1, 2] < [1, 3])               # True — lexicographic comparison

# Lists are unhashable — cannot be dict keys or set elements
# hash([1, 2])  # TypeError: unhashable type: 'list'
# Use tuple instead if you need a hashable sequence

# Large list creation: range vs list(range)
r = range(10_000_000)       # tiny — lazy sequence
lst_big = list(r)           # materializes 10M ints — memory heavy
```

## Summary

- A list is a mutable dynamic array of object references.
- Use `.append`/`.extend` to grow; distinguish adding one element vs many.
- Sorting is in-place via `.sort()` (stable Timsort) or functional via `sorted()`; `key` is transformative.
- Aliasing is pervasive — assignment shares, slicing/copying makes shallow copies.
- `[[0]*n]*m` shares inner lists; always use a comprehension for mutable grids.
- For FIFO queues, prefer `collections.deque`; for membership tests on large collections, prefer `set`.

Lists underpin almost every Python program. Mastering their semantics — especially aliasing, stability of sort, and the shallow-reference model — prevents an outsized share of bugs.
