# 2.7 Comprehensions

Comprehensions are Python's declarative syntax for building collections from iterables — compact, fast, and readable when used well. Python offers **list comprehensions**, **dict comprehensions**, **set comprehensions**, and **generator expressions (genexps)**. Understanding their scoping, performance, filtering/order semantics, the walrus operator inside comprehensions, and when *not* to use them is a core Python skill.

## Overview — Four Forms

```python
# 1. List comprehension — produces a list (eager)
lst = [x*x for x in range(5)]                # [0, 1, 4, 9, 16]

# 2. Set comprehension — produces a set  (eager)
st = {x*x for x in range(5)}                 # {0, 1, 4, 9, 16}

# 3. Dict comprehension — produces a dict (eager)
d = {x: x*x for x in range(5)}               # {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}

# 4. Generator expression — produces a lazy generator (iterable, one-shot)
gen = (x*x for x in range(5))                # <generator object ...>
print(list(gen))                             # [0, 1, 4, 9, 16] — evaluated on demand
```

| Comprehension | Syntax | Eager/Lazy | Output type | Empty? |
|---|---|---|---|---|
| List | `[expr for vars in iter]` | Eager | `list` | `[]` if no items match |
| Set | `{expr for vars in iter}` | Eager | `set` | `set()` — use `set()` directly, `{}` is dict |
| Dict | `{key: val for vars in iter}` | Eager | `dict` | `{}` |
| Generator | `(expr for vars in iter)` | **Lazy** | `generator` | Consumes lazily; `list(gen)` is `[]` |

> **Collective takeaway:** Comprehensions are *expressions*, not statements — they can appear anywhere an expression is needed (arguments, returns, nested inside another expression). PyPy and CPython optimize them to run in C-speed loops where possible.

## List Comprehensions — The Canonical Form

### Basic Syntax: `[expression for variable in iterable]`

```python
# Simple transform — apply function to each element
words = ["hello", "world", "python"]
upper = [w.upper() for w in words]           # ['HELLO', 'WORLD', 'PYTHON']
print(upper)

# Equivalent loop:
equiv = []
for w in words:
    equiv.append(w.upper())
print(equiv)                                # same result, slower, more verbose

# Range-driven
evens = [x for x in range(10)]               # [0 .. 9]
# But comprehensions shine with transformation:
squares = [x*x for x in range(6)]           # [0, 1, 4, 9, 16, 25]
```

### Filtering with `if`

`if` clauses are applied *after* iteration, optionally *before* the output expression is evaluated.

```python
# Keep only elements that satisfy predicate
print([x for x in range(10) if x % 2 == 0])          # [0, 2, 4, 6, 8]
print([w for w in words if len(w) > 5])              # ['python']

# Transform after filtering — only even squares
print([x*x for x in range(10) if x % 2 == 0])        # [0, 4, 16, 36, 64]

# Filtering + transform where both need computation — avoid double work
raw = ["  hello  ", "  ", "world", ""]
# Naive: computes strip twice
print([s.strip().title() for s in raw if s.strip()])
# Better: use assignment expression (walrus) or helper — see § walrus later
```

### Multiple `if` Clauses (Treated as `and`)

```python
# Consecutive `if` are ANDed; ordering is sequential
print([x for x in range(20) if x % 2 == 0 if x % 3 == 0])  # [0, 6, 12, 18]
# Equivalent to: if x%2==0 and x%3==0 — but each `if` can reference walrus bindings from prior

# Realistic: multiple predicates
entries = ["alice:30", "bob:", "carol:25", ":bad", "dave:27"]
valid = [line for line in entries if ":" in line if line.split(":")[1].isdigit()]
print(valid)                                # ['alice:30', 'carol:25', 'dave:27']
```

### Nested `for` Clauses — Flat is Better (but Sometimes Nested)

```python
# Single comprehension with multiple `for` iterates nested loops left-to-right:
# [expr for x in A for y in B]  is equivalent to:
# for x in A:
#   for y in B:
#     result.append(expr)

print([f"{r}{c}" for r in "AB" for c in "12"])  # ['A1','A2','B1','B2']

# Realistic: flatten one level (covered in 2.1)
grid = [[1, 2], [3, 4], [5]]
print([x for row in grid for x in row])     # [1, 2, 3, 4, 5]
# Equivalent loops:
flat = []
for row in grid:
    for x in row:
        flat.append(x)

# Pairs / cross product — often better to use itertools.product
import itertools
print(list(itertools.product("AB", "12")))  # [('A','1'),('A','2'),('B','1'),('B','2')]

# Filtering across nested loops — if goes after its `for`
print([x*y for x in range(4) for y in range(4) if x != y])  # exclude diagonal
# This means: for x: for y: if y!=x: append

# Triple nesting — readability dies quickly
print([(x, y, z) for x in range(2) for y in range(2) for z in range(2)])
# If comprehension needs 3+ fors and/or 2+ ifs, prefer explicit loops for reviewability.
```

### Conditional Expression (`x if cond else y`) vs Filter `if`

Two unrelated uses of `if` cause frequent confusion:

```python
# Filter `if` — keeps or discards element
print([x for x in range(6) if x % 2 == 0])          # [0, 2, 4]

# Ternary in expression — always keeps element, chooses which value
print([x if x % 2 == 0 else -x for x in range(6)])  # [0, -1, 2, -3, 4, -5]
# Equivalent: for x in range(6): append(x if even else -x)

# Combined — both at once
print([x*2 if x % 2 == 0 else -x for x in range(6) if x > 1])
# means: for x in range(6): if x>1: append(x*2 if x%2==0 else -x)
# Read ordering: FOR -> IF (filter) on the right; TERNARY in the expr on the left
```

## Dict Comprehensions

Syntax: `{key_expr: value_expr for vars in iterable ... if cond}`

```python
# Basic
print({x: x*x for x in range(5)})           # {0:0, 1:1, 2:4, 3:9, 4:16}

# From pair sequence — can overwrite pattern from list/dict lesson
words = ["hello", "world", "hi"]
print({w: len(w) for w in words})           # {'hello':5, 'world':5, 'hi':2}

# Filtering entries
print({x: x*x for x in range(10) if x % 2 == 0})  # {0:0, 2:4, 4:16, 6:36, 8:64}

# Inverting a mapping where values are unique
invert = {v: k for k, v in {"a": 1, "b": 2}.items()}
print(invert)                               # {1: 'a', 2: 'b'}
# Non-unique values -> last wins (like dict construction) — see defaultdict pattern:
orig = {"a": 1, "b": 1, "c": 2}
# {v: k for ...} would lose 'a' -> need grouping
from collections import defaultdict
grouped = defaultdict(list)
for k, v in orig.items(): grouped[v].append(k)
print(dict(grouped))                        # {1: ['a','b'], 2: ['c']}

# From two parallel iterables
keys = ["a", "b", "c"]
vals = [1, 2, 3]
print({k: v for k, v in zip(keys, vals)})   # same as dict(zip(keys, vals))

# Realistic: normalizing dict values
raw = {"a": "  HELLO ", "b": " world ", "c": "  PYTHON"}
print({k: v.strip().lower() for k, v in raw.items()})

# Grouping with comprehension? Dict comprehension alone can't append to lists because new dict is built.
# But you can build via loops or use comprehension that groups first then aggregates with other tools.
```

## Set Comprehensions

Syntax: `{expr for vars in iter if cond}` — identical to list but with braces and uniqueness.

```python
# Basic — deduplication implicit via set
print({x*x for x in range(5)})                 # {0, 1, 4, 9, 16}
# From string — unique chars squared?
print({c.upper() for c in "hello"})           # {'H','E','L','O'}

# Filtering
print({x for x in range(10) if x % 2 == 0})    # {0, 2, 4, 6, 8}

# Realistic: extracting unique tokens
texts = ["hello world", "world peace", "hello python"]
vocab = {word for text in texts for word in text.split()}
print(vocab)                                    # {'hello','world','peace','python'}

# Since Python 3.2+, set([...]) with a genexp is slower; use {... for ...} directly.
```

> **Ambiguity:** `{x for x in seq}` (set comprehension) vs `{x: x for x in seq}` (dict). Empty `{}` is **dict**, not set — use `set()` for empty set, `{}` for empty dict, `{x for x...}` for non-empty set.

## Generator Expressions — Lazy Comprehensions

Syntax: `(expr for vars in iter if cond)` — parentheses form; can omit parens when sole argument to a function.

```python
# Lazy — produces values on demand; no intermediate container
gen = (x*x for x in range(5))
print(type(gen))            # <class 'generator'>
print(next(gen))            # 0 — first value computed on demand
print(sum(x*x for x in range(5)))           # 30 — parens optional as argument
print(max(x*x for x in range(5)))           # 16
print(" ".join(str(x) for x in range(5)))   # '0 1 2 3 4'

# Must parenthesize if there are other arguments:
print(list(x*x for x in range(3)))          # [0, 1, 4]
# Or unpacking with multiple elements, use list() with generator -> avoid confusion

# Infinite/lazy advantage — range() is already lazy, but filtering/transforming huge files lazily matters
def read_lines():
    for i in range(1_000_000): yield f"line {i}"
# Genexp does NOT consume the whole iterator to build a list
large = (line.upper() for line in read_lines() if "500" in line)
# Only iterates what is actually consumed — next(large) or for ... in large
print(next(large))          # LINE 500

# Single-use: generators exhaust
g = (x for x in range(3))
print(list(g))              # [0, 1, 2]
print(list(g))              # [] — exhausted
# If you need multiple passes, use list comprehension; if one pass with memory limits, use genexp.

# Chaining generators via genexp — pipelines
raw = (line.strip() for line in read_lines())
nonempty = (line for line in raw if line)
# Each stage is lazy; the whole pipeline is still a generator
```

## Walrus Operator (`:=`) Inside Comprehensions

PEP 572 allows assigning inside an expression. This eliminates duplicated computation and enables filtering on a computed value that is also needed in the output.

```python
# Before walrus — computation duplicated (inefficient, or inconsistent if expression has side effects)
raw = ["  hello  ", "  ", "world", "", "  py  "]
# Wants stripped + filter nonempty; naive duplicates strip():
print([s.strip() for s in raw if s.strip()])  # strips twice per element

# With walrus — compute once, bind name, filter and use it
print([clean for s in raw if (clean := s.strip())])    # ['hello','world','py']
# Next step: also transform filtered value
print([clean.title() for s in raw if (clean := s.strip())])

# Realistic: regex with expensive computation
import re
pattern = re.compile(r"\d+")
lines = ["score=42", "no score", "val=100"]
# Without walrus you'd call search twice or loop:
print([m.group() for line in lines if (m := pattern.search(line))])

# Pitfall: walrus scope leaks to containing scope (unlike loop variable in comp, the walrus target is assigned in the enclosing scope)
results = [y for x in range(5) if (y := x*2) > 3]
print(y)                    # 8 — last value, leaked into caller scope!
# In list/set/dict comps the loop variable itself does NOT leak (see § Scope below), but walrus does.

# For generator expressions, same scoping — walrus binds in the frame where genexp is defined
```

## Nesting and the "When Not To" Rule

Comprehensions are powerful; overusing them hurts readability. The Pythonic rule is expressed in PEP 20 and PEP 8: **flat is better than nested; readability counts.**

```python
# Clear — one transform + optional filter
evens_sq = [x*x for x in range(10) if x % 2 == 0]

# Still clear — two fors with simple expr
flat = [x for row in [[1,2],[3,4]] for x in row]  # borderline but okay

# UNCLEAR — don't do this in review
unreadable = [
    y*z if y > 5 else y+z for x in range(5)
    for y in [x*2, x*3]
    for z in range(y) if z % 2 == 0
]
# Prefer explicit nested loops for multi-stage logic:
out = []
for x in range(5):
    for y in (x*2, x*3):
        for z in range(y):
            if z % 2 == 0:
                out.append(y*z if y > 5 else y+z)

# Heuristic: if comprehension needs 3+ fors, 2+ ifs, or a complex ternary,
# rewrite as a loop. Code reviews should rarely require others to mentally
# unroll comprehension levels.
```

> **Performance myth:** "List comps are always faster than loops" — usually true (C-level loop + `LIST_APPEND`), but the win is typically 10–50%, not order-of-magnitude. For dict/set comprehensions built on non-constant keys, loop+`[]=` is similarly performant. Choose based on readability first; measure if puzzled by hot spots.

## Performance vs Loop — Concrete Benchmarks

```python
# Idiomatic comparison (do NOT micro-optimize prematurely; measure with timeit)
import timeit

# List comp vs loop+append — comp is faster
t_comp = timeit.timeit("[x*x for x in range(1000)]", number=10000)
t_loop = timeit.timeit("""
result = []
for x in range(1000):
    result.append(x*x)
""", number=10000)
# Typically t_comp < t_loop by 1.5-2x — implementation detail, not contract

# Generator vs list comp for one-pass consumption: genexp wins on memory; speed tie if consumed with sum
t_gen  = timeit.timeit("sum(x*x for x in range(1000))", number=10000)
t_list = timeit.timeit("sum([x*x for x in range(1000)])", number=10000)
# t_gen is slightly slower due to per-item generator protocol; t_list pays O(n) memory.
# For streaming large data, prefer genexp. For small materialized results, either.

# Set/dict comps vs dict() + generator: comp is usually faster and clearer
# set(... for ...) vs { ... for ... } — braced form is faster (one opcode)
```

## Scoping — Isolated but Not Hermetic

This is subtle and historically changed.

```python
# Python 3: list comprehensions have their own scope (implemented as a hidden function)
# Loop variables do NOT leak into the surrounding scope
x = 99
lst = [x for x in range(5)]
print(x)                    # 99 — loop x did not overwrite outer x

# Same for set/dict comps and genexps — all isolated since Python 3

# Consequence: variables assigned inside the comp ARE local to it,
# except the walrus (:=) which intentionally binds in the containing scope (see above)
y = 10
comp = [y for y in range(3)]  # outer y stays 10
print(y)                    # 10

# Python 2 behavior was different — list comps leaked; upgrading historical code broke.
# If you evaluate a loop variable after a comprehension, you are reading the old enclosing binding, not last loop value
# To capture last iteration value, use an explicit loop.

# Shadowing: a comprehension variable shadows an outer one WITHIN the comp only
outer = "outer"
print([outer + str(i) for i, outer in enumerate(["a", "b"])])  # outer inside comprehension is loop var
print(outer)                # still "outer"

# Closures referencing loop vars inside a new closure/function behave unexpectedly
funcs = [lambda: x for x in range(3)]
# Each lambda captures the VARIABLE `x`, which after the loop is 2
print(funcs[0]())           # 2 — not 0 (late binding)
# But in comprehensions, late binding occurs after the hidden function returns
# To capture by value:
funcs2 = [lambda x=x: x for x in range(3)]  # default-arg captures
print(funcs2[0]())          # 0
```

## Distinguishing Filter vs Ternary vs Chained Fors — Reading Order

```python
# Parsing a comprehension left-to-right mirrors nested loops with trailing if:

# [expr for a in A for b in B if cond]
# ==
# result = []
# for a in A:
#   for b in B:
#     if cond:
#       result.append(expr)

# So: filters (if) apply AFTER the nearest for to their left.
# Ternaries (x if c else y) are INSIDE the expr (before the first for).

examples = []

# 1. Filter before transform: only odd numbers squared
print([x*x for x in range(6) if x % 2])    # [1, 9, 25]

# 2. Ternary: all numbers, but odd become negative
print([x if x%2==0 else -x for x in range(6)])  # [0, -1, 2, -3, 4, -5]

# 3. Nested for + filter: cartesian product without diagonal
print([(a, b) for a in range(3) for b in range(3) if a != b])

# 4. Multiple filters chaining via AND — each after its nearest for
# [x for x in A if p(x) for y in f(x) if q(y)] means nested loops with respective filters
# Prefer: [y for x in A if p(x) for y in f(x) if q(y)] -> explicit
```

## Realistic End-to-End Examples

```python
# 1. Deduplication + normalization pipeline (genexp + set comp + dict comp)
raw = ["  Alice ", "bob ", "ALICE", "  Bob ", "carol"]
# Step 1: lazy cleanup
cleaned = (s.strip().lower() for s in raw)
# Step 2: unique usernames (set comprehension materializes)
unique = {name for name in cleaned}  # {'alice','bob','carol'}
# Or sorted: sorted({name for name in cleaned})
print(unique)
# With counts (dict comp):
from collections import Counter
# Two passes: but illustrates
raw2 = ["Alice ", "bob ", "ALICE", "  Bob "]
print(Counter(s.strip().lower() for s in raw2))  # Counter({'alice':2,'bob':2})

# 2. Matrix transpose using nested comprehension
matrix = [[1, 2, 3], [4, 5, 6]]
transposed = [[row[i] for row in matrix] for i in range(len(matrix[0]))]
print(transposed)           # [[1,4], [2,5], [3,6]]
# For numerical workloads, prefer zip(*matrix) or NumPy; comprehension is educational

# 3. CSV parsing — walrus + filter + transform
lines = ["id:1  val: 100", "id:2  val: bad", "id:3  val: 200"]
import re
pat = re.compile(r"val:\s*(\d+)")
# Extract numeric vals only:
vals = [int(m.group(1)) for line in lines if (m := pat.search(line))]
print(vals)                 # [100, 200]

# 4. Nested dict comprehension — equivalence table
symbols = ["A", "B", "C"]
# Pairwise equality matrix as dict of dicts
eq_table = {a: {b: (a == b) for b in symbols} for a in symbols}
print(eq_table)             # {'A': {'A':True,'B':False,...}, ...}

# 5. Filtering a dict kept comprehension-style
scores = {"Alice": 95, "Bob": 40, "Carol": 80, "Dave": 30}
passing = {k: v for k, v in scores.items() if v >= 60}
print(passing)              # {'Alice':95,'Carol':80}

# 6. Flat-map with condition inside — using conditional expression correctly
nums = [1, 2, 3, 4]
# Double evens, keep odds as-is
print([x*2 if x%2==0 else x for x in nums])  # [1, 4, 3, 8]

# 7. Large-file pipeline without loading everything into memory (genexp vs list comp)
# List comp would store the whole dataset:
# big = [int(line.strip()) for line in huge_file if line.strip().isdigit()]  # O(n) memory
# Genexp streams it:
# gen = (int(line.strip()) for line in huge_file if line.strip().isdigit())  # O(1) memory for the generator;
# sum(gen) / next/gen loops consume one at a time

# 8. Enumerate + comprehension for index-aware transforms
items = ["a", "b", "c"]
print([f"{i}:{s}" for i, s in enumerate(items, start=1)])  # ['1:a','2:b','3:c']

# 9. Any/all with generator for short-circuit predicate checks
vals = [0, 1, 2, 3]
print(any(x*x > 5 for x in vals))   # True — stops once 9 > 5 at x=3
print(all(x >= 0 for x in vals))    # True
# Generator + any/all is Pythonic and short-circuits; list comp would always materialize fully.
```

## Common Mistakes and Gotchas

```python
# 1. Empty set literal is not set
print(type({}))             # dict — {x for x in []} is set() when empty

# 2. [] vs () vs {} overload in type hints vs values
# In runtime, [1,2] != (1,2); in type hints Sequence[int] accepts both.
# In comprehension runtime, [x for x in t] is list, (x for x in t) is generator

# 3. Late-binding closures in comprehension (classic gotcha, repeated for emphasis)
funcs = [lambda: x for x in range(3)]
print(funcs[1]())           # 2 — late binding; fix: lambda x=x: x

# 4. Modifying iterable during comprehension — undefined behavior (skip/shift)
vals = [1, 2, 3, 4]
# [vals.pop(0) for _ in vals]  # DON'T: comprehension iterates sequence that is being mutated
# Snapshot if you must: [x for x in list(vals)]

# 5. Reusing variable name that shadows in walrus context
y = 0
print([y := x for x in range(3)])   # assigns y=2 in outer scope (walrus leaks)
print(y)                    # 2

# 6. Assuming evaluation order left-to-right for expr — it is, but keep side effects out
# [do_side_effect(x) for x in seq] is discouraged where effect matters; use a for loop.

# 7. Over-nesting comprehension then performing side-effect-only ops
# Bad: [print(x) for x in seq]  — builds list of Nones; use a plain for loop.
for x in [1, 2, 3]:
    print(x)                # correct for side effects

# 8. Dict comprehension duplicate keys — last wins silently
print({x % 2: x for x in range(5)})  # {0:4, 1:3} — overwrites on collision, no error

# 9. Forgetting that set comprehension deduplicates (by hash/eq) — including True==1 quirk
print({1: 1 for _ in [True, 1, 1.0]}) # not set, but {1, True, 1.0} => {1}
print({x for x in [1, True, 1.0]})    # {1} — collapse to one

# 10. Generator is single-use — unexpectedly empty second time
g = (x for x in range(3))
print(len(list(g)))         # 3 — first pass exhausts
print(len(list(g)))         # 0 — empty now
```

## Summary

- Four forms: list `[...]`, dict `{k:v for ...}`, set `{x for ...}`, generator `(x for ...)` — all share `for` / `if` / `walrus` mechanics.
- `if` after `for` filters elements; `x if cond else y` before `for` transforms unconditionally; nested `for` loops read left-to-right as nested blocks.
- Dict comprehensions are the idiomatic way to transform/filter mappings; set comprehensions deduplicate; generator expressions are **lazy** and single-pass, ideal for pipelines and memory-bound streams.
- The walrus operator `:=` inside comprehensions avoids recomputing expensive expressions and binds in the enclosing scope (loop variables themselves remain isolated).
- Comprehensions run in their own scope — loop variables do not leak (unlike Python 2) — and should stay flat and readable; over-nested comprehensions hurt reviewability and should be loops.
- Prefer comprehensions for *value construction* (producing a new collection); prefer explicit `for` loops for *side effects* or multi-stage branching.
