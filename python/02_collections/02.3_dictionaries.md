# 2.3 Dictionaries

The `dict` is Python's hash table — the single most important built-in collection. It backs object attributes, keyword arguments, modules, and countless user programs. Since Python 3.7, dictionaries are also **insertion-ordered**, a property that changes how idiomatic code is written. This lesson covers construction, ordering guarantees, every core method, views, merging, missing-key handling, and the critical hashability requirement.

## What a `dict` Is

A `dict` is:

- **A hash table** — O(1) average lookup, insertion, and deletion by key.
- **Insertion-ordered** (Python 3.7+) — iteration order reflects insertion order; in 3.6 it was an implementation detail, in 3.7+ a language guarantee.
- **Mutable** — you can add, remove, and replace key-value pairs.
- **Keys must be hashable** — `int`, `str`, `tuple` (of hashables), `frozenset`, `None` are typical; `list`, `dict`, `set` are not.
- **Values may be anything** — any object, including mutable collections.
- **Sparse representation** — over-allocated to keep collisions low; faster than linear search but larger than a list.

```python
# Basic dict — mapping user -> score
scores = {"Alice": 95, "Bob": 87, "Carol": 92}
print(scores["Alice"])      # 95 — O(1) lookup
scores["Dave"] = 78         # insertion
del scores["Bob"]           # deletion
print("Bob" in scores)      # False — O(1) membership
print(scores)
```

> **Mental model:** A `dict` holds an array of slots indexed by `hash(key) % size`; collisions are resolved by probing. Keys are compared with `==` *after* their hashes match. This explains hashability, the equal-objects-must-hash-equal rule, and why mutable keys are forbidden.

## Construction — Seven Ways

```python
# 1. Literal — most common, fastest, most readable
empty = {}
d1 = {"a": 1, "b": 2}
# Trailing comma allowed:
d = {
    "Alice": 95,
    "Bob": 87,
}

# 2. dict() with keyword arguments — keys must be valid identifiers (no spaces, not int)
d2 = dict(alice=95, bob=87)         # {"alice": 95, "bob": 87}
# Useful for function-argument-style construction

# 3. dict() with iterable of pairs
d3 = dict([("a", 1), ("b", 2)])
d4 = dict((k, k*k) for k in range(5))
# Common: dict(zip(keys, values))
keys = ["a", "b", "c"]
values = [1, 2, 3]
print(dict(zip(keys, values)))      # {'a': 1, 'b': 2, 'c': 3}

# 4. dict(mapping) — shallow copy constructor
original = {"a": 1}
copy = dict(original)               # shallow copy
print(copy)

# 5. dict(mapping, **kwargs) — copy + extend
print(dict({"a": 1}, b=2, c=3))    # {'a': 1, 'b': 2, 'c': 3}

# 6. Comprehension
squares = {n: n*n for n in range(5)}  # {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}
# With filter:
evens = {n: n*n for n in range(10) if n % 2 == 0}

# 7. fromkeys() — see pitfalls below
```

> **Idiom preference:** Prefer literal `{}` and comprehension for readability and performance. `dict(a=1, b=2)` is occasionally convenient but forces string keys that are valid identifiers.

## Insertion Ordering — Guaranteed Since 3.7

```python
d = {}
d["c"] = 3
d["a"] = 1
d["b"] = 2
print(list(d))              # ['c', 'a', 'b'] — insertion order
print(list(d.keys()))       # ['c', 'a', 'b']
print(list(d.values()))     # [3, 1, 2]
print(list(d.items()))      # [('c', 3), ('a', 1), ('b', 2)]

# Updating an existing key preserves its position:
d["a"] = 99
print(list(d))              # ['c', 'a', 'b'] — 'a' stays where it was

# Deleting and reinserting moves to end:
del d["a"]
d["a"] = 55
print(list(d))              # ['c', 'b', 'a'] — 'a' now last

# Insertion order is used by tools (json, dataclasses, kwargs):
def fn(**kwargs):
    print(list(kwargs.keys()))  # order reflects call site since 3.6+

# Historical note: In Python 3.5 and earlier, dict order was arbitrary.
# OrderedDict (collections) was needed for predictable order. Since 3.7,
# plain dict is ordered and OrderedDict remains mostly for backward compat
# and for reordering/equality-sensitive features.
```

## Core Methods — Complete Reference

### Access

#### `d[key]` and Assignment `d[key] = value`

```python
d = {"a": 1, "b": 2}
print(d["a"])               # 1
d["c"] = 3                  # insert new key
d["a"] = 99                 # update existing key (position preserved)
# print(d["missing"])       # KeyError
```

#### `d.get(key, default=None)` — Safe Lookup

```python
d = {"a": 1, "b": 2}
print(d.get("a"))           # 1
print(d.get("missing"))     # None (default)
print(d.get("missing", 0))  # 0
# Realistic: counting with fallback
text = "hello world"
counts = {}
for ch in text:
    counts[ch] = counts.get(ch, 0) + 1
print(counts)
# Contrast: d[key] raises. get() never raises for missing key.
```

#### `d.setdefault(key, default=None)` — Get or Insert Default

```python
# If key exists, returns its value (no overwrite). If missing, inserts default and returns it.
d = {"a": 1}
print(d.setdefault("a", 0))         # 1 — existing value, not overwritten
print(d.setdefault("b", 99))        # 99 — inserted
print(d)                            # {'a': 1, 'b': 99}

# Classic: grouping without collections.defaultdict
groups = {}
for word in ["apple", "avocado", "banana", "blueberry"]:
    key = word[0]
    groups.setdefault(key, []).append(word)
print(groups)               # {'a': ['apple','avocado'], 'b': ['banana','blueberry']}

# Pitfall — default is evaluated immediately, even if key exists:
# d.setdefault("a", expensive_fn())  # expensive_fn() always called
# Use `if key not in d: d[key] = expensive_fn()` or defaultdict if that's costly.
```

### Removal

#### `d.pop(key[, default])` — Remove and Return

```python
d = {"a": 1, "b": 2}
print(d.pop("a"))           # 1 — removed and returned
print(d)                    # {'b': 2}
# d.pop("missing")          # KeyError
print(d.pop("missing", None))  # None — default suppresses error
```

#### `d.popitem()` — Remove LIFO Last Item

```python
d = {"a": 1, "b": 2, "c": 3}
print(d.popitem())          # ('c', 3) — LIFO: last inserted removed
print(d)                    # {'a': 1, 'b': 2}

# Before 3.7, popitem() was arbitrary (random). Since 3.7, LIFO.
# Use to dismantle a dict in reverse insertion order.
# Raises KeyError if empty.
```

#### `d.clear()` — Remove All

```python
d = {"a": 1}
d.clear()
print(d)                    # {}
# Same object (id unchanged) — any other references see the clear.
```

#### `del d[key]`

```python
d = {"a": 1}
del d["a"]                  # remove; raises KeyError if absent
# del d["missing"]          # KeyError — no default support
```

### Bulk Update

#### `d.update(other)` — Merge In Place

```python
d = {"a": 1}
d.update({"b": 2, "c": 3})
print(d)                    # {'a': 1, 'b': 2, 'c': 3}

# Accepts dict, iterable of pairs, or kwargs
d.update([("d", 4), ("e", 5)])
d.update(f=6, g=7)
print(d)

# Existing keys are overwritten, keeping their original insertion position? Actually no:
# - For existing key: value updated, insertion position PREERVED.
# - For new key: appended at end.
d = {"a": 1, "b": 2}
d.update({"b": 99, "c": 3})
print(list(d.keys()))       # ['a', 'b', 'c'] — 'b' position preserved

# Realistic: merging config defaults with overrides
defaults = {"host": "localhost", "port": 8080}
overrides = {"port": 9090}
config = dict(defaults)
config.update(overrides)
print(config)
```

### Introspection

```python
d = {"a": 1, "b": 2}
print(len(d))               # 2 — O(1)
print("a" in d)             # True — O(1), checks keys (== "a" in d.keys())
print("a" not in d)         # False
print(2 in d)               # False — values NOT checked; use `2 in d.values()` for values
```

## `keys()`, `values()`, `items()` — Dictionary Views (Dynamic Windows)

This is subtle and powerful. Since Python 3.0, these methods return **view objects**, not lists.

```python
d = {"a": 1, "b": 2, "c": 3}
keys = d.keys()
values = d.values()
items = d.items()

print(type(keys))           # <class 'dict_keys'>
print(list(keys))           # ['a', 'b', 'c']
print("a" in keys)          # True — O(1)
print(("a", 1) in items)    # True — checks pair membership

# Views are DYNAMIC — they reflect dict mutations
d["d"] = 4
print(list(keys))           # ['a', 'b', 'c', 'd'] — automatically updated!
print(list(values))         # [1, 2, 3, 4]
del d["a"]
print(list(keys))           # ['b', 'c', 'd']

# Views are iterable, support len(), and support set-like operations for keys/items
print(len(keys))            # 3
print(keys & {"b", "c", "x"})  # {'b', 'c'} — intersection (dict_keys behaves like set)
print(keys | {"x", "y"})    # {'b', 'c', 'd', 'x', 'y'}
print(keys - {"b"})         # {'c', 'd'}
# values view does NOT support set operations (values are not unique)

# Realistic: filtering without copying
d = {"a": 1, "b": 2, "c": 3, "d": 4}
# Get keys whose value > 2 — views are efficient
big_keys = [k for k in d if d[k] > 2]
# Or: intersecting dict keys with another set
active = {"a", "c", "x"}
print(d.keys() & active)    # {'a', 'c'}

# Gotcha: mutating dict while iterating views raises RuntimeError
# for k in d.keys():
#     if k == "b": del d[k]  # RuntimeError: dictionary changed size during iteration
# Fix: iterate over a snapshot
for k in list(d.keys()):
    if k == "b":
        del d[k]
print(d)
```

| View | Set Operations? | Notes |
|---|---|---|
| `dict_keys` | Yes (`&`, `\|`, `-`, `^`, `<`, `>`) | Acts like a set; O(1) membership |
| `dict_items` | Yes (if all values hashable) | Set of key-value tuples |
| `dict_values` | No | Membership is O(n) — scans values |

## Merging — `|` and `|=` (Python 3.9+) and Older Idioms

```python
a = {"x": 1, "y": 2}
b = {"y": 99, "z": 3}

# Python 3.9+ — | and |= (PEP 584)
merged = a | b              # {'x': 1, 'y': 99, 'z': 3} — new dict, b wins on conflict
print(merged)
# a |= b                    # in-place merge (a.update(b) equivalent)
print(a)                    # unchanged until |=

# Older idioms — still common for 3.8 compatibility
merged_old = {**a, **b}    # unpacking — {'x': 1, 'y': 99, 'z': 3}
print(merged_old)
# With three or more:
c = {"w": 0}
print({**a, **b, **c})

# Chaining updates (older still):
merged2 = dict(a)
merged2.update(b)
print(merged2)

# Priority: rightmost wins
print({"a": 1} | {"a": 2})  # {'a': 2}

# Realistic: config layering
defaults = {"debug": False, "port": 8000, "host": "localhost"}
env_overrides = {"port": 9000}
user_overrides = {"debug": True}
config = defaults | env_overrides | user_overrides
print(config)               # {'debug': True, 'port': 9000, 'host': 'localhost'}
```

> **Use `|` when you want a *new* dict; `update`/`|=` when you want to mutate.** Neither performs deep merging; nested dicts are replaced, not recursively merged.

```python
# Shallow merge — nested dict replaced entirely
base = {"db": {"host": "local", "port": 5432}}
patch = {"db": {"port": 9999}}
print(base | patch)         # {'db': {'port': 9999}} — host lost!
# For deep merge you must write a recursive function or use a library.

# Shallow nature explains why | is fast — O(n+m) without recursion.
```

## Missing-Key Handling — Five Strategies

```python
d = {"a": 1}

# 1. Let it raise — valid when missing is a bug
value = d["a"]  # KeyError if missing — correct for "must exist"

# 2. get() with default — when missing is expected and non-fatal
print(d.get("a", 0))        # 0 if missing
# Patterns: counters, optional config
def get_config(key):
    return d.get(key, "default_value")

# 3. in / not in guard
if "a" in d:
    print(d["a"])

# 4. setdefault() — insert-on-read
d.setdefault("b", []).append(1)  # creates [] if missing, then appends

# 5. collections.defaultdict — auto-inserts default on __getitem__
from collections import defaultdict

dd = defaultdict(list)      # int, str, set, etc. all work as factories
dd["a"].append(1)           # no setdefault/get dance needed
dd["b"].append(2)
print(dict(dd))

# int defaultdict for counting
counts = defaultdict(int)
for ch in "hello":
    counts[ch] += 1
print(dict(counts))

# setdefault vs defaultdict vs get:
# - get: read-only default, does not insert.
# - setdefault: inserts default if missing (mutates), returns value.
# - defaultdict: inserts by calling factory on any missing __getitem__/__missing__ path.
```

### `__missing__` Hook — Customizing Missing Behavior

```python
class CaseInsensitiveDict(dict):
    def __missing__(self, key):
        if isinstance(key, str):
            for k in self:
                if k.lower() == key.lower():
                    return self[k]
        raise KeyError(key)

ci = CaseInsensitiveDict({"Hello": 1})
print(ci["HELLO"])          # 1 — fallback
# Note: __missing__ is called only by __getitem__(key), not dict.get().

# Realistic: defaultdict subclasses using __missing__
```

## Hashability Requirement — The Invariant

```python
# Only hashable types can be dict keys
# Hashable means: has a __hash__ and __eq__, and hash never changes
print(hash("hello"))        # stable within run (randomized across runs for str/bytes since 3.3)
print(hash((1, 2)))         # tuple of immutables is hashable
print(hash(frozenset([1, 2])))
# hash([1, 2])              # TypeError: unhashable type: 'list'
# hash({"a": 1})            # TypeError: unhashable type: 'dict'
# hash({1, 2})              # TypeError: unhashable type: 'set'

# Composite keys must be recursively hashable:
# valid:
d2 = {(1, "a"): 100, (frozenset([1, 2]), "b"): 200}
# invalid:
# d2 = {([1, 2], "a"): 100}  # TypeError — tuple containing list is unhashable

# The dict invariant: if a == b then hash(a) == hash(b)
# This is why floats and ints can be "equivalent" keys:
print({1: "int key", 1.0: "float key"})  # {'1': 'float key'} — 1 == 1.0 and hash(1) == hash(1.0)
# Last write wins; only one entry remains.

# Pitfall: mutable subclass of immutable that overrides __eq__ without __hash__
# class BadKey(str):  # str is hashable
#     def __eq__(self, other): return True
# # Setting __eq__ without __hash__ sets __hash__ to None -> unhashable
# print(hash(BadKey("x")))  # TypeError: unhashable type
```

> **Why must keys be hashable?** Mutating a key's hash after insertion would leave the entry in the wrong bucket, making it irretrievable. Immutability (or at least hash stability) prevents this. Lists are mutable → intentionally unhashable.

## `fromkeys()` Pitfall

```python
# fromkeys(iterable, value=None) — creates new dict with same value for each key
print(dict.fromkeys(["a", "b", "c"], 0))      # {'a': 0, 'b': 0, 'c': 0}
print(dict.fromkeys(range(3)))                # {0: None, 1: None, 2: None}

# Dangerous with mutable value — shares reference!
bad = dict.fromkeys(["a", "b", "c"], [])
print(bad)                    # {'a': [], 'b': [], 'c': []}
bad["a"].append(1)
print(bad)                    # {'a': [1], 'b': [1], 'c': [1]} — all share same list!

# Fix: use comprehension to create fresh values
good = {k: [] for k in ["a", "b", "c"]}
good["a"].append(1)
print(good)                   # {'a': [1], 'b': [], 'c': []}

# Alternative with fromkeys and None sentinel, then populate
good2 = dict.fromkeys(["a", "b", "c"])
for k in good2:
    good2[k] = []
```

## Iteration — Order and Patterns

```python
d = {"a": 1, "b": 2, "c": 3}

# Default iteration is keys — like `for k in d.keys()`
for k in d:
    print(k)

# Idiomatic unpacking
for k, v in d.items():
    print(f"{k} -> {v}")

# Need both index and key? enumerate works
for i, (k, v) in enumerate(d.items()):
    print(i, k, v)

# Deleting during iteration — forbidden; snapshot first
for k in list(d):           # list(d) snapshots keys
    if k == "b":
        del d[k]
print(d)

# Sorting by keys or values
for k in sorted(d):         # sorted keys
    print(k, d[k])
# Sort by values
for k in sorted(d, key=lambda k: d[k]):
    print(k)

# Realistic: building reverse index (value -> list of keys) — values may repeat
d = {"a": 1, "b": 2, "c": 1}
rev = {}
for k, v in d.items():
    rev.setdefault(v, []).append(k)
print(rev)                  # {1: ['a', 'c'], 2: ['b']}
```

## Equality and Ordering

```python
# Equality: checks same key-val pairs, ignores insertion order
print({"a": 1, "b": 2} == {"b": 2, "a": 1})  # True — order irrelevant for ==

# Order can be important for comparisons in some serialization; equality does not check order.
# If you need order-sensitive comparison, compare list(d.items()).

# Size
d1 = {"a": 1}
d2 = {"a": 1, "b": 2}
print(len(d1), len(d2))
```

## Performance Characteristics

| Operation | Average | Worst | Notes |
|---|---|---|---|
| Lookup `d[k]`, `d.get(k)` | O(1) | O(n) | Collision attack worst case |
| Insert `d[k]=v`, `update` | O(1) | O(n) | Amortized; resizes geometric |
| Delete `del d[k]`, `pop` | O(1) | O(n) | Leaves tombstone marker |
| Membership `k in d` | O(1) | O(n) | Hash probe |
| Iteration `for k in d` | O(n) | — | Insertion order |
| Views (`keys/items/values`) | O(1) to create | — | Dynamic window |
| `k in d.values()` | O(n) | — | Linear scan of values |

> **Value lookup is O(n)** — `x in d.values()` is a linear scan. For O(1) value membership, maintain a reverse dict or set.

## Realistic End-to-End Example

```python
from collections import defaultdict, Counter

# Word frequency with punctuation stripping
text = "hello world hello Python hello World"
words = text.lower().split()

# Counter (dict subclass) approach — simplest
freq = Counter(words)
print(freq)                 # Counter({'hello': 3, 'world': 2, 'python': 1})
print(freq.most_common(2))  # [('hello', 3), ('world', 2)]
print(freq["hello"])        # 3

# Manual with dict.get:
freq2 = {}
for w in words:
    freq2[w] = freq2.get(w, 0) + 1
print(freq2)

# default dict approach:
freq3 = defaultdict(int)
for w in words:
    freq3[w] += 1
print(dict(freq3))

# Inversion: frequency -> words
inv = defaultdict(list)
for w, c in freq.items():
    inv[c].append(w)
print(dict(inv))            # {3: ['hello'], 2: ['world'], 1: ['python']}

# Merging word counts from two sources (Counter | adds, dict | overwrites)
c1 = Counter({"hello": 2, "world": 1})
c2 = Counter({"hello": 1, "python": 3})
print(c1 + c2)              # Counter({'hello': 3, 'python': 3, 'world': 1})

# JSON-safe dict keys must be strings — tuple keys serialize poorly
import json
# json.dumps({("a","b"): 1})  # TypeError if tuple keys
# Workaround: join keys or encode explicitly
```

## Common Mistakes and Gotchas

```python
# 1. Mutable default argument holding a dict — classic Python bug
def add_item(item, bag={}):   # ONE dict shared across all calls!
    bag[item] = bag.get(item, 0) + 1
    return bag

print(add_item("a"))  # {'a': 1}
print(add_item("b"))  # {'a': 1, 'b': 1} — leaked previous items!
# Fix: use None sentinel
def add_item_ok(item, bag=None):
    if bag is None:
        bag = {}
    bag[item] = bag.get(item, 0) + 1
    return bag

# 2. Forgetting that dict assignment shares reference
a = {"x": [1, 2]}
b = a                    # alias
b["y"] = 3
print(a)                 # {'x': [1,2], 'y': 3} — mutated via alias
# Shallow copy: b = dict(a) or a.copy() — but inner lists still shared!

# 3. Dict comprehension vs fromkeys with mutable default already covered.

# 4. Expecting d[k] to return None for missing — it raises KeyError, not None.

# 5. Modifying dict during iteration raises RuntimeError — snapshot first.

# 6. Not realizing 1 and 1.0 collide as keys.
d = {1: "one"}
d[1.0] = "one point zero"
print(d)                 # {1: 'one point zero'} — same slot
print(d[1], d[1.0])      # 'one point zero' 'one point zero'

# 7. Unpack limits
# dict unpacking order: {**a, **b} respects insertion order of a then new keys of b
```

## Summary

- Dicts are hash tables: O(1) lookup by hashable keys; insertion-ordered since Python 3.7.
- Construct via literals `{k: v}` (preferred), comprehensions `{k: v for ...}`, or `dict(iterable)`.
- Key methods `get`/`setdefault`/`pop`/`update`/`popitem`; addition via `d[key]=v` and `del d[key]`.
- `keys()`/`values()`/`items()` return dynamic, set-like views — not lists — reflecting mutations.
- Merge with `|`/`|=` (3.9+) or `**` unpacking; both are shallow.
- Missing keys handled by `KeyError` (default), `get` (fallback), `setdefault`/`defaultdict` (insert default), `__missing__` (custom).
- Hashability requires stable `__hash__` and equality; mutables are intentionally unhashable to protect the hash table invariant.
- `fromkeys(value=mutable)` shares references — use a comprehension instead.
