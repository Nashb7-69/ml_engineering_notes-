# 06.4 Exception Chaining, Context, and Tracebacks: cause, context, and Exception Groups

When one exception triggers another — a file-read failure causing a config-load failure, or cleanup code raising while handling an earlier error — Python does not discard the original. It *chains* them, preserving the full causal history via `__cause__`, `__context__`, and tracebacks. Understanding chaining, how to control it, and the new `ExceptionGroup`/`except*` machinery (3.11+) is essential for debugging and for writing libraries that wrap low-level errors in domain exceptions.

## Tracebacks — The Foundation

Every exception object carries a **traceback** — a linked list of frame objects describing the call stack at the point of raising.

```python
import traceback
import sys

def inner():
    raise ValueError("something bad in inner")

def outer():
    inner()

try:
    outer()
except ValueError as exc:
    # Three ways to inspect the traceback:
    print("--- 1. print_exc() ---")
    traceback.print_exc()

    print("\n--- 2. format_exc() as string ---")
    tb_str = traceback.format_exc()
    print(tb_str)

    print("\n--- 3. exc.__traceback__ object ---")
    tb = exc.__traceback__
    print(f"tb type: {type(tb)}")
    print(f"tb_frame: {tb.tb_frame}")
    print(f"tb_lineno: {tb.tb_lineno}")
    print(f"tb_next: {tb.tb_next}")  # linked list — next frame

    # Walk the stack manually:
    print("\n--- Walk ---")
    for line in traceback.format_exception(type(exc), exc, exc.__traceback__):
        print(line, end="")

    # New in 3.10: format_exception only needs exc
    if sys.version_info >= (3, 10):
        for line in traceback.format_exception(exc):
            pass  # same, exc carries type and tb

# Traceback is None until the exception is raised
exc = ValueError("not yet raised")
print(f"Before raise: __traceback__ = {exc.__traceback__}")  # None
try:
    raise exc
except ValueError as caught:
    print(f"After raise: __traceback__ is not None = {caught.__traceback__ is not None}")
```

**Key facts:**

| Attribute | Meaning |
|-----------|---------|
| `exc.__traceback__` | Traceback object or `None` (before raise). Set at `raise` time. |
| `exc.__traceback__.tb_frame` | Execution frame where exception occurred |
| `exc.__traceback__.tb_lineno` | Line number |
| `exc.__traceback__.tb_next` | Next (caller) frame's traceback, or `None` |
| `traceback.print_exc()` | Prints current exception's traceback to stderr |
| `traceback.format_exc()` | Returns traceback as string |

> **Note:** Traceback holds references to frames, which hold references to local variables. Keeping an exception alive (e.g., in a global) can keep large objects alive. Python clears `exc` at the end of `except` blocks partly for this reason (see 06.2).

### Chaining Adds More Tracebacks

When exceptions are chained, *each* exception in the chain has its own traceback. Printing shows them all:

```python
def read_config(path):
    with open(path) as f:
        import json
        return json.load(f)

def load_app_config():
    try:
        return read_config("missing.json")
    except FileNotFoundError as exc:
        raise RuntimeError("app config unavailable") from exc

try:
    load_app_config()
except RuntimeError as exc:
    traceback.print_exc()
    # Shows:
    #   Traceback (most recent call last):
    #     File "...", in load_app_config
    #       return read_config("missing.json")
    #     ...
    #   FileNotFoundError: [Errno 2] No such file ...
    #
    #   The above exception was the direct cause of the following exception:
    #
    #   Traceback (most recent call last):
    #     File "...", in load_app_config
    #       raise RuntimeError(...) from exc
    #   RuntimeError: app config unavailable
```

## Implicit Chaining — __context__

Python automatically chains exceptions when a new exception is raised *while handling* another. The original becomes `__context__`.

```python
# Implicit chaining — no 'from' keyword
try:
    try:
        raise ValueError("original failure")
    except ValueError as exc:
        print(f"Handling: {exc}")
        # Raising a NEW exception while handling the old one
        raise RuntimeError("handling failed")
except RuntimeError as exc:
    print(f"Caught: {exc}")
    print(f"__context__: {exc.__context__!r}")   # ValueError('original failure')
    print(f"__cause__: {exc.__cause__!r}")       # None — no explicit 'from'
    print(f"__suppress_context__: {exc.__suppress_context__}")  # False
    traceback.print_exc()
    # Output includes:
    #   ValueError: original failure
    #   During handling of the above exception, another exception occurred:
    #   RuntimeError: handling failed
```

**Explanation:** Python set `exc.__context__ = ValueError(...)` automatically. The traceback printer sees `__context__` and prints "During handling of the above exception...".

```python
# Implicit chaining also happens WITHOUT an except block — any active exception
# (In practice, this means inside an except or finally that was entered due to an exception)

# finally with exception — also implicit chaining
try:
    try:
        raise ValueError("original")
    finally:
        print("finally — raising new error")
        raise RuntimeError("cleanup failed")
except RuntimeError as exc:
    print(f"__context__: {exc.__context__!r}")  # ValueError('original')
    traceback.print_exc()
    # "During handling of the above exception, another exception occurred:"

# No active exception — no chaining
try:
    raise RuntimeError("standalone")
except RuntimeError as exc:
    print(f"__context__: {exc.__context__!r}")  # None — no prior active exception
```

**When implicit chaining happens:**

| Situation | Chaining? |
|-----------|-----------|
| `raise B` inside `except A:` block | Yes — `B.__context__ = A` |
| `raise B` inside `finally:` that was entered due to `A` | Yes — `B.__context__ = A` |
| `raise B` when no exception is being handled | No — `B.__context__ = None` |
| `raise B` inside `except A:` but after `exc = None` / cleared context | Still yes — context is captured at raise time from thread state |

## Explicit Chaining — raise ... from ... (__cause__)

Use `raise NewError(...) from original` to declare that the new exception was *directly caused by* the original. This sets `__cause__` and implies `__suppress_context__ = True`.

```python
# Explicit chaining — 'from exc'
try:
    try:
        raise ValueError("low-level failure")
    except ValueError as exc:
        raise RuntimeError("high-level failure") from exc
except RuntimeError as exc:
    print(f"__cause__: {exc.__cause__!r}")      # ValueError('low-level failure')
    print(f"__context__: {exc.__context__!r}")  # ValueError('low-level failure') — also set!
    print(f"__suppress_context__: {exc.__suppress_context__}")  # True
    traceback.print_exc()
    # Output says:
    #   ValueError: low-level failure
    #   The above exception was the direct cause of the following exception:
    #   RuntimeError: high-level failure

# 'from None' — suppress chaining entirely (see next section)
try:
    try:
        raise ValueError("low-level")
    except ValueError:
        raise RuntimeError("high-level") from None
except RuntimeError as exc:
    print(f"__cause__: {exc.__cause__!r}")      # None
    print(f"__context__: {exc.__context__!r}")  # ValueError — still there but suppressed!
    print(f"__suppress_context__: {exc.__suppress_context__}")  # True
    traceback.print_exc()
    # Only shows RuntimeError — context is hidden
```

### cause vs context — The Full Picture

Every exception has three chaining-related attributes:

| Attribute | Set by | Printed as | Suppressed when |
|-----------|--------|------------|-----------------|
| `__cause__` | `raise ... from cause` | "The above exception was the **direct cause**..." | Only if `cause is None` (i.e., `from None`) |
| `__context__` | Implicit chaining (raise while handling) | "During handling of the above exception, another exception occurred:" | When `__suppress_context__ is True` |
| `__suppress_context__` | `raise ... from ...` (any) | — | — |

**Priority:** If `__cause__` is not None, Python prints the cause chain and *ignores* context for display (even though `__context__` is still stored). If `__cause__` is None and `__suppress_context__` is True, nothing is printed. If `__cause__` is None and `__suppress_context__` is False, context is printed.

```python
# Demonstrating priority
# 1. cause takes precedence over context
try:
    try:
        raise ValueError("context value")
    except ValueError as exc:
        try:
            raise TypeError("cause value") from TypeError("explicit cause")
        except TypeError as inner:
            # inner.__context__ is ValueError, inner.__cause__ is TypeError("explicit cause")
            print(f"context: {inner.__context__!r}")
            print(f"cause: {inner.__cause__!r}")
            raise RuntimeError("outer") from inner
except RuntimeError as exc:
    print(f"outer cause: {exc.__cause__!r}")  # TypeError('cause value') chain
    print(f"outer context: {exc.__context__!r}")  # TypeError — but not printed, cause wins
    traceback.print_exc()
```

### When to Use Explicit Chaining

```python
# PATTERN 1: Wrapping a low-level error in a domain error — USE 'from exc'
import json

class ConfigError(Exception):
    pass

def load_config(path):
    try:
        with open(path) as f:
            return json.load(f)
    except FileNotFoundError as exc:
        # We ARE translating this error — preserve the cause
        raise ConfigError(f"config {path!r} not found") from exc
    except json.JSONDecodeError as exc:
        raise ConfigError(f"config {path!r} is invalid JSON") from exc
    except OSError as exc:
        raise ConfigError(f"cannot read config {path!r}") from exc

try:
    load_config("missing.json")
except ConfigError as exc:
    print(f"ConfigError: {exc}")
    print(f"Cause: {exc.__cause__!r}")  # FileNotFoundError — invaluable for debugging
    # traceback shows both — operator sees "ConfigError ... caused by FileNotFoundError"

# PATTERN 2: Raising a new error that REPLACES the old one — USE 'from None'
# When the original is an implementation detail that would confuse the caller

def parse_age(s):
    try:
        return int(s)
    except ValueError:
        # Caller passed "abc" — they don't need to see ValueError details
        # They need a domain error. Suppress the noisy low-level context.
        raise ValueError(f"invalid age {s!r}: must be an integer") from None

try:
    parse_age("abc")
except ValueError as exc:
    print(f"Error: {exc}")
    print(f"__cause__: {exc.__cause__!r}")    # None
    print(f"__context__ suppressed: {exc.__suppress_context__}")  # True
    traceback.print_exc()  # Only shows the new ValueError — clean

# PATTERN 3: Letting the original propagate — DON'T wrap
def read_data(path):
    # No try/except — let FileNotFoundError propagate directly
    # Wrapping would just add noise if caller can handle FileNotFoundError themselves
    with open(path) as f:
        return f.read()

# PATTERN 4: Bare 'raise' — re-raise without wrapping or chaining
def read_with_logging(path):
    try:
        with open(path) as f:
            return f.read()
    except OSError as exc:
        print(f"LOG: failed to read {path}: {exc}")
        raise  # re-raise same exception, same traceback, no new chaining
```

> **Idiom:** "Wrap and chain with `from exc`" when translating between abstraction layers. "Suppress with `from None`" when the original is noise. Bare `raise` when you log and re-raise the same error.

## Suppressing Context — from None in Depth

```python
# Without 'from None' — noisy double traceback
def without_suppression():
    try:
        int("not-a-number")
    except ValueError as exc:
        # New error, but traceback shows BOTH
        raise RuntimeError("processing failed") from exc  # or implicit

try:
    without_suppression()
except RuntimeError:
    traceback.print_exc()
    # Shows ValueError + "direct cause" + RuntimeError

# With 'from None' — clean single traceback
def with_suppression():
    try:
        int("not-a-number")
    except ValueError:
        raise RuntimeError("processing failed") from None

try:
    with_suppression()
except RuntimeError:
    traceback.print_exc()
    # Only shows RuntimeError — ValueError hidden

# When to suppress — checklist:
# - The original exception is an implementation detail (e.g., KeyError inside a cache miss that should be a CacheMissError)
# - The original message would confuse users (e.g., internal JSON error vs user-facing validation error)
# - You are intentionally replacing one error with a more appropriate one for the abstraction level

# Example — suppressing internal lookup as domain error
class Cache:
    def __init__(self):
        self._data = {}

    def get(self, key):
        try:
            return self._data[key]
        except KeyError:
            # Don't leak KeyError — it's an internal detail
            # Callers should handle CacheMissError, not KeyError
            from dataclasses import dataclass

            @dataclass
            class CacheMissError(LookupError):
                key: str
                def __str__(self):
                    return f"cache miss for {self.key!r}"

            raise CacheMissError(key) from None

try:
    Cache().get("missing")
except LookupError as exc:
    print(f"LookupError: {exc}")
    print(f"Cause: {exc.__cause__!r}")  # None — suppressed
    traceback.print_exc()  # Clean — only CacheMissError
```

**Important subtlety — `from None` still stores context, just suppresses display:**

```python
try:
    try:
        raise ValueError("original")
    except ValueError:
        raise RuntimeError("new") from None
except RuntimeError as exc:
    print(f"__context__ is still there: {exc.__context__!r}")  # ValueError('original')
    print(f"__cause__: {exc.__cause__!r}")  # None
    print(f"__suppress_context__: {exc.__suppress_context__}")  # True
    # __context__ is NOT None — it's just not printed
    # Programmatic access still works: exc.__context__ is available
    # To truly clear context: exc.__context__ = None (rarely needed)
```

## Manually Setting Chain Attributes

You can set `__cause__` and `__context__` directly, though `raise ... from ...` is preferred:

```python
# Manual — equivalent to 'raise RuntimeError(...) from exc'
exc = RuntimeError("high-level")
cause = ValueError("low-level")
exc.__cause__ = cause
exc.__suppress_context__ = True
raise exc
# Traceback will show "direct cause"

# Clearing context after the fact (rare)
try:
    try:
        raise ValueError("original")
    except ValueError:
        raise RuntimeError("new") from None
except RuntimeError as exc:
    print(f"Before clear: __context__={exc.__context__!r}")
    exc.__context__ = None
    print(f"After clear: __context__={exc.__context__!r}")
```

## Traceback Details — Advanced

### traceback Module Essentials

```python
import traceback

def level3():
    raise ValueError("deep error")

def level2():
    level3()

def level1():
    level2()

try:
    level1()
except ValueError as exc:
    # 1. Print to stderr (or file)
    traceback.print_exc()
    traceback.print_exc(file=open("/tmp/tb.txt", "w"))

    # 2. Get as string
    tb_str = traceback.format_exc()
    tb_list = traceback.format_exception(type(exc), exc, exc.__traceback__)
    tb_list2 = traceback.format_exception(exc)  # 3.10+ shorthand

    # 3. Extract structured data
    tb = exc.__traceback__
    extracted = traceback.extract_tb(tb)
    for frame in extracted:
        print(f"  File {frame.filename!r}, line {frame.lineno}, in {frame.name}")
        print(f"    {frame.line!r}")

    # 4. Print with limit / chain control
    traceback.print_exception(type(exc), exc, exc.__traceback__, limit=2, chain=True)
    # limit=2 — only show 2 frames
    # chain=True/False — whether to show cause/context chains

    # 5. Walk with StackSummary
    summary = traceback.extract_tb(exc.__traceback__)
    print(f"Frames: {len(summary)}")
    print("".join(traceback.format_list(summary)))
```

### Adding Notes to Exceptions (Python 3.11+)

```python
import sys

if sys.version_info >= (3, 11):
    try:
        raise ValueError("bad value")
    except ValueError as exc:
        exc.add_note("while processing user 123")
        exc.add_note("input was: {'age': -5}")
        print(f"Notes: {exc.__notes__}")
        traceback.print_exc()
        # Traceback now includes:
        #   ValueError: bad value
        #   while processing user 123
        #   input was: {'age': -5}
else:
    print("add_note requires Python 3.11+")

# Use case — enriching without wrapping
def process_users(users):
    for user in users:
        try:
            validate(user)
        except ValueError as exc:
            if sys.version_info >= (3, 11):
                exc.add_note(f"failed for user {user.get('id', '?')}")
            raise

def validate(user):
    if user.get("age", 0) < 0:
        raise ValueError(f"age cannot be negative: {user['age']}")

try:
    process_users([{"id": 1, "age": -5}])
except ValueError:
    traceback.print_exc()
```

### Exception Notes vs Chaining — When to Use Which

| Technique | Use when | Example |
|-----------|----------|---------|
| `raise NewError from exc` | Translating between abstraction layers | `ConfigError` from `FileNotFoundError` |
| `raise NewError from None` | Replacing a noisy internal error | `CacheMissError` from internal `KeyError` |
| `exc.add_note(...)` (3.11+) | Adding context without creating a new exception type | "while processing user 123" |
| Bare `raise` | Logging and re-raising the same error | Log then `raise` |
| `__context__` (implicit) | Automatic — indicates "another error happened during handling" | Debugging unexpected double failures |

## Exception Groups and except* (Python 3.11+)

Traditional `except` handles one exception at a time. Structured concurrency (`asyncio.TaskGroup`, `concurrent.futures`) can produce *multiple* simultaneous failures. `ExceptionGroup` + `except*` handle this.

### Creating and Raising ExceptionGroups

```python
import sys

if sys.version_info >= (3, 11):
    # Basic group
    try:
        raise ExceptionGroup("validation failed", [
            ValueError("age must be >= 0"),
            TypeError("name must be str"),
            ValueError("email must contain '@'"),
        ])
    except ExceptionGroup as eg:
        print(f"Message: {eg.message}")
        print(f"Count: {len(eg.exceptions)}")
        for sub in eg.exceptions:
            print(f"  {type(sub).__name__}: {sub}")
        print(f"Full: {eg!r}")

    # Groups can nest
    inner = ExceptionGroup("inner", [ValueError("a"), ValueError("b")])
    outer = ExceptionGroup("outer", [inner, TypeError("c")])
    print(f"Nested: {outer!r}")
    print(f"Outer len: {len(outer.exceptions)}")  # 2 (inner group + TypeError)

    # BaseExceptionGroup — can hold BaseExceptions
    try:
        raise BaseExceptionGroup("mixed", [
            ValueError("regular"),
            KeyboardInterrupt("interrupt"),
        ])
    except BaseExceptionGroup as beg:
        print(f"Base group: {beg.message}, count={len(beg.exceptions)}")
else:
    print("ExceptionGroup requires Python 3.11+ — install 'exceptiongroup' backport for earlier versions")
    # pip install exceptiongroup
    # from exceptiongroup import ExceptionGroup, BaseExceptionGroup
```

### except* — Filtering Groups by Type

`except*` is *not* `except`. It *filters* the group, handling matching sub-exceptions and leaving non-matching ones to propagate (possibly as a new group).

```python
import sys

if sys.version_info >= (3, 11):
    # except* handles matching sub-exceptions, re-raises non-matching as a group
    def demo_except_star():
        try:
            raise ExceptionGroup("multiple failures", [
                ValueError("bad value 1"),
                TypeError("bad type"),
                ValueError("bad value 2"),
                RuntimeError("runtime problem"),
            ])
        except* ValueError as eg:
            print(f"Handled ValueErrors: {[str(e) for e in eg.exceptions]}")
            # After this handler, the group still contains TypeError + RuntimeError
            # They propagate to the next handler or caller
        except* TypeError as eg:
            print(f"Handled TypeErrors: {[str(e) for e in eg.exceptions]}")
        except* RuntimeError as eg:
            print(f"Handled RuntimeErrors: {[str(e) for e in eg.exceptions]}")

    demo_except_star()
    print("All handled — no exception propagates")

    # Partial handling — unmatched sub-exceptions propagate
    try:
        try:
            raise ExceptionGroup("mixed", [
                ValueError("a"),
                RuntimeError("b"),  # no handler for this
            ])
        except* ValueError as eg:
            print(f"Handled ValueErrors: {[str(e) for e in eg.exceptions]}")
            # RuntimeError sub-group propagates!
    except ExceptionGroup as remaining:
        print(f"Remaining unhandled group: {remaining!r}")
        print(f"Remaining: {[type(e).__name__ for e in remaining.exceptions]}")

    # except* with else/finally
    try:
        raise ExceptionGroup("errors", [ValueError("a"), TypeError("b")])
    except* ValueError as eg:
        print(f"Values: {eg.exceptions}")
    except* TypeError as eg:
        print(f"Types: {eg.exceptions}")
    else:
        print("else — no exception at all (not reached if group raised)")
    finally:
        print("finally — always")

    # Splitting groups programmatically — without except*
    eg = ExceptionGroup("all", [
        ValueError("v1"), ValueError("v2"), TypeError("t1")
    ])
    # split by type — returns (matching, non_matching)
    matching, non_matching = eg.split(ValueError)
    print(f"Matching ValueError: {matching!r}")
    print(f"Non-matching: {non_matching!r}")

    # subgroup — keeps nesting structure, filters recursively
    eg2 = ExceptionGroup("nested", [
        ExceptionGroup("inner", [ValueError("v1"), TypeError("t1")]),
        ValueError("v2"),
    ])
    vals, rest = eg2.split(ValueError)
    print(f"Vals subgroup: {vals!r}")
    print(f"Rest subgroup: {rest!r}")

    # Bare 'except Exception' catches the WHOLE group as one object
    try:
        raise ExceptionGroup("group", [ValueError("a")])
    except Exception as exc:
        print(f"Caught group as single Exception: {type(exc).__name__}: {exc}")
        # To handle sub-exceptions, you need except* or .split()

else:
    print("except* requires Python 3.11+")
```

**Key differences — `except` vs `except*`:**

| Aspect | `except Type:` | `except* Type:` |
|--------|----------------|-----------------|
| Catches | Single exception matching Type | Sub-exceptions of a group matching Type |
| Group handling | Catches the group as one opaque object | Filters group, extracts matching sub-exceptions |
| Multiple handlers | First match wins, rest skipped | Each handler filters its type; handlers can *all* fire on different sub-exceptions |
| Bare propagation | If no match, propagates the original | If some sub-exceptions unmatched, propagates a *new* group with remaining |
| Valid outside group context | Yes | Yes — but if no group is raised, behaves like normal `except` for that type |

```python
# except* can handle non-group exceptions too (for uniformity)
import sys
if sys.version_info >= (3, 11):
    try:
        raise ValueError("single error — not a group")
    except* ValueError as eg:
        # When a non-group ValueError is caught by except*, eg is an ExceptionGroup
        # containing that single ValueError? No — actually, it IS caught!
        # In 3.11, except* can catch both groups and single exceptions
        print(f"except* caught single ValueError as group: {eg!r}")
        print(f"exceptions: {eg.exceptions}")
```

### Realistic Use — TaskGroup

```python
import sys

if sys.version_info >= (3, 11):
    import asyncio

    async def fetch(url):
        if "bad" in url:
            raise ValueError(f"bad url: {url}")
        if "timeout" in url:
            raise TimeoutError(f"timeout for {url}")
        return f"data from {url}"

    async def main():
        try:
            async with asyncio.TaskGroup() as tg:
                tg.create_task(fetch("https://good.example.com"))
                tg.create_task(fetch("https://bad.example.com"))
                tg.create_task(fetch("https://timeout.example.com"))
        except* ValueError as eg:
            print(f"ValueErrors: {[str(e) for e in eg.exceptions]}")
        except* TimeoutError as eg:
            print(f"Timeouts: {[str(e) for e in eg.exceptions]}")

    # asyncio.run(main())  # would demonstrate TaskGroup -> ExceptionGroup

# Validation pattern — collect all errors, raise as group
def validate_user(data):
    errors = []
    if not isinstance(data.get("name"), str):
        errors.append(TypeError("name must be str"))
    if not isinstance(data.get("age"), int) or data["age"] < 0:
        errors.append(ValueError("age must be non-negative int"))
    if "@" not in data.get("email", ""):
        errors.append(ValueError("email must contain '@'"))

    if errors:
        if sys.version_info >= (3, 11):
            raise ExceptionGroup("validation failed", errors)
        else:
            # Pre-3.11: raise first error, or aggregate message
            raise ValueError("; ".join(str(e) for e in errors))

try:
    validate_user({"name": 123, "age": -5, "email": "bad"})
except Exception as exc:
    print(f"Validation error: {exc}")
    if sys.version_info >= (3, 11) and isinstance(exc, ExceptionGroup):
        for sub in exc.exceptions:
            print(f"  - {type(sub).__name__}: {sub}")
```

## Putting It All Together — Chaining Decision Guide

```python
"""Complete chaining patterns — reference implementation."""

import json
import traceback

# Domain exceptions
class AppError(Exception): pass
class ConfigError(AppError): pass
class ValidationError(AppError, ValueError): pass

def load_config_v2(path):
    """Load config — demonstrates all chaining patterns."""
    try:
        with open(path) as f:
            data = json.load(f)
    except FileNotFoundError as exc:
        # Pattern: wrap with cause — caller needs to know WHY config failed
        raise ConfigError(f"config {path!r} not found") from exc
    except IsADirectoryError as exc:
        raise ConfigError(f"config path {path!r} is a directory") from exc
    except json.JSONDecodeError as exc:
        # JSON error has lineno/colno — preserve it via chaining
        raise ConfigError(f"config {path!r} is not valid JSON: {exc}") from exc
    except OSError as exc:
        raise ConfigError(f"cannot read config {path!r}") from exc

    # Validation — suppress low-level details, use domain error
    try:
        validate_config(data)
    except ValueError as exc:
        # validate_config raises ValueError with internal details
        # We want a clean ValidationError — but preserve cause for debugging?
        # Choice A: chain (debugging needs cause)
        raise ValidationError(f"invalid config in {path!r}: {exc}") from exc
        # Choice B: suppress (user-facing, internal details are noise)
        # raise ValidationError(f"invalid config in {path!r}: {exc}") from None
    return data

def validate_config(data):
    if "version" not in data:
        raise ValueError("missing 'version' key")
    if not isinstance(data["version"], int):
        raise ValueError(f"version must be int, got {type(data['version']).__name__}")

# Caller handling
for path in ["missing.json", "/tmp", "bad.json"]:
    # Create bad.json for demo
    import os, tempfile
    if path == "bad.json":
        fd, bad_path = tempfile.mkstemp(suffix=".json")
        os.write(fd, b"{not valid json")
        os.close(fd)
        path = bad_path
    try:
        load_config_v2(path)
    except ValidationError as exc:
        print(f"Validation: {exc}")
        print(f"  cause: {exc.__cause__!r}")
    except ConfigError as exc:
        print(f"Config: {exc}")
        print(f"  cause type: {type(exc.__cause__).__name__ if exc.__cause__ else None}")
        # traceback shows full chain
        traceback.print_exc(limit=5)
    except AppError as exc:
        print(f"App: {exc}")
    finally:
        if path.endswith(".json") and os.path.exists(path) and "tmp" in path:
            os.unlink(path)
```

## Common Mistakes

### Mistake 1: Losing the Cause by Forgetting from

```python
# BAD — original traceback lost
try:
    int("bad")
except ValueError:
    raise RuntimeError("processing failed")  # implicit chaining — says "During handling..."
    # Less clear than "direct cause", and easily confused with accidental double-fault

# GOOD — explicit cause
try:
    int("bad")
except ValueError as exc:
    raise RuntimeError("processing failed") from exc  # "direct cause" — intentional wrapping

# Also BAD — bare raise loses domain translation
try:
    int("bad")
except ValueError as exc:
    print(f"Log: {exc}")
    raise  # re-raises ValueError — caller sees low-level error, not domain error
    # If you need domain translation, wrap with 'from exc'
```

### Mistake 2: Over-Suppressing with from None

```python
# BAD — debugging becomes impossible
try:
    load_config("missing.json")
except FileNotFoundError:
    raise ConfigError("config failed") from None  # WHY did it fail? No cause!

# GOOD — preserve cause unless you have a reason to hide it
try:
    load_config("missing.json")
except FileNotFoundError as exc:
    raise ConfigError("config failed") from exc  # cause tells you: file not found
```

### Mistake 3: Catching the Group as a Single Exception

```python
import sys
if sys.version_info >= (3, 11):
    try:
        raise ExceptionGroup("errors", [ValueError("a"), TypeError("b")])
    except Exception as exc:
        # Catches the group, but you only see the group message — sub-exceptions hidden!
        print(f"Caught as Exception: {exc}")  # "errors (2 sub-exceptions)"
        # You lost per-exception handling!

    # Correct — use except* to handle sub-exceptions
    try:
        raise ExceptionGroup("errors", [ValueError("a"), TypeError("b")])
    except* ValueError as eg:
        print(f"Values: {eg.exceptions}")
    except* TypeError as eg:
        print(f"Types: {eg.exceptions}")
```

## Summary

- **Traceback** (`__traceback__`) records the call stack at `raise` time. Each exception in a chain has its own.
- **`__context__`** (implicit): set automatically when `raise B` happens while handling `A`. Displayed as *"During handling of the above exception, another exception occurred"*.
- **`__cause__`** (explicit): set by `raise B from A`. Displayed as *"The above exception was the direct cause of the following exception"* and takes display priority over context.
- **`raise ... from None`** suppresses the chain display (sets `__suppress_context__ = True`), hiding implementation-detail exceptions. `__context__` is still stored but not printed.
- **`raise`** (bare) re-raises the current exception with its original traceback — no new chaining.
- **`ExceptionGroup` / `BaseExceptionGroup` (3.11+)** bundle multiple exceptions. Handle them with **`except*`**, which filters sub-exceptions by type; unmatched sub-exceptions propagate as a new group. Use `.split()` / `.subgroup()` for programmatic filtering.
- **`add_note()` (3.11+)** enriches an exception without wrapping — useful for adding "while processing X" context.
- **Choose:** `from exc` for intentional wrapping across abstraction layers, `from None` to hide internal noise, bare `raise` to log-and-re-raise, and implicit chaining is usually a sign of an accidental second failure during handling.
