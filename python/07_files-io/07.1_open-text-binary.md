# 07.1 open — Text and Binary Modes

> `open()` looks trivial — `open("file.txt").read()` — until you ship code that
> corrupts data on Windows, crashes on a French user's machine, or silently mangles
> UTF-8. This lesson dissects `open()` completely: modes, text vs binary, encoding,
> newlines, buffering, and the file object's API.

## Why `open()` Deserves a Full Lesson

If you come from C, Java, Go, or Rust you already know file I/O. Python adds two
wrinkles that bite even experienced programmers:

1. **Text vs binary is a strict split.** You cannot read `str` from a binary file
   or `bytes` from a text file. The boundary is enforced by the type system.
2. **Encoding is not optional.** Python 3 `str` is Unicode. Every text file must be
   decoded on the way in and encoded on the way out. The default encoding is
   *locale-dependent* — a portability trap.

Understanding these two facts prevents 90% of file-related bugs.

---

## 1. The `open()` Built-in — Signature

```python
open(
    file,              # path-like object or int file descriptor
    mode="r",          # str: how to open
    buffering=-1,      # int: buffering policy
    encoding=None,     # str | None: text mode only
    errors=None,       # str | None: how to handle encoding errors
    newline=None,      # str | None: how to handle line endings (text mode)
    closefd=True,      # bool: close the fd when file is closed?
    opener=None,       # callable | None: custom opener
)
```

The return value is a *file object* (an `io` class) — not a file descriptor, not
a path.

### Minimal Examples

```python
# Simple: open for reading text, rely on defaults (fragile — see encoding below)
f = open("data.txt")
text = f.read()
f.close()

# Better: be explicit about encoding even when it "works by accident"
f = open("data.txt", encoding="utf-8")
text = f.read()
f.close()

# Idiomatic (but we will improve with `with` in §7.2):
with open("data.txt", encoding="utf-8") as f:
    text = f.read()
```

> **File descriptors vs file objects:** `open(3)` where `3` is an `int` wraps an
> already-open OS file descriptor. `closefd=False` keeps the descriptor open when
> the file object is closed. Rarely needed outside low-level code.

## 2. Modes — A Complete Reference

Mode is a short string. The first character selects the base operation; modifiers
change creation, truncation, and read/write capability.

### 2.1 Base Modes

| Mode | Meaning | File must exist? | Truncates? | Cursor | Typical use |
|------|---------|------------------|------------|--------|-------------|
| `r`  | **read** | yes → `FileNotFoundError` | no | start | Reading |
| `w`  | **write** | no → creates; yes → **truncates to 0** | **yes** | start | Fresh output |
| `a`  | **append** | no → creates | no | **end** | Logs |
| `x`  | **exclusive creation** | no → creates; yes → `FileExistsError` | no | start | Lock files, safe creation |

### 2.2 Modifiers

| Modifier | Effect | Combined example | Meaning |
|----------|--------|------------------|---------|
| `b` | binary | `rb`, `wb` | No encoding / newline translation |
| `t` | text (default) | `rt`, `wt` | Decode / encode `str` |
| `+` | update (read + write) | `r+`, `w+`, `a+` | Bidirectional |

> `t` is the default. `open("f.txt", "r")` is `open("f.txt", "rt")`. You never
> need to write `t` explicitly — but you *must* write `b` when you mean binary.

### 2.3 Common Combinations

| Mode | Description |
|------|-------------|
| `r` / `rt` | Read text. Fails if missing. |
| `rb` | Read binary. |
| `w` / `wt` | Write text, clobber. |
| `wb` | Write binary, clobber. |
| `a` | Append text. |
| `ab` | Append binary. |
| `x` | Create text, fail if exists. |
| `xb` | Create binary, fail if exists. |
| `r+` | Read + write text without truncating. Cursor at 0. |
| `w+` | Read + write text, truncates first. |
| `a+` | Read + append text. Writes always at end; reads anywhere after `seek`. |

### 2.4 Examples — Mode Behaviour

```python
# r: fails if missing
try:
    f = open("missing.txt", encoding="utf-8")
except FileNotFoundError as exc:
    print(f"not found: {exc}")

# w: silently destroys previous contents!
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("fresh\n")

# x: safe creation — atomic check-and-create at OS level
try:
    with open("output.txt", "x", encoding="utf-8") as f:
        f.write("only if absent\n")
except FileExistsError:
    print("output.txt already exists — refusing to overwrite")

# a: append never overwrites existing data
with open("app.log", "a", encoding="utf-8") as f:
    f.write("new log line\n")

# r+ vs w+: the truncation trap
with open("counter.txt", "w", encoding="utf-8") as f:
    f.write("10\n")

with open("counter.txt", "r+", encoding="utf-8") as f:
    value = int(f.read().strip())
    f.seek(0)
    f.write(str(value + 1))
    f.truncate()  # without this, leftover bytes remain if new value is shorter
    print(f"incremented to {value + 1}")
```

**Explanation:** The last block demonstrates the canonical `r+` pattern. `seek(0)`
rewinds; `truncate()` cuts the file at the current position so that writing `"9\n"`
over `"10\n"` does not leave `"9\n\n"` (or `"90\n"` without correct truncation).

> **Common mistake — `w+` when you meant `r+`:**
> ```python
> # BUG: w+ truncates immediately, so read() always returns ""
> with open("counter.txt", "w+", encoding="utf-8") as f:
>     old = f.read()  # "" — file was just emptied!
> ```

#### Why `x` Matters

`x` (since Python 3.3) eliminates a TOCTOU race when two processes try to create
the same file. The old pattern:

```python
import os
if not os.path.exists("lock"):
    open("lock", "w").close()  # race: another process could create it here!
```

Atomic replacement:

```python
try:
    with open("lock", "x", encoding="utf-8") as f:
        f.write(str(os.getpid()))
except FileExistsError:
    print("another instance is running")
```

## 3. Text vs Binary — The Fundamental Split

|  | Text mode (`t`) | Binary mode (`b`) |
|---|---|---|
| `read()` returns | `str` | `bytes` |
| `write()` accepts | `str` | `bytes` (or `bytearray`, `memoryview`) |
| `encoding` | **required** (or locale default) | **forbidden** (`ValueError` if given) |
| `newline` | active (universal newlines) | disabled |
| `errors` | active | n/a |
| Line iteration | yields `str` lines | yields `bytes` lines |

```python
# Text mode — you get str
with open("hello.txt", "w", encoding="utf-8") as f:
    f.write("héllo 🌍\n")  # str

with open("hello.txt", encoding="utf-8") as f:
    s = f.read()
    print(type(s), repr(s))  # <class 'str'> 'héllo 🌍\n'

# Binary mode — you get bytes
with open("hello.txt", "rb") as f:
    b = f.read()
    print(type(b), b)  # <class 'bytes'> b'h\xc3\xa9llo \xf0\x9f\x8c\x8d\n'

# Mixing types is a hard error
with open("hello.txt", "w", encoding="utf-8") as f:
    try:
        f.write(b"bytes")  # type: ignore
    except TypeError as exc:
        print(exc)  # write() argument must be str, not bytes

with open("hello.txt", "wb") as f:
    try:
        f.write("str")  # type: ignore
    except TypeError as exc:
        print(exc)  # a bytes-like object is required, not 'str'
```

**Why the split?**

* In Python 3, `str` is an immutable sequence of Unicode code points, `bytes` is
  an immutable sequence of 0–255 values. Text mode bridges them via an *encoding*.
  Binary mode leaves bytes untouched, exactly as the OS stores them.
* This prevents the classic Python 2 bug where text and bytes were conflated and
  mojibake appeared far from the source.

### When to Use Which

- **Text mode:** configuration, CSV, JSON, source code, logs, anything human-readable
  where *characters* matter.
- **Binary mode:** images, PDFs, zip files, `pickle`, protobuf, encrypted data, or
  any format specified in bytes. Also when you need exact byte control (e.g., you
  will decode manually).

## 4. Encoding — Never Rely on the Locale

### 4.1 The Default Is Dangerous

If you omit `encoding`, Python calls `locale.getpreferredencoding(False)`:

```python
import locale
print(locale.getpreferredencoding(False))
# On many Linux containers: UTF-8
# On US Windows: cp1252
# On Japanese Windows: cp932
```

Code that works on your machine may `UnicodeDecodeError` or silently produce
mojibake on another machine. **Always pass `encoding` explicitly for text files.**

> **Python 3.15 / PEP 686 (Python 3.15+):** CPython is moving toward making
> `encoding="utf-8"` the default when no encoding is specified (UTF-8 mode).
> Do not rely on this transition — explicit is still better than implicit, and
> your code may run on older interpreters.

### 4.2 Common Encodings

| Encoding | What it is | When to use |
|----------|------------|-------------|
| `utf-8` | Variable-width Unicode, ASCII-compatible | **Default for new files** |
| `utf-8-sig` | UTF-8 with optional BOM handling | Reading files from Windows tools (Notepad, Excel) that emit a BOM |
| `ascii` | 7-bit | Only when spec says ASCII |
| `latin-1` / `iso-8859-1` | Single-byte, maps 0–255 directly | Legacy Western European data |
| `cp1252` | Windows Western European | Legacy Windows files |
| `utf-16`, `utf-32` | Fixed/variable width | Rare; Windows APIs, some Java interop |

```python
# Writing and reading UTF-8 (canonical)
with open("utf8.txt", "w", encoding="utf-8") as f:
    f.write("café — naïve — résumé\n")

with open("utf8.txt", encoding="utf-8") as f:
    print(f.read())

# latin-1 can decode ANY byte 0-255 — it never raises, but may produce garbage
with open("utf8.txt", "rb") as f:
    raw = f.read()
print(raw.decode("latin-1"))  # mojibake: cafÃ© ...

# utf-8-sig strips the BOM if present, harmless if absent
with open("with_bom.txt", "w", encoding="utf-8-sig") as f:
    f.write("hello\n")

with open("with_bom.txt", encoding="utf-8-sig") as f:
    print(repr(f.read()))  # 'hello\n' — no \ufeff

with open("with_bom.txt", encoding="utf-8") as f:
    print(repr(f.read()))  # '\ufeffhello\n' — BOM leaks as a character!
```

### 4.3 The `errors` Parameter — Handling Bad Data

`errors` controls what happens when bytes cannot be decoded (reading) or characters
cannot be encoded (writing).

| Strategy | Behaviour | Example (decoding `b"\xff"`) |
|----------|-----------|------------------------------|
| `strict` (default) | Raise `UnicodeDecodeError` / `UnicodeEncodeError` | exception |
| `ignore` | Silently skip | `""` |
| `replace` | Replace with `�` (U+FFFD) on decode, `?` on encode | `"�"` |
| `surrogateescape` | Map undecodable bytes to surrogates U+DC80–U+DCFF | `"\udcff"` (round-trippable) |
| `backslashreplace` | Insert `\xNN` escapes | `"\\xff"` |
| `namereplace` | Insert `\N{...}` escapes (encode only) | — |
| `xmlcharrefreplace` | Insert `&#NNN;` (encode only) | — |

```python
bad = b"hello \xff world"

# strict — good for catching corruption early
try:
    print(bad.decode("utf-8"))  # strict by default
except UnicodeDecodeError as exc:
    print(f"decode failed at {exc.start}: {exc.reason}")

# replace — good for displaying user data where loss is acceptable
print(bad.decode("utf-8", errors="replace"))  # hello � world

# surrogateescape — good for round-tripping arbitrary bytes through str
# (used by the OS file-system encoding)
s = bad.decode("utf-8", errors="surrogateescape")
print(repr(s))  # 'hello \udcff world'
print(s.encode("utf-8", errors="surrogateescape") == bad)  # True

# ignore — dangerous, loses data silently; avoid unless you really mean it
print(bad.decode("utf-8", errors="ignore"))  # hello  world
```

**Guidance:**

- Use `strict` (default) for files you control.
- Use `replace` for logs / user-facing display where you prefer `�` to a crash.
- Use `surrogateescape` when you must preserve arbitrary bytes on POSIX file systems.
- Never use `ignore` for data you care about — prefer `replace` so corruption is visible.

### 4.4 Encoding Pitfalls — A Field Guide

```python
# Pitfall 1: Writing with one encoding, reading with another
with open("pitfall.txt", "w", encoding="cp1252") as f:
    f.write("€ — euro sign\n")  # € is 0x80 in cp1252

with open("pitfall.txt", encoding="utf-8") as f:
    try:
        print(f.read())
    except UnicodeDecodeError as exc:
        print(f"mismatch: {exc}")  # 0x80 is invalid in UTF-8

# Pitfall 2: Forgetting encoding on write — locale decides, file becomes non-portable
# Bad:
# with open("out.txt", "w") as f:   # on Windows cp1252, on Linux utf-8
#     f.write("café")

# Good:
with open("out.txt", "w", encoding="utf-8") as f:
    f.write("café")

# Pitfall 3: Double-encoding — encoding an already-encoded string
s = "café"
b = s.encode("utf-8")       # b'caf\xc3\xa9'
# b.decode("utf-8").encode("latin-1")  # wrong chain produces mojibake
```

> **Rule of thumb:** Decode early, encode late, and name your encodings.

## 5. Newline Handling — `newline` Parameter

Python implements *universal newlines*: on read, `\r`, `\n`, and `\r\n` are all
recognised as line boundaries. The `newline` parameter controls translation.

| `newline` | On read (input) | On write (output) |
|-----------|-----------------|-------------------|
| `None` (default) | Translate `\r`, `\r\n` → `\n`; `read()` returns `\n` | Translate `\n` → `os.linesep` (`\r\n` on Windows) |
| `""` | No translation on read, but universal mode: all endings recognised; returned as-is | No translation |
| `"\n"` | Only `\n` is a line break | `\n` unchanged |
| `"\r\n"` | Only `\r\n` is a line break | `\n` → `\r\n` |
| `"\r"` | Only `\r` is a line break | `\n` → `\r` |

```python
# Default: reading a Windows file on Linux still gives \n
# (assume win.txt contains "a\r\nb\r\n")
with open("win.txt", encoding="utf-8", newline=None) as f:
    print(repr(f.read()))  # 'a\nb\n'
    print(f.newlines)      # '\r\n' — remembers what was seen (str or tuple)

# newline="" preserves endings as stored — useful when you need fidelity
with open("win.txt", encoding="utf-8", newline="") as f:
    print(repr(f.read()))  # 'a\r\nb\r\n'

# Writing with explicit newline: force \n even on Windows
with open("unix_out.txt", "w", encoding="utf-8", newline="\n") as f:
    f.write("line1\nline2\n")  # stored as \n regardless of OS

# csv module REQUIRES newline="" — see lesson 07.4
import csv
with open("data.csv", "w", encoding="utf-8", newline="") as f:
    w = csv.writer(f)
    w.writerow(["a", "b"])
```

> **Key distinction:** `newline` only applies in *text* mode. In binary mode newlines
> are never translated — you get raw bytes.

### The `f.newlines` Attribute

After reading, a text file object exposes `f.newlines` — `None`, a string (`"\n"`,
`"\r\n"`, `"\r"`), or a tuple of seen endings. Useful for detecting a file's
convention.

## 6. Buffering

```python
open("file.txt", "w", encoding="utf-8", buffering=-1)  # default
```

| `buffering` | Meaning |
|-------------|---------|
| `-1` (default) | System default: usually 8192 bytes / `io.DEFAULT_BUFFER_SIZE` |
| `0` | Unbuffered — **only allowed in binary mode** |
| `1` | Line-buffered — flush on `\n` (only in text mode) |
| `>1` | Fixed buffer size in bytes |
| `None` is not valid; use `-1` |

```python
# Unbuffered binary — every write goes straight to the OS
with open("raw.bin", "wb", buffering=0) as f:
    f.write(b"x")

# Line-buffered text — ideal for logs you tail -f
with open("live.log", "w", encoding="utf-8", buffering=1) as f:
    f.write("started\n")  # flushed immediately
    f.write("processing")  # buffered until \n or flush()

# Fully buffered (default) — fastest, but data may sit in memory
with open("bulk.txt", "w", encoding="utf-8", buffering=8192) as f:
    for i in range(100_000):
        f.write(f"{i}\n")
    # implicit flush on close
```

> `flush()` forces buffered data to the OS. `os.fsync(f.fileno())` forces the OS
> to flush to disk — needed for durability guarantees (databases, crash recovery).

## 7. The File Object API

Opening returns an `io` object with a rich interface.

### 7.1 Hierarchy

```
io.RawIOBase          — raw bytes (os.read)
  └─ io.BufferedIOBase — buffered bytes (BufferedReader/Writer)
       └─ io.TextIOBase  — str layer (TextIOWrapper)  ← text mode
```

`open()` picks the right class for you.

### 7.2 Reading Methods

```python
with open("sample.txt", "w", encoding="utf-8") as f:
    f.write("alpha\nbeta\ngamma\n")

# read(size=-1) — read all (or up to size chars/bytes)
with open("sample.txt", encoding="utf-8") as f:
    print(repr(f.read()))       # 'alpha\nbeta\ngamma\n'
    f.seek(0)
    print(repr(f.read(5)))      # 'alpha' — 5 characters

# readline(size=-1) — one line, keeps trailing \n (if present)
with open("sample.txt", encoding="utf-8") as f:
    print(repr(f.readline()))   # 'alpha\n'
    print(repr(f.readline()))   # 'beta\n'
    print(repr(f.readline(2)))  # 'ga' — limit even mid-line

# readlines(hint=-1) — list of lines; hint is soft byte/char limit
with open("sample.txt", encoding="utf-8") as f:
    lines = f.readlines()
    print(lines)  # ['alpha\n', 'beta\n', 'gamma\n']

# Iteration — lazy, memory-efficient, THE idiomatic way for large files
with open("sample.txt", encoding="utf-8") as f:
    for line in f:  # same as for line in iter(f.readline, "")
        print(line.rstrip("\n"))
```

> **Memory warning:** `read()` and `readlines()` slurp the whole file. For
> multi-GB logs, iterate instead.

```python
# Realistic: processing a 10 GB log without loading it
from collections import Counter

counts: Counter[str] = Counter()
with open("huge.log", encoding="utf-8", errors="replace") as f:
    for raw_line in f:
        line = raw_line.strip()
        if not line or line.startswith("#"):
            continue
        level = line.split()[0]  # e.g. "ERROR ..."
        counts[level] += 1
print(counts)
```

### 7.3 Writing Methods

```python
with open("out.txt", "w", encoding="utf-8") as f:
    n = f.write("hello\n")       # returns number of characters written
    print(n)                      # 6
    f.writelines(["a\n", "b\n"])  # takes iterable of str — does NOT add newlines!
    # writelines is just: for chunk in lines: f.write(chunk)

# writelines pitfall: it does not add separators
lines = ["first", "second", "third"]
with open("out.txt", "w", encoding="utf-8") as f:
    f.writelines(lines)             # file contains "firstsecondthird"!
    # Correct:
    f.seek(0); f.truncate()
    f.writelines(line + "\n" for line in lines)
```

### 7.4 Positioning — `seek`, `tell`, `truncate`

```python
with open("seek_demo.txt", "w+", encoding="utf-8") as f:
    f.write("0123456789")
    print(f.tell())          # 10 — position after write

    f.seek(0)                # absolute from start (whence=0)
    print(repr(f.read(3)))   # '012'

    f.seek(2, 1)             # 2 forward from current (whence=1)
    print(repr(f.read(3)))   # '567'  (was at 3, now at 5)

    f.seek(-3, 2)            # 3 before end (whence=2)
    print(repr(f.read()))    # '789'

    f.seek(0)
    f.truncate(5)            # cut to 5 chars
    f.seek(0)
    print(repr(f.read()))    # '01234'
```

| `whence` | Meaning | Text-mode restriction |
|----------|---------|-----------------------|
| `0` | From start (default) | Any offset |
| `1` | From current | Only offset `0` (or via `tell()`) |
| `2` | From end | Only offset `0` (or via `tell()`) |

> In text mode, `seek` offsets are opaque except for `0` and values returned by
> `tell()`. Non-zero offsets with `whence=1,2` may raise `OSError` because
> variable-width encodings make byte offsets ambiguous. For precise byte seeking,
> use binary mode.

### 7.5 Other Attributes and Methods

```python
with open("sample.txt", encoding="utf-8") as f:
    print(f.name)        # 'sample.txt'
    print(f.mode)        # 'r'
    print(f.encoding)    # 'utf-8'
    print(f.errors)      # 'strict'
    print(f.newlines)    # None until you read
    print(f.readable())  # True
    print(f.writable())  # False
    print(f.seekable())  # True
    print(f.closed)      # False

print(f.closed)          # True — after with block

# File-like duck-typing: some functions accept any object with read()/write()
import io
buf = io.StringIO("in-memory text")
print(buf.read())

buf2 = io.BytesIO(b"in-memory bytes")
print(buf2.read())
```

## 8. Closing — Why It Matters and How to Get It Right

### 8.1 What Happens If You Don't Close

- **Data loss:** Buffered writes may never reach disk.
- **File descriptor leak:** OS limits open descriptors (often 1024). Leaking in a
  loop will eventually raise `OSError: [Errno 24] Too many open files`.
- **Locking on Windows:** Open files cannot be deleted/renamed by other processes.

```python
# Anti-pattern: leak in a loop
for i in range(10_000):
    f = open(f"tmp_{i}.txt", "w", encoding="utf-8")
    f.write("x")
    # forgot f.close() — on iteration 1024 you may hit EMFILE
```

### 8.2 Explicit Close with `try/finally`

```python
f = open("data.txt", encoding="utf-8")
try:
    process(f.read())
finally:
    f.close()  # runs even if process() raises
```

This is correct but verbose. The `with` statement (lesson 07.2) automates it.

### 8.3 `close()`, `flush()`, and `__del__`

- `flush()` pushes buffers to the OS — does *not* guarantee disk persistence.
- `close()` flushes then releases the descriptor. After `close()`, any operation
  raises `ValueError: I/O operation on closed file`.
- `__del__` may close the file when garbage-collected, but GC timing is
  implementation-dependent (CPython refcounts promptly; PyPy does not). **Never
  rely on `__del__` for correctness.**

```python
f = open("tmp.txt", "w", encoding="utf-8")
f.write("hello")
print(f.closed)  # False
f.close()
print(f.closed)  # True
try:
    f.write("oops")
except ValueError as exc:
    print(exc)
```

## 9. Binary Handling — Working with `bytes`

Binary mode is simpler: no encoding, no newlines, no `errors`.

```python
# Writing a custom binary header: magic + version + length-prefixed payload
import struct

payload = b"hello world"
with open("archive.bin", "wb") as f:
    f.write(b"\x89BIN")                        # magic bytes
    f.write(struct.pack(">H", 1))               # version 1, big-endian uint16
    f.write(struct.pack(">I", len(payload)))    # length, big-endian uint32
    f.write(payload)

# Reading it back
with open("archive.bin", "rb") as f:
    magic = f.read(4)
    assert magic == b"\x89BIN", "not a BIN file"
    (version,) = struct.unpack(">H", f.read(2))
    (length,) = struct.unpack(">I", f.read(4))
    data = f.read(length)
    print(f"v{version}: {data!r}")  # v1: b'hello world'
    # Extra bytes? File may be truncated or concatenated:
    remainder = f.read()
    if remainder:
        print(f"warning: {len(remainder)} trailing bytes")
```

### Binary Iteration and Chunking

```python
# Chunked copy — constant memory regardless of file size
def copy_binary(src: str, dst: str, chunk: int = 8192) -> None:
    with open(src, "rb") as fin, open(dst, "wb") as fout:
        while True:
            data = fin.read(chunk)
            if not data:
                break
            fout.write(data)

# Iterating binary lines (lines delimited by b"\n")
with open("archive.bin", "rb") as f:
    for line in f:
        # line is bytes, includes trailing b"\n" if present
        print(line)
```

> Binary reads return `b""` at EOF. Text reads return `""`.

### `bytes` vs `bytearray` vs `memoryview`

- `bytes` — immutable, the default from `read()`.
- `bytearray` — mutable, writable with `write()` if you need in-place edits.
- `memoryview` — zero-copy view; useful for slicing large buffers without copying.

```python
with open("archive.bin", "rb") as f:
    data = f.read()

view = memoryview(data)
header = view[:4]  # no copy
print(bytes(header))
```

## 10. Realistic End-to-End Examples

### Example 1: Robust Text Reader — Encoding Detection & Fallback

```python
from pathlib import Path

def read_text_robust(path: str | Path, *, encoding: str = "utf-8") -> str:
    """Try UTF-8 first, fall back to latin-1 with a warning.

    In production, consider `charset-normalizer` or `chardet` for guessing.
    """
    p = Path(path)
    try:
        return p.read_text(encoding=encoding)  # strict by default
    except UnicodeDecodeError as exc:
        print(f"warning: {p} is not {encoding}: {exc}; trying latin-1")
        return p.read_text(encoding="latin-1")


print(read_text_robust("sample.txt"))
```

### Example 2: Atomic Write — Never Leave a Half-Written File

A crash mid-write should not corrupt the output.

```python
import os
import tempfile
from pathlib import Path

def atomic_write_text(path: str | Path, content: str, *, encoding: str = "utf-8") -> None:
    """Write atomically: create temp file in same directory, then rename."""
    p = Path(path)
    fd, tmp = tempfile.mkstemp(dir=str(p.parent), text=True)
    try:
        with os.fdopen(fd, "w", encoding=encoding, newline="\n") as f:
            f.write(content)
            f.flush()
            os.fsync(f.fileno())  # durability — optional but strong
        os.replace(tmp, p)  # atomic on POSIX and modern Windows
    finally:
        # If replace failed, clean up temp
        try:
            os.unlink(tmp)
        except FileNotFoundError:
            pass
```

**Why this works:** `os.replace` is atomic — readers see either the old or the
new file, never a half-written one. `mkstemp` in the same directory guarantees
the rename does not cross filesystem boundaries (which would make it non-atomic).

### Example 3: Merging Large CSV-like Files Without Loading Them

```python
def merge_sorted_files(inputs: list[str], output: str) -> None:
    """Merge pre-sorted text files line-by-line."""
    handles = [open(p, encoding="utf-8") for p in inputs]
    try:
        with open(output, "w", encoding="utf-8", newline="\n") as out:
            # naive merge: round-robin for demo; real code would heap-merge
            for fh in handles:
                for line in fh:
                    out.write(line)
    finally:
        for fh in handles:
            fh.close()
```

### Example 4: Binary Protocol With `struct` and Buffered I/O

```python
import struct

RECORD_FMT = ">Id"  # big-endian: uint32 id, float64 value
RECORD_SIZE = struct.calcsize(RECORD_FMT)  # 12 bytes

def write_records(path: str, records: list[tuple[int, float]]) -> None:
    with open(path, "wb", buffering=8192) as f:
        for rec_id, val in records:
            f.write(struct.pack(RECORD_FMT, rec_id, val))

def read_records(path: str) -> list[tuple[int, float]]:
    out: list[tuple[int, float]] = []
    with open(path, "rb") as f:
        while True:
            chunk = f.read(RECORD_SIZE)
            if not chunk:
                break
            if len(chunk) != RECORD_SIZE:
                raise ValueError(f"truncated record: got {len(chunk)} bytes")
            out.append(struct.unpack(RECORD_FMT, chunk))
    return out
```

## 11. Pitfalls, Edge Cases, and How to Avoid Them

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| Omitting `encoding` | Works locally, fails in prod / on Windows | Always pass `encoding="utf-8"` (or appropriate) |
| `w` instead of `x` | Silently overwrites | Use `x` when you must not clobber |
| Forgetting `truncate()` after `seek(0)` + shorter write | Trailing garbage | Call `f.truncate()` |
| `writelines` without adding `\n` | Concatenated line | Join with `"\n"` or generator |
| Seeking in text mode with arbitrary offset | `OSError` / wrong position | Use binary mode or only `tell()` offsets |
| `newline=None` default surprise on Windows | `\r\n` appears in output | Pass `newline="\n"` if you want portable `\n` |
| Reading entire file with `read()` on huge input | OOM | Iterate `for line in f:` or chunk `read(8192)` |
| Leaking descriptors in loop | `OSError: Too many open files` | Use `with` (next lesson) |
| BOM (`\ufeff`) at start of file | Invisible character breaks parsing | Use `encoding="utf-8-sig"` when reading |
| Double-decoding / wrong chain | Mojibake | Trace encoding at every boundary |
| Opening CSV without `newline=""` | Blank lines on Windows | `open(..., newline="")` |

## 12. Quick-Reference — Which Call to Use?

```python
# Read entire text file (small files only)
text = Path("file.txt").read_text(encoding="utf-8")
# or
with open("file.txt", encoding="utf-8") as f:
    text = f.read()

# Stream text file line by line
with open("file.txt", encoding="utf-8") as f:
    for line in f:
        process(line)

# Write text atomically
with open("file.txt", "w", encoding="utf-8", newline="\n") as f:
    f.write(content)

# Read binary file
with open("file.bin", "rb") as f:
    data = f.read()

# Copy binary safely, constant memory
with open("src.bin", "rb") as src, open("dst.bin", "wb") as dst:
    for chunk in iter(lambda: src.read(8192), b""):
        dst.write(chunk)
```

## Summary

- Mode string selects read/write/append/exclusive + text/binary + update. `w` truncates, `x` fails if exists, `b` switches to `bytes`.
- Text mode decodes/encodes via `encoding`; binary mode transfers raw bytes. Never mix `str` and `bytes` on the same handle.
- **Always pass `encoding` explicitly.** The locale default is a portability bug.
- `newline` controls universal-newline translation; `errors` controls failure policy; `buffering` controls flush timing.
- File objects offer `read` / `readline` / `readlines` / iteration / `write` / `writelines` / `seek` / `tell` / `truncate`.
- Prefer iteration over `read()` for large files.
- Seeking in text mode is opaque; use binary mode for random byte access.
- Close files promptly — ideally with `with` (lesson 07.2).

and exception-safe, and generalising the pattern beyond files.
