# 00.2 Installation and Interpreters

Up to this point Python has been an abstract description. This lesson makes it concrete: which Python to install, how to install it on each major operating system, how to verify the installation, and how the moving parts — interpreter, launcher, package manager, and environment — fit together. By the end you should be able to install a current Python, reason about `python` vs `python3` vs `py`, manage multiple versions with `pyenv`, and install packages with `pip` without polluting your system.

---

## 1. Which Python Version Should You Use?

### 1.1 Python 3.x Is the Only Choice

As covered in Lesson 00.1, Python 2 reached end-of-life on 2020-01-01 and receives no security fixes. Every maintained library, framework, and tool targets Python 3. Unless you are maintaining a legacy system that cannot yet be ported, Python 2 should not be installed intentionally.

### 1.2 Which 3.x?

Python releases on a 12-month cadence, each with ~5 years of support (18 months of full bug fixes + ~3.5 years of security fixes). As of late 2025 / early 2026:

| Version | Released | Full support ends | Security ends | Status |
|---|---|---|---|---|
| 3.9 | Oct 2020 | Oct 2024 | Oct 2025 | EOL — do not start new projects |
| 3.10 | Oct 2021 | Oct 2024 | Oct 2026 | Security only |
| 3.11 | Oct 2022 | Oct 2024 | Oct 2027 | Security only — major speedups (Faster CPython) |
| 3.12 | Oct 2023 | Apr 2025 | Oct 2028 | Stable, widely adopted |
| 3.13 | Oct 2024 | Oct 2025 | Oct 2029 | Current stable — free-threaded build (no-GIL) experimental, improved REPL, `except*` polish |

**Guidance for 2026:**

- For **new learning** (this course): use **3.12 or 3.13**. All course examples target 3.10+ and note when a feature needs 3.11+.
- For **production** with many dependencies: 3.12 is the conservative default; 3.13 is fine if your key dependencies declare support for it.
- For **maximum compatibility** with older tutorials: anything ≥ 3.10 will run the code in this course.

You can see the official support table at `https://devguide.python.org/versions/` and download pages at `https://www.python.org/downloads/`.

### 1.3 How Version Numbers Work

`3.12.4` follows `major.minor.micro` (PEP 440 / semantic-ish):

- `3` — major version; has been 3 since 2008.
- `12` — minor version; each minor can add syntax and stdlib features (e.g., `match`/`case` in 3.10). Code written for 3.10 may not run on 3.9.
- `4` — micro/patch; bug fixes and security fixes only. `3.12.4` is always safe to replace `3.12.3`.

Pre-releases append `a`/`b`/`rc` (e.g., `3.13.0rc1`). Avoid them unless testing the upcoming release.

Pinning advice: pin to `>=3.12,<3.14` or `==3.12.*` in applications; libraries should declare `requires-python = ">=3.10"` in `pyproject.toml` to state the minimum they support.

## 2. Checking What You Already Have

Before installing, see what is already present. Open a terminal:

- **Linux/macOS**: Terminal, iTerm2, GNOME Terminal, etc.
- **Windows**: PowerShell, Windows Terminal, or `cmd.exe`. PowerShell is recommended going forward.

Run:

```bash
python --version
python3 --version
py --version        # Windows launcher, may not exist on Linux/macOS

which python
which python3
where python        # Windows cmd
where py            # Windows launcher location
Get-Command python  # PowerShell equivalent of which
```

Typical outputs and what they mean:

```
$ python --version
Python 3.12.4
# Good — `python` already points to a recent Python 3.

$ python --version
Python 2.7.18
# Ancient system Python 2. Do NOT use it. Install a current Python 3 and use `python3`.

$ python --version
bash: python: command not found
$ python3 --version
Python 3.11.8
# Common on modern Linux/macOS. Use `python3` and `pip3`, or create an alias / use pyenv.
```

Also check `pip`:

```bash
pip --version
pip3 --version
python -m pip --version
python3 -m pip --version
```

The most reliable invocation is `python3 -m pip` (or `python -m pip` if `python` is 3.x) — it guarantees `pip` matches the interpreter you just checked, avoiding the common pitfall where `pip` points to a different Python than `python`.

```python
# Inside a REPL, double-check the running interpreter:
import sys
print(sys.version)        # full build string
print(sys.executable)     # path to the binary actually running
print(sys.prefix)         # install prefix
```

If this already shows a current Python you are happy with, you can skip to Section 4 (interpreters) and Section 5 (pip). Otherwise, continue to installation.

## 3. Installing Python

### 3.1 Linux

Most distributions ship a system Python. That copy belongs to the OS — package managers (`apt`, `dnf`, `pacman`) use it for their own scripts. **Do not replace or `sudo pip install` into it.** Install a separate user-managed Python instead.

#### Option A — System package manager (simplest, one version)

```bash
# Ubuntu / Debian
sudo apt update
sudo apt install python3 python3-venv python3-pip python3-dev
python3 --version   # e.g. Python 3.12.3

# Fedora / RHEL
sudo dnf install python3 python3-venv python3-pip python3-devel

# Arch
sudo pacman -S python python-pip
```

Pros: trivial, integrates with OS. Cons: you get whatever version the distro froze on; upgrading means upgrading the distro or adding a PPA.

#### Option B — `pyenv` (recommended for developers who need multiple versions)

`pyenv` builds and manages multiple Python versions in `~/.pyenv/versions/` without touching the system Python. It shims the `python`/`pip` commands so the version selected per-project (via `.python-version` file) is used automatically.

```bash
# 1. Install build dependencies (Ubuntu/Debian example)
sudo apt update
sudo apt install -y make build-essential libssl-dev zlib1g-dev \
  libbz2-dev libreadline-dev libsqlite3-dev libncursesw5-dev \
  xz-utils tk-dev libxml2-dev libxmlsec1-dev libffi-dev liblzma-dev

# 2. Install pyenv (official installer)
curl https://pyenv.run | bash

# 3. Add to shell startup (bash example — adapt for zsh/fish)
echo 'export PYENV_ROOT="$HOME/.pyenv"' >> ~/.bashrc
echo 'command -v pyenv >/dev/null || export PATH="$PYENV_ROOT/bin:$PATH"' >> ~/.bashrc
echo 'eval "$(pyenv init -)"' >> ~/.bashrc
exec "$SHELL"   # reload

# 4. Install and select a Python version
pyenv install 3.12.4
pyenv global 3.12.4     # default everywhere
# or per-project:
# cd ~/projects/myapp && pyenv local 3.12.4  # writes .python-version

python --version  # now 3.12.4 via pyenv shim
which python      # ~/.pyenv/shims/python
```

For `zsh`, add the same lines to `~/.zshrc`; for `fish`, follow the pyenv wiki's fish instructions. The `pyenv` approach also installs matching `pip` for each version automatically.

#### Option C — Official source build

For completeness, you can compile CPython from source (what `pyenv` does underneath):

```bash
wget https://www.python.org/ftp/python/3.12.4/Python-3.12.4.tgz
tar -xf Python-3.12.4.tgz && cd Python-3.12.4
./configure --enable-optimizations
make -j"$(nproc)"
sudo make altinstall   # `altinstall` avoids overwriting `python3` system binary
python3.12 --version
```

Use `altinstall`, not `install`, to avoid clobbering the system `python3`.

### 3.2 macOS

#### System Python — do not use it

macOS ships a system Python (historically 2.7, now 3.9 on recent macOS). It exists for the OS and Xcode tools. Leave it alone.

#### Option A — Official installer from python.org (simplest)

1. Go to `https://www.python.org/downloads/macos/` and download the `macOS 64-bit universal2 installer` for 3.12 or 3.13.
2. Run the `.pkg`. It installs to `/Library/Frameworks/Python.framework/Versions/3.12/` and adds `python3`/`pip3` to `/usr/local/bin`.
3. Run the `Install Certificates.command` bundled in `/Applications/Python 3.12/` to enable TLS verification (required for `pip` to fetch over HTTPS).

Check:

```bash
python3 --version
pip3 --version
ls -l /usr/local/bin/python3
```

#### Option B — Homebrew (popular with developers)

```bash
# Install Homebrew if needed: https://brew.sh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew update
brew install python@3.12
# Homebrew installs as `python3.12` and `python3`
python3 --version
pip3 --version

# Optionally make `python` point to `python3`
echo 'export PATH="$(brew --prefix)/opt/python@3.12/libexec/bin:$PATH"' >> ~/.zshrc
```

Homebrew keeps versions current with `brew upgrade`. Note that `brew` may upgrade Python automatically, so pin if you need reproducibility.

#### Option C — pyenv on macOS (multiple versions)

`pyenv` works identically to Linux (see above). macOS prerequisites:

```bash
brew install openssl readline sqlite3 xz zlib tcl-tk
pyenv install 3.12.4
pyenv global 3.12.4
```

If builds fail, the usual cause is missing Xcode Command Line Tools:

```bash
xcode-select --install
```

### 3.3 Windows

#### Option A — Official installer (recommended)

1. Download the `Windows installer (64-bit)` from `https://www.python.org/downloads/windows/` for 3.12 or 3.13.
2. Run the installer. **Check both boxes at the bottom of the first screen:**
   - `Add python.exe to PATH`
   - `Use admin privileges when available` (if you want `py` launcher for all users)
3. Choose `Customize installation` → ensure `pip`, `tcl/tk`, `Python test suite`, and `py launcher` are selected.
4. On the Advanced screen, enable `Add Python to environment variables` and `Precompile standard library`.

The installer provides:

- `python.exe` (or `python3.exe`) in `%LocalAppData%\Programs\Python\Python312\`
- The **Python Launcher** `py.exe` in `C:\Windows\py.exe` — the preferred entry point on Windows.
- `pip` in `Scripts\`.

Verify in a **new** PowerShell/terminal (PATH changes need a new window):

```powershell
py --version
# Python 3.12.4

py -0
# Installed Pythons found by py Launcher for Windows
#  -3.12-64 *
#  -3.11-64

# Explicit version selection:
py -3.12 --version
py -3.11 --version

# pip via launcher (most reliable):
py -m pip --version
py -m pip install --upgrade pip
```

Why `py` matters: Windows traditionally has no `python3` vs `python` distinction in PATH. The launcher `py` lets you run any installed version with `py -3.12`, `py -3.11-32`, etc., and reads shebangs (`#!/usr/bin/env python3`) on Windows.

#### Option B — Microsoft Store

A `Python 3.12` package exists in the Microsoft Store. It installs via `winget` and auto-updates. It works but has sandbox quirks (restricted filesystem access, odd `PATH`). Prefer the python.org installer for development unless your organization mandates Store apps.

#### Option C — pyenv-win

For multiple versions on Windows:

```powershell
# PowerShell (pyenv-win via pip or git — see https://github.com/pyenv-win/pyenv-win)
pip install pyenv-win --target "$HOME/.pyenv"
# or: git clone https://github.com/pyenv-win/pyenv-win.git "$HOME/.pyenv"

pyenv install 3.12.4
pyenv global 3.12.4
```

Windows developers also commonly use `conda`/`miniconda` for data-science stacks; it bundles its own Python. That is fine for that ecosystem, but understand it is a parallel distribution — `pyenv` + `pip` + `venv` is the stdlib-native approach taught in this course.

## 4. Interpreters — What `python` Actually Is

### 4.1 CPython Is the Default — But Not the Only Interpreter

When you type `python` or `python3`, you are launching an *interpreter* — a program that compiles your source to bytecode and executes it. The distribution you installed above was **CPython** (C implementation). Other interpreters implement the same language with different tradeoffs (reviewed in Lesson 00.1):

| Interpreter | How to invoke | Installed by | Notes |
|---|---|---|---|
| **CPython** | `python`, `python3`, `py` | python.org installer, apt/brew/pyenv | Reference; what this course assumes. |
| **PyPy** | `pypy3`, `pypy` | `pyenv install pypy3.10-7.3.15` etc. | JIT; faster loops, slower startup. Run `pypy3 -m pip ...` separately. |
| **GraalPy** | `graalpy` | GraalVM distribution | Polyglot. |
| **MicroPython** | `micropython` | Firmware flash | For microcontrollers. |

Unless you explicitly installed an alternative, `python` is CPython. Verify:

```bash
python -c "import platform; print(platform.python_implementation())"
# CPython
python -c "import sys; print(sys.version)"
# 3.12.4 (main, Jun  6 2024, 18:26:44) [GCC 13.2.0]
```

### 4.2 `python` vs `python3` vs `py` — A Practical History

This confusion is historical:

- On **Unix**, `python` meant Python 2 for ~20 years. During the 2→3 transition, `python3` was introduced so both could coexist. PEP 394 recommends `python` should point to Python 2 where both exist, and `python3` to Python 3. On modern systems where Python 2 is gone, many distros now make `python` point to `python3`, but some still ship no `python` at all — only `python3`. Hence tutorials hedge with `python3`.

- On **Windows**, the launcher `py` was introduced (PEP 397) to solve the same problem differently: `py` dispatches to the right version based on arguments and shebangs, so neither `python` nor `python3` needs to be in PATH.

- With **pyenv**, a shim intercepts `python` and routes to the active version, so `python` and `python3` are the same binary.

**Rule of thumb for this course:**

```bash
# In documentation and scripts, prefer `python` or `python3` explicitly.
# For maximum portability in course examples, we show `python3`.
python3 --version

# Most reliable programmatic form (works regardless of PATH aliasing):
python3 -m pip --version
python3 -m venv .venv

# Windows:
py -3.12 --version
py -3.12 -m pip --version
```

If you want `python` to mean `python3` on a system that only has `python3`:

```bash
# bash/zsh — add to ~/.bashrc or ~/.zshrc
alias python=python3
alias pip=pip3
# Better: use pyenv so `python` is a real shim, not an alias (aliases don't work in scripts)
```

### 4.3 How the Interpreter Starts — What Happens Before Your Code

When you run `python script.py`, the interpreter:

1. Initializes the runtime (GC, import system, signal handlers).
2. Builds `sys.path` — the list of directories searched for imports (see Lesson 00.3 for full `PYTHONPATH` coverage).
3. Compiles `script.py` to bytecode (in memory; writes `.pyc` in `__pycache__` when imported as a module).
4. Sets `__name__ == "__main__"` and executes top-level statements sequentially.

You can observe this:

```python
# show_path.py
import sys
import pprint
pprint.pprint(sys.path)
print("executable:", sys.executable)
print("version:", sys.version.splitlines()[0])
```

```bash
python3 show_path.py
# ['', '/usr/lib/python312.zip', '/usr/lib/python3.12', ...]
# '' means "current directory" — your script's directory comes first.
```

### 4.4 Selecting a Version Per Project

Professional workflows pin the interpreter per project so collaborators and CI use the same Python. Three common mechanisms:

```bash
# pyenv — writes .python-version (read by the shim)
pyenv local 3.12.4
cat .python-version  # 3.12.4

# venv — creates an isolated copy/link of the interpreter
python3.12 -m venv .venv
source .venv/bin/activate   # Linux/macOS
# .venv\Scripts\activate    # Windows PowerShell

# py launcher (Windows) — shebang chooses version for `py script.py`
# Add as first line of script.py:  #!/usr/bin/env python3.12
py script.py   # launcher reads shebang on Windows
```

For reproducible projects, also declare the minimum in `pyproject.toml`:

```toml
[project]
requires-python = ">=3.12"
```

Tools like `pip`, `poetry`, `uv`, and `tox` read this to reject wrong interpreters early.

## 5. Package Management with `pip`

### 5.1 What `pip` Is

`pip` is the standard package installer for Python. It fetches packages from **PyPI** (the Python Package Index, `https://pypi.org`) and installs them into the current environment's `site-packages` directory.

Every CPython install from python.org, Homebrew, apt (`python3-pip`), and pyenv includes `pip`. Verify:

```bash
python3 -m pip --version
# pip 24.0 from /home/you/.pyenv/versions/3.12.4/lib/python3.12/site-packages/pip (python 3.12)

pip --version       # may point elsewhere — prefer `python3 -m pip`
```

If `pip` is missing (minimal Docker images, embedded installs):

```bash
python3 -m ensurepip --upgrade
# or the bootstrapping script:
curl -sS https://bootstrap.pypa.io/get-pip.py | python3
```

### 5.2 Core `pip` Workflows

```bash
# Always upgrade pip itself first (many bugs are fixed by upgrading)
python3 -m pip install --upgrade pip

# Install a package (latest version)
python3 -m pip install requests

# Install a specific version
python3 -m pip install "requests==2.31.0"

# Install with version bounds
python3 -m pip install "numpy>=1.26,<2"

# Install from a requirements file
python3 -m pip install -r requirements.txt
# requirements.txt example:
# requests==2.31.0
# rich>=13.0

# Show what is installed
python3 -m pip list
python3 -m pip show requests   # metadata, location, dependencies

# Upgrade a package
python3 -m pip install --upgrade requests

# Uninstall
python3 -m pip uninstall requests

# Search (local only — use pypi.org for discovery)
python3 -m pip list --outdated
```

```python
# After installing, import normally — pip placed it on sys.path
import requests
print(requests.__version__)
print(requests.__file__)  # where it was installed, e.g. .../site-packages/requests/__init__.py
```

### 5.3 `pip` vs `pip3` vs `python -m pip` — Which to Use?

| Command | What it runs | Risk |
|---|---|---|
| `pip install requests` | The `pip` found first on PATH | May belong to Python 2 or a different 3.x than your `python`. Common source of "installed but `ModuleNotFoundError`" bugs. |
| `pip3 install requests` | The `pip` for Python 3 nearest on PATH | Better, but still ambiguous if you have 3.11 and 3.12. |
| `python3 -m pip install requests` | The `pip` *inside* the `python3` you named | **Always correct.** Explicitly couples installer to interpreter. Use this form in docs and scripts. |
| `py -m pip` (Windows) | Launcher's selected Python | Preferred on Windows. |

**Strong recommendation:** always write `python3 -m pip` (or `python -m pip` / `py -m pip`) in instructions, Makefiles, and CI configs. Treat bare `pip` as a shortcut for interactive use only when you have already verified PATH.

### 5.4 Where Packages Go — and Why Virtual Environments Matter

By default, `pip` installs into the interpreter's global `site-packages`:

```bash
python3 -c "import site; print(site.getsitepackages())"
# ['/home/you/.pyenv/versions/3.12.4/lib/python3.12/site-packages']
python3 -c "import site; print(site.getusersitepackages())"
# /home/you/.local/lib/python3.12/site-packages  (with `pip install --user`)
```

Global installs cause two problems: version conflicts between projects, and permission errors that tempt `sudo pip install` (which can break the OS Python). The solution is **virtual environments** — isolated directories with their own interpreter link and `site-packages`:

```bash
# Create and activate a venv (stdlib, no extra install)
python3 -m venv .venv
source .venv/bin/activate        # Linux/macOS — prompt gains (.venv)
# .venv\Scripts\Activate.ps1    # Windows PowerShell (may need Set-ExecutionPolicy)

which python   # .../.venv/bin/python  — now inside the venv
pip --version  # .../.venv/lib/... — pip is also isolated
pip install requests   # goes into .venv/lib/.../site-packages only
pip list
deactivate     # leave the venv
```

Modern alternatives (`virtualenv`, `conda`, `poetry`, `pipenv`, `uv`, `hatch`) all provide the same isolation with different UX. The stdlib `venv` is sufficient for this course; you will meet the others naturally as you adopt them.

A minimal per-project setup that works everywhere:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt  # or: pip install -e .  for an installable package
```

Add `.venv/` to `.gitignore` — virtual environments are not committed.

### 5.5 Keeping Installs Healthy

```bash
# Upgrade pip, setuptools, wheel periodically
python3 -m pip install --upgrade pip setuptools wheel

# Check for known vulnerabilities (requires pip-audit)
python3 -m pip install pip-audit
python3 -m pip-audit

# Clean stale caches if disk grows
python3 -m pip cache purge
python3 -m pip cache dir
```

Never do:

```bash
sudo pip install requests        # contaminates system Python — use --user or a venv
pip install --upgrade pip --user # mixing --user with system pip creates confusion
```

## 6. Common Installation Pitfalls and Fixes

| Symptom | Cause | Fix |
|---|---|---|
| `python: command not found` but `python3` works | Distro does not alias `python` → `python3` | Use `python3` explicitly or `pyenv` shim. |
| `pip install X` succeeds but `import X` → `ModuleNotFoundError` | `pip` and `python` point to different interpreters | Use `python3 -m pip install X` and `python3 -c "import X"`. |
| `error: externally-managed-environment` (Debian 12+, Fedora 38+) | PEP 668 marks system Python as externally managed to prevent `pip` pollution | Use `python3 -m venv .venv` then pip inside it; or `pip install --user` / `--break-system-packages` if you understand the risk. |
| `SSL: CERTIFICATE_VERIFY_FAILED` with python.org installer on macOS | Certificates not installed | Run `Install Certificates.command` in `/Applications/Python 3.12/`. |
| `zlib not available` / `_ctypes` build failure with `pyenv` | Missing build dependencies | Install `zlib1g-dev`, `libffi-dev`, etc. (see Section 3.1 deps list). |
| Windows `python` opens Microsoft Store | App execution alias intercepts `python` | Disable alias in Settings → Apps → Advanced app settings → App execution aliases, or rely on `py`. |
| `pyenv: command not found` after install | Shell not reloaded | `exec "$SHELL"` or open a new terminal; check `~/.bashrc`/`~/.zshrc` lines. |

A diagnostic script that answers most "which Python am I using?" questions:

```python
# diagnose.py
import sys
import sysconfig
import platform

print("implementation:", platform.python_implementation())
print("version:       ", sys.version.replace("\n", " "))
print("executable:    ", sys.executable)
print("prefix:        ", sys.prefix)
print("path[0:3]:     ", sys.path[:3])
print("site-packages: ", sysconfig.get_paths()["purelib"])
try:
    import pip
    print("pip:           ", pip.__version__, "at", pip.__file__)
except ImportError:
    print("pip:            not installed")
```

```bash
python3 diagnose.py
# implementation: CPython
# version:        3.12.4 (main, Jun  6 2024, ...)
# executable:     /home/you/.pyenv/versions/3.12.4/bin/python
# ...
```
