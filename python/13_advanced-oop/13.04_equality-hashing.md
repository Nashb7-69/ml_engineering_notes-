# 13.04 Equality and Hashing: __eq__ and __hash__

## Identity vs Equality — The Foundational Distinction

Python has two notions of "sameness":

| Concept | Operator | Method | Meaning |
|---------|----------|--------|---------|
| **Identity** | `a is b` | (none — checks `id`) | Same object in memory (`id(a) == id(b)`) |
| **Equality** | `a == b` | `a.__eq__(b)` | Same *value* / semantics, possibly different objects |

```python
# Identity vs equality
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a is b)   # False — different objects, different ids
print(a == b)   # True  — same value (list.__eq__ compares elements)
print(a is c)   # True  — same object
print(id(a), id(b), id(c))
print(id(a) == id(c))  # True == `is` semantics for the `a, c` pair

# Numbers and strings add interning fun:
x = 1000
y = 1000
print(x is y)   # False (usually) — distinct int objects; CPython interns small ints -5..256 only
print(x == y)   # True

# Never use `is` to compare values. Only use `is` for None/sentinels:
if value is None: ...       # correct — None is a singleton
if value == None: ...       # wrong — triggers __eq__ that may misbehave
```

> **Mental model:** `is` asks "are you the same box?", `==` asks "do you have the same contents?" Most domain types care about contents.

### The Default Behavior (`object.__eq__` / `object.__hash__`)

If you define no `__eq__`, you inherit `object.__eq__` which is **identity-based**:

```python
class Bare: pass

a = Bare()
b = Bare()
print(a == b)          # False — object.__eq__ is `a is b`
print(hash(a), hash(b)) # different ints — object.__hash__ is id-based
print({a: 1, b: 2})    # both can be dict keys — distinct entries
```

This default satisfies a crucial invariant (see below) and makes every object usable as a dict key — but with identity semantics. As soon as you define `__eq__` to mean value equality, the invariant forces a decision about `__hash__`.

## The Equality-Hash Contract (The Most Important Invariant)

> **If `a == b`, then `hash(a) == hash(b)`. The converse need not be true (hash collisions are allowed).**

This contract exists because hash tables (dicts, sets) bucket by hash, then compare with `==` within the bucket. If equal objects had different hashes, a dict lookup would go to the wrong bucket and miss.

```python
# Why the contract matters: dict lookup algorithm (simplified)
# d[key]  →  bucket = hash(key) % nbuckets
#            for k in bucket:
#                if k == key and hash(k) == hash(key):  → found
#            else: → KeyError

class Bad:
    def __init__(self, x): self.x = x
    def __eq__(self, other):
        if isinstance(other, Bad):
            return self.x == other.x
        return NotImplemented
    def __hash__(self):
        # ❌ Violates contract: hash is id-based but equality is value-based
        return id(self)

a = Bad(1)
b = Bad(1)
print(a == b)            # True
print(hash(a) == hash(b)) # False — violates contract!
d = {a: "hello"}
print(d.get(b))          # None — lookup fails even though a==b, because hashes differ
print(b in d)            # False

# The opposite (equal hashes, non-equal objects) is fine — it's a collision:
class CollisionOk:
    def __init__(self, x): self.x = x
    def __eq__(self, other): return isinstance(other, CollisionOk) and self.x == other.x
    def __hash__(self): return 42  # terrible for performance but correct — all objects collide

x = CollisionOk(1)
y = CollisionOk(2)
print(x == y)  # False
print(hash(x) == hash(y))  # True — legal, just slow (hash table degrades to linear search)
```

## `__eq__` — Implementing Value Equality

### Signature and Return Value

```python
class MyClass:
    def __eq__(self, other: object) -> bool:
        # Return True/False for known types
        # Return NotImplemented for unsupported types (NOT False, NOT None)
        ...
```

**Critical:** `__eq__` must return `NotImplemented` (the singleton, not `NotImplementedError`) when `other` is of an unsupported type. This signals Python to try the reflected operation `other.__eq__(self)` or fall back to identity.

```python
class Money:
    def __init__(self, cents: int, currency: str = "USD"):
        self.cents, self.currency = cents, currency
    def __eq__(self, other: object) -> bool:
        if isinstance(other, Money):
            return (self.cents, self.currency) == (other.cents, other.currency)
        # Do NOT return False here — that would claim "Money != int" even when int might claim equality
        return NotImplemented
    def __repr__(self): return f"Money({self.cents!r}, {self.currency!r})"

m = Money(100)
print(m == Money(100))   # True — our __eq__ handles it
print(m == 100)          # False — see dispatch below
print(100 == m)          # False — same dispach path reversed

# What actually happens for `m == 100`:
#   1. Money.__eq__(m, 100) -> NotImplemented  (we said "I don't know how to compare to int")
#   2. int.__eq__(100, m)   -> NotImplemented  (int doesn't know about Money either)
#   3. Python falls back to identity check: m is 100 -> False
#   => result False

# Contrast returning False directly:
class EagerFalse:
    def __eq__(self, other): return False  # ❌ Blocks reflected attempt
class Cooperative:
    def __eq__(self, other):
        if isinstance(other, Cooperative): return True
        return NotImplemented  # ✅ Lets other.__eq__ try

# If int had a Money-aware __eq__, returning False would prevent it from ever being tried.
# Always return NotImplemented for unsupported types — except when you explicitly want to declare "never equal".
```

### `__ne__` — You Rarely Need to Define It

Since Python 3, `__ne__` automatically delegates to `__eq__`:

```python
class Point:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, other):
        if isinstance(other, Point): return (self.x, self.y) == (other.x, other.y)
        return NotImplemented
    # No __ne__ — Python synthesizes: a != b  ==  not (a == b)

p = Point(1, 2)
print(p != Point(1, 2))  # False — not (True)
print(p != Point(3, 4))  # True

# Only override __ne__ when negation is NOT logical NOT (rare — SQL expression builders etc.)
# Example — SQLAlchemy style:
class Column:
    def __eq__(self, other): return f"{self} == {other}"  # builds expression, doesn't return bool
    def __ne__(self, other): return f"{self} != {other}"  # must override, because `not (self==other)` would be bool
```

### Equality with Inheritance

```python
class Animal:
    def __init__(self, name): self.name = name
    def __eq__(self, other):
        if isinstance(other, Animal):
            return self.name == other.name
        return NotImplemented

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed
    def __eq__(self, other):
        if isinstance(other, Dog):
            return self.name == other.name and self.breed == other.breed
        # For cross-type equality: delegate to parent logic or NotImplemented
        if isinstance(other, Animal) and not isinstance(other, Dog):
            # Animal("Rex") should not equal Dog("Rex", "Labrador") — different granularity
            return False
        return NotImplemented

a = Animal("Rex")
d = Dog("Rex", "Labrador")
print(a == d)  # False — Dog overrides to be strict
print(d == a)  # False — same

# Liskov subtlety: if Dog.__eq__ used isinstance(other, Animal) only, then
# Dog("Rex","Lab") == Animal("Rex") would be True but Animal("Rex") == Dog("Rex","Lab") might differ
# if Animal checked exact type. Hence: check exact logical scope.

# For value types, prefer `type(self) is type(other)` when strictness matters:
class StrictPoint:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, other):
        if type(self) is not type(other):  # exact type match — subclass Point3D not equal
            return NotImplemented  # or False — choice depends on desired semantics
        return (self.x, self.y) == (other.x, other.y)
```

## `__hash__` — Hashing Deep Dive

### Requirements for Hashability

An object is **hashable** iff:

1.  It has a `__hash__` method (not `None`).
2.  Its hash value never changes during its lifetime (so it must be effectively immutable — or at least the fields contributing to hash must not mutate while in a hash table).
3.  If `a == b`, then `hash(a) == hash(b)`.

Hashable objects can be used as `dict` keys and `set` members. Unhashable objects cannot.

### Default `__hash__` Is Identity-Based

```python
class IdentityDefault:
    pass  # inherits object.__hash__ == id(self) derived

a = IdentityDefault()
print(hash(a))          # some int derived from id(a)
print(hash(a) == hash(a))  # True — stable for same object
# But two different objects are never equal (identity equality), so distinct hashes are fine
```

### Defining `__eq__` Resets `__hash__` to `None` — The Python Safety Net

**This is the most frequent gotcha for learners. Memorize it.**

```python
class WithEq:
    def __eq__(self, other):
        if isinstance(other, WithEq): return True
        return NotImplemented
    # No __hash__ defined — Python SETS __hash__ = None automatically!

w = WithEq()
print(WithEq.__hash__)       # None
try:
    hash(w)
except TypeError as e:
    print(e)  # unhashable type: 'WithEq'

try:
    d = {w: 1}
except TypeError as e:
    print(e)  # unhashable type: 'WithEq'

try:
    s = {w}
except TypeError as e:
    print(e)  # unhashable type: 'WithEq'
```

**Why?** If you define value equality but keep id-based hashing, you would violate the contract for every distinct-but-equal pair. Python chooses safety: make the type unhashable rather than silently broken. You must explicitly fix it.

### The Three Fixes

```python
# 1. Make it hashable by defining a correct __hash__ consistent with __eq__
class HashableValue:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, other):
        if isinstance(other, HashableValue): return (self.x, self.y) == (other.x, other.y)
        return NotImplemented
    def __hash__(self):
        return hash((self.x, self.y))  # tuple hashing is the standard technique
    def __repr__(self): return f"HashableValue({self.x!r}, {self.y!r})"

a = HashableValue(1, 2)
b = HashableValue(1, 2)
print(a == b, hash(a) == hash(b))  # True True — correct
print({a: "first", b: "second"})   # {HashableValue(1,2): "second"} — b overwrites a (same key)

# 2. Explicitly mark as unhashable when value type is mutable — be intentional
class MutablePoint:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, other):
        if isinstance(other, MutablePoint): return (self.x, self.y) == (other.x, other.y)
        return NotImplemented
    __hash__ = None  # explicit: "I know this is unhashable, and I mean it"

# 3. Restore identity hashing when you want value equality but still use identity buckets
#    (Rare — usually indicates design confusion. Prefer not to.)
class IdentityHashDespiteEq:
    def __eq__(self, other):
        if isinstance(other, IdentityHashDespiteEq): return self is other  # identity equality
        return NotImplemented
    __hash__ = object.__hash__  # explicit restore — but then why override __eq__ to identity?
```

### `__hash__` Must Be Stable While in a Collection

```python
# ❌ Danger: mutable object with value-based hash — hash changes after dict insertion
class MutableHashed:
    def __init__(self, x):
        self.x = x
    def __eq__(self, other):
        if isinstance(other, MutableHashed): return self.x == other.x
        return NotImplemented
    def __hash__(self):
        return hash(self.x)

m = MutableHashed(1)
d = {m: "one"}
print(m in d)       # True — found in bucket hash(1)
m.x = 2             # mutate — hash now hash(2), but object is still in bucket hash(1)
print(hash(m))      # hash(2)
print(m in d)       # False — lookup goes to bucket hash(2), misses!
print(list(d.keys())[0].x)  # 2 — but dict still holds it under old bucket (now orphaned)
# The dict is now corrupt for that key — del d[m] raises KeyError even though m is "in" d's keys.

# ✅ Fix: make type immutable or hash only immutable fields
class ImmutableHashed:
    __slots__ = ("_x",)
    def __init__(self, x): self._x = x
    @property
    def x(self): return self._x  # no setter — effectively immutable
    def __eq__(self, other):
        if isinstance(other, ImmutableHashed): return self._x == other._x
        return NotImplemented
    def __hash__(self): return hash(self._x)
    def __repr__(self): return f"ImmutableHashed({self._x!r})"

im = ImmutableHashed(1)
print(hash(im), {im: "one"})  # stable

# Or: use frozen dataclass (lesson 13.14)
from dataclasses import dataclass
@dataclass(frozen=True)
class PointHashable:
    x: int
    y: int
# frozen=True auto-generates correct __hash__ and prevents mutation

ph = PointHashable(1, 2)
print(hash(ph), {ph})
try:
    ph.x = 99
except Exception as e:
    print(f"frozen blocks mutation: {e}")
```

### Implementing `__hash__` — Techniques

```python
# Technique 1: tuple hashing (most common, correct mixing)
class GeoPoint:
    def __init__(self, lat: float, lon: float):
        self.lat, self.lon = lat, lon
    def __eq__(self, other):
        if isinstance(other, GeoPoint):
            return (self.lat, self.lon) == (other.lat, other.lon)
        return NotImplemented
    def __hash__(self):
        return hash((self.lat, self.lon))

# But floats need care: NaN and -0.0
import math
print(hash(float("nan")) == hash(float("nan")))  # may vary; but NaN != NaN, so ok
print(math.nan == math.nan)                        # False — no contract issue
print(hash(0.0) == hash(-0.0))                     # True — Python ensures
print(0.0 == -0.0)                                 # True — consistent

# Technique 2: XOR combining for manual hashes (rarely needed)
class ManualHash:
    def __init__(self, a, b, c):
        self.a, self.b, self.c = a, b, c
    def __eq__(self, other):
        if isinstance(other, ManualHash): return (self.a, self.b, self.c) == (other.a, other.b, other.c)
        return NotImplemented
    def __hash__(self):
        # Don't just hash(self.a) ^ hash(self.b) ^ hash(self.c) — symmetric collisions
        # Use tuple hashing instead, or if manual, include order:
        return hash((self.a, self.b, self.c))

# Technique 3: hash based on id for identity-like objects (singleton values)
class Symbol:
    """Interned symbol — equal only if identical. Identity hash is fine."""
    _intern: dict[str, "Symbol"] = {}
    def __new__(cls, name: str):
        if name in cls._intern:
            return cls._intern[name]
        inst = super().__new__(cls)
        cls._intern[name] = inst
        return inst
    def __init__(self, name: str):
        if hasattr(self, "name"): return
        self.name = name
    def __eq__(self, other):
        # Identity equality — safe with id-based hash
        return self is other
    def __hash__(self):
        return object.__hash__(self)  # explicitly identity hash — but value equality is identity, so ok
    def __repr__(self): return f"Symbol({self.name!r})"

# Technique 4: None for unhashable
class UnhashableExplicit:
    def __eq__(self, other): return isinstance(other, UnhashableExplicit)
    __hash__ = None  # signals to type system: this is intentionally unhashable
```

## Hashability Matrix

| Defines `__eq__`? | `__hash__` status | Result | Use case |
|-------------------|-------------------|--------|----------|
| No | `object.__hash__` (id-based) | Hashable by identity | Default — every bare class |
| Yes | Not defined | `__hash__ = None` (unhashable) | Python safety net — most common gotcha |
| Yes | `__hash__ = None` explicitly | Unhashable (intentional) | Mutable value types (lists-like domain objects) |
| Yes | `def __hash__(self): return hash(...)` | Hashable by value | Immutable value types (points, money, colors) |
| Yes (identity equality) | `__hash__ = object.__hash__` | Hashable by identity despite custom `__eq__` | Identity semantics preserved intentionally |
| Frozen dataclass | Auto-generated consistent hash | Hashable, immutable | Recommended for value types |

## Realistic Domain Example: Product & SKU System

```python
from __future__ import annotations
from dataclasses import dataclass, field
import hashlib

# Scenario: inventory system — SKU is hashable identity, Product is value-equal but stock-dependent so not hashable

class SKU:
    """Immutable stock-keeping unit — used as dict key and set element. Must be hashable."""
    __slots__ = ("_code", "__weakref__")
    def __init__(self, code: str):
        if not code or not code.isupper():
            raise ValueError("SKU code must be non-empty uppercase")
        self._code = code

    @property
    def code(self) -> str: return self._code

    def __eq__(self, other: object) -> bool:
        if isinstance(other, SKU):
            return self._code == other._code
        return NotImplemented

    def __hash__(self) -> int:
        # Immutable field, stable
        return hash(self._code)

    def __repr__(self) -> str:
        return f"SKU({self._code!r})"

    def __str__(self) -> str:
        return self._code

# Mutable product — equal by SKU but hash explicitly disabled (stock changes)
class Product:
    def __init__(self, sku: SKU, name: str, price_cents: int, stock: int):
        self.sku = sku
        self.name = name
        self.price_cents = price_cents
        self.stock = stock  # mutable — changes over time

    def __eq__(self, other: object) -> bool:
        if isinstance(other, Product):
            # Products considered same inventory item if same SKU
            return self.sku == other.sku
        return NotImplemented

    __hash__ = None  # explicitly unhashable — stock is mutable, SKU equality would need stable hash but stock semantics forbid

    def __repr__(self) -> str:
        return f"Product(sku={self.sku!r}, name={self.name!r}, price_cents={self.price_cents!r}, stock={self.stock!r})"

sku_a = SKU("WIDGET-001")
sku_b = SKU("WIDGET-001")
print(sku_a == sku_b, hash(sku_a) == hash(sku_b))  # True True
print(sku_a is sku_b)                               # False — different objects, same value

# SKUs work in dicts/sets:
catalog: dict[SKU, Product] = {}
catalog[sku_a] = Product(sku_a, "Widget", 999, stock=50)
print(catalog[sku_b].name)  # Widget — sku_b finds same bucket (equal hash + equal value)

# Products intentionally cannot be set members:
try:
    s = {Product(sku_a, "Widget", 999, 50)}
except TypeError as e:
    print(f"Products unhashable: {e}")

# For when you DO need hashable products (e.g., frozen snapshots), create a value snapshot:
@dataclass(frozen=True)
class ProductSnapshot:
    sku: SKU
    name: str
    price_cents: int
    # no stock — snapshots are frozen, immutable

snap = ProductSnapshot(sku_a, "Widget", 999)
print(hash(snap), {snap: "snapshot"})  # works — immutable snapshot is hashable

# Collections needing hash — detailed example:
# set, dict, frozenset, collections.Counter, interning
from collections import Counter
# Counter requires hashable elements:
counts = Counter([sku_a, sku_b, SKU("GADGET-002")])
print(counts)  # Counter({SKU('WIDGET-001'): 2, SKU('GADGET-002'): 1})

# dict with SKU keys — demonstrates why stable hash matters during resizing:
inventory: dict[SKU, int] = {SKU(f"ITEM-{i:03d}"): i for i in range(1000)}
print(f"Inventory size {len(inventory)}, lookup ITEM-042: {inventory[SKU('ITEM-042')]}")
```

## Interaction with `__bool__`, Sorting, and Collections

```python
# Equality is independent from truthiness and ordering — but __eq__ returning NotImplemented affects `in`:
# list.__contains__ iterates and uses `==` element-by-element; dict.__contains__ uses hash first

# Set membership uses both hash and equality:
class HashThenEq:
    def __init__(self, value): self.value = value
    def __eq__(self, other):
        print(f"  __eq__ {self.value} == {getattr(other, 'value', other)!r}")
        if isinstance(other, HashThenEq): return self.value == other.value
        return NotImplemented
    def __hash__(self):
        print(f"  __hash__ {self.value} -> {hash(self.value)}")
        return hash(self.value)

a = HashThenEq(1)
b = HashThenEq(1)
c = HashThenEq(2)
s = {a}
print("-- test membership --")
print(b in s)  # hash(b) == hash(a), then __eq__
print(c in s)  # hash(c) != hash(a), __eq__ not needed
# Output shows:
#   __hash__ 1 -> 1
#   -- test membership --
#   __hash__ 1 -> 1
#     __eq__ 1 == 1
#   True
#   __hash__ 2 -> 2
#   False  — no __eq__ call due to different hash
```

## `dataclass` and `hash` — Auto-Generation Rules

```python
from dataclasses import dataclass

# 1. Mutable dataclass — hash disabled (safest default)
@dataclass
class MutableDC:
    x: int
    y: int

print(MutableDC.__hash__)  # None — because dataclass sets eq=True by default, so hash becomes None

# 2. Explicitly request unsafe hash (you promise not to mutate while in collections)
@dataclass(eq=True, unsafe_hash=True)
class UnsafeHashDC:
    x: int
    y: int
# Now hashable but still mutable — dangerous!

uh = UnsafeHashDC(1, 2)
d = {uh: "hi"}
uh.x = 99            # mutate while in dict — hash now differs
print(uh in d)       # False — corrupted! Don't do this.

# 3. Frozen — auto hash, immutable
@dataclass(frozen=True)
class FrozenDC:
    x: int
    y: int

f = FrozenDC(1, 2)
print(hash(f), {f: 1})  # works
# f.x = 9 -> FrozenInstanceError

# 4. No eq — keep object identity hash
@dataclass(eq=False)
class NoEqDC:
    x: int
    y: int
# Inherits object.__hash__ (id-based), no __eq__ generated — identity semantics

ne = NoEqDC(1, 2)
print(hash(ne))     # id-based

# 5. Custom __eq__ / __hash__ — dataclass respects them
@dataclass
class CustomHashDC:
    x: int
    _secret: str = field(repr=False, compare=False, hash=False)

    def __hash__(self):
        return hash(self.x)  # only x participates — _secret excluded
    def __eq__(self, other):
        if isinstance(other, CustomHashDC): return self.x == other.x
        return NotImplemented

print(CustomHashDC(1, "a") == CustomHashDC(1, "b"))  # True — _secret excluded from equality
print(hash(CustomHashDC(1, "a")) == hash(CustomHashDC(1, "b")))  # True — consistent
```

## Performance Considerations

*   **Hash computation must be fast.** `hash` is called for every dict/set insertion and every lookup. Keep `__hash__` O(1) or cheaper than comparison. For large objects, hash a canonical tuple — Python's tuple hash mixes well and is C-speed.
*   **Immutability enables caching.** Since hash never changes for immutable types, CPython caches `str` and `bytes` hashes after first compute. You can mimic: `self._hash = hash(...)` in `__init__` for frozen types.
*   **Collision cost.** All objects returning the same hash degrade dict/set to linked-list scanning (O(n) instead of O(1)). Always include discriminating fields.
*   **Equality short-circuit.** Place cheapest checks first: identity `if self is other: return True`, then `isinstance`, then cheap fields before deep comparisons (e.g., check `id` fields before comparing large collections).

```python
class FastEq:
    def __init__(self, key: str, payload: list[int]):
        self.key, self.payload = key, payload
    def __eq__(self, other):
        if self is other:  # fastest — same object, no field comparison needed
            return True
        if not isinstance(other, FastEq):
            return NotImplemented
        if self.key != other.key:  # cheaper than list comparison
            return False
        return self.payload == other.payload  # expensive, only if keys match

    def __hash__(self):
        # Don't hash the mutable payload — only the stable key
        return hash(self.key)
        # But then two FastEq with same key but diff payload would collide yet compare !=
        # That's allowed (collisions via shared key), but correctness of eq/hash contract still needs:
        #   if a == b then hash(a) == hash(b)
        # Since FastEq equality requires payload equality, and payload not in hash, hash(1, [1]) == hash(1, [2])
        # even when payloads differ — that's a collision, not a contract violation (because then a != b).
        # Only if a == b (payloads equal too) we need hash(a)==hash(b) — which holds because it depends only on key
        # and when payloads equal, keys already equal, so hashes equal.
```

## Common Mistakes Table

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Defining `__eq__` without `__hash__` | `TypeError: unhashable type` | Add `__hash__` or `__hash__ = None` explicitly |
| Returning `False` instead of `NotImplemented` in `__eq__` | Blocks reflected `other.__eq__`; subtype equality like `int` vs `Money` may behave asymmetrically | `return NotImplemented` for unsupported types |
| Hashing mutable fields | Dict corruption after mutation; `in` returns False for existing key | Hash only immutable fields or make type immutable / unhashable |
| `__hash__` returns non-int | `TypeError: __hash__ returned non-int` | `return hash(tuple(...))` — must be `int`, within `sys.hash_info.modulus` range is auto-masked |
| Comparing with `is` for values | False negatives when equal objects are distinct | Use `==` for values; `is` only for `None` / singletons |
| `__eq__` that can raise for valid `other` | Unexpected exceptions in `list.__contains__`, `set` comparisons | Guard with `isinstance` and return `NotImplemented` |
| `__hash__` that ignores a field used in `__eq__` in a way that breaks contract | Two equal objects with different hashes | Every field that participates in `__eq__` must also be reflected in `__hash__` (or make collisions intentional and safe) |

---

## Checklist

1.  Does your `__eq__` handle `NotImplemented` correctly? Test `obj == unsupported_type` and `unsupported_type == obj`.
2.  Are you using `isinstance` (value-type family) vs `type(self) is type(other)` (exact match) intentionally?
3.  If you defined `__eq__`, did you explicitly decide on `__hash__` (correct value hash or `None`)? No silent default.
4.  Are all fields contributing to `__eq__` also reflected in `__hash__` (or documented collision-safe)?
5.  Is `__hash__` stable for the object's lifetime in a collection? If mutable, disable hashing.
6.  Did you include `if self is other: return True` short-circuit?
7.  Is your frozen type truly immutable (slots, no setters, no exposed mutable containers)?

## Exercises (Mental)

1.  Prediction: `class A: def __eq__(self, o): return NotImplemented` — what does `A() == A()` return?
2.  Implement `__eq__`/`__hash__` for `class Interval(lo, hi)` where equality is inclusive range equality, and hash uses `(lo, hi)` tuple. Why must `Interval` be immutable to be hashable?
3.  Design `Version(major, minor, patch)` that compares numerically and is hashable. Can `Version("1.0") == "1.0.0"` ever be True? Should it?
4.  Explain why `list` is unhashable but `tuple` is hashable — what invariant would break if `hash([1,2])` were defined naively?
5.  Write a test that would catch a mutation-after-insertion corruption bug.
