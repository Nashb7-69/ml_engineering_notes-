# 13.15 __slots__, Memory, and Performance

## What `__slots__` Is — A Layout Declaration

By default every instance carries a `__dict__` (a hash table of attribute name → value) plus a separate `__weakref__` pointer storage if enabled. `__slots__` replaces that per-instance dictionary with **fixed, C-level array slots**:

```python
class Normal:
    def __init__(self, x, y): self.x, self.y = x, y

class Slotted:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y

n = Normal(1, 2)
s = Slotted(1, 2)
print(n.__dict__)          # {'x': 1, 'y': 2}
print(hasattr(s, "__dict__"))  # False — no dict
print(Slotted.__slots__)   # ('x', 'y')
print(type(inspect := __import__("inspect")))  # just to contrast memory below

# Internally, CPython stores slotted attributes in `PyObject *slots[]` array contiguous with the object header,
# indexed at C speed — no hashing, no dictionary probing.
```

> **Mental model:** Without slots, an instance is `header + dict pointer → hash table` (indirect). With slots, it is `header + inline array[fixed positions]` (direct). The class's `__slots__` descriptor maps `obj.x` to `array[index_of_x]` at class-defined offset.

### Why It Matters — The Two Promises

1.  **Memory per instance shrinks dramatically** — no `__dict__` allocation, no per-attribute hash entry. Measured savings ~40–70% depending on attribute count. For millions of objects, difference can be GBs.
2.  **Attribute access is slightly faster** (≈10–30% faster reads) — slot descriptor is a C array index, not a hash-table lookup.

Both promises are conditional: you must handle inheritance, dynamic attributes, pickle, weakrefs, and debugging tooling tradeoffs.

## Declaration Forms and What They Create

```python
class A:
    __slots__ = ("x", "y")        # string tuple — preferred, ordered, explicit
class B:
    __slots__ = ["x", "y"]        # list also accepted
class C:
    __slots__ = "x"               # ❌ Wrong: string is iterable -> slots = 'x' -> per-char slots 'x', not "x"
    # Correct for single slot: __slots__ = ("x",)
class D:
    __slots__ = {"x": "docstring for x", "y": None}  # dict supported — values are docstrings

# Each entry becomes a member descriptor on the class:
print(Slotted.__dict__["x"])   # <member 'x' of 'Slotted' objects>
print(type(Slotted.__dict__["x"])) # <class 'member_descriptor'>
# member_descriptor is the slot proxy — its __get__/__set__ forward to the array offset.

# Classes with slots also get a `__slotname__` descriptor per slot — compare to property in 13.10 but at C level.
```

### The `__slots__` Descriptor Is a Data Descriptor

```python
class S:
    __slots__ = ("x",)
    # So S.__dict__["x"].__get__(instance, S) reads instance's slot array at index 0
    # and S.__dict__["x"].__set__(instance, value) writes there.

s = S()
s.x = 10
print(s.x)                # 10 via member descriptor
# Instance dict path not available:
try: s.__dict__
except AttributeError as e: print(e)  # 'S' object has no attribute '__dict__'

# Slots without values raise AttributeError before first assignment:
class E:
    __slots__ = ("x",)
e = E()
try: print(e.x)
except AttributeError as e: print(f"Unassigned slot: {e}")
```

## Memory Layout and Measured Savings

### How Much Is Saved

| Component | Normal instance (2 attrs) | Slotted (2 slots) |
|-----------|---------------------------|-------------------|
| Object header (PyObject) | ~32 bytes | ~32 bytes |
| Slot array (2 pointers) | — | 16 bytes (2 × 8) |
| `__dict__` allocation | ~56 bytes dict + entry table | 0 |
| Per-attribute dict entry (`PyDictKeyEntry`) | ~72 bytes × 2 | 0 |
| Total measured (CPython 3.11, 64-bit) | ~232 bytes | ~64 bytes |
| For 1M instances | ~232 MB | ~64 MB |

Measured more precisely with `sys`, `tracemalloc`, or `pympler`:

```python
import sys, tracemalloc, gc

class Plain:
    def __init__(self, a,b,c): self.a, self.b, self.c = a,b,c

class Slotted3:
    __slots__ = ("a","b","c")
    def __init__(self, a,b,c): self.a, self.b, self.c = a,b,c

# Rough per-instance size:
print(sys.getsizeof(Plain(1,2,3).__dict__))   # ~104 bytes for dict
print(sys.getsizeof(Slotted3(1,2,3)))          # ~56 bytes object
# But true overhead is retained heap: use tracemalloc / pympler.asizeof
# tracemalloc: 
# tracemalloc.start()
# snapshot = tracemalloc.take_snapshot() etc. — omitted runtime, but principle below.

# More realistic measurement via `__slots__` savings on a production cloud trace:
# 10M SensorReading(x,y,z,ts) plain would be ~2.8 GB, slotted ~0.9 GB.
# Coders at Instagram/Dropbox attribute slot adoption to measurable tail-latency drops.
```

### Implementation Detail — Why Savings Vary With `__dict__` Slot

Adding `__dict__` to `__slots__` restores per-instance dict for dynamic attributes, reclaiming flexibility at the cost of memory reclaiming almost nothing. Similarly, `__weakref__` adds a weak-pointer slot:

```python
class WithDict:
    __slots__ = ("x", "__dict__")
    def __init__(self, x, extra=None):
        self.x = x
        if extra: self.extra = extra  # stored in instance.__dict__

wd = WithDict(5, extra=99)
print(wd.x, wd.extra, wd.__dict__)  # 5 99 {'extra': 99}
print(hasattr(wd, "__dict__"))      # True — extra memory again
# Slots savings only realized when you omit __dict__.

class WithWeak:
    __slots__ = ("x", "__weakref__")
    def __init__(self, x): self.x = x

import weakref
w = WithWeak(1)
print(weakref.ref(w)() is w)  # True — weakref support slot
# Without __weakref__, weakref.ref(slotted_obj) raises TypeError.
```

## Access Semantics — Subtle Differences

### `__slots__` vs `__dict__` Behavior

```python
class Plain2:
    def __init__(self, x): self.x = x

class Slot2:
    __slots__ = ("x",)
    def __init__(self, x): self.x = x

p = Plain2(1)
s = Slot2(1)
print("__dict__" in dir(p), "x" in p.__dict__)  # True True
print("__dict__" in dir(s))                     # False (but `hasattr(s, "x")` works via descriptor)
print("x in Slot2.__dict__", "x" in Slot2.__dict__)
print(hasattr(s, "x"))                          # True — before del, present
del s.x
print(hasattr(s, "x"))                          # False — slot can be unbound, like descriptor state missing
try: print(s.x)
except AttributeError as e: print(f"after del: {e}")  # slot descriptor raises AttributeError when not yet set

Slot2.x = 999  # ❌ Setting on the CLASS replaces the descriptor with plain 999!
print(Slot2.__dict__["x"])   # 999 — member descriptor overwritten
print(Slot2(1).x)            # TypeError or surprising — instance slot now hidden
# Restore: del Slot2.x; then member descriptor gone; no slot. Don't assign to Slot Class attrs arbitrarily.
```

### Default Values for Slots — No Direct Support

```python
# Plain classes with dict allow class attr default for instance fallback
class WithDefault:
    x = 10  # class default — instance __dict__ without x returns this
    def __init__(self, x=None):
        if x is not None: self.x = x

print(WithDefault().x)       # 10 — class attr, fallback
print(WithDefault(5).x)      # 5 — instance dict overrides

class SlotDefault:
    __slots__ = ("x",)
    x = 10  # ❌ If present in __slots__, `x = 10` collides with member descriptor? Actually defining class attr with same name as slot is confusing and not valid as default:
    # When `x` in __slots__, `class SlotDefault: x = 10` as slot descriptor's slot — but slot descriptor already present.
    # So Python may reject or treat it ambiguously. Instead provide defaults via __init__:
    def __init__(self, x=None):
        if x is None:
            self.x = 10  # explicit slot assignment in __init__
        else: self.x = x

# So patterns:
# - For slot class default, always initialize in __init__, not via class attribute with same name.
# - Class attr shared state that slots hide is not accessible via normal lookup.
```

## Inheritance — Where Slots Get Confusing

### Single Inheritance Chains

```python
class Base:
    __slots__ = ("x", "y")

class Child(Base):
    __slots__ = ("z",)  # only new slots — inherited x,y come from Base layout

c = Child()
c.x, c.y, c.z = 1,2,3
print(c.x, c.y, c.z)         # 1 2 3
print(hasattr(c, "__dict__")) # False — neither Base nor Child declared __dict__

# What Child.__slots__ inherits:
print(Base.__slots__)   # ('x', 'y')
print(Child.__slots__)  # ('z',)
# Total slots: tuple of all slot names along the MRO that are defined in that class's __slots__.
# MRO aggregation: no duplication — derived lists only its additions.

# Dict shape: plain instances have only most-derived layout;
# but slotted subclasses allocate slots from EACH class with __slots__ consecutively:
# layout = [Base.x, Base.y, Child.z] contiguous array offsets.
```

### `__slots__` and `__dict__` Inheritance

```python
class DictBase:
    __slots__ = ("x", "__dict__")  # base allows dynamic attributes
    def __init__(self, x): self.x=x

class SlottedChild(DictBase):
    __slots__ = ("y",)
    def __init__(self, x, y): super().__init__(x); self.y=y

s = SlottedChild(1,2)
s.dynamic = 99         # works — falls to base's __dict__
print(s.__dict__)      # {'dynamic': 99} — stored via inherited dict

# The dict lives at the level that declared it — per-instance dict is still one dict attached to base.
# Not repeated per subclass — one pointer.

# The inverse: base without slots, child with slots:
class DictPlainBase:
    def __init__(self, x): self.x = x
    # no __slots__, so has __dict__

class SlotMixedChild(DictPlainBase):
    __slots__ = ("y",)
    # Child adds slots but still inherits base's __dict__
    def __init__(self, x, y):
        super().__init__(x)
        self.y = y

m = SlotMixedChild(1,2)
print(m.x, m.y, m.__dict__)  # 1 2 {'x': 1} — x via dict, y via slot
# So mixing dict base + slotted child gives hybrid: x lives in __dict__, y in slot array
# Consequence: `hasattr` works for both, but storage is split — edge for ORM serializers that inspect __dict__ only.

# Pitfall: multiple inheritance with non-empty slots in both bases -> TypeError unless layout compatible
try:
    class BothSlotsA:
        __slots__ = ("a",)
    class BothSlotsB:
        __slots__ = ("b",)  # distinct slots — two non-empty slot bases not allowed
    # class BothSlotsC(BothSlotsA, BothSlotsB):  # uncomment to see:
    #   __slots__ = ("c",)
    # TypeError: multiple bases have instance lay-out conflict
    print("Multiple slot bases demonstration skipped")
except Exception as e:
    print(e)
```

### Empty Slots Trick — Prevent Dynamic Attributes Explicitly

```python
class Strict:
    __slots__ = ()  # no slots — but `__dict__` absent -> no dynamic attrs
    def __init__(self, data): self.data = data  # ❌ data not in slots -> AttributeError

try:
    Strict("hello")
except AttributeError as e: print(f"Strict rejects .data assignments: {e}")

# Combine with subclass that DOES have slots:
class StrictSub(Strict):
    __slots__ = ("data",)
    def __init__(self, data): self.data = data

ss = StrictSub("allowed")
print(ss.data)  # allowed

# Multiple bases with empty slots can mix: empty slot bases contribute no layout conflict,
# so they are used as mixin side-car constraints.
```

### `__slots__` and Method Resolution Order with `property`/`descriptor`

Slot member descriptors are data descriptors (like `property`) — they dominate instance `__dict__` lookups. Since slotted instances often lack `__dict__`, the lookup order simplifies: data descriptor → slot storage → class attribute non-data fallback → `__getattr__`.

```python
class SProp:
    __slots__ = ("_x",)
    def __init__(self, x): self._x = x
    @property
    def x(self):
        return self._x
    @x.setter
    def x(self, v):
        if v < 0: raise ValueError("x must be >= 0")
        self._x = v

s = SProp(5)
print(s.x)          # 5 — property reading from slot _x
s.x = 10
print(s.x)          # 10 — property setter
try: s.x = -1
except ValueError as e: print(e)
```

## Special Slots: `__slots__` Name Collision With Dunders

Do not use dunders `__dict__`, `__weakref__`, or any `__name__` with two leading underscores as a regular slot name — they are reserved. But there are two legal special entries you *should* know:

```python
class DemoWeak:
    __slots__ = ("value", "__weakref__")  # enables weak references — without it `weakref.ref(obj)` fails

class DemoDict:
    __slots__ = ("value", "__dict__")     # enables dynamic attributes — preserves extension-style transition

class DemoBoth:
    __slots__ = ("value", "__dict__", "__weakref__")  # enables both — flexibility at memory cost
```

## Pickling, `copy`, and Serialization

`__slots__` classes picklable by default only if slots contain picklable values and the class is at an importable location. But older pickle tools and naive serializers that assume `__dict__` break:

```python
import pickle, copy

class S:
    __slots__ = ("x","y")
    def __init__(self, x, y): self.x, self.y = x, y
    def __repr__(self): return f"S({self.x},{self.y})"

s = S(1,2)
# pickle handles slots by storing (__setstate__/__getstate__) fallback slot values if defined;
# otherwise it records slot tuple.
data = pickle.dumps(s)
s2 = pickle.loads(data)
print(s2, s2.x, s2.y)  # S(1,2) 1 2 — works out-of-the-box for plain slots

# But custom reduce:
class SR:
    __slots__ = ("x",)
    def __init__(self, x): self.x = x
    def __getstate__(self):
        # Called by pickle — without it, pickle uses __slots__ introspection; with it, customize
        return {"x": self.x}
    def __setstate__(self, state):
        self.x = state["x"]
    def __repr__(self): return f"SR({self.x})"

print(pickle.loads(pickle.dumps(SR(9))))  # SR(9)

# JSON serializers that do `vars(obj)` or `obj.__dict__` fail on slots:
import json
try:
    json.dumps(s.__dict__)
except AttributeError as e:
    print(f"vars on slotted: {e} — json fallback needed")
# So add a helper:
def slotted_to_dict(o):
    return {slot: getattr(o, slot) for slot in getattr(o, "__slots__", ()) if hasattr(o, slot)}

print(slotted_to_dict(s))  # {'x': 1, 'y': 2}

# copy/copy.copy also work — slots storage is copied directly at C level:
c = copy.copy(s)
print(c is s, c.x)  # False 1 — shallow copy, slots copied
```

### Dataclasses + `__slots__`

Python 3.10 `dataclass(slots=True)`, 3.11 `slots` stable, naturally handles pickling, `__getstate__`, and weakrefs for you:

```python
from dataclasses import dataclass

@dataclass(slots=True)
class SlotDC:
    x: int
    y: int
    label: str = ""

print(SlotDC.__slots__)          # ('x', 'y', 'label') — generated, no __dict__
print(hasattr(SlotDC(1,2), "__dict__")) # False
print(pickle.loads(pickle.dumps(SlotDC(1,2,"hi"))))  # works
# `dataclass(slots=True, weakref_slot=True)` mirrors __weakref__ addition.
```

## When to Use `__slots__` — Scorecard

| Indicator | Without slots | With slots |
|-----------|---------------|------------|
| Millions of instances (1k× scale) | Memory dominates; GC slower | Memory reduced ~40–70%; faster allocation |
| Fixed attribute set, rarely dynamic | Access via dict lookup | Fixed array — access slightly faster |
| Rare instance, many types | Negligible win, debug friction not worth | Avoid — flexibility of `__dict__` wins |
| Needs `__dict__` for expansion (e.g., `obj.extra = ...`) | Supported | Breaks unless `__dict__` in slots |
| Uses `weakref` on instances | Works (dict object supports `__weakref__`) | Requires `__weakref__` in slots |
| Pickle / deep serializers assuming `__dict__` | Works | May need `slotted_to_dict` wrappers |
| Debugging with `vars`, `obj.__dict__` introspection, JSON | dict inspection | Introspection less convenient — tuple of slot names |
| Multiple inheritance with disjoint slot layouts | N/A | Conflict (`multiple bases have instance lay-out conflict`) |
| Per-instance hooks (`__setattr__`/`__getattribute__`) | Works | Works — but now bypass interplay matters; slot descriptor dominates |
| Total toolkit compatibility (`attrs`, `dataclass`) | Full | Attrs/dataclass support `slots=True` |


> **Heuristic from Instagram/YouTube streaming experience:** Adopt `__slots__` when profiling shows `__dict__` memory is >30% of live RAM or allocation spikes are traceable to instance dictionaries. Don't prematurely slot a domain model with <1k instances.

## Measurements — How to Profile Correctly

```python
# Example profiling harness (conceptual — run in a separate Python process measuring RSS):

"""
import psutil, os, gc
import sys
from dataclasses import dataclass

@dataclass
class Normal:
    a: int; b: int; c: int; d: int

@dataclass(slots=True)
class Slotted:
    a: int; b: int; c: int; d: int

def size_of_class(cls, n=1_000_000):
    import tracemalloc
    tracemalloc.start()
    objs = [cls(1,2,3,4) for _ in range(n)]
    # prevent optimizer elimination
    s = sum(o.a for o in objs[:10])
    snap = tracemalloc.take_snapshot()
    stats = snap.statistics("lineno")
    # or sum sys.getsizeof with included __dict__
    alive = sum(sys.getsizeof(o) + (sys.getsizeof(o.__dict__) if hasattr(o,'__dict__') else 0)
                for o in objs)
    print(f"RSS: {psutil.Process().memory_info().rss/1e6:.1f} MB, sum snippet {s}")
    tracemalloc.stop()

# Typical production measurement you see shared online (CPython 3.11, 64-bit, 4 int fields):
# Normal (4 slots): ~72 bytes per instance dict + object header -> ~10M inst ~700 MB
# Slotted (4 slots): ~56 bytes object -> ~10M inst ~280 MB  — ~60% savings
"""

# For attributive speed microbench:
"""
import timeit
N = 1_000_000
plain = Normal(1,2,3,4)
slot = Slotted(1,2,3,4)
print(timeit.timeit('plain.a; plain.b; plain.c', globals=globals(), number=N))
print(timeit.timeit('slot.a; slot.b; slot.c', globals=globals(), number=N))
# Slotted tends to be ~15–30% faster due to direct offset, not hash.

# Note: benchmark on hot inner loop only, not on startup; warm JIT etc. doesn't exist in CPython,
# but branch prediction warm-up matters for microbenches — rerun multiple times.
"""
```

### GC Behavior

*   Objects with `__dict__` participate in cyclic-GC when they may own cycles via `__dict__` values; slotted objects without `__dict__` but with slot pointings still track if any slot holds a `GC-tracked` object (list, dict). Overall GC of slotted allocations may involve fewer `PyGC_Head` entries only marginally — not a primary win.

## Common Mistakes & Hard-Won Advice

| Mistake | What Breaks | Fix |
|---------|-------------|-----|
| Forgetting `__slots__ = ()` vs `__slots__ = "__dict__"` | No slots vs accidental slot per character | Tuple assignment `( "name",)` not bare string |
| Assigning undeclared `obj.foo = 1` on slotted instance without `__dict__` | `AttributeError: 'X' object has no attribute 'foo'` | Add `__dict__` to slots or use fixed slot name design |
| No `__weakref__` but expecting `weakref.ref(slotted_obj)` | `TypeError: cannot create weak reference to 'X' object` | Include `__weakref__` in slots |
| Providing default via class attr named like a slot | Slot descriptor shadowed; default never reached | Assign defaults in `__init__` |
| `class Child(BaseWithSlots): pass` without own `__slots__` | Child gets `__dict__` and `__weakref__` (implicitly) — saves nothing | Child must declare `__slots__ = ()` explicitly to inherit slot-only nature |
| Shadowing slot descriptor with a class attribute assignment `Cls.x = ...` | Slot machinery destroyed | Never assign to `Cls.__slots__` name as a data setter; treat as immutable layout |
| Serializer assumes `obj.__dict__` | Missing slots fields in dump | Provide `slots_dict(o)` helper or `object.__slots__` introspection; or switch to `dataclass` `asdict` |
| Not measuring before adopting | Complexity added with no measured win | Profile with `memory_profiler`/`tracemalloc`/`pympler` first |

## Checklist

1.  Have you measured live RAM with `tracemalloc` / `pympler` and confirmed `__dict__` is a significant fraction?
2.  Does every subclass declare `__slots__` (even `__slots__ = ()` when it adds no new slots but should remain slotted)?
3.  Is `__dict__` / `__weakref__` included intentionally, not accidentally?
4.  Have you added constructor `__init__` defaults for all required slots (no relying on class-attr fallback)?
5.  Did you back-test pickle/JSON serializers via `pickle.dumps` / `vars` introspection?
6.  Have you confirmed `weakref` / `copy` / `gc` compatibility for your use-case?
7.  Is inheritance hierarchy shallow and compatible — no double slot-bearing bases causing layout conflict?
8.  Is a `dataclass(slots=True)` or `attrs` slot variant more maintainable than manual `__slots__` for your team?

## Slots As Descriptors and Inheritance

### Slots As Data Descriptors

```python
class SlotDemo:
    __slots__ = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y
    @property
    def total(self): return self.x + self.y
print(type(SlotDemo.__dict__["x"]))
print(type(SlotDemo.__dict__["total"]))

class ValidatedSlot:
    __slots__ = ("_value",)
    def __init__(self, value): self.value = value
    @property
    def value(self): return self._value
    @value.setter
    def value(self, v):
        if v < 0: raise ValueError("value must be non-negative")
        self._value = v
vs = ValidatedSlot(10)
print(vs.value)
```

### Inheritance Conflict Table

```python
class A: __slots__ = ("a",)
class Bmix: __slots__ = ()  # no layout, no conflict
class CA(Bmix, A):
    __slots__ = ("extra",)
ca = CA(); ca.a = 1; ca.extra = 2
print(ca.a, ca.extra)

class WeakSlotParent:
    __slots__ = ("x", "__weakref__")
    def __init__(self, x): self.x = x
class WeakSlotChild(WeakSlotParent):
    __slots__ = ("y",)
    def __init__(self, x, y): super().__init__(x); self.y = y
import weakref, pickle
w = WeakSlotChild(1, 2)
print(weakref.ref(w)() is w)
print(pickle.loads(pickle.dumps(w)).x)
```
