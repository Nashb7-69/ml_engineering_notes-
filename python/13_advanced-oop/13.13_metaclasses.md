# 13.13 Metaclasses: type, __new__, __prepare__, __call__, and the Simpler __init_subclass__

## The Class Is An Object Too

In Python, classes are objects. The object that *constructs* classes — the class of classes — is its metaclass. By default that metaclass is `type`:

```python
class Foo:
    x = 1

print(type(Foo))            # <class 'type'> — Foo's metaclass is type
print(isinstance(Foo, type))# True — Foo is an instance of type
print(type(type(Foo)))      # <class 'type'> — type is its own metaclass (circular, but consistent)
print(type)                 # <class 'type'> — type is the universal factory
print(Foo.__class__)        # <class 'type'> — same thing

# type does three jobs:
#   1. Called as type(obj) -> returns obj's type (introspection)
#   2. Called as type(name, bases, dict) -> constructs a new class (metaclass call)
#   3. As default metaclass, its __call__ orchestrates instance construction (13.02)
```

> **Mental model:** If `obj = Class()` creates an instance by calling `type.__call__` then `Class(...)`, then `Class = type(...)` creates a class by calling `type.__call__` on the *metaclass*. The same instantiation machinery operates one level up.

```
Instance creation:          Class(...)  →  type.__call__(Class, ...)  →  Class.__new__ + Class.__init__
Class creation:        class Foo: ...   →  type.__call__(type, "Foo", (Base,), {...})  →  type.__new__ + type.__init__
```

## The Class Definition Execution Model

When Python executes a `class` statement, it runs these steps (simplified, matching CPython 3.11 docs https://docs.python.org/3/reference/datamodel.html#customizing-class-creation):

```python
# Written:
class Foo(BaseA, BaseB, metaclass=Meta, kw=val):
    x = 1
    def method(self): pass

# Executes as (approximately):

# 1. Determine metaclass:
#    - if metaclass= given, that's it
#    - else use type(b) for the first base's type that has a metaclass
#    - else `type`
metaclass = Meta if "metaclass" in keywords else _figure_metaclass((BaseA, BaseB))
# Conflict rule: all base metaclasses must be subclasses of chosen metaclass (or TypeError)

# 2. Prepare namespace:
#    - Call metaclass.__prepare__("Foo", (BaseA, BaseB), kw=val) -> dict-like namespace (often plain dict)
#    - For OrderedDict preserving insertion order pre-3.7, needed custom mapping; now plain dict is ordered.
namespace = metaclass.__prepare__("Foo", (BaseA, BaseB), kw=val)

# 3. Execute class body in namespace:
#    exec("x = 1\ndef method(self): pass", namespace)

# 4. Construct class object:
#    Foo = metaclass.__new__(metaclass, "Foo", (BaseA, BaseB), namespace)
#    metaclass.__init__(Foo, "Foo", (BaseA, BaseB), namespace)  # initialize class object
#    (Internally, type.__call__ orchestrates __new__ + __init__, same as instance creation)
```

So `class` is syntax sugar for calling the metaclass. The class body *executes* to fill the namespace dict, then the metaclass builds the class object.

```python
# Manual construction equivalent:
MyClass = type("MyClass", (object,), {"x": 1, "method": lambda self: 42})
# type(name, bases, dict) is just `type.__call__(type, name, bases, dict)` via its `__new__` + `__init__`
# Check: same as `class MyClass: x=1; def method(self): return 42`
print(MyClass, MyClass.x, MyClass().method())

# Dynamic class creation:
def make_class(name: str, bases, attrs):  return type(name, bases, attrs)
Point = make_class("Point", (), {"x": 1, "y": 2})
print(Point.x, Point.y)
```

## `type.__new__` vs `type.__call__` vs Metaclass `__prepare__`

| Hook | Signature | Role |
|------|-----------|------|
| `__prepare__(mcls, name, bases, **kw)` | `@classmethod` returning a mapping | Allocate the namespace dict (or custom Ordered mapping) where the class body will execute. 3.7+ defaults to plain `dict`. Rarely needed. |
| `__new__(mcls, name, bases, ns, **kw)` | `(cls, name, bases, dict)` | Create and return the class object. Allocate properties, transform the namespace. Most metaclass work goes here. |
| `__init__(cls, name, bases, ns, **kw)` | `(cls, name, bases, dict)` | Initialize the already-created class object. Optional — `__new__` already created it. |
| `__call__(cls, *args, **kw)` | on metaclass — orchestration | Called when you write `Cls(*args)` to make an instance; delegates to `Cls.__new__` + `Cls.__init__` as seen in 13.02. Overriding lets you customize instance creation semantics (argument preprocessing, pooling, registry on construction). |

```python
# Metaclass hooks demonstration in order:

class ShowMetaclass(type):
    @classmethod
    def __prepare__(mcls, name, bases, **kw):
        print(f"[{mcls.__name__}.__prepare__] name={name}, bases={bases}, kw={kw}")
        # Return a dict subclass that logs insertions
        d = dict()
        original_setitem = d.__setitem__
        def logging_setitem(k, v):
            print(f"  [prepare ns] {k!r} = {v!r}")
            original_setitem(k, v)
        d.__setitem__ = logging_setitem  # crude logging namespace — cleaner to subclass dict
        return d

    def __new__(mcls, name, bases, ns, **kw):
        print(f"[{mcls.__name__}.__new__] name={name}, bases={bases}, ns.keys={list(ns.keys())}, kw={kw}")
        cls = super().__new__(mcls, name, bases, dict(ns))
        print(f"  -> created {cls}")
        return cls

    def __init__(cls, name, bases, ns, **kw):
        print(f"[{type(cls).__name__}.__init__] cls={cls.__name__}, name={name}")
        super().__init__(name, bases, ns)

    def __call__(cls, *args, **kwargs):
        print(f"[{type(cls).__name__}.__call__] constructing {cls.__name__}({args},{kwargs})")
        # Replicate type.__call__ with instrumentation:
        obj = cls.__new__(cls, *args, **kwargs)
        if isinstance(obj, cls):
            cls.__init__(obj, *args, **kwargs)
        print(f"  -> {obj!r}")
        return obj

class Service(metaclass=ShowMetaclass, version=1):  # kw arg `version` passes to __prepare__/__new__/__init__
    x = 10
    def method(self): return self.x

print("--- instantiation ---")
s = Service()
print(s.method())
```

Output order:

```
[ShowMetaclass.__prepare__] name=Service ...
  [prepare ns] '__module__' = '__main__'
  [prepare ns] '__qualname__' = 'Service'
  [prepare ns] 'x' = 10
  [prepare ns] 'method' = <function ...>
[ShowMetaclass.__new__] ...
[ShowMetaclass.__init__] ...
--- instantiation ---
[ShowMetaclass.__call__] constructing Service ...
```

## What `__prepare__` Actually Enables (And When You'd Need It)

`__prepare__` returns the mapping used for the class namespace. The main historical use was collecting ordered `__slots__` or preserving definition order before `dict` became ordered (Python 3.7). Modern uses:

*   Validate or transform attributes as they are defined (e.g., reject duplicate keys, collect ordered declarations)
*   Return a custom mapping that enforces constraints (e.g., "every method must have a docstring")

```python
class EnforceDocDict(dict):
    """Dict subclass that rejects functions without docstrings."""
    def __setitem__(self, key, value):
        if callable(value) and not key.startswith("_") and value.__doc__ is None:
            raise TypeError(f"Method {key!r} must have a docstring")
        super().__setitem__(key, value)

class DocEnforcer(type):
    @classmethod
    def __prepare__(mcls, name, bases):
        return EnforceDocDict()

    def __new__(mcls, name, bases, ns):
        # EnforceDocDict -> plain dict for final class
        return super().__new__(mcls, name, bases, dict(ns))

try:
    class Bad(metaclass=DocEnforcer):
        def method_without_docs(self):  # ❌ no docstring
            pass
except TypeError as e:
    print(e)

class Good(metaclass=DocEnforcer):
    def method_with_docs(self):
        """I have docs."""
        pass
print("Good class defined — docstring enforced at class-definition-time, not at call time")
```

In practice, `__prepare__` is rarely needed — 95% of metaclass work uses `__new__` alone. If you can enforce the constraint in `__new__` after the body executes, prefer that over `__prepare__` complexity.

## Use Cases — When a Metaclass IS the Right Tool

### 1. Registry Pattern — Collect Every Subclass Automatically

Classic ORM / plugin use-case: every subclass of `Model` or `Plugin` registers itself into a central map by name:

```python
# Via metaclass:
class RegistryMeta(type):
    registry: dict[str, type] = {}

    def __new__(mcls, name, bases, ns):
        cls = super().__new__(mcls, name, bases, ns)
        # Don't register the abstract base itself — only concrete subclasses
        if not ns.get("_abstract", False):
            mcls.registry[name] = cls
            print(f"[registry] registered {name}")
        return cls

    def __call__(cls, *args, **kwargs):
        print(f"[registry] constructing {cls.__name__}")
        return super().__call__(*args, **kwargs)

class Base(metaclass=RegistryMeta):
    _abstract = True  # skip self-registration

class PluginA(Base): pass
class PluginB(Base): pass

print(RegistryMeta.registry)  # {'PluginA': <class 'PluginA'>, 'PluginB': ...}
# Instantiate via name:
plugin = RegistryMeta.registry["PluginA"]()
# Factory: `def make(name, *a, **kw): return RegistryMeta.registry[name](*a, **kw)`

# Why metaclass? The registry collects at *class definition* time, not instantiation — ideal for
# plugin discovery before any object exists.
```

**Alternative (usually preferred): `__init_subclass__` (PEP 560, Python 3.6+) — no metaclass needed:**

```python
# Same registry WITHOUT a metaclass — simpler, avoids metaclass conflict:
class SimpleRegistry:
    registry: dict[str, type] = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        # __init_subclass__ runs on the PARENT when a CHILD is defined — perfect registry hook
        if getattr(cls, "_abstract", False):
            return
        SimpleRegistry.registry[cls.__name__] = cls
        print(f"[SimpleRegistry] registered {cls.__name__}")

    def __init__(self): pass  # regular instance init

class SBase(SimpleRegistry):
    _abstract = True

class SPluginA(SBase): pass
class SPluginB(SBase): pass

print(SimpleRegistry.registry)  # {'SPluginA': ..., 'SPluginB': ...}
print("Registry via __init_subclass__ — no metaclass, no conflicts, testable")
```

> **Rule of thumb (Guido's advice):** If you can solve it with `__init_subclass__`, a class decorator, or a `__new__` override, do — reach for a metaclass only when you need to intercept the full namespace (e.g., collect `__prepare__`, transform the class object *before* `__init_subclass__` runs, or coordinate multiple inheritance at the metaclass level).

### 2. Validation — Enforce Invariants on the Class Itself

```python
# Require every subclass to define `table_name`:
class RequireTableMeta(type):
    def __new__(mcls, name, bases, ns):
        # Locate table_name — consider inherited value? Check both ns and bases' attributes.
        has_own = "table_name" in ns
        has_inherited = any(hasattr(b, "table_name") for b in bases)
        is_abstract = ns.get("_abstract", False)
        if not is_abstract and not has_own and not has_inherited:
            raise TypeError(f"Class {name!r} must define `table_name = ...`")
        cls = super().__new__(mcls, name, bases, ns)
        return cls

class BaseModel(metaclass=RequireTableMeta):
    _abstract = True

class GoodModel(BaseModel):
    table_name = "good_table"  # ok

try:
    class BadModel(BaseModel):  # ❌ missing table_name
        pass
except TypeError as e:
    print(f"Validation caught: {e}")

# Equivalent with __init_subclass__ — clearer and avoids metaclass:

class RequireTableVirtue:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if getattr(cls, "_abstract", False):
            return
        if not hasattr(cls, "table_name"):
            raise TypeError(f"Class {cls.__name__!r} must define `table_name`")
        print(f"[validate] {cls.__name__} has table_name={cls.table_name!r}")

class VirtueBase(RequireTableVirtue):
    _abstract = True
class VirtueGood(VirtueBase):
    table_name = "virtue_good"
# class VirtueBad(VirtueBase): pass  # would raise TypeError here
```

### 3. Singleton Metaclass — Make Every Class a Singleton

```python
class SingletonMeta(type):
    """Metaclass making any class a singleton — __call__ returns the cached instance."""
    def __init__(cls, name, bases, ns):
        super().__init__(name, bases, ns)
        cls._instance = None

    def __call__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__call__(*args, **kwargs)
        return cls._instance

class Config(metaclass=SingletonMeta):
    def __init__(self, dsn: str = "default"):
        # This runs only once — second construction reuses instance and skips __init__ (via __call__'s guard)
        self.dsn = dsn
        print(f"Config.__init__({dsn})")

a = Config("postgres://a")
b = Config("postgres://b")  # second call IGNORED — same object, __init__ not re-run
print(a is b)               # True
print(a.dsn, b.dsn)         # postgres://a postgres://a

# Warning: Singleton via metaclass is heavy. Module-level instance `config = Config(...)` is almost always simpler.
# Use metaclass singleton only when the singleton guarantee must survive inheritance:
# `class Sub(Config): pass` — Sub would share Config's singleton! Usually unwanted.
# So the meta-version couples inheritance and instance-sharing oddly — prefer composition.
```

### 4. Caching / Interning at Instance Level via Metaclass `__call__`

```python
class InternedMeta(type):
    """Cache instances by constructor args — value-object flyweight."""
    def __init__(cls, name, bases, ns):
        super().__init__(name, bases, ns)
        cls._pool: dict[tuple, object] = {}

    def __call__(cls, *args, **kwargs):
        key = (args, tuple(sorted(kwargs.items())))
        if key in cls._pool:
            return cls._pool[key]
        obj = super().__call__(*args, **kwargs)
        cls._pool[key] = obj
        return obj

class Color(metaclass=InternedMeta):
    def __init__(self, r, g, b): self.r, self.g, self.b = r, g, b
    def __repr__(self): return f"Color({self.r},{self.g},{self.b})"

a, b = Color(255,0,0), Color(255,0,0)
print(a is b)  # True — interned via metaclass

# Same without metaclass: override `__new__` (13.02) or use `__call__` on `__new__` level;
# pick whichever level your pooling logic belongs to. Metaclass interning is natural when it applies
# uniformly to all instances via class-level policy.
```

### 5. Auto-Generated Members (`__slots__` synthesis, auto-`__repr__`, enum)

```python
# Auto-injected `__repr__` via metaclass — frameworks like `typing.NamedTuple` and stdlib `enum.Enum` use this:
class AutoRepr(type):
    def __new__(mcls, name, bases, ns):
        # If class has `fields: tuple[str]` declare, auto-build __repr__
        fields = ns.get("fields")
        if fields and "__repr__" not in ns:
            def __repr__(self):
                parts = ", ".join(f"{f}={getattr(self, f)!r}" for f in self.fields)
                return f"{type(self).__name__}({parts})"
            ns["__repr__"] = __repr__
        return super().__new__(mcls, name, bases, ns)

class Point(metaclass=AutoRepr):
    fields = ("x", "y")
    def __init__(self, x, y): self.x, self.y = x, y

print(Point(1,2))  # Point(x=1, y=2) — injected
# Again, `@dataclass` or a class decorator achieves the same with less ceremony:
# @auto_repr(fields=("x","y"))
```

## Metaclass Conflicts — The MRO of Metaclasses

When a class inherits from multiple bases with different metaclasses, Python requires the resulting metaclass to be a common subclass of all base metaclasses. If not, you get `TypeError: metaclass conflict`:

```python
class M1(type): pass
class M2(type): pass

class Base1(metaclass=M1): pass
class Base2(metaclass=M2): pass

# try:
#   class Child(Base1, Base2): pass  # ❌ TypeError: metaclass conflict: the metaclass of a derived class must be a (non-strict) subclass of the metaclasses of all its bases
# except TypeError as e: print(e)

# Fix: make M1 and M2 share a common sub-metaclass:
class M12(M1, M2): pass

class Fixed(Base1, Base2, metaclass=M12): pass  # resolves — explicit metaclass satisfies
print(f"M12 resolved conflict — Fixed's type is {type(Fixed).__name__}")

# Because metaclasses participate in the same MRO algebra as classes, conflicts are rare but
# diagnosing them requires understanding the two-level MRO. Prevention: prefer `__init_subclass__`
# — it has no metaclass conflict issue because it runs on the parent, not on a metacross layer.
```

### `__classcell__` and `super()` Interaction

When a class body uses `super()` (zero-argument form), the compiler inserts a `__classcell__` closure. Metaclasses must propagate it:

```python
# Inside a metaclass __new__, if you deepcopy/transform ns, you must preserve `__classcell__`:
# cls = super().__new__(mcls, name, bases, ns)  # CPython requires __classcell__ in ns if present
# If you accidentally drop it, `super()` inside methods declared in the class body will fail with
# `RuntimeError: super(): no arguments`.
# So never `dict(ns)` blindly when ns is a custom __prepare__ mapping — keep the original key.
```

## When NOT to Use a Metaclass — The Simpler Alternatives

| Need | Use | Why not metaclass |
|------|-----|-------------------|
| Transform/inject per-class on definition | `__init_subclass__` (PEP 487) | No conflict, simpler syntax, per-parent customization via keyword args |
| Per-class decorator / wrap methods | `@decorator` on class | Applied after construction, no need for two-level hooks |
| Generic `Type[int]` style | `__class_getitem__` (PEP 560) | Handles `List[int]` syntax without metaclass `__getitem__` on type |
| Single inheritance registry / validation | `__init_subclass__` | One-level — inheritance doesn't exponentiate complexity |
| Factory that returns diff subtype | `__new__` on parent class | No metaclass needed — see 13.02 |
| Attribute injection / auto `__repr__` | `@dataclass`, class decorator | Library-built alternatives exist |

```python
# Before PEP 560, generic alias syntax required metaclass __getitem__:
# Old way (still valid):
class GenericMeta(type):
    def __getitem__(cls, item): return f"{cls.__name__}[{item.__name__}]"
class List_generic(metaclass=GenericMeta): pass
print(List_generic[int])  # List_generic[int]
# Now: define __class_getitem__ directly on the class — no metaclass needed:
class Modern:
    def __class_getitem__(cls, item): return f"{cls.__name__}[{item.__name__}]"
print(Modern[int])  # Modern[int]

# __init_subclass__ with kwargs — often confused for metaclass __new__:
class PluginBase:
    plugins: dict[str, type] = {}
    def __init_subclass__(cls, plugin_name: str | None = None, **kwargs):
        super().__init_subclass__(**kwargs)
        if plugin_name is not None:
            PluginBase.plugins[plugin_name] = cls
            print(f"  Plugin registered: {plugin_name} -> {cls.__name__}")

class CSVPlugin(PluginBase, plugin_name="csv"): pass
class JSONPlugin(PluginBase, plugin_name="json"): pass
print(PluginBase.plugins)

# So when the distinction matters, here's a side-by-side:
# Metaclass sees the full raw namespace dict before the class object is created.
# __init_subclass__ sees the *already-created* subclass and can mutate it, but the parent hook runs
# after construction — so transforming `ns` pre-creation requires metaclass.
# Example of pre-creation transform that __init_subclass__ cannot do cleanly: re-ordering fields
# declared as plain annotations before dataclass fields are finalized.
```

## Combining Metaclass, Descriptors, and `__prepare__` — Advanced Synthesis

```python
# Rich example: a minimal field-collector ORM-style base using metaclass + descriptor

class Field:
    def __init__(self, col_type): self.col_type = col_type
    def __set_name__(self, owner, name): self.name = name

class EntityMeta(type):
    @classmethod
    def __prepare__(mcls, name, bases):
        # Preserve definition order for column ordering
        return {}

    def __new__(mcls, name, bases, ns):
        # Collect Field instances in definition order
        fields = {k: v for k, v in ns.items() if isinstance(v, Field)}
        # Inject `__fields__` for introspection
        ns["__fields__"] = fields
        # Auto `__init__` that pulls kwargs for declared fields
        if "__init__" not in ns and fields:
            def __init__(self, **kwargs):
                for f in fields:
                    if f not in kwargs:
                        raise TypeError(f"Missing field {f!r}")
                    setattr(self, f, kwargs[f])
            ns["__init__"] = __init__
        # Auto `__repr__`
        if "__repr__" not in ns and fields:
            def __repr__(self):
                parts = ", ".join(f"{k}={getattr(self, k)!r}" for k in type(self).__fields__)
                return f"{type(self).__name__}({parts})"
            ns["__repr__"] = __repr__
        return super().__new__(mcls, name, bases, ns)

class Entity(metaclass=EntityMeta): pass

class User(Entity):
    name = Field(str)
    email = Field(str)
    age = Field(int)

u = User(name="Alice", email="a@example.com", age=30)
print(u)                         # User(name='Alice', email='a@example.com', age=30)
print(User.__fields__)           # {'name': Field, ...} — ordered as declared

# Validation hook could be in Field.__set__: e.g., check type on assignment; metaclass not needed there.
# So the metaclass contributes: collection, ordering, injection — descriptors handle per-attribute logic.
```

## The Modern Ladder of Customization — From Lightest to Heaviest

| Weight | Tool | Detects/Affects | Conflict risk |
|--------|------|-----------------|---------------|
| Light | Class decorator `@dec` | After construction, mutate class | None |
| | `__init_subclass__` | On each subclass definition, per-parent | None |
| | Descriptor + `__set_name__` | Per-attribute wiring | None |
| | `__class_getitem__` | Generic alias syntax | None |
| | Metaclass (`type` subclass) with `__new__` | Pre-construction transform of raw namespace | Medium |
| Heavy | Metaclass with `__prepare__` | Namespace allocation policy | Medium |
| Heavy+ | Metaclass `__call__` | Instance construction orchestration | High — interacts with metaclass `__call__` across hierarchy |

> **Guidance:** Start at the top and descend only when you can state precisely what `__init_subclass__` or a decorator cannot achieve.

## Common Mistakes and Anti-Patterns

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Forgetting `super().__new__` in metaclass `__new__` and not returning a class object | `class Foo(...):` results in `Foo is None` or `TypeError` | `return super().__new__(mcls, name, bases, ns)` or `return type.__new__(mcls, ...)` |
| Defining `type.__new__` without handling extra kwargs | `TypeError: type.__new__() takes ...` on class with keyword args like `class Foo(metaclass=M, kw=1):` | `def __new__(mcls, name, bases, ns, **kw): ...` and pass through |
| Returning a non-type from metaclass `__new__` when not intended | `class Foo` binds to weird object, `isinstance` breaks | Only return `cls` unless you intend factory semantics (rare and confusing — prefer explicit function) |
| Overriding metaclass `__call__` without guarding `isinstance` | `__init__` called even when `__new__` returned different type | Mimic `type.__call__` gating: `obj = cls.__new__(cls, ...); if isinstance(obj, cls): cls.__init__(obj, ...)` |
| Dropping `__classcell__` in transformed `ns` | `super()` inside methods fails | Preserve `ns.get("__classcell__")` when wrapping |
| Using metaclass where `__init_subclass__` suffices | Metaclass conflict surprises, harder testing | Rewrite as `__init_subclass__(cls, ...)` on parent |
| `__prepare__` returning wrong type (non-mapping or plain mapping that loses invariants) | `class Body: ...` `TypeError` at `exec` or lost ordering/validation | Return a mapping that behaves like `dict` for `__setitem__`; test by defining a class with unusual body |
| Metaclass singleton that couples subclasses | `SubSingleton is BaseSingleton` — same instance | Avoid hierarchy-coupled singleton; prefer module-instance |

## Checklist

1.  Is `type` the right mental base? Draw the two-level diagram: instance ← class ← metaclass.
2.  Have you written the class creation desugaring and checked which hook you actually need: `__prepare__` (custom ns allocation), `__new__` (namespace transform before class exists), `__call__` (instance creation orchestration)?
3.  If the hook is per-subclass registration or validation, consider `__init_subclass__` first.
4.  Does your metaclass handle `**kwargs` keywords from `class Foo(metaclass=M, kw=1):` without throwing?
5.  Have you handled metaclass conflict before shipping for multiple inheritance? Prefer single-metaclass design or structural composition.
6.  Is `__classcell__` preserved when you wrap the namespace?
7.  Have you benchmarked or at least read the class creation path — metaclass overhead per class definition is tiny and only at import time, not per instance.

5.  When would you expose `__class_getitem__` instead of a metaclass `__getitem__` for generic alias like `MyGeneric[int]`? Test both and explain import-time behavior.

## Additional Metaclass Patterns

### Plugin Metadata via Metaclass Keywords

```python
class PluginMeta(type):
    def __new__(mcls, name, bases, ns, **kw):
        plugin_name = kw.pop("plugin_name", None)
        cls = super().__new__(mcls, name, bases, ns)
        if plugin_name: cls._plugin_name = plugin_name
        return cls

class PluginBase(metaclass=PluginMeta): pass
class CSVPlugin(PluginBase, plugin_name="csv"): pass
print(CSVPlugin._plugin_name)
```

### Dataclass and Metaclass Validation

```python
from dataclasses import dataclass
class OrderMeta(type):
    def __new__(mcls, name, bases, ns):
        for k in list(ns.get("__annotations__", {})):
            if k != k.lower():
                raise TypeError(f"field {k!r} must be lowercase")
        return super().__new__(mcls, name, bases, ns)

@dataclass
class PointMeta(metaclass=OrderMeta):
    x: int
    y: int
print(PointMeta(1,2))
```
