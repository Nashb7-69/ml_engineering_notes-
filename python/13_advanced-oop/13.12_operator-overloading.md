# 13.12 Operator Overloading: Arithmetic, Reflected, Augmented, and Unary Operators

## Why Operators Are Hooks, Not Privileges

Arithmetic in Python never assumed "numbers only". `a + b` means `type(a).__add__(a, b)` with a fallback to `type(b).__radd__(b, a)` — the same protocol as `len(obj)` but with an extra reflection step that lets the *right* operand participate when the left doesn't know how.

This makes operator semantics cooperative: a custom `Money` class can add with `int` by returning `NotImplemented` for unknowns and letting the `int` side decide; or both sides can meet at equality via the contract.

```python
# Desugaring:
#   a + b  -->
#     result = type(a).__add__(a, b)
#     if result is NotImplemented:
#         result = type(b).__radd__(b, a)
#     if result is NotImplemented:
#         raise TypeError(f"unsupported operand type(s) for +: '{type(a).__name__}' and '{type(b).__name__}'")

# Same pattern for every binary operator: +, -, *, /, //, %, **, &, |, ^, <<, >>, @
# Unary operators have no reflection:  -a  -->  type(a).__neg__(a)
# In-place (augmented):  a += b  -->  type(a).__iadd__(a, b)  falling back to type(a).__add__(a, b)
```

> **Mental model:** Operators are *double-dispatch*. Left goes first; right gets a chance only if left opts out (`NotImplemented`). If both opt out, the operation is a `TypeError`. This symmetry is what makes heterogeneous arithmetic correct.

| Category | Left (`__xxx__`) | Right (`__rxxx__`) | In-place (`__ixxx__`) |

| Method | Syntax | Purpose |
|--------|--------|---------|

## Reflected Operations — The Symmetry That Matters

### Commutative Case (`+` is often commutative but not always — strings are not)

```python
class Vector:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, other):
        if isinstance(other, Vector): return Vector(self.x + other.x, self.y + other.y)
        return NotImplemented  # ← lets int try __radd__ (which will also fail, so TypeError)
    __radd__ = __add__  # Vectors add commutatively, so symmetric — alias is fine

    def __mul__(self, scalar):
        if isinstance(scalar, (int, float)):
            return Vector(self.x * scalar, self.y * scalar)
        return NotImplemented
    __rmul__ = __mul__  # scalar * Vector commutatively via __rmul__

    def __repr__(self): return f"Vector({self.x}, {self.y})"

v = Vector(1, 2)
print(v + Vector(3, 4))  # Vector(4, 6) — __add__
print(v * 3)             # Vector(3, 6) — __mul__
print(3 * v)             # Vector(3, 6) — __rmul__ (int.__mul__(3, v) returns NotImplemented, then v.__rmul__)

# Trace for 3 * v:
#   type(3).__mul__(3, v) -> NotImplemented (int doesn't know Vector)
#   type(v).__rmul__(v, 3) -> Vector(3, 6) — succeeds
print(v * 3.5)           # Vector(3.5, 7.0) — float
```

### Non-Commutative Case — Subtraction is Anti-commutative; Matrix Multiply Not Commutative

```python
class Money:
    def __init__(self, cents: int, currency: str = "USD"):
        self.cents, self.currency = cents, currency

    def _check(self, other):
        if not isinstance(other, Money): return NotImplemented
        if other.currency != self.currency:
            raise ValueError(f"Cannot mix {self.currency} and {other.currency}")
        return None

    def __add__(self, other):
        chk = self._check(other)
        if chk is NotImplemented: return NotImplemented
        return Money(self.cents + other.cents, self.currency)
    __radd__ = __add__  # commutative within Money domain

    def __sub__(self, other):
        chk = self._check(other)
        if chk is NotImplemented: return NotImplemented
        return Money(self.cents - other.cents, self.currency)

    def __rsub__(self, other):
        # other - self  where other is not Money
        if isinstance(other, Money):
            # Should not reach here via _check — delegated case
            return other.__sub__(self)
        # Allow int - Money?
        if isinstance(other, int):
            # e.g., 1000 - Money(100, "USD") = Money(900, "USD")
            return Money(other - self.cents, self.currency)
        return NotImplemented

    def __repr__(self): return f"Money({self.cents}, {self.currency!r})"

m = Money(100, "USD")
print(m + Money(50, "USD"))   # Money(150, 'USD')
print(m - Money(30, "USD"))   # Money(70, 'USD')
print(200 - m)                # Money(100, 'USD') — via __rsub__, int minus money notion
print(m - 20)                 # TypeError — Money._check expects Money, returns NotImplemented, both sides opt out -> TypeError
```

> **Design advice:** Decide what `__rxxx__` should support. Often, `__add__/__radd__` is symmetric (alias), but `__sub__/__rsub__` is not — `a - b` ≠ `b - a`. Document which mixed types each operator accepts.

## Augmented Assignment (`__ixxx__`) — In-Place Contract

`a += b` first tries `type(a).__iadd__(a, b)`. If `__iadd__` missing, it falls back to `a = a.__add__(a, b)`. Crucially, `__iadd__` **must** return `self` (or the mutated thing) — it does *not* need to mutate in place, but for mutable types mutating and returning `self` is faster (no allocation).

```python
class Accum:
    """Demonstrates __iadd__ correctly."""
    def __init__(self, value=0): self.value = value
    def __add__(self, other):
        if isinstance(other, Accum): return Accum(self.value + other.value)
        if isinstance(other, (int, float)): return Accum(self.value + other)
        return NotImplemented
    __radd__ = __add__

    def __iadd__(self, other):
        if isinstance(other, Accum): self.value += other.value
        elif isinstance(other, (int, float)): self.value += other
        else: return NotImplemented
        return self  # ← must return self for `a += b` to rebind to self

    def __repr__(self): return f"Accum({self.value})"

a = Accum(10)
print(id(a))
a += Accum(5)           # mutates a in place — id unchanged
print(a, id(a))

# Pitfall: forgetting return
class Forgetful:
    def __init__(self, v): self.v = v
    def __iadd__(self, other):
        self.v += other.v  # mutates
        # Missing `return self` — implicitly returns None!
    def __repr__(self): return f"Forgetful({self.v})"

f = Forgetful(1)
print("before id", id(f))
f += Forgetful(2)             # f.__iadd__(f, Forgetful(2)) -> None  → f = None
print(f)                       # None — catastrophically lost object
# Always end __ixxx__ with `return self` (or meaningful re-bound value).
```

### Mutable vs Immutable `__ixxx__` Strategy

```python
# Immutable: __iadd__ returns a NEW object (no in-place optimization)
class ImmutableVec:
    __slots__ = ("x","y")
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, other):
        if isinstance(other, ImmutableVec): return ImmutableVec(self.x+other.x, self.y+other.y)
        return NotImplemented
    __radd__ = __add__
    def __iadd__(self, other):
        # For immutables (tuple-like), just delegate — no mutation
        result = self.__add__(other)
        if result is NotImplemented:
            return NotImplemented
        # Return the NEW object — `a += b` for immutable rebinds a to new value, like tuple += does
        return result
    def __repr__(self): return f"ImmutableVec({self.x}, {self.y})"

# Tuple's += is `t = t + other` (new tuple) — same contract.

# Mutable: __iadd__ mutates and returns self
class MutableVec:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, other):
        if isinstance(other, MutableVec): return MutableVec(self.x+other.x, self.y+other.y)
        return NotImplemented
    def __iadd__(self, other):
        if isinstance(other, MutableVec): self.x += other.x; self.y += other.y; return self
        return NotImplemented
    def __repr__(self): return f"MutableVec({self.x}, {self.y})"

a = MutableVec(1,1)
b = a                    # alias
a += MutableVec(2,2)
print(a, b)              # both mutated — same object; callers sharing alias see change (intentional for mutable)
```

## Complete Realistic Example: `Money` with Full Ops

```python
from decimal import Decimal

class Money:
    """
    Money as value type: immutable, hashable, exact cents via integer, currency-enforced ops.
    Demonstrates: __add__/__radd__/__sub__/__rsub__/__mul__/__rmul__/__truediv__/__floordiv__/__neg__/__abs__/__round__
    """
    __slots__ = ("_cents", "currency")

    def __init__(self, cents: int, currency: str = "USD"):
        self._cents, self.currency = int(cents), currency

    @classmethod
    def from_decimal(cls, amount: Decimal, currency: str = "USD") -> "Money":
        cents = int((amount * 100).quantize(Decimal("1")))
        return cls(cents, currency)

    @property
    def cents(self) -> int: return self._cents

    @property
    def dollars(self) -> Decimal: return Decimal(self._cents) / 100

    # ---- Binary ops (non-commutative split) ----
    def _check_money(self, other):
        if isinstance(other, Money):
            if other.currency != self.currency:
                raise ValueError(f"Cannot operate across currencies: {self.currency} vs {other.currency}")
            return True
        return NotImplemented

    def __add__(self, other):
        if isinstance(other, Money):
            if other.currency != self.currency:
                raise ValueError(f"Cannot add {self.currency} and {other.currency}")
            return Money(self._cents + other._cents, self.currency)
        return NotImplemented
    __radd__ = __add__

    def __sub__(self, other):
        if isinstance(other, Money):
            if other.currency != self.currency:
                raise ValueError(f"Cannot subtract {other.currency} from {self.currency}")
            return Money(self._cents - other._cents, self.currency)
        return NotImplemented

    def __rsub__(self, other):
        # int (cents) - Money: allow raw cents subtraction? Rare — expose as explicit method instead.
        return NotImplemented

    def __mul__(self, other):
        if isinstance(other, (int, float, Decimal)):
            # Multiply money by scalar → money
            # For float/Decimal, round to cents
            if isinstance(other, float):
                # Avoid floating hysteresis — convert via Decimal for count
                other = Decimal(str(other))
            if isinstance(other, Decimal):
                cents = int((Decimal(self._cents) * other).quantize(Decimal("1")))
            else:
                cents = self._cents * other
            return Money(cents, self.currency)
        return NotImplemented

    def __rmul__(self, other):
        # scalar * Money — symmetric to above, so alias
        return self.__mul__(other)

    def __truediv__(self, other):
        # Money / scalar -> Money
        if isinstance(other, (int, float, Decimal)):
            if other == 0: raise ZeroDivisionError("division by zero")
            if isinstance(other, float): other = Decimal(str(other))
            cents = int((Decimal(self._cents) / Decimal(str(other))).quantize(Decimal("1")))  # round
            return Money(cents, self.currency)
        # Money / Money -> ratio (float or Decimal)
        if isinstance(other, Money):
            if other.currency != self.currency:
                raise ValueError("Cannot divide across currencies")
            return self._cents / other._cents  # ratio, not Money
        return NotImplemented

    # __rtruediv__ would be scalar / Money — atypical (what does 100 / Money mean?) → NotImplemented

    def __floordiv__(self, other):
        if isinstance(other, Money):
            if other.currency != self.currency:
                raise ValueError("Cannot floor-divide across currencies")
            return self._cents // other._cents  # how many whole units
        if isinstance(other, (int, float, Decimal)):
            return Money(int(self._cents // float(other)), self.currency)
        return NotImplemented

    # ---- Unary ----
    def __neg__(self): return Money(-self._cents, self.currency)
    def __pos__(self): return Money(+self._cents, self.currency)  # copy
    def __abs__(self): return Money(abs(self._cents), self.currency)

    # ---- Conversions ----
    def __int__(self): return self._cents
    def __float__(self): return self._cents / 100.0
    def __index__(self): return self._cents  # allows Money to be used as sequence index? unusual, but legal

    # ---- Comparisons & Hashing (from 13.04/13.05) ----
    def __eq__(self, other):
        if isinstance(other, Money): return (self._cents, self.currency) == (other._cents, other.currency)
        return NotImplemented
    def __hash__(self): return hash((self._cents, self.currency))
    def __lt__(self, other):
        if isinstance(other, Money):
            if other.currency != self.currency:
                raise ValueError("Cannot compare across currencies")
            return self._cents < other._cents
        return NotImplemented

    # ---- String ----
    def __repr__(self): return f"Money({self._cents!r}, {self.currency!r})"
    def __str__(self): return f"{self.currency} {self.dollars:.2f}"

m = Money(10000, "USD")   # $100.00
print(m)                  # USD 100.00
print(m + Money(5000, "USD"))   # USD 150.00
print(m * 1.5)            # USD 150.00
print(2 * m)              # USD 200.00  — via __rmul__
print(m / 2)              # Money cents ~5000
print(m / Money(2000, "USD"))  # 5.0  — ratio
print(-m)                 # USD -100.00
print(abs(-m))            # USD 100.00
try: print(m + 10)
except TypeError as e: print(f"Invalid mix raises: {e}")
try: print(m + Money(100, "EUR"))
except ValueError as e: print(f"Currency mismatch: {e}")
```

## Vector / Matrix Example: `__matmul__`, `@` Operator

```python
class Vec:
    def __init__(self, *coords): self.coords = tuple(float(c) for c in coords)
    def __len__(self): return len(self.coords)
    def __iter__(self): return iter(self.coords)
    def __getitem__(self, i): return self.coords[i]
    def __repr__(self): return f"Vec({', '.join(repr(c) for c in self.coords)})"
    def __eq__(self, other):
        if isinstance(other, Vec): return self.coords == other.coords
        return NotImplemented
    def __add__(self, other):
        if isinstance(other, Vec) and len(self)==len(other):
            return Vec(*(a+b for a,b in zip(self, other)))
        return NotImplemented
    __radd__ = __add__

    def __matmul__(self, other):
        """Dot product: v @ w."""
        if isinstance(other, Vec) and len(self)==len(other):
            return sum(a*b for a,b in zip(self, other))
        return NotImplemented
    __rmatmul__ = __matmul__

    def __mul__(self, s):
        if isinstance(s, (int,float)): return Vec(*(c*s for c in self))
        return NotImplemented
    __rmul__ = __mul__
    def __neg__(self): return Vec(*(-c for c in self))

v = Vec(1, 2, 3)
w = Vec(4, 5, 6)
print(v + w)      # Vec(5.0, 7.0, 9.0)
print(v @ w)      # 32.0 — dot product
print(2 * v)      # Vec(2.0, 4.0, 6.0)
print(-v)         # Vec(-1.0, -2.0, -3.0)
```

## `NotImplemented` Propagation — The Only Correct Return for Unsupported Types

Returning `None`, `False`, `0`, or raising `TypeError` eagerly prevents the reflected method from running and breaks heterogeneous operations:

```python
class BadAdd:
    def __add__(self, other):
        if isinstance(other, BadAdd): return BadAdd(1)
        # ❌ Wrong: return None — Python treats None as a valid result, not a signal to try __radd__
        return None

class BadAdd2:
    def __add__(self, other):
        if isinstance(other, BadAdd2): return BadAdd2(1)
        # ❌ Also wrong: return False — again, not NotImplemented
        return False

# Correct:
class GoodAdd:
    def __add__(self, other):
        if isinstance(other, GoodAdd): return GoodAdd(1)
        return NotImplemented  # ✅ signals "I don't know, try other.__radd__"

print(GoodAdd().__add__(5))  # NotImplemented — caller checks `is NotImplemented`
# The real dunder call `GoodAdd() + 5` checks:
#   GoodAdd.__add__(GoodAdd(), 5) -> NotImplemented
#   int.__radd__(5, GoodAdd())   -> NotImplemented
#   => TypeError: unsupported operand types
try: print(GoodAdd() + 5)
except TypeError as e: print(e)

# Common nuance: inside a helper, check with `is NotImplemented`, not `== NotImplemented`
# `NotImplemented == NotImplemented` is True, but don't rely on equality — singleton identity check is canonical.
```

### Comparisons and `NotImplemented` vs Truthiness

```python
# __lt__, __eq__, etc. also must return NotImplemented for unknown types — else ordering breaks (13.05)
# For operators, returning NotImplemented ultimately raises TypeError if both sides opt out.
# For equality, returning NotImplemented on both sides makes Python fall back to identity (not TypeError).
# So the same singleton triggers different outcomes per protocol — important to understand.
```

## Edge Cases: Division, Modulus, Power, Bitwise

```python
class DivDemo:
    def __init__(self, v): self.v = v
    def __truediv__(self, other):
        if isinstance(other, DivDemo): return DivDemo(self.v / other.v)
        return NotImplemented
    def __rtruediv__(self, other):
        if isinstance(other, (int,float)): return DivDemo(other / self.v)
        return NotImplemented
    def __floordiv__(self, other):
        if isinstance(other, DivDemo): return DivDemo(self.v // other.v)
        return NotImplemented
    def __mod__(self, other):
        if isinstance(other, DivDemo): return DivDemo(self.v % other.v)
        return NotImplemented
    def __pow__(self, other):
        if isinstance(other, (int,float, DivDemo)):
            exp = other.v if isinstance(other, DivDemo) else other
            return DivDemo(self.v ** exp)
        return NotImplemented
    def __rpow__(self, other):
        if isinstance(other, (int,float)): return DivDemo(other ** self.v)
        return NotImplemented
    def __repr__(self): return f"DivDemo({self.v})"

d = DivDemo(10)
print(d / DivDemo(2))    # DivDemo(5.0)
print(d % DivDemo(3))    # DivDemo(1)
print(d ** 2)            # DivDemo(100)
print(2 ** DivDemo(3))   # DivDemo(8) — via __rpow__
```

## When NOT to Overload Operators

Overloading is elegant for numeric and vector types, pathological for domain objects where the operation is not obvious:

```python
# ❌ Abuse: Employee + Employee = merged Employee? No intuition.
class Employee:
    def __add__(self, other): return Employee(self.name + other.name)  # what does addition MEAN?
    # Readers will guess wrong — use named methods.

# ✅ Clear: named methods for non-arithmetic merges
class Team:
    def __init__(self, members): self.members = list(members)
    def merged_with(self, other: "Team") -> "Team":
        return Team(self.members + other.members)
    def __repr__(self): return f"Team({self.members!r})"

# Rule: overload when the operator's mathematical meaning is unambiguous to every reader.
# For Money, Vector, Date arithmetic — yes.
# For Customer, Order, Employee — almost always no. Use explicit `transfer`, `merge`, `combine`.
```

## Common Mistakes Table

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Returning `None`/`False` instead of `NotImplemented` | Silent wrong value or `TypeError` not raised; reflected path never tried | `return NotImplemented` for unsupported types |
| Forgetting `__rxxx__` for asymmetric ops | `3 * Vector(...)` raises `TypeError` even though `Vector * 3` works | Define `__rmul__ = __mul__` for symmetric ops; define appropriate `__rsub__/__rtruediv__` for asymmetric |
| `__iadd__` without `return self` | `obj += other` clobbers `obj` to `None` | Always `return self` (or meaningful re-bound value) |
| Mutating immutable type in `__iadd__` | Callers assuming immutability see surprise alias mutation | For immutables, `__iadd__` returns new object: `return self + other` |
| Implementing operators for incomparable currencies/units without guard | Silently mixes USD and EUR | Check `other.currency` and `raise ValueError` when mixing |
| Overloading `__add__` to accept mixed string coercion | `Money(100) + "10"` coerces string to money — hidden bug surface | Only accept known types; `NotImplemented` for others so caller gets `TypeError` |
| `__neg__` mutating instead of copying | `neg = -obj` modifies `obj` | Return new instance: `return type(self)(-self._value)` |

## Performance

*   Operator dispatch is a slot call (fast, C-level). The Python overhead is only your `__add__` body. Keep type checks (`isinstance`) first and short-circuit cheap failures before heavy math.
*   `__iadd__` mutating forms avoid allocation — important when `+=` runs per-element in a million-item loop.
*   Returning `NotImplemented` is cheap — one singleton compare. The reflected try costs one extra method lookup only when the left opts out, so hot homogeneous loops stay single-dispatch.
*   Converting `float` via `Decimal(str(x))` inside tight loops is expensive — cache conversion or require `Decimal`/`int` only for high-throughput money math.

## Checklist

1.  Have you implemented `__add__`/`__mul__` and aliased `__radd__`/`__rmul__` for symmetric ops?
2.  Do you `return NotImplemented` (identity check, not falsy) for unsupported operand types?
3.  Do reflected ops (`__rsub__`, `__rtruediv__`, `__rmatmul__`) reflect semantically (not just call `self.__add__` blindly)?
4.  Does `__iadd__`/`__imul__` `return self` (mutable) or delegate to `__add__` (immutable)?
5.  Is cross-unit comparison (currency, unit system) explicitly guarded rather than silently accepted?
6.  Are you overloading only where arithmetic semantics are universally clear?
7.  Have you tested mixed-type paths: `MyType + int`, `int + MyType`, `MyType + MyType`, `MyType + OtherMoneyType`?

### divmod and pow Integration

```python
class DivModDemo:
    def __init__(self, v: int): self.v = v
    def __divmod__(self, other):
        if isinstance(other, DivModDemo):
            q, r = divmod(self.v, other.v)
            return DivModDemo(q), DivModDemo(r)
        return NotImplemented
    def __pow__(self, other, modulo=None):
        if modulo is not None:
            if isinstance(other, DivModDemo) and isinstance(modulo, DivModDemo):
                return DivModDemo(pow(self.v, other.v, modulo.v))
            return NotImplemented
        if isinstance(other, (int, DivModDemo)):
            exp = other.v if isinstance(other, DivModDemo) else other
            return DivModDemo(self.v ** exp)
        return NotImplemented
    def __repr__(self): return f"DivModDemo({self.v})"

print(divmod(DivModDemo(10), DivModDemo(3)))
print(pow(DivModDemo(2), 10))
```

### Indexable Custom Type via __index__

```python
class RingIndex:
    def __init__(self, value: int, modulus: int):
        self.value = value % modulus
        self.modulus = modulus
    def __index__(self) -> int: return self.value
    def __repr__(self): return f"RingIndex({self.value} mod {self.modulus})"

r = RingIndex(2, 5)
lst = [10,20,30,40,50]
print(lst[r])
```

### Truthiness vs Length Interaction

```python
class AlwaysTruthy:
    def __init__(self, v): self.v = v
    def __bool__(self): return bool(self.v)
    def __len__(self): return self.v

print(bool(AlwaysTruthy(0)))  # False via __bool__
print(bool(AlwaysTruthy(1)))  # True
```
