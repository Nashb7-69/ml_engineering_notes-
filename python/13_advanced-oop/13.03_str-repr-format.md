# 13.03 String Representations: __str__, __repr__, and __format__

## Two Audiences, Two Representations

Every object has two string-conversion methods because it has two audiences:

| Method | Audience | Goal | Trigger |
|--------|----------|------|---------|
| `__repr__` | Developers, logs, debugger | **Unambiguous**, ideally `eval`-roundtrippable | `repr(obj)`, `!r` in f-strings, REPL echo |
| `__str__` | End users, UI, `print()` | **Readable**, pleasant, possibly lossy | `str(obj)`, `print(obj)`, `!s` in f-strings, `f"{obj}"` |
| `__format__` | Formatting system | **Custom presentation** per spec string | `format(obj, spec)`, `f"{obj:spec}"` |

The language enforces this split: if `__str__` is missing, Python falls back to `__repr__`. If `__repr__` is missing, Python falls back to `object.__repr__` (`<ClassName object at 0x...>`). Never the reverse.

```python
class Demo:
    def __repr__(self):
        return "Demo(repr)"
    # no __str__

print(str(Demo()))   # Demo(repr)  — falls back to __repr__
print(repr(Demo()))  # Demo(repr)

class Demo2:
    def __str__(self):
        return "Demo(str)"
    # no __repr__

print(str(Demo2()))  # Demo(str)
print(repr(Demo2())) # <__main__.Demo2 object at 0x...> — object.__repr__, NOT __str__
```

**Rule of thumb:** Always implement `__repr__`. Implement `__str__` when the user-facing form should differ (shorter, prettier, localized).

## `__repr__` — The Developer View

### Contract

> `__repr__` should return a string that, when passed to `eval()`, recreates an equal object — if feasible. When not feasible, return an unambiguous `<...>` description. It must return `str` (not bytes, not None) and should never raise.

From the docs: *"If at all possible, this should look like a valid Python expression that could be used to recreate an object with the same value."*

### Minimal Example and `!r` vs `!s`

```python
class Point:
    def __init__(self, x: float, y: float):
        self.x, self.y = x, y
    def __repr__(self) -> str:
        # !r (repr) inside f-string ensures nested repr quoting
        return f"Point({self.x!r}, {self.y!r})"
    def __str__(self) -> str:
        return f"({self.x}, {self.y})"

p = Point(3, 4)
print(repr(p))      # Point(3, 4)       — for code
print(str(p))       # (3, 4)             — for humans
print(f"{p!r}")     # Point(3, 4) — explicit repr
print(f"{p!s}")     # (3, 4)       — explicit str
print(f"{p}")       # (3, 4)       — f-string without !r defaults to __format__ -> __str__
# But bare REPL echoes repr:
# >>> p
# Point(3, 4)

# eval roundtrip:
q = eval(repr(p))
print(q, type(q).__name__)  # (3.0, 4.0) Point — works because repr is valid expression
# However, eval needs `Point` in scope — repr assumes import context.
```

### The `!r` Inside `__repr__`

A common error is quoting manually:

```python
class User:
    def __init__(self, name: str):
        self.name = name
    # ❌ Broken: manual quoting fails on quotes inside the string
    def __repr__(self) -> str:
        return f"User('{self.name}')"

print(User("Alice"))        # User('Alice') — looks ok
print(User("O'Brien"))      # User('O'Brien') — SyntaxError if eval'd!
# SyntaxError: unterminated string

# ✅ Correct: delegate quoting to !r
class GoodUser:
    def __init__(self, name: str):
        self.name = name
    def __repr__(self) -> str:
        return f"GoodUser({self.name!r})"

print(GoodUser("O'Brien"))   # GoodUser("O'Brien") — !r chose double quotes
print(eval(repr(GoodUser("O'Brien"))).name)  # O'Brien — roundtrips correctly
```

**Rule:** Always use `{value!r}` inside `__repr__`. Never write `'{value}'`.

### When Roundtrip Is Not Feasible

For objects tied to external resources (files, sockets, DB connections) or with complex state, return an informative `<...>` string:

```python
import threading

class Counter:
    def __init__(self, value: int = 0):
        self._value = value
        self._lock = threading.Lock()
    def __repr__(self) -> str:
        # Cannot eval — needs live lock object — so describe
        return f"<Counter value={self._value} at {id(self):#x}>"

# For collections, repr must handle recursion and truncation:
# Python's built-in list repr already handles self-reference:
a = [1, 2]
a.append(a)
print(repr(a))  # [1, 2, [...]] — not infinite recursion

# If you build a custom container, mimic this:
class Node:
    def __init__(self, value, nxt=None):
        self.value = value
        self.next = nxt
    def __repr__(self) -> str:
        # Guard against cycles
        nxt = "..." if self.next is self else repr(self.next)
        return f"Node({self.value!r}, {nxt})"
```

### `__repr__` Should Never Raise

Logging frameworks, debuggers, and crash reporters call `repr(obj)` on arbitrary objects — including partially initialized ones (e.g., if `__init__` raised). If `repr` raises, you lose the diagnostic:

```python
class RiskyRepr:
    def __init__(self, data=None):
        # Simulate failure before self.data exists
        if data is None:
            raise ValueError("data required")
        self.data = data

    def __repr__(self) -> str:
        # ❌ Fragile: assumes self.data exists
        return f"RiskyRepr({self.data!r})"

try:
    r = RiskyRepr(None)
except ValueError:
    import traceback
    # During exception handling, debugger may try repr(r) — but r was never assigned
    pass

# ✅ Defensive:
class SafeRepr:
    def __init__(self, data=None):
        if data is None:
            raise ValueError("data required")
        self.data = data

    def __repr__(self) -> str:
        # getattr with fallback — works even when __init__ failed
        data = getattr(self, "data", "<uninitialized>")
        return f"SafeRepr({data!r})"

# Now even a partially constructed object reprs safely:
obj = object.__new__(SafeRepr)  # bypass __init__
print(repr(obj))  # SafeRepr('<uninitialized>')
```

## `__str__` — The User View

### When to Define `__str__`

`__str__` is for display — logs shown to customers, CLI output, reports. It can be lossy, pretty, or localized:

```python
from datetime import date

class Money:
    def __init__(self, cents: int, currency: str = "USD"):
        self.cents = cents
        self.currency = currency

    def __repr__(self) -> str:
        return f"Money({self.cents!r}, {self.currency!r})"

    def __str__(self) -> str:
        # User-facing: format as localized currency
        symbols = {"USD": "$", "EUR": "€", "GBP": "£", "JPY": "¥"}
        sym = symbols.get(self.currency, self.currency + " ")
        dollars, cents = divmod(abs(self.cents), 100)
        sign = "-" if self.cents < 0 else ""
        return f"{sign}{sym}{dollars:,}.{cents:02d}"

m = Money(123456, "USD")
print(repr(m))  # Money(123456, 'USD') — for developers
print(str(m))   # $1,234.56 — for users
print(m)        # $1,234.56 — print uses __str__
print(f"{m}")   # $1,234.56 — f-string without format spec uses __format__ -> __str__

# In containers, repr is used for elements — str is NOT used:
print([m])       # [Money(123456, 'USD')] — list.__repr__ calls repr on elements
```

### Fallback Behavior — Critical to Understand

```python
class OnlyRepr:
    def __repr__(self): return "repr-only"
    # str(obj) will call __repr__

class OnlyStr:
    def __str__(self): return "str-only"
    # repr(obj) still gives object.__repr__, NOT __str__!

class Both:
    def __repr__(self): return "both-repr"
    def __str__(self): return "both-str"

print("OnlyRepr:")
print(f"  str:  {str(OnlyRepr())}")    # repr-only
print(f"  repr: {repr(OnlyRepr())}")   # repr-only
print("OnlyStr:")
print(f"  str:  {str(OnlyStr())}")     # str-only
print(f"  repr: {repr(OnlyStr())}")    # <__main__.OnlyStr object at 0x...>
print("Both:")
print(f"  str:  {str(Both())}")        # both-str
print(f"  repr: {repr(Both())}")       # both-repr

# And the formatting system:
# f"{obj}" and format(obj) call __format__, which falls back to __str__ if missing,
# which falls back to __repr__.
# So the chain is: __format__ -> __str__ -> __repr__ -> object.__repr__
```

### `__str__` Should Be Concise for Logging — But Not For Core Use

Some style guides suggest `__str__` return a short, human summary and `__repr__` return full reconstruction. For log lines you often see:

```python
import logging
logging.basicConfig(level=logging.INFO, format="%(message)s")

class Order:
    def __init__(self, oid: int, customer: str, total_cents: int):
        self.oid, self.customer, self.total_cents = oid, customer, total_cents
    def __repr__(self):
        return f"Order(oid={self.oid!r}, customer={self.customer!r}, total_cents={self.total_cents!r})"
    def __str__(self):
        return f"Order #{self.oid} for {self.customer} — ${self.total_cents/100:.2f}"

o = Order(417, "Acme Corp", 99900)
logging.info("Created %r", o)  # repr for dev log: Order(oid=417, customer='Acme Corp', total_cents=99900)
print(f"Invoice: {o}")         # str for user: Order #417 for Acme Corp — $999.00
```

## `__format__` — The Formatting Engine

`__format__(self, spec)` powers `format(obj, spec)` and `f"{obj:spec}"`. If missing, Python falls back to `str(obj).__format__(spec)` — which just returns `str(obj)` for empty spec.

### Basic Delegation Pattern

```python
class Vector:
    def __init__(self, x: float, y: float):
        self.x, self.y = x, y
    def __repr__(self): return f"Vector({self.x!r}, {self.y!r})"
    def __str__(self): return f"({self.x}, {self.y})"

    def __format__(self, spec: str) -> str:
        if not spec:
            # f"{v}" with no spec — return str(v)
            return str(self)
        if spec == "polar":
            import math
            r = math.hypot(self.x, self.y)
            theta = math.degrees(math.atan2(self.y, self.x))
            return f"{r:.2f}@{theta:.1f}°"
        if spec == "raw":
            return f"{self.x} {self.y}"
        # Unknown spec — delegate to str formatting or raise
        # Option 1: raise ValueError so caller knows spec is unsupported
        raise ValueError(f"Unknown format spec {spec!r} for Vector")

v = Vector(3, 4)
print(f"{v}")         # (3.0, 4.0) — via __format__("") -> str
print(f"{v:polar}")   # 5.00@53.1°  — custom polar
print(f"{v:raw}")     # 3.0 4.0
print(format(v, "polar"))  # same as f-string
```

### Production-Grade `__format__` — Numeric Style Spec

For numeric types you should mimic built-in numeric formatting (alignment, width, precision):

```python
import math

class Money:
    def __init__(self, cents: int, currency: str = "USD"):
        self.cents = cents
        self.currency = currency
    def __repr__(self): return f"Money({self.cents!r}, {self.currency!r})"
    def __str__(self): return self.__format__("")

    def __format__(self, spec: str) -> str:
        """
        Supported specs:
          "" / "s"  — symbol format: $1,234.56
          "c"       — code format: 1234.56 USD
          ".2f"     — numeric-like: delegates to amount float formatting
          Any other spec raises ValueError.
        """
        amount = self.cents / 100
        if spec in ("", "s"):
            sym = {"USD": "$", "EUR": "€", "GBP": "£"}.get(self.currency, self.currency + " ")
            return f"{sym}{amount:,.2f}"
        if spec == "c":
            return f"{amount:.2f} {self.currency}"
        # Allow Python's float format mini-language on the amount:
        # e.g., f"{m:.0f}" or f"{m:>10,.2f}"
        # Detect float-like specs by trying to format a float
        try:
            # Validate spec is a legal format spec for floats by trial
            format(0.0, spec)
            # If succeeded, apply it to our amount, then append styling?
            # For Money we format amount and keep symbol:
            return f"${format(amount, spec)}"
        except ValueError:
            raise ValueError(f"Unknown format spec {spec!r} for Money")

m = Money(123456, "USD")
print(f"{m}")        # $1,234.56
print(f"{m:c}")      # 1234.56 USD
print(f"{m:.0f}")    # $1235  — float formatting
print(f"{m:,.2f}")   # $1,234.56 — commas via float spec passthrough

# Edge: alignment specs like f"{m:>15}" should also work.
# To support them properly, customize handling:
class AlignedMoney(Money):
    def __format__(self, spec: str) -> str:
        # Split spec into alignment part and type — use Python's FormatSpec parsing
        # Simplified: just format the string result via built-in format
        raw = super().__format__("") if not spec or spec in ("s", "c") else super().__format__(spec)
        # If spec contains alignment (detected by width), re-apply alignment to final string
        # For full correctness, parse spec via string.Formatter().parse — but usually
        # just do: return format(str_value, spec) when str_value already computed
        # Example naive passthrough:
        if spec and any(c in spec for c in "<>^="):
            return format(raw, spec)
        return raw
```

### `__format__` and Date/Time — The Gold Standard Example

Python's own `datetime` objects have the richest `__format__` implementations. Study them:

```python
from datetime import datetime

dt = datetime(2025, 6, 15, 14, 30, 0)
print(f"{dt:%Y-%m-%d}")          # 2025-06-15
print(f"{dt:%B %d, %Y}")         # June 15, 2025
print(f"{dt:%H:%M}")             # 14:30
print(format(dt, "%Y-%m-%d"))    # same

# A custom type can support strftime-like specs too:

class ProjectDate:
    def __init__(self, year: int, month: int, day: int):
        self._date = date(year, month, day)
    def __repr__(self): return f"ProjectDate({self._date!r})"
    def __str__(self): return self._date.isoformat()
    def __format__(self, spec: str) -> str:
        if not spec:
            return str(self)
        # Treat spec as strftime pattern
        return self._date.strftime(spec)

d = ProjectDate(2025, 6, 15)
print(f"{d}")              # 2025-06-15
print(f"{d:%B %d, %Y}")    # June 15, 2025
print(f"{d:%Y/%m/%d}")     # 2025/06/15
```

## Interactions, Edge Cases, and Gotchas

### `repr` vs `str` in Containers and Joins

```python
class Item:
    def __init__(self, name): self.name = name
    def __repr__(self): return f"Item({self.name!r})"
    def __str__(self): return self.name

items = [Item("apple"), Item("banana")]
print(items)                # [Item('apple'), Item('banana')] — repr of each
print(", ".join(str(x) for x in items))  # apple, banana — manual str
print(", ".join(map(str, items)))        # same

# Joining repr vs str matters for logging:
# Always use %r placeholder for containers/values in logs:
import logging
logging.basicConfig(level=logging.DEBUG, format="%(message)s")
logging.debug("Items: %r", items)  # repr — unambiguous, shows Item('...')
logging.debug("Items: %s", items)  # calls str(items) -> "[Item('apple'), Item('banana')]" — same here but not always
```

### F-String Conversions: `!s`, `!r`, `!a`

```python
class Weird:
    def __repr__(self): return "repr"
    def __str__(self): return "str"
    def __format__(self, spec): return f"format:{spec}"

w = Weird()
print(f"{w}")    # format: — via __format__("")
print(f"{w!s}")  # str — via __str__, ignoring __format__
print(f"{w!r}")  # repr — via __repr__, ignoring __format__
print(f"{w!a}")  # ascii(repr) — non-ASCII escaped
print(f"{w:.2f}") # format:.2f — via __format__(".2f")

# So:
#   f"{obj}"     -> obj.__format__("")
#   f"{obj!s}"   -> obj.__str__()
#   f"{obj!r}"   -> obj.__repr__()
# This matters when your __format__ is lossy — logging should use !r explicitly.
```

### `ascii()` and `__repr__`

```python
class Greeting:
    def __init__(self, msg: str): self.msg = msg
    def __repr__(self): return f"Greeting({self.msg!r})"

g = Greeting("héllo 🌍")
print(repr(g))   # Greeting('héllo 🌍')
print(ascii(g))  # Greeting('h\xe9llo \U0001f30d') — escapes non-ascii
print(f"{g!a}")  # same as ascii
```

### Returning Non-`str` From `__repr__` / `__str__`

```python
class BadRepr:
    def __repr__(self):
        return 42  # TypeError: __repr__ returned non-string (type int)

try:
    repr(BadRepr())
except TypeError as e:
    print(e)

# Same for __str__ and __format__: must return str, not bytes or other
```

### Self-Referential `__repr__` and Infinite Recursion

```python
# Already seen: list handles self-reference with [...]
# Your type should handle it too for safety:

class LinkedNode:
    def __init__(self, value, nxt=None):
        self.value = value
        self.next = nxt

    def __repr__(self):
        # Simple safe version: limit recursion depth
        return self._repr(set())

    def _repr(self, seen: set[int]) -> str:
        if id(self) in seen:
            return "Node(...)"
        seen.add(id(self))
        nxt_repr = self.next._repr(seen) if isinstance(self.next, LinkedNode) else repr(self.next)
        return f"Node({self.value!r}, {nxt_repr})"

a = LinkedNode(1)
b = LinkedNode(2, a)
a.next = b  # cycle: a -> b -> a
print(repr(a))  # Node(1, Node(2, Node(...)))

# Alternative: use reprlib for truncated reprs
import reprlib
print(reprlib.repr([1,2,3,4,5,6]*10))  # [1, 2, 3, 4, 5, 6, ...]
```

### Dataclass `__repr__` Generation

```python
from dataclasses import dataclass

@dataclass
class PointDC:
    x: float
    y: float
    label: str = ""

# Dataclass auto-generates: PointDC(x=3, y=4, label='origin')
print(repr(PointDC(3, 4, "origin")))

# Customizing: repr=False on a field hides it (e.g., secrets)
@dataclass
class UserDC:
    name: str
    password: str = dataclass.__dataclass_fields__ and ""  # placeholder — see field() below
    # Actually:
    # from dataclasses import field
    # password: str = field(repr=False)

@dataclass
class Account:
    username: str
    password: str = field(repr=False, compare=False)
    balance: float = 0.0

a = Account("alice", "s3cr3t", 100.0)

print(str(a))   # same as repr unless you define __str__ — dataclass doesn't generate __str__
# Note: if you define __str__, dataclass still auto-generates __repr__
```

## Performance & Design Guidance

*   **`repr` is on the hot path of debugging.** It is called for every object that appears in tracebacks, log lines, and debugger variable views. Keep it fast and allocation-light. Avoid heavy formatting or I/O inside `__repr__`.
*   **`__format__` with parsing is costlier.** If you parse `spec` on every f-string interpolation in a tight loop, pre-compile or cache parsed specs.
*   **Don't do work in `__repr__` that can raise.** A failing `__repr__` during exception handling hides the original exception. Defensive `getattr` / `try/except` inside `__repr__` is justified.
*   **API design checklist:**
    1.  Have you implemented `__repr__`? If not, do so before any other dunder.
    2.  Is `__repr__` import-context aware? (Does it include module path?)
    3.  Does `__str__` add value beyond `__repr__`? If they would be identical, omit `__str__` and rely on the fallback.
    4.  Does `__format__` handle `""` correctly (fallback to `__str__`)?
    5.  Do you use `{value!r}` consistently inside `__repr__`?
    6.  Are secrets excluded from `__repr__` / `__str__` (passwords, tokens)?

### Module-Qualified `__repr__` for Proper `eval` Semantics

For types imported from a module, `repr` should include qualification when eval requires it:

```python
# In mymodule.geometry:
class Point:
    def __repr__(self): return f"Point({self.x!r}, {self.y!r})"       # bare
    def __repr_qualified__(self): return f"mymodule.geometry.Point({self.x!r}, {self.y!r})"

# If repr is used across modules, the qualified form is safer:
# eval(repr(obj)) only works if `Point` is in scope where eval is called.
# For pickle / logging across services, qualified repr is better for grep.

# Dataclasses use qualified names when repr includes module path automatically.
```

## Common Mistakes Table

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Manual quoting in `__repr__`: `f"User('{self.name}')" ` | SyntaxError on names with quotes; eval fails | `f"User({self.name!r})"` |
| Returning `self` or non-`str` from `__repr__` | `TypeError: __repr__ returned non-string` | `return str(...)` |
| Defining `__repr__` that calls `str(self)` which calls `__repr__` | Infinite recursion, `RecursionError` | Keep `__repr__` and `__str__` independent; never `str(self)` inside `__repr__` |
| Heavy I/O in `__repr__` | Debugger hangs / latency | Keep `__repr__` pure and cheap |
| Including secrets in `__repr__` | Leaked credentials in logs | Mask or omit: `password="***"` or `field(repr=False)` |
| No `__repr__` on a domain type | Logs show `<DomainObj at 0x...>` — useless | Implement `__repr__` first |
| `__format__` not handling `""` | `f"{obj}"` breaks or returns wrong thing | `if not spec: return str(self)` |
| Using `f"{obj}"` when you needed `f"{obj!r}"` in logs | Lossy user display hides structural info | Use `!r` in logs, `__format__` for display |

```python
# Recursion trap example:
class Trap:
    def __repr__(self):
        return f"Trap({str(self)!r})"  # str(self) -> __str__ -> maybe calls repr?

    def __str__(self):
        return f"Trap:{repr(self)}"    # repr(self) -> __repr__ -> recursion!

t = Trap()
try:
    repr(t)
except RecursionError:
    print("Recursion between __repr__ and __str__!")

# Fix: each uses raw attributes, not the other:
class Fixed:
    def __init__(self, v): self.v = v
    def __repr__(self): return f"Fixed({self.v!r})"
    def __str__(self): return f"Fixed value={self.v}"  # direct attribute, no repr/str call
```

## Realistic Domain Example: Invoice System

```python
from datetime import date
from decimal import Decimal

class LineItem:
    def __init__(self, sku: str, qty: int, unit_price: Decimal):
        self.sku, self.qty, self.unit_price = sku, qty, unit_price

    @property
    def total(self) -> Decimal:
        return self.qty * self.unit_price

    def __repr__(self) -> str:
        return f"LineItem(sku={self.sku!r}, qty={self.qty!r}, unit_price={self.unit_price!r})"

    def __str__(self) -> str:
        return f"{self.sku} x{self.qty} @ {self.unit_price:.2f} = {self.total:.2f}"

    def __format__(self, spec: str) -> str:
        if spec == "csv":
            return f"{self.sku},{self.qty},{self.unit_price:.2f},{self.total:.2f}"
        if spec == "md":
            return f"| {self.sku} | {self.qty} | {self.unit_price:.2f} | {self.total:.2f} |"
        if not spec:
            return str(self)
        raise ValueError(f"Unknown LineItem format {spec!r}")

class Invoice:
    def __init__(self, number: str, issued: date, items: list[LineItem]):
        self.number, self.issued, self.items = number, issued, list(items)

    def __repr__(self) -> str:
        return f"Invoice(number={self.number!r}, issued={self.issued!r}, items={self.items!r})"

    def __str__(self) -> str:
        lines = "\n  ".join(str(it) for it in self.items)
        total = sum(it.total for it in self.items)
        return f"Invoice {self.number} ({self.issued.isoformat()}):\n  {lines}\n  Total: {total:.2f}"

    def __format__(self, spec: str) -> str:
        if spec == "csv":
            header = "sku,qty,unit_price,total"
            rows = "\n".join(f"{it:csv}" for it in self.items)
            return header + "\n" + rows
        if spec == "summary":
            total = sum(it.total for it in self.items)
            return f"Invoice {self.number}: {len(self.items)} items, total {total:.2f}"
        if not spec:
            return str(self)
        raise ValueError(f"Unknown Invoice format {spec!r}")

items = [LineItem("WIDGET", 3, Decimal("9.99")), LineItem("GADGET", 1, Decimal("24.50"))]
inv = Invoice("INV-2025-001", date(2025, 6, 15), items)
print(repr(inv))         # full reconstruction string
print(str(inv))          # human invoice print
print(f"{inv:summary}")  # Invoice INV-2025-001: 2 items, total 54.47
print(f"{inv:csv}")      # CSV table
print(f"{items[0]:csv}") # WIDGET,3,9.99,29.97
print(f"{items[0]:md}")  # markdown table row

# Roundtrip: eval(repr(inv)) would require date and Decimal in scope + LineItem/Invoice definitions
# Still valuable for logging — grep for Invoice(number=...
```
