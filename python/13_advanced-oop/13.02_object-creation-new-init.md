# 13.02 Object Creation: __new__, __init__, and __call__

## The Two-Phase Construction Nobody Told You About

In most languages there is a single constructor: `new Class(args)` allocates and initializes in one step. Python splits this into **two distinct phases**, plus a third hook on the metaclass that orchestrates them. Mastering these phases is essential for immutable types, singletons, caching, interning, and metaclass-driven factories.

```
MyClass(args)
    │
    ▼
type.__call__(MyClass, *args, **kw)       ← metaclass hook (you rarely see this)
    │
    ├─► MyClass.__new__(MyClass, *args, **kw)   ← PHASE 1: create & return instance
    │
    └─► MyClass.__init__(instance, *args, **kw) ← PHASE 2: initialize (only if __new__ returned correct type)
```

*If you have never overridden `__new__`, you have been using the default `object.__new__` which simply allocates a bare instance with the correct type and a fresh `__dict__` (or slots).*

---

## Phase 1: `__new__(cls, ...)` — The Real Constructor

### Signature and Semantics

```python
class MyClass:
    def __new__(cls, *args, **kwargs):
        # cls is the class being instantiated, e.g., MyClass
        # Must create and return an instance (usually via super().__new__(cls))
        instance = super().__new__(cls)
        # ... custom allocation logic ...
        return instance
```

Key facts that surprise even experienced developers:

| Fact | Detail |
|------|--------|
| `__new__` is implicitly `static` | Python automatically treats it as `staticmethod`; writing `@staticmethod` is redundant but sometimes added for clarity. First argument is the class, not an instance. |
| It is the *only* method that creates the object | If you do not call `object.__new__(cls)` (or equivalent), no object exists. |
| Its return value determines what `MyClass(...)` returns — and whether `__init__` runs | If `__new__` returns an instance of `cls` (or subclass), `__init__` is invoked. If it returns something of a different type (e.g., an `int`, a cached instance of another type), `__init__` is **skipped**. |
| It receives the same `*args, **kw` as `MyClass(...)` | Usually you ignore extra args and just use `cls`. But for immutable types you *must* use them to set state before the object becomes immutable. |
| It can return *any* object | Not necessarily an instance of `cls`. This power enables factory-like classes, but also creates bugs if misused. |

### Minimal Correct Override

```python
class Logged:
    """Demonstrates correct __new__ + __init__ boilerplate."""
    def __new__(cls, *args, **kwargs):
        print(f"__new__ called with cls={cls.__name__}, args={args}, kwargs={kwargs}")
        # Correct delegation: let object allocate
        instance = super().__new__(cls)
        print(f"  → allocated instance id={id(instance):#x}")
        return instance

    def __init__(self, value: int):
        print(f"__init__ called with self id={id(self):#x}, value={value}")
        self.value = value

l = Logged(42)
# Output:
# __new__ called with cls=Logged, args=(42,), kwargs={}
#   → allocated instance id=0x...
# __init__ called with self id=0x... (same id), value=42
```

Notice `__new__` receives `(42,)` even though it typically ignores it. `__init__` receives `self` already allocated.

### The `NotImplemented` vs `None` Trap

A common beginner error:

```python
class Broken:
    def __new__(cls, value):
        instance = super().__new__(cls)
        instance.value = value
        # BUG: forgot to return instance!
        # Implicit return None

b = Broken(10)
print(b)         # None
print(type(b))   # <class 'NoneType'>
# __init__ was NOT called (because None is not an instance of Broken)
# No error at creation time — silent, confusing bug.

class AlsoBroken:
    def __new__(cls, value):
        super().__new__(cls)  # allocated but discarded
        return "hello"        # returned wrong type

x = AlsoBroken(10)
print(x)         # "hello"
# __init__ skipped, no error — but x is a str, not AlsoBroken!
```

**Rule:** `__new__` *must* explicitly `return instance`. Lint with `mypy` or add `-> Self` annotation to catch missing returns.

## Phase 2: `__init__(self, ...)` — The Initializer

```python
class MyClass:
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

| Fact | Detail |
|------|--------|
| `__init__` is an *instance* method | First argument is `self`, the already-allocated object. |
| It must return `None` | Returning anything else raises `TypeError: __init__() should return None`. |
| It cannot create the object | By the time it runs, `self` already has a type, `__dict__`, and identity. |
| It is not a constructor | Calling `__init__` twice re-initializes the same object (sometimes useful, usually a bug). |
| It is skipped if `__new__` returned the wrong type | See below. |

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        return "oops"  # TypeError: __init__() should return None

class Cheat:
    def __new__(cls, value):
        # Return an int instead of Cheat — __init__ will NOT run
        return 42

    def __init__(self, value):
        print("__init__ running — you will never see this")
        self.value = value

c = Cheat(10)
print(c, type(c))  # 42 <class 'int'>
```

### Why Split?

For mutable types, the split seems redundant. For **immutable** types, it is essential:

```python
# Attempting to initialize an immutable type via __init__ — TOO LATE
class BadImmutable(tuple):
    def __init__(self, values):
        # self is already a tuple — tuples are immutable, cannot assign items!
        # This does nothing useful for the tuple value itself.
        self.extra = "metadata"  # You can add attributes (if no __slots__), but tuple contents are fixed
        # The tuple is still empty! We never set its elements.

b = BadImmutable([1, 2, 3])
print(b)        # () — empty tuple, not [1,2,3]
print(b.extra)  # metadata

# Correct: set immutable value in __new__
class GoodImmutable(tuple):
    def __new__(cls, values):
        # tuple.__new__ takes the iterable as its value
        instance = super().__new__(cls, values)
        return instance

    def __init__(self, values):
        # Optional: add mutable metadata after allocation
        self.created_at = __import__("time").time()

g = GoodImmutable([1, 2, 3])
print(g)              # (1, 2, 3)
print(g.created_at)   # timestamp
```

**Mental model:** `__new__` controls the *value* (bytes of the object), `__init__` controls the *attributes*. For immutables, value must be set at birth.

## The Orchestrator: `type.__call__` (Metaclass Level)

When you write `MyClass(1, 2)`, you are really calling the *metaclass's* `__call__`:

```python
# What Python actually does when you write MyClass(1, 2):
#   type.__call__(MyClass, 1, 2)   where type is the metaclass (usually `type` itself)

# Simplified CPython pseudocode for type.__call__:
def type_call(cls, *args, **kwargs):
    obj = cls.__new__(cls, *args, **kwargs)   # phase 1
    if isinstance(obj, cls):                   # only init if correct type
        cls.__init__(obj, *args, **kwargs)     # phase 2
    return obj
```

This explains the "only if correct type" rule. You can override this orchestrator by defining `__call__` on a custom metaclass — useful for sophisticated factories, dependency injection, or argument preprocessing:

```python
class CallLogger(type):
    """Metaclass that logs every instantiation."""
    def __call__(cls, *args, **kwargs):
        print(f"[metaclass] Creating {cls.__name__} with {args}, {kwargs}")
        # Replicate type.__call__ logic so we don't break __init__ gating:
        obj = cls.__new__(cls, *args, **kwargs)
        if isinstance(obj, cls):
            cls.__init__(obj, *args, **kwargs)
        print(f"[metaclass] Created {obj!r}")
        return obj

class Service(metaclass=CallLogger):
    def __new__(cls, name):
        print(f"  Service.__new__({name})")
        return super().__new__(cls)
    def __init__(self, name):
        print(f"  Service.__init__({name})")
        self.name = name
    def __repr__(self):
        return f"Service({self.name!r})"

s = Service("auth")
# [metaclass] Creating Service with ('auth',) {}
#   Service.__new__(auth)
#   Service.__init__(auth)
# [metaclass] Created Service('auth')
```

> Most code never touches metaclass `__call__`. If you find yourself reaching for it, consider whether a class decorator or `__init_subclass__` would be simpler (lesson 13.13).

## When to Override `__new__` — Five Legitimate Use Cases

### 1. Immutable Types (tuple, str, frozenset, bytes, int subclasses)

```python
class Currency(int):
    """An int subclass that tracks its currency unit."""
    def __new__(cls, amount: int, unit: str = "USD"):
        # int.__new__ takes the numeric value; must pass it here
        instance = super().__new__(cls, amount)
        # Store extra attribute — ints normally have no __dict__, but subclass can
        instance.unit = unit
        return instance

    def __repr__(self) -> str:
        return f"Currency({int(self)}, {self.unit!r})"

    def __str__(self) -> str:
        return f"{int(self)} {self.unit}"

    def __add__(self, other):
        if isinstance(other, Currency) and other.unit != self.unit:
            raise ValueError(f"Cannot add {self.unit} and {other.unit}")
        # Preserve unit: create new Currency, not plain int
        result = super().__add__(other)
        if isinstance(result, int):  # super().__add__ may return int for plain ints
            return Currency(result, self.unit)
        return result

usd = Currency(100, "USD")
eur = Currency(50, "EUR")
print(usd)          # 100 USD
print(usd + 10)     # 110 USD — still a Currency
try:
    print(usd + eur)
except ValueError as e:
    print(e)        # Cannot add USD and EUR

# Edge: int subclasses are tricky because arithmetic may return plain int
# Always test that operations preserve your subclass when intended.
```

A `str` subclass is similar:

```python
class TitleStr(str):
    """A string that is always title-cased."""
    def __new__(cls, content: str):
        # str.__new__ does the actual string creation
        instance = super().__new__(cls, content.title())
        return instance

    def shout(self) -> str:
        return self.upper() + "!"

t = TitleStr("hello world")
print(t)           # Hello World
print(t.shout())   # HELLO WORLD!
print(type(t))     # <class '__main__.TitleStr'>
```

### 2. Singleton Pattern — Correct Implementation

The naive singleton is deceptively easy to get wrong:

```python
# ❌ Broken singleton — __init__ runs every time, resetting state
class BrokenSingleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, value=None):
        # This runs on EVERY call, even when returning cached instance!
        print(f"__init__ value={value}")
        self.value = value

a = BrokenSingleton("first")
print(a.value)   # first
b = BrokenSingleton("second")
print(a.value)   # second — a was mutated!
print(a is b)    # True — same object, but re-initialized

# ✅ Correct singleton — guard __init__
class Singleton:
    _instance = None
    _initialized = False

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, value=None):
        # Guard: only initialize once
        if self.__class__._initialized:
            return
        self.value = value
        self.__class__._initialized = True

a = Singleton("first")
b = Singleton("second")
print(a.value, b.value, a is b)  # first first True — second call ignored init

# ✅ Better singleton — do all setup in __new__
class BetterSingleton:
    _instance = None

    def __new__(cls, value=None):
        if cls._instance is None:
            instance = super().__new__(cls)
            instance.value = value    # initialize here, __init__ not needed
            cls._instance = instance
        return cls._instance

    def __init__(self, *args, **kwargs):
        pass  # intentionally empty — all work in __new__

# ✅ Thread-safe singleton (for completeness)
import threading

class ThreadSafeSingleton:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:  # double-checked locking
                    instance = super().__new__(cls)
                    # initialize here...
                    cls._instance = instance
        return cls._instance
```

> **Design advice:** Singleton is often an anti-pattern. Prefer dependency injection or a module-level single instance (`_default = MyClass(); def get_default(): return _default`). Use singleton only when the type *semantically* must have one instance (e.g., `NoneType`, sentinel values).

### 3. Caching / Interning / Flyweight

```python
class Color:
    """Flyweight: identical RGB values share the same object — saves memory for millions of colors."""
    _cache: dict[tuple[int,int,int], "Color"] = {}

    def __new__(cls, r: int, g: int, b: int):
        key = (r, g, b)
        if key in cls._cache:
            return cls._cache[key]
        instance = super().__new__(cls)
        # Store directly to avoid triggering __init__ re-entry issues
        cls._cache[key] = instance
        return instance

    def __init__(self, r: int, g: int, b: int):
        # Guard: if already initialized (from cache), skip
        if hasattr(self, "_initialized"):
            return
        self.r, self.g, self.b = r, g, b
        self._initialized = True
        # Note: __hash__ and __eq__ would normally be added here for proper value semantics

    def __repr__(self):
        return f"Color({self.r}, {self.g}, {self.b})"

a = Color(255, 0, 0)
b = Color(255, 0, 0)
print(a is b)  # True — same object reused
print(len(Color._cache))  # 1

# For production caching, consider functools.lru_cache or weak references:
import weakref

class WeakCached:
    """Cache that does not prevent garbage collection."""
    _cache: weakref.WeakValueDictionary = weakref.WeakValueDictionary()

    def __new__(cls, key: str):
        if key in cls._cache:
            return cls._cache[key]
        instance = super().__new__(cls)
        cls._cache[key] = instance
        return instance

    def __init__(self, key: str):
        if hasattr(self, "key"):
            return
        self.key = key
```

### 4. Validated Construction / Alternative Constructors That Return Different Types

```python
class Shape:
    """Factory class: Shape(...) returns Circle or Rectangle based on arguments."""
    def __new__(cls, *args, **kwargs):
        # If called as Shape(kind="circle", r=5), delegate to subclass
        if cls is Shape:
            kind = kwargs.get("kind") or (args[0] if args else None)
            if kind == "circle":
                return object.__new__(Circle)
            elif kind == "rectangle":
                return object.__new__(Rectangle)
        # Normal path for subclasses: allocate correct type
        return super().__new__(cls)

    def __init__(self, kind=None, **kwargs):
        # Shape-level init — subclasses handle their own
        pass

class Circle(Shape):
    def __init__(self, kind=None, r: float = 0):
        self.r = r
    def area(self):
        import math
        return math.pi * self.r ** 2
    def __repr__(self):
        return f"Circle(r={self.r})"

class Rectangle(Shape):
    def __init__(self, kind=None, w: float = 0, h: float = 0):
        self.w, self.h = w, h
    def area(self):
        return self.w * self.h
    def __repr__(self):
        return f"Rectangle(w={self.w}, h={self.h})"

c = Shape(kind="circle", r=5)
r = Shape(kind="rectangle", w=3, h=4)
print(c, type(c).__name__, c.area())  # Circle(r=5) Circle 78.5...
print(r, type(r).__name__, r.area())  # Rectangle(w=3, h=4) Rectangle 12

# Note: this factory pattern is often better expressed as:
#   Shape.create(kind="circle", ...) classmethod
#   or a standalone function make_shape(...)
# Use __new__ factory only when you need `isinstance(obj, Shape)` to work and class syntax matters.
```

### 5. `__slots__` Interaction and `__new__` with Slots

```python
class SlottedPoint:
    __slots__ = ("x", "y")  # no __dict__, fixed attributes

    def __new__(cls, x: float, y: float):
        # object.__new__ handles slots allocation correctly
        instance = super().__new__(cls)
        # Must use object.__setattr__ or direct slot assignment;
        # normal `instance.x = ...` works because slots create descriptors
        instance.x = x
        instance.y = y
        return instance

    def __init__(self, x: float, y: float):
        # If __new__ already set x/y, __init__ could be empty
        # or re-assign — but be careful with inheritance
        pass

    def __repr__(self):
        return f"SlottedPoint({self.x}, {self.y})"

p = SlottedPoint(3, 4)
print(p)  # SlottedPoint(3, 4)

# Subclassing a slotted class: must redeclare slots or get __dict__
class SlottedPoint3D(SlottedPoint):
    __slots__ = ("z",)  # new slot in addition to parent's x, y

    def __new__(cls, x, y, z):
        instance = super().__new__(cls)
        instance.x = x
        instance.y = y
        instance.z = z
        return instance

    def __repr__(self):
        return f"SlottedPoint3D({self.x}, {self.y}, {self.z})"

p3 = SlottedPoint3D(1, 2, 3)
print(p3)  # SlottedPoint3D(1, 2, 3)

# Pitfall: __slots__ without __dict__ means instance has no __dict__
# Setting an undeclared attribute raises AttributeError:
try:
    p.extra = 99
except AttributeError as e:
    print(f"Slots error: {e}")
```

## `__new__` vs `__init__` vs `__call__` — Side-by-Side

| Aspect | `__new__` | `__init__` | `__call__` (instance) | `__call__` (metaclass) |
|--------|-----------|------------|----------------------|----------------------|
| **Role** | Allocate / construct | Initialize | Make instance callable | Orchestrate `__new__` + `__init__` |
| **First argument** | `cls` (class) | `self` (instance) | `self` (instance) | `cls` (class) |
| **Implicit decorator** | `staticmethod` | `function` (becomes method) | `function` | `function` on metaclass |
| **When called** | `Cls(...)` phase 1 | `Cls(...)` phase 2 | `instance(...)` | `Cls(...)` orchestration |
| **Must return** | instance (usually) | `None` (enforced) | anything | instance |
| **Common override reason** | Immutable, singleton, cache | Normal setup | Stateful functor, decorator | Argument preprocessing, registry |
| **Can be skipped?** | Never skipped when `Cls(...)` called | Skipped if `__new__` returns wrong type | N/A | If you bypass `Cls(...)` and call `__new__` directly |

```python
# Demonstrating all three together:

class Meta(type):
    def __call__(cls, *args, **kwargs):
        print(f"[Meta.__call__] {cls.__name__}({args}, {kwargs})")
        obj = super().__call__(*args, **kwargs)  # delegates to type.__call__
        print(f"[Meta.__call__] → {obj!r}")
        return obj

class Demo(metaclass=Meta):
    def __new__(cls, value):
        print(f"[Demo.__new__] allocating {cls.__name__}")
        return super().__new__(cls)

    def __init__(self, value):
        print(f"[Demo.__init__] initializing with {value}")
        self.value = value

    def __call__(self, extra):
        print(f"[Demo.__call__] {self.value} + {extra} = {self.value + extra}")
        return self.value + extra

    def __repr__(self):
        return f"Demo({self.value!r})"

d = Demo(10)
# [Meta.__call__] Demo((10,), {})
# [Demo.__new__] allocating Demo
# [Demo.__init__] initializing with 10
# [Meta.__call__] → Demo(10)

result = d(5)
# [Demo.__call__] 10 + 5 = 15
print(result)  # 15
```

## Advanced Edge Cases

### `__new__` Returning an Existing Instance Skips `__init__` Only for Type Mismatch

A nuance many miss: `isinstance` check uses the class being called, not arbitrary equality:

```python
class Parent:
    def __init__(self):
        print("Parent.__init__")

class Child(Parent):
    def __new__(cls):
        # Return a Parent instance, not a Child
        print("Child.__new__ returning Parent instance")
        return Parent.__new__(Parent)

    def __init__(self):
        print("Child.__init__ — will NOT run")

c = Child()
print(type(c))  # <class '__main__.Parent'> — not a Child!
# Child.__init__ skipped because Parent instance is not an instance of Child

class Sibling(Parent):
    def __new__(cls):
        print("Sibling.__new__ returning Sibling via super")
        return super().__new__(cls)
    def __init__(self):
        print("Sibling.__init__ — WILL run")
        super().__init__()

s = Sibling()  # both __new__ and __init__ run
```

### Calling `__new__` Directly Without `__call__`

```python
class Manual:
    def __new__(cls, v):
        print(f"new {v}")
        return super().__new__(cls)
    def __init__(self, v):
        print(f"init {v}")
        self.v = v

# Normal construction:
m1 = Manual(1)
# new 1
# init 1

# Manual construction — you must call both phases yourself:
m2 = Manual.__new__(Manual, 2)  # no init!
print(f"has v? {hasattr(m2, 'v')}")  # False
Manual.__init__(m2, 2)               # now init
print(m2.v)  # 2

# Useful for deserialization / __reduce__ / copy:
import copy
m3 = copy.copy(m1)  # copy internally calls __new__ without __init__
```

### Inheritance and Cooperative `__new__`

```python
class A:
    def __new__(cls, *args, **kwargs):
        print(f"A.__new__ {cls.__name__}")
        return super().__new__(cls)
    def __init__(self, *args, **kwargs):
        print(f"A.__init__")
        super().__init__()

class B(A):
    def __new__(cls, *args, **kwargs):
        print(f"B.__new__ {cls.__name__}")
        return super().__new__(cls)
    def __init__(self, *args, **kwargs):
        print(f"B.__init__")
        super().__init__()

class C(B):
    def __new__(cls, *args, **kwargs):
        print(f"C.__new__ {cls.__name__}")
        return super().__new__(cls)
    def __init__(self):
        print(f"C.__init__")
        super().__init__()

# Chain: C.__new__ -> B.__new__ -> A.__new__ -> object.__new__ -> allocation
#        then C.__init__ -> B.__init__ -> A.__init__
# But note: naive super().__init__ chain requires compatible signatures!
# If A.__init__ takes (x, y) and B.__init__ takes (x), passing *args blindly may break.
# Always design __new__/__init__ signatures cooperatively or use **kwargs.

b = B()
print("---")
c = C()
```

### `__new__` with `__slots__` and `__weakref__`

```python
class NoWeakRef:
    __slots__ = ("x",)
    def __new__(cls, x):
        inst = super().__new__(cls)
        inst.x = x
        return inst

import weakref
nw = NoWeakRef(1)
try:
    weakref.ref(nw)
except TypeError as e:
    print(f"No weakref: {e}")  # cannot create weak reference — need __weakref__ slot

class WithWeakRef:
    __slots__ = ("x", "__weakref__")  # explicitly enable weak refs
    def __new__(cls, x):
        inst = super().__new__(cls)
        inst.x = x
        return inst

ww = WithWeakRef(1)
r = weakref.ref(ww)
print(f"Weak ref works: {r() is ww}")  # True
```

## Common Mistakes and Anti-Patterns

| Mistake | Why It's Wrong | Correct Approach |
|---------|---------------|------------------|
| Forgetting `return instance` in `__new__` | Returns `None`, `__init__` skipped, silent bug | Always `return super().__new__(cls)` at end |
| Returning wrong type from `__new__` unintentionally | `__init__` skipped, type confusion | Ensure `return` is instance of `cls` or document factory behavior |
| Re-initializing singleton in `__init__` | Resets state on every `Singleton(...)` call | Guard `__init__` with flag or move init to `__new__` |
| Using `__init__` for immutable types like `tuple` subclasses | Cannot set tuple value after allocation | Override `__new__` |
| Adding `@staticmethod` to `__new__` incorrectly | Redundant (implicit), but harmless; adding `@classmethod` breaks it | Just `def __new__(cls, ...):` — no decorator |
| Calling `object.__new__(cls, args)` with args | `object.__new__` takes only `cls` — extra args raise `TypeError` | `object.__new__(cls)` or `super().__new__(cls)`; pass args only to subclass `__new__` that needs them |
| Overriding metaclass `__call__` without calling `super().__call__` and without `isinstance` check | May call `__init__` on wrong type or skip it when needed | Either call `super().__call__` or replicate the `isinstance` gating logic |

```python
# Example of the object.__new__ args trap:
class Sneaky:
    def __new__(cls, value):
        # ❌ TypeError: object.__new__() takes exactly one argument (the type to instantiate)
        try:
            instance = object.__new__(cls, value)  # wrong!
        except TypeError as e:
            print(f"Trapped: {e}")
        # ✅ Correct
        instance = object.__new__(cls)
        instance.value = value
        return instance

s = Sneaky(42)
print(s.value)  # 42
```

## Performance Notes

*   Overriding `__new__` adds one Python function call to every instantiation. For millions of objects, this is measurable (~100–200 ns overhead per call). If object creation is a hot path and the logic is simple, consider a factory function instead.
*   `__slots__` + `__new__` saves memory but `object.__new__` with slots still performs slot allocation (zeroing). Slightly faster than `__dict__` because no hash table is created.
*   Caching in `__new__` (flyweight) trades memory for identity sharing. Profile before optimizing — sharing may add dict lookup cost that outweighs allocation savings for small numbers of objects.

---

## Checklist: Do You Need `__new__`?

Ask in order:

1.  **Are you subclassing an immutable built-in (`str`, `bytes`, `int`, `float`, `tuple`, `frozenset`)?** → Yes, override `__new__`.
2.  **Need singleton / interning / caching by value?** → Yes, override `__new__` (with `__init__` guard).
3.  **Factory that returns different subtype based on arguments?** → Consider `__new__` *or* a `@classmethod` factory — the latter is usually clearer.
4.  **Everything else?** → No, use `__init__` (or `__post_init__` for dataclasses). Overriding `__new__` for mutable, non-caching types is almost always over-engineering.

> When in doubt, start with `__init__`. Move logic to `__new__` only when you hit a concrete case where `__init__` is insufficient — the split is a tool, not a default.
