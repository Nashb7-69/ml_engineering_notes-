# 13.10 Descriptors: __get__, __set__, __delete__, and __set_name__

## The Hidden Engine Behind `property`, Methods, and `slot` Access

Every attribute access `obj.attr` in Python is, at its core, descriptor-aware. Descriptors are objects that define `__get__`, `__set__`, or `__delete__` and are placed in a *class dictionary* (not instance dictionary). When Python resolves `obj.attr`, it checks whether the class attribute is a descriptor and, if so, *delegates* to it instead of returning the descriptor object itself.

This one mechanism powers:

*   `property` — data descriptor that intercepts reads and writes
*   functions as methods — non-data descriptors that bind `self`/`cls`
*   `classmethod`, `staticmethod` — wrappers that alter binding
*   `__slots__` — data descriptors for fixed attributes
*   Custom validated / typed / lazy attributes

> **Mental model:** A descriptor is an **attribute access interceptor** that lives on the class. You describe *how* to get or set the attribute, and Python automatically routes every `getattr/setattr` through it.

---

## Anatomy: The Three Hooks + `__set_name__`

```python
class Descriptor:
    def __set_name__(self, owner, name):
        """Called once when the descriptor is assigned to a class attribute."""
        self.name = name          # e.g., "x"
        self.private = f"_{name}" # where to store actual value on the instance

    def __get__(self, instance, owner=None):
        """Called on `owner.attr` (instance is not None) or `Class.attr` (instance is None)."""
        if instance is None:
            return self             # accessed via Class.attr — return descriptor itself (allows introspection)
        return getattr(instance, self.private, None)

    def __set__(self, instance, value):
        """Called on `instance.attr = value`."""
        setattr(instance, self.private, value)

    def __delete__(self, instance):
        """Called on `del instance.attr`."""
        delattr(instance, self.private)
```

Which hooks you define determines the *category*:

| Defined hooks | Category | Behavior |
|---------------|----------|----------|
| `__get__` only | **Non-data descriptor** | Intercepts only *reads*; instance `__dict__` value shadows the descriptor on read (but write goes to `__dict__`) |
| `__get__` + `__set__` (or `__delete__`) | **Data descriptor** | Intercepts reads *and* writes; takes priority over instance `__dict__` |
| None (plain attribute) | No interception | `obj.attr` is just the class attribute object; assignment writes to `instance.__dict__` |

This distinction is the single most important subtlety for descriptors.

### Data vs Non-Data — Why It Matters

```python
# Non-data descriptor: function — read through descriptor, write shadowing
class Foo:
    def bar(self): return "method"
    # bar is a function object with __get__ — non-data descriptor (no __set__)
# So: obj.bar reads via function.__get__(obj, Foo) -> bound method
# But: obj.bar = 99 writes to obj.__dict__["bar"] = 99, shadowing the method on next read!

obj = Foo()
print(obj.bar())                # method — via descriptor binding
obj.bar = 99                    # writes to instance __dict__, not through descriptor (no __set__)
print(obj.bar)                  # 99 — shadows the method!
del obj.bar                     # removes shadow
print(obj.bar())                # method again — descriptor active once shadow removed
print(Foo.__dict__["bar"])      # <function Foo.bar at ...> — still the non-data descriptor on class

# Data descriptor: property — always intercepts
class Baz:
    def __init__(self): self._x = 0
    @property
    def x(self): return self._x
    @x.setter
    def x(self, v): self._x = int(v)

b = Baz()
print(b.x)                      # 0 — via property.__get__
b.__dict__["x"] = 999           # manually insert instance dict entry
print(b.x)                      # still 0 — data descriptor wins over __dict__!
print(b.__dict__)               # {'_x': 0, 'x': 999} — stale entry ignored by descriptor
# Only deleting the instance shadowing entry exposes ... still ignored due to data descriptor.
# Property reads ALWAYS go through descriptor, never fall through to __dict__["x"].

# So: data descriptors are "authoritative" (like slots), non-data descriptors are "fallback".
# This is why `obj.attr = value` can shadow a method but cannot shadow a property — because
# attribute write checks for data descriptors first.

# Attribute lookup order (simplified):
# obj.attr  (get):
#   1. data descriptor on class chain (via __get__)
#   2. instance __dict__[attr]
#   3. non-data descriptor on class / plain class attribute
#   4. __getattr__ fallback
# obj.attr = val (set):
#   1. data descriptor __set__ on class chain
#   2. instance __dict__[attr] = val
```

## Functions Are (Non-Data) Descriptors — Method Binding Demystified

The reason `obj.method` binds `obj` as `self` is *exactly* the descriptor protocol:

```python
class MyClass:
    def method(self, x): return self, x

obj = MyClass()
# What happens on `obj.method`:
#   MyClass.__dict__["method"].__get__(obj, MyClass)  →  bound method (self already pinned)
print(MyClass.__dict__["method"])      # <function MyClass.method at ...> — descriptor object
print(type(MyClass.__dict__["method"]))# <class 'function'> — has __get__
print(MyClass.__dict__["method"].__get__(None, MyClass))  # accessed via class -> returns function itself
print(MyClass.__dict__["method"].__get__(obj, MyClass))   # -> <bound method MyClass.method of <MyClass>>
print(obj.method(5))                  # (<MyClass>, 5)

# Manual equivalence:
func = MyClass.__dict__["method"]
bound = func.__get__(obj, MyClass)    # descriptor protocol directly
print(bound(5))                       # same

# This also explains classmethod / staticmethod wrappers:
class Demo:
    @classmethod
    def cm(cls, x): return cls, x
    @staticmethod
    def sm(x): return x

# classmethod is a descriptor whose __get__ returns a bound method with cls pinned
# staticmethod is a descriptor whose __get__ returns the raw function with no binding

import inspect
print(inspect.isfunction(Demo.__dict__["cm"]))  # False — it's a classmethod object, not a function
print(type(Demo.__dict__["cm"]))                # <class 'classmethod'>
print(Demo.cm)                                  # <bound method Demo.cm of <class 'Demo'>>
print(Demo().cm)                                # <bound method Demo.cm of <class 'Demo'>>
print(Demo.sm)                                  # <function Demo.sm at ...>
print(Demo().sm)                                # same function object — no binding

# So `classmethod` and `staticmethod` are library descriptors built on the same protocol you use.
```

## `property` Is Just a Ready-Made Data Descriptor

Before using `property`, understand that it *is* a descriptor — not syntax fairy dust:

```python
# Equivalent: manual descriptor vs property

class Temperature_manual:
    """Descriptor-based property for Celsius <-> Fahrenheit."""
    class _Celsius:
        def __get__(self, obj, objtype=None):
            if obj is None: return self
            return obj._c
        def __set__(self, obj, value):
            if value < -273.15: raise ValueError("below absolute zero")
            obj._c = float(value)
        def __set_name__(self, owner, name):
            self.name = name

    celsius = _Celsius()

    @property
    def fahrenheit(self):
        return self._c * 9/5 + 32

    @fahrenheit.setter
    def fahrenheit(self, v):
        self.celsius = (v - 32) * 5/9

t = Temperature_manual()
t.celsius = 25
print(t.fahrenheit)  # 77.0

# Same with property — shorter, idiomatic:
class Temperature:
    def __init__(self, c=0): self._c = float(c)
    @property
    def celsius(self): return self._c
    @celsius.setter
    def celsius(self, v):
        if v < -273.15: raise ValueError("below absolute zero")
        self._c = float(v)
    @property
    def fahrenheit(self): return self._c * 9/5 + 32
    @fahrenheit.setter
    def fahrenheit(self, v): self.celsius = (v - 32) * 5/9

t2 = Temperature(25)
print(t2.fahrenheit)

# Implementation sketch of property:
class MyProperty:
    def __init__(self, fget=None, fset=None, fdel=None, doc=None):
        self.fget, self.fset, self.fdel = fget, fset, fdel
        self.__doc__ = doc or (fget.__doc__ if fget else None)
    def __get__(self, obj, objtype=None):
        if obj is None: return self
        if self.fget is None: raise AttributeError("unreadable attribute")
        return self.fget(obj)
    def __set__(self, obj, value):
        if self.fset is None: raise AttributeError("can't set attribute")
        self.fset(obj, value)
    def __delete__(self, obj):
        if self.fdel is None: raise AttributeError("can't delete attribute")
        self.fdel(obj)
    # decorators to chain:
    def getter(self, f): return type(self)(f, self.fset, self.fdel, self.__doc__)
    def setter(self, f): return type(self)(self.fget, f, self.fdel, self.__doc__)
    def deleter(self, f): return type(self)(self.fget, self.fset, f, self.__doc__)

# `@property` populates fget, `.setter` builds a new descriptor with fset, etc.
# So property objects are immutable descriptor factories — each decorator returns a new one.
```

## Writing Custom Descriptors — Validated, Typed, Cached

### Example 1: `Typed` — Type-Enforcing Attribute

```python
class Typed:
    """Descriptor that enforces a type (and optionally None-ability)."""
    def __init__(self, typ, *, allow_none=False):
        self.typ, self.allow_none = typ, allow_none
        self.name = self.private = None  # set via __set_name__

    def __set_name__(self, owner, name):
        self.name = name
        self.private = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None: return self
        # Use getattr to include default handling; careful to avoid recursion
        return getattr(obj, self.private, None)

    def __set__(self, obj, value):
        if value is None and self.allow_none:
            setattr(obj, self.private, None)
            return
        if not isinstance(value, self.typ):
            raise TypeError(f"{self.name} must be {self.typ.__name__}, got {type(value).__name__}")
        setattr(obj, self.private, value)

    def __delete__(self, obj):
        raise AttributeError(f"Cannot delete {self.name}")

class Order:
    symbol = Typed(str)
    quantity = Typed(int)
    price = Typed(float)

o = Order()
o.symbol, o.quantity, o.price = "AAPL", 100, 150.5
print(o.symbol, o.quantity, o.price)
try:
    o.quantity = "lots"
except TypeError as e: print(e)  # quantity must be int, got str
print(Order.quantity)  # <__main__.Typed object> — descriptor itself via class access
```

### Example 2: `RangeChecked` / `Validated` — Constraint Attribute

```python
class RangeChecked:
    """Descriptor that validates value is in [min, max] (inclusive) plus optional predicate."""
    def __init__(self, *, min=None, max=None, predicate=None, name_hint=None):
        self.min, self.max, self.predicate = min, max, predicate
        self.name_hint = name_hint

    def __set_name__(self, owner, name):
        self.name = name
        self.private = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None: return self
        return getattr(obj, self.private)

    def __set__(self, obj, value):
        if self.min is not None and value < self.min:
            raise ValueError(f"{self.name} must be >= {self.min}, got {value}")
        if self.max is not None and value > self.max:
            raise ValueError(f"{self.name} must be <= {self.max}, got {value}")
        if self.predicate is not None and not self.predicate(value):
            raise ValueError(f"{self.name} failed validation for {value!r}")
        setattr(obj, self.private, value)

class Account:
    balance = RangeChecked(min=0)
    age = RangeChecked(min=0, max=150)

a = Account()
a.balance = 100
print(a.balance)
try: a.balance = -5
except ValueError as e: print(e)
try: a.age = 200
except ValueError as e: print(e)

# Per-instance storage: using `self.private` string means values live in instance.__dict__
# That's the standard pattern — shared descriptor on class, per-instance storage in instance dict.
```

### Example 3: `Cached` / Lazy Computation — Computed Once Descriptor (Non-Data vs Data Tradeoff)

```python
# Non-data caching descriptor — instance dict shadows after first compute
class Cached:
    """
    Lazy computed property cached after first access.
    Accessing `obj.attr = value` after caching would shadow — but we want to prevent that.
    So we demonstrate both variants.
    """
    def __init__(self, func):
        self.func = func
        self.name = func.__name__

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None: return self
        # Compute, cache in instance dict under same name (shadows descriptor on next read, O(1) hit)
        value = self.func(obj)
        # Direct dict write avoids descriptor protocol recursion
        obj.__dict__[self.name] = value
        return value
        # Note: this is a non-data descriptor (only __get__), so after this line,
        # future reads find obj.__dict__[name] before hitting descriptor — fast path.

# Data-descriptor variant that remains intercepting (can enforce read-only and support cache invalidation):
class CachedData:
    def __init__(self, func):
        self.func, self.name, self.private = func, func.__name__, None
    def __set_name__(self, owner, name):
        self.name, self.private = name, f"_{name}_cached"
        self.valid_flag = f"_{name}_valid"
    def __get__(self, obj, objtype=None):
        if obj is None: return self
        if not getattr(obj, self.valid_flag, False):
            value = self.func(obj)
            setattr(obj, self.private, value)
            setattr(obj, self.valid_flag, True)
        return getattr(obj, self.private)
    def __set__(self, obj, value):
        raise AttributeError(f"{self.name} is a cached read-only attribute; del to reset")
    def __delete__(self, obj):
        # Invalidate cache — next read recomputes
        setattr(obj, self.valid_flag, False)
        try: delattr(obj, self.private)
        except AttributeError: pass


class Report:
    def __init__(self, data):
        self.data = list(data)

    @Cached
    def total(self):
        print("  computing total (Cached non-data)")
        return sum(self.data)

    @CachedData
    def average(self):
        print("  computing average (CachedData data-desc)")
        return sum(self.data) / len(self.data) if self.data else 0

r = Report([1,2,3,4])
print(r.total)    # computing total — cached
print(r.total)    # not recomputed — found in __dict__
r.data.append(10)
print(r.total)    # still stale (5 cached, not 15) — non-data variant has no invalidation
r.total = 999     # ❌ shadows descriptor! Future reads return 999, descriptor dead
print(r.total)    # 999

print("--- data descriptor ---")
print(r.average)  # computing average — cached via valid flag
print(r.average)  # not recomputed
r.data.append(10)
print(r.average)  # still cached stale — but we can invalidate:
del r.average     # invalidates
print(r.average)  # recomputed with new data

# Tradeoff:
# - Non-data (Cached): faster after cache (dict lookup wins), but allows shadowing and has no delete hook.
# - Data (CachedData): controllable, invalidation-capable, prevents accidental shadowing, slightly slower post-cache.
# stdlib choice: functools.cached_property (3.8+) is similar to non-data (fast, shadowing) — del obj.attr invalidates.
# Python 3.8: from functools import cached_property
```

## `__set_name__` — The Class Wiring Hook (Python 3.6+)

`__set_name__(self, owner, name)` is called automatically when the class is *constructed* for each descriptor in the class body. It solves the "how does a descriptor know its attribute name?" problem without polluting `__init__`.

```python
class Tracked:
    def __set_name__(self, owner, name):
        print(f"Tracked.__set_name__ owner={owner.__name__} name={name}")
        self.name = name
        self.private = f"_{name}"

    def __get__(self, obj, objtype=None):
        if obj is None: return self
        return getattr(obj, self.private, 0)
    def __set__(self, obj, value):
        print(f"Setting {self.name} = {value}")
        setattr(obj, self.private, value)

class Model:
    a = Tracked()
    b = Tracked()
    # Output at class definition time:
    # Tracked.__set_name__ owner=Model name=a
    # Tracked.__set_name__ owner=Model name=b

# Inheritance: __set_name__ is called per-class, so a descriptor reused across classes gets wired twice
# (once per owner). Subclasses re-invoke for inherited descriptors if own __dict__ re-assigns them.

# Alternative without __set_name__ (old style): required explicit name argument:
class OldStyle:
    def __init__(self, name): self.name, self.private = name, f"_{name}"
    def __get__(self, obj, objtype=None):
        if obj is None: return self
        return getattr(obj, self.private, 0)
    def __set__(self, obj, value): setattr(obj, self.private, value)

class ModelOld:
    a = OldStyle("a")  # duplication — must match attribute name manually
    b = OldStyle("b")  # error prone if refactored — __set_name__ fixes this.
```

## Descriptor vs `property` vs `__getattr__` / `__getattribute__`

| Mechanism | Lives | Scope | When to use |
|-----------|-------|-------|-------------|
| **Descriptor** (`__get__`/`__set__` on class attr) | Class dict, per-attribute | One attribute | Validated / typed / lazy / bound-method logic, reuse across classes |
| **`property`** | Class dict, one attribute | One attribute | Single computed property for one class — syntactic sugar over descriptor |
| **`__getattr__`** (fallback) + `__getattribute__` (universal) | Defined on instance class as method | Every attribute | Dynamic attributes (proxy, delegation, virtual attributes), lazy fallthrough — see 13.11 |

**Rule:** Use a descriptor/property for *known* attributes; use `__getattr__` for *unknown* / dynamic / proxied attributes. Never use `__getattribute__` where a descriptor would suffice.

```python
from typing import Any

# Descriptor for fixed field validation:
class Price:
    def __set_name__(self, owner, name): self.name, self.private = name, f"_{name}"
    def __get__(self, obj, objtype=None):
        if obj is None: return self
        return getattr(obj, self.private)
    def __set__(self, obj, value):
        if value < 0: raise ValueError(f"{self.name} must be >= 0")
        setattr(obj, self.private, value)

# __getattr__ for dynamic remote fetching (proxy):
class Remote:
    """Proxy that fetches unknown attributes on demand — descriptor NOT suitable because field names unknown."""
    def __getattr__(self, name: str) -> Any:
        print(f"[remote] fetching {name}")
        # simulate: self.data.get(name) or raise AttributeError
        if name.startswith("_"):
            raise AttributeError(name)
        return f"value_of_{name}"

r = Remote()
print(r.anything)   # value_of_anything — via __getattr__
print(r.dynamic)    # value_of_dynamic  — dynamic

class Product:
    price = Price()          # known, validated -> descriptor
    # description fetched lazily from DB? still descriptor if name known; but for unknown metadata keys -> __getattr__
    def __getattr__(self, name):
        if name.startswith("meta_"):
            return f"meta:{name}"
        raise AttributeError(name)

p = Product()
p.price = 10                 # via descriptor
print(p.price)               # 10
print(p.meta_color)          # meta:meta_color — via __getattr__, not via Price
```

## Storage Strategies: Where Does the Value Live?

| Strategy | How | Lifetime | Notes |
|----------|-----|----------|-------|
| `instance.__dict__[private]` | `setattr(instance, self.private, value)` | Until instance GC, mutable, picklable | Standard — works for most descriptors; breaks with `__slots__` classes lacking `__dict__` |
| `__slots__` per-instance slot | Requires slot alias | Instance-scoped, fixed | Must know slot names — advanced |
| `WeakKeyDictionary` | `self.cache[instance] = value` with `WeakKeyDictionary` | Shared storage, instance-GCed when obj dies | Needed when instance has no `__dict__` (slotted) or you want external caching control |
| Closure / descriptor-owned dict | `self._values[id(instance)]` + manual WeakRef | Leaky if not WeakKeyDictionary | Prefer `WeakKeyDictionary` |

```python
import weakref

class StoreExternally:
    """Descriptor that cannot use instance.__dict__ (perhaps the instance is slotted or the value must be shared)."""
    def __init__(self):
        self._cache: weakref.WeakKeyDictionary = weakref.WeakKeyDictionary()
    def __set_name__(self, owner, name): self.name = name
    def __get__(self, obj, objtype=None):
        if obj is None: return self
        try:
            return self._cache[obj]
        except KeyError:
            raise AttributeError(f"{self.name} not set") from None
    def __set__(self, obj, value):
        self._cache[obj] = value
    def __delete__(self, obj):
        del self._cache[obj]

class Slotted:
    __slots__ = ()  # no __dict__
    x = StoreExternally()  # but must store externally because slotless instances fail setattr to __dict__

s = Slotted()
s.x = 42
print(s.x)  # 42 via WeakKeyDictionary — instance.__dict__ doesn't exist but weak map works
# When s is GC'd, entry automatically removed from WeakKeyDictionary.
```

## Metaclass vs Descriptor Interaction: Order and `__set_name__`

`__set_name__` was introduced in Python 3.6 specifically to make descriptors work cleanly without metaclasses. Before that, frameworks needed a metaclass to scan attributes and wire private names. Now the class creation machinery calls `__set_name__` for every class attribute that defines it.

```python
# Historically: metaclass scanned for descriptors
class OldMeta(type):
    def __new__(mcls, name, bases, ns):
        for attr, val in list(ns.items()):
            if hasattr(val, "bind_name"):  # custom hook, precursor to __set_name__
                val.bind_name(attr)
        return super().__new__(mcls, name, bases, ns)

# Now: no metaclass needed — language calls descriptor.__set_name__(owner, name) automatically
```

## Edge Cases: Read-Only, Write-Only, `instance is None`, Deletion

```python
class ReadOnly:
    def __init__(self, value): self._value = value
    def __set_name__(self, owner, name): self.name = name
    def __get__(self, obj, objtype=None):
        if obj is None:
            # Class-level access: e.g., Cls.attr — return descriptor or class-wide default
            return self  # or return f"<ReadOnly {self.name}>"
        return self._value
        # But per-instance read-only that still respects instance? Use external storage or instance private.
        # This variant is global, not per-instance — just demo of the None path.
    def __set__(self, obj, value):
        raise AttributeError(f"{self.name} is read-only")

class W:
    x = ReadOnly(42)

print(W.x)       # <__main__.ReadOnly ...> — class access returns descriptor (if __get__ returns self)
print(W().x)     # 42 — instance access returns value
try: W().x = 1
except AttributeError as e: print(e)
# Deletion behaves like set for data descriptors — define __delete__ similarly if needed.
```

## Common Mistakes Table

| Mistake | Why It Breaks | Fix |
|---------|---------------|-----|
| Forgetting `instance is None` branch in `__get__` | `Class.attr` triggers descriptor with `obj=None` and may return raw value instead of descriptor; tools like `help`, `inspect` rely on class-level access | Always `if obj is None: return self` |
| Forgetting `__set_name__` and hardcoding storage key | Rename breaks silently; reuse across attributes collides | Implement `__set_name__` to assign `self.private = f"_{name}"` |
| Non-data descriptor allows instance shadowing | `obj.attr = x` shadows method/validator silently | Make it data descriptor (`__set__`) to prevent shadowing |
| Using `WeakKeyDictionary` without holding `WeakKeyDictionary` correctly | GC collects descriptor? No — but entries may linger if instance is not hashable / not weak-referencable (e.g., `__slots__` without `__weakref__`) | Ensure instance supports `weakref` (`__weakref__` slot or `__dict__`) |
| Doing heavy computation in `__get__` on every access | Hot-path slowdown (e.g., `obj.price` in a loop) | `cached_property` or store derived value; invalidate only when dependencies change |
| Recursive `__get__` via `getattr(obj, self.private)` when private also triggers descriptor | Recursion loop if private name overlaps descriptor name | Use `object.__getattribute__(obj, self.private)` or prefix private with `_` that shadows differently |
| Shadowing `__slots__` value and descriptor external storage diverges | Two sources of truth | Choose one storage: slots *or* dict vs external map, consistently |

## Performance

*   Descriptor access is a Python-level call per `__get__` / `__set__` invocation — but the dispatch itself is C-level slot machinery, so nimble. Expect ~30–70 ns extra over plain `instance.__dict__` access.
*   `WeakKeyDictionary` indirection adds hash-table lookup overhead — ~2–3× slower than `__dict__` storage.
*   `property` has extra frame (function call) per access — negligible outside tight loops; profile before pursuing descriptor micro-optimization.
*   `functools.cached_property` optimization: first access calls function, second is `__dict__` directly (no descriptor call) — fastest cached read path.

## Checklist

1.  Decide data vs non-data: does the attribute need write interception? If yes → data descriptor.
2.  Implement `__set_name__` to allocate a per-attribute private key.
3.  Implement `__get__` with `if obj is None: return self` branch.
4.  Choose storage: `instance.__dict__[private]` (default), `WeakKeyDictionary` (slotted / external), or `object.__getattribute__` (when dict unavailable).
5.  Test class-level and instance-level access: do they behave as intended for both?
6.  Test shadowing: does `obj.attr = x` correctly route through descriptor (data) or shadow correctly (non-data)?
7.  Is the descriptor reusable across multiple classes? Verify `__set_name__` wires per-owner.
8.  Measure: is descriptor access on the hot path? Would `cached_property` or plain attribute suit better?

## Exercises (Mental)

1.  Write `NonNegative` descriptor that rejects negative values — make it data vs non-data and predict behavior when `obj.__dict__["x"]` is pre-populated.
2.  Explain why `class A: def f(self): pass` makes `A().f` a bound method — trace the descriptor path with `func.__get__`.
3.  Implement `Lazy(expr: Callable[[obj], T])` that computes once from instance state and caches in `__dict__`, supporting `del obj.attr` reset. When would you use `WeakKeyDictionary` instead?
4.  When does `__set_name__` run relative to `class` body execution and `type.__new__`? What if a subclass reassigns the descriptor under a different name?
5.  `hasattr(obj, attr)` triggers `__get__` — what happens if `__get__` raises `AttributeError`? How does this differ from `getattr(obj, attr, sentinel)`?
