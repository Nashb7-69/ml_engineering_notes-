# 13.14 Dataclasses: @dataclass, field(), and the Generated Boilerplate

## Why Dataclasses Exist

Most domain types consist of a handful of typed attributes with generated `__init__`, `__repr__`, `__eq__`, ordering, and hashing that you would otherwise hand-write for every class. `dataclasses` (stdlib, Python 3.7+, PEP 557) automates this without inheritance or metaclass exposure — the decorator synthesizes methods from declared fields:

```python
# Before: ~30 lines of boilerplate
class Point_old:
    def __init__(self, x: int, y: int, label: str = ""):
        self.x, self.y, self.label = x, y, label
    def __repr__(self): return f"Point_old(x={self.x!r}, y={self.y!r}, label={self.label!r})"
    def __eq__(self, other):
        if isinstance(other, Point_old): return (self.x,self.y,self.label)==(other.x,other.y,other.label)
        return NotImplemented
    def __hash__(self): return hash((self.x,self.y,self.label)) # if frozen
    # plus ordering would add four more methods...

# After: 4 lines, correct handling with typing integration, optional slots, ordering, and immutability
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int
    label: str = ""

print(Point(1, 2, "A"))           # Point(x=1, y=2, label='A')
print(Point(1,2)==Point(1,2))     # True
print(Point(1,2))                 # repr auto
```

> **Mental model:** `@dataclass` introspects the class's annotations, builds a list of `Field` objects, and injects generated methods into the class dict. It is conceptually equivalent to a sophisticated *class decorator* (not a metaclass, though technically `dataclass` uses `exec()` to compile fast paths). No runtime overhead beyond the generated code.

## Minimal Dataclass and Generated Methods

```python
from dataclasses import dataclass, field

@dataclass
class Product:
    sku: str
    name: str
    price_cents: int
    tags: list[str] = field(default_factory=list)  # mutable default needs factory, not []

# Generated:
# - __init__(self, sku, name, price_cents, tags=default_factory)
# - __repr__(self)  -> Product(sku='...', ...)
# - __eq__(self, other) and __ne__ (auto not, but eq)
# (hash/order not generated by default — see below)
# - __init__ validates types only statically (mypy/pyright), not at runtime

p = Product("WIDGET-1", "Widget", 999)
print(p)                      # Product(sku='WIDGET-1', name='Widget', price_cents=999, tags=[])
print(p == Product("WIDGET-1","Widget", 999))  # True — value equality
# Anatomy: Product(sku: str) means sku is last-inited but first declared? Equals signature order.
# Order is definition order: sku, name, price_cents, tags.

# Inspect generated fields:
from dataclasses import fields, asdict, astuple
print([f.name for f in fields(Product)])  # ['sku', 'name', 'price_cents', 'tags']
print(asdict(p))  # {'sku': 'WIDGET-1', ...} — recursive conversion
print(astuple(p)) # ('WIDGET-1', 'Widget', 999, [])
```

### `field()` — Every Knob For an Attribute

`dataclasses.field()` customizes a single field. Every parameter maps to code-generation behavior:

```python
from dataclasses import dataclass, field

def default_id():
    import uuid
    return str(uuid.uuid4())[:8]

@dataclass
class Order:
    # Required field — no default (must come before optionals in signature)
    customer: str

    # Default value (immutable literal)
    status: str = "pending"

    # Mutable default — use factory, never literal []
    items: list[str] = field(default_factory=list)

    # Auto-generated but hidden from repr/eq/compare/hash
    _id: str = field(default_factory=default_id, compare=False, hash=False, repr=False)

    # Only available via keyword arguments (Python 3.10+ kw_only)
    priority: int = field(default=0, kw_only=True)

    # Excluded from generated __init__ — computed afterwards
    total_cents: int = field(init=False, default=0)

    # Include in init but not comparison/ordering
    note: str = field(default="", compare=False)

    def __post_init__(self):
        # After auto __init__, compute init=False fields or normalize
        self.total_cents = sum({"apple": 100, "banana": 50}.get(it, 0) for it in self.items)
        # self._id already set via factory before __post_init__

# Inspect:
o = Order(customer="Alice", items=["apple","apple"], note="urgent")
print(o)  # note excluded from eq/order, _id hidden even from repr
print(o._id, o.total_cents, o.status)

# Signature: help(Order) shows:
# Order(customer: str, status: str = 'pending', items: ... , priority: int)
# and priority is kw_only, so:
# Order(customer="Bob", priority=5)  — kw
# Order("Bob", priority=5)  — still requires kw for priority: priority= kw only

# Default vs default_factory:
#   default=42     →  same literal shared (safe for immutables)
#   default_factory=list  →  fresh list per instance, called as factory()
# Never do `items: list = field(default=[])` — mutable literal shared across instances!

# All field params:
# default: value                (MISSING means required)
# default_factory: () -> value  (callable, no args)
# init: bool= True              (include in __init__)
# repr: bool= True
# hash: Optional[bool]= None    (None follows compare's inclusion; for hashable dataclass behavior)
# compare: bool= True           (include in __eq__ and ordering)
# metadata: dict | None         (arbitrary payload for frameworks)
# kw_only: bool= False (3.10+)  (only pass as keyword in __init__)
# slots interaction -> not a field param but class param
```

### `__post_init__`

```python
@dataclass
class Rational:
    num: int
    den: int
    value: float = field(init=False)

    def __post_init__(self):
        # Normalize: reduce fraction, validate denominator
        import math
        if self.den == 0: raise ValueError("denominator cannot be zero")
        g = math.gcd(self.num, self.den)
        # mutate in place:
        object.__setattr__(self, "num", self.num // g)
        object.__setattr__(self, "den", self.den // g)  # for frozen, must use object.__setattr__
        # Even on mutable, explicit setattr is fine: self.num //= g
        object.__setattr__(self, "value", self.num / self.den)

    def __repr__(self): return f"Rational({self.num}/{self.den} = {self.value})"

print(Rational(6, 8))  # Rational(3/4 = 0.75)
```

`__post_init__` runs after auto `__init__` has set all `init=True` fields. For `frozen=True` classes, assignments inside `__post_init__` must use `object.__setattr__(self, name, value)` because normal `self.name = ...` is forbidden (immutability enforced).

## Decorator Parameters — The Global Knobs

```python
@dataclass(
    init=True,        # generate __init__
    repr=True,        # generate __repr__
    eq=True,          # generate __eq__ (and __ne__)
    order=False,      # generate __lt__, __le__, __gt__, __ge__ — requires eq=True
    unsafe_hash=False,# generate __hash__ even when mutable (you promise not to mutate while hashed)
    frozen=False,     # make immutable — sets __setattr__/__delattr__ to raise & generates __hash__ if eq
    match_args=True,  # generate __match_args__ for structural pattern matching (3.10+)
    kw_only=False,    # make all fields keyword-only in __init__ (3.10+)
    slots=False,      # use __slots__ for memory/layout (3.10+)
    weakref_slot=False,# include __weakref__ slot when slots=True
)
class Example: pass
```

### Each Knob In Detail

#### `eq` and `hash` Together

```python
from dataclasses import dataclass

# Default: eq=True, no hash — eq implies hash=None (same as plain class)
@dataclass
class MutableDefault:
    x: int
    y: int

print(MutableDefault.__hash__)  # None — mutable by default, unhashable

try:
    hash(MutableDefault(1,2))
except TypeError as e: print(e)

# unsafe_hash=True — generate hash even on mutable (dangerous!)
@dataclass(eq=True, unsafe_hash=True)
class MutableHashable:
    x: int

mh = MutableHashable(1)
d = {mh: 1}
mh.x = 2        # mutation while in dict — hash now differs -> corruption!
print(mh in d)  # False — same danger as 13.04

# Frozen: eq + hash auto-generated, immutable
@dataclass(frozen=True)
class FrozenPoint:
    x: int
    y: int

fp = FrozenPoint(1,2)
print(hash(fp), {fp: "hi"})  # hashable
try: fp.x = 9
except Exception as e: print(f"frozen blocks: {e}")

# eq=False — no __eq__ generated, inherits object identity equality and identity hash
@dataclass(eq=False, frozen=True)  # even with frozen, eq=False means identity hash stays
class IdentityFrozen:
    x: int
# Useful when you want frozen immutability (no setter) but identity semantics for equality/hashing.

# Explicit custom __hash__ on a dataclass:
@dataclass
class CustomHash:
    x: int
    secret: str = field(compare=False, hash=False)  # excluded
    # Defining your own __hash__ overrides dataclass generation (when unsafe_hash not set, eq's hash=None not used)
    def __hash__(self): return hash(self.x)
    def __eq__(self, other):
        if isinstance(other, CustomHash): return self.x == other.x  # secret excluded — so is hash, contract holds
        return NotImplemented

print(CustomHash(1,"a") == CustomHash(1,"b"))  # True
```

#### `order` — Ordering Via Field Tuple

```python
@dataclass(order=True, frozen=True)
class OrderedItem:
    priority: int
    name: str = field(compare=False)  # excluded from ordering — only priority decides

print(OrderedItem(1,"b") < OrderedItem(2,"a"))  # True — by priority
print(OrderedItem(1,"b") == OrderedItem(1,"a")) # True — because name excluded from eq too! (compare=False)

# When order=True, dataclass generates __lt__ etc. that compares fields tuple lexicographically.
# If compare=False on a field, that field NOT in equality nor ordering tuple — so two objects
# differing only in that field will be considered equal/order-equivalent. Make sure that's intended.

# Pitfall: order=True but repr includes compare=False fields — repr distinct while equality says equal, surprising:
from dataclasses import dataclass, field
@dataclass(order=True)
class Pitfall:
    key: int
    label: str = field(compare=False)
print(Pitfall(1, "a") == Pitfall(1, "b"))  # True — label ignored
print(Pitfall(1, "a"))                     # Pitfall(key=1, label='a') — look different!
# Document or use field(compare=True) unless you truly intend equality to ignore the field.

# kw_only and ordering: ordering tuple respects field definition order, not call-site keyword order.
```

#### `frozen`, `slots`, `kw_only` (3.10+ Features)

```python
from dataclasses import dataclass, field
import sys

# kw_only — all fields keyword-only or per-field distinction
@dataclass(kw_only=True)
class ConfigKW:
    host: str
    port: int
    timeout: float = field(default=30.0, kw_only=True)  # explicit kw_only per field

# ConfigKW("host", 8080)  # TypeError: positional arg not allowed
cfg = ConfigKW(host="localhost", port=8080)
print(cfg)

# slots — saves memory, faster attribute access, enforces no dynamic attributes
@dataclass(slots=True)
class SlotPoint:
    x: float
    y: float

sp = SlotPoint(1,2)
print(SlotPoint.__slots__)   # ('x', 'y')
try:
    sp.extra = 9
except AttributeError as e: print(e)  # no __dict__
print(sys.getsizeof(sp), SlotPoint.__slots__)

# slots + weakref_slot
@dataclass(slots=True, weakref_slot=True)
class WeakSlot:
    name: str

import weakref
w = WeakSlot("w")
r = weakref.ref(w)  # requires weakref slot
print(r() is w)

# frozen + slots — most memory-efficient immutable value type
@dataclass(frozen=True, slots=True)
class FrozenSlotted:
    x: int
    y: int
print(hash(FrozenSlotted(1,2)))
```

## Inheritance With Dataclasses

```python
from dataclasses import dataclass, field

@dataclass
class Base:
    x: int
    label: str = "base"

@dataclass
class Child(Base):
    y: int
    label: str = "child"  # override — defaults ordering rules apply

# Generated __init__ signature: Child(x, y, label="child") but with caveats about defaults ordering.
# Rule: dataclass collects fields from bases first, then own fields, but if a non-default follows a default
# in base, Child must keep invariants: non-defaults before defaults.
# So define bases such that non-default supersede ordering? Example:

# ❌ TypeError: non-default argument 'y' follows default argument 'label'
# @dataclass
# class Base2:
#     label: str = "base"  # default
# @dataclass
# class Child2(Base2):
#     y: int               # non-default after default — conflict

# ✅ Fix: use kw_only for the child's extra non-defaults, or make base field kw_only, or provide default for y:

@dataclass
class Base3:
    label: str = "base"

@dataclass(kw_only=True)
class Child3(Base3):
    y: int = 0  # default — ok (or y: int = field(kw_only=True) without default concept)

# Alternative fix in 3.10+: make y keyword-only so non-default positional restriction doesn't apply
@dataclass
class ChildKW(Base):
    y: int = field(kw_only=True)  # positional for Base fields only, y always keyword

c = ChildKW(x=1, y=2)
print(c)

# Inheritance and ordering: ordering compares all fields inherited (in MRO definition order),
# not just child's declared fields.
@dataclass(order=True)
class BaseOrder:
    a: int

@dataclass(order=True)
class ChildOrder(BaseOrder):
    b: int

print(ChildOrder(1,2) < ChildOrder(1,3))  # lex on (a,b): (1,2) < (1,3) True
```

## Dataclass vs Manual vs NamedTuple vs `attrs`

| Need | Tool | Why |
|------|------|-----|
| Mutable value type, quick setup | `@dataclass` | Syntax, fields introspection |
| Immutable value type, hashable, slots | `@dataclass(frozen=True, slots=True)` | Best memory/hash combo; validates invariants in `__post_init__` |
| Also immutable but tuple-based | `typing.NamedTuple` / `collections.namedtuple` | Tuple sequence + fields, C-optimized; but inherits tuple methods (`count`, `_fields`) |
| Advanced validators, converters, more features | `attrs` / `pydantic` | `attrs` inspired dataclasses; pydantic adds parsing/JSON schema |
| Hand-coded for maximum control | Manual class with explicit `__init__`/`__eq__`/... | When construction logic is non-field decomposition (e.g., cached interning, complex `__new__`) |

```python
from collections import namedtuple

TP = namedtuple("TP", ["x","y"])
@dataclass(frozen=True, slots=True)
class DC:
    x: int
    y: int

print(TP(1,2).count, DC(1,2))  # namedtuple has tuple API, dataclass does not (unless you add sequence mixin)
print(asdict(DC(1,2)), TP(1,2)._asdict())

# Dataclass advantage: default_factory, field metadata, per-field repr/compare/hash/visibility, __post_init__, slots toggle.
# NamedTuple advantage: unpacking `x,y = TP(...)`, indexing `t[0]`, immutable due to tuple immutability guarantee.
```

### Performance / Memory Measurements (Guidance)

```python
# Illustrative memory delta (measured with sys.getsizeof + __dict__ size in CPython 3.11):
# plain object with __dict__:  ~56 bytes per instance dict + per attribute dict entry ~72 bytes each
# dataclass (no slots): same as plain — nothing saved.
# dataclass(slots=True): no __dict__ per instance — ~40% memory saving per million instances.
# dataclass(frozen=True, slots=True): same footprint as slots but immutability enforced + hash auto.

# Speed: dataclass-generated __init__ is Python code compiled via exec — effectively hand-written speed.
# The generated __eq__ compares fields tuple, not sorted list — O(k) where k = number of fields, equal to manual.
# So dataclass is not slower than manual — it's equal, with less maintenance.

# When slots matters: millions of small value objects (points, records, events streaming).
# When it doesn't: a few hundred config objects — clarity over micro-optimization.
```

## Pitfalls & Common Mistakes

| Mistake | Why It Breaks | Fix |
|---------|---------------|-----|
| `items: list = []` instead of `field(default_factory=list)` | Single list shared across all instances (mutable default) | `items: list = field(default_factory=list)` |
| `__eq__` field excluded but forgetting `hash` exclusion | If `secret` in `__eq__` but not in `__hash__`, equal objects may have different hashes — contract violation | Field not in compare → remove from hash, or use `compare=False, hash=False` together; or define custom `__hash__` |
| Expecting runtime type enforcement | `@dataclass` doesn't validate `x: int = "hello"` — type hints are static only | Use `pydantic @dataclass` or add `__post_init__` checks: `if not isinstance(self.x, int): raise TypeError` |
| Non-default field after default across inheritance | `TypeError: non-default argument follows default argument` at decoration time | Use `kw_only=True` for later fields or reorder bases and give defaults |
| Mutating frozen instance bypassing `object.__setattr__` | `FrozenError` or hashed collection corruption if mutated via hacking `_object._setattr__` | Respect frozen immutability; if mutation needed, make new instance: `dataclasses.replace(obj, x=1)` |
| Assuming `asdict` is deep-copy cheap | `asdict` copies lists and nested dataclasses recursively — O(n) and may duplicate | Use `obj.__dict__.copy()` for shallow, or know cost for large trees |
| Using dataclass fields as a public mutation API when invariant requires freezing | External `obj.x = broken` breaks invariant | `frozen=True` or `field(init=False, repr=False)` plus validators; consider `property` over direct field if expensive invariant |

```python
# Mutable default trap demo:
from dataclasses import dataclass

@dataclass
class Bad:
    items: list = []  # ❌ Dangerous!
b1 = Bad()
b2 = Bad()
b1.items.append(1)
print(b1.items, b2.items)  # [1] [1] — shared!
# Dataclasses actually warn at decoration: `ValueError: mutable default <class 'list'> for field items is not allowed: use default_factory`
# Wait — stdlib dataclass checks this and raises at import time since 3.11? Actually earlier it still catches.
# E.g., defining `@dataclass class Bad: items: list = []` raises ValueError at decoration.

from dataclasses import dataclass, field
@dataclass
class Good:
    items: list = field(default_factory=list)
g1, g2 = Good(), Good()
g1.items.append(1)
print(g1.items, g2.items)  # [1] [] — isolated

# Frozen mutation attempt:
@dataclass(frozen=True)
class Frozen:
    x: int
f = Frozen(1)
try: f.x = 2
except Exception as e: print(f"frozen error: {type(e).__name__}: {e}")
# Even object.__setattr__ is discouraged outside __post_init__; use replace:
import dataclasses
f2 = dataclasses.replace(f, x=2)
print(f2)  # Frozen(x=2) — new instance, no mutation
```

## `dataclasses` Toolbox — Helpers

```python
from dataclasses import dataclass, field, fields, asdict, astuple, replace, is_dataclass, make_dataclass, MISSING

@dataclass
class PointEx:
    x: int
    y: int
    label: str = field(default="", compare=False, metadata={"doc": "human label"})

# is_dataclass
print(is_dataclass(PointEx), is_dataclass(PointEx(1,2)))  # True, True (instance also true)
# MISSING sentinel for field default checking inside processing code:
for f in fields(PointEx):
    has_default = f.default is not MISSING or f.default_factory is not MISSING
    print(f"{f.name}: has_default={has_default}, metadata={f.metadata}")

# replace — functional update (like case class copy)
p = PointEx(1,2, "origin")
q = replace(p, x=9)
print(p, q)  # orig unchanged

# make_dataclass — dynamic dataclass creation
Dyn = make_dataclass("Dyn", [("x", int), ("y", int, field(default=0))])
print(Dyn(1))  # Dyn(x=1, y=0)

# asdict / astuple — deep conversion with recursion and memoization options
@dataclass
class Node:
    value: int
    next: "Node | None" = None
# Avoid recursion here — asdict will traverse next.

# Field metadata for frameworks:
@dataclass
class WithMeta:
    x: int = field(metadata={"units": "m", "min": 0})
print(fields(WithMeta)[0].metadata)
```

## Checklist

1.  Have you used `field(default_factory=...)` for every mutable default?
2.  Is `eq` correctly exposing `hash` — frozen yields hashable, mutable yields `None` unless `unsafe_hash` explicitly justified?
3.  Are `compare=False` / `hash=False` fields excluded pairwise so contract holds?
4.  Does `order=True` only when total ordering via field tuple is semantically meaningful and not partial?
5.  Have you added `__post_init__` validation for invariants beyond type hints?
6.  Have you picked `slots=True` when millions of instances or fail-fast on dynamic attributes matters?
7.  Does inheritance ordering of defaults/positional parameters type-check? Use `kw_only=True` to avoid ordering conflicts.
8.  Is frozen immutability used deliberately (`replace` instead of mutation) and enforced for hashables?
