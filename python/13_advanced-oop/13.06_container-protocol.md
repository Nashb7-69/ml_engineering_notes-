# 13.06 The Container Protocol: __len__, __getitem__, __setitem__, __delitem__, __contains__, __missing__

## What "Container" Means in Python

A **container** is any object that holds other objects and exposes membership and sized access. Python formalizes this through a family of special methods that, together, let you emulate built-in `list`, `dict`, `set`, and sequence behavior:

| Method | Operation | Required? |
|--------|-----------|-----------|
| `__len__(self)` | `len(obj)` | For `Sized` |
| `__getitem__(self, key)` | `obj[key]` , `obj[start:stop:step]` | For indexing |
| `__setitem__(self, key, value)` | `obj[key] = value` | For mutable mapping/sequence |
| `__delitem__(self, key)` | `del obj[key]` | For mutable |
| `__contains__(self, item)` | `item in obj` | Optimized membership; otherwise iteration fallback |
| `__iter__(self)` | `for x in obj` , `iter(obj)` | For iteration (also covered in 13.07) |
| `__reversed__(self)` | `reversed(obj)` | Optional reverse iteration |
| `__missing__(self, key)` | `dict[key]` missing on Mapping subclass | Hook for custom default logic |

A type does not need all of them — implement what your abstraction promises. A read-only mapping needs `__getitem__` + `__len__` + `__iter__` + `__contains__`. A mutable sequence adds `__setitem__`, `__delitem__`, `insert`, etc.

### The `collections.abc` Lens

```python
from collections.abc import Sized, Container, Mapping, MutableMapping, Sequence, MutableSequence

# isinstance checks reflect protocol presence:
# Sized   -> requires __len__
# Iterable -> requires __iter__
# Container -> requires __contains__
# Mapping  -> requires __getitem__, __len__, __iter__ (keys), __contains__
# MutableMapping -> adds __setitem__, __delitem__

print(issubclass(dict, Mapping))            # True
print(issubclass(list, MutableSequence))     # True
# Registering your class as a Sequence gives you mixin methods for free when inheriting
```
> **Key idea from Python's design:** Protocols are structural. If you implement the methods, you *are* that kind of container — no declaration needed. But inheriting from `collections.abc.Mapping` gives you free implementations of `keys()`, `values()`, `items()`, `get()`, `__contains__`, and `__eq__` in terms of your abstract methods.

## `__len__` — The Size

```python
class Bag:
    def __init__(self, items): self._items = list(items)
    def __len__(self) -> int:
        return len(self._items)
    def __repr__(self): return f"Bag({self._items!r})"

bag = Bag([1,2,3])
print(len(bag))   # 3
print(bool(bag))  # True via __len__ fallback — bool(obj) == (len(obj) != 0) when __bool__ missing
print(bool(Bag([])))  # False

# Contract:
# - Must return int >= 0, or TypeError/ValueError raised depending on misuse.
# - Must be consistent with __bool__ if both defined: __bool__ takes precedence.
# - CPython optimizes `len(x)` to a slot call — O(1) expected; don't do O(n) scans.

class SlowLen:
    def __init__(self, data): self.data = data
    def __len__(self):
        # ❌ Anti-pattern: O(n) length — hides performance trap
        count = 0
        for _ in self.data: count += 1
        return count
    # ✅ Store length incrementally or delegate
```

## `__getitem__` — Indexed Access and Slicing

`__getitem__` is the most versatile container hook. It receives **either** a single key (int, str, tuple) or a `slice` object. Python translates `obj[1:10:2]` into `obj.__getitem__(slice(1, 10, 2))` before your code runs.

### Basic Integer Key Access

```python
class FixedBuffer:
    """A fixed-size circular buffer — realistic bounded queue."""
    def __init__(self, capacity: int):
        self._cap = capacity
        self._data = [None] * capacity
        self._size = 0
        self._head = 0  # oldest index

    def append(self, value) -> None:
        pos = (self._head + self._size) % self._cap if self._size < self._cap else self._head
        self._data[pos] = value
        if self._size < self._cap:
            self._size += 1
        else:
            self._head = (self._head + 1) % self._cap

    def __len__(self) -> int: return self._size

    def __getitem__(self, idx):
        # Handle slices
        if isinstance(idx, slice):
            # slice.indices handles negative/clamping relative to len(self)
            return [self[i] for i in range(*idx.indices(len(self)))]
        # Handle integer indexing with negative support
        if not isinstance(idx, int):
            raise TypeError(f"indices must be integers or slices, not {type(idx).__name__}")
        if idx < 0:
            idx += len(self)
        if not 0 <= idx < len(self):
            raise IndexError("buffer index out of range")
        real = (self._head + idx) % self._cap
        return self._data[real]

    def __repr__(self): return f"FixedBuffer({[self[i] for i in range(len(self))]!r})"

buf = FixedBuffer(4)
for v in [10, 20, 30, 40, 50]:  # 10 evicted
    buf.append(v)
print(buf)         # FixedBuffer([20, 30, 40, 50])
print(buf[0], buf[-1], buf[1:3])  # 20 50 [30, 40]
print(buf[::-1])   # [50, 40, 30, 20] — reversed via slice
print(list(buf))   # uses __getitem__ iteration fallback? No — we haven't defined __iter__, so for loop uses __getitem__ from 0 until IndexError!
for x in buf:
    print(x, end=" ")  # 20 30 40 50
print()
```

### The `slice` Object

```python
s = slice(1, 10, 2)
print(s.start, s.stop, s.step)  # 1 10 2
# Important helper: slice.indices(n) normalizes negatives and clamping
print(slice(-3, None).indices(5))   # (2, 5, 1) — for len 5, -3 => index 2
print(slice(None, None, -1).indices(5))  # (4, -1, -1) — reverse full sequence
print(slice(1, 100).indices(4))     # (1, 4, 1) — clamped to length

# Delegating slicing to an internal list is the common pattern:
class Playlist:
    def __init__(self, tracks): self._tracks = list(tracks)
    def __getitem__(self, idx):
        # Just delegate — list handles int, slice, negative indices, step
        return self._tracks[idx]
    def __len__(self): return len(self._tracks)

pl = Playlist(["A","B","C","D"])
print(pl[1])       # B
print(pl[1:3])     # ['B', 'C']
print(pl[::2])     # ['A', 'C']
print(pl[-1])      # D
print(pl[10])      # IndexError from list — propagated correctly
```

### Mapping Keys: `__getitem__` with Arbitrary Keys

```python
class CaseInsensitiveDict:
    """Mapping that treats string keys case-insensitively but preserves original casing in iteration."""
    def __init__(self, mapping=None):
        self._data: dict[str, tuple[str, object]] = {}  # lower -> (original, value)
        if mapping:
            for k, v in mapping.items():
                self[k] = v

    def _lower(self, key) -> str:
        if not isinstance(key, str):
            raise KeyError(key)  # or TypeError — choose one and document
        return key.lower()

    def __getitem__(self, key):
        k = self._lower(key)
        try:
            return self._data[k][1]
        except KeyError:
            # Option A: raise plain KeyError
            raise KeyError(key)
            # Option B: if subclassing dict, call __missing__(key) — see below

    def __setitem__(self, key, value):
        self._data[self._lower(key)] = (key, value)

    def __delitem__(self, key):
        del self._data[self._lower(key)]

    def __len__(self): return len(self._data)
    def __iter__(self): return (orig for orig, _ in self._data.values())
    def __contains__(self, key):
        try:
            return self._lower(key) in self._data
        except Exception:
            return False

    def __repr__(self):
        items = ", ".join(f"{k!r}: {v!r}" for k, v in self._data.values())
        return "{" + items + "}"

cid = CaseInsensitiveDict({"Host": "example.com", "Accept": "json"})
print(cid["host"])   # example.com — case insensitive lookup
print(cid["HOST"])   # example.com
cid["Content-Type"] = "text/html"
print(list(cid))     # ['Host', 'Accept', 'Content-Type'] — original casing preserved
print("host" in cid) # True
```

## `__setitem__`, `__delitem__` — Mutable Access

```python
class BoundedList:
    """List with fixed capacity — set/del with bounds checking and side effects."""
    def __init__(self, capacity: int, initial=None):
        self._cap = capacity
        self._data = list(initial) if initial else []
        if len(self._data) > capacity:
            raise ValueError("initial exceeds capacity")

    def __len__(self): return len(self._data)
    def __getitem__(self, key): return self._data[key]
    def __setitem__(self, key, value):
        # Can receive int or slice — must handle both
        self._data[key] = value
        # Could add validation:
        # if isinstance(key, slice): validate each value in `value` is allowed

    def __delitem__(self, key):
        del self._data[key]

    def append(self, value):
        if len(self) >= self._cap:
            raise OverflowError("capacity reached")
        self._data.append(value)

    def __iter__(self): return iter(self._data)
    def __repr__(self): return f"BoundedList(cap={self._cap}, {self._data!r})"

bl = BoundedList(3, [1, 2])
bl[0] = 99
print(bl[:])       # [99, 2]
bl[1:1] = [10, 20] # slice assignment — inserted at position 1
print(bl)          # would exceed capacity? Actually slice assignment via list bypasses our cap check — vulnerability!
# So you must validate slice assignments too:

class SafeBoundedList(BoundedList):
    def __setitem__(self, key, value):
        # Predict resulting length
        if isinstance(key, slice):
            # Simulate assignment to check capacity
            tmp = list(self._data)
            tmp[key] = value
            if len(tmp) > self._cap:
                raise OverflowError("assignment would exceed capacity")
        else:
            # single index — only valid if index in range
            if not (-len(self._data) <= key < len(self._data)):
                raise IndexError("assignment index out of range")
        super().__setitem__(key, value)

# Another edge: del with slice
del bl[0]
print(bl)  # after deletion
```

> **Lesson:** `__setitem__` receives either `int` or `slice` for the key, and `value` is either a single value or an iterable (for slice). Always handle both, or explicitly raise `TypeError` for unsupported slicing.

## `__contains__` vs Iteration Fallback

`in` first tries `__contains__`. If absent, it iterates via `__iter__` (or `__getitem__`) linearly.

```python
class NaiveContainer:
    def __init__(self, items): self._items = list(items)
    def __iter__(self): return iter(self._items)
    # No __contains__ — `in` will iterate linearly, O(n)

class OptimizedContainer:
    def __init__(self, items): 
        self._items = list(items)
        self._set = set(items)  # cache for O(1) membership
    def __iter__(self): return iter(self._items)
    def __contains__(self, item) -> bool:
        # O(1) via set, but must keep in sync with _items for mutations
        return item in self._set
    def add(self, item):
        if item not in self._set:
            self._items.append(item)
            self._set.add(item)

# Decision: implement __contains__ when you can answer membership faster than O(n) iteration.
# e.g., hash set, sorted array with binary search, indexed column.

class SortedArray:
    """Sorted container with binary-search __contains__."""
    def __init__(self, items):
        self._data = sorted(items)
    def __len__(self): return len(self._data)
    def __getitem__(self, i): return self._data[i]
    def __iter__(self): return iter(self._data)
    def __contains__(self, item):
        import bisect
        idx = bisect.bisect_left(self._data, item)
        return idx < len(self._data) and self._data[idx] == item
    def __repr__(self): return f"SortedArray({self._data!r})"

sa = SortedArray([5,3,1,4,2])
print(sa)            # SortedArray([1, 2, 3, 4, 5])
print(3 in sa)       # True — binary search
print(99 in sa)      # False — without scanning 5 items linearly
```

## `__missing__` — The Mapping Escape Hatch

`__missing__` is only invoked on **`dict` subclasses** (and `collections.abc.Mapping` subclasses that call it). It is triggered by `d[key]` when `key` is absent. It is **not** a general protocol for arbitrary `__getitem__` — it is specifically for mapping types that want auto-creation or alternative lookup.

```python
# Classic use: defaultdict, Counter, and custom auto-vivifying dicts

class DefaultDict(dict):
    """Manual defaultdict — demonstrates __missing__ wiring."""
    def __init__(self, default_factory, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.default_factory = default_factory
    def __missing__(self, key):
        if self.default_factory is None:
            raise KeyError(key)
        # Create default value, store it, and return it
        value = self.default_factory()
        self[key] = value
        return value

d = DefaultDict(list)
d["a"].append(1)
d["a"].append(2)
d["b"].append(3)
print(d)  # {'a': [1, 2], 'b': [3]}

# Another pattern: key-transforming mapping (e.g., case-insensitive dict via __missing__ alternative)

class FlexibleDict(dict):
    """Dict that tries case-insensitive fallback via __missing__."""
    def __missing__(self, key):
        if isinstance(key, str):
            lowered = key.lower()
            for k in self:
                if isinstance(k, str) and k.lower() == lowered:
                    return self[k]
        raise KeyError(key)

fd = FlexibleDict({"Name": "Alice", "city": "Boston"})
print(fd["name"])    # Alice — via __missing__
print(fd["CITY"])    # Boston — via __missing__
try:
    print(fd["missing"])
except KeyError as e:
    print(f"KeyError: {e}")

# Important: __getitem__ must explicitly call __missing__ — dict.__getitem__ does,
# but if you write your own Mapping from scratch, you must wired it yourself:

class MappingFromScratch:
    def __init__(self): self._data = {}
    def __getitem__(self, key):
        try:
            return self._data[key]
        except KeyError:
            # Check if subclass defined __missing__
            if hasattr(self, "__missing__"):
                return self.__missing__(key)
            raise
    def __setitem__(self, key, value): self._data[key] = value
    def __len__(self): return len(self._data)
    def __iter__(self): return iter(self._data)

# collections.UserDict and collections.abc.Mapping handle this automatically when you subclass them.
```

### `__missing__` vs `dict.get()` vs `__getitem__` fallback chain

| Access | Behavior when missing |
|--------|-----------------------|
| `d[key]` | raises `KeyError` → tries `d.__missing__(key)` if `d` is `dict` subclass and defines it |
| `d.get(key, default)` | returns `default` — never calls `__missing__` |
| `d.__getitem__(key)` | same as `d[key]` — calls `__missing__` |
| `key in d` | returns `False` — uses `__contains__`, not `__missing__` |
| Iteration `for k in d` | never calls `__missing__` |

## `__iter__` and `__reversed__` in the Container Context

While full iteration is lesson **13.07**, a container should provide sensible iteration over its "keys" or elements:

```python
class RangeSet:
    """An efficient set of integer ranges — container with compact storage."""
    def __init__(self, *ranges):  # ranges like (0,10), (20,30)
        merged = []
        for lo, hi in sorted(ranges):
            if merged and lo <= merged[-1][1]:
                merged[-1] = (merged[-1][0], max(merged[-1][1], hi))
            else:
                merged.append((lo, hi))
        self._ranges = merged
        self._size = sum(hi - lo for lo, hi in merged)

    def __len__(self): return self._size
    def __contains__(self, x):
        # binary search over ranges
        lo, hi = 0, len(self._ranges)
        while lo < hi:
            mid = (lo + hi)//2
            rlo, rhi = self._ranges[mid]
            if x < rlo: hi = mid
            elif x >= rhi: lo = mid + 1
            else: return True
        return False

    def __iter__(self):
        for lo, hi in self._ranges:
            for x in range(lo, hi):
                yield x

    def __reversed__(self):
        for lo, hi in reversed(self._ranges):
            for x in range(hi-1, lo-1, -1):
                yield x

    def __getitem__(self, index):
        # Support random access by position (like a sorted list of all members)
        if isinstance(index, slice):
            # Slow path: materialize (in production use range slicing)
            data = list(self)
            return data[index]
        if index < 0: index += len(self)
        if not 0 <= index < len(self):
            raise IndexError("RangeSet index out of range")
        # Walk ranges to find offset
        for lo, hi in self._ranges:
            span = hi - lo
            if index < span:
                return lo + index
            index -= span

    def __repr__(self): return f"RangeSet({self._ranges!r})"

rs = RangeSet((0,3), (10,13))
print(list(rs))        # [0, 1, 2, 10, 11, 12]
print(list(reversed(rs)))  # [12, 11, 10, 2, 1, 0] — via __reversed__
print(rs[0], rs[-1], rs[1:3])  # 0 12 [1, 2] — via __getitem__
print(2 in rs, 5 in rs)        # True False — via __contains__
```

### When to Define `__reversed__`

If `reversed(obj)` without `__reversed__` will try to iterate via `__len__` + `__getitem__` from `len-1` down to `0` (if sequence-like) or use `__iter__` then reverse (which copies). Defining `__reversed__` is an optimization and a correctness hook for containers where direct reversal is more efficient (trees, deques, ranges).

## Full Example: Custom Mapping via `collections.abc`

The most robust way to build a mapping: subclass `MutableMapping` (or `Mapping` for read-only) and implement the abstract methods. You get a full `dict` API for free.

```python
from collections.abc import MutableMapping

class AttrDict(MutableMapping):
    """
    A case-preserving mapping that also supports attribute access (a la JS objects).
    Inherits MutableMapping to get keys(), values(), items(), get(), pop(), clear(), update(), setdefault(), etc.
    Must implement: __getitem__, __setitem__, __delitem__, __iter__, __len__.
    """
    def __init__(self, *args, **kwargs):
        self._data: dict = {}
        self.update(dict(*args, **kwargs))

    # ---- Required abstract methods ----
    def __getitem__(self, key):
        return self._data[key]

    def __setitem__(self, key, value):
        self._data[key] = value

    def __delitem__(self, key):
        del self._data[key]

    def __iter__(self):
        return iter(self._data)

    def __len__(self):
        return len(self._data)

    # ---- Enhanced protocol ----
    def __contains__(self, key):  # MutableMapping already provides this via __getitem__ trial, but explicit is faster
        return key in self._data

    def __repr__(self):
        return f"AttrDict({self._data!r})"

    # Bonus: attribute access via __getattr__/__setattr__ (see 13.11)
    def __getattr__(self, name):
        try:
            return self._data[name]
        except KeyError:
            raise AttributeError(f"AttrDict has no key {name!r}") from None

    def __setattr__(self, name, value):
        if name == "_data":
            object.__setattr__(self, name, value)
        else:
            self._data[name] = value

    def __delattr__(self, name):
        try:
            del self._data[name]
        except KeyError:
            raise AttributeError(f"AttrDict has no key {name!r}") from None

ad = AttrDict({"name": "Alice", "age": 30})
print(ad["name"], ad.name)     # Alice Alice
ad.city = "Boston"
print(ad["city"])              # Boston
print(list(ad.keys()))         # ['name', 'age', 'city'] — free from MutableMapping
print(ad.get("missing", "?"))  # ?           — free
print("age" in ad)             # True        — via __contains__
ad.update({"age": 31, "zip": "02101"})
print(ad)                      # AttrDict({'name': 'Alice', 'age': 31, 'city': 'Boston', 'zip': '02101'})
print(len(ad))                 # 4
del ad["zip"]
print(ad.pop("city", None))    # Boston — free pop() implementation
```

### Sequence via `collections.abc.Sequence`

```python
from collections.abc import Sequence

class SortedList(Sequence):
    """
    Immutable sorted list — inherits Sequence's mixin __contains__, __iter__, index, count, __reversed__.
    Must implement: __getitem__, __len__.
    """
    def __init__(self, iterable):
        self._data = sorted(iterable)

    def __getitem__(self, index):
        return self._data[index]  # delegates int and slice correctly

    def __len__(self):
        return len(self._data)

    def __repr__(self):
        return f"SortedList({self._data!r})"

sl = SortedList([3,1,4,1,5])
print(sl[0], sl[-1], sl[1:4])   # 1 5 [1, 3, 4]
print(3 in sl)                  # True  — via Sequence.__contains__ (linear scan over __iter__)
print(list(sl))                 # [1, 1, 3, 4, 5]
print(sl.index(4))              # 3     — free from Sequence
print(sl.count(1))              # 2     — free
print(list(reversed(sl)))       # [5, 4, 3, 1, 1] — via __reversed__ from Sequence

# For O(log n) `in`, override __contains__ as shown earlier with bisect.
```

## Slicing Deep Dive: What Your `__getitem__` Receives

```python
class InspectSlices:
    def __getitem__(self, idx):
        print(f"idx={idx!r:30s} type={type(idx).__name__}")
        if isinstance(idx, slice):
            print(f"  start={idx.start} stop={idx.stop} step={idx.step}")
            print(f"  indices(10) = {idx.indices(10)}")  # normalized
            # extras:
            print(f"  slice has .indices method for clamping")
        return idx

s = InspectSlices()
s[5]                # idx=5
s[1:5]              # slice(1, 5, None) — step is None, not 1!
s[::2]              # slice(None, None, 2)
s[::-1]             # slice(None, None, -1)
s[1:10:2]           # slice(1, 10, 2)
s[-3:]              # slice(-3, None, None)
s[...]              # Ellipsis — not a slice, but valid __getitem__ arg (numpy uses this)
s[1, 2]             # (1, 2) — tuple (numpy uses multi-dim indexing)
s[1:2, 3:4]         # (slice(1, 2), slice(3, 4)) — tuple of slices

# Practical normalization inside __getitem__:
class SliceAware:
    def __init__(self, data): self._data = list(data)
    def __getitem__(self, idx):
        if isinstance(idx, slice):
            start, stop, step = idx.indices(len(self._data))
            print(f"normalized slice({start}, {stop}, {step})")
            # Either delegate:
            return self._data[idx]
            # Or generate manually:
            # return [self._data[i] for i in range(start, stop, step)]
        return self._data[idx]

sa = SliceAware(range(10))
print(sa[2:8:2])    # normalized slice(2, 8, 2) -> [2, 4, 6]
print(sa[-3:])      # normalized slice(7, 10, 1) -> [7, 8, 9]
print(sa[::-1])     # normalized slice(9, -1, -1) -> [9, 8, ..., 0]
```

## Edge Cases and Pitfalls

| Pitfall | Why It Bites | Fix |
|---------|--------------|-----|
| `__getitem__` handles only `int` | `obj[1:5]` raises `TypeError` | `if isinstance(key, slice): ...` with `slice.indices` |
| `__contains__` not defined and `__iter__` yields non-hashable | `in` is O(n) and may be surprisingly slow | Define `__contains__` with faster check if possible |
| `__missing__` without `dict` subclass | Never called | Subclass `dict` or `collections.UserDict`, or wire manually in custom `__getitem__` |
| Forgetting negative index handling | `obj[-1]` raises incorrectly | `if idx < 0: idx += len(self)` or delegate to internal list |
| `__len__` returning negative or non-int | `TypeError`/`ValueError` at `len()` | Always return `int >= 0` |
| Defining `__getitem__` without `__len__` | `bool(obj)` always `True`; `list(obj)` works via `__getitem__` legacy iteration (pre-2.2) but `len` fails | Define `__len__` when sized semantics apply |
| Slice assignment with `__setitem__` | `value` for slice may be unsized iterable | Handle: `self._data[key] = value` or validate `len(value)` if bounded capacity |

---

## Performance & Memory

*   **Delegate to built-in collections** (`list`, `dict`, `set`) internally — they are C-level arrays/dicts. Don't reimplement hash tables in Python loops.
*   **`__getitem__` per-element access in a loop is Python-call heavy.** Iteration via `__iter__` (yielding directly from internal storage) is faster than legacy `__getitem__(0), __getitem__(1), ...` iteration.
*   **Slice delegation `self._data[idx]` is C-optimized.** Manually building `[self[i] for i in range(*slice.indices(n))]` is ~3–5× slower for large slices.
*   **`__contains__` linear vs hash.** For `n = 1M`, `x in list` is O(n) with Python-level loop per element (~tens of ms). `x in set` is O(1) with C hash table lookup (~tens of ns). Always choose the right membership strategy for your size.

4.  Did you delegate where possible rather than reimplement?
5.  Is `__contains__` needed for fast membership, or is linear scan acceptable?
6.  If you wanted `__missing__`, did you subclass `dict` / `UserDict`?
7.  Have you inherited from `collections.abc` to get mixin methods?
8.  Is your iteration contract satisfied (`__iter__` returns iterator, or `__getitem__` with `IndexError` sentinel)?
