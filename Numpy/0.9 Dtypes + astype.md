# 0.9 Dtypes + `astype()` — The Complete Guide

> You do not need any other source after this file. Everything about NumPy data types — what they are, how NumPy picks them, how to set them, how to convert them with `astype()` — is explained here with runnable examples.

Start every example with:

```python
import numpy as np
```

---

## 1. What Is a `dtype`?

Every NumPy array (`ndarray`) holds **one type only**, called its `dtype` (data-type).

```
Python list:  [1, 2.5, "hi", True]  -> each item is a separate Python object,
                                     each with its own type, any mix allowed.

NumPy array:  array([1, 2, 3])      -> ONE dtype (here int64),
                                     all values packed side-by-side in one
                                     raw memory buffer.
```

Think of it like this:

```
┌────────────────────────────────────────────┐
│  ndarray = buffer + dtype + shape          │
│                                            │
│  buffer: [0101|0101|0101] raw bytes        │
│  dtype:  "read every 8 bytes as int64"     │
│  shape:  (3,) = 3 elements                 │
└────────────────────────────────────────────┘
```

The `dtype` tells NumPy **how many bytes per element** and **how to interpret those bytes** (as integer? float? True/False? text?).

Why one type only? Two reasons:

1. **Speed** — one tight C loop can process the whole buffer, no per-element type check.
2. **Memory** — no pointers, no `PyObject` overhead. Just raw numbers.

```python
py_list = [1, 2, 3]          # 3 pointers -> 3 separate int objects (~28 bytes each)
np_array = np.array([1,2,3]) # 3 x 8 bytes = 24 bytes total, contiguous
print(np_array.dtype)        # int64
print(np_array.nbytes)       # 24  -> size * itemsize = 3 * 8
```

## 2. How NumPy Chooses a `dtype` (Inference)

If you do **not** specify `dtype`, NumPy guesses from the input:

```python
print(np.array([1, 2, 3]).dtype)          # int64  (all Python ints -> default int)
print(np.array([1.0, 2, 3]).dtype)        # float64 (one float infects all -> float)
print(np.array([True, False]).dtype)      # bool
print(np.array([1, 2.5, 'a']).dtype)      # <U32  (mix number + string -> string!)
```

Rules, in order:

1. **All ints** -> `int64` on most computers (Windows sometimes `int32`). This is the platform default, called `np.int_` / long.
2. **Any float mixed in** -> `float64`. `np.array([1, 2.0])` is float, not int.
3. **Any string mixed in** -> string dtype `<U...` (Unicode). Numbers get converted to text! `np.array([1, 2.0, 'a'])` gives `array(['1', '2.0', 'a'])`.
4. **Any `None` mixed with numbers** -> becomes `object` or float `nan` depending on context — avoid mixing, it kills performance.

> **Rule of thumb:** NumPy promotes to the most general type that can hold *all* inputs without losing information (as text). This is called **type promotion** — full details in section 7.

Check what your platform defaults are:

```python
print(np.dtype(int))    # int64 on Linux/Mac, int32 on some Windows
print(np.dtype(float))  # float64 everywhere
```

## 3. Inspecting a `dtype`

Three attributes answer everything:

```python
a = np.array([1, 2, 3], dtype=np.int32)

print(a.dtype)        # int32
print(a.itemsize)     # 4      -> bytes per ONE element
print(a.nbytes)       # 12     -> bytes for WHOLE array = size * itemsize
print(a.size)         # 3      -> number of elements
```

More inspection tools:

```python
a = np.array([1.5, 2.5])

print(a.dtype.name)   # 'float64'
print(a.dtype.kind)   # 'f'  -> one-letter code, see table below
print(a.dtype.char)   # 'd'
print(a.dtype.str)    # '<f8'  -> < = little-endian, f = float, 8 = 8 bytes
print(a.dtype.itemsize)  # 8
```

`kind` codes you will actually see:

| kind | Means | Example dtypes |
|---|---|---|
| `i` | signed integer | `int8, int16, int32, int64` |
| `u` | unsigned integer | `uint8, uint16, uint32, uint64` |
| `f` | floating point | `float16, float32, float64` |
| `b` | boolean | `bool` |
| `U` | Unicode string (fixed length) | `U3, U10` |
| `c` | complex | `complex64, complex128` |
| `O` | Python object (any) | `object` |
| `M` | datetime | `datetime64` |
| `m` | timedelta | `timedelta64` |

Useful helpers:

```python
print(np.iinfo(np.int8))     # min=-128, max=127
print(np.finfo(np.float32))  # max ~3.4e38, precision=6 digits
print(np.can_cast(np.int32, np.float64))                  # True  (safe direction)
print(np.can_cast(np.float64, np.int32, casting='safe'))  # False (loses decimal part)
```

## 4. The Full `dtype` Catalog (What to Actually Use)

### 4.1 Integers — exact whole numbers

| dtype | Bytes | Range | When to use |
|---|---|---|---|
| `int8` / `np.int8` | 1 | -128 to 127 | Tiny data, images (-128..127), memory-critical |
| `int16` | 2 | -32,768 to 32,767 | Rarely needed |
| `int32` | 4 | -2.1B to 2.1B | Large arrays where 64-bit is wasteful, IDs |
| `int64` (default) | 8 | -9e18 to 9e18 | **Default. Use unless you have a reason not to.** |
| `uint8` | 1 | 0 to 255 | Images (0-255 pixels), counts that can't be negative |
| `uint16/32/64` | 2/4/8 | 0 to ... | Counters, indices, bit masks |

```python
print(np.array([1, 2, 3], dtype=np.int8).dtype)   # int8
print(np.array([1, 2, 3], dtype=np.uint8).dtype)  # uint8
```

> **Signed vs unsigned:** `int8` holds negatives but only up to 127. `uint8` holds no negatives but up to 255. Pick `uint8` for pixels (never negative), `int32/64` for general math.

### 4.2 Floats — decimals / scientific numbers

| dtype | Bytes | Precision | When to use |
|---|---|---|---|
| `float16` | 2 | ~3 decimal digits | ML half-precision on GPU only. Not for CPU math (inaccurate). |
| `float32` | 4 | ~7 digits | ML models, large arrays, GPU. Half the memory of float64. |
| `float64` (default) | 8 | ~15 digits | **Default. Science, money-ish math, any division.** |

```python
print(np.array([1.5], dtype=np.float32).dtype)  # float32
print(np.zeros((2, 3), dtype=float).dtype)      # float64 (Python float = float64)
```

### 4.3 Boolean — `True` / `False`

1 byte per element, values only `True`/`False`.

```python
b = np.array([True, False, True])
print(b.dtype)      # bool
print(b.itemsize)   # 1
```

Main use: **masks for filtering** (see `0.7 filtering`):

```python
a = np.array([10, 20, 30])
mask = a > 15          # array([False, True, True]) dtype=bool
print(a[mask])         # [20 30]
```

### 4.4 Strings — fixed-length Unicode `<U`

```python
s = np.array(['hello', 'hi'])
print(s.dtype)  # <U5  -> Unicode, max 5 characters (length of longest)
print(s)        # ['hello' 'hi']
```

Critical: length is **fixed at creation**. Longer strings get **silently cut**:

```python
s = np.array(['hello', 'hi'], dtype='U3')
print(s)  # ['hel' 'hi']  -> 'hello' truncated to 'hel'! No error!
```

| dtype | Means |
|---|---|
| `U3` | Unicode string, max 3 chars |
| `S10` | byte string, max 10 bytes (rare, for file I/O) |
| `object` | any Python object (list, dict, mixed) — slow, no vectorization |

> Use NumPy strings only for fixed labels/IDs. For real text work use Python lists or Pandas.

### 4.5 The rest (know they exist)

| dtype | Example | Use |
|---|---|---|
| `complex64/128` | `1+2j` | Signal processing, FFT. `np.array([1+2j]).dtype` -> `complex128` |
| `object` | `np.array([1, 'a', None], dtype=object)` | Mixed types. Falls back to slow Python — avoid for numbers. |
| `datetime64` | `np.array(['2024-01-01'], dtype='datetime64')` | Dates, time series |
| `timedelta64` | `np.array([5], dtype='timedelta64[D]')` | Differences between dates |

You can write dtypes many ways — all equivalent:

```python
np.dtype('int32') == np.dtype(np.int32) == np.dtype('i4')  # True
# 'i4' means: i=signed int, 4=4 bytes. '<f8' means little-endian float 8 bytes.
```

## 5. Setting `dtype` at Creation

Pass `dtype=` to any creation function:

```python
print(np.array([1, 2, 3], dtype=np.float32))  # [1. 2. 3.] float32
print(np.zeros((2, 3), dtype=int))            # 2x3 zeros, int64
print(np.ones(3, dtype=np.int16))             # [1 1 1] int16
print(np.arange(5, dtype=np.float64))         # [0. 1. 2. 3. 4.]
print(np.eye(2, dtype=bool))                  # [[ True False] [False  True]]
```

Why set it upfront?

1. **Save memory** — `np.zeros(1_000_000, dtype=np.int8)` uses 1 MB, default `int64` uses 8 MB.
2. **Match requirements** — image libraries want `uint8`, GPUs want `float32`.
3. **Avoid later conversion cost** — creating directly is cheaper than creating then `astype()`.

## 6. `astype()` — Converting After Creation (The Core of This File)

### 6.1 Signature and the #1 rule

```python
new_array = old_array.astype(dtype, copy=True)
```

- `dtype` — the target type (required). E.g. `np.int32`, `float`, `bool`, `'U10'`, `str`.
- `copy=True` (default) — **always returns a NEW array**, never changes the original.

```python
a = np.array([1, 2, 3], dtype=np.int32)
b = a.astype(np.float64)

print(a.dtype)  # int32   -> original UNCHANGED
print(b.dtype)  # float64 -> new array
print(b)        # [1. 2. 3.]
print(np.shares_memory(a, b))  # False -> separate memory
```

> **#1 trap:** `astype()` does NOT work in place. `a.astype(float)` alone does nothing — you must assign: `a = a.astype(float)`.

The only exception:

```python
c = a.astype(np.int32, copy=False)  # same dtype + copy=False -> returns SAME array, no copy
print(np.shares_memory(a, c))       # True
```

With a *different* dtype, `copy=False` still copies (it has to — bytes change size).

### 6.2 The 5 conversions you will use 99% of the time

**a) int -> float (always safe, never loses data for small ints):**

```python
print(np.array([1, 2, 3]).astype(float))      # [1. 2. 3.] float64
print(np.array([1, 2, 3], dtype=np.int32).astype(np.float32))  # float32 version
```

**b) float -> int (TRUNCATES toward zero, not rounds!):**

```python
print(np.array([1.99, 2.5, 2.1, -1.99]).astype(int))
# [ 1  2  2 -1]  -> decimals chopped off, NOT rounded!
# Want rounding? Do it explicitly:
print(np.round([1.99, 2.5, 2.1]).astype(int))  # [2 2 2]
```

**c) Anything -> bool (0/empty = False, everything else = True):**

```python
print(np.array([0, 1, 2, -5]).astype(bool))        # [False  True  True  True]
print(np.array([0.0, 0.5, 1.0]).astype(bool))      # [False  True  True]
print(np.array(['', 'hi', '0']).astype(bool))      # [False  True  True] -> non-empty string is True, even '0'!
print(np.array([True, False]).astype(int))         # [1 0]  -> reverse direction
```

**d) Numbers <-> strings:**

```python
print(np.array(['1', '2', '3']).astype(int))    # [1 2 3]
print(np.array([1, 2, 3]).astype(str))          # ['1' '2' '3']  dtype <U21
print(np.array([1.5, 2.0]).astype(str))         # ['1.5' '2.0']
# Fails if text is not a number:
# np.array(['1.5', 'abc']).astype(float)  -> ValueError: could not convert string to float: 'abc'
```

**e) Downcasting to save memory (int64 -> int32/int8, float64 -> float32):**

```python
big = np.arange(1000)              # int64, 8000 bytes
small = big.astype(np.int16)       # int16, 2000 bytes (if values fit in -32768..32767)
print(big.nbytes, small.nbytes)    # 8000 2000
```

### 6.3 What can go wrong — overflow, precision loss, truncation

These fail **silently** (no error). You must know them:

**a) Integer overflow — wraps around:**

```python
print(np.array([300], dtype=np.int16).astype(np.int8))  # [44]  not 300!
# Why? int8 max is 127. 300 - 256 = 44. NumPy wraps modulo 256, no warning.
print(np.array([127], dtype=np.int8).astype(np.uint8))  # [127] safe (fits)
print(np.array([-1], dtype=np.int8).astype(np.uint8))   # [255] -1 wraps to 255!
```

**b) Float precision loss — float64 -> float32:**

```python
x = np.array([1.123456789])
print(x.astype(np.float32))  # [1.1234568] -> last digits lost (~7 digits kept)
```

**c) String truncation — fixed length cuts silently:**

```python
print(np.array(['hello', 'hi'], dtype='U3'))  # ['hel' 'hi'] -> cut, no error
# Fix: give enough length
print(np.array(['hello', 'hi'], dtype='U5'))  # ['hello' 'hi']
```

**d) Invalid string -> number raises:**

```python
# np.array(['abc']).astype(int)  # ValueError — the one case that DOES error
```

Safety checklist before `astype()`:

1. Check range: does max/min fit? `print(a.min(), a.max(), np.iinfo(np.int8))`
2. Check float->int: did you want truncation or rounding? Use `np.round()` / `np.floor()` / `np.ceil()` first if needed.
3. Check strings: is length long enough? Use a generous `dtype='U50'` or let NumPy infer.
4. Remember to assign: `a = a.astype(...)`.

## 7. Type Promotion — What Happens When Dtypes Mix

When you combine two different dtypes (in `np.array([...])` or `a + b`), NumPy picks the **smallest dtype that can hold both without losing info**:

```python
print(np.result_type(np.int32, np.float64))  # float64 (float wins over int)
print((np.array([1, 2]) + np.array([1.5])).dtype)  # float64

print(np.result_type(np.int8, np.int16))     # int16 (wider int wins)
print(np.result_type(np.int32, np.uint8))    # int32
print(np.result_type(True, np.int32))        # int32 (bool + int -> int)
```

Practical consequences:

```python
a = np.array([1, 2, 3], dtype=np.int32)
b = np.array([1.5, 2.5, 3.5])                # float64
print((a + b).dtype)  # float64 -> result upcast, inputs unchanged

c = np.array([1, 2, 3])       # int64
d = np.array([1, 2, 3], dtype=np.float32)
print((c + d).dtype)  # float64 (int64 + float32 -> float64, NOT float32!)
```

> Integer division is a classic surprise: `np.array([1, 2, 3]) / 2` gives `float64` `[0.5 1. 1.5]`, not ints. Use `//` for integer division.

## 8. Memory & Performance — Why `dtype` Choice Matters

Memory = `size * itemsize`:

```python
for dt in [np.int8, np.int32, np.int64, np.float32, np.float64]:
    a = np.zeros(1_000_000, dtype=dt)
    print(f"{np.dtype(dt).name:10s} itemsize={a.itemsize}  total={a.nbytes / 1e6:.1f} MB")
# int8       itemsize=1  total=1.0 MB
# int32      itemsize=4  total=4.0 MB
# int64      itemsize=8  total=8.0 MB
# float32    itemsize=4  total=4.0 MB
# float64    itemsize=8  total=8.0 MB
```

Guidelines:

| Situation | Use |
|---|---|
| Default math, science, learning | `int64` / `float64` (defaults — don't overthink) |
| Large arrays (>100K elements) with small values | Downcast: `int32`, `int16`, `float32` |
| Images (pixels 0-255) | `uint8` |
| GPU / neural nets | `float32` (standard), `float16` only on GPU |
| Masks / conditions | `bool` |
| IDs that must be exact beyond 2^53 | Keep as `int64` — `float64` can't represent every integer above 9e15 exactly |

Smaller dtype = less RAM + faster transfer + more SIMD elements per instruction. But too small = overflow / precision bugs. Always verify `min`/`max` fit.

## 9. Cheat Sheet (Copy-Paste)

```python
import numpy as np

# Inspect
a = np.array([1, 2, 3])
a.dtype       # int64
a.itemsize    # 8
a.nbytes      # 24

# Create with dtype
np.array([1, 2, 3], dtype=np.float32)
np.zeros((2, 3), dtype=np.int16)
np.ones(5, dtype=bool)
np.arange(10, dtype=np.float64)

# Convert with astype (remember to assign!)
b = a.astype(np.float64)   # int -> float
c = np.array([1.9, 2.1]).astype(int)       # float -> int (truncate: [1 2])
d = np.array([0, 1, 5]).astype(bool)       # -> [False True True]
e = np.array(['1', '2']).astype(int)       # strings -> ints
f = np.array([1, 2]).astype(str)           # ints -> strings

# Safe downcast pattern
vals = np.arange(100)                      # int64
assert vals.max() < 127 and vals.min() >= -128
tiny = vals.astype(np.int8)                # safe: verified range first

# Promotion check
np.result_type(np.int32, np.float64)       # float64
```

## 11. Common Traps — One-Line Each

1. `a.astype(t)` without assignment does nothing — always `a = a.astype(t)`.
2. float->int **truncates** (`1.99 -> 1`), never rounds.
3. Overflow **wraps silently** (`300 -> 44` in int8). Check `min/max` vs `np.iinfo` first.
4. String dtype is fixed-length — `'hello'` in `U3` becomes `'hel'` with no warning.
5. Mixed list `[1, 'a']` becomes all-strings — rarely what you want.
6. `object` dtype kills speed — fix the input instead of accepting it.
7. `int64 + float32 -> float64`, not `float32` — check `.dtype` after mixed ops.
